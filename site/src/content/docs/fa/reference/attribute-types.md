ویژگی‌ها فیلدهای یک نوع محتوا یا کامپوننت هستند که زیر `attributes` در فایل طرح‌وارهٔ (schema)
آن تعریف می‌شوند. این صفحه همهٔ `type`ها، گزینه‌هایی که هر کدام می‌پذیرد، نحوهٔ اعتبارسنجی و
ذخیره‌سازی آن‌ها در Verdin، و شکل آن‌ها در API را فهرست می‌کند. قالب همان قالب Strapi v5 است؛
تفاوت‌ها [در پایان](#تفاوتها-با-strapi) آمده‌اند.

```json title="schema/content-types/article.json"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "attributes": {
    "title": { "type": "string", "required": true, "maxLength": 200 },
    "slug": { "type": "uid", "targetField": "title", "required": true },
    "readingTime": { "type": "integer", "min": 0 },
    "category": { "type": "relation", "relation": "manyToOne", "target": "category", "inversedBy": "articles" },
    "seo": { "type": "component", "component": "shared.seo" }
  }
}
```

فایل‌های طرح‌واره سخت‌گیرانه‌اند: یک کلید ناشناخته، یا گزینه‌ای که نوع آن را نمی‌پذیرد، خطایی است
که `verdin schema check` آن را همراه با مسیرش (`attributes.title.maxLength`) گزارش می‌کند.

## گزینه‌هایی که همهٔ ویژگی‌ها می‌پذیرند

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| `type` | الزامی | یکی از نوع‌های زیر. |
| `required` | `false` | مقدار باید وجود داشته باشد. هنگام انتشار یک مدخل بررسی می‌شود (پیش‌نویس‌ها می‌توانند ناقص باشند)، و در هر نوشتن روی نوعی بدون پیش‌نویس و انتشار. درون کامپوننت‌ها و ناحیه‌های پویا هم اعمال می‌شود. |
| `private` | `false` | هرگز توسط API محتوا برگردانده نمی‌شود و در `filters` یا `sort` قابل استفاده نیست. ویژگی‌های `password` همیشه خصوصی‌اند. |
| `configurable` | `true` | پرچم Strapi برای سازندهٔ پنل مدیریت؛ همان‌طور که نوشته شده نگه داشته می‌شود. |
| `pluginOptions.i18n.localized` | `true` | در یک نوع محتوای بومی‌سازی‌شده، `false` مقدار را بین زبان‌ها مشترک می‌کند، به جای یک مقدار برای هر زبان. |
| `customField` | تنظیم‌نشده | `plugin::<plugin>.<field>` (یا `global::<field>`): پنل مدیریت ویژگی را با فیلد سفارشی یک افزونه ویرایش می‌کند. `type` نحوهٔ ذخیرهٔ مقدار است. [افزونه‌ها](/fa/extending/plugins/) را ببینید. |
| `conditions` | تنظیم‌نشده | فیلدهای شرطی Strapi (`{ "visible": <JSON Logic> }`). ویرایشگر تا وقتی قاعده نادرست است فیلد را پنهان می‌کند و سرور فیلد پنهان را الزامی نمی‌داند. |
| `default` | تنظیم‌نشده | مقدار مدخل‌های جدید وقتی نوشتن، ویژگی را شامل نمی‌شود. باید برای آن نوع معتبر باشد. همهٔ نوع‌ها آن را نمی‌پذیرند (هر نوع را ببینید). |

نام ویژگی‌ها با یک حرف شروع می‌شود و سپس حروف، ارقام و `_`، حداکثر 50 نویسه.
در نوع‌های محتوا، `id`، `documentId`، `locale`، `publicationState`، `publishedAt`،
`createdAt`، `updatedAt`، `createdBy` و `updatedBy` رزرو شده‌اند؛ در کامپوننت‌ها، `id`.
دو نامی که به یک ستون نگاشت می‌شوند (`metaTitle` و `meta_title`) خطا هستند.

### محل ذخیرهٔ مقدارها

هر ویژگی یک نوع محتوا یک ستون از جدول آن نوع است (`collectionName`، یا
نام جمع)، با نامی به شکل `snake_case`. روابط و رسانه به جای آن در جدول‌های پیوند نگه داشته می‌شوند.
یک پیش‌نویس و نسخهٔ منتشرشدهٔ آن دو ردیف هستند، در نوع‌های بومی‌سازی‌شده یکی برای هر زبان.

نوع ستون‌ها در هر پایگاه داده:

| ستون | PostgreSQL | MySQL و MariaDB | SQLite |
| --- | --- | --- | --- |
| varchar | `varchar(255)` | `varchar(255)` | `text` |
| text | `text` | `longtext` | `text` |
| integer | `integer` | `int` | `integer` |
| bigint | `bigint` | `bigint` | `integer` |
| double | `double precision` | `double` | `real` |
| decimal | `numeric(p,s)` | `decimal(p,s)` | `text` (دقیق) |
| boolean | `boolean` | `tinyint(1)` | `integer` |
| date | `date` | `date` | `text` |
| time | `time(3)` | `time(3)` | `text` |
| datetime | `timestamptz(3)` | `datetime(3)` | `text` |
| json | `jsonb` | `json` | `text` |

یک نوع محتوا می‌تواند حداکثر 60 ویژگی `string`، `email`، `uid` و `enumeration` داشته باشد
(محدودیت اندازهٔ ردیف در MySQL)؛ برای بیشتر از آن از `text` استفاده کنید.

### `unique`

نوع‌هایی که `unique: true` را می‌پذیرند، یک نمایهٔ یکتا روی `(column, locale, publication_state)` می‌گیرند:
دو مدخل منتشرشده، یا دو پیش‌نویس، در یک زبان نمی‌توانند مقدار مشترک داشته باشند، در حالی که یک
پیش‌نویس و نسخهٔ منتشرشدهٔ خودش می‌توانند. نوشتنی که این قاعده را بشکند با یک خطای اعتبارسنجی
روی آن ویژگی شکست می‌خورد. درون کامپوننت‌ها، `unique` پذیرفته می‌شود اما اعمال نمی‌شود
(مقدارهای کامپوننت به‌صورت JSON ذخیره می‌شوند).

## متن

### `string`

یک خط متن.

| گزینه | توضیح |
| --- | --- |
| `minLength`، `maxLength` | محدودهٔ طول بر حسب نویسه. `maxLength` حداکثر 255 است. |
| `regex` | الگویی که مقدار باید با آن تطبیق کند. نحوی شبیه JavaScript، با look-around و backreference. |
| `unique` | [`unique`](#unique) را ببینید. |
| `default` | رشته‌ای در محدوده که با `regex` تطبیق کند. |

به‌صورت `varchar(255)` ذخیره می‌شود. API: یک رشته.

### `text`

متن سادهٔ طولانی‌تر (یک textarea در پنل مدیریت).

| گزینه | توضیح |
| --- | --- |
| `minLength`، `maxLength` | محدودهٔ طول، بدون سقف. |
| `default` | رشته‌ای در محدوده. |

به‌صورت `text` ذخیره می‌شود (`longtext` در MySQL). API: یک رشته.

### `richtext`

متن Markdown. گزینه‌ها، ذخیره‌سازی و API همانند `text`؛ پنل مدیریت آن را با
ویرایشگر Markdown ویرایش می‌کند.

### `blocks`

متن غنی به شکل JSON بلوک‌های Strapi: فهرستی از بلوک‌های `paragraph`، `heading` (`level` از 1 تا 6)،
`list` (`format` برابر `ordered` یا `unordered`، با فرزندان `list-item`، تا 8 سطح تودرتو)،
`quote`، `code` (با `language` اختیاری) و `image`. فرزندان درون‌خطی گره‌های
`text` هستند، با نشانه‌های `bold`، `italic`، `underline`، `strikethrough` و `code`،
و گره‌های `link`. حداکثر 10,000 بلوک.

بدون گزینه، بدون `default`. به‌صورت JSON ذخیره می‌شود. API: فهرست بلوک‌ها، همان‌طور که نوشته شده‌اند.

```json
[
  { "type": "heading", "level": 2, "children": [{ "type": "text", "text": "Hello" }] },
  { "type": "paragraph", "children": [{ "type": "text", "text": "bold", "bold": true }] }
]
```

### `email`

یک نشانی ایمیل (`name@domain.tld`، بدون فاصله).

| گزینه | توضیح |
| --- | --- |
| `minLength`، `maxLength` | محدودهٔ طول؛ `maxLength` حداکثر 255. |
| `unique` | [`unique`](#unique) را ببینید. |
| `default` | یک نشانی ایمیل. |

به‌صورت `varchar(255)` ذخیره می‌شود. API: یک رشته.

### `password`

یک مقدار محرمانه که هنگام نوشتن با Argon2id هش می‌شود.

| گزینه | توضیح |
| --- | --- |
| `minLength`، `maxLength` | محدودهٔ طول گذرواژه، همان‌طور که فرستاده می‌شود. |

بدون `default`. همیشه خصوصی: هرگز برگردانده، فیلتر یا مرتب نمی‌شود. درون
کامپوننت‌ها مجاز نیست. به‌صورت `varchar(255)` (هش) ذخیره می‌شود. درون‌ریزی‌ها هش‌های موجود bcrypt و Argon2
را همان‌طور که هستند نگه می‌دارند، بنابراین حساب‌های درون‌ریزی‌شده همچنان می‌توانند وارد شوند.

### `uid`

یک شناسه برای URLها، مانند slug. پنل مدیریت آن را از `targetField` تولید می‌کند.

| گزینه | توضیح |
| --- | --- |
| `targetField` | یک ویژگی `string` یا `text` از همان نوع که مقدار از آن تولید می‌شود. |
| `minLength`، `maxLength` | محدودهٔ طول؛ `maxLength` حداکثر 255. |
| `regex` | الگویی که مقدارها باید با آن تطبیق کنند؛ بدون آن، `^[A-Za-z0-9\-_.~]*$`. |
| `default` | یک مقدار معتبر. |

همیشه یکتاست ([`unique`](#unique) را ببینید). به‌صورت `varchar(255)` ذخیره می‌شود. API: یک رشته.

### `enumeration`

یک مقدار از یک فهرست ثابت.

| گزینه | توضیح |
| --- | --- |
| `enum` | مقدارها: دست‌کم یکی، هر کدام 1 تا 255 نویسه، بدون تکرار. |
| `default` | یکی از مقدارها. |

به‌صورت `varchar(255)` ذخیره می‌شود. API: یک رشته. نوشتن هر مقدار دیگری شکست می‌خورد.

## عددها

### `integer`

یک عدد صحیح 32 بیتی (−2,147,483,648 تا 2,147,483,647).

| گزینه | توضیح |
| --- | --- |
| `min`، `max` | کران‌ها (عدد صحیح). |
| `unique` | [`unique`](#unique) را ببینید. |
| `default` | یک عدد صحیح در محدوده. |

به‌صورت `integer` ذخیره می‌شود. API: یک عدد. نوشتن‌ها عدد و رشته‌های عدد صحیح را می‌پذیرند.

### `biginteger`

یک عدد صحیح 64 بیتی. گزینه‌ها همانند `integer`.

به‌صورت `bigint` ذخیره می‌شود. API: یک رشته (`"9007199254740993"`)، مانند Strapi، چون عددهای
JavaScript پس از 2⁵³ دقت خود را از دست می‌دهند. نوشتن‌ها رشته و عدد را می‌پذیرند.

### `float`

یک عدد ممیز شناور با دقت مضاعف. گزینه‌ها همانند `integer`، با کران‌های عددی.

به‌صورت `double precision` (`double`، `real`) ذخیره می‌شود. API: یک عدد.

### `decimal`

یک عدد اعشاری دقیق.

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| `precision` | `10` | تعداد کل ارقام، از 1 تا 38. |
| `scale` | `2` | ارقام پس از ممیز، حداکثر `precision`. |
| `min`، `max` | | کران‌ها. |
| `unique` | | [`unique`](#unique) را ببینید. |
| `default` | | عددی در محدوده. |

مقدارها به `scale` رقم گرد می‌شوند (نیمه به دور از صفر، همان کاری که پایگاه‌های داده می‌کنند)، و
وقتی بیش از `precision - scale` رقم پیش از ممیز داشته باشند رد می‌شوند. نوشتن‌ها
عدد و رشته‌های عددی را می‌پذیرند. به‌صورت `numeric(precision,scale)` ذخیره می‌شود (`text` در
SQLite، پس هیچ چیزی گرد نمی‌شود). API: یک عدد، یا یک رشتهٔ دقیق با
[`[api].decimal_as_string`](/fa/reference/configuration/).

## تاریخ‌ها و بولی‌ها

### `boolean`

`true` یا `false`. `default` را می‌پذیرد. به‌صورت `boolean` (`tinyint(1)`، `integer`) ذخیره می‌شود. API: یک
مقدار بولی.

### `date`

یک تاریخ تقویمی، `YYYY-MM-DD`. `unique` و `default` را می‌پذیرد. به‌صورت `date` ذخیره می‌شود. API:
`"2026-09-29"`.

### `time`

یک زمان از روز، `HH:MM`، `HH:MM:SS` یا `HH:MM:SS.mmm`. `unique` و `default` را می‌پذیرد. با
دقت میلی‌ثانیه ذخیره می‌شود. API: `"14:30:00.000"`.

### `datetime`

یک لحظه از زمان: یک مُهر زمانی ISO 8601 با منطقهٔ زمانی (`Z` یا `+02:00`). `unique` و
`default` را می‌پذیرد. به وقت UTC با دقت میلی‌ثانیه ذخیره می‌شود. API: `"2026-09-29T12:30:00.000Z"`.

## `json`

هر مقدار JSON. `default` را می‌پذیرد (هر JSON). به‌صورت `jsonb` (`json`، `text`) ذخیره می‌شود. API: مقدار
همان‌طور که نوشته شده. در `filters`، ویژگی‌های JSON فقط از `$null` و `$notNull` پشتیبانی می‌کنند و
نمی‌توان بر اساس آن‌ها مرتب کرد.

## رسانه

### `media`

فایل‌هایی از کتابخانهٔ رسانه.

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| `multiple` | `false` | به جای یک فایل، فهرستی از فایل‌ها نگه می‌دارد. |
| `allowedTypes` | هر نوع | گونه‌های فایل: `images`، `videos`، `audios`، `files` (هر چیز دیگر). |

بدون `default`. در یک جدول پیوند `{table}_{attribute}_mda`، به ترتیب، ذخیره می‌شود. نوشتن‌ها شناسهٔ
فایل می‌گیرند: `12`، `{ "id": 12 }`، فهرستی از آن‌ها، یا `null`. API: فقط با `populate`؛ یک شیء
فایل (`url`، `mime`، `width`، `formats`…، مانند Strapi)، فهرستی از آن‌ها، یا `null`.
[رسانه](/fa/concepts/media/) را ببینید.

## روابط

### `relation`

به سندهای یک نوع محتوای دیگر پیوند می‌دهد.

| گزینه | توضیح |
| --- | --- |
| `relation` | `oneToOne`، `oneToMany`، `manyToOne`، `manyToMany`، `oneWay`، `manyWay`، یا یک گونهٔ چندریختی (پایین‌تر). |
| `target` | نوع محتوای مقصد: `article`، `api::article` یا `api::article.article`. |
| `inversedBy` | در سمت مالک یک رابطهٔ دوطرفه: ویژگی‌ای از مقصد که آینهٔ آن است. |
| `mappedBy` | در سمت دیگر: ویژگی مالک در مقصد. |

دو سمت یک رابطهٔ دوطرفه باید با هم سازگار باشند: `oneToMany` آینهٔ `manyToOne` است،
`oneToOne` و `manyToMany` آینهٔ خودشان هستند، و سمت `mappedBy` ویژگی‌ای را نام می‌برد
که `inversedBy` آن به این سمت برمی‌گردد. `oneWay` و `manyWay` سمت دیگری ندارند.

پیوندها در سمت مالک (سمت بدون `mappedBy`) در `{table}_{attribute}_lnk` ذخیره می‌شوند و
به `documentId` مقصد، به ترتیب، اشاره می‌کنند. نوشتن‌ها `documentId` می‌گیرند:

| نوشتن | معنا |
| --- | --- |
| `"d8f3…"`، `{ "documentId": "d8f3…" }`، فهرستی از آن‌ها | پیوندها را جایگزین می‌کند. |
| `null` یا `[]` | همهٔ پیوندها را حذف می‌کند. |
| `{ "set": [...] }` | پیوندها را جایگزین می‌کند. |
| `{ "connect": [...], "disconnect": [...] }` | پیوند اضافه و حذف می‌کند. یک آیتم `connect` می‌تواند `position` داشته باشد: `{ "before": id }`، `{ "after": id }`، `{ "start": true }` یا `{ "end": true }`. |

API: فقط با `populate`، به شکل سندهای مرتبط (حداکثر 1,000 برای هر مدخل و
رابطه)، یا `{ "count": n }` با `populate[tags][count]=true`.
[روابط](/fa/concepts/relations/) را ببینید.

درون کامپوننت‌ها فقط `oneWay` و `manyWay` مجازند؛ کامپوننت `documentId`ها را ذخیره
می‌کند.

### روابط چندریختی

`relation` گونه‌های چندریختی (polymorphic) را هم می‌پذیرد که سندهایی از هر نوع محتوایی را پیوند می‌دهند:

| `relation` | گزینه‌ها | توضیح |
| --- | --- | --- |
| `morphToOne` | هیچ | یک سند از هر نوعی را پیوند می‌دهد. |
| `morphToMany` | هیچ | سندهایی از هر نوعی را پیوند می‌دهد. |
| `morphOne` | `target`، `morphBy` | سمت معکوس: پیوندهای ویژگی `morphToOne` یا `morphToMany` با نام `morphBy` در `target` را می‌خواند. |
| `morphMany` | `target`، `morphBy` | همان، برای چندتایی. |

مالک‌ها جفت‌های `(type, documentId)` را در `{table}_{attribute}_mph` ذخیره می‌کنند. نوشتن‌ها
آیتم‌های `{ "__type": "api::article", "documentId": "…" }` می‌گیرند (یکی، یک فهرست، `null` یا
`{ "set": [...] }`). آیتم‌های populateشده نوع خود را در `__type` دارند. درون
کامپوننت‌ها مجاز نیست.

## کامپوننت‌ها و ناحیه‌های پویا

### `component`

گروهی از فیلدها که در `schema/components/<category>/<name>.json` تعریف شده است.

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| `component` | الزامی | uid کامپوننت، `category.name` (`shared.seo`). |
| `repeatable` | `false` | به جای یک آیتم، فهرستی از آیتم‌ها نگه می‌دارد. |
| `min`، `max` | | تعداد آیتم‌ها؛ فقط با `repeatable`. |

بدون `default`: آیتم‌های جدید پیش‌فرض‌های ویژگی‌های خودشان را می‌گیرند. به‌صورت JSON در ردیف
مدخل ذخیره می‌شود، هر آیتم با یک `id`. نوشتن‌ها شیء آیتم (یا یک فهرست) را می‌گیرند، با `id`
برای نگه داشتن یک آیتم موجود. API: فقط با `populate`، کل آیتم یا فهرست. در
`filters` می‌توانید روی فیلدهای یک کامپوننت فیلتر کنید
(`filters[seo][metaTitle][$eq]=…`).
[کامپوننت‌ها و ناحیه‌های پویا](/fa/concepts/components-and-dynamic-zones/) را ببینید.

### `dynamiczone`

فهرستی از آیتم‌ها که هر کدام یکی از چند کامپوننت است.

| گزینه | توضیح |
| --- | --- |
| `components` | uidهای کامپوننت مجاز: دست‌کم یکی، بدون تکرار. |
| `min`، `max` | تعداد آیتم‌ها. |

هر آیتم `__component` را با uid خود دارد. به‌صورت JSON در ردیف مدخل ذخیره می‌شود. API:
فقط با `populate`، کل فهرست. فیلتر بر اساس کامپوننت با
`filters[blocks][__component][$eq]=blocks.hero`. ناحیه‌های پویا نمی‌توانند درون
کامپوننت‌ها تودرتو باشند.

## اعتبارسنجی‌های میان‌فیلدی

علاوه بر گزینه‌های هر ویژگی، یک نوع محتوا می‌تواند قاعده‌هایی روی چند فیلد را در
`validations` تعریف کند که هر بار `required` بررسی می‌شود، بررسی می‌شوند:

```json
"validations": [
  {
    "rule": { "<=": [{ "var": "startDate" }, { "var": "endDate" }] },
    "message": "The end date must be after the start date",
    "field": "endDate"
  }
]
```

`rule` یک عبارت JSON Logic روی مدخل است که باید برقرار باشد. می‌تواند از `var`، `==`،
`!=`، `===`، `!==`، `<`، `>`، `<=`، `>=`، `!`، `!!`، `and`، `or`، `in`، `if`، `?:`، `+`، `-`،
`*`، `/`، `%`، `min`، `max` و `cat` استفاده کند. `message` روی `field` (یک ویژگی از
آن نوع) یا روی مدخل گزارش می‌شود. این یک افزودهٔ Verdin است؛ Strapi معادلی برای آن ندارد.

## تفاوت‌ها با Strapi

- **کامپوننت‌ها به‌صورت JSON ذخیره می‌شوند**، در ردیف مدخل، نه در جدول‌های کامپوننت با جدول‌های
  اتصال. خواندن‌ها به join نیاز ندارند؛ در نتیجه، ویژگی‌های `password`، روابط چندریختی
  و روابط دوطرفه نمی‌توانند درون کامپوننت‌ها باشند، و `unique` آنجا اعمال نمی‌شود.
- **کامپوننت‌های populateشده کامل برمی‌گردند.** `populate` روی یک کامپوننت یا ناحیهٔ پویا
  همهٔ فیلدهای آن را برمی‌گرداند؛ نمی‌توانید مانند Strapi فیلدهای تودرتو را انتخاب کنید.
- **فایل‌های طرح‌وارهٔ سخت‌گیرانه.** کلیدهای ناشناخته و گزینه‌هایی که یک نوع نمی‌پذیرد خطا هستند، در حالی که
  Strapi آن‌ها را نادیده می‌گیرد. در `pluginOptions` فقط `i18n.localized` خوانده می‌شود؛ بقیه
  نادیده گرفته می‌شود.
- **`string`، `email` و `uid` حداکثر 255 نویسه دارند**، یعنی اندازهٔ ستون، به جای اینکه
  در پایگاه داده شکست بخورند.
- **`conditions`** (فیلدهای شرطی) مانند Strapi 5.17 کار می‌کنند: فیلدهای پنهان الزامی نیستند.
- **`validations`** مخصوص خود Verdin است.
- بقیه با Strapi v5 یکسان است: نام نوع‌ها، گزینه‌هایشان، مقدارهای `biginteger` به‌صورت
  رشته، نوشتن روابط با `connect`، `disconnect`، `set` و `position`، و قالب
  blocks.
