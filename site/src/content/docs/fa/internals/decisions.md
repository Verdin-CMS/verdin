این فهرست انتخاب‌های طراحی را که به Verdin شکل داده‌اند، به ترتیبی که گرفته شده‌اند، ثبت می‌کند تا پیش از پیشنهاد تغییر در کد ببینید چرا کد این‌گونه است. مدخل‌ها همان‌طور که نوشته شده‌اند نگه داشته می‌شوند، از جمله نام نقطه‌های عطف (M2 تا M4 نقطه‌های عطف پیش از نخستین نسخه‌ها هستند)؛ یک مدخل بعدی ممکن است مدخل قبلی را اصلاح کند، همان‌طور که 28 برای 1 این کار را می‌کند. وقتی تصمیمی می‌گیرید که در غیر این صورت کسی باید آن را با مهندسی معکوس از کد بیرون بکشد، یک ردیف جدید اضافه کنید.

| # | تصمیم | نتیجه | دلیل |
|---|---|---|---|
| 1 | کامپوننت‌ها: JSON در برابر جدول | **ستون JSON** ([ذخیره‌سازی](/fa/internals/storage/#کامپوننتها-و-ناحیههای-پویا-یک-ستون-json)) | join کمتر، انتشار و نسخه‌بندی ساده، مهاجرت‌های ساده‌تر. فیلتر روی کامپوننت‌های تکرارشونده نادر است؛ بعداً با تابع‌های JSON قابل افزودن است |
| 2 | کدگذاری JSON برای `decimal` | به‌طور پیش‌فرض **عدد**، و `api.decimal_as_string` به‌صورت اختیاری | سازگاری با Strapi پذیرش را به حداکثر می‌رساند؛ مقدارهای دقیق در صورت نیاز در دسترس‌اند |
| 3 | فرم‌های پنل مدیریت | **Signal Forms** | با پنل مدیریتی signal-محور و zoneless سازگار است؛ درخت‌های فرم پویا از طرح‌واره مشتق می‌شوند |
| 4 | زبان | **انگلیسی** برای کد، مستندات و commitها | دسترسی گسترده در جامعهٔ متن‌باز |
| 5 | سازگاری با REST در Strapi | **همان پارامترها و شکل پاسخ**؛ افزونه‌های مخصوص Verdin زیر `actions/` | فرانت‌اندها با کمترین تغییر مهاجرت می‌کنند |
| 6 | الگوریتم JWT مدیریت | HS256 | یک کلید محرمانهٔ واحد، ساده؛ اگر روزی تأییدکننده‌های خارجی پیدا شوند EdDSA |
| 7 | شناسهٔ سندها | ULID (26 نویسه) | قابل مرتب‌سازی و قابل حمل؛ شناسه‌های خود Strapi رشته‌های مبهم 24 نویسه‌ای‌اند و کلاینت‌ها هرگز آن‌ها را parse نمی‌کنند |
| 8 | محتوای snapshot | مدل فیزیکی، نه طرح‌واره | نسخه‌های بعدی می‌توانند از طرح‌واره‌ای بدون تغییر، جدول‌های جدید مشتق کنند |
| 9 | nullable بودن ویژگی‌ها | همیشه nullable؛ `required` هنگام انتشار بررسی می‌شود | پیش‌نویس‌ها می‌توانند ناقص باشند (رفتار Strapi v5)؛ افزودن فیلدهای الزامی امن است |
| 10 | اعمال `unique` | نمایهٔ یکتا روی `(column, locale, publication_state)` | بدون شرایط رقابتی؛ پیش‌نویس‌ها و نسخهٔ منتشرشدهٔ آن‌ها مقدار مشترک دارند |
| 11 | نام ستون وضعیت | `publication_state` | `state` نام رایجی برای ویژگی است |
| 12 | واژه‌های رزروشدهٔ SQL | همیشه شناسه‌ها را نقل‌قول کن | بدون فهرست سیاه دلبخواه برای نام ویژگی‌ها |
| 13 | ساخت DML | سازندهٔ خودمان به جای `sea-query` | جزئیات هر گویش غالب‌اند (NULLهای تایپ‌شده، collationها، قالب‌های SQLite)؛ یک لایهٔ انتزاع کمتر |
| 14 | نوشتن‌های بدون `?status=draft` | انتشار (رفتار REST در Strapi v5) | سازگاری کامل برای کلاینت‌های موجود |
| 15 | مقایسهٔ متن | به‌طور پیش‌فرض دقیق روی همهٔ موتورها؛ عملگرهای `…i` برای حالت غیرحساس به بزرگی و کوچکی حروف | نتیجهٔ یکسان در MySQL و PostgreSQL |
| 16 | کنترل دسترسی موقت (M2–M3) | کلید `[api].open_access`، در M4 حذف شد | امن به‌طور پیش‌فرض تا زمانی که مجوزها وجود داشتند |
| 17 | «مقصد به یک سند تعلق دارد» | با جابه‌جا کردن مقصد، برای هر وضعیت، اعمال می‌شود | یک نمایهٔ یکتا مانع اشتراک یک مقصد بین پیش‌نویس و نسخهٔ منتشرشدهٔ آن می‌شد |
| 18 | سمت‌های معکوس (`mappedBy`) | فقط‌خواندنی | نوشتن از طریق آن‌ها با پیش‌نویس و انتشار مبهم است (کدام نسخهٔ مالک؟) |
| 19 | موقعیت پیوندها | در هر نوشتن از 1 تا n دوباره شماره‌گذاری می‌شوند | تمام شدن دقت اعشاری رخ نمی‌دهد؛ فهرست‌ها کوچک‌اند |
| 20 | ردیف‌های جدول پیوند | یک کلید اصلی `id` نگه دار | جدول‌های یکنواخت برای موتور مهاجرت و بازسازی‌های SQLite |
| 21 | کتابخانهٔ JWT | HS256 خودمان (HMAC-SHA256، تأیید در زمان ثابت، `alg` ثابت) | `jsonwebtoken` 11 به یک backend رمزنگاری نیاز دارد که RSA را وارد می‌کند |
| 22 | جدول‌های پلتفرم | همراه با مدل محتوا مشتق می‌شوند | یک سازوکار مهاجرت برای همه‌چیز |
| 23 | استفادهٔ دوباره از توکن refresh | کل خانواده را باطل کن، بدون بازهٔ ارفاق | ساده و سخت‌گیرانه؛ مدیر دوباره وارد می‌شود |
| 24 | پیش‌نویس‌ها از طریق API محتوا | مجوز جداگانهٔ `readDrafts` | توکن‌هایی که محتوای منتشرشده را می‌خوانند پیش‌نویس‌ها را نشت نمی‌دهند |
| 25 | ترتیب اعمال در سازنده | مهاجرت، سپس نوشتن فایل‌ها، سپس جایگزینی داغ برنامه | یک مهاجرت ناموفق فایل‌ها و برنامهٔ در حال اجرا را دست‌نخورده باقی می‌گذارد |
| 26 | نوشتن‌های پنل مدیریت | فقط ذخیرهٔ پیش‌نویس؛ انتشار یک کنش صریح است | با انتظار ویرایشگران جور است؛ API محتوا انتشار پیش‌فرض Strapi را حفظ می‌کند |
| 27 | پیکربندی زمان اجرای پنل مدیریت | تگ `<meta>`، نه اسکریپت درون‌خطی | CSP را از اسکریپت‌های `unsafe-inline` پاک نگه می‌دارد |
| 28 | فیلتر روی فیلدهای کامپوننت | عملگرهای مسیر JSON برای هر گویش (`#>>`، `JSON_VALUE`، `json_extract`)؛ `EXISTS` روی آیتم‌های آرایه برای کامپوننت‌های تکرارشونده و ناحیه‌های پویا (0.8) | ناحیه‌های پویا فقط با `__component`: آیتم‌هایشان فیلدهای متفاوتی دارند |
| 29 | i18n پنل مدیریت | Transloco با کاتالوگ‌های JSON تخت (`admin/public/i18n`) و ICU MessageFormat از طریق FormatJS (یک transpiler سفارشی)، پشت یک facade کوچک به نام `I18n`؛ نه i18n زمان کامپایل Angular | تغییر زبان در زمان اجرا؛ فایل‌های استاندارد برای Weblate/Crowdin؛ FormatJS پیام‌ها را تفسیر می‌کند، پس CSP سخت‌گیرانه به `unsafe-eval` نیاز ندارد (`@messageformat/core` با `new Function` کامپایل می‌کند)؛ کلیدها از `en.json` تایپ می‌شوند و کامل بودن با `npm run i18n:check` بررسی می‌شود |
| 30 | آغاز هفته | `Intl.Locale#getWeekInfo` از تگ منطقه‌ای مرورگر (en-GB ≠ en-US)، جدول منطقه‌ها به‌عنوان جایگزین، بازنویسی توسط کاربر | از منطقهٔ هر کاربر پیروی می‌کند، حتی وقتی زبان UI مشترک است |
| 31 | ذخیرهٔ چیدمان داشبورد | ستون JSON به نام `preferences` برای هر کاربر در `vd_admin_users` (≤ 64 KiB) | در مرورگرهای مختلف همراه کاربر است؛ پوسته و زبان در `localStorage` می‌مانند چون پیش از ورود اعمال می‌شوند |
| 32 | پیش‌فرض `Secure` برای کوکی refresh | در `start` روشن، در `dev` خاموش، قابل بازنویسی | `verdin dev` روی HTTP ساده در همهٔ مرورگرها کار می‌کند؛ production سخت‌گیرانه می‌ماند |
| 33 | پروفایل release | Thin LTO، 1 codegen unit، strip‌شده؛ unwinding حفظ می‌شود | یک handler که panic می‌کند نباید سرور را از کار بیندازد |
| 34 | سندهای «دیده‌نشده» | ردیف‌های `vd_document_views` برای هر کاربر، که وقتی سند تغییر می‌کند برای همه به جز ویرایشگر حذف می‌شوند؛ با `NOT EXISTS` در SQL فیلتر می‌شوند | صفحه‌بندی و شمارش‌ها دقیق می‌مانند؛ مُهر زمانی برای مقایسه در هر ردیف لازم نیست |
| 35 | رأی‌ها و نظرسنجی‌ها | جدول‌های همکاری فقط برای مدیران (`vd_document_votes`، `vd_polls`، `vd_poll_votes`)، برای هر نوع محتوا | صندوق پیشنهادها و تصمیم‌های تیمی بدون مدل کردن فیلدهای رأی در هر طرح‌واره |
| 36 | ذخیره‌سازی رسانه | `object_store` برای محلی و S3 | یک مسیر کد؛ بارگذاری‌های multipart به‌صورت جریانی؛ RustFS در پشتهٔ توسعه و CI |
| 37 | پیوندهای رسانه | جدول‌های پیوند برای هر فیلد، مانند روابط | همان معناشناسی پیش‌نویس و انتشار روابط؛ cascadeها پیوندها را سازگار نگه می‌دارند |
| 38 | ارتقای مجوزهای داخلی | نشانگر نسخه در `vd_settings`، افزوده‌ها یک بار اعمال می‌شوند | نصب‌های موجود مجوزهای جدید را می‌گیرند بدون اینکه ویرایش‌های بعدی مدیر لغو شوند |
| 39 | قابلیت‌های زمان اجرا | کاتالوگ در `verdin-api`، کلیدها در `vd_settings` (`features`)، برنامه در هر حالت در جای خود بازسازی می‌شود (ArcSwap) | کلیدهای افزونه به سبک Strapi بدون راه‌اندازی دوباره؛ قابلیت‌های در دسترس نبوده با نسخهٔ برنامه‌ریزی‌شده‌شان فهرست می‌شوند |
| 40 | UI مرجع API | Scalar (`scalar_api_reference`، bundle جاسازی‌شده) در `{api}/docs`، فقط وقتی سند عمومی است؛ CSP بوت‌استرپ درون‌خطی آن را با hash مجاز می‌کند | خودمیزبان (بدون CDN، فونت، عامل هوش مصنوعی یا telemetry)؛ سند به‌طور پیش‌فرض فقط با توکن در دسترس می‌ماند |
| 41 | GraphQL | طرح‌وارهٔ پویای `async-graphql` که همراه برنامه ساخته می‌شود؛ آرگومان‌ها و انتخاب‌ها به درخت پارامتر REST ترجمه و با همان parser کوئری parse می‌شوند | یک مجموعه قاعده برای فیلترها، صفحه‌بندی، populate، اعتبارسنجی و مجوزها در REST و GraphQL؛ populate مشتق از انتخاب، بارگذاری دسته‌ای را حفظ می‌کند |
| 42 | رویدادهای سند | شنونده‌ها روی Document Service، پس از commit فراخوانی می‌شوند | اثرات جانبی (نشانه‌های دیده‌شدن، وب‌هوک‌های آینده) بدون هوک برای هر handler روی همهٔ APIها اعمال می‌شوند |
