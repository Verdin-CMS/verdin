وقتی قابلیت **بلادرنگ** روشن باشد، Verdin هر بار که یک مدخل یا یک فایل رسانه تغییر می‌کند،
رویداد کوچکی را در یک جریان (stream) می‌فرستد. فرانت‌اند در این جریان مشترک می‌شود و آنچه
تغییر کرده را دوباره دریافت می‌کند: یک بلاگ زنده، یک جدول امتیاز، داشبوردی که هرگز به بارگذاری
دوباره نیاز ندارد. هر مشترک فقط رویدادهای مربوط به محتوایی را دریافت می‌کند که اجازهٔ خواندنش
را دارد.

این صفحه نشان می‌دهد چگونه از جریان در فرانت‌اند استفاده کنید. نام رویدادها، محتوای آن‌ها و
قواعد در [مرجع API بلادرنگ](/fa/api/realtime/) آمده است. Strapi v5 معادل داخلی ندارد.

## روشن کردن

<Steps>

1. در **تنظیمات ← قابلیت‌ها**، **بلادرنگ** را روشن کنید.
2. تصمیم بگیرید چه کسی مشترک می‌شود. جریان از مجوزهای content API استفاده می‌کند:
   - برای همه، **یافتن** یا **یافتن یکی** را روی نوع‌ها در **تنظیمات ← دسترسی عمومی** مجاز کنید؛
   - برای یک سرور یا یک برنامه، یک [توکن API](/fa/guides/auth/api-tokens/) با همین مجوزها بسازید
     (و **خواندن پیش‌نویس‌ها** را برای دریافت رویدادهای مخصوص پیش‌نویس)؛
   - برای کاربران نهایی واردشده، JWT آن‌ها هم کار می‌کند ([کاربران نهایی](/fa/guides/auth/end-users/) را ببینید).

</Steps>

جریان `GET /api/_events` است. برای دریافت فقط برخی نوع‌ها، `?types=` را با فهرستی از uid
نوع‌های محتوا که با ویرگول جدا شده‌اند اضافه کنید (`plugin::upload` کتابخانهٔ رسانه است):

```sh title="Terminal"
curl -N "https://cms.example.com/api/_events?types=api::article,api::category"
```

## اشتراک از مرورگر

رویدادها شناسه‌ها را حمل می‌کنند، نه محتوا را. با هر رویداد، آنچه نمایش می‌دهید را از طریق
همان API و همان مجوزهای هر خواندن دیگری دوباره دریافت کنید.

<Tabs syncKey="auth">
<TabItem label="عمومی">

با نقش عمومی، `EventSource` مرورگر کافی است و خودش دوباره وصل می‌شود:

```js
const CMS = 'https://cms.example.com';
const events = new EventSource(`${CMS}/api/_events?types=api::article`);

for (const name of ['entry.publish', 'entry.unpublish', 'entry.delete']) {
  events.addEventListener(name, (event) => {
    const { documentId } = JSON.parse(event.data);
    refreshArticle(documentId);
  });
}

events.addEventListener('lagged', () => refreshEverything());
```

</TabItem>
<TabItem label="با توکن">

`EventSource` نمی‌تواند سرآیند `Authorization` بفرستد. به‌جای آن جریان را با `fetch` بخوانید و
وقتی تمام شد دوباره وصل شوید:

```js
async function subscribe(token, onEvent) {
  for (;;) {
    try {
      const response = await fetch(`${CMS}/api/_events?types=api::article`, {
        headers: { authorization: `Bearer ${token}` },
      });
      if (response.status === 401 || response.status === 403) return; // token refused
      const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
      let buffer = '';
      for (;;) {
        const { value, done } = await reader.read();
        if (done) break;
        buffer += value;
        let end;
        while ((end = buffer.indexOf('\n\n')) >= 0) {
          const block = buffer.slice(0, end);
          buffer = buffer.slice(end + 2);
          const name = block.match(/^event: (.*)$/m)?.[1];
          const data = block.match(/^data: (.*)$/m)?.[1];
          if (name && data) onEvent(name, JSON.parse(data));
        }
      }
    } catch {
      // network error: retry below
    }
    await new Promise((resolve) => setTimeout(resolve, 2000));
  }
}
```

هر کتابخانهٔ کلاینت SSE که از سرآیندها پشتیبانی کند هم کار می‌کند.

</TabItem>
</Tabs>

<Aside type="caution">
توکنی که در کد مرورگر باشد برای هر کسی که صفحه را باز کند خواناست. فقط یک توکن فقط‌خواندنی
محدود به نوع‌هایی که صفحه نمایش می‌دهد منتشر کنید، یا از سرور خود مشترک شوید و به‌روزرسانی‌ها
را به مرورگر برسانید.
</Aside>

فراخوانی جریان از سایتی روی origin دیگر نیاز دارد که آن origin در
[`[api].cors_origins`](/fa/reference/configuration/) باشد.

## سالم نگه داشتن جریان

- اولین رویداد `ready` است: اشتراک فعال شده است.
- هر جریان پس از یک ساعت تمام می‌شود. آن وقت دوباره وصل شوید: `EventSource` این کار را خودکار
  انجام می‌دهد، و اتصال دوباره توکن را هم دوباره بررسی می‌کند؛ بنابراین توکن باطل‌شده دیگر
  رویدادی دریافت نمی‌کند.
- رویدادی با نام `lagged` یعنی کلاینت خیلی کند خوانده و رویدادهایی را از دست داده است. همهٔ
  آنچه صفحه نمایش می‌دهد را دوباره دریافت کنید.
- رویدادهای مخصوص پیش‌نویس (`entry.create`، `entry.update` و `entry.discard-draft` روی نوع‌های
  دارای پیش‌نویس و انتشار) فقط به فراخواننده‌هایی با **خواندن پیش‌نویس‌ها** می‌رسند. یک سایت
  عمومی معمولاً به `entry.publish`، `entry.unpublish` و `entry.delete` گوش می‌دهد.

## پشت load balancer

با چند نمونه، گذرگاه رویداد مشترک (`[cluster].bus = "database"`) را روشن کنید: آن‌وقت کلاینتی که به
هر نمونه‌ای وصل است رویدادهای همهٔ نمونه‌ها را دریافت می‌کند. بدون آن، رویدادها مربوط به همان نمونه‌ای
هستند که کلاینت به آن وصل است؛ برای `/api/_events` از sticky session استفاده کنید، یا کلاینت‌های بلادرنگ را
به یک نمونهٔ واحد هدایت کنید. [مقیاس‌پذیری](/fa/deploy/scaling/#گذرگاه-رویداد-مشترک) را ببینید.

پنل مدیریت برای به‌روزرسانی‌های زنده، حضور کاربران و قفل‌های نرم هنگام ویرایش از جریان مخصوص
خود (`/admin/api/events`) استفاده می‌کند؛ [مرجع API بلادرنگ](/fa/api/realtime/) را ببینید.
