قابلیت **فرم‌ها** فرم‌های سایت شما (تماس، عضویت در خبرنامه، ثبت‌نام در رویداد) را بدون
سرویس فرم جداگانه مدیریت می‌کند. ویراستاران فیلدها را در پنل مدیریت تعریف می‌کنند، سایت
شما آن‌ها را نمایش می‌دهد و به Verdin ارسال می‌کند، و ارسالی‌ها اعتبارسنجی، ذخیره و ایمیل
می‌شوند و به‌صورت CSV قابل خروجی گرفتن هستند.

## روشن کردن

در **تنظیمات ← قابلیت‌ها**، **فرم‌ها** را روشن کنید و سپس **مدیریت فرم‌ها** را انتخاب کنید (یا
به **تنظیمات ← فرم‌ها** بروید). مدیریت فرم‌ها و خواندن ارسالی‌ها به مجوز
**مدیریت SEO، تغییرمسیرها، منوها و فرم‌ها** (`site.manage`) نیاز دارد که نقش داخلی
Editor آن را دارد. [مجوزها](/fa/reference/permissions/) را ببینید.

برای ایمیل‌های اطلاع‌رسانی، یک ارائه‌دهنده را در [`[email]`](/fa/reference/configuration/)
پیکربندی کنید؛ با ارائه‌دهندهٔ پیش‌فرض `log`، ایمیل‌ها فقط در لاگ سرور نوشته می‌شوند.

## ساخت یک فرم

<Steps>

1. در **تنظیمات ← فرم‌ها**، **فرم جدید** را انتخاب کنید.
2. به آن یک نام (مثلاً **تماس**) و یک **Slug** (`contact`) بدهید. Slug بخشی از
   نشانی فرم است.
3. در زبانهٔ **فیلدها**، برای هر فیلد **افزودن فیلد** را انتخاب کنید و **برچسب**،
   **نام**، **نوع**، **الزامی**، **جانگهدار** و **حداکثر طول** آن را تعیین کنید.
4. در زبانهٔ **تنظیمات**، این موارد را تنظیم کنید:
   - **اطلاع‌رسانی**: نشانی‌های ایمیلی که هر ارسالی را دریافت می‌کنند.
   - **پیام موفقیت**: پس از هر ارسال به سایت شما برگردانده می‌شود.
   - **تلهٔ هرزنامه**: به‌طور پیش‌فرض روشن است (بخش [هرزنامه](#هرزنامه) را ببینید).
5. ذخیره کنید. زبانهٔ **یکپارچه‌سازی** نقطهٔ پایانی عمومی و یک نمونه برای کپی کردن را نشان می‌دهد.

</Steps>

| نوع | برچسب در پنل مدیریت | چه چیزی می‌پذیرد |
| --- | --- | --- |
| `text` | **متن** | هر متنی. |
| `email` | **ایمیل** | یک نشانی ایمیل. |
| `textarea` | **متن بلند** | هر متنی. |
| `number` | **عدد** | یک عدد که به‌صورت عدد ذخیره می‌شود. |
| `select` | **گزینه‌ای** | یکی از **گزینه‌ها**ی آن (هر کدام در یک خط). |
| `checkbox` | **چک‌باکس** | `true`، `on`، `1` یا `yes` یعنی علامت‌خورده؛ هر چیز دیگری یعنی نه. چک‌باکس الزامی باید علامت بخورد. |
| `date` | **تاریخ** | هر متنی (از `<input type="date">` استفاده کنید). |
| `url` | **نشانی** | یک URL. |
| `tel` | **تلفن** | هر متنی. |

نام فیلدها با یک حرف شروع می‌شود و پس از آن حروف، ارقام یا `_` می‌آید، و در فرم یکتاست.
هر فرم 1 تا 50 فیلد دارد. طول مقادیر حداکثر به اندازهٔ **حداکثر طول** نویسه است (به‌طور
پیش‌فرض 5,000 و حداکثر 20,000).

## نمایش فرم

`GET /api/_forms/{slug}` تعریف فرم را برمی‌گرداند تا سایت شما بتواند فیلدهایی را که
ویراستاران انتخاب کرده‌اند نمایش دهد:

```json
{
  "data": {
    "slug": "contact",
    "name": "Contact",
    "fields": [
      { "name": "email", "label": "Email", "type": "email", "required": true },
      { "name": "message", "label": "Message", "type": "textarea", "required": true, "maxLength": 2000 },
      { "name": "topic", "label": "Topic", "type": "select", "options": ["Sales", "Support"] }
    ],
    "honeypot": "_gotcha"
  }
}
```

وقتی تلهٔ هرزنامه خاموش باشد، `honeypot` برابر `null` است. تعریف فرم یک دقیقه کش می‌شود
(`Cache-Control: public, max-age=60`).

## ارسال

`POST /api/_forms/{slug}` مقادیر را به‌صورت JSON (خود فیلدها، یا `{ "data": { … } }`) یا
به‌صورت ارسال سادهٔ فرم (`application/x-www-form-urlencoded`) می‌پذیرد. به توکن نیازی نیست.

<Tabs syncKey="form">
<TabItem label="HTML form">

```html
<form method="post" action="https://cms.example.com/api/_forms/contact">
  <input name="email" type="email" required />
  <textarea name="message" required maxlength="2000"></textarea>
  <input name="_gotcha" tabindex="-1" autocomplete="off" aria-hidden="true" style="position:absolute;left:-9999px" />
  <button>Send</button>
</form>
```

</TabItem>
<TabItem label="fetch">

```js
const response = await fetch('https://cms.example.com/api/_forms/contact', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ data: { email, message, _gotcha: '' } }),
});
const body = await response.json();
if (response.ok) showThanks(body.data.message);
else showErrors(body.error.details.errors); // [{ path: ['email'], message: 'must be an email address' }]
```

</TabItem>
</Tabs>

| پاسخ | چه زمانی |
| --- | --- |
| `201` با `{ "data": { "message": … } }` | پذیرفته شد. `message` همان **پیام موفقیت** است، یا `Thank you!`. |
| `400` `ValidationError` | مقداری وجود ندارد یا نامعتبر است. `details.errors` برای هر فیلد `{ path, message }` را فهرست می‌کند. |
| `404` | فرمی با این slug وجود ندارد، یا قابلیت خاموش است. |
| `413` | حجم ارسالی بیش از 64 KB است. |
| `429` | یک بازدیدکننده در یک دقیقه بیش از 10 ارسال به این فرم داشته است. |

فاصله‌های ابتدا و انتهای مقادیر حذف و مقادیر با فیلدها مقایسه می‌شوند. فیلدهای ناشناخته
کنار گذاشته می‌شوند، بنابراین بازدیدکننده نمی‌تواند داده‌ای اضافه کند که شما نخواسته‌اید.

ارسال سادهٔ فرم HTML پاسخ JSON را به‌عنوان صفحه دریافت می‌کند. برای تجربهٔ بهتر، با
`fetch` ارسال کنید و پیام را خودتان نمایش دهید. ارسال از مرورگر به یک origin دیگر نیاز دارد
که origin سایت شما در [`[api].cors_origins`](/fa/reference/configuration/) باشد.

### هرزنامه

وقتی **تلهٔ هرزنامه** روشن است، یک فیلد پنهان و خالی `_gotcha` به فرم اضافه کنید. ربات‌ها
همهٔ فیلدها را پر می‌کنند؛ ارسالی‌ای که `_gotcha` آن پر شده باشد، پاسخ «پذیرفته شد» (`201`)
می‌گیرد و دور ریخته می‌شود، بنابراین ربات چیزی نمی‌فهمد. این روش همراه با محدودیت نرخ، بیشتر
هرزنامه‌های فرم را بدون CAPTCHA متوقف می‌کند.

## خواندن ارسالی‌ها

زبانهٔ **ارسالی‌ها**ی فرم آنچه بازدیدکنندگان فرستاده‌اند را همراه با زمان **دریافت‌شده**
فهرست می‌کند. می‌توانید یک ارسالی را حذف کنید، و **خروجی CSV** همه را دانلود می‌کند.

هر ارسالی پذیرفته‌شده همچنین به نشانی‌های **اطلاع‌رسانی** ایمیل می‌شود، همراه با پیوندی به
ارسالی‌ها در پنل مدیریت (که از [`[server].public_url`](/fa/reference/configuration/) ساخته می‌شود).

<Aside type="note">
Verdin مقادیر هر ارسالی، user agent بازدیدکننده و یک هش کلیددار از نشانی IP او (نه خود
نشانی) را ذخیره می‌کند؛ این برای تشخیص سیل ارسال‌ها کافی است، بدون اینکه افراد ردیابی شوند.
حذف یک فرم ارسالی‌های آن را هم حذف می‌کند.
</Aside>

## Admin API

پنل مدیریت از `/admin/api/site/forms` و `/admin/api/site/forms/{id}`، به‌علاوهٔ
`/admin/api/site/forms/{id}/submissions` و `…/submissions/export` (CSV) استفاده می‌کند، با
توکن دسترسی یک مدیر و مجوز `site.manage`. [Admin API](/fa/api/admin/) را ببینید.
