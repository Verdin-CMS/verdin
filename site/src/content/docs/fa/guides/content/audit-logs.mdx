گزارش‌های حسابرسی ثبت می‌کنند چه کسی چه چیزی را و چه زمانی تغییر داده است: محتوا، رسانه،
ورودها و هر تغییری که در پنل مدیریت انجام شده باشد. این راهنما نشان می‌دهد چه چیزی ثبت می‌شود،
چگونه گزارش‌ها را فیلتر کنید و چه مدت نگهداری می‌شوند.

گزارش‌های حسابرسی در Strapi یک قابلیت Enterprise هستند. در Verdin بخشی از هستهٔ متن‌باز‌اند.

## پیش از شروع

- **تنظیمات ← قابلیت‌ها ← گزارش‌های حسابرسی** به‌طور پیش‌فرض روشن است. خاموش کردن آن ثبت
  اقدامات جدید را متوقف می‌کند؛ مدخل‌های موجود همچنان قابل خواندن می‌مانند.
- خواندن گزارش‌ها به **خواندن گزارش‌های حسابرسی** (`audit.read`) نیاز دارد.
  [مجوزها](/fa/reference/permissions/) را ببینید.

## چه چیزی ثبت می‌شود

| حوزه | اقدامات | توضیحات |
| --- | --- | --- |
| محتوا | `entry.create`، `entry.update`، `entry.publish`، `entry.unpublish`، `entry.discard-draft`، `entry.delete` | از همهٔ APIها: پنل مدیریت، REST، GraphQL و افزونه‌ها. زبان در جزئیات آمده است. |
| گردش‌کارهای بازبینی | `entry.stage`، `entry.assign` | تغییر مرحله‌ها و واگذاری‌ها. |
| رسانه | `media.create`، `media.update`، `media.delete` | بارگذاری، تغییر و حذف فایل‌ها. نام فایل در جزئیات آمده است. |
| ورودها | `admin.login` | ورود با رمز عبور و ورود اولین مدیر (اگر حساب عامل دوم داشته باشد، پس از عامل دوم ثبت می‌شود)، و ورودهای SSO همراه با ارائه‌دهنده. |
| تغییرات مدیریتی | `{METHOD} {route}`، برای مثال `PUT /roles/{id}` | هر نوشتن موفق روی admin API: کاربران، نقش‌ها، توکن‌های API، تنظیمات، قابلیت‌ها، وب‌هوک‌ها، زبان‌ها، افزونه‌ها، بسته‌های انتشار… پارامترهای مسیر در جزئیات آمده است. |

هر مدخل یک زمان، یک انجام‌دهنده، یک اقدام، یک موضوع (uid یک نوع محتوا، `plugin::upload.file`
یا منبع مدیریتی مانند `roles`)، شناسهٔ موضوع، جزئیات و، برای درخواست‌ها، نشانی IP کلاینت دارد.

انجام‌دهنده یکی از این‌هاست:

- **مدیر**: یک مدیر واردشده که نامش در گزارش آمده است.
- **API**: تغییری که از طریق content API یا GraphQL انجام شده، با یک توکن API، توکن یک کاربر
  نهایی یا دسترسی عمومی.
- **سیستم**: یک نوشتن روی admin API بدون مدیر واردشده.

پشت یک reverse proxy، `[server].trusted_proxies` را تنظیم کنید تا گزارش‌ها نشانی کلاینت را
به‌جای نشانی proxy نشان دهند. [مرجع پیکربندی](/fa/reference/configuration/) را ببینید.

## فیلتر کردن گزارش‌ها

<Steps>

1. **تنظیمات ← گزارش‌های حسابرسی** را باز کنید.
2. از یک پیش‌تنظیم **فیلترهای سریع** (**محتوا**، **رسانه**، **ورودها**) استفاده کنید، یا
   فیلترها را پر کنید:
   - **اقدام**: یک اقدام دقیق مانند `entry.publish`، یا پیشوندی که به `*` ختم می‌شود، مانند
     `entry.*`.
   - **انجام‌دهنده**: یک مدیر، یا **هر کسی**.
   - **موضوع**: uid یک نوع محتوا مانند `api::article`.
   - **از** و **تا**: یک بازهٔ تاریخ. تاریخی بدون ساعت کل آن روز را شامل می‌شود.
3. **اعمال** را انتخاب کنید. **جزئیات** را روی یک ردیف باز کنید تا همهٔ آنچه برای آن ثبت شده را ببینید.

</Steps>

## کوئری گرفتن از API

```sh title="Terminal"
curl -G 'http://localhost:1337/admin/api/audit-logs' \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  --data-urlencode 'action=entry.*' \
  --data-urlencode 'subject=api::article' \
  --data-urlencode 'actor=3' \
  --data-urlencode 'from=2026-09-01' \
  --data-urlencode 'to=2026-09-30' \
  --data-urlencode 'page=1' --data-urlencode 'pageSize=50'
```

مدخل‌ها از جدیدترین به قدیمی‌ترین می‌آیند، به‌طور پیش‌فرض 50 مدخل در هر صفحه و حداکثر 200:

```json
{
  "data": [
    {
      "id": 812,
      "at": "2026-09-28T14:03:11.000Z",
      "action": "entry.publish",
      "subject": "api::article",
      "subjectId": "k3v9…",
      "details": { "locale": "fr" },
      "ip": null,
      "actor": { "kind": "admin", "id": 3, "email": "ana@example.com", "name": "Ana Ruiz" }
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 50, "total": 1, "pageCount": 1 } }
}
```

`from` و `to` تاریخ یا تاریخ‌وزمان ISO 8601 می‌پذیرند؛ هر چیز دیگری خطای `400` است.

## تعیین مدت نگهداری مدخل‌ها

مدخل‌های قدیمی‌تر از `[audit].retention_days` روزی یک بار حذف می‌شوند. پیش‌فرض 90 روز است.

```toml title="verdin.toml"
[audit]
retention_days = 365
```

<Aside type="tip">
برای نگه داشتن مدخل‌های حسابرسی بیش از مدتی که پایگاه داده‌تان باید نگه دارد، آن‌ها را به‌طور
منظم با API بالا در ذخیره‌سازی خودتان کپی کنید.
</Aside>
