گردش‌کار بازبینی فهرستی مرتب از مراحل است، مانند *برای انجام*، *در حال بازبینی* و *آماده*، که
مدخل‌های برخی نوع‌های محتوا پیش از انتشار از آن‌ها عبور می‌کنند. این راهنما یک گردش‌کار
راه‌اندازی می‌کند، مدخل‌ها را جابه‌جا و واگذار می‌کند، و admin API مربوط را نشان می‌دهد.

در Strapi، گردش‌کارهای بازبینی یک قابلیت Enterprise هستند. در Verdin بخشی از هستهٔ متن‌باز‌اند.

## پیش از شروع

- **تنظیمات ← قابلیت‌ها ← گردش‌کارهای بازبینی** را روشن کنید. به‌طور پیش‌فرض خاموش است.
- راه‌اندازی گردش‌کارها به **مدیریت گردش‌کارهای بازبینی** (`workflows.manage`) نیاز دارد.
- جابه‌جا کردن و واگذاری یک مدخل به دسترسی به‌روزرسانی آن نیاز دارد.
  [مجوزها](/fa/reference/permissions/) را ببینید.

## ساخت یک گردش‌کار

<Steps>

1. **تنظیمات ← گردش‌کارهای بازبینی** را باز کنید و **گردش‌کار جدید** را انتخاب کنید.
2. به آن یک **نام** بدهید.
3. زیر **انواع محتوا**، نوع‌هایی را که مدخل‌هایشان از آن پیروی می‌کنند انتخاب کنید. هر نوع حداکثر
   از یک گردش‌کار پیروی می‌کند.
4. زیر **مراحل**، مراحل را به ترتیب فهرست کنید. هر کدام یک **نام مرحله** و یک **رنگ** دارد. برای
   مراحل بیشتر از **افزودن مرحله** و برای تغییر ترتیب از دکمه‌های پیکان استفاده کنید. مدخل‌های
   جدید از مرحلهٔ اول شروع می‌کنند.
5. در صورت تمایل، روی یک مرحله **نقش‌هایی که می‌توانند مدخل‌ها را به این مرحله ببرند** را انتخاب
   کنید. اگر نقشی انتخاب نشود، هر کسی که بتواند مدخل را به‌روزرسانی کند می‌تواند.
6. در صورت تمایل، **مرحلهٔ لازم برای انتشار** را تنظیم کنید. در این صورت مدخل‌ها فقط وقتی در آن
   مرحله باشند قابل انتشارند. **هر مرحله‌ای** انتشار را بدون محدودیت می‌گذارد.
7. ذخیره کنید.

</Steps>

مدخل‌هایی که پیش از پیوستن نوعشان به گردش‌کار وجود داشتند، در مرحلهٔ اول قرار می‌گیرند.

وقتی بعداً یک گردش‌کار را تغییر می‌دهید:

- حذف یک مرحله مدخل‌های آن را به مرحلهٔ اول برمی‌گرداند.
- حذف یک نوع محتوا از گردش‌کار، مراحل مدخل‌های آن را پاک می‌کند.
- حذف گردش‌کار، مراحل و مسئولان مدخل‌هایش را پاک می‌کند.

## جابه‌جا کردن و واگذاری مدخل‌ها

ویرایشگر مدخل یک پنل **بازبینی** با **مرحله** و **مسئول** نشان می‌دهد.

- برای جابه‌جا کردن مدخل، **مرحله** دیگری را برگزینید. مراحلی که برای نقش‌های دیگر رزرو شده‌اند
  قابل انتخاب نیستند و پنل این را اعلام می‌کند. مدیرانی که **مدیریت گردش‌کارهای بازبینی** دارند
  همیشه می‌توانند مدخل‌ها را جابه‌جا کنند.
- یک **مسئول** از میان مدیران فعالی که می‌توانند نوع محتوا را بخوانند برگزینید، یا **حذف مسئول**
  را انتخاب کنید. هر کسی که بتواند مدخل را به‌روزرسانی کند می‌تواند آن را واگذار کند.
- وقتی گردش‌کار مرحلهٔ الزامی دارد، پنل می‌گوید مدخل پیش از کار کردن **انتشار** باید به کدام
  مرحله برسد.

نمای فهرست یک ستون **مرحله** نشان می‌دهد، و صفحهٔ خانه مدخل‌هایی را که به شما واگذار شده‌اند زیر
**واگذارشده به من** فهرست می‌کند. نوع‌های بومی‌سازی‌شده برای هر زبان یک مرحله نگه می‌دارند.

## مرحلهٔ انتشار چه چیزی را مسدود می‌کند

مرحلهٔ الزامی روی همهٔ راه‌های انتشار اعمال می‌شود: پنل مدیریت، REST، GraphQL، بسته‌های انتشار و
افزونه‌ها. انتشار مدخلی که بیرون از آن مرحله باشد با `400` شکست می‌خورد:

```text
the entry must be in the review stage `Ready` to be published
```

در Strapi الزام مرحله فقط روی پنل مدیریت اعمال می‌شود. نقش‌های مرحله هم متفاوت‌اند: در Verdin
محدود می‌کنند چه کسی مدخل‌ها را *به* یک مرحله می‌برد.

## گزارش‌های حسابرسی و وب‌هوک‌ها

- تغییر مرحله‌ها و واگذاری‌ها در [گزارش‌های حسابرسی](/fa/guides/content/audit-logs/) به‌صورت
  `entry.stage` و `entry.assign` ثبت می‌شوند.
- وب‌هوک‌ها می‌توانند در **مرحلهٔ مدخل تغییر کرد** (`review-workflows.updateEntryStage`) مشترک
  شوند. [وب‌هوک‌ها](/fa/guides/integrations/webhooks/) را ببینید.

## Admin API

همهٔ مسیرها زیر `/admin/api` هستند و یک توکن دسترسی مدیر می‌گیرند.

| مسیر | مجوز | کار |
| --- | --- | --- |
| `GET /review-workflows`، `GET /review-workflows/{id}` | `workflows.manage` | گردش‌کارها همراه با مراحلشان. |
| `POST /review-workflows`، `PUT /review-workflows/{id}` | `workflows.manage` | ایجاد یا جایگزینی یک گردش‌کار (بدنه در ادامه). |
| `DELETE /review-workflows/{id}` | `workflows.manage` | مدخل‌های نوع‌های آن مراحل خود را از دست می‌دهند. |
| `GET /content/{uid}/{documentId}/review?locale=` | خواندن مدخل | مرحله، مسئول، و مراحلی که می‌توانید مدخل را به آن‌ها ببرید (`canMoveTo`). |
| `PUT /content/{uid}/{documentId}/review?locale=` | به‌روزرسانی مدخل | `{ "stageId": 3, "assigneeId": 7 }`. هر دو فیلد اختیاری‌اند؛ `"assigneeId": null` مسئول را حذف می‌کند. |
| `GET /content/{uid}/review?documentIds=a,b` | خواندن نوع | مراحل حداکثر 200 مدخل، همراه با گردش‌کار در `meta.workflow`. |
| `GET /review/assigned` | واردشده | مدخل‌هایی که به شما واگذار شده‌اند. |
| `GET /review/assignees?uid=` | به‌روزرسانی نوع | مدیران فعالی که می‌توانند نوع را بخوانند. |
| `GET /review/roles` | `workflows.manage` | کدها و نام‌های نقش‌ها، برای نقش‌های مرحله. |

یک گردش‌کار، همان‌طور که به `POST` و `PUT` فرستاده می‌شود:

```json
{
  "name": "Editorial",
  "contentTypes": ["api::article"],
  "stages": [
    { "id": 1, "name": "To do", "color": "#4945ff" },
    { "id": 2, "name": "In review", "color": "#ff8800" },
    { "name": "Ready", "color": "#2f9e44", "roles": ["editor"] }
  ],
  "publishStage": "Ready"
}
```

- هر گردش‌کار 1 تا 50 مرحله با نام‌های یکتا و رنگ‌های `#rrggbb` دارد.
- `publishStage` نام یکی از مراحل است؛ برای نداشتن مرحلهٔ انتشار آن را حذف کنید.
- مراحل موجود را با `id` آن‌ها بفرستید تا مدخل‌هایشان سر جایشان بمانند. مراحل بدون `id` جدید هستند.

<Aside type="note">
خاموش کردن قابلیت مراحل را پنهان می‌کند و اعمال مرحلهٔ انتشار را متوقف می‌کند. گردش‌کارها و
مراحل مدخل‌ها برای زمانی که دوباره روشنش کنید نگه داشته می‌شوند.
</Aside>
