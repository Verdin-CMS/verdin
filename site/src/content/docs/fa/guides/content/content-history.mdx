Verdin هر بار که یک مدخل از هر APIای ایجاد، ذخیره، منتشر یا لغو انتشار شود یا پیش‌نویسش دور
انداخته شود، نسخه‌ای از آن نگه می‌دارد. این راهنما نشان می‌دهد چگونه یک نسخهٔ قدیمی را پیدا و
بازیابی کنید، چند نسخه نگهداری می‌شود، و admin API مربوط به آن را.

تاریخچهٔ محتوا مانند Strapi کار می‌کند، که در آنجا یک قابلیت پولی است.

## پیش از شروع

- **تنظیمات ← قابلیت‌ها ← تاریخچهٔ محتوا** به‌طور پیش‌فرض روشن است. تا وقتی خاموش باشد، هیچ
  نسخه‌ای ثبت نمی‌شود و تاریخچه در دسترس نیست.
- خواندن تاریخچهٔ یک مدخل به دسترسی خواندن آن مدخل نیاز دارد؛ بازیابی به دسترسی به‌روزرسانی
  نیاز دارد. محدودیت‌های فیلد اعمال می‌شوند: فقط فیلدهایی را می‌بینید و بازیابی می‌کنید که نقش
  شما اجازهٔ خواندن یا به‌روزرسانی آن‌ها را دارد. [مجوزها](/fa/reference/permissions/) را ببینید.

## بازیابی یک نسخه

<Steps>

1. مدخل را باز کنید و **تاریخچه** را انتخاب کنید.
2. فهرست **نسخه‌ها** هر نسخه را با رویداد آن (**ایجاد شد**، **ذخیره شد**، **منتشر شد**،
   **انتشار لغو شد**، **پیش‌نویس دور انداخته شد**)، تاریخ و سازنده‌اش نشان می‌دهد. برای
   تغییراتی که از طریق content API انجام شده‌اند، **API** به‌عنوان نویسنده نشان داده می‌شود.
3. یک نسخه را انتخاب کنید تا فیلدهای آن را ببینید.
4. **بازیابی** را انتخاب و تأیید کنید.

</Steps>

نسخه جایگزین پیش‌نویس فعلی می‌شود؛ هر وقت آماده بودید آن را منتشر کنید. در نوع‌های بدون
پیش‌نویس و انتشار، بازیابی مستقیماً مدخل را به‌روزرسانی می‌کند.

آنچه هنگام بازیابی کنار گذاشته می‌شود:

- فیلدهایی که دیگر در طرح‌واره وجود ندارند فهرست می‌شوند و بازیابی نمی‌شوند.
- ارجاع به مدخل‌ها یا فایل‌های حذف‌شده کنار گذاشته می‌شود و ویرایشگر به شما می‌گوید کدام
  فیلدها آن‌ها را از دست داده‌اند.

**بازگشت به ویرایشگر** بدون هیچ تغییری به مدخل برمی‌گردد.

## چند نسخه نگهداری می‌شود

Verdin جدیدترین `[history].max_versions` نسخه از هر مدخل و زبان را نگه می‌دارد (به‌طور پیش‌فرض
50) و با رسیدن نسخه‌های جدید، نسخه‌های قدیمی‌تر را حذف می‌کند:

```toml title="verdin.toml"
[history]
max_versions = 100
```

هر زبانِ یک مدخل بومی‌سازی‌شده تاریخچهٔ خودش را دارد. حذف یک مدخل، یا یکی از زبان‌های آن،
نسخه‌هایش را هم حذف می‌کند. [مرجع پیکربندی](/fa/reference/configuration/) را ببینید.

<Aside type="note">
برخلاف Strapi که تاریخچه را برای تعدادی روز نگه می‌دارد، Verdin تعدادی نسخه برای هر مدخل نگه
می‌دارد، هر قدر هم قدیمی باشند.
</Aside>

## Admin API

همهٔ مسیرها زیر `/admin/api` هستند.

| مسیر | مجوز | کار |
| --- | --- | --- |
| `GET /history/{uid}/{documentId}?locale=&page=&pageSize=` | خواندن مدخل | نسخه‌ها، از جدیدترین، بدون داده‌هایشان (20 در هر صفحه، حداکثر 100). |
| `GET /history/versions/{id}` | خواندن مدخل | یک نسخه همراه با داده‌هایش. |
| `POST /history/versions/{id}/restore` | به‌روزرسانی مدخل | نسخه را به‌عنوان پیش‌نویس فعلی بازیابی می‌کند. |

پاسخ بازیابی آنچه کنار گذاشته شده را فهرست می‌کند:

```json
{
  "data": {
    "documentId": "k3v9…",
    "restored": 42,
    "dropped": [{ "field": "tags", "count": 1 }]
  }
}
```

تا وقتی قابلیت خاموش باشد، مسیرها پاسخ `404` می‌دهند.
