یک نوع محتوای بومی‌سازی‌شده برای هر مدخل در هر زبان یک نسخه نگه می‌دارد. این راهنما زبان‌هایی
را که در آن‌ها منتشر می‌کنید اضافه می‌کند، بومی‌سازی را برای یک نوع روشن می‌کند، مدخل‌ها را در
پنل مدیریت ترجمه می‌کند و هر زبان را از طریق API می‌خواند یا می‌نویسد. برای مدل پشت آن (فیلدهای
مشترک، روابط بین نوع‌های بومی‌سازی‌شده)، [بین‌المللی‌سازی](/fa/concepts/internationalization/) را
ببینید.

بومی‌سازی بخشی از هسته است: قابلیتی برای روشن کردن ندارد. مانند افزونهٔ i18n در Strapi v5 کار
می‌کند و همان پارامتر `locale` را می‌پذیرد.

## پیش از شروع

- برای افزودن، تغییر نام یا حذف زبان‌ها به **مدیریت زبان‌ها** (`locales.manage`) نیاز دارید.
- برای بومی‌سازی‌شده کردن یک نوع، طرح‌وارهٔ آن را ویرایش می‌کنید، در **سازندهٔ نوع محتوا**
  (`verdin dev`) یا در `schema/content-types/<name>.json`.
- برای مجوزهای محتوایی که ویراستاران نیاز دارند، [مجوزها](/fa/reference/permissions/) را ببینید.

## افزودن زبان‌ها

اولین اجرا انگلیسی (`en`) را به‌عنوان زبان پیش‌فرض می‌سازد. درخواست‌هایی که زبانی مشخص نمی‌کنند
از زبان پیش‌فرض استفاده می‌کنند و مدخل‌های جدید در آن شروع می‌شوند.

<Steps>

1. **تنظیمات ← بین‌المللی‌سازی** را باز کنید و **افزودن زبان** را انتخاب کنید.
2. یک **کد** وارد کنید: کد زبان با حروف کوچک، در صورت نیاز همراه با منطقه یا خط، مانند
   `fr`، `pt-BR` یا `zh-Hans`. نام برای شما پر می‌شود و قابل تغییر است.
3. اگر درخواست‌های بدون زبان باید از آن استفاده کنند، **به‌عنوان زبان پیش‌فرض تنظیم شود** را
   علامت بزنید و سپس ذخیره کنید.

</Steps>

برای تغییر زبان پیش‌فرض در آینده، روی زبان دیگری **تنظیم به‌عنوان پیش‌فرض** را انتخاب کنید.
زبان پیش‌فرض قابل حذف نیست.

<Aside type="caution" title="حذف یک زبان مدخل‌های آن را حذف می‌کند">
حذف یک زبان همهٔ مدخل‌هایی را که به آن زبان نوشته شده‌اند، در همهٔ نوع‌های محتوا و از جمله
نسخه‌های منتشرشده، برای همیشه حذف می‌کند. پنجرهٔ تأیید از شما می‌خواهد کد زبان را برای تأیید
تایپ کنید.
</Aside>

## بومی‌سازی‌شده کردن یک نوع محتوا

در **سازندهٔ نوع محتوا**، نوع را باز کنید و در تنظیمات آن **بومی‌سازی‌شده** را روشن کنید. سپس
فیلد به فیلد تصمیم بگیرید کدام مقادیر در هر زبان متفاوت‌اند: فیلدی که **بومی‌سازی‌شده** آن
خاموش باشد، یک مقدار مشترک برای همهٔ زبان‌ها نگه می‌دارد.

همین کار در فایل طرح‌واره، برای نوع `article` پروژهٔ نمونه:

```json title="schema/content-types/article.json" {6,9}
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

فیلدهای مشترک این‌گونه رفتار می‌کنند:

- ذخیرهٔ یک فیلد مشترک در یک زبان، آن را در پیش‌نویس‌های همهٔ زبان‌ها می‌نویسد.
- انتشار یک زبان، فیلدهای مشترک آن را به نسخه‌های منتشرشدهٔ زبان‌های دیگر کپی می‌کند.
- روابط و فیلدهای رسانه هم می‌توانند مشترک باشند.

نوع‌هایی که `pluginOptions.i18n.localized` ندارند بومی‌سازی‌شده نیستند و پارامترهای `locale` را
نادیده می‌گیرند. تغییر بومی‌سازی یک نوع، تغییر طرح‌واره است: پیش از استقرار، مهاجرت را با
`verdin migrate plan` بازبینی کنید.

## ترجمهٔ یک مدخل در پنل مدیریت

<Steps>

1. مدخل را باز کنید و زبان مقصد را در انتخابگر **زبان** بالای ویرایشگر برگزینید. زبان‌هایی که
   نسخه‌ای ندارند **هنوز ایجاد نشده** را نشان می‌دهند.
2. ویرایشگر می‌گوید مدخل هنوز در آن زبان نسخه‌ای ندارد و ذخیره کردن آن را می‌سازد. فیلدهای
   مشترک از قبل مقادیر خود را نشان می‌دهند.
3. برای شروع از یک ترجمهٔ موجود، در همان پیام **پر کردن از زبان دیگر** را انتخاب کنید. منبع را
   در **کپی از** برگزینید و **کپی فیلدها** را انتخاب کنید. این کار فیلدهای بومی‌سازی‌شده، از
   جمله روابط و رسانه، را در فرم کپی می‌کند. هنوز چیزی ذخیره نشده است.
4. فیلدها را ویرایش کنید، سپس **ذخیرهٔ پیش‌نویس** یا **انتشار** را انتخاب کنید. هر زبان پیش‌نویس
   و نسخهٔ منتشرشدهٔ خود را دارد.

</Steps>

نمای فهرست هم همان انتخابگر **زبان** را دارد: در هر بار نسخه‌های یک زبان را فهرست می‌کند. حذف از
ویرایشگر فقط نسخهٔ زبان فعلی را حذف می‌کند؛ زبان‌های دیگر حفظ می‌شوند.

وقتی قابلیت **اقدامات هوش مصنوعی** روشن باشد، ویرایشگر می‌تواند فیلدهای متنی را از پیش‌نویس
زبان دیگری هم ترجمه کند. [اقدامات هوش مصنوعی](/fa/guides/integrations/ai-actions/) را ببینید.

## محدود کردن ویراستاران به برخی زبان‌ها

مجوزهای محتوایی یک نقش می‌توانند فقط برخی زبان‌ها را پوشش دهند. در **تنظیمات ← نقش‌ها**، نقش را
باز کنید، نوع محتوا را پیدا کنید و **زبان‌ها** را انتخاب کنید. **فقط این زبان‌ها** را برگزینید و
آن‌ها را انتخاب کنید. مدیرانی که این نقش را دارند نمی‌توانند نسخه‌های زبان‌های دیگر را بخوانند یا
تغییر دهند؛ انتخابگر **زبان** آن زبان‌ها را با «(بدون دسترسی)» نشان می‌دهد.

## خواندن و نوشتن زبان‌ها از طریق API

`locale` را به هر درخواست REST اضافه کنید، یا آن را به‌عنوان آرگومان در GraphQL بدهید. بدون آن،
زبان پیش‌فرض استفاده می‌شود. زبان ناشناخته خطای `400` است.

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
# خواندن نسخه‌های فرانسوی
curl 'http://localhost:1337/api/articles?locale=fr'

# ایجاد یا به‌روزرسانی نسخهٔ فرانسوی یک سند
curl -X PUT 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"data":{"title":"Bonjour"}}'

# حذف فقط نسخهٔ فرانسوی
curl -X DELETE 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN"
```

</TabItem>
<TabItem label="GraphQL">

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
    locale
  }
}
```

</TabItem>
<TabItem label="TypeScript">

```ts
const { data } = await verdin.collection('articles').find({ locale: 'fr' });
```

</TabItem>
</Tabs>

چه انتظاری داشته باشید:

- `PUT` با یک `locale`، وقتی سند هنوز نسخه‌ای در آن زبان ندارد، آن را می‌سازد.
- پاسخ‌های نوع‌های بومی‌سازی‌شده `locale` را دارند. همهٔ نسخه‌ها `documentId` یکسانی دارند.
- `DELETE` فقط نسخهٔ زبان درخواست‌شده را حذف می‌کند (اگر زبانی داده نشود، زبان پیش‌فرض را).
  پیوندهایی که به سند اشاره می‌کنند وقتی حذف می‌شوند که هیچ زبانی باقی نماند.
- وقتی یک نوع بومی‌سازی‌شده به نوع بومی‌سازی‌شدهٔ دیگری پیوند دارد، خواندن‌ها مقصد را در همان
  زبان حل می‌کنند و فیلترهای روی روابط هم همین‌طور. مقصدهایی که بومی‌سازی‌شده نیستند بین همهٔ
  زبان‌ها مشترک‌اند.
- محتوای وب‌هوک‌ها و نسخه‌های تاریخچه زبان را ثبت می‌کنند.

برخلاف Strapi، content API مسیر `/api/i18n/locales` ندارد. زبان‌ها در admin API در
`GET /admin/api/i18n/locales` فهرست می‌شوند و با `POST`،
`PUT /admin/api/i18n/locales/{code}` و `DELETE /admin/api/i18n/locales/{code}` مدیریت می‌شوند
(`locales.manage`).
