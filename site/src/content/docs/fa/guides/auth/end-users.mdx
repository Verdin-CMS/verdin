کاربران نهایی کسانی هستند که وارد سایت یا برنامهٔ شما می‌شوند، نه پنل مدیریت. Verdin به آن‌ها
ثبت‌نام، ورود، تأیید ایمیل، بازنشانی رمز عبور، ارائه‌دهندگان OAuth و نقش‌هایی می‌دهد که تعیین
می‌کنند در API محتوا چه کاری می‌توانند انجام دهند. مسیرها و payloadها همان‌های افزونهٔ
users-permissions در Strapi v5 هستند، بنابراین فرانت‌اندهای موجود همچنان کار می‌کنند.

## پیش از شروع

<Steps>

1. **تنظیمات ← قابلیت‌ها ← کاربران و مجوزها** را روشن کنید (به‌طور پیش‌فرض خاموش است)، یا
   **کاربران نهایی** را در **تنظیمات ← کاربران نهایی ← تنظیمات** روشن کنید.
2. اگر از تأیید ایمیل یا بازنشانی رمز عبور استفاده می‌کنید، `[email]` را پیکربندی کنید:

   ```toml title="verdin.toml"
   [email]
   provider = "smtp"          # log (default), smtp, resend or postmark
   from = "My site <no-reply@example.com>"

   [email.smtp]
   host = "smtp.example.com"
   port = 587
   username = "apikey"        # password in VERDIN_EMAIL_SMTP_PASSWORD
   ```

   Resend و Postmark کلید خود را از `VERDIN_EMAIL_API_KEY` می‌خوانند. **تنظیمات ← قابلیت‌ها ←
   ایمیل** گزینهٔ **ارسال ایمیل آزمایشی** را دارد. برای کار محلی، `docker/compose.dev.yml` شامل
   Mailpit است (SMTP روی پورت 1025، صندوق ورودی در `http://localhost:8025`).

3. `[server].public_url` را تنظیم کنید: پیوندهای ایمیل‌ها و callbackهای OAuth از آن استفاده می‌کنند.

</Steps>

مدیریت حساب‌ها و نقش‌ها به **مدیریت کاربران نهایی** (`endusers.manage`) نیاز دارد. تغییر زبانهٔ
تنظیمات (ثبت‌نام، ارائه‌دهندگان، قالب‌ها) به **مدیریت قابلیت‌ها** (`features.manage`) نیاز دارد.

## پیکربندی ثبت‌نام و نشست‌ها

در **تنظیمات ← کاربران نهایی ← تنظیمات**، زیر **ثبت‌نام و نشست‌ها**:

| تنظیم | پیش‌فرض | اثر |
| --- | --- | --- |
| **اجازهٔ ثبت‌نام** | روشن | هر کسی می‌تواند از طریق API محتوا حساب بسازد. خاموش: `register` با `400` پاسخ می‌دهد. |
| **تأیید نشانی‌های ایمیل** | خاموش | کاربران جدید پیش از اینکه بتوانند وارد شوند باید پیوندی را که ایمیل شده باز کنند. |
| **نقش پیش‌فرض** | Authenticated | نقش حساب‌های جدید. |
| **نشست‌ها** | یک توکن طولانی‌مدت | **یک توکن طولانی‌مدت** (حالت قدیمی Strapi) یا **توکن‌های کوتاه‌مدت با تازه‌سازی**. |
| **طول نشست (روز)** | 30 | طول عمر توکن طولانی‌مدت. |
| **طول عمر توکن دسترسی (دقیقه)**، **طول عمر توکن تازه‌سازی (روز)** | 30، 30 | با توکن‌های تازه‌سازی. |

زیر **صفحه‌های برنامهٔ شما**، **پس از تأیید ایمیل** (جایی که کاربران پس از تأیید نشانی‌شان به آن
می‌رسند) و **صفحهٔ بازنشانی رمز عبور** (صفحه‌ای از شما که `?code=` را دریافت می‌کند و رمز عبور جدید
می‌خواهد) را تنظیم کنید. بازنشانی رمز عبور به صفحهٔ بازنشانی نیاز دارد.

## تنظیم نقش‌ها

هر درخواست به‌عنوان یکی از این‌ها انجام می‌شود:

- **Public**: درخواست‌های بدون توکن. مجوزهای آن همان مجوزهای **تنظیمات ← دسترسی
  عمومی** است.
- **Authenticated**: نقش داخلی‌ای که به حساب‌های جدید داده می‌شود. قابل حذف نیست.
- **نقش‌های سفارشی**: آن‌ها را در **تنظیمات ← کاربران نهایی ← نقش‌ها** با **ایجاد نقش** بسازید.

**مجوزها**ی یک نقش از همان ماتریس دسترسی عمومی و توکن‌های API استفاده می‌کنند: **یافتن**،
**یافتن یکی**، **ایجاد**، **به‌روزرسانی**، **حذف**، **انتشار** و **خواندن پیش‌نویس‌ها** برای هر
نوع محتوا، **کتابخانهٔ رسانه**، و **کاربران** (مسیرهای `/api/users`). کاربر واردشده فقط مجوزهای
نقش خود را می‌گیرد، نه دسترسی عمومی را هم: وقتی کاربران واردشده به خواندن‌های عمومی نیاز دارند،
آن‌ها را به نقش هم بدهید. حذف یک نقش کاربرانش را به Authenticated منتقل می‌کند.

برای عمل کردن به‌جای یک کاربر، فرانت‌اند JWT او را به‌صورت `Authorization: Bearer <jwt>` می‌فرستد.
توکن‌های API با `vd_` شروع می‌شوند؛ Verdin از همین راه این دو را از هم تشخیص می‌دهد.

## ثبت‌نام و ورود

<Tabs>
<TabItem label="ثبت‌نام">

```sh title="Terminal"
curl -X POST http://localhost:1337/api/auth/local/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"ana","email":"ana@example.com","password":"a long password"}'
# → { "jwt": "…", "user": { "id": 1, "username": "ana", … } }
#   or { "user": … } when email confirmation is on
```

</TabItem>
<TabItem label="ورود">

```sh title="Terminal"
curl -X POST http://localhost:1337/api/auth/local \
  -H 'Content-Type: application/json' \
  -d '{"identifier":"ana@example.com","password":"a long password"}'
# → { "jwt": "…", "user": {…} }
```

`identifier` ایمیل یا نام کاربری است.

</TabItem>
<TabItem label="خواندن به‌عنوان کاربر">

```sh title="Terminal"
curl -H "Authorization: Bearer $JWT" http://localhost:1337/api/users/me
curl -H "Authorization: Bearer $JWT" http://localhost:1337/api/articles
```

</TabItem>
</Tabs>

ورود برای کاربران مسدودشده ("Your account has been blocked by an administrator") و، وقتی تأیید
روشن است، برای کاربران تأییدنشده ("Your account email is not confirmed") رد می‌شود.

## توکن‌ها و نشست‌ها

- **یک توکن طولانی‌مدت** (`jwtManagement: "legacy-support"`): JWT به اندازهٔ
  **طول نشست (روز)** دوام دارد.
- **توکن‌های کوتاه‌مدت با تازه‌سازی** (`jwtManagement: "refresh"`، مانند Strapi 5): JWT به اندازهٔ
  **طول عمر توکن دسترسی (دقیقه)** دوام دارد و پاسخ‌های ورود یک `refreshToken` هم دارند. برای گرفتن
  یک جفت جدید، `POST /api/auth/refresh` را با `{ refreshToken }` فراخوانی کنید. هر توکن تازه‌سازی
  یک بار کار می‌کند؛ ارائهٔ توکنی که قبلاً استفاده شده کل نشست را پایان می‌دهد.
  `POST /api/auth/logout` با `{ refreshToken }` آن را عمداً پایان می‌دهد.
- تغییر یا بازنشانی رمز عبور توکن‌های قبلی کاربر را باطل می‌کند، و مسدود کردن کاربر هم همین‌طور.
- درخواست‌های ورود، ثبت‌نام و بازنشانی به 20 در دقیقه برای هر IP کلاینت محدود می‌شوند.
- رمزهای عبور با Argon2id ذخیره می‌شوند. حساب‌هایی که از Strapi درون‌ریزی شده‌اند هش bcrypt خود
  را تا ورود بعدی نگه می‌دارند، که در آن هنگام دوباره هش می‌شود.

## تأیید نشانی‌های ایمیل و بازنشانی رمزهای عبور

وقتی **تأیید نشانی‌های ایمیل** روشن است، ثبت‌نام پیوندی به
`/api/auth/email-confirmation?confirmation=…` ایمیل می‌کند. باز کردن آن حساب را تأیید می‌کند و به
**پس از تأیید ایمیل** تغییرمسیر می‌دهد. `POST /api/auth/send-email-confirmation` با `{ email }`
پیوند جدیدی می‌فرستد.

برای رمز عبور فراموش‌شده:

<Steps>

1. برنامهٔ شما `POST /api/auth/forgot-password` را با `{ email }` فراخوانی می‌کند. پاسخ، چه حساب
   وجود داشته باشد چه نه، یکسان است.
2. کاربر ایمیلی با پیوندی به **صفحهٔ بازنشانی رمز عبور** شما، همراه با `?code=…`، دریافت می‌کند.
   کد یک ساعت کار می‌کند.
3. صفحهٔ شما `POST /api/auth/reset-password` را با
   `{ code, password, passwordConfirmation }` فراخوانی می‌کند و `{ jwt, user }` را می‌گیرد.

</Steps>

کاربران واردشده رمز عبور خود را با `POST /api/auth/change-password`
(`{ currentPassword, password, passwordConfirmation }`) تغییر می‌دهند.

ایمیل‌ها در **تنظیمات ← کاربران نهایی ← تنظیمات ← قالب‌های ایمیل** ویرایش می‌شوند: یک
**موضوع**، یک **پیام** و یک **بدنهٔ HTML (اختیاری)** برای **تأیید ایمیل** و
**بازنشانی رمز عبور**. آن‌ها جانگهدارهای `{{username}}`، `{{email}}` و `{{url}}` را می‌پذیرند؛
مقادیر در بدنهٔ HTML به‌صورت HTML escape می‌شوند.

## ورود با ارائه‌دهندگان OAuth

پیش‌تنظیم‌های داخلی برای GitHub، Google، Microsoft، Discord، Facebook، GitLab و LinkedIn وجود دارد.
هر نام دیگری یک ارائه‌دهندهٔ عمومی OAuth 2 است که به **نشانی مجوزدهی**، **نشانی
توکن** و **نشانی اطلاعات کاربر** خود نیاز دارد: Keycloak، Auth0 و Okta با URLهای realm یا tenant
شما به همین شکل کار می‌کنند. Sign in with Apple پشتیبانی نمی‌شود.

<Steps>

1. در **تنظیمات ← کاربران نهایی ← تنظیمات ← ارائه‌دهندگان ورود**، **افزودن GitHub** (یا
   پیش‌تنظیم دیگری، یا **افزودن ارائه‌دهندهٔ OAuth 2**) را انتخاب کنید.
2. نزد ارائه‌دهنده، **نشانی بازگشت (Callback) برای ثبت نزد ارائه‌دهنده** را که در پنجره نمایش داده
   می‌شود ثبت کنید: `https://cms.example.com/api/connect/github/callback`.
3. **شناسهٔ کلاینت**، **دامنه‌های دسترسی (Scopes)** اختیاری، و **بازگشت به برنامهٔ شما** را وارد
   کنید: صفحه‌ای از فرانت‌اند شما که پس از ورود `?access_token=` را دریافت می‌کند. **فعال** را
   روشن کنید.
4. کلید محرمانهٔ کلاینت (client secret) را در محیط سرور قرار دهید و آن را دوباره راه‌اندازی کنید:

   ```sh title=".env"
   VERDIN_OAUTH_GITHUB_SECRET=…
   ```

   متغیر `VERDIN_OAUTH_<PROVIDER>_SECRET` است. کلیدهای محرمانه هرگز در پایگاه داده ذخیره
   نمی‌شوند.

</Steps>

ورود از جریان Strapi پیروی می‌کند:

<Diagram
  caption="ورود OAuth برای کاربران نهایی"
  code={`sequenceDiagram
  participant B as مرورگر
  participant V as Verdin
  participant P as ارائه‌دهنده
  B->>V: GET /api/connect/github
  V-->>B: تغییرمسیر به ارائه‌دهنده
  B->>P: رضایت
  P-->>B: تغییرمسیر به /api/connect/github/callback
  B->>V: callback
  V-->>B: تغییرمسیر به صفحهٔ شما ?access_token=…
  B->>V: GET /api/auth/github/callback?access_token=…
  V-->>B: { jwt, user }`}
/>

`state` در OAuth امضا شده و با یک کوکی به مرورگر گره خورده است. حساب‌ها بر اساس ایمیل تطبیق داده
می‌شوند؛ ایمیلی که قبلاً توسط ارائه‌دهندهٔ دیگری یا توسط یک حساب ایمیل-و-رمز عبور استفاده شده
باشد رد می‌شود ("Email is already taken.").

## مدیریت حساب‌ها در پنل مدیریت

**تنظیمات ← کاربران نهایی ← کاربران** حساب‌ها را با امکان جستجو بر اساس نام کاربری یا ایمیل
فهرست می‌کند. می‌توانید با **افزودن کاربر** حساب بسازید، یک حساب را ویرایش کنید (نام کاربری، ایمیل،
رمز عبور، نقش، **تأییدشده**، **مسدود**)، آن را با **مسدود کردن** و **رفع مسدودیت** مسدود یا آزاد
کنید، و حذفش کنید.

## مسیرها

مسیرها زیر پیشوند API محتوا قرار دارند که به‌طور پیش‌فرض `/api` است. شکل درخواست‌ها و پاسخ‌ها از
Strapi v5 پیروی می‌کند.

| مسیر | کار |
| --- | --- |
| `POST /auth/local/register` | `{ username, email, password }` ← `{ jwt, user }`، یا وقتی تأیید ایمیل روشن است `{ user }`. |
| `POST /auth/local` | `{ identifier, password }` ← `{ jwt, user }`. |
| `GET /auth/email-confirmation?confirmation=` | ایمیل را تأیید می‌کند، سپس تغییرمسیر می‌دهد یا کاربر را برمی‌گرداند. |
| `POST /auth/send-email-confirmation` | `{ email }`: یک پیوند تأیید جدید. |
| `POST /auth/forgot-password` | `{ email }`: پیوند بازنشانی را ایمیل می‌کند. |
| `POST /auth/reset-password` | `{ code, password, passwordConfirmation }` ← `{ jwt, user }`. |
| `POST /auth/change-password` | واردشده. `{ currentPassword, password, passwordConfirmation }` ← `{ jwt, user }`. |
| `POST /auth/refresh`، `POST /auth/logout` | فقط در حالت تازه‌سازی: `{ refreshToken }`. |
| `GET /users/me` | کاربر واردشده. |
| `GET /users`، `GET /users/count`، `GET /users/{id}` | به **یافتن** / **یافتن یکی** روی **کاربران** نیاز دارد. JSON ساده، بدون پوشش `data`، مانند Strapi. `populate=role` نقش را اضافه می‌کند، `_q=` در نام‌های کاربری و ایمیل‌ها جستجو می‌کند، و `pagination[page]` و `pagination[pageSize]` (حداکثر 100) صفحه‌بندی می‌کنند. |
| `POST /users`، `PUT /users/{id}`، `DELETE /users/{id}` | به **ایجاد** / **به‌روزرسانی** / **حذف** روی **کاربران** نیاز دارد. `{ username, email, password, confirmed, blocked, role }`، که `role` شناسهٔ یک نقش است. |
| `GET /connect/{provider}` | ورود OAuth را آغاز می‌کند. |
| `GET /auth/{provider}/callback?access_token=` | توکن ارائه‌دهنده را با `{ jwt, user }` مبادله می‌کند. |

`verdin import strapi` کاربران نهایی را همراه با رمزهای عبورشان، نقش‌های سفارشی، و مجوزهای
نقش‌های public، authenticated و سفارشی منتقل می‌کند. [مهاجرت از Strapi](/fa/migrate/from-strapi/)
را ببینید.

<Aside type="caution">
نقشی که روی **کاربران** مجوز ایجاد، به‌روزرسانی یا حذف دارد به اعضای خود اجازه می‌دهد همهٔ حساب‌های
کاربران نهایی را مدیریت کنند. آن را فقط به نقش‌ها یا توکن‌های API مورد اعتماد بدهید.
</Aside>
