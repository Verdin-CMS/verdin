مدیران کسانی هستند که وارد پنل مدیریت می‌شوند. آن‌ها از
[کاربران نهایی](/fa/guides/auth/end-users/) سایت‌ها و برنامه‌های شما جدا هستند. این راهنما
نخستین مدیر را می‌سازد، بقیه را دعوت می‌کند، به آن‌ها نقش می‌دهد و وقتی دسترسی‌شان قفل شده است
کمکشان می‌کند دوباره وارد شوند.

## پیش از شروع

- Verdin به `VERDIN_ADMIN_JWT_SECRET` و `VERDIN_TOKEN_PEPPER` در محیط نیاز دارد. آن‌ها را یک بار
  با `verdin secrets` تولید کنید.
- مدیریت مدیران به **مدیریت کاربران** (`users.manage`) و مدیریت نقش‌ها به **مدیریت
  نقش‌ها** (`roles.manage`) نیاز دارد. [مجوزها](/fa/reference/permissions/) را ببینید.
- دعوت‌نامه‌ها و بازنشانی رمز عبور از طریق `[email]` ایمیل می‌شوند. با ارائه‌دهندهٔ پیش‌فرض
  `log`، ایمیل‌ها، همراه با پیوندها، در لاگ سرور نوشته می‌شوند.

## ساخت نخستین مدیر

پنل مدیریت را باز کنید (به‌طور پیش‌فرض `http://localhost:1337/admin/`). تا وقتی هیچ مدیری وجود
ندارد، پنل نخستین مدیر را می‌خواهد که **مدیر ارشد** می‌شود. رمزهای عبور 8 تا 128 نویسه دارند.

بدون مرورگر، از CLI یا API استفاده کنید:

<Tabs>
<TabItem label="CLI">

```sh title="Terminal"
verdin admin create --email you@example.com
```

رمز عبور از `VERDIN_ADMIN_PASSWORD` گرفته می‌شود یا از ورودی استاندارد خوانده می‌شود. این فرمان
یک مدیر ارشد می‌سازد و در هر زمانی کار می‌کند، نه فقط برای نخستین مدیر.

</TabItem>
<TabItem label="API">

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/register-first-admin \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a long password"}'
```

این مسیر فقط تا وقتی هیچ مدیری وجود ندارد کار می‌کند.

</TabItem>
</Tabs>

## دعوت یک مدیر

<Steps>

1. **تنظیمات ← کاربران** را باز کنید و **افزودن کاربر** را انتخاب کنید.
2. ایمیل و در صورت تمایل **نام** و **نام خانوادگی** را وارد کنید.
3. یک یا چند نقش را در **نقش‌ها** انتخاب کنید.
4. **هم‌اکنون رمز عبوری تنظیم کنید** را خاموش بگذارید تا دعوت‌نامه فرستاده شود، یا آن را روشن کنید
   تا رمز عبور را خودتان تعیین کنید.
5. **دعوت** (یا با رمز عبور، **ذخیره**) را انتخاب کنید.

</Steps>

پنجرهٔ **پیوند دعوت** پیوند را نشان می‌دهد و می‌گوید آیا ایمیل شده است یا نه. اگر ایمیل نشده بود،
خودتان آن را به اشتراک بگذارید؛ با ارائه‌دهندهٔ `log` همیشه همین‌طور است. پیوند یک بار و به مدت 7 روز
کار می‌کند؛ مدیر دعوت‌شده آن را باز می‌کند، رمز عبوری انتخاب می‌کند و وارد می‌شود.

تا وقتی مدیر هرگز وارد نشده است، **پیوند دعوت جدید** در ردیف او پیوند قبلی را جایگزین می‌کند.
پس از اینکه وارد شد، دسترسی را به‌جای آن با بازنشانی رمز عبور بازیابی می‌کند.

## نقش‌ها

Verdin، مانند Strapi، سه نقش می‌سازد:

| نقش | می‌تواند |
| --- | --- |
| **مدیر ارشد** | همه‌چیز. مجوزهای آن قابل تغییر نیست. |
| **Editor** | ایجاد، ویرایش، انتشار و حذف همهٔ محتوا؛ مدیریت کتابخانهٔ رسانه؛ راه‌اندازی استقرارها؛ مدیریت SEO، تغییرمسیرها، منوها و فرم‌ها. |
| **Author** | ایجاد محتوا، و ویرایش و حذف مدخل‌ها و فایل‌های خود. نمی‌تواند منتشر کند. |

نقش‌های بیشتری را در **تنظیمات ← نقش‌ها** با **نقش جدید** بسازید. برای هر نقش انتخاب کنید:

- **محتوا**: برای هر نوع محتوا (یا **همهٔ نوع‌های محتوا**)، سطح **خواندن**، **ایجاد**،
  **به‌روزرسانی**، **حذف** و **انتشار**: **بدون دسترسی**، **مال خود** (فقط مدخل‌هایی که
  خود مدیر ساخته است) یا **همه**. **فیلدها** یک عمل را به برخی فیلدها و **زبان‌ها** به برخی
  زبان‌ها محدود می‌کند.
- **کتابخانهٔ رسانه**: عمل‌های مربوط به فایل، برای **همهٔ فایل‌ها** یا **فایل‌های خود**.
- **تنظیمات**: دسترسی به بخش‌های مدیریتی، مانند **مدیریت کاربران** یا **خواندن گزارش‌های
  حسابرسی**.
- **الزامی کردن تأیید دومرحله‌ای**: [تأیید دومرحله‌ای](/fa/guides/auth/two-factor/) را ببینید.

مدیری که چند نقش دارد اجتماع مجوزهای آن‌ها را می‌گیرد. فهرست کامل در
[مرجع مجوزها](/fa/reference/permissions/) است.

فقط یک مدیر ارشد می‌تواند نقش مدیر ارشد را بدهد، یا مدیر ارشد دیگری را ویرایش، حذف یا
بازنشانی کند.

## غیرفعال کردن یا حذف یک مدیر

مدیر را در **تنظیمات ← کاربران** ویرایش کنید و **فعال** را خاموش کنید: کاربران غیرفعال نمی‌توانند
وارد شوند. **حذف** حساب را برای همیشه پاک می‌کند؛ از آن پس نظرهای او به‌عنوان نوشتهٔ یک مدیر
حذف‌شده نمایش داده می‌شوند.

## بازنشانی رمز عبور

- **خود مدیر آن را بازنشانی می‌کند:** **رمز عبور را فراموش کرده‌اید؟** در صفحهٔ ورود پیوندی ایمیل
  می‌کند که یک ساعت کار می‌کند. پس از تغییر رمز عبور، همهٔ نشست‌های حساب پایان می‌یابند.
- **مدیر دیگری آن را تعیین می‌کند:** مدیر را در **تنظیمات ← کاربران** ویرایش کنید و رمز عبور جدیدی
  بنویسید. برای نگه داشتن رمز فعلی، فیلد را خالی بگذارید.
- **از سمت سرور:** وقتی هیچ‌کس نمی‌تواند وارد شود، این را اجرا کنید

  ```sh title="Terminal"
  verdin admin reset-password --email you@example.com
  ```

  با رمز عبور در `VERDIN_ADMIN_PASSWORD` یا در ورودی استاندارد. این فرمان رمز عبور را تنظیم
  می‌کند، قفل حساب را باز می‌کند و نشست‌های آن را پایان می‌دهد. تأیید دومرحله‌ای را حذف نمی‌کند:
  مدیری که عامل دوم خود را گم کرده است به مدیر دیگری نیاز دارد تا
  [آن را بازنشانی کند](/fa/guides/auth/two-factor/).

## محافظت از ورود

- پس از 5 رمز عبور نادرست پشت سر هم، حساب به مدت 15 دقیقه قفل می‌شود.
- درخواست‌های ورود، ثبت‌نام و تازه‌سازی برای هر IP کلاینت با
  `[admin].auth_rate_limit` محدود می‌شوند (به‌طور پیش‌فرض 20 در دقیقه).
- نشست مدیر یک توکن دسترسی 15 دقیقه‌ای است که با یک کوکی تازه‌سازی 30 روزه تمدید می‌شود. در
  `verdin start` این کوکی `Secure` است؛ `[admin].secure_cookies` را ببینید.

هر مدیر دستگاه‌هایی را که با آن‌ها وارد شده است زیر **نشست‌ها** در **نمایه** خود می‌بیند، و
می‌تواند از یکی یا همهٔ دستگاه‌های دیگر **خروج** کند. تغییر رمز عبور همهٔ دستگاه‌های دیگر را خارج
می‌کند.

## Admin API

برای گرفتن توکن دسترسی Admin API وارد شوید:

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → { "data": { "user": {…}, "accessToken": "…", "accessTokenExpiresAt": "…" } }
```

| مسیر | مجوز | کار |
| --- | --- | --- |
| `GET /users`، `GET /users/{id}` | `users.manage` | مدیران همراه با نقش‌هایشان. |
| `POST /users` | `users.manage` | `{ email, firstname?, lastname?, roles: [ids], isActive?, password? }`. بدون `password`، بخش `meta` پاسخ `inviteUrl` و `emailed` را دارد. |
| `PUT /users/{id}`، `DELETE /users/{id}` | `users.manage` | تغییر یا حذف یک مدیر. |
| `POST /users/{id}/invite` | `users.manage` | پیوند دعوت جدید، برای مدیرانی که هرگز وارد نشده‌اند. |
| `GET /roles`، `POST /roles`، `PUT /roles/{id}`، `DELETE /roles/{id}` | `roles.manage` | نقش‌ها و مجوزهایشان. |
| `POST /auth/forgot-password` | عمومی | `{ email }`. همیشه `204` پاسخ می‌دهد. |
| `GET /auth/sessions`، `DELETE /auth/sessions/{id}` | واردشده | نشست‌های شما. |

همهٔ مسیرها زیر `/admin/api` هستند. [Admin API](/fa/api/admin/) را ببینید.

<Aside type="caution">
کلیدهای محرمانه (secret) هرگز در `verdin.toml` قرار نمی‌گیرند. هر دو کلید را میان راه‌اندازی‌های
دوباره و نمونه‌ها ثابت نگه دارید: `VERDIN_ADMIN_JWT_SECRET` توکن‌های دسترسی، JWTهای کاربران نهایی و
پیوندهای پیش‌نمایش را امضا می‌کند، و `VERDIN_TOKEN_PEPPER` از توکن‌های API و عامل‌های دوم محافظت
می‌کند ([توکن‌های API](/fa/guides/auth/api-tokens/) را ببینید).
</Aside>
