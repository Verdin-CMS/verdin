`verdin import strapi` یک پروژهٔ Strapi v4 یا v5 را به Verdin می‌آورد: نوع‌های محتوا و
کامپوننت‌هایش به فایل‌های طرح‌واره (schema) تبدیل می‌شوند، و مدخل‌ها، زبان‌ها، کتابخانهٔ رسانه،
روابط، کاربران نهایی و مجوزهای عمومی‌اش درون‌ریزی می‌شوند. این صفحه یک مهاجرت را گام‌به‌گام
پیش می‌برد و آنچه را فرانت‌اند شما باید تغییر دهد فهرست می‌کند. برای مقایسهٔ قابلیت‌به‌قابلیت،
[سازگاری با Strapi](/fa/migrate/compatibility/) را ببینید.

## پیش از شروع

- یک پروژهٔ Strapi v4 یا v5 که بتوانید در آن `strapi export` را اجرا کنید.
- یک پروژهٔ Verdin تازه (`verdin new my-site`)، یا پروژه‌ای بدون فایل‌های طرح‌واره با همان
  نام‌ها. ببینید [شروع سریع](/fa/start/quickstart/).
- در صورت امکان، پایگاه داده و ذخیره‌سازی رسانه‌ای که پروژهٔ Verdin در محیط تولید استفاده خواهد
  کرد: فایل‌ها هنگام درون‌ریزی در provider بارگذاری پیکربندی‌شده کپی می‌شوند.

## 1. خروجی گرفتن از Strapi

در پروژهٔ Strapi:

```sh frame="terminal"
npx strapi export --no-encrypt -f my-export      # writes my-export.tar.gz
```

Verdin نمی‌تواند خروجی‌های رمزنگاری‌شده (`.tar.gz.enc`) را بخواند؛ دوباره با `--no-encrypt`
خروجی بگیرید. خروجی‌های فشرده‌نشده (`--no-compress`، یک `.tar`) و یک پوشهٔ خروجی بازشده هم
کار می‌کنند.

## 2. درون‌ریزی در Verdin

<Steps>

1. پروژه را بسازید و خروجی را درون‌ریزی کنید:

   ```sh frame="terminal"
   verdin new my-site && cd my-site
   verdin import strapi ../my-export.tar.gz
   ```

2. خلاصه را بخوانید. درون‌ریز چاپ می‌کند چند سند، نسخه، فایل، پوشه، زبان و پیوند درون‌ریزی
   کرده است، سپس برای هر هشدار یک خط.

3. سرور توسعه را اجرا کنید و پنل مدیریت را باز کنید:

   ```sh frame="terminal"
   verdin dev
   ```

</Steps>

فرمان این گام‌ها را به ترتیب اجرا می‌کند:

1. برای هر نوع محتوای `api::` و هر کامپوننت یک فایل طرح‌واره در `schema/` می‌نویسد. اگر
   طرح‌وارهٔ تبدیل‌شده اعتبارسنجی نشود، هیچ چیزی نوشته نمی‌شود.
2. پایگاه داده را مهاجرت می‌دهد (گام‌های امن).
3. زبان‌ها، پوشه‌ها و فایل‌های رسانه، مدخل‌ها (همهٔ پیش‌نویس‌ها، نسخه‌های منتشرشده و زبان‌ها)،
   روابط، و رسانه‌های پیوست‌شده به مدخل‌ها و کامپوننت‌ها را درون‌ریزی می‌کند.
4. کاربران نهایی، نقش‌هایشان و مجوزهای public و authenticated را درون‌ریزی می‌کند.
5. `strapi-id-map.json` را در پوشهٔ پروژه می‌نویسد.

| گزینه | اثر |
| --- | --- |
| `--schema-only` | پس از نوشتن فایل‌های طرح‌واره متوقف می‌شود. برای بازبینی یا اصلاح طرح‌واره پیش از ادامه مفید است. |
| `--force` | فایل‌های طرح‌وارهٔ موجود را بازنویسی می‌کند، و در نوع‌های محتوایی که از قبل مدخل دارند هم درون‌ریزی می‌کند. |

بدون `--force`، اگر فایل طرح‌واره‌ای که قرار است نوشته شود از قبل وجود داشته باشد، یا اگر یک
نوع محتوا از قبل مدخل داشته باشد، درون‌ریزی متوقف می‌شود.

## آنچه منتقل می‌شود

| Strapi | Verdin |
| --- | --- |
| نوع‌های محتوای `api::…` و کامپوننت‌ها | فایل‌های طرح‌واره، با حفظ `collectionName`، پیش‌نویس و انتشار، گزینه‌های i18n و گزینه‌های فیلد (`required`، `private`، `unique`، طول‌ها، `regex`، مقادیر پیش‌فرض…) |
| روابط بین نوع‌های `api::` | همان روابط |
| روابط درون کامپوننت‌ها | ارجاع‌های `oneWay` / `manyWay` |
| روابط چندریختی (`morphToOne`، `morphToMany`، `morphOne`، `morphMany`) | همان‌ها، با پیوندهایشان به نوع‌های محتوای درون‌ریزی‌شده |
| فیلدهای رسانه (در کامپوننت‌ها هم) | فیلدهای رسانه |
| سطرهای v5 (پیش‌نویس و منتشرشده) | نسخه‌های پیش‌نویس و منتشرشده |
| سطرهای v4 | یک پیش‌نویس، به‌علاوهٔ یک نسخهٔ منتشرشده وقتی `publishedAt` تنظیم شده باشد؛ `localizations` به زبان‌های یک سند تبدیل می‌شوند |
| `plugin::i18n.locale` | زبان‌ها (زبان پیش‌فرض Strapi پیش‌فرض می‌ماند) |
| `plugin::upload.file` و `folder` | فایل‌های کتابخانهٔ رسانه (با قالب‌هایشان) و پوشه‌ها |
| فیلدهای `password` | فیلدهای `password`، با حفظ هش‌های bcrypt در Strapi |
| فیلدهای سفارشی (`customField`) | ویژگی با `customField` حفظ‌شده؛ در ادامه را ببینید |
| فیلدهای شرطی (`conditions`، Strapi 5.17) | در طرح‌واره حفظ می‌شوند و ویرایشگر اعمالشان می‌کند |
| `plugin::users-permissions.user` | کاربران نهایی، با گذرواژه‌های bcrypt (که در ورود بعدی با Argon2id دوباره هش می‌شوند)، `confirmed` و `blocked` |
| نقش‌های Users & Permissions | مجوزهای نقش Public به مجوزهای عمومی Verdin تبدیل می‌شوند؛ Authenticated و نقش‌های سفارشی به نقش‌های کاربر نهایی تبدیل می‌شوند |
| مجوزهای نقش روی نوع‌های محتوا و بارگذاری‌ها | مجوزهای `find`، `findOne`، `create`، `update` و `delete`؛ و برای بارگذاری `find`، `findOne`، `upload` و `destroy` |

## آنچه منتقل نمی‌شود

به‌صورت هشدار گزارش می‌شوند:

- روابط با کاربران مدیر، کاربران نهایی یا نوع‌های افزونه‌های دیگر (فقط مقصدهای `api::`
  درون‌ریزی می‌شوند). فیلدهای `createdBy` / `updatedBy` کنار گذاشته می‌شوند.
- `unique` روی ویژگی‌های `text`، `richtext`، `blocks` و `json` (Verdin آن را روی نوع‌های متن
  کوتاه پشتیبانی می‌کند).
- نوع‌های ویژگی که Verdin نمی‌شناسد، و نوع‌های رابطه‌ای که نمی‌تواند درون یک کامپوننت ذخیره کند.
- نیمه‌های رابطه‌ای که `inversedBy` / `mappedBy` آن‌ها با طرف دیگر نمی‌خواند.
- کدهای زبانی که معتبر نیستند.

اصلاً درون‌ریزی نمی‌شوند: کاربران مدیر و نقش‌های مدیر، توکن‌های API، توکن‌های انتقال،
وب‌هوک‌ها، بسته‌های انتشار، مرحله‌های گردش‌کار بازبینی، تاریخچهٔ محتوا و گزارش‌های حسابرسی، و
تنظیمات افزونه‌های Strapi. کد Strapi شما — کنترلرها، سرویس‌ها، مسیرها، policyها،
middlewareها، هوک‌های lifecycle، کارهای cron و سفارشی‌سازی‌های پنل مدیریت — معادلی در Verdin
ندارد که به آن تبدیل شود؛ ببینید [بازسازی کد سفارشی](#بازسازی-کد-سفارشی).

<Aside type="note">
فیلدهای سفارشی نام `customField` خود را حفظ می‌کنند، مثلاً `plugin::color-picker.color`.
ویرایشگر آن‌ها را با یک [افزونه](/fa/extending/plugins/) که آن فیلد را فراهم می‌کند نشان می‌دهد،
و وقتی چنین افزونه‌ای نباشد به ورودی مربوط به نوع ذخیره‌شده برمی‌گردد.
</Aside>

## نگاشت شناسه‌ها

Verdin شناسه‌های سند تازه تولید می‌کند: `documentId`های Strapi 24 نویسه دارند و مال Verdin
26 نویسه، پس هر سند شناسهٔ تازه‌ای می‌گیرد. `id`های عددی هم تغییر می‌کنند.
`strapi-id-map.json` این نگاشت را ثبت می‌کند:

```json title="strapi-id-map.json"
{
  "documents": {
    "api::article": {
      "hq7xw1c6m2vkn0f3t8ybz5sd": "01k6b3xg0r9m2m7c1d4e5f6g7h"
    }
  },
  "files": {
    "12": 3
  }
}
```

- کلید `documents` ابتدا uid نوع محتوا در Verdin است (`api::article`، که در Strapi
  `api::article.article` است)، سپس `documentId` در Strapi (v5) یا شناسهٔ سطر (v4: یک شناسه
  نمایندهٔ همهٔ زبان‌های یک سند است).
- `files` شناسه‌های فایل Strapi را به شناسه‌های فایل Verdin نگاشت می‌کند.

از آن برای بازنویسی شناسه‌هایی استفاده کنید که بیرون از CMS ذخیره شده‌اند: پیوندها در کد
فرانت‌اند، شناسه‌ها در پایگاه دادهٔ دیگر، تحلیل‌ها، نشانک‌ها.

## بررسی نتیجه

1. `verdin schema check` بدون خطا می‌گذرد، و `verdin migrate plan` می‌گوید پایگاه داده به‌روز
   است.
2. در پنل مدیریت، هر مجموعه را باز کنید و تعداد مدخل‌ها، پیش‌نویس‌ها و زبان‌ها را با Strapi
   مقایسه کنید.
3. چند مدخل دارای روابط، کامپوننت‌ها، ناحیه‌های پویا و رسانه را باز کنید و بررسی کنید که
   پیوندها به سندها و فایل‌های درست اشاره کنند.
4. **کتابخانهٔ رسانه** را باز کنید و بررسی کنید که پوشه‌ها و تصاویر (با قالب‌هایشان) موجود
   باشند.
5. در **تنظیمات ← دسترسی عمومی** و **تنظیمات ← کاربران نهایی**، مجوزها و نقش‌های درون‌ریزی‌شده
   را بازبینی کنید.
6. API خود را همان‌طور که فرانت‌اند فراخوانی می‌کند فراخوانی کنید و پاسخ‌ها را با پاسخ‌های
   Strapi مقایسه کنید.

سپس `schema/` را commit کنید، مدیران، توکن‌های API و وب‌هوک‌های خود را بسازید و مستقر کنید
(ببینید [چک‌لیست محیط تولید](/fa/deploy/production-checklist/)).

## تغییرات فرانت‌اند

API محتوا از شکل‌های REST و GraphQL در Strapi v5 پیروی می‌کند، پس بیشتر درخواست‌ها همان‌طور
که هستند کار می‌کنند. این موارد را تغییر دهید:

- **URL پایه.** فرانت‌اند را به سرور Verdin اشاره دهید. API محتوا زیر `/api`
  (`[api].prefix`) است، و GraphQL پس از روشن کردنش در **تنظیمات ← قابلیت‌ها** در `/graphql`.
- **توکن‌های API.** توکن‌ها درون‌ریزی نمی‌شوند: در **تنظیمات ← توکن‌های API** توکن‌های تازه
  بسازید و آن‌ها را در محیط فرانت‌اند جایگزین کنید.
- **شناسه‌های سند.** هر `documentId` و `id` عددی تازه است. شناسه‌های hard-coded در فرانت‌اند
  را با شناسه‌های موجود در `strapi-id-map.json` جایگزین کنید، یا بهتر از آن، مدخل‌ها را با یک
  slug یا فیلد `uid` دیگری پیدا کنید.
- **URLهای رسانه.** URL فایل‌ها به provider تازه اشاره می‌کنند: `/uploads/…` روی سرور Verdin
  برای provider محلی، یا `[upload.provider].public_url` برای S3. دامنه‌های تصویر مجاز در
  فریم‌ورک خود را به‌روز کنید (مثلاً `images.remotePatterns` در Next.js).
- **کاربران نهایی واردشده** باید دوباره وارد شوند: گذرواژه‌هایشان کار می‌کند، اما JWTهایی که
  Strapi صادر کرده کار نمی‌کنند.
- **CORS.** اگر یک مرورگر API را از origin دیگری فراخوانی می‌کند، آن را در
  `[api].cors_origins` فهرست کنید.
- **وب‌هوک‌ها.** آن‌ها را در **تنظیمات ← وب‌هوک‌ها** دوباره بسازید. رویداد
  `entry.draft-discard` در Strapi اینجا `entry.discard-draft` نام دارد، و ارسال‌ها امضا می‌شوند
  (ببینید [وب‌هوک‌ها](/fa/guides/integrations/webhooks/)).
- **فرانت‌اندهای Strapi v4** به تغییرات v5 هم نیاز دارند: پاسخ‌های تخت بدون `attributes`،
  `documentId` به‌جای `id` در URLها، و `status=draft` به‌جای `publicationState=preview`.

برای دسترسی تایپ‌شده، نوع‌های TypeScript را با `verdin types` تولید کنید و از
[کلاینت تایپ‌شده](/fa/guides/frontend/typed-client/) استفاده کنید.

## بازسازی کد سفارشی

| Strapi | Verdin |
| --- | --- |
| هوک‌های lifecycle، middlewareهای document service | هوک‌های افزونه (`beforeCreate`، `afterUpdate`…) در یک [افزونهٔ WebAssembly](/fa/extending/plugins/) |
| مسیرها و کنترلرهای سفارشی | مسیرهای افزونه زیر `/api/plugins/<name>/` |
| کارهای cron | کارهای (job) افزونه (`[[jobs]]`) |
| فیلدهای سفارشی | فیلدهای سفارشی افزونه |
| ویجت‌های پنل مدیریت | ویجت‌های افزونه، یا ویجت‌های داخلی داشبورد |
| لوگو، رنگ‌ها و متن‌های پنل مدیریت | `[admin.branding]` در `verdin.toml` |
| `config/*.js` | `verdin.toml` و متغیرهای محیطی ([مرجع پیکربندی](/fa/reference/configuration/)) |
