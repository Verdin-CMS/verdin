در این آموزش یک وبلاگ با [Next.js](https://nextjs.org) و App Router می‌سازید که محتوایش را از
Verdin می‌خواند: یک صفحهٔ اصلی که مقاله‌ها را فهرست می‌کند، یک صفحه برای هر مقاله در
`/articles/<slug>` همراه با دسته‌اش، و در صورت تمایل صفحه‌ای که پیش‌نویس‌ها را از پیوند
پیش‌نمایش پنل مدیریت نشان می‌دهد. از کلاینت تایپ‌شدهٔ `@verdin/client` با نوع‌هایی که از
طرح‌واره تولید شده‌اند، در Server Components استفاده می‌کنید.

نوشته‌شده برای Next.js 16.3 (`create-next-app` 16.3)، React 19.2 و Node.js 20.9 یا بالاتر، با
Verdin و `@verdin/client` 0.10. از کش پیش‌فرض Next.js استفاده می‌کند، بدون
`cacheComponents`. [آموزش Astro](/fa/start/tutorial-astro/) همین وبلاگ را با Astro می‌سازد.

## پیش از شروع

به فایل باینری `verdin` در `PATH` (ببینید [شروع سریع](/fa/start/quickstart/))، Node.js و Git
نیاز دارید. در پایان دو پوشه کنار هم خواهید داشت: `cms`، پروژهٔ Verdin، و `blog`، اپلیکیشن
Next.js.

## 1. راه‌اندازی Verdin با طرح‌وارهٔ وبلاگ

پروژهٔ [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) در مخزن
یک وبلاگ را مدل می‌کند: مقاله‌هایی با عنوان، یک `slug`، خلاصه، یک `body` به Markdown، دسته و
برچسب‌ها، به‌علاوهٔ یک نوع تکی homepage و چند کامپوننت.

<Steps>

1. یک پروژهٔ Verdin بسازید و طرح‌وارهٔ نمونه را در آن کپی کنید:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. آن را اجرا کنید:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   نخستین اجرا جدول‌های چهار نوع محتوا را می‌سازد.

3. [http://localhost:1337/admin/](http://localhost:1337/admin/) را باز کنید و نخستین مدیر را بسازید.

4. زیر **مجموعه‌ها**، **Category** را باز کنید، **مدخل جدید** را انتخاب کنید، نامش را `News`
   بگذارید و ذخیره کنید.

5. **Article** را باز کنید، **مدخل جدید** را انتخاب کنید و یک عنوان، یک خلاصه و یک متن به
   Markdown وارد کنید. `slug` از روی عنوان تولید می‌شود. `News` را به‌عنوان دسته انتخاب کنید و
   **انتشار** را بزنید. مقالهٔ دومی را هم به همین شکل اضافه کنید.

6. **تنظیمات ← دسترسی عمومی** را باز کنید، **یافتن** و **یافتن یکی** را برای **Article** و
   **Category** مجاز کنید و **ذخیره** را انتخاب کنید.

</Steps>

بررسی کنید که API پاسخ می‌دهد:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
populate کردن یک رابطه به دسترسی خواندن روی مقصد آن نیاز دارد. بدون **یافتن** روی **Category**،
`populate=category` با `400` و پیام ``invalid key `category` in populate`` پاسخ می‌دهد.
</Aside>

## 2. ساختن اپلیکیشن Next.js

در یک ترمینال تازه، کنار `cms`:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) محتوای Markdown فیلد `body` را به HTML تبدیل می‌کند.

## 3. تولید نوع‌ها

`verdin types` طرح‌واره را می‌خواند و برای هر نوع محتوا و کامپوننت یک interface در TypeScript
می‌نویسد، به‌علاوهٔ یک نگاشت `VerdinSchema` از مسیرها برای کلاینت. آن را از پوشهٔ `blog` اجرا کنید
و به پیکربندی پروژهٔ Verdin اشاره دهید:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

فایل، از جمله، شامل این است:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

روابط، رسانه‌ها و کامپوننت‌ها اختیاری هستند، چون API آن‌ها را فقط وقتی populate کنید
برمی‌گرداند. هر بار که طرح‌واره تغییر کرد، فرمان را دوباره اجرا کنید.

## 4. اتصال به Verdin

URL سرور را در `.env.local` قرار دهید:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

بدون توکن، کلاینت با نقش عمومی می‌خواند، همان چیزی که در گام 1 باز کردید. برای خواندن با توکن،
یک توکن **فقط‌خواندنی** در **تنظیمات ← توکن‌های API** بسازید و `VERDIN_TOKEN` را تنظیم کنید. هر دو
متغیر روی سرور می‌مانند: پیشوند `NEXT_PUBLIC_` ندارند و کلاینت فقط در Server Components اجرا
می‌شود.

کلاینت را یک بار بسازید و به اشتراک بگذارید:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

اکنون `verdin.collection('articles')` فقط مسیرهای طرح‌وارهٔ شما را می‌پذیرد و نتایجش از نوع
`Article` هستند.

## 5. جایگزین کردن layout

layout آغازین را جایگزین کنید و `src/app/page.module.css` را که صفحه‌های تازه از آن استفاده
نمی‌کنند حذف کنید:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import Link from 'next/link';

export const metadata: Metadata = {
  title: 'My blog',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. فهرست کردن مقاله‌ها

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

این کوئری همان فراخوانی REST
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`
با قالب Strapi v5 است. `fields` پاسخ را کوچک نگه می‌دارد و `populate` دسته را فقط با نامش اضافه
می‌کند. نقش عمومی فقط مقاله‌های منتشرشده را می‌خواند.

`revalidate = 60` صفحه را هنگام ساخت (build) از پیش رندر می‌کند و پس از آن حداکثر دقیقه‌ای یک
بار تازه‌اش می‌کند، پس تغییرات منتشرشده بدون ساخت دوباره نمایان می‌شوند.

## 7. افزودن یک صفحه برای هر مقاله

صفحهٔ مقاله، مقاله‌اش را با یک فیلتر بر اساس slug پیدا می‌کند. `generateStaticParams` مقاله‌های
موجود را از پیش رندر می‌کند؛ مقاله‌هایی که بعداً منتشر شوند در نخستین بازدید رندر می‌شوند.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

در Next.js 16، `params` یک promise است: پیش از خواندن slug آن را await کنید. یک slug ناشناخته
هیچ مقاله‌ای پیدا نمی‌کند و از طریق `notFound()` با 404 پاسخ می‌دهد. `pageSize` با
`[api].max_page_size` محدود می‌شود (به‌طور پیش‌فرض 100).

<Aside type="caution">
`marked` HTML را پاک‌سازی نمی‌کند. برای Markdown که ویراستاران خودتان می‌نویسند این مشکلی
ندارد؛ اگر محتوا ممکن است از افراد غیرقابل‌اعتماد بیاید، HTML را پیش از رندر پاک‌سازی کنید.
</Aside>

## 8. اجرای آن

```sh title="Terminal"
npm run dev
```

[http://localhost:3000](http://localhost:3000) را باز کنید: فهرست، مقاله‌های منتشرشدهٔ شما را
نشان می‌دهد و هر کدام به صفحهٔ خودش پیوند دارد. `npm run build` به Verdin در حال اجرا نیاز
دارد، چون مقاله‌ها را برای پیش‌رندر دریافت می‌کند.

برای تازه کردن صفحه‌ها بلافاصله پس از تغییر محتوا، به‌جای ظرف یک دقیقه، `revalidatePath` را از
یک route handler فراخوانی کنید که یک وب‌هوک Verdin آن را فعال می‌کند؛ ببینید
[وب‌هوک‌ها](/fa/guides/integrations/webhooks/).

پروژهٔ شما اکنون چنین است:

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts تولیدشده توسط `verdin types`
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. اختیاری: پیش‌نمایش پیش‌نویس‌ها

پنل مدیریت می‌تواند یک پیش‌نویس را با یک توکن پیش‌نمایش کوتاه‌عمر روی سایت شما باز کند. این
توکن فقط همان یک سند را، پیش‌نویس‌ها را هم، می‌خواند و نه چیز دیگری.

کلاینتی اضافه کنید که توکن پیش‌نمایش را در هدر `x-verdin-preview` بفرستد:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

سپس صفحه. این صفحه `searchParams` را می‌خواند، پس Next.js آن را در هر درخواست رندر می‌کند؛
توکن به‌صورت پارامتر کوئری `preview` می‌رسد:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

یک توکن پیش‌نمایش نمی‌تواند مدخل‌ها را فهرست کند، پس صفحه پیش‌نویس را با `documentId` پیدا
می‌کند نه با slug. حالا به Verdin بگویید صفحه کجاست:

<Steps>

1. در پنل مدیریت، **تنظیمات ← قابلیت‌ها** را باز کنید، **پیش‌نمایش** را روشن کنید و
   **پیکربندی نشانی‌های پیش‌نمایش** را انتخاب کنید.
2. قالب URL مربوط به **Article** را `http://localhost:3000/preview/{documentId}` بگذارید و
   ذخیره کنید. Verdin توکن را به‌صورت `?preview=…` به انتها اضافه می‌کند.
3. یک مقاله را باز کنید، تغییرش دهید و **ذخیرهٔ پیش‌نویس** را انتخاب کنید، سپس
   **باز کردن پیش‌نمایش** را انتخاب کنید.

</Steps>

صفحه پیش‌نویس را نشان می‌دهد. پیوندها به‌طور پیش‌فرض 60 دقیقه اعتبار دارند. برای جای‌نگهدارها
و تنظیمات [پیش‌نمایش](/fa/guides/content/preview/) را ببینید، و برای ویرایش از داخل پیش‌نمایش
[ویرایش دیداری](/fa/guides/frontend/visual-editing/) را.
