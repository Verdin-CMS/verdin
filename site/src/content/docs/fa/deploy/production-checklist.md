پیش از اینکه یک پروژهٔ Verdin را در اختیار کاربران واقعی قرار دهید، این فهرست را مرور کنید. هر مورد
به صفحه‌ای پیوند دارد که آن را توضیح می‌دهد. صفحه‌های پلتفرم‌ها ([Docker](/fa/deploy/docker/)،
[Fly.io](/fa/deploy/fly/)، [Render](/fa/deploy/render/)، [Railway](/fa/deploy/railway/)،
[Kubernetes](/fa/deploy/kubernetes/)) تا جایی که بتوانند این تنظیمات را برای شما اعمال می‌کنند.

## اجرای سرور تولید

- [ ] **از `verdin start` استفاده کنید، نه `verdin dev`.** `dev` به سازندهٔ نوع محتوا اجازه می‌دهد
      فایل‌های طرح‌واره را بازنویسی کند، در هر تغییر مهاجرت‌ها را اعمال می‌کند و قواعد cookie و
      وب‌هوک را برای کار محلی آسان‌تر می‌کند. طرح‌واره را در محیط توسعه تغییر دهید، فایل‌ها را commit کنید،
      و آن‌ها را مستقر کنید.
- [ ] **مهاجرت‌ها را هنگام استقرار اعمال کنید.** `verdin start` تا وقتی پایگاه داده از
      طرح‌واره عقب باشد از اجرا خودداری می‌کند. `verdin start --migrate` ابتدا گام‌های *امن* در انتظار را
      اعمال می‌کند (این فرمان پیش‌فرض ایمیج Docker است). گام‌های پرخطر یا مخرب
      (تغییر نوع، قیدهای یکتایی جدید، حذف ستون‌ها) به
      `verdin migrate apply --allow risky|destructive` نیاز دارند که خودتان یک بار اجرا می‌کنید. بخش
      [مهاجرت طرح‌واره](/fa/concepts/schema-migrations/) را ببینید.
- [ ] **طرح‌واره را همراه سرور منتشر کنید.** پوشهٔ `schema/` را به‌صورت فقط‌خواندنی mount کنید، یا
      آن را درون ایمیج خود قرار دهید، تا آنچه اجرا می‌شود همان چیزی باشد که commit کرده‌اید.

## کلیدهای محرمانه

- [ ] **دو کلید محرمانهٔ الزامی را یک بار بسازید** با `verdin secrets` و آن‌ها را در
      مخزن secret پلتفرم خود نگه دارید: `VERDIN_ADMIN_JWT_SECRET` توکن‌های نشست را امضا می‌کند، و
      `VERDIN_TOKEN_PEPPER` کلید هش توکن‌های API و دیگر کلیدهای محرمانهٔ ذخیره‌شده است.
      اگر هر کدام وجود نداشته باشد یا کوتاه‌تر از 32 بایت باشد، `verdin start` شکست می‌خورد. کلیدهای محرمانه
      فقط از محیط خوانده می‌شوند، هرگز از `verdin.toml`.
- [ ] **آن‌ها را ثابت نگه دارید.** تغییر `VERDIN_TOKEN_PEPPER` باعث می‌شود همهٔ توکن‌های API از کار
      بیفتند، و همچنین کدهای برنامهٔ احراز هویت و کدهای بازیابی مدیران. تغییر
      `VERDIN_ADMIN_JWT_SECRET` توکن‌های دسترسی کوتاه‌مدت مدیران و کاربران نهایی، پیوندهای پیش‌نمایش باز
      و ورودهای OAuth در حال انجام را باطل می‌کند (پنل مدیریت و کلاینت‌هایی که توکن تازه‌سازی دارند،
      خودشان آن‌ها را تمدید می‌کنند). همهٔ
      نمونه‌های یک پروژه به مقادیر یکسان نیاز دارند.
- [ ] کلیدهای محرمانهٔ دیگری را که استفاده می‌کنید هم در محیط قرار دهید: `VERDIN_EMAIL_SMTP_PASSWORD`
      یا `VERDIN_EMAIL_API_KEY`، `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`،
      `VERDIN_METRICS_TOKEN`، `VERDIN_SSO_<ID>_SECRET`، `VERDIN_IMAGE_SECRET`. فهرست
      کامل در [مرجع پیکربندی](/fa/reference/configuration/) آمده است.

## پایگاه داده

- [ ] **موتور را انتخاب کنید.** PostgreSQL (نسخهٔ 14 یا بالاتر) انتخاب معمول است و همان گزینه‌ای است که
      اگر [چند نمونه](/fa/deploy/scaling/) اجرا می‌کنید باید برگزینید. MySQL 8.4+ و MariaDB
      10.11+ به همان شکل کار می‌کنند. SQLite برای یک نمونهٔ واحد با دیسک پایدار مناسب است.
- [ ] **`VERDIN_DATABASE_URL` را تنظیم کنید**: `postgres://…`، `mysql://…` (MySQL و MariaDB) یا
      `sqlite:///data/verdin.db`. برای سرورهای PostgreSQL که به TLS نیاز دارند `?sslmode=require` را
      اضافه کنید.
- [ ] **اندازهٔ pool را تعیین کنید.** هر نمونه تا `[database].pool_max` اتصال (10) باز می‌کند.
      `instances × pool_max` را زیر حد اتصال سرور نگه دارید.

## URLها، proxyها و cookieها

- [ ] **روی HTTPS سرویس دهید.** Verdin با HTTP ساده کار می‌کند؛ TLS را در یک reverse proxy،
      load balancer یا لبهٔ پلتفرم خود خاتمه دهید.
- [ ] **`[server].public_url` را تنظیم کنید** (`VERDIN_SERVER__PUBLIC_URL`) روی نشانی‌ای که مرورگرها
      استفاده می‌کنند، مانند `https://cms.example.com`. پیوندهای ایمیل‌ها، callbackهای SSO، خلاصهٔ
      روزانه و کلیدهای دسترسی (passkey) به آن وابسته‌اند؛ کلیدهای دسترسی به host آن گره خورده‌اند.
- [ ] **`[server].trusted_proxies` را تنظیم کنید** روی نشانی‌های reverse proxyهای خود (IPها یا
      بازه‌های CIDR). فقط در این صورت Verdin نشانی کلاینت را از
      `X-Forwarded-For` می‌خواند؛ بدون آن، همهٔ کلاینت‌های پشت proxy برای محدودیت نرخ و
      گزارش‌های حسابرسی یک نشانی مشترک دارند.
- [ ] **cookieهای امن را روشن نگه دارید.** در `verdin start`، cookie بازآوری (refresh) مدیر به‌طور پیش‌فرض `Secure`
      است. `[admin].secure_cookies` را تنظیم‌نشده بگذارید؛ تنظیم آن روی `false` در
      محیط تولید هنگام شروع یک هشدار در لاگ ثبت می‌کند.

## APIها

- [ ] **فقط آنچه عموم لازم دارند را مجاز کنید.** API محتوا بسته است تا وقتی مجوزهای
      عمومی بدهید (**تنظیمات ← دسترسی عمومی**) یا توکن API بسازید. بخش
      [مجوزها](/fa/concepts/permissions/) را ببینید.
- [ ] **`[api].cors_origins` را تنظیم کنید** اگر مرورگری در origin دیگری API محتوا
      یا GraphQL را فراخوانی می‌کند، برای مثال `["https://www.example.com"]`. بدون آن، فقط
      صفحه‌های هم‌origin می‌توانند آن‌ها را از مرورگر فراخوانی کنند. API مدیریت هرگز به
      درخواست‌های cross-origin پاسخ نمی‌دهد.
- [ ] **محدودیت نرخ را در نظر بگیرید** برای ترافیک ناشناس: `[api].public_rate_limit` و
      `[api].token_rate_limit` (درخواست در دقیقه؛ `0`، مقدار پیش‌فرض، یعنی نامحدود).

## رسانه

- [ ] **بارگذاری‌ها را جایی ذخیره کنید که پس از استقرار دوباره باقی بمانند.** ارائه‌دهندهٔ محلی پیش‌فرض
      روی دیسک می‌نویسد: به آن یک volume پایدار بدهید، یا از ارائه‌دهندهٔ S3 استفاده کنید (AWS S3، Cloudflare
      R2، Backblaze B2، MinIO، Tigris…). روی پلتفرم‌هایی با دیسک ناپایدار، و با
      چند نمونه، از S3 استفاده کنید. بخش [رسانه](/fa/concepts/media/) را ببینید.

## ایمیل

- [ ] **یک ارائه‌دهندهٔ واقعی پیکربندی کنید.** مقدار پیش‌فرض `[email].provider = "log"` ایمیل‌ها را
      در لاگ می‌نویسد و `verdin start` دربارهٔ آن هشدار می‌دهد. دعوت‌نامه‌ها، بازنشانی گذرواژه،
      تأیید کاربران نهایی، اشاره‌ها در نظرها و خلاصهٔ روزانه به `smtp`، `resend` یا
      `postmark` نیاز دارند، و `[email].from` باید روی نشانی‌ای تنظیم شود که ارائه‌دهندهٔ شما می‌پذیرد.

## پشتیبان‌گیری و پایش

- [ ] **از پایگاه داده و ذخیره‌سازی رسانه نسخهٔ پشتیبان بگیرید** طبق یک زمان‌بندی، و یک بازیابی را امتحان کنید.
      بخش [پشتیبان‌گیری](/fa/deploy/backups/) را ببینید.
- [ ] **بررسی‌های سلامت را به `/_ready`** و بررسی‌های liveness را به `/_health` هدایت کنید.
- [ ] **لاگ را به‌صورت JSON بنویسید** (`[log].format = "json"`، پیش‌فرض ایمیج Docker) و
      standard error را جمع‌آوری کنید.
- [ ] **از `/_metrics` scrape کنید** اگر از Prometheus استفاده می‌کنید، با یک `VERDIN_METRICS_TOKEN`. بخش
      [پایش](/fa/deploy/monitoring/) را ببینید.

## پیش از راه‌اندازی عمومی

- [ ] نخستین مدیر را بلافاصله پس از نخستین اجرا خودتان ثبت کنید: تا وقتی هیچ مدیری
      وجود ندارد، هر کسی که به `/admin/` برسد می‌تواند به‌عنوان مدیر ارشد ثبت‌نام کند. همچنین می‌توانید
      آن را از خط فرمان با `verdin admin create --email …` بسازید.
- [ ] [مدل امنیتی](/fa/deploy/security/) را مرور کنید و
      [تأیید دومرحله‌ای](/fa/guides/auth/two-factor/) را برای مدیران ارشد روشن کنید.
