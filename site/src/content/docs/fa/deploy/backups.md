داده‌های یک پروژهٔ Verdin در دو جا نگهداری می‌شود: **پایگاه داده** (محتوا، مدیران، نقش‌ها،
توکن‌ها، تنظیمات، تاریخچه، گزارش‌های حسابرسی) و **ذخیره‌سازی رسانه** (فایل‌های
کتابخانهٔ رسانه، روی دیسک یا در یک باکت). فایل‌های طرح‌واره (schema) در مخزن شما هستند. از
هر دو ذخیره‌گاه نسخهٔ پشتیبان بگیرید؛ `verdin export` یک آرشیو قابل‌حمل از محتوا هم به آن اضافه می‌کند.

| روش | شامل | کاربرد |
| --- | --- | --- |
| dump پایگاه داده + کپی رسانه | همه‌چیز | بازیابی پس از فاجعه برای همان پروژه |
| `verdin export` | طرح‌واره، زبان‌ها، رسانه، همهٔ نسخه‌های همهٔ مدخل‌ها | انتقال محتوا به نمونه یا موتور پایگاه دادهٔ دیگر؛ یک نسخهٔ اضافی و قابل‌حمل |

## dump پایگاه داده

از ابزارهای خود پایگاه داده یا پشتیبان‌گیری خودکار ارائه‌دهندهٔ خود استفاده کنید:

```sh frame="terminal"
# PostgreSQL
pg_dump --format=custom --file=verdin-$(date +%F).dump "$VERDIN_DATABASE_URL"

# MySQL / MariaDB
mysqldump --single-transaction --routines -h <host> -u <user> -p <database> > verdin-$(date +%F).sql

# SQLite: یک کپی سازگار در حالی که سرور در حال اجراست
sqlite3 /data/verdin.db ".backup '/backups/verdin-$(date +%F).db'"
```

یک فایل SQLite در حال استفاده را با `cp` کپی نکنید: از `.backup` استفاده کنید (یا ابتدا سرور را متوقف کنید).

یک dump شامل هش گذرواژه‌ها، هش توکن‌های API و فیلدهای خصوصی است. آن را رمزنگاری کنید و
دور از سرورهایی که از آن‌ها محافظت می‌کند نگه دارید. برای بازیابی آن، همان
`VERDIN_TOKEN_PEPPER` و `VERDIN_ADMIN_JWT_SECRET` را هم لازم دارید: بدون pepper، توکن‌های API و
کدهای برنامهٔ احراز هویت مدیران دیگر کار نمی‌کنند.

## ذخیره‌سازی رسانه

- **ارائه‌دهندهٔ محلی**: پوشهٔ بارگذاری (`[upload].provider.dir`،
  `/data/uploads` در ایمیج Docker) را با پشتیبان‌گیری فایل معمول خود کپی کنید، پس از dump
  پایگاه داده، تا هیچ فایلی که dump به آن ارجاع می‌دهد جا نیفتد.
- **ارائه‌دهندهٔ S3**: نسخه‌بندی (versioning) یا تکثیر (replication) را روی باکت روشن کنید، یا آن را با
  ابزارهای ارائه‌دهندهٔ خود کپی کنید.

کش تبدیل تصویر و نمایهٔ جستجو قابل بازسازی هستند و به نسخهٔ پشتیبان نیاز ندارند.

## `verdin export`

`verdin export` طرح‌واره، محتوا و رسانهٔ یک پروژه را در یک فایل `.tar.gz` می‌نویسد، و
`verdin import verdin` آن را در همان پروژه یا نمونه‌ای دیگر، روی هر
موتور پایگاه داده‌ای، بازیابی می‌کند.

```sh frame="terminal"
verdin export backup-2026-09-28.tar.gz            # طرح‌واره، زبان‌ها، رسانه و مدخل‌ها
verdin export content-only.tar.gz --no-media      # بدون فایل‌های رسانه
verdin import verdin backup-2026-09-28.tar.gz     # به این پروژه
```

آن‌ها را با پیکربندی پروژه اجرا کنید (همان `verdin.toml` و محیطی که
سرور دارد). در یک کانتینر: `docker compose exec verdin verdin export /data/backup.tar.gz`.

### چه چیزهایی شامل می‌شود

- **فایل‌های طرح‌واره**، همان‌طور که هستند.
- **زبان‌ها.** یک پروژهٔ خالی همهٔ آن‌ها را می‌گیرد، از جمله زبان پیش‌فرض. پروژه‌ای
  که زبان دارد فقط زبان‌های غایب را می‌گیرد.
- **پوشه‌ها و فایل‌های رسانه**، همراه با قالب‌های واکنش‌گرای (responsive) آن‌ها. فایل‌ها
  `documentId` خود را حفظ می‌کنند؛ شناسه‌های عددی آن‌ها تغییر می‌کند.
- **همهٔ نسخه‌های همهٔ مدخل‌ها**: پیش‌نویس‌ها، نسخه‌های منتشرشده و همهٔ زبان‌ها، همراه با
  تاریخ‌ها، روابط (بر اساس `documentId`) و رسانهٔ آن‌ها، از جمله روابط و رسانهٔ
  درون کامپوننت‌ها و ناحیه‌های پویا. فیلدهای خصوصی و هش گذرواژه‌ها هم شامل می‌شوند.

**شامل نمی‌شود**: کاربران مدیر، نقش‌ها، توکن‌های API، وب‌هوک‌ها، تنظیمات قابلیت‌ها، گردش‌کارهای
بازبینی و بسته‌های انتشار. آن‌ها را در مقصد دوباره بسازید، یا به‌جای آن یک dump پایگاه داده
را بازیابی کنید.

:::caution
یک خروجی شامل فیلدهای خصوصی و هش گذرواژه‌هاست. آن را مانند یک dump پایگاه داده نگهداری کنید.
:::

### درون‌ریزی

1. درون‌ریزی فایل‌های طرح‌واره را می‌نویسد و پایگاه داده را فقط با گام‌های امن مهاجرت می‌دهد.
2. اگر فایل‌های طرح‌واره از قبل وجود داشته باشند و متفاوت باشند، درون‌ریزی متوقف می‌شود، مگر اینکه `--force` بدهید.
3. نوع‌های محتوایی که از قبل مدخل دارند هم آن را متوقف می‌کنند، مگر اینکه
   `--force` بدهید؛ در این صورت مدخل‌ها کنار مدخل‌های موجود اضافه می‌شوند.
4. سندهای درون‌ریزی‌شده `documentId` خود را حفظ می‌کنند، بنابراین درون‌ریزی در پروژه‌ای که از قبل
   همان سندها را دارد شکست می‌خورد.

درون‌ریزی وب‌هوک‌ها یا هوک‌های افزونه را فعال نمی‌کند و تاریخچه نمی‌نویسد.

### قالب آرشیو

یک آرشیو tar فشرده‌شده با gzip:

| مسیر | محتوا |
| --- | --- |
| `manifest.json` | `format: "verdin-export"`، نسخهٔ قالب، نسخهٔ Verdin، نسخه‌ها برای هر نوع محتوا |
| `schema/…` | فایل‌های طرح‌واره |
| `locales.json` | `{ default, locales: [{ code, name }] }` |
| `folders.json`، `files.jsonl` | پوشه‌ها و فایل‌های رسانه، یک شیء JSON در هر خط |
| `assets/{hash}{ext}` | اشیای ذخیره‌شدهٔ فایل‌ها و قالب‌های آن‌ها |
| `entries/{uid}.jsonl` | یک نسخه در هر خط: `documentId`، `locale`، `published`، تاریخ‌ها، `data`، `relations`، `media` |

برای آوردن یک پروژهٔ Strapi، [مهاجرت از Strapi](/fa/migrate/from-strapi/) را ببینید.

## بازیابی‌های خود را تست کنید

هر از گاهی در یک پایگاه دادهٔ آزمایشی بازیابی کنید،
Verdin را با `verdin start` روی آن اجرا کنید، و بررسی کنید که می‌توانید وارد شوید و مدخل‌ها
و رسانه را بخوانید.
