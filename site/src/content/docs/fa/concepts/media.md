کتابخانهٔ رسانه تصویرها، ویدیوها، صداها و دیگر فایل‌هایی را که محتوای شما استفاده می‌کند نگه
می‌دارد. این صفحه توضیح می‌دهد فایل‌ها چگونه ذخیره، توصیف و به سندها پیوند داده می‌شوند. برای
ارائهٔ تصویرهای تغییراندازه‌یافته در سایت خود، نگاه کنید به [تصویرها](/fa/guides/frontend/images/).

## فایل‌ها

هر بارگذاری یک رکورد فایل با شکل Strapi است، بنابراین فرانت‌اندهایی که برای Strapi نوشته
شده‌اند آن را بدون تغییر می‌خوانند (`formats` خلاصه شده است):

```json
{
  "id": 5,
  "documentId": "v3k…",
  "name": "harbour.jpg",
  "alternativeText": "Boats in the harbour at dawn",
  "caption": null,
  "width": 2400,
  "height": 1600,
  "focalPoint": { "x": 0.4, "y": 0.6 },
  "formats": {
    "thumbnail": { "url": "/uploads/harbour_thumbnail_4f1c.jpg", "width": 234, "height": 156 },
    "large": { "url": "/uploads/harbour_large_4f1c.jpg", "width": 1000, "height": 667 }
  },
  "hash": "harbour_4f1c",
  "ext": ".jpg",
  "mime": "image/jpeg",
  "size": 812.4,
  "url": "/uploads/harbour_4f1c.jpg",
  "previewUrl": null,
  "provider": "local",
  "provider_metadata": null,
  "createdAt": "2026-09-25T09:00:00.000Z",
  "updatedAt": "2026-09-25T09:00:00.000Z",
  "publishedAt": "2026-09-25T09:00:00.000Z"
}
```

- `size` بر حسب کیلوبایت است، مانند Strapi.
- نوع MIME از بایت‌های فایل به دست می‌آید، هرگز از آنچه کلاینت ادعا می‌کند.
- `focalPoint` بخشی از تصویر را مشخص می‌کند که هنگام برش باید در دید بماند.

فایل‌ها پیش‌نویس ندارند: یک بارگذاری به محض ذخیره شدن در دسترس است.

## کتابخانهٔ رسانه

در پنل مدیریت، **کتابخانهٔ رسانه** فایل‌ها را با جستجو، فیلتر بر اساس نوع و پوشه‌ها فهرست
می‌کند. مدیران فایل بارگذاری می‌کنند، آن‌ها را از یک URL درون‌ریزی می‌کنند، نام، متن جایگزین،
زیرنویس و نقطهٔ کانونی آن‌ها را ویرایش می‌کنند، محتوای یک فایل را با حفظ شناسه‌اش جایگزین
می‌کنند، و می‌بینند **کجا استفاده شده است**: فیلدهای رسانه، رسانه درون کامپوننت‌ها، بلوک‌های
متن غنی و Markdownی که URL آن را در بر دارد.

**پوشه‌ها** کتابخانه را برای ویرایشگران سازمان‌دهی می‌کنند. اشیای فایل در پاسخ‌های API آن‌ها را
نشان نمی‌دهند، اما یک بارگذاری از طریق content API می‌تواند شناسهٔ یک پوشه را در `fileInfo`
خود نام ببرد. حذف یک پوشه فایل‌های درون آن را حذف می‌کند.

دسترسی مدیران با مجوزهای `media.read`، `media.create`، `media.update` و `media.delete` کنترل
می‌شود. نقش داخلی Author فقط می‌تواند فایل‌هایی را که خودش بارگذاری کرده ویرایش و حذف کند.
نگاه کنید به [مجوزها](/fa/concepts/permissions/).

## فیلدهای رسانه

یک نوع محتوا فایل‌ها را از طریق ویژگی `media` پیوند می‌دهد:

```json
"cover": { "type": "media", "allowedTypes": ["images"] },
"gallery": { "type": "media", "multiple": true, "allowedTypes": ["images", "videos"] }
```

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| `multiple` | `false` | به جای یک فایل، فهرستی از فایل‌ها نگه می‌دارد. |
| `allowedTypes` | هر فایلی | هر یک از `images`، `videos`، `audios` و `files` (هر چیز دیگر) که در هر نوشتن با نوع MIME ذخیره‌شده بررسی می‌شود. |

فیلدهای رسانه مانند روابط رفتار می‌کنند: هر نسخه از یک سند پیوندهای خودش را دارد، انتشار آن‌ها
را کپی می‌کند و `required` هنگام انتشار بررسی می‌شود. این فیلدها در یک جدول پیوند به ازای هر
فیلد ذخیره می‌شوند. درون [کامپوننت‌ها](/fa/concepts/components-and-dynamic-zones/)، JSON
کامپوننت به جای آن شناسهٔ فایل‌ها را ذخیره می‌کند.

در نوشتن، شناسهٔ فایل‌ها را بفرستید: `5`، `{ "id": 5 }`، `[5, 6]`، یا `null` برای پاک کردن
فیلد. در خواندن، فیلدهای رسانه فقط وقتی populate شوند (`populate=cover`) و به شکل اشیای فایل
برگردانده می‌شوند. حذف یک فایل آن را از هر سندی که از آن استفاده می‌کرد حذف می‌کند.

## قالب‌های تصویر

وقتی یک تصویر رستری بارگذاری می‌شود، Verdin قالب‌های Strapi را در قالب خودِ تصویر و با رعایت
جهت EXIF آن تولید می‌کند:

| قالب | اندازه |
| --- | --- |
| `thumbnail` | در ابعاد 245 × 156 جا می‌شود |
| `large` | عرض 1000 px |
| `medium` | عرض 750 px |
| `small` | عرض 500 px |

اگر تصویر اصلی بزرگ‌تر از یک قالب نباشد، آن قالب ساخته نمی‌شود. `[upload].breakpoints` عرض‌ها و
نام‌ها را تغییر می‌دهد و `responsive_formats = false` آن‌ها را خاموش می‌کند.
`max_original_size` تصویرهای اصلی بزرگ را هنگام بارگذاری کوچک می‌کند، که فراداده‌هایشان
(EXIF، GPS) را هم حذف می‌کند. `max_image_megapixels` (به‌طور پیش‌فرض 100) تصویرهایی را که
رمزگشایی‌شان حافظهٔ زیادی می‌گیرد رد می‌کند. با ارائه‌دهندهٔ محلی، `/uploads` می‌تواند تصویرها
را در صورت درخواست تغییر اندازه دهد و تبدیل کند؛ نگاه کنید به
[تصویرها](/fa/guides/frontend/images/).

## ارائه‌دهندگان ذخیره‌سازی

فایل‌ها توسط یک ارائه‌دهنده ذخیره می‌شوند که در `[upload].provider` تعیین می‌شود:

| ارائه‌دهنده | فایل‌ها را کجا ذخیره می‌کند | از کجا ارائه می‌کند |
| --- | --- | --- |
| `local` (پیش‌فرض) | در `public/uploads` (گزینهٔ `dir`)، نسبت به پروژه | در `/uploads` روی سرور Verdin |
| `s3` | در هر bucket سازگار با S3: AWS S3، Cloudflare R2، Backblaze B2، MinIO، RustFS… | از `public_url` مربوط به bucket یا CDN |

```toml title="verdin.toml"
[upload]
provider = { name = "s3", bucket = "media", region = "auto",
             endpoint = "https://<account>.r2.cloudflarestorage.com",
             public_url = "https://media.example.com" }
```

اعتبارنامه‌های S3 از متغیرهای محیطی استاندارد `AWS_*` می‌آیند، هرگز از `verdin.toml`. همهٔ
گزینه‌ها در [مرجع پیکربندی](/fa/reference/configuration/) آمده‌اند.

نام‌های ذخیره‌شده به شکل `{slug}_{random}{ext}` هستند و هرگز تغییر نمی‌کنند، بنابراین URLها
می‌توانند برای همیشه کش شوند. با چند نمونهٔ Verdin، از S3 استفاده کنید: فایل‌های محلی فقط روی
نمونه‌ای وجود دارند که آن‌ها را دریافت کرده است.

## ایمنی

- بارگذاری‌ها به‌صورت جریانی در فایل‌های موقت نوشته می‌شوند، هرگز در حافظه نگه داشته نمی‌شوند،
  و با `[upload].max_file_size` (به‌طور پیش‌فرض 200 MB) محدود می‌شوند، با حداکثر 20 فایل در
  هر درخواست.
- فایل‌هایی که از `/uploads` ارائه می‌شوند `Content-Security-Policy: sandbox` و
  `X-Content-Type-Options: nosniff` دارند. هر چیزی که تصویر، ویدیو، صدا، PDF یا متن ساده
  نباشد به‌صورت دانلود فرستاده می‌شود، بنابراین یک فایل HTML یا SVG بارگذاری‌شده نمی‌تواند روی
  دامنهٔ شما اسکریپت اجرا کند. اشیای این نوع‌ها در S3 هم به‌صورت دانلود ذخیره می‌شوند.

## رسانه از طریق content API

content API مسیرهای بارگذاری Strapi را دارد که با مجوزهای **کتابخانهٔ رسانه**
(`plugin::upload`) بررسی می‌شوند:

| مسیر | مجوز |
| --- | --- |
| `POST /api/upload` (multipart `files`، `fileInfo` اختیاری) | `create` |
| `POST /api/upload?id={id}` (`fileInfo` جدید، و در صورت تمایل یک فایل جدید) | `update` |
| `GET /api/upload/files` | `find` |
| `GET /api/upload/files/{id}` | `findOne` |
| `DELETE /api/upload/files/{id}` | `delete` |

مانند Strapi، این مسیرها اشیای فایل و آرایه‌های ساده را بدون پوشش `data` برمی‌گردانند. نگاه
کنید به [REST API](/fa/api/rest/#کتابخانهٔ-رسانه). تغییرات رویدادهای `media.create`،
`media.update` و `media.delete` را به‌صورت رویدادهای [وب‌هوک](/fa/api/webhooks/) و
[بلادرنگ](/fa/api/realtime/) می‌فرستند.
