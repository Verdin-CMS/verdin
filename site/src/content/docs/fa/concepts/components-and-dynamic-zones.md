کامپوننت‌ها به شما امکان می‌دهند یک گروه فیلد را در چند نوع محتوا دوباره به کار ببرید، و
ناحیه‌های پویا (dynamic zone) به ویرایشگران امکان می‌دهند یک صفحه را از فهرستی از بلوک‌ها بسازند.
این صفحه توضیح می‌دهد هر دو چگونه مدل و ذخیره می‌شوند و این موضوع چه اثری بر خواندن، نوشتن و
فیلتر کردن آن‌ها دارد. خودِ قالب طرح‌واره (schema) در [مدل محتوا](/fa/concepts/content-model/)
آمده است.

## کامپوننت‌ها

کامپوننت گروهی از فیلدهاست که فایل خودش را در `schema/components/<category>/` دارد.
کامپوننت `shared.seo` در مثال وبلاگ یک عنوان متا و یک توضیح متا نگه می‌دارد:

```json title="schema/components/shared/seo.json"
{
  "displayName": "SEO",
  "attributes": {
    "metaTitle": { "type": "string", "maxLength": 60 },
    "metaDescription": { "type": "text", "maxLength": 160 }
  }
}
```

یک نوع محتوا از طریق ویژگی `component` از آن استفاده می‌کند. `repeatable: true` آن را به
فهرست تبدیل می‌کند و می‌توان تعداد آیتم‌ها را با `min` و `max` محدود کرد:

```json
"seo": { "type": "component", "component": "shared.seo" },
"links": { "type": "component", "component": "shared.link", "repeatable": true, "max": 10 }
```

کامپوننت‌ها می‌توانند کامپوننت‌های دیگری را در بر بگیرند. یک کامپوننت نمی‌تواند خودش را، به‌طور
مستقیم یا از طریق کامپوننت‌های دیگر، در بر بگیرد؛ بررسی طرح‌واره چنین چرخه‌هایی را رد می‌کند.

## ناحیه‌های پویا

ناحیهٔ پویا فهرستی است که آیتم‌هایش می‌توانند هر یک از کامپوننت‌هایی باشند که نام می‌برد.
بدنهٔ مقاله در وبلاگ، heroها و نقل‌قول‌ها را با هم ترکیب می‌کند:

```json
"blocks": { "type": "dynamiczone", "components": ["blocks.hero", "blocks.quote"], "max": 20 }
```

هر آیتم در `__component` مشخص می‌کند کدام کامپوننت است. `min` و `max` تعداد آیتم‌ها را
محدود می‌کنند. ناحیه‌های پویا فقط به نوع‌های محتوا تعلق دارند: یک کامپوننت نمی‌تواند ناحیهٔ
پویا داشته باشد.

## ذخیره به‌صورت JSON

Verdin مقدار یک کامپوننت یا ناحیهٔ پویا را در یک ستون JSON از ردیف سند ذخیره می‌کند
(`jsonb` در PostgreSQL، `json` در MySQL و MariaDB، و متن در SQLite):

```json
// the "seo" column
{ "id": 1, "metaTitle": "Rust for CMS authors", "metaDescription": "…" }

// the "blocks" column
[
  { "__component": "blocks.hero", "id": 1, "title": "Hello", "subtitle": "…" },
  { "__component": "blocks.quote", "id": 2, "text": "…", "author": "Ferris" }
]
```

Strapi هر کامپوننت را در جدول جداگانهٔ خودش نگه می‌دارد که از طریق جدول‌های پیوند چندریختی
(polymorphic) متصل می‌شوند. ذخیرهٔ مقدار همراه با سند به این معناست که:

- خواندن یک سند همراه با کامپوننت‌هایش به هیچ join نیازی ندارد، هر قدر هم که تودرتو باشند.
- انتشار، کنار گذاشتن پیش‌نویس و [تاریخچهٔ محتوا](/fa/guides/content/content-history/)
  مقدار را همان‌طور که هست کپی می‌کنند.
- افزودن یک فیلد به کامپوننت هیچ جدولی را تغییر نمی‌دهد: مهاجرت خالی است.
- فیلتر روی فیلدهای کامپوننت از توابع JSON هر پایگاه داده استفاده می‌کند و برخی فیلترها
  در دسترس نیستند (نگاه کنید به [فیلتر کردن](#فیلتر-کردن)).

هر آیتم یک `id` دارد، یک عدد صحیح مثبت که در مقدار آن ویژگی یکتاست. Verdin به آیتم‌های جدید
یک `id` اختصاص می‌دهد؛ هنگام به‌روزرسانی یک فهرست، `id` را برگردانید تا آیتم‌ها پایدار بمانند.

## روابط و رسانه درون کامپوننت‌ها

یک کامپوننت می‌تواند روابط و رسانه داشته باشد که در خودِ JSON ذخیره می‌شوند: `documentId`ها
برای روابط و شناسهٔ فایل‌ها برای رسانه.

- روابط درون کامپوننت‌ها باید `oneWay` یا `manyWay` باشند: به هدف‌هایشان اشاره می‌کنند و
  سمت معکوس ندارند. نگاه کنید به [روابط](/fa/concepts/relations/#روابط-درون-کامپوننتها).
- هر ارجاع هنگام نوشتن بررسی می‌شود: سند یا فایل هدف باید وجود داشته باشد و فایل‌ها باید با
  `allowedTypes` فیلد مطابقت داشته باشند.
- وقتی کامپوننت populate می‌شود، ارجاع‌ها با کوئری‌های دسته‌ای و در همان وضعیت و زبان سند
  resolve می‌شوند. هدفی که حذف شده، یا در وضعیت و زبانی که خوانده می‌شود نسخه‌ای ندارد،
  کنار گذاشته می‌شود.
- روابط چندریختی (`morphToOne`، `morphToMany`) و فیلدهای `password` نمی‌توانند درون
  کامپوننت‌ها باشند.

## خواندن

کامپوننت‌ها و ناحیه‌های پویا فقط وقتی برگردانده می‌شوند که آن‌ها را populate کنید، مانند Strapi:

```http
GET /api/articles?populate[0]=seo&populate[1]=blocks
GET /api/articles?populate=*
```

کامپوننت populateشده به‌طور کامل برمی‌گردد، همراه با کامپوننت‌های تودرتو و روابط و رسانه‌های
resolveشده. Strapi برای هر کامپوننت تودرتو به یک سطح `populate` نیاز دارد؛ Verdin این
گزینه‌های تودرتو را برای سازگاری می‌پذیرد و نادیده می‌گیرد. آیتم‌های ناحیهٔ پویا به ترتیب
ذخیره‌شده‌شان و هر کدام با `__component` خود برمی‌گردند.

در GraphQL، یک کامپوننت یک نوع شیء است که نامش از UID آن گرفته می‌شود (`ComponentSharedSeo`)
و یک ناحیهٔ پویا یک union است (`ArticleBlocksDynamicZone`) که با fragmentها کوئری می‌شود.
نگاه کنید به [GraphQL API](/fa/api/graphql/).

## نوشتن

کل مقدار ویژگی را بفرستید. این مقدار جایگزین چیزی می‌شود که ذخیره شده بود:

```json
{
  "data": {
    "seo": { "metaTitle": "Rust for CMS authors" },
    "blocks": [
      { "__component": "blocks.hero", "title": "Hello" },
      { "__component": "blocks.quote", "text": "Fast and small.", "author": "Ferris" }
    ]
  }
}
```

مقدار در هر نوشتن با طرح‌وارهٔ کامپوننت اعتبارسنجی می‌شود: کلیدهای ناشناخته، نوع‌های نادرست
و `__component`ای که ناحیهٔ پویا مجاز نمی‌داند، خطا هستند و مسیرهایی مانند
`["blocks", 1, "text"]` دارند. فیلدهای `required` درون کامپوننت‌ها هنگام انتشار سند بررسی
می‌شوند، درست مانند فیلدهای سطح بالا.

## فیلتر کردن

| چه چیزی | مثال | نکته‌ها |
| --- | --- | --- |
| فیلدهای یک کامپوننت | `filters[seo][metaTitle][$containsi]=rust` | فیلدهای اسکالر، از جمله کامپوننت‌های تودرتو. |
| فیلدهای یک کامپوننت تکرارشونده | `filters[links][url][$contains]=github` | وقتی یکی از آیتم‌ها مطابقت داشته باشد، مطابقت دارد. |
| ناحیه‌های پویا | `filters[blocks][__component][$eq]=blocks.quote` | فقط بر اساس `__component`: آیتم‌های کامپوننت‌های مختلف فیلدهای متفاوتی دارند. |

نمی‌توانید بر اساس فیلدهای کامپوننت مرتب‌سازی کنید، و فیلدهای `json` درون کامپوننت‌ها قابل
فیلتر نیستند. برای عملگرها نگاه کنید به [REST API](/fa/api/rest/#فیلترها).
