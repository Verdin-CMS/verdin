بین‌المللی‌سازی (i18n) محتوای یک سند را به چند زبان نگه می‌دارد. این صفحه مدل را توضیح می‌دهد:
زبان‌ها (locale)، فیلدهای بومی‌سازی‌شده و مشترک، و اینکه خواندن‌ها و نوشتن‌ها چگونه یک زبان را
انتخاب می‌کنند. برای روند کار ویرایشگر، نگاه کنید به
[بومی‌سازی محتوا](/fa/guides/content/localizing-content/).

## زبان‌ها

زبان‌های پروژه در **تنظیمات ← بین‌المللی‌سازی** فهرست شده‌اند (مجوز `locales.manage`). نخستین
اجرا انگلیسی (`en`) را به‌عنوان زبان پیش‌فرض اضافه می‌کند.

- همیشه یک زبان پیش‌فرض است. درخواست‌هایی که زبانی را نام نمی‌برند از آن استفاده می‌کنند و
  نمی‌توان آن را حذف کرد.
- کدها یک زبان دو یا سه حرفی با حروف کوچک هستند که می‌توانند زیربرچسب‌هایی به دنبال داشته
  باشند: `en`، `fr`، `pt-BR`، `zh-Hans`.

:::caution
حذف یک زبان همهٔ نسخه‌هایی را هم که به آن زبان نوشته شده‌اند حذف می‌کند.
:::

## نوع‌های محتوای بومی‌سازی‌شده

یک نوع محتوا وقتی بومی‌سازی‌شده است که طرح‌واره‌اش چنین بگوید. آنگاه هر سند برای هر زبان یک
نسخه دارد و همهٔ آن‌ها در `documentId` مشترک‌اند:

```json title="schema/content-types/article.json (excerpt)"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

با [پیش‌نویس و انتشار](/fa/concepts/draft-and-publish/)، هر زبان پیش‌نویس و نسخهٔ منتشرشدهٔ
خودش را دارد، بنابراین ترجمهٔ فرانسوی می‌تواند پیش یا پس از متن انگلیسی منتشر شود. نوع‌های
بدون `pluginOptions.i18n.localized` بومی‌سازی‌شده نیستند و پارامترهای `locale` را نادیده
می‌گیرند.

## چه چیزی بومی‌سازی می‌شود

در یک نوع بومی‌سازی‌شده، هر ویژگی بومی‌سازی‌شده است مگر اینکه
`"pluginOptions": { "i18n": { "localized": false } }` داشته باشد. چنین فیلد **مشترکی** برای کل
سند یک مقدار دارد:

- ذخیرهٔ یک فیلد مشترک در یک زبان، آن را در پیش‌نویس‌های همهٔ زبان‌ها می‌نویسد.
- انتشار یک زبان، فیلدهای مشترک آن را به نسخه‌های منتشرشدهٔ زبان‌های دیگر کپی می‌کند.
- این دربارهٔ روابط و رسانه هم صدق می‌کند: یک رابطهٔ مشترک در همهٔ زبان‌ها به همان سندها
  پیوند می‌دهد.

فیلدهای سیستمی از نسخه پیروی می‌کنند: هر زبان `createdAt`، `updatedAt` و `publishedAt` خودش را
دارد. مقدارهای `unique` و `uid` به ازای هر زبان یکتا هستند، بنابراین دو ترجمه می‌توانند یک
slug مشترک داشته باشند.

## روابط میان نوع‌های بومی‌سازی‌شده

روابط سندها را به هم پیوند می‌دهند، نه نسخه‌ها را (نگاه کنید به
[روابط](/fa/concepts/relations/#پیوند-با-سند-نه-با-ردیف))، بنابراین زبان هنگام خواندن
انتخاب می‌شود:

- وقتی هر دو نوع بومی‌سازی‌شده باشند، مقالهٔ فرانسوی نسخهٔ فرانسوی دسته‌اش را نشان می‌دهد.
  فیلترهایی که از طریق رابطه اعمال می‌شوند در همان زبان تطبیق داده می‌شوند.
- وقتی نوع هدف بومی‌سازی‌شده نباشد، همهٔ زبان‌ها همان هدف را می‌بینند.

## انتخاب زبان در APIها

REST و Admin API پارامتر کوئری `locale` را در قالب Strapi v5 می‌گیرند؛ GraphQL یک آرگومان
`locale` می‌گیرد:

```http
GET /api/articles?locale=fr
PUT /api/articles/{documentId}?locale=fr
DELETE /api/articles/{documentId}?locale=fr
```

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
  }
}
```

- بدون `locale`، درخواست‌ها زبان پیش‌فرض را می‌خوانند و می‌نویسند.
- یک `PUT` در زبانی که سند هنوز ندارد، آن نسخه را می‌سازد.
- یک `DELETE` فقط نسخهٔ زبان درخواست‌شده را حذف می‌کند. پیوندهایی که به سند اشاره می‌کنند
  وقتی هیچ زبانی باقی نماند حذف می‌شوند.
- پاسخ‌های REST برای نوع‌های بومی‌سازی‌شده شامل `locale` هستند. یک زبان ناشناخته خطای `400`
  است.
- بدنهٔ وب‌هوک‌ها، رویدادهای بلادرنگ و تاریخچهٔ محتوا زبان نسخه‌ای را که تغییر کرده ثبت
  می‌کنند.

## مجوزها به ازای هر زبان

نقش‌های مدیر می‌توانند مجوزهای محتوا را به برخی زبان‌ها محدود کنند، بنابراین یک ویرایشگر
فرانسوی فقط می‌تواند نسخه‌های فرانسوی را بخواند یا تغییر دهد. نگاه کنید به
[مجوزها](/fa/concepts/permissions/#مجوزهای-فیلد-و-زبان). مجوزهای content API (دسترسی عمومی،
توکن‌های API، نقش‌های کاربران نهایی) بر همهٔ زبان‌ها اعمال می‌شوند.

## مقایسه با Strapi

مدل و پارامترها با i18n در Strapi v5 مطابقت دارند: نوع‌های بومی‌سازی‌شده، فیلدهای
`localized: false`، `?locale=` و زبان پیش‌فرض. در Verdin، i18n بخشی از هسته و همیشه روشن
است: آن را برای هر نوع محتوا در طرح‌واره فعال می‌کنید.
