Администраторы — это люди, которые входят в админ-панель. Они отделены от
[конечных пользователей](/ru/guides/auth/end-users/) ваших сайтов и приложений. В этом
руководстве вы создадите первого администратора, пригласите остальных, выдадите им роли и
поможете вернуть доступ тем, кто его потерял.

## Перед началом

- Verdin нужны `VERDIN_ADMIN_JWT_SECRET` и `VERDIN_TOKEN_PEPPER` в окружении. Сгенерируйте их
  один раз через `verdin secrets`.
- Для управления администраторами нужно **Управление пользователями** (`users.manage`), для
  управления ролями — **Управление ролями** (`roles.manage`). См.
  [Разрешения](/ru/reference/permissions/).
- Приглашения и сброс пароля отправляются по почте через `[email]`. С провайдером `log` по
  умолчанию письма вместе со ссылками записываются в лог сервера.

## Создайте первого администратора

Откройте админ-панель (по умолчанию `http://localhost:1337/admin/`). Пока нет ни одного
администратора, она просит создать первого, и он становится Super Admin. Пароль — от 8 до 128
символов.

Без браузера используйте CLI или API:

<Tabs>
<TabItem label="CLI">

```sh title="Terminal"
verdin admin create --email you@example.com
```

Пароль берётся из `VERDIN_ADMIN_PASSWORD` или читается из стандартного ввода. Команда создаёт
Super Admin и работает в любой момент, а не только для первого администратора.

</TabItem>
<TabItem label="API">

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/register-first-admin \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a long password"}'
```

Этот маршрут работает, только пока нет ни одного администратора.

</TabItem>
</Tabs>

## Пригласите администратора

<Steps>

1. Откройте **Настройки → Пользователи** и выберите **Добавить пользователя**.
2. Введите email и, при желании, **Имя** и **Фамилию**.
3. Выберите одну или несколько **Ролей**.
4. Оставьте **Задать пароль сейчас** выключенным, чтобы отправить приглашение, или включите,
   чтобы задать пароль самостоятельно.
5. Выберите **Пригласить** (или **Сохранить**, если задали пароль).

</Steps>

Диалог **Ссылка-приглашение** показывает ссылку и сообщает, была ли она отправлена по почте.
Если нет — а с провайдером `log` это всегда так, — передайте её сами. Ссылка срабатывает один
раз и действует 7 дней; приглашённый администратор открывает её, выбирает пароль и входит в
систему.

Пока администратор ни разу не входил, **Новая ссылка-приглашение** в его строке заменяет
старую ссылку. После первого входа доступ восстанавливается через сброс пароля.

## Роли

Verdin создаёт три роли, как Strapi:

| Роль | Может |
| --- | --- |
| **Super Admin** | Всё. Её разрешения изменить нельзя. |
| **Editor** | Создавать, редактировать, публиковать и удалять весь контент; управлять медиатекой; запускать деплои; управлять SEO, редиректами, меню и формами. |
| **Author** | Создавать контент, а редактировать и удалять — только свои записи и файлы. Не может публиковать. |

Другие роли создаются в **Настройки → Роли** кнопкой **Новая роль**. Для каждой роли выберите:

- **Контент**: для каждого типа содержимого (или **Все типы содержимого**) уровень доступа для
  **Чтение**, **Создание**, **Изменение**, **Удаление** и **Публикация**: **Нет доступа**,
  **Свои** (только записи, созданные администратором) или **Все**. **Поля** ограничивают
  действие частью полей, а **Языки** — частью локалей.
- **Медиатека**: действия с файлами для **Все файлы** или **Свои файлы**.
- **Настройки**: доступ к разделам администрирования, например **Управление пользователями**
  или **Чтение журналов аудита**.
- **Требовать двухфакторную аутентификацию**: см.
  [Двухфакторная аутентификация](/ru/guides/auth/two-factor/).

Администратор с несколькими ролями получает объединение их разрешений. Полный список — в
[справочнике по разрешениям](/ru/reference/permissions/).

Только Super Admin может выдавать роль Super Admin, а также редактировать, удалять или
сбрасывать другого Super Admin.

## Деактивация и удаление администратора

Отредактируйте администратора в **Настройки → Пользователи** и выключите **Активен**:
неактивные пользователи не могут входить. **Удалить** удаляет учётную запись навсегда; тогда
её комментарии отображаются как написанные удалённым администратором.

## Сброс пароля

- **Администратор сбрасывает сам:** **Забыли пароль?** на странице входа отправляет по почте
  ссылку, которая действует один час. После смены пароля все сессии учётной записи
  завершаются.
- **Пароль задаёт другой администратор:** отредактируйте администратора в
  **Настройки → Пользователи** и введите новый пароль. Оставьте поле пустым, чтобы сохранить
  текущий.
- **С сервера:** когда никто не может войти, выполните

  ```sh title="Terminal"
  verdin admin reset-password --email you@example.com
  ```

  с паролем в `VERDIN_ADMIN_PASSWORD` или в стандартном вводе. Команда задаёт пароль,
  разблокирует учётную запись и завершает её сессии. Двухфакторную аутентификацию она не
  снимает: администратору, потерявшему второй фактор, нужен другой администратор, чтобы
  [сбросить его](/ru/guides/auth/two-factor/).

## Защита входа

- После 5 неверных паролей подряд учётная запись блокируется на 15 минут.
- Запросы входа, регистрации и обновления токена ограничены для каждого IP клиента параметром
  `[admin].auth_rate_limit` (по умолчанию 20 в минуту).
- Сессия администратора — это токен доступа на 15 минут, который обновляется с помощью
  refresh-cookie, действующей 30 дней. В `verdin start` cookie имеет флаг `Secure`; см.
  `[admin].secure_cookies`.

Каждый администратор видит свои устройства с выполненным входом в разделе **Сессии** своего
**Профиля** и может **Завершить сессию** на одном из них или на всех остальных. Смена пароля
завершает сессии на всех других устройствах.

## Admin API

Войдите, чтобы получить токен доступа к admin API:

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → { "data": { "user": {…}, "accessToken": "…", "accessTokenExpiresAt": "…" } }
```

| Маршрут | Разрешение | Что делает |
| --- | --- | --- |
| `GET /users`, `GET /users/{id}` | `users.manage` | Администраторы с их ролями. |
| `POST /users` | `users.manage` | `{ email, firstname?, lastname?, roles: [ids], isActive?, password? }`. Без `password` в `meta` ответа есть `inviteUrl` и `emailed`. |
| `PUT /users/{id}`, `DELETE /users/{id}` | `users.manage` | Изменить или удалить администратора. |
| `POST /users/{id}/invite` | `users.manage` | Новая ссылка-приглашение для администраторов, которые ни разу не входили. |
| `GET /roles`, `POST /roles`, `PUT /roles/{id}`, `DELETE /roles/{id}` | `roles.manage` | Роли и их разрешения. |
| `POST /auth/forgot-password` | публичный | `{ email }`. Всегда отвечает `204`. |
| `GET /auth/sessions`, `DELETE /auth/sessions/{id}` | выполнен вход | Ваши сессии. |

Все маршруты находятся под `/admin/api`. См. [admin API](/ru/api/admin/).

<Aside type="caution">
Секреты никогда не записываются в `verdin.toml`. Не меняйте оба секрета между перезапусками и
экземплярами: `VERDIN_ADMIN_JWT_SECRET` подписывает токены доступа, JWT конечных
пользователей и ссылки предпросмотра, а `VERDIN_TOKEN_PEPPER` защищает API-токены и вторые
факторы (см. [API-токены](/ru/guides/auth/api-tokens/)).
</Aside>
