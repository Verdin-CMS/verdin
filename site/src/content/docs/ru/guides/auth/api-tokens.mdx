API-токены позволяют вашим сайтам, приложениям и скриптам обращаться к content API с большим
доступом, чем у публики. В этом руководстве вы создадите токен, выберете его доступ,
воспользуетесь им и замените его в случае утечки. Токены работают как API-токены Strapi.

По умолчанию content API закрыт: без токена запросы получают только то, что разрешено в
**Настройки → Публичный доступ**, а там ничего нет, пока вы это не выдадите.

## Перед началом

- Для управления токенами нужно **Управление API-токенами** (`tokens.manage`). См.
  [Разрешения](/ru/reference/permissions/).
- Должен быть задан `VERDIN_TOKEN_PEPPER`; см. [Где важен pepper](#где-важен-pepper).

## Создайте токен

<Steps>

1. Откройте **Настройки → API-токены** и выберите **Создать токен**.
2. Введите **Название** и, при желании, **Описание**.
3. Выберите **Тип**:

   | Тип | Разрешает |
   | --- | --- |
   | **Только чтение** | Найти и Найти одну для всех типов содержимого, только опубликованные версии. |
   | **Полный доступ** | Все действия для всех типов содержимого и медиатеки. |
   | **Настраиваемый** | Только действия, отмеченные в **Разрешениях**. |

4. Выберите, когда он **Истекает**: **Никогда** или через 7, 30 или 90 дней.
5. Для настраиваемого токена отметьте действия в **Разрешениях** для каждого типа содержимого:
   **Найти**, **Найти одну**, **Создать**, **Изменить**, **Удалить**, **Опубликовать** и
   **Читать черновики**. Строка **Медиатека** отвечает за загрузки, а строка **Пользователи** —
   за маршруты `/api/users` [конечных пользователей](/ru/guides/auth/end-users/).
6. Выберите **Создать** и скопируйте токен. Он показывается только один раз.

</Steps>

Токены начинаются с `vd_`. Список показывает первые символы каждого, время последнего
использования и срок действия.

## Используйте токен

Передавайте его как bearer-токен:

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
curl -H "Authorization: Bearer $VERDIN_TOKEN" 'http://localhost:1337/api/articles?status=draft'
```

</TabItem>
<TabItem label="GraphQL">

```sh title="Terminal"
curl -X POST http://localhost:1337/graphql \
  -H "Authorization: Bearer $VERDIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"query":"{ articles { documentId title } }"}'
```

</TabItem>
<TabItem label="TypeScript">

```ts
import { createClient } from '@verdin/client';
import type { VerdinSchema } from './verdin-types';

const verdin = createClient<VerdinSchema>({
  url: 'http://localhost:1337',
  token: process.env.VERDIN_TOKEN,
});
```

</TabItem>
</Tabs>

- Доступ токена заменяет публичный доступ, а не добавляется к нему. Настраиваемый токен без
  **Найти** для типа не может получить его список, даже если публике это разрешено.
- Для чтения черновиков (`?status=draft`) нужно **Читать черновики**; токены только для
  чтения никогда не видят черновики.
- Неизвестные и просроченные токены получают `401`. Действия за пределами доступа токена —
  `403`.
- `[api].token_rate_limit` ограничивает число запросов на токен в минуту (по умолчанию
  выключено).
- Те же токены авторизуют GraphQL и [MCP-сервер](/ru/guides/integrations/mcp/).

<Aside type="caution">
Токен в браузере виден каждому посетителю. Используйте токены только с серверов, на шагах
сборки и в закрытых приложениях; для публичных страниц выдайте нужное в
**Настройки → Публичный доступ**.
</Aside>

## Перевыпуск и удаление токена

- **Перевыпустить** в строке токена создаёт новый ключ с тем же названием, типом и
  разрешениями. Текущий ключ сразу перестаёт работать, поэтому приложения, которые его
  используют, получают ошибки, пока вы их не обновите.
- **Удалить** удаляет токен; клиенты, которые его используют, теряют доступ.

Сделайте одно из двух, как только появится подозрение на утечку токена.

## Где важен pepper

Verdin никогда не хранит сами токены. Он хранит хеш каждого токена с ключом (HMAC-SHA256),
где ключ — `VERDIN_TOKEN_PEPPER`, поэтому одной копии базы данных недостаточно, чтобы
воспользоваться токенами. Тот же pepper защищает:

- API-токены.
- Секреты аутентификаторов и резервные коды администраторов
  ([двухфакторная аутентификация](/ru/guides/auth/two-factor/)).
- Хешированные IP-адреса, которые хранятся вместе с отправками форм.

Сгенерируйте pepper один раз через `verdin secrets`, не храните его в `verdin.toml` и в
резервных копиях базы данных и задайте всем экземплярам одинаковое значение.

<Aside type="caution" title="Смена pepper">
С другим pepper перестают работать все API-токены, а также приложения-аутентификаторы и резервные
коды всех администраторов. Меняйте его, только если он утёк, а затем создайте новые
токены и сбросьте двухфакторную аутентификацию всем администраторам. На ключи доступа и
пароли это не влияет.
</Aside>

## Admin API

Все маршруты находятся под `/admin/api` и требуют `tokens.manage`.

```http
GET    /admin/api/api-tokens
POST   /admin/api/api-tokens                  { "name": "Website", "kind": "custom", "expiresInDays": 90,
                                                "permissions": [{ "subject": "api::article", "action": "find" }] }
GET    /admin/api/api-tokens/{id}
PUT    /admin/api/api-tokens/{id}             { "name": "…", "description": null, "kind": "read-only", "permissions": [...] }
POST   /admin/api/api-tokens/{id}/regenerate
DELETE /admin/api/api-tokens/{id}
```

- `kind` — это `read-only`, `full-access` или `custom`; `expiresInDays` необязателен (без
  него токен бессрочный) и потом не меняется.
- `permissions` перечисляет пары `{ subject, action }`. `subject` — это UID типа содержимого,
  `plugin::upload` (медиатека) или `plugin::users-permissions.user`; `action` — `find`,
  `findOne`, `create`, `update`, `delete`, `publish` или `readDrafts`. `publish` и
  `readDrafts` к двум последним объектам не применяются.
- `POST /api-tokens` и `/regenerate` возвращают ключ один раз, в `accessKey`.

Публичный доступ использует те же пары: `PUT /admin/api/public-permissions`
`{ "permissions": [...] }`, для чего нужно **Управление ролями** (`roles.manage`).
