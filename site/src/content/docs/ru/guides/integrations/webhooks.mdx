Вебхуки отправляют HTTP-запрос `POST` на ваш URL, когда меняется контент или медиа: чтобы
пересобрать статический сайт, очистить кеш, синхронизировать поисковый индекс, написать в
чат. Доставки ставятся в очередь, подписываются, повторяются и записываются в журнал.

На этой странице показано, как настроить вебхук и принять его. События, полезная нагрузка и
заголовки перечислены в [справочнике по вебхукам](/ru/api/webhooks/).

## Включите функцию

Функция **Вебхуки** по умолчанию включена; выключить её можно в **Настройки → Функции**. Для
управления вебхуками нужно разрешение **Управление вебхуками** (`webhooks.manage`). См.
[Разрешения](/ru/reference/permissions/).

## Создайте вебхук

<Steps>

1. Перейдите в **Настройки → Вебхуки** и выберите **Новый вебхук**.
2. В разделе **Общее** задайте **Имя** и **URL**, который должен вызывать Verdin.
3. В разделе **События** выберите события, которые запускают доставку: **Записи** (создание,
   обновление, публикация, снятие с публикации, отмена черновика, удаление), **Медиа**,
   **Релизы** (**Релиз опубликован**) и **Процессы проверки** (**Этап записи изменён**).
4. В разделе **Типы контента** оставьте **Все типы контента** или выберите некоторые. Это
   фильтрует только события записей; события медиа отправляются в любом случае.
5. В разделе **Заголовки** добавьте заголовки, которые нужны вашему эндпоинту, например токен
   `authorization` (**Добавить заголовок**). `content-type`, `host` и заголовки
   `x-verdin-*` задаёт Verdin.
6. В разделе **Подпись** оставьте включённым **Подписывать доставки** (по умолчанию).
7. Выберите **Создать**. Verdin один раз покажет секрет подписи (`whsec_…`): скопируйте его в
   конфигурацию своего эндпоинта.

</Steps>

**Включён** выключает вебхук, не удаляя его. Выключенные вебхуки не получают событий, но их
по-прежнему можно тестировать.

## Проверьте его

Выберите **Отправить тестовое событие** у вебхука. Verdin сразу отправит:

```json
{ "event": "trigger-test", "createdAt": "2026-09-25T09:00:00.000Z" }
```

Доставка появится в **Журнале доставок** вебхука со статусом, HTTP-статусом, длительностью и
началом тела ответа. Откройте доставку, чтобы увидеть полную полезную нагрузку и ошибку, если
она есть.

Чтобы получать вебхуки на своём компьютере во время разработки, запускайте сервер с
`verdin dev`: он разрешает URL `localhost`, которые `verdin start` отклоняет (см.
[Безопасность](#безопасность)).

## Приём доставки

Доставка — это `POST` с JSON-телом и такими заголовками:

| Заголовок | Значение |
| --- | --- |
| `content-type` | `application/json` |
| `x-verdin-event` | Имя события, например `entry.publish`. |
| `x-verdin-delivery` | Id доставки. Он не меняется при повторных попытках: используйте его, чтобы отбрасывать дубликаты. |
| `x-verdin-signature` | `t=<unix seconds>,v1=<hex>` для подписанных вебхуков. |

```json
{
  "event": "entry.publish",
  "createdAt": "2026-09-25T09:00:00.000Z",
  "model": "article",
  "uid": "api::article",
  "entry": { "id": 3, "documentId": "01J…", "title": "Hello", "publishedAt": "2026-09-25T09:00:00.000Z" }
}
```

Отвечайте любым статусом `2xx`, и быстро. Медленную работу (полную пересборку) делайте после
ответа или ставьте в очередь: доставка, которая длится дольше тайм-аута (по умолчанию 10
секунд), считается неудачной.

### Проверка подписи

`v1` — это HMAC-SHA256 от `"<t>.<raw body>"` с секретом вебхука в качестве ключа. Чтобы
проверить доставку:

1. Пересчитайте HMAC от **сырого** тела запроса, а не от заново сериализованного JSON.
2. Сравните его с `v1` за постоянное время.
3. Отклоняйте метки времени старше нескольких минут, чтобы перехваченную доставку нельзя было
   воспроизвести.

<Tabs syncKey="lang">
<TabItem label="Node.js">

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(secret, header, rawBody, toleranceSeconds = 300) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((part) => part.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > toleranceSeconds) return false;
  const expected = createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  return v1?.length === expected.length && timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}
```

В Express сохраняйте сырое тело: `app.post('/hooks/verdin', express.raw({ type: 'application/json' }), …)`
и передавайте `req.body.toString()`.

</TabItem>
<TabItem label="Python">

```python
import hashlib, hmac, time

def verify(secret: str, header: str, raw_body: bytes, tolerance: int = 300) -> bool:
    parts = dict(part.split("=", 1) for part in header.split(","))
    if abs(time.time() - int(parts["t"])) > tolerance:
        return False
    expected = hmac.new(secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])
```

</TabItem>
<TabItem label="Edge (Web Crypto)">

```ts
export async function verify(secret: string, header: string, rawBody: string, tolerance = 300) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((part) => part.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > tolerance) return false;
  const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(secret),
    { name: 'HMAC', hash: 'SHA-256' }, false, ['verify']);
  const signature = new Uint8Array(v1.match(/../g)!.map((byte) => parseInt(byte, 16)));
  return crypto.subtle.verify('HMAC', key, signature, new TextEncoder().encode(`${t}.${rawBody}`));
}
```

`crypto.subtle.verify` сравнивает за постоянное время.

</TabItem>
</Tabs>

**Сменить секрет** выпускает новый секрет (показывается один раз); старый сразу перестаёт
работать. **Прекратить подпись** удаляет секрет и отправляет доставки без подписи.

## Повторные попытки

Доставки сохраняются в базе данных при фиксации изменения и отправляются фоновым
обработчиком, поэтому медленный эндпоинт никогда не замедляет редакторов.

- **Успех:** любой ответ `2xx`.
- **Неудача:** всё остальное, включая редиректы (по ним не переходят), ошибки соединения и
  тайм-ауты.
- **Повторные попытки:** неудачная доставка повторяется через 30 секунд, 2 минуты, 10 минут,
  1 час и 6 часов. После этого она помечается как **Ошибка**.

Выберите **Повторить** у доставки в журнале, чтобы отправить её снова прямо сейчас. Журнал
хранится 30 дней. Поскольку повторные попытки используют тот же `x-verdin-delivery`, делайте
обработчик идемпотентным: сохраняйте обработанные id или делайте работу безопасной для
повторения.

## Безопасность

При `verdin start` URL вебхуков не могут указывать на loopback, частные, link-local и другие
зарезервированные адреса, включая имена хостов, которые в них разрешаются. Это не позволяет
администратору использовать вебхуки, чтобы достучаться до внутренних сервисов (SSRF).
Учётные данные в URL (`https://user:pass@…`) отклоняются; передавайте их в заголовке.

```toml title="verdin.toml"
[webhooks]
allow_private_networks = false   # unset: false with `verdin start`, true with `verdin dev`
timeout_secs = 10
retention_days = 30
```

См. [`[webhooks]`](/ru/reference/configuration/).

## Переход со Strapi

Вебхуки Verdin повторяют события и полезную нагрузку Strapi со следующими отличиями:

- доставки подписываются, повторяются и записываются в журнал;
- вебхук можно ограничить некоторыми типами содержимого;
- событие Strapi `entry.draft-discard` называется `entry.discard-draft`.

Чтобы пересобирать статический сайт из админки по кнопке, а не при каждом изменении, см.
[Деплои и CDN](/ru/guides/integrations/deploys-and-cdn/).
