Content API и админ-панель ищут записи с параметром `_q`, как в Strapi. По умолчанию `_q`
находит текстовые поля, которые содержат указанные слова. Включите индекс `[search]`, чтобы
ранжировать результаты с помощью полнотекстового движка (Tantivy), встроенного в сервер. В
этом руководстве показаны оба варианта и когда стоит использовать индекс.

## Поиск через `_q`

```sh title="Terminal"
curl -G 'http://localhost:1337/api/articles' --data-urlencode '_q=rust cms'
```

`_q` сочетается с другими параметрами: `filters`, `status`, `locale`, `pagination`,
`fields` и `populate`. Поле поиска в списке админки отправляет тот же параметр.

По каким полям идёт поиск:

- Текстовые поля: `string`, `text`, `richtext`, `email`, `uid` и `enumeration`.
- С индексом — также текст внутри `blocks`, компонентов и динамических зон.
- Никогда — приватные поля и пароли.

`_q` — параметр REST. У GraphQL и параметров запросов TypeScript-клиента аргумента поиска
нет; используйте там фильтр `$containsi`.

## Без индекса

Без `[search]` `_q` находит записи, в которых любое текстовое поле содержит весь текст
запроса без учёта регистра, как `$containsi` в Strapi. Результаты идут в обычном порядке
сортировки. Это не требует настройки и работает во всех базах данных, но сканирует таблицу и
не ранжирует результаты.

## Включите полнотекстовый индекс

<Steps>

1. Включите индекс в `verdin.toml`:

   ```toml title="verdin.toml"
   [search]
   enabled = true
   ```

2. Перезапустите Verdin. Он строит индекс в фоне по всем записям; пока индекс не готов, `_q`
   работает через `$containsi`.

</Steps>

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `enabled` | `false` | Ранжировать `_q` с помощью полнотекстового индекса. |
| `dir` | `"data/search"` | Каталог индекса относительно проекта. |
| `memory_mb` | `50` | Бюджет памяти на индексирование в мегабайтах. |

См. [справочник по конфигурации](/ru/reference/configuration/).

Как индекс ищет совпадения:

- Слова разделяются по всему, что не является буквой или цифрой, приводятся к нижнему
  регистру и очищаются от диакритики, поэтому `cafe` находит `Café`.
- Должно совпасть каждое слово. Последнее слово совпадает и как префикс, поэтому результаты
  появляются, пока пользователь печатает.
- Заголовок (первое текстовое поле типа) имеет двойной вес.
- Без `sort` результаты идут от лучшего совпадения. С `sort` совпадения сортируются по
  вашему правилу. За один поиск учитывается не больше 1000 совпадений.
- Черновики и опубликованные версии, а также каждая локаль ищутся по отдельности, согласно
  `status` и `locale`.

Индекс отслеживает каждую запись из любого API. Он перестраивается, когда схема меняет
поля, доступные для поиска, и когда его каталог отсутствует.

## Несколько экземпляров

Индекс хранится на диске экземпляра и отслеживает записи этого экземпляра. Если вы запускаете
несколько экземпляров, записи на одном не попадают в индекс остальных. Держите поиск на одном
экземпляре или перестраивайте индекс после деплоя, удаляя его каталог перед запуском. См.
[Масштабирование](/ru/deploy/scaling/).

<Aside type="tip">
Каталог индекса можно безопасно удалять. Не включайте его в резервные копии и систему
контроля версий; Verdin перестраивает его по базе данных.
</Aside>
