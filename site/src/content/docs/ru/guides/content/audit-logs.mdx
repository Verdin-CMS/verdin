Журналы аудита записывают, кто, что и когда изменил: контент, медиа, входы и все изменения,
сделанные в админ-панели. В этом руководстве показано, что записывается, как фильтровать
журналы и сколько хранятся записи.

В Strapi журналы аудита — функция Enterprise. В Verdin они входят в открытое ядро.

## Перед началом

- **Настройки → Функции → Журналы аудита** по умолчанию включено. Выключение прекращает запись
  новых действий; существующие записи остаются доступными для чтения.
- Для чтения журналов нужно **Чтение журналов аудита** (`audit.read`). См.
  [Разрешения](/ru/reference/permissions/).

## Что записывается

| Область | Действия | Примечания |
| --- | --- | --- |
| Контент | `entry.create`, `entry.update`, `entry.publish`, `entry.unpublish`, `entry.discard-draft`, `entry.delete` | Из всех API: админ-панели, REST, GraphQL и плагинов. Локаль указана в подробностях. |
| Процессы проверки | `entry.stage`, `entry.assign` | Смена этапа и назначения. |
| Медиа | `media.create`, `media.update`, `media.delete` | Загрузка, изменение и удаление файлов. Имя файла указано в подробностях. |
| Входы | `admin.login` | Вход по паролю и вход первого администратора (записывается после второго фактора, если он есть у учётной записи), а также вход через SSO с указанием провайдера. |
| Изменения в админке | `{METHOD} {route}`, например `PUT /roles/{id}` | Каждая успешная запись через admin API: пользователи, роли, API-токены, настройки, функции, вебхуки, локали, плагины, релизы… Параметры маршрута указаны в подробностях. |

У каждой записи есть время, исполнитель, действие, объект (UID типа содержимого,
`plugin::upload.file` или ресурс админки, например `roles`), id объекта, подробности и, для
запросов, IP-адрес клиента.

Исполнитель — один из:

- **Администратор**: вошедший администратор, указанный по имени.
- **API**: изменение через content API или GraphQL с API-токеном, токеном конечного
  пользователя или через публичный доступ.
- **Система**: запись через admin API без вошедшего администратора.

За обратным прокси задайте `[server].trusted_proxies`, чтобы в журналах был адрес клиента, а
не прокси. См. [справочник по конфигурации](/ru/reference/configuration/).

## Фильтрация журналов

<Steps>

1. Откройте **Настройки → Журналы аудита**.
2. Выберите пресет из **Быстрых фильтров** (**Содержимое**, **Медиафайлы**, **Входы**) или
   заполните фильтры:
   - **Действие**: точное действие, например `entry.publish`, или префикс, оканчивающийся на
     `*`, например `entry.*`.
   - **Исполнитель**: один администратор или **Кто угодно**.
   - **Объект**: UID типа содержимого, например `api::article`.
   - **С** и **По**: диапазон дат. Дата без времени включает весь день.
3. Выберите **Применить**. Откройте **Подробности** в строке, чтобы увидеть всё, что для неё
   записано.

</Steps>

## Запросы через API

```sh title="Terminal"
curl -G 'http://localhost:1337/admin/api/audit-logs' \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  --data-urlencode 'action=entry.*' \
  --data-urlencode 'subject=api::article' \
  --data-urlencode 'actor=3' \
  --data-urlencode 'from=2026-09-01' \
  --data-urlencode 'to=2026-09-30' \
  --data-urlencode 'page=1' --data-urlencode 'pageSize=50'
```

Записи идут от новых к старым, по умолчанию 50 на странице, не больше 200:

```json
{
  "data": [
    {
      "id": 812,
      "at": "2026-09-28T14:03:11.000Z",
      "action": "entry.publish",
      "subject": "api::article",
      "subjectId": "k3v9…",
      "details": { "locale": "fr" },
      "ip": null,
      "actor": { "kind": "admin", "id": 3, "email": "ana@example.com", "name": "Ana Ruiz" }
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 50, "total": 1, "pageCount": 1 } }
}
```

`from` и `to` принимают даты или дату-время в ISO 8601; всё остальное — ошибка `400`.

## Срок хранения записей

Записи старше `[audit].retention_days` удаляются раз в день. По умолчанию — 90 дней.

```toml title="verdin.toml"
[audit]
retention_days = 365
```

<Aside type="tip">
Чтобы хранить записи аудита дольше, чем стоит хранить их в базе данных, регулярно копируйте их
в собственное хранилище через API выше.
</Aside>
