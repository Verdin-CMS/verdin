Релиз объединяет записи, которые выходят в свет или снимаются вместе: запуск продукта,
кампания, набор переводов. Вы публикуете его вручную или назначаете дату. В этом руководстве
вы создадите релиз, добавите записи, выполните его и познакомитесь с admin API.

Релизы работают как Releases в Strapi, которые входят в платные тарифы Strapi.

## Перед началом

- **Настройки → Функции → Релизы** по умолчанию включено. Пока функция выключена, страница
  **Релизы** и маршруты недоступны, а запланированные релизы ждут.
- Для управления релизами нужно **Управление релизами** (`releases.manage`).
- Для добавления записи нужно также **Публикация** для её типа содержимого, и тип должен
  использовать [черновики и публикацию](/ru/concepts/draft-and-publish/).

## Создайте релиз

<Steps>

1. Откройте **Релизы** в боковой панели и выберите **Новый релиз**.
2. Введите **Название**.
3. При желании задайте **Опубликовать (необязательно)**: дату и время в вашем часовом поясе,
   когда выполнится релиз. Без даты релиз ждёт, пока вы его не опубликуете.
4. Выберите **Создать**.

</Steps>

## Добавьте записи

<Steps>

1. Откройте запись в редакторе. Панель **Релизы** показывает релизы, в которые она входит.
2. Выберите **Добавить в релиз**.
3. Выберите **Релиз** и в разделе **При выполнении релиза** выберите **Опубликовать** или
   **Снять с публикации**.
4. Выберите **Добавить**.

</Steps>

Для локализованных типов добавляется только версия в текущей локали редактора. Добавьте
каждую локаль, которую хотите выпустить. Повторное добавление записи, которая уже есть в
релизе, заменяет её действие.

Страница релиза показывает его записи с типом содержимого и действием. Удалить запись можно
кнопкой в её строке.

## Опубликуйте релиз

- **Сейчас:** откройте релиз и выберите **Опубликовать сейчас**.
- **В назначенную дату:** фоновая задача каждые 30 секунд проверяет и выполняет релизы, срок
  которых наступил, от имени создавшего их администратора.

<Diagram
  caption="Статусы релиза"
  code={`flowchart LR
  P[Ожидает] -->|Опубликовать сейчас или наступила дата| R[Выполняется]
  R -->|все действия успешны| D[Выполнен]
  R -->|часть действий не удалась| F[Ошибка]`}
/>

Каждое действие записывает, успешно ли оно выполнено. Если одно не удалось, например потому
что запись удалена или не проходит валидацию, остальные действия всё равно выполняются, а
релиз завершается со статусом **Ошибка**, с ошибкой каждого неудачного действия в его строке.

<Aside type="caution">
Выполненный релиз больше нельзя изменить. Чтобы повторить неудачные действия, добавьте эти
записи в новый релиз.
</Aside>

Релиз публикуется целиком: он не ждёт [этапов проверки](/ru/guides/content/review-workflows/).
Если процесс требует определённого этапа для публикации, записи не на этом этапе завершаются
ошибкой, как при любой другой публикации.

Вебхуки могут подписаться на **Релиз опубликован** (`releases.publish`), который отправляется
при выполнении релиза. См. [Вебхуки](/ru/guides/integrations/webhooks/).

## Admin API

Все маршруты находятся под `/admin/api` и требуют `releases.manage`.

```http
GET    /admin/api/releases?status=pending&page=1&pageSize=25
POST   /admin/api/releases                    { "name": "Launch", "scheduledAt": "2026-10-01T08:00:00Z" }
GET    /admin/api/releases/{id}
PUT    /admin/api/releases/{id}               { "name": "Launch", "scheduledAt": null }
DELETE /admin/api/releases/{id}
POST   /admin/api/releases/{id}/actions       { "uid": "api::article", "documentId": "…", "locale": "fr", "action": "publish" }
DELETE /admin/api/releases/{id}/actions/{actionId}
POST   /admin/api/releases/{id}/publish
GET    /admin/api/content/{uid}/{documentId}/releases
```

- `status` — это `pending`, `running`, `done` или `failed`; у каждого действия свои `status` и
  `error`.
- Изменение, добавление в релиз или публикация релиза, который уже не ожидает, отвечает `409`.
- `action` — это `publish` или `unpublish`. Для добавления действия нужно также
  `content.publish` для типа. Локаль определяется при добавлении действия, поэтому
  последующая смена локали по умолчанию его не сдвигает.
- Удаление релиза удаляет его список записей. Сами записи не меняются.
- `GET /content/{uid}/{documentId}/releases` требует доступа на чтение к записи и возвращает
  пустой список администраторам без `releases.manage`.
