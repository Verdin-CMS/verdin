Список каждого типа содержимого в админке экспортирует записи в CSV или JSON и импортирует их
обратно из файла того же вида: чтобы исправить много записей в таблице, загрузить каталог
товаров или скопировать записи между проектами. В этом руководстве описаны оба направления и
формат файла.

Это работает для записей одного типа содержимого за раз. Чтобы перенести проект целиком, см.
[`verdin export` и `verdin import verdin`](/ru/reference/cli/). Для переезда со Strapi см.
[Миграция со Strapi](/ru/migrate/from-strapi/).

## Перед началом

- Для экспорта нужен доступ на чтение к типу содержимого. Экспортируются только поля, которые
  ваша роль может читать.
- Для импорта нужен доступ на создание, на изменение или оба: строкам, которые создают
  записи, нужно создание, а строкам, которые их обновляют, — изменение. Для публикации
  импортированных строк нужна ещё и публикация. См. [Разрешения](/ru/reference/permissions/).

## Экспорт записей

<Steps>

1. Откройте список типа содержимого и настройте его так, как нужно для экспорта: фильтры,
   поиск, сортировка, статус и локаль.
2. Выберите **Экспорт**, затем **Экспортировать как CSV** или **Экспортировать как JSON**.

</Steps>

Файл содержит записи, которые показывает список, с его фильтрами, поиском и сортировкой, со
всех страниц, до 50 000 записей. Каждая строка начинается с `documentId`, за ним идут поля.

## Импорт записей

<Steps>

1. Откройте список типа содержимого и выберите **Импорт**.
2. Выберите **Файл**: `.csv` со строкой заголовков или `.json` со списком объектов, до 1 МБ.
3. В разделе **Столбцы** выберите, в какое поле идёт каждый столбец. Столбцы, названные как
   поля, уже сопоставлены. Выберите **Пропустить**, чтобы исключить столбец, и **ID документа
   (обновление)** для столбца, который указывает существующие записи.
4. При желании включите **Публиковать импортированные записи**. Иначе они сохраняются как
   черновики.
5. Выберите **Проверить**. Verdin проверяет каждую строку, включая ограничения и ссылки,
   ничего не записывая, и сообщает, какие строки он создал бы, обновил или отклонил.
6. При необходимости исправьте файл, затем выберите **Импортировать**.

</Steps>

Как записываются строки:

- Строка с `documentId` обновляет эту запись; остальные создают новые записи.
- Строки записываются по одной. Строка с ошибкой попадает в отчёт с полем и описанием
  проблемы и пропускается; остальные всё равно записываются.
- Отчёт перечисляет до 100 строк с ошибками и столбцы, которые не сопоставились ни с одним
  полем.
- Импорт принимает не больше 5000 строк. Разбивайте большие файлы.
- Записи создаются в текущей локали списка.

<Aside type="caution">
Импорт пропускает ваши строки через ту же валидацию, что и редактор, но отменить его нельзя.
Сначала выполните **Проверить** и экспортируйте список перед крупным обновлением, чтобы его
можно было восстановить. При включённой [истории содержимого](/ru/guides/content/content-history/)
каждая обновлённая запись сохраняет предыдущую версию.
</Aside>

## Формат файла

Поля используют те же формы, что и формат записи content API:

| Поле | Значение |
| --- | --- |
| Текст, числа, логические значения, даты | Как в API (`true`/`false`, даты ISO 8601). |
| Связи | Значения `documentId` связанных записей. |
| Медиа | Id файлов из медиатеки. |
| Полиморфные связи | `uid:documentId`, например `api::article:k3v9…`. |
| Компоненты, динамические зоны, blocks и JSON | JSON. |

В CSV списки (несколько связей или файлов) объединяются через `|`.

```csv title="articles.csv"
documentId,title,slug,featured,tags
,Hello world,hello-world,true,t1a2b3|t4c5d6
k3v9x8…,Updated title,updated-title,false,
```

Те же строки в JSON:

```json title="articles.json"
[
  { "title": "Hello world", "slug": "hello-world", "featured": true, "tags": ["t1a2b3", "t4c5d6"] },
  { "documentId": "k3v9x8…", "title": "Updated title", "slug": "updated-title", "featured": false }
]
```

Экспорт списка — всегда корректный файл для импорта в тот же тип содержимого.

## Admin API

- `GET /admin/api/content/{uid}/export?format=csv` (или `json`) принимает параметры запроса
  списка: `filters`, `_q`, `sort`, `status` и `locale`.
- `POST /admin/api/content/{uid}/import?locale=` принимает содержимое файла строкой:

```json
{
  "format": "csv",
  "data": "title,slug\nHello world,hello-world\n",
  "mapping": { "slug": "slug", "notes": null },
  "dryRun": true,
  "publish": false
}
```

`mapping` сопоставляет столбец с полем; `null` пропускает столбец, а несопоставленные столбцы
сохраняют своё имя. Тело запроса ограничено `[server].body_limit` (по умолчанию 1 МБ).
