Verdin сохраняет версию записи каждый раз, когда её создают, сохраняют, публикуют, снимают с
публикации или отменяют её черновик, через любой API. В этом руководстве показано, как найти
старую версию и восстановить её, сколько версий хранится и соответствующий admin API.

История содержимого работает как в Strapi, где это платная функция.

## Перед началом

- **Настройки → Функции → История содержимого** по умолчанию включено. Пока функция
  выключена, версии не записываются, а история недоступна.
- Для чтения истории записи нужен доступ на чтение к записи, для восстановления — доступ на
  изменение. Ограничения по полям действуют: вы видите и восстанавливаете только поля,
  которые ваша роль может читать или изменять. См. [Разрешения](/ru/reference/permissions/).

## Восстановите версию

<Steps>

1. Откройте запись и выберите **История**.
2. Список **Версии** показывает каждую версию с её событием (**Создано**, **Сохранено**,
   **Опубликовано**, **Снято с публикации**, **Черновик отменён**), датой и автором.
   Изменения через content API показывают автором **API**.
3. Выберите версию, чтобы посмотреть её поля.
4. Выберите **Восстановить** и подтвердите.

</Steps>

Версия заменяет текущий черновик; опубликуйте его потом, когда будете готовы. Для типов без
черновиков и публикации восстановление сразу обновляет запись.

Что не восстанавливается:

- Поля, которых больше нет в схеме, перечисляются и не восстанавливаются.
- Ссылки на удалённые записи или файлы отбрасываются, и редактор сообщает, в каких полях они
  пропали.

**Назад к редактору** возвращает к записи, ничего не меняя.

## Сколько версий хранится

Verdin хранит последние `[history].max_versions` версий каждой записи и локали (по умолчанию
50) и удаляет более старые по мере появления новых:

```toml title="verdin.toml"
[history]
max_versions = 100
```

У каждой локали локализованной записи своя история. Удаление записи или одной из её локалей
удаляет и её версии. См. [справочник по конфигурации](/ru/reference/configuration/).

<Aside type="note">
В отличие от Strapi, где история хранится определённое число дней, Verdin хранит определённое
число версий на запись, независимо от их возраста.
</Aside>

## Admin API

Все маршруты находятся под `/admin/api`.

| Маршрут | Разрешение | Что делает |
| --- | --- | --- |
| `GET /history/{uid}/{documentId}?locale=&page=&pageSize=` | чтение записи | Версии от новых к старым, без данных (20 на странице, не больше 100). |
| `GET /history/versions/{id}` | чтение записи | Одна версия с данными. |
| `POST /history/versions/{id}/restore` | изменение записи | Восстанавливает версию как текущий черновик. |

Ответ на восстановление перечисляет, что было отброшено:

```json
{
  "data": {
    "documentId": "k3v9…",
    "restored": 42,
    "dropped": [{ "field": "tags", "count": 1 }]
  }
}
```

Пока функция выключена, маршруты отвечают `404`.
