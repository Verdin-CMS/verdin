Функция **Формы** обрабатывает формы вашего сайта (обратная связь, подписка на рассылку,
регистрация на мероприятие) без стороннего сервиса форм. Редакторы описывают поля в
админ-панели, сайт выводит их и отправляет данные в Verdin, а ответы проверяются, сохраняются,
пересылаются по почте и экспортируются в CSV.

## Включите функцию

В **Настройки → Функции** включите **Формы**, затем выберите **Управление формами** (или
перейдите в **Настройки → Формы**). Для управления формами и чтения ответов нужно разрешение
**Управление SEO, редиректами, меню и формами** (`site.manage`), которое есть у встроенной
роли Editor. См. [Разрешения](/ru/reference/permissions/).

Для писем-уведомлений настройте провайдера в [`[email]`](/ru/reference/configuration/); с
провайдером `log` по умолчанию письма только записываются в лог сервера.

## Создайте форму

<Steps>

1. В **Настройки → Формы** выберите **Новая форма**.
2. Задайте название (например, **Контакты**) и **Slug** (`contact`). Slug входит в URL формы.
3. На вкладке **Поля** выберите **Добавить поле** для каждого поля и укажите **Метку**,
   **Имя**, **Тип**, **Обязательное**, **Текст-подсказку** и **Максимальную длину**.
4. На вкладке **Настройки** задайте:
   - **Уведомлять**: адреса email, которые получают каждый ответ.
   - **Сообщение об успехе**: возвращается сайту после отправки.
   - **Ловушка для спама**: по умолчанию включена (см. [Спам](#спам)).
5. Сохраните. Вкладка **Интеграция** показывает публичный эндпоинт и пример для копирования.

</Steps>

| Тип | Подпись в админке | Принимает |
| --- | --- | --- |
| `text` | **Текст** | Любой текст. |
| `email` | **Эл. почта** | Адрес email. |
| `textarea` | **Длинный текст** | Любой текст. |
| `number` | **Число** | Число, сохраняется как число. |
| `select` | **Выбор** | Один из **Вариантов** (по одному на строку). |
| `checkbox` | **Флажок** | `true`, `on`, `1` или `yes` — отмечен; всё остальное — нет. Обязательный флажок должен быть отмечен. |
| `date` | **Дата** | Любой текст (используйте `<input type="date">`). |
| `url` | **URL** | URL. |
| `tel` | **Телефон** | Любой текст. |

Имена полей начинаются с буквы, дальше идут буквы, цифры или `_`, и они уникальны в пределах
формы. В форме от 1 до 50 полей. Значения не длиннее **Максимальной длины** символов (по
умолчанию 5000, не больше 20 000).

## Выведите форму

`GET /api/_forms/{slug}` возвращает описание формы, чтобы сайт мог вывести поля, выбранные
редакторами:

```json
{
  "data": {
    "slug": "contact",
    "name": "Contact",
    "fields": [
      { "name": "email", "label": "Email", "type": "email", "required": true },
      { "name": "message", "label": "Message", "type": "textarea", "required": true, "maxLength": 2000 },
      { "name": "topic", "label": "Topic", "type": "select", "options": ["Sales", "Support"] }
    ],
    "honeypot": "_gotcha"
  }
}
```

`honeypot` равен `null`, если ловушка для спама выключена. Описание кешируется на минуту
(`Cache-Control: public, max-age=60`).

## Отправка

`POST /api/_forms/{slug}` принимает значения в JSON (поля или `{ "data": { … } }`) или как
обычную отправку формы (`application/x-www-form-urlencoded`). Токен не нужен.

<Tabs syncKey="form">
<TabItem label="HTML-форма">

```html
<form method="post" action="https://cms.example.com/api/_forms/contact">
  <input name="email" type="email" required />
  <textarea name="message" required maxlength="2000"></textarea>
  <input name="_gotcha" tabindex="-1" autocomplete="off" aria-hidden="true" style="position:absolute;left:-9999px" />
  <button>Send</button>
</form>
```

</TabItem>
<TabItem label="fetch">

```js
const response = await fetch('https://cms.example.com/api/_forms/contact', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ data: { email, message, _gotcha: '' } }),
});
const body = await response.json();
if (response.ok) showThanks(body.data.message);
else showErrors(body.error.details.errors); // [{ path: ['email'], message: 'must be an email address' }]
```

</TabItem>
</Tabs>

| Ответ | Когда |
| --- | --- |
| `201` с `{ "data": { "message": … } }` | Принято. `message` — это **Сообщение об успехе** или `Thank you!`. |
| `400` `ValidationError` | Значение отсутствует или некорректно. `details.errors` перечисляет `{ path, message }` для каждого поля. |
| `404` | Формы с таким slug нет или функция выключена. |
| `413` | Отправка больше 64 КБ. |
| `429` | Один и тот же посетитель отправил в эту форму больше 10 ответов за минуту. |

Значения обрезаются по краям и проверяются по полям. Неизвестные поля отбрасываются, поэтому
посетитель не может добавить данные, которые вы не запрашивали.

При обычной отправке HTML-формы JSON-ответ открывается как страница. Для большего удобства
отправляйте через `fetch` и показывайте сообщение сами. Для отправки из браузера на другой
origin нужен origin вашего сайта в [`[api].cors_origins`](/ru/reference/configuration/).

### Спам

С включённой **Ловушкой для спама** добавьте в форму скрытое пустое поле `_gotcha`. Боты
заполняют все поля; на отправку с заполненным `_gotcha` сервер отвечает как на принятую
(`201`) и выбрасывает её, так что бот ничего не узнаёт. Вместе с ограничением частоты это
останавливает большую часть спама без CAPTCHA.

## Чтение ответов

Вкладка **Ответы** формы показывает, что отправили посетители, со временем в столбце
**Получено**. Ответ можно удалить, а **Экспортировать CSV** скачивает их все.

Каждый принятый ответ также отправляется по почте на адреса из **Уведомлять** со ссылкой на
ответы в админке (она строится из [`[server].public_url`](/ru/reference/configuration/)).

<Aside type="note">
Verdin хранит значения каждого ответа, user agent посетителя и хеш его IP-адреса с ключом (а
не сам адрес) — этого достаточно, чтобы заметить флуд, не отслеживая людей. Удаление формы
удаляет и её ответы.
</Aside>

## Admin API

Админ-панель использует `/admin/api/site/forms` и `/admin/api/site/forms/{id}`, а также
`/admin/api/site/forms/{id}/submissions` и `…/submissions/export` (CSV) с токеном доступа
администратора и `site.manage`. См. [Admin API](/ru/api/admin/).
