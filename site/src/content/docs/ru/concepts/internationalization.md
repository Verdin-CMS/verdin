Интернационализация (i18n) позволяет хранить содержимое документа на нескольких языках. На
этой странице описана модель: локали, локализованные и общие поля и то, как чтение и запись
выбирают локаль. Работа редактора описана в разделе
[Локализация контента](/ru/guides/content/localizing-content/).

## Локали

Локали проекта перечислены в **Настройки → Интернационализация** (разрешение
`locales.manage`). При первом запуске добавляется английский (`en`) как локаль по умолчанию.

- Одна локаль всегда используется по умолчанию. Запросы без указания локали используют её, и
  её нельзя удалить.
- Код — это язык из двух или трёх строчных букв, за которым могут идти подтеги:
  `en`, `fr`, `pt-BR`, `zh-Hans`.

:::caution
Удаление локали удаляет и все версии, написанные на ней.
:::

## Локализованные типы содержимого

Тип содержимого локализован, если это указано в его схеме. Тогда у каждого документа есть
одна версия на локаль, и все они имеют общий `documentId`:

```json title="schema/content-types/article.json (excerpt)"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

С [черновиками и публикацией](/ru/concepts/draft-and-publish/) у каждой локали свой черновик
и своя опубликованная версия, поэтому французский перевод можно опубликовать раньше или позже
английского текста. Типы без `pluginOptions.i18n.localized` не локализованы и игнорируют
параметры `locale`.

## Что локализуется

В локализованном типе локализуется каждый атрибут, если в нём не указано
`"pluginOptions": { "i18n": { "localized": false } }`. У такого **общего** поля одно значение
на весь документ:

- Сохранение общего поля в одной локали записывает его в черновики всех локалей.
- Публикация локали копирует её общие поля в опубликованные версии других локалей.
- Это относится и к связям и медиа: общая связь ссылается на одни и те же документы во всех
  локалях.

Системные поля следуют за версией: у каждой локали свои `createdAt`, `updatedAt` и
`publishedAt`. Значения `unique` и `uid` уникальны в рамках локали, поэтому у двух переводов
может быть одинаковый slug.

## Связи между локализованными типами

Связи соединяют документы, а не версии (см.
[Связи](/ru/concepts/relations/#связь-по-документу-а-не-по-строке)), поэтому локаль
выбирается при чтении:

- Если оба типа локализованы, французская статья показывает французскую версию своей
  категории. Фильтры через связь сравниваются в той же локали.
- Если целевой тип не локализован, все локали видят одну и ту же цель.

## Выбор локали в API

REST и admin API принимают `locale` как параметр запроса в формате Strapi v5; GraphQL
принимает аргумент `locale`:

```http
GET /api/articles?locale=fr
PUT /api/articles/{documentId}?locale=fr
DELETE /api/articles/{documentId}?locale=fr
```

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
  }
}
```

- Без `locale` запросы читают и записывают локаль по умолчанию.
- `PUT` в локали, которой у документа ещё нет, создаёт эту версию.
- `DELETE` удаляет только версию в запрошенной локали. Ссылки на документ удаляются, когда у
  него не остаётся ни одной локали.
- Ответы REST для локализованных типов содержат `locale`. Неизвестная локаль — ошибка `400`.
- Полезная нагрузка вебхуков, события реального времени и история содержимого записывают
  локаль изменённой версии.

## Разрешения по локалям

Роли администраторов могут ограничивать разрешения на контент некоторыми локалями, чтобы
французский редактор мог читать и менять только французские версии. См.
[Разрешения](/ru/concepts/permissions/#разрешения-на-поля-и-локали). Права content API
(публичный доступ, API-токены, роли конечных пользователей) действуют для всех локалей.

## Сравнение со Strapi

Модель и параметры совпадают с i18n в Strapi v5: локализованные типы, поля с
`localized: false`, `?locale=` и локаль по умолчанию. В Verdin i18n входит в ядро и всегда
включена: вы включаете локализацию для каждого типа содержимого в схеме.
