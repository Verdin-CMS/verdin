Черновики и публикация позволяют редакторам работать над документом, не меняя того, что
показывает ваш сайт, и публиковать его, когда он готов. На этой странице описана модель:
документы, версии, действия, которые переносят контент между ними, и то, как с ними работает
каждый API. Всё устроено так же, как в Strapi v5.

Функция включается для каждого типа содержимого в его схеме:

```json title="schema/content-types/article.json (excerpt)"
"options": { "draftAndPublish": true }
```

Если `options.draftAndPublish` отсутствует, функция выключена.

## Документы и версии

**Документ** — это одна запись, которую определяет её `documentId`. С черновиками и
публикацией у документа может быть до двух **версий**:

- **черновик**, который меняется при каждом редактировании, и
- **опубликованная** версия, которую content API отдаёт по умолчанию.

У [локализованного](/ru/concepts/internationalization/) типа у каждой локали свой черновик и
своя опубликованная версия, и все они имеют общий `documentId`.

У типов без черновиков и публикации одна версия на локаль, и она всегда опубликована: каждая
запись меняет то, что видят читатели.

## Состояния

Админ-панель показывает состояние каждой записи в списке и в редакторе:

| Состояние | Черновик | Опубликованная версия | Что видят читатели опубликованного контента |
| --- | --- | --- | --- |
| **Черновик** | есть | нет | Ничего: документ не виден. |
| **Опубликовано** | совпадает с опубликованной | есть | Опубликованную версию. |
| **Изменено** | изменён после последней публикации | есть | Опубликованную версию, без новых изменений. |

Действия переводят документ между этими состояниями:

| Действие | Результат | Из → в |
| --- | --- | --- |
| Сохранение | Записывает черновик. | Черновик → Черновик, Опубликовано → Изменено |
| **Опубликовать** | Копирует черновик в опубликованную версию, при необходимости создавая её. | Черновик или Изменено → Опубликовано |
| **Снять с публикации** | Удаляет опубликованную версию; черновик остаётся. | Опубликовано или Изменено → Черновик |
| **Отменить изменения** | Заменяет черновик копией опубликованной версии. | Изменено → Опубликовано |
| Удаление | Удаляет все версии (для локализованных типов — в запрошенной локали). | любое → удалён |

Публикация выполняется в одной транзакции. Она проверяет в черновике поля `required` и
[правила между полями](/ru/concepts/content-model/#проверки-между-полями) типа; если проверка
не прошла, ничего не публикуется. До этого момента черновики могут быть неполными и нарушать
эти правила.

У черновиков `publishedAt` равно `null`. В опубликованной версии хранится время последней
публикации.

## Связи и медиа следуют за версией

У каждой версии свои ссылки на связи и медиа, и публикация копирует ссылки черновика в
опубликованную версию. Ссылки указывают на документы и разрешаются в читаемой версии:
опубликованная статья показывает опубликованную версию своей категории, а черновик —
черновик категории. Если категорию снять с публикации, она пропадает из опубликованной статьи,
пока её снова не опубликуют, причём ни одна ссылка не перезаписывается. См.
[Связи](/ru/concepts/relations/#связь-по-документу-а-не-по-строке).

Компоненты и динамические зоны — часть строки, поэтому публикация копирует их как есть.

## Чтение черновиков и опубликованного контента

| API | По умолчанию читает | Чтобы читать черновики |
| --- | --- | --- |
| [REST](/ru/api/rest/#статус) | Опубликованные версии | `?status=draft`, для этого нужно разрешение **Читать черновики** |
| [GraphQL](/ru/api/graphql/) | Опубликованные версии | `status: DRAFT` с тем же разрешением |
| [Admin API](/ru/api/admin/) | Черновики | `?status=published` |

Чтение черновиков — отдельное разрешение (`readDrafts`), чтобы токен, который читает контент
вашего сайта, не мог читать неопубликованную работу. API-токены только для чтения никогда не
читают черновики.

Чтобы отличать документы, которые когда-либо публиковались, фильтруйте по
`hasPublishedVersion`: `?status=draft&hasPublishedVersion=false` перечисляет документы, которые
ни разу не публиковались.

## Запись через API

При записи API ведут себя как в Strapi v5:

- **REST и GraphQL**: `create` и `update` записывают черновик **и публикуют его**, если в
  запросе нет `status=draft` (`status: DRAFT` в GraphQL). Неудачная публикация откатывает
  весь запрос.
- **Админ-панель и admin API** сохраняют только черновики. Публикация — всегда отдельное
  явное действие.

У REST API есть и явные действия, которых в REST API Strapi нет:

```http
POST /api/articles/{documentId}/actions/publish
POST /api/articles/{documentId}/actions/unpublish
POST /api/articles/{documentId}/actions/discard-draft
```

Для них нужно разрешение **Опубликовать** на тип. См. [REST API](/ru/api/rest/#действия).

## Другие функции, которые публикуют

- [Релизы](/ru/guides/content/releases/) объединяют документы и публикуют или снимают их с
  публикации вместе — сразу или в назначенную дату.
- [Процессы проверки](/ru/guides/content/review-workflows/) могут требовать определённого
  этапа, прежде чем документ можно будет опубликовать.
- Публикация и снятие с публикации отправляют события `entry.publish` и `entry.unpublish`
  [вебхуков](/ru/api/webhooks/) и [реального времени](/ru/api/realtime/). Сохранение черновика
  отправляет `entry.update`, которое по realtime получают только клиенты с правом читать
  черновики.
