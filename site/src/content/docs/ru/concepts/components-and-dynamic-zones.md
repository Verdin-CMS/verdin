Компоненты позволяют повторно использовать группу полей в разных типах содержимого, а
динамические зоны позволяют редакторам собирать страницу из списка блоков. На этой странице
объясняется, как они моделируются и хранятся и как это влияет на их чтение, запись и
фильтрацию. Сам формат схемы описан в разделе [Модель контента](/ru/concepts/content-model/).

## Компоненты

Компонент — это группа полей с собственным файлом в `schema/components/<category>/`.
Компонент `shared.seo` из примера блога хранит мета-заголовок и описание:

```json title="schema/components/shared/seo.json"
{
  "displayName": "SEO",
  "attributes": {
    "metaTitle": { "type": "string", "maxLength": 60 },
    "metaDescription": { "type": "text", "maxLength": 160 }
  }
}
```

Тип содержимого использует его через атрибут `component`. `repeatable: true` превращает его в
список, число элементов которого можно ограничить через `min` и `max`:

```json
"seo": { "type": "component", "component": "shared.seo" },
"links": { "type": "component", "component": "shared.link", "repeatable": true, "max": 10 }
```

Компоненты могут содержать другие компоненты. Компонент не может содержать сам себя — ни
напрямую, ни через другие; проверка схемы отклоняет такие циклы.

## Динамические зоны

Динамическая зона — это список, элементами которого могут быть любые из перечисленных в ней
компонентов. В теле статьи блога чередуются блоки hero и цитаты:

```json
"blocks": { "type": "dynamiczone", "components": ["blocks.hero", "blocks.quote"], "max": 20 }
```

Каждый элемент указывает свой компонент в `__component`. `min` и `max` ограничивают число
элементов. Динамические зоны бывают только у типов содержимого: компонент не может содержать
динамическую зону.

## Хранение в JSON

Verdin хранит значение компонента или динамической зоны в одной JSON-колонке строки документа
(`jsonb` в PostgreSQL, `json` в MySQL и MariaDB, текст в SQLite):

```json
// the "seo" column
{ "id": 1, "metaTitle": "Rust for CMS authors", "metaDescription": "…" }

// the "blocks" column
[
  { "__component": "blocks.hero", "id": 1, "title": "Hello", "subtitle": "…" },
  { "__component": "blocks.quote", "id": 2, "text": "…", "author": "Ferris" }
]
```

Strapi хранит каждый компонент в отдельной таблице и соединяет их через полиморфные таблицы
связей. Хранение значения вместе с документом означает следующее:

- Чтение документа с компонентами не требует JOIN, какой бы глубокой ни была вложенность.
- Публикация, отмена черновика и [история содержимого](/ru/guides/content/content-history/)
  копируют значение как есть.
- Добавление поля в компонент не меняет ни одной таблицы: миграция пустая.
- Фильтрация по полям компонентов использует JSON-функции каждой базы данных, и некоторые
  фильтры недоступны (см. [Фильтрация](#фильтрация)).

У каждого элемента есть `id` — положительное целое число, уникальное в пределах значения
атрибута. Verdin присваивает его новым элементам; при обновлении списка передавайте `id`
обратно, чтобы элементы оставались стабильными.

## Связи и медиа внутри компонентов

Компонент может содержать связи и медиа, которые хранятся прямо в JSON: `documentId` для
связей и id файлов для медиа.

- Связи внутри компонентов должны быть `oneWay` или `manyWay`: они указывают на цели и не
  имеют обратной стороны. См. [Связи](/ru/concepts/relations/#связи-внутри-компонентов).
- Каждая ссылка проверяется при записи: целевой документ или файл должен существовать, а
  файлы должны соответствовать `allowedTypes` поля.
- Когда компонент подгружается через populate, ссылки разрешаются пакетными запросами в том
  же статусе и локали, что и документ. Удалённая цель или цель без версии в читаемом варианте
  пропускается.
- Полиморфные связи (`morphToOne`, `morphToMany`) и поля `password` не могут находиться
  внутри компонентов.

## Чтение

Компоненты и динамические зоны возвращаются, только если их запросить через populate, как в
Strapi:

```http
GET /api/articles?populate[0]=seo&populate[1]=blocks
GET /api/articles?populate=*
```

Подгруженный компонент возвращается целиком, вместе с вложенными компонентами и разрешёнными
связями и медиа. Strapi требует уровень `populate` для каждого вложенного компонента; Verdin
принимает такие вложенные параметры ради совместимости и игнорирует их. Элементы динамической
зоны возвращаются в сохранённом порядке, каждый со своим `__component`.

В GraphQL компонент — это объектный тип, названный по его UID (`ComponentSharedSeo`), а
динамическая зона — объединение (`ArticleBlocksDynamicZone`), которое запрашивают с помощью
фрагментов. См. [GraphQL API](/ru/api/graphql/).

## Запись

Передавайте значение атрибута целиком. Оно заменяет сохранённое:

```json
{
  "data": {
    "seo": { "metaTitle": "Rust for CMS authors" },
    "blocks": [
      { "__component": "blocks.hero", "title": "Hello" },
      { "__component": "blocks.quote", "text": "Fast and small.", "author": "Ferris" }
    ]
  }
}
```

Значение проверяется по схеме компонента при каждой записи: неизвестные ключи, неверные типы
и `__component`, который динамическая зона не разрешает, — это ошибки с путями вроде
`["blocks", 1, "text"]`. Поля `required` внутри компонентов проверяются при публикации
документа, как и поля верхнего уровня.

## Фильтрация

| Что | Пример | Примечания |
| --- | --- | --- |
| Поля компонента | `filters[seo][metaTitle][$containsi]=rust` | Скалярные поля, включая вложенные компоненты. |
| Поля повторяемого компонента | `filters[links][url][$contains]=github` | Совпадает, если подходит хотя бы один элемент. |
| Динамические зоны | `filters[blocks][__component][$eq]=blocks.quote` | Только по `__component`: у элементов разных компонентов разные поля. |

Сортировать по полям компонентов нельзя, а поля `json` внутри компонентов нельзя
фильтровать. Операторы описаны в [REST API](/ru/api/rest/#фильтры).
