[`deploy/playground/`](https://github.com/verdin-cms/verdin/tree/main/deploy/playground)
собирает контейнер для публичной демонстрации: [пример блога](https://github.com/verdin-cms/verdin/tree/main/examples/blog)
на SQLite с несколькими опубликованными статьями и демо-аккаунтом, под которым могут входить
посетители. Каждый час он выбрасывает базу данных и начинает заново. Контейнеру не нужны ни
том, ни сервер базы данных, ни ваши секреты. Где его хостить, решаете вы; подойдёт любая
платформа, которая запускает один контейнер с публичным адресом HTTPS.

Скрипты запускались с локальной сборкой 2026-09-30 (три цикла сброса); образ был собран, но
не запускался из опубликованного релиза.

## Что получают посетители

- Админ-панель на `/admin/` с входом под **demo@example.com** / **verdin-demo-1234**. У
  аккаунта роль **Editor**: он может создавать, редактировать, публиковать и удалять
  контент и загружать медиа, но не может управлять пользователями, ролями, API-токенами,
  вебхуками и настройками.
- Публичный доступ на чтение к статьям, категориям, тегам и главной странице через REST
  (`/api/articles?populate=*`) и GraphQL.
- Две опубликованные статьи, черновик, две категории, два тега и главная страница.

Существует и Super Admin со случайным паролем, который никто не знает.

## Как это работает

`run.sh` работает в цикле:

1. Удаляет `/var/lib/verdin-playground` (база данных, загрузки, поисковый индекс, кеш
   изображений) и генерирует новые секреты, поэтому сессии прошлого цикла заканчиваются.
2. Запускает `verdin start --migrate` и ждёт `/_ready`.
3. Выполняет `seed.sh`: создаёт аккаунты через CLI и admin API, открывает публичный доступ
   на чтение и создаёт контент.
4. Ждёт `PLAYGROUND_RESET_SECONDS` (3600), останавливает сервер и начинает сначала. Если
   сервер останавливается сам, цикл начинается сразу.

Конфигурация (`deploy/playground/verdin.toml`) ограничивает загрузки 2 МБ, ограничивает
анонимные запросы до 300 в минуту на адрес, не пускает доставки вебхуков на приватные адреса
и включает поиск.

## Сборка и запуск

Из корня репозитория:

```sh frame="terminal"
docker build -f deploy/playground/Dockerfile -t verdin-playground .
docker run -p 1337:1337 --tmpfs /var/lib/verdin-playground:uid=65532,gid=65532 verdin-playground
```

Образ — Alpine с `curl` и `jq` (скриптам нужна оболочка, которой нет в официальном образе) и
статическим бинарником, скопированным из `ghcr.io/verdin-cms/verdin`. Передайте
`--build-arg VERDIN_IMAGE=ghcr.io/verdin-cms/verdin:<version>`, чтобы выбрать релиз.
`tmpfs` держит данные в памяти; без него данные лежат в файловой системе контейнера, что тоже
работает.

| Переменная | По умолчанию | Что это |
| --- | --- | --- |
| `PLAYGROUND_RESET_SECONDS` | `3600` | Время между сбросами. |
| `PLAYGROUND_EMAIL`, `PLAYGROUND_PASSWORD` | `demo@example.com`, `verdin-demo-1234` | Демо-аккаунт. |
| `VERDIN_SERVER__PUBLIC_URL` | | Публичный адрес демо-площадки. |
| `VERDIN_SERVER__TRUSTED_PROXIES` | | Диапазон прокси платформы, чтобы ограничения частоты действовали на каждого посетителя. |

## Хостинг

Запускайте ровно один экземпляр (база данных локальная), не давайте ему останавливаться (без
масштабирования до нуля: таймер сброса живёт в процессе) и поставьте перед ним HTTPS: cookie
сессии админ-панели в режиме `start` имеет флаг `Secure`, поэтому для входа нужен HTTPS.
Любой может писать контент и загружать изображения до часа, поэтому на странице, которая
ссылается на демо, укажите расписание сброса и держите экземпляр на домене, отдельном от всего,
что делит с ним cookie.
