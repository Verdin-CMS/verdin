На этой странице описано, что Verdin делает для защиты проекта, и какие настройки вы
контролируете. Используйте её вместе с [чек-листом для продакшена](/ru/deploy/production-checklist/),
когда готовите экземпляр к реальному трафику.

## Что закрыто по умолчанию

- **Content API.** Анонимные запросы не получают ничего, пока вы не выдадите публичные
  разрешения в **Настройки → Публичный доступ**. Неизвестный, просроченный или некорректный
  токен даёт `401`, а не откат к публичной роли. См. [Разрешения](/ru/concepts/permissions/).
- **Документ OpenAPI** по адресу `/api/_openapi.json` требует действительного API-токена,
  пока вы не сделаете его публичным в **Настройки → Функции → Документация API**.
- **Необязательные функции**, такие как GraphQL, конечные пользователи, SSO и MCP-сервер,
  остаются выключенными, пока администратор с разрешением `features.manage` не включит их в
  **Настройки → Функции**.
- **Плагины** остаются выключенными, пока администратор не включит каждый из них в
  **Настройки → Плагины**.
- **Кросс-доменные вызовы из браузера.** Ни один origin не может вызывать API из браузера,
  пока вы не укажете его в `[api].cors_origins`.

## Вход администраторов

| Защита | Подробности |
| --- | --- |
| Хеширование паролей | Argon2id с параметрами OWASP; при изменении параметров хеш пересчитывается. |
| Сессии | Токен доступа на 15 минут хранится в памяти страницы (никогда в `localStorage`), а refresh-токен на 30 дней — в cookie `HttpOnly`, `SameSite=Strict`, ограниченной путём `/admin/api/auth`. Refresh-токен ротируется при каждом использовании; предъявление старого завершает всю сессию. |
| Secure-cookie | В `verdin start` refresh-cookie имеет флаг `Secure`. `[admin].secure_cookies = false` отключает его и пишет предупреждение в лог. |
| CSRF | Обновление токена и выход требуют заголовка `X-Verdin-CSRF`, который межсайтовая форма отправить не может. |
| Блокировка | Пять неудачных попыток блокируют учётную запись на 15 минут. Неудачи суммируются по шагам пароля и второго фактора. Неизвестные email и неверные пароли получают одинаковый ответ за одинаковое время. |
| Ограничение частоты | Вход, регистрация и обновление токена: `[admin].auth_rate_limit` запросов в минуту на адрес клиента (20). |
| Второй фактор | Приложения-аутентификаторы (TOTP) и ключи доступа, с резервными кодами. Роль может его требовать (`requireTwoFactor`). См. [Двухфакторная аутентификация](/ru/guides/auth/two-factor/). |
| Super Admin | Только Super Admin может создавать, редактировать, удалять или сбрасывать Super Admin либо выдавать эту роль. Последнего активного Super Admin удалить нельзя. |

Первый администратор регистрируется через панель, пока нет ни одного администратора. Сделайте
это сразу после первого запуска или создайте его через `verdin admin create --email …` до
того, как открыть доступ к серверу.

## Админ-панель и admin API

- Admin API (`/admin/api`) не отправляет CORS-заголовков, что бы ни было в
  `[api].cors_origins`: браузеры позволяют читать его ответы только собственному origin
  панели.
- Панель отдаётся со строгой Content Security Policy (скрипты только с собственного origin),
  `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` и
  `Referrer-Policy: strict-origin-when-cross-origin`.
- Verdin не отправляет `Strict-Transport-Security`. Добавьте его на обратном прокси, который
  терминирует TLS.

## Content API

- **API-токены** показываются один раз. Verdin хранит HMAC-SHA256 каждого токена с ключом
  `VERDIN_TOKEN_PEPPER` и 10-символьный префикс для отображения. У токенов может быть срок
  действия, и их можно перегенерировать.
- **Разрешения на поля и локали** ограничивают, что роль читает и записывает, а `populate`,
  фильтры и сортировка по связям достигают только тех типов, которые клиент может читать.
- **Ограничения запросов**: `pageSize` до `[api].max_page_size` (100), глубина `populate` до
  5, не больше 100 условий фильтра, строки запроса до 16 КБ и не больше 1000 подгружаемых
  записей на связь. Неизвестные или приватные поля в запросе дают `400`.
- **GraphQL** имеет собственные ограничения глубины и сложности (`maxDepth`,
  `maxComplexity`) и переключатель интроспекции в настройках функции.
- **Ограничения частоты**: `[api].public_rate_limit` на адрес клиента без токена и
  `[api].token_rate_limit` на API-токен или конечного пользователя, в запросах в минуту. Оба
  по умолчанию выключены (`0`). Запросы с неизвестным bearer-токеном ограничиваются по адресу.

### CORS

`[api].cors_origins` перечисляет origin браузеров, которым разрешено вызывать content API и
GraphQL:

```toml title="verdin.toml"
[api]
cors_origins = ["https://www.example.com", "https://preview.example.com"]
```

Каждая запись имеет вид `scheme://host[:port]` без пути и завершающего слеша; `["*"]`
разрешает любой origin и не сочетается с другими. Разрешены методы `GET`, `POST`, `PUT` и
`DELETE` и заголовки запроса `Authorization`, `Content-Type` и `If-None-Match`. Запуск
завершается ошибкой, если запись не является origin.

Серверные фронтенды (Astro, Next.js на сервере) вызывают API без браузера, и им запись CORS
не нужна.

## Запросы и загрузки

| Настройка | По умолчанию | Защищает от |
| --- | --- | --- |
| `[server].body_limit` | `"1mb"` | Больших тел запросов к обычным API. |
| `[server].request_timeout_secs` | `30` | Медленных запросов, удерживающих соединения. |
| `[upload].max_file_size` | 200 МБ | Больших загрузок (у загрузок свой лимит вместо `body_limit`). |
| `[upload].max_image_megapixels` | `100` | Бомб декомпрессии. |

Тип загруженного файла определяется по его байтам, а не по типу, который отправляет клиент;
имя файла используется только как запасной вариант и никогда — для типов, которые браузеры
активно выполняют (такие файлы сохраняются как `application/octet-stream`). Ссылки в rich
text `blocks` должны быть `http(s)`, `mailto:` или относительными.

## Адреса клиентов за прокси

Ограничения частоты и журналы аудита используют адрес клиента. За обратным прокси каждый
запрос приходит от прокси, поэтому укажите прокси в `[server].trusted_proxies`:

```toml title="verdin.toml"
[server]
trusted_proxies = ["10.0.0.0/8"]   # the proxies' IPs or CIDR ranges
```

Тогда Verdin читает `X-Forwarded-For` справа налево и берёт первый адрес, который не
является доверенным прокси. Запросы с любого другого адреса сохраняют адрес соединения,
поэтому клиент не может подделать свой адрес, отправив заголовок сам. Не указывайте
диапазоны, из которых могут подключаться недоверенные клиенты.

## Исходящие запросы

Вебхуки, хуки деплоя, вебхуки очистки CDN и загрузки по URL выполняют запросы, адрес которых
выбирает администратор. В `verdin start` они отклоняют loopback, частные и link-local адреса
(включая формы IPv6 со встроенными частными адресами IPv4), поэтому администратор не может
использовать их, чтобы достучаться до сервисов вашей внутренней сети.
`[webhooks].allow_private_networks = true` снимает это ограничение; делайте так, только если
всем администраторам можно доверить доступ к внутренней сети.

## Секреты

`VERDIN_ADMIN_JWT_SECRET` и `VERDIN_TOKEN_PEPPER` читаются только из окружения, и каждый
должен быть не короче 32 байт (`verdin secrets` выводит новые). Pepper также шифрует
TOTP-секреты администраторов и служит для получения ключа, которым хешируются адреса
отправителей форм. Храните оба в менеджере секретов своей платформы и никогда не коммитьте
`.env`.

Логи запросов скрывают значения параметров запроса, имена которых похожи на секретные
(`token`, `code`, `password`, `key`, `signature`…), и секретную часть URL обратных вызовов
деплоя.

## Метрики

`/_metrics` выключен, если не задано `[metrics].enabled = true`. Когда он включён, а токен
не задан, его может читать любой, кто достучится до порта. Задайте `VERDIN_METRICS_TOKEN`
(или `[metrics].token`) и собирайте метрики с `Authorization: Bearer <token>` либо закройте
путь на прокси. См. [Мониторинг](/ru/deploy/monitoring/).

## Плагины

Плагины — это модули WebAssembly, которые Extism выполняет в песочнице. У модуля нет
собственной файловой системы, сети или базы данных: всё идёт через функции хоста,
ограниченные возможностями из его `plugin.toml` (типы содержимого, которые он читает или
записывает, HTTP-хосты, собственное хранилище «ключ — значение»), с ограничением времени и
памяти на вызов (`[limits]`, 5 с и 64 МБ в примере манифеста). Перед включением плагина
администраторы видят, что он запрашивает. Скрипты админки плагинов выполняются на странице
панели, поэтому устанавливайте только плагины, которым доверяете. См.
[Плагины](/ru/extending/plugins/).

## Экспорт и резервные копии

Архивы `verdin export` содержат приватные поля и хеши паролей. Храните их как дампы базы
данных. См. [Резервные копии](/ru/deploy/backups/).

## Сообщение об уязвимости

Не открывайте публичный issue о проблеме безопасности. Следуйте
[политике безопасности](https://github.com/Verdin-CMS/verdin/blob/main/SECURITY.md)
репозитория: сообщите о ней приватно через вкладку **Security**
[репозитория](https://github.com/Verdin-CMS/verdin/security) (**Report a vulnerability**),
указав версию, шаги воспроизведения и видимые последствия. Исправления безопасности
перечислены в разделе **Security** [журнала изменений](/ru/project/changelog/).
