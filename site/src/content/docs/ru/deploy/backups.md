Данные проекта Verdin хранятся в двух местах: в **базе данных** (контент, администраторы,
роли, токены, настройки, история, журналы аудита) и в **хранилище медиа** (файлы медиатеки на
диске или в бакете). Файлы схемы находятся в вашем репозитории. Делайте резервные копии обоих
хранилищ; `verdin export` добавляет к ним переносимый архив контента.

| Способ | Содержит | Для чего |
| --- | --- | --- |
| Дамп базы данных + копия медиа | Всё | Восстановление того же проекта после аварии |
| `verdin export` | Схему, локали, медиа, все версии всех записей | Перенос контента на другой экземпляр или другую СУБД; дополнительная переносимая копия |

## Дампы базы данных

Используйте собственные инструменты вашей базы данных или автоматические резервные копии
провайдера:

```sh frame="terminal"
# PostgreSQL
pg_dump --format=custom --file=verdin-$(date +%F).dump "$VERDIN_DATABASE_URL"

# MySQL / MariaDB
mysqldump --single-transaction --routines -h <host> -u <user> -p <database> > verdin-$(date +%F).sql

# SQLite: согласованная копия во время работы сервера
sqlite3 /data/verdin.db ".backup '/backups/verdin-$(date +%F).db'"
```

Не копируйте работающий файл SQLite через `cp`: используйте `.backup` (или сначала
остановите сервер).

Дамп содержит хеши паролей, хеши API-токенов и приватные поля. Шифруйте его и храните
отдельно от серверов, которые он защищает. Чтобы восстановить дамп, нужны также те же
`VERDIN_TOKEN_PEPPER` и `VERDIN_ADMIN_JWT_SECRET`: без pepper перестают работать API-токены и
коды из приложений-аутентификаторов администраторов.

## Хранилище медиа

- **Локальный провайдер**: копируйте каталог загрузок (`[upload].provider.dir`,
  `/data/uploads` в образе Docker) обычным файловым бэкапом — после дампа базы данных, чтобы
  не пропал ни один файл, на который ссылается дамп.
- **Провайдер S3**: включите версионирование или репликацию бакета либо копируйте его
  инструментами провайдера.

Кеш преобразований изображений и поисковый индекс можно пересоздать, их резервное
копирование не нужно.

## `verdin export`

`verdin export` записывает схему, контент и медиа проекта в один файл `.tar.gz`, а
`verdin import verdin` восстанавливает его в том же проекте или на другом экземпляре, с любой
СУБД.

```sh frame="terminal"
verdin export backup-2026-09-28.tar.gz            # схема, локали, медиа и записи
verdin export content-only.tar.gz --no-media      # без медиафайлов
verdin import verdin backup-2026-09-28.tar.gz     # в этот проект
```

Запускайте их с конфигурацией проекта (тем же `verdin.toml` и окружением, что у сервера). В
контейнере: `docker compose exec verdin verdin export /data/backup.tar.gz`.

### Что входит в архив

- **Файлы схемы** как есть.
- **Локали.** Пустой проект получает их все, включая локаль по умолчанию. Проект, в котором
  уже есть локали, получает только недостающие.
- **Папки и файлы медиа** вместе с адаптивными форматами. Файлы сохраняют свой `documentId`;
  их числовые id меняются.
- **Все версии всех записей**: черновики, опубликованные версии и все локали, с их датами,
  связями (по `documentId`) и медиа, включая связи и медиа внутри компонентов и динамических
  зон. Приватные поля и хеши паролей включены.

**Не входят**: администраторы, роли, API-токены, вебхуки, настройки функций, процессы
проверки и релизы. Создайте их заново на целевом экземпляре или вместо этого восстановите
дамп базы данных.

:::caution
Экспорт содержит приватные поля и хеши паролей. Храните его так же, как дамп базы данных.
:::

### Импорт

1. Импорт записывает файлы схемы и мигрирует базу данных только безопасными шагами.
2. Если файлы схемы уже существуют и отличаются, импорт останавливается, если не передан
   `--force`.
3. Если в типах содержимого уже есть записи, импорт тоже останавливается, если не передан
   `--force`; тогда записи добавляются рядом с существующими.
4. Импортированные документы сохраняют свой `documentId`, поэтому импорт в проект, где уже
   есть те же документы, завершается ошибкой.

Импорт не запускает вебхуки и хуки плагинов и не записывает историю.

### Формат архива

Архив tar, сжатый gzip:

| Путь | Содержимое |
| --- | --- |
| `manifest.json` | `format: "verdin-export"`, версия формата, версия Verdin, число версий по типам содержимого |
| `schema/…` | Файлы схемы |
| `locales.json` | `{ default, locales: [{ code, name }] }` |
| `folders.json`, `files.jsonl` | Папки и файлы медиа, по одному JSON-объекту на строку |
| `assets/{hash}{ext}` | Сохранённые объекты файлов и их форматов |
| `entries/{uid}.jsonl` | По одной версии на строку: `documentId`, `locale`, `published`, даты, `data`, `relations`, `media` |

Чтобы перенести проект Strapi, см. [Миграция со Strapi](/ru/migrate/from-strapi/).

## Проверяйте восстановление

Время от времени восстанавливайте копию во временную базу данных, запускайте на ней Verdin
командой `verdin start` и проверяйте, что можете войти и прочитать записи и медиа.
