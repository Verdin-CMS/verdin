`verdin import strapi` переносит проект Strapi v4 или v5 в Verdin: его типы содержимого и
компоненты становятся файлами схемы, а записи, локали, медиатека, связи, конечные
пользователи и публичные разрешения импортируются. На этой странице разобрана миграция и
перечислено, что нужно изменить во фронтенде. Сравнение по функциям — в разделе
[Совместимость со Strapi](/ru/migrate/compatibility/).

## Перед началом

- Проект Strapi v4 или v5, в котором можно выполнить `strapi export`.
- Новый проект Verdin (`verdin new my-site`) или проект без файлов схемы с такими же именами.
  См. [быстрый старт](/ru/start/quickstart/).
- По возможности — база данных и хранилище медиа, которые проект Verdin будет использовать в
  продакшене: во время импорта файлы копируются в настроенный провайдер загрузок.

## 1. Экспорт из Strapi

В проекте Strapi:

```sh frame="terminal"
npx strapi export --no-encrypt -f my-export      # записывает my-export.tar.gz
```

Verdin не умеет читать зашифрованные экспорты (`.tar.gz.enc`); экспортируйте заново с
`--no-encrypt`. Несжатые экспорты (`--no-compress`, файл `.tar`) и распакованный каталог
экспорта тоже подходят.

## 2. Импорт в Verdin

<Steps>

1. Создайте проект и импортируйте экспорт:

   ```sh frame="terminal"
   verdin new my-site && cd my-site
   verdin import strapi ../my-export.tar.gz
   ```

2. Прочитайте сводку. Импортёр выводит, сколько документов, версий, файлов, папок, локалей и
   ссылок он импортировал, затем по строке на каждое предупреждение.

3. Запустите сервер разработки и откройте админ-панель:

   ```sh frame="terminal"
   verdin dev
   ```

</Steps>

Команда выполняет следующие шаги по порядку:

1. Записывает по одному файлу схемы на каждый тип содержимого `api::` и каждый компонент в
   `schema/`. Если преобразованная схема не проходит проверку, ничего не записывается.
2. Мигрирует базу данных (безопасными шагами).
3. Импортирует локали, папки и файлы медиа, записи (все черновики, опубликованные версии и
   локали), связи и медиа, прикреплённые к записям и компонентам.
4. Импортирует конечных пользователей, их роли и публичные и authenticated-разрешения.
5. Записывает `strapi-id-map.json` в каталог проекта.

| Параметр | Действие |
| --- | --- |
| `--schema-only` | Остановиться после записи файлов схемы. Полезно, чтобы сначала проверить или поправить схему. |
| `--force` | Перезаписать существующие файлы схемы и импортировать в типы содержимого, в которых уже есть записи. |

Без `--force` импорт останавливается, если файл схемы, который он собирается записать, уже
существует или если в типе содержимого уже есть записи.

## Что переносится

| Strapi | Verdin |
| --- | --- |
| Типы содержимого `api::…` и компоненты | Файлы схемы с сохранением `collectionName`, черновиков и публикации, параметров i18n и параметров полей (`required`, `private`, `unique`, длины, `regex`, значения по умолчанию…) |
| Связи между типами `api::` | Те же связи |
| Связи внутри компонентов | Ссылки `oneWay` / `manyWay` |
| Полиморфные связи (`morphToOne`, `morphToMany`, `morphOne`, `morphMany`) | Те же, со ссылками на импортированные типы содержимого |
| Медиаполя (в том числе в компонентах) | Медиаполя |
| Строки v5 (черновые и опубликованные) | Черновые и опубликованные версии |
| Строки v4 | Черновик плюс опубликованная версия, если задан `publishedAt`; `localizations` становятся локалями одного документа |
| `plugin::i18n.locale` | Локали (локаль по умолчанию в Strapi остаётся локалью по умолчанию) |
| `plugin::upload.file` и `folder` | Файлы медиатеки (с их форматами) и папки |
| Поля `password` | Поля `password` с сохранением хешей bcrypt из Strapi |
| Пользовательские поля (`customField`) | Атрибут с сохранённым `customField`; см. ниже |
| Условные поля (`conditions`, Strapi 5.17) | Сохраняются в схеме и применяются редактором |
| `plugin::users-permissions.user` | Конечные пользователи с их паролями bcrypt (пересчитываются в Argon2id при следующем входе), `confirmed` и `blocked` |
| Роли Users & Permissions | Права роли Public становятся публичными разрешениями Verdin; Authenticated и пользовательские роли становятся ролями конечных пользователей |
| Разрешения ролей на типы содержимого и загрузки | Права `find`, `findOne`, `create`, `update` и `delete`; для загрузок — `find`, `findOne`, `upload` и `destroy` |

## Что не переносится

Сообщается в виде предупреждений:

- Связи с администраторами, конечными пользователями или типами других плагинов
  (импортируются только цели `api::`). Поля `createdBy` / `updatedBy` не переносятся.
- `unique` у атрибутов `text`, `richtext`, `blocks` и `json` (Verdin поддерживает его у
  коротких текстовых типов).
- Типы атрибутов, которых Verdin не знает, и типы связей, которые он не может хранить внутри
  компонента.
- Половины связей, у которых `inversedBy` / `mappedBy` не совпадают с другой стороной.
- Некорректные коды локалей.

Не импортируются вовсе: администраторы и роли администраторов, API-токены, transfer-токены,
вебхуки, релизы, этапы процессов проверки, история содержимого и журналы аудита, а также
настройки плагинов Strapi. Для вашего кода Strapi — контроллеров, сервисов, маршрутов,
политик, middleware, lifecycle-хуков, cron-задач и настроек админки — нет аналога в Verdin,
в который его можно было бы преобразовать; см. [Перенос собственного кода](#перенос-собственного-кода).

<Aside type="note">
Пользовательские поля сохраняют своё имя `customField`, например `plugin::color-picker.color`.
Редактор показывает их с помощью [плагина](/ru/extending/plugins/), который предоставляет это
поле, а если такого нет — обычным полем ввода для типа хранения.
</Aside>

## Карта id

Verdin генерирует новые id документов: `documentId` в Strapi состоит из 24 символов, а в
Verdin — из 26, поэтому каждый документ получает новый. Числовые `id` тоже меняются.
`strapi-id-map.json` записывает соответствие:

```json title="strapi-id-map.json"
{
  "documents": {
    "api::article": {
      "hq7xw1c6m2vkn0f3t8ybz5sd": "01k6b3xg0r9m2m7c1d4e5f6g7h"
    }
  },
  "files": {
    "12": 3
  }
}
```

- В `documents` ключи — UID типа содержимого в Verdin (`api::article`, в Strapi —
  `api::article.article`), затем `documentId` из Strapi (v5) или id строки (v4: один id
  обозначает все локали документа).
- `files` сопоставляет id файлов Strapi с id файлов Verdin.

Используйте карту, чтобы переписать id, хранящиеся вне CMS: ссылки в коде фронтенда, id в
другой базе данных, аналитике, закладках.

## Проверьте результат

1. `verdin schema check` проходит, а `verdin migrate plan` сообщает, что база данных
   актуальна.
2. В админ-панели откройте каждую коллекцию и сравните число записей, черновиков и локалей
   со Strapi.
3. Откройте несколько записей со связями, компонентами, динамическими зонами и медиа и
   проверьте, что ссылки указывают на нужные документы и файлы.
4. Откройте **Медиатеку** и проверьте, что папки и изображения (с их форматами) на месте.
5. В **Настройки → Публичный доступ** и **Настройки → Конечные пользователи** проверьте
   импортированные разрешения и роли.
6. Вызовите API так, как это делает ваш фронтенд, и сравните ответы с ответами Strapi.

Затем закоммитьте `schema/`, создайте администраторов, API-токены и вебхуки и выполните
деплой (см. [чек-лист для продакшена](/ru/deploy/production-checklist/)).

## Изменения во фронтенде

Content API следует формату REST и GraphQL Strapi v5, поэтому большинство запросов работают
как есть. Измените следующее:

- **Базовый URL.** Направьте фронтенд на сервер Verdin. Content API находится под `/api`
  (`[api].prefix`), GraphQL — на `/graphql`, после того как вы включите его в
  **Настройки → Функции**.
- **API-токены.** Токены не импортируются: создайте новые в **Настройки → API-токены** и
  замените их в окружении фронтенда.
- **Id документов.** Все `documentId` и числовые `id` новые. Замените id, зашитые во
  фронтенде, на значения из `strapi-id-map.json` или, лучше, ищите записи по slug или другому
  полю `uid`.
- **URL медиа.** URL файлов указывают на нового провайдера: `/uploads/…` на сервере Verdin
  для локального провайдера или `[upload.provider].public_url` для S3. Обновите домены
  изображений, разрешённые вашим фреймворком (например, `images.remotePatterns` в Next.js).
- **Вошедшие конечные пользователи** должны войти заново: их пароли работают, а JWT,
  выданные Strapi, — нет.
- **CORS.** Если браузер вызывает API с другого origin, укажите его в `[api].cors_origins`.
- **Вебхуки.** Создайте их заново в **Настройки → Вебхуки**. Событие Strapi
  `entry.draft-discard` называется `entry.discard-draft`, а доставки подписываются (см.
  [Вебхуки](/ru/guides/integrations/webhooks/)).
- **Фронтендам для Strapi v4** нужны и изменения v5: плоские ответы без `attributes`,
  `documentId` вместо `id` в URL и `status=draft` вместо `publicationState=preview`.

Для типизированного доступа сгенерируйте типы TypeScript через `verdin types` и используйте
[типизированный клиент](/ru/guides/frontend/typed-client/).

## Перенос собственного кода

| Strapi | Verdin |
| --- | --- |
| Lifecycle-хуки, middleware document service | Хуки плагинов (`beforeCreate`, `afterUpdate`…) в [плагине WebAssembly](/ru/extending/plugins/) |
| Собственные маршруты и контроллеры | Маршруты плагинов под `/api/plugins/<name>/` |
| Cron-задачи | Задания плагинов (`[[jobs]]`) |
| Пользовательские поля | Пользовательские поля плагинов |
| Виджеты админки | Виджеты плагинов или встроенные виджеты главной панели |
| Логотип, цвета и тексты админки | `[admin.branding]` в `verdin.toml` |
| `config/*.js` | `verdin.toml` и переменные окружения ([справочник по конфигурации](/ru/reference/configuration/)) |
