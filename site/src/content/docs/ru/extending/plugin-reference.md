Эта страница — полный контракт между Verdin и плагином: манифест, что Verdin передаёт каждой
экспортируемой функции и что ожидает в ответ, и функции хоста, которые может вызывать модуль.
Введение — в разделе [Плагины](/ru/extending/plugins/), разобранный пример — в
[руководстве по созданию плагина](/ru/extending/plugin-tutorial/).

## Каталог плагина

Каждый плагин — это каталог внутри `[plugins].path` (по умолчанию `plugins/` рядом с
`verdin.toml`):

| Файл | Обязательный | Содержимое |
| --- | --- | --- |
| `plugin.toml` | да | Манифест. |
| `plugin.wasm` | да | Модуль (другой путь задаётся через `wasm`). |
| `admin/` | нет | Файлы, которые загружает админ-панель: модуль `admin.script` и его ресурсы. |

При запуске Verdin загружает все каталоги, в которых есть `plugin.toml`, в порядке имён.
Каталог пропускается и показывается с причиной в **Настройки → Плагины**, если его манифест
некорректен, модуль отсутствует или его `name` уже занято другим плагином.

## Манифест

```toml title="plugins/slugs/plugin.toml"
name = "slugs"
version = "1.0.0"
description = "Slugs from titles, and a color field"

[capabilities]
read = ["api::article"]
write = ["api::tag"]
http = ["api.example.com"]
kv = true

[limits]
timeout_ms = 5000
memory_mb = 64

[[hooks]]
on = "beforeCreate"
uid = "api::article"
function = "before_write"

[routes]
function = "handle"

[[jobs]]
schedule = "*/15 * * * *"
function = "refresh"

[[graphql]]
name = "slugStats"
function = "stats"

[admin]
script = "index.js"

[[admin.widgets]]
id = "stats"
title = "Slug stats"
element = "slugs-stats"

[[admin.fields]]
id = "color"
title = "Color"
element = "slugs-color"
type = "string"

[[settings]]
key = "separator"
label = "Separator"
type = "select"
options = ["-", "_"]
default = "-"
```

Неизвестные ключи — ошибка в любой таблице.

### Ключи верхнего уровня

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `name` | обязательный | Id плагина в URL, настройках и пользовательских полях: строчные буквы, цифры и `-`, начинается с буквы, не больше 64 символов. |
| `version` | обязательный | Показывается в админке и в логе. |
| `description` | не задан | Показывается в **Настройки → Плагины**. |
| `wasm` | `"plugin.wasm"` | Модуль относительно каталога плагина (без `..`, не абсолютный путь). |
| `wasi` | `false` | Дать модулю WASI: часы и случайные числа. Файлов и сокетов нет в любом случае. |

### `[capabilities]`

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `read` | `[]` | Типы содержимого, которые может читать `verdin_content` (`findMany`, `findOne`): UID вроде `api::article` или `"*"` для всех. |
| `write` | `[]` | Типы содержимого, для которых разрешены `create`, `update`, `delete`, `publish` и `unpublish`. Подразумевает `read`. |
| `http` | `[]` | Хосты, на которые модуль может отправлять HTTP-запросы: `api.example.com` или `*.example.com`. |
| `kv` | `false` | Собственное хранилище «ключ — значение» плагина (`verdin_kv_get`, `verdin_kv_set`). |

Возможности ограничивают только вызовы хоста. Хуки срабатывают для указанных в них типов
независимо от `read`, а маршруты доступны всем.

### `[limits]`

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `timeout_ms` | `5000` | Ограничение времени одного вызова в миллисекундах. |
| `memory_mb` | `64` | Максимальный объём памяти модуля в мегабайтах. |

Оба значения должны быть положительными.

### `[[hooks]]`

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `on` | обязательный | Событие, см. ниже. |
| `uid` | `"*"` | Тип содержимого (`api::article`) или `"*"` для всех. |
| `function` | обязательный | Экспортируемая функция, которую нужно вызвать. |

События:

| До записи | После записи |
| --- | --- |
| `beforeCreate` | `afterCreate` |
| `beforeUpdate` | `afterUpdate` |
| `beforeDelete` | `afterDelete` |
| `beforePublish` | `afterPublish` |
| `beforeUnpublish` | `afterUnpublish` |
| `beforeDiscardDraft` | `afterDiscardDraft` |

Это имена событий жизненного цикла Strapi. Хуки срабатывают при записи из админ-панели, REST и
GraphQL API и релизов, но не при записи, сделанной плагинами (см.
[Запись из плагинов](#запись-из-плагинов)) или командами `verdin import`.

### `[routes]`

| Ключ | Описание |
| --- | --- |
| `function` | Экспортируемая функция, которая обслуживает все запросы к `/api/plugins/<name>` и `/api/plugins/<name>/…` с любым методом. |

Путь следует `[api].prefix`.

### `[[jobs]]`

| Ключ | Описание |
| --- | --- |
| `schedule` | Выражение cron в UTC, с необязательными секундами: `*/15 * * * *`, `0 0 3 * * *`. |
| `function` | Экспортируемая функция, которую нужно вызвать. |

### `[[graphql]]`

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `name` | обязательный | Имя поля: начинается со строчной буквы, дальше буквы, цифры и `_`. |
| `function` | обязательный | Экспортируемая функция, которая его разрешает. |
| `mutation` | `false` | Добавить поле в `Mutation` вместо `Query`. |
| `description` | не задан | Описание поля в схеме. |

Каждая запись добавляет `name(args: JSON): JSON`. Имя, которое уже использует тип содержимого
или раньше занял другой плагин, пропускается с предупреждением в логе.

### `[admin]`

| Ключ | Описание |
| --- | --- |
| `script` | ES-модуль в `admin/`, который определяет пользовательские элементы (без `..`, не абсолютный путь). |
| `[[admin.widgets]]` | Типы виджетов главной панели: `id`, `title`, `element`, необязательный `description`. |
| `[[admin.fields]]` | Пользовательские поля: `id`, `title`, `element`, `type` (тип атрибута, в котором хранится значение, например `string` или `json`), необязательный `description`. |

`element` — имя пользовательского элемента: строчные буквы, цифры и `-`, минимум один `-`
(`slugs-color`).

### `[[settings]]`

Описывает форму **Настройки → Плагины → Настройки**. Без этой секции настройки — это
произвольный JSON-объект.

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `key` | обязательный | Ключ в объекте настроек: буквы, цифры и `_`, не начинается с цифры, уникален. |
| `label` | обязательный | Подпись в форме. |
| `type` | `"string"` | `string`, `text`, `url`, `number`, `integer`, `boolean` или `select`. |
| `description` | не задан | Текст подсказки под полем. |
| `required` | `false` | Нужно значение (для текста — непустое), если нет `default`. |
| `options` | `[]` | Варианты для `select` (для него обязательны). |
| `default` | не задан | Используется, если ключ отсутствует или равен `null`. Должен подходить полю. |
| `min`, `max` | не заданы | Границы значений `number` и `integer`; границы длины для `string` и `text`. |

Значения `url` пусты или являются URL `http(s)://`. Если форма описана, сервер отклоняет
настройки с неизвестными ключами, неверными типами, значениями вне границ или без
обязательных значений (400).

## Экспортируемые функции

Каждая экспортируемая функция принимает один JSON-документ и возвращает один (или ничего).
Пустой вывод считается `null`; вывод, который не является JSON, считается сбоем.

### Хуки «до»

Вход:

```json
{
  "event": "beforeUpdate",
  "uid": "api::article",
  "documentId": "01m3p88ry359w82nsx496mep5t",
  "locale": "en",
  "data": { "title": "Hello" }
}
```

| Поле | Описание |
| --- | --- |
| `event` | Событие хука. |
| `uid` | Тип содержимого. |
| `documentId` | Документ или `null` при `beforeCreate`. |
| `locale` | Для локализованных типов — записываемая локаль (локаль по умолчанию, если в запросе её нет); для остальных типов — `null`. |
| `data` | Записываемые данные в том виде, в каком их отправил запрос: при создании и обновлении. Для остальных событий — `null`. При обновлении — только переданные поля. |

Выход:

| Выход | Результат |
| --- | --- |
| `{ "data": { … } }` | Заменяет записываемые данные. Они проверяются так же, как исходные. |
| `{ "error": "message" }` | Отклоняет запись: клиент получает 400 с этим сообщением. |
| `{}` или что-то другое | Запись продолжается без изменений. |

Если подходит несколько хуков, они выполняются в порядке плагинов (имён каталогов), затем в
порядке манифеста; каждый видит данные, которые вернул предыдущий. Упавший хук (trap,
тайм-аут, некорректный вывод) записывается в лог и пропускается: запись продолжается.

### Хуки «после»

Вход: `{ "event", "uid", "documentId", "locale" }`, отправляется после фиксации записи. Выход
игнорируется; сбои записываются в лог. Если вам нужны поля записи, прочитайте её через
`verdin_content` (с возможностью `read`).

### Маршруты

Вход:

```json
{
  "method": "GET",
  "path": "/stats",
  "query": "page=2&sort=title",
  "headers": { "accept": "application/json", "user-agent": "curl/8.7.1" },
  "body": "",
  "actor": { "kind": "public" }
}
```

| Поле | Описание |
| --- | --- |
| `method` | HTTP-метод. |
| `path` | Путь после `/api/plugins/<name>`, начинается с `/` (`/` для корня плагина). |
| `query` | Сырая строка запроса без `?` (пустая, если её нет). |
| `headers` | Только `content-type`, `accept`, `user-agent` и `accept-language`, если они есть. |
| `body` | Тело запроса строкой (некорректный UTF-8 заменяется). |
| `actor` | Кто вызывает: `{ "kind": "public" }`, `{ "kind": "token", "id": 3 }` (API-токен) или `{ "kind": "user", "id": 12 }` (вошедший конечный пользователь). |

Заголовок `Authorization` с недействительным токеном отклоняется с 401 до вызова плагина.
Разрешения публичного доступа и API-токенов не применяются: проверяйте `actor` сами.

Выход:

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `status` | `200` | HTTP-статус. |
| `headers` | нет | Заголовки ответа. Сохраняются только `content-type`, `cache-control`, `location`, `etag`, `last-modified` и `content-disposition`. |
| `body` | пусто | Строка отправляется как есть (`text/plain`, если вы не задали `content-type`); любое другое значение JSON отправляется как `application/json`. |

Выключенный или неизвестный плагин либо плагин без `[routes]` отвечает 404. Неудачный вызов
отвечает 502 с `{ "data": null, "error": { "status": 502, "name": "PluginError", … } }`.
Маршруты используют общие с content API `[server].body_limit` и
`[server].request_timeout_secs`.

### Задания

Вход: `{ "scheduledAt": "2026-09-29T03:00:00+00:00" }` — время, на которое был запланирован
запуск. Выход игнорируется; сбои записываются в лог. Задания выполняются, только пока плагин
включён, и только на экземплярах с `[plugins].run_jobs = true`. Запуск, пропущенный, пока
сервер не работал, не наверстывается.

### Поля GraphQL

Вход: `{ "args": …, "actor": … }`, где `args` — аргумент `args` поля (любой JSON или `null`),
а `actor` — как для маршрутов. Выход — значение поля. Сбой или выключенный плагин дают ошибку
GraphQL с кодом `PLUGIN_ERROR`. Как и в маршрутах, доступ проверяет плагин.

## Функции хоста

Импортируйте их из пространства имён `extism:host/user` (`extern "ExtismHost"` в Rust). Они
принимают и возвращают JSON в виде строк; `Json<Value>` из `extism-pdk` выполняет
преобразование.

| Функция | Вход | Выход |
| --- | --- | --- |
| `verdin_log` | `{ "level": "info" \| "warn" \| "error", "message": "…" }` | нет |
| `verdin_content` | Запрос к контенту (см. ниже) | Результат или `{ "error": "…" }` |
| `verdin_kv_get` | Ключ простой строкой | Сохранённое значение JSON или `null` |
| `verdin_kv_set` | `{ "key": "…", "value": … }` | нет |
| `verdin_config` | нет | Объект настроек с подставленными объявленными значениями по умолчанию |

### `verdin_log`

Пишет в лог сервера (с именем плагина) и в журнал плагина в **Настройки → Плагины →
Журнал**. Другие уровни считаются `info`. Журнал плагина хранит в памяти последние 200
сообщений, каждое обрезается до 2000 символов.

### `verdin_content`

```json
{ "op": "findMany", "uid": "api::article", "query": { "filters": { "title": { "$eq": "x" } }, "sort": ["title"] } }
```

| Поле | Используется в | Описание |
| --- | --- | --- |
| `op` | всех | `findMany`, `findOne`, `create`, `update`, `delete`, `publish` или `unpublish`. |
| `uid` | всех | Тип содержимого. Должен быть в возможностях. |
| `documentId` | `findOne`, `update`, `delete`, `publish`, `unpublish` | Документ. |
| `query` | `findMany`, `findOne` | Параметры REST API в виде JSON-объекта: `filters`, `sort`, `fields`, `populate`, `pagination`, `status`. |
| `data` | `create`, `update` | Записываемые поля, как в `data` REST-запроса. |
| `status` | `create`, `update` | `"draft"` сохраняет черновик. Иначе запись публикуется, как REST-запись без `?status=draft`. |
| `locale` | всех | Локаль для чтения или записи. |

Результаты:

| `op` | Результат |
| --- | --- |
| `findMany` | `{ "documents": [...], "meta": { "pagination": {…} } }` |
| `findOne` | `{ "document": {…} }` (`null`, если не найден) |
| `create`, `update` | `{ "documentId": "…" }` |
| `delete` | `{ "deleted": true }` |
| `publish` | `{ "published": true }` |
| `unpublish` | `{ "unpublished": true }` |

Вызов вне возможностей, неизвестная операция, ошибка валидации или отсутствующий документ
вместо этого дают `{ "error": "…" }`. Чтение возвращает опубликованные версии, если запрос не
просит `"status": "draft"`.

#### Запись из плагинов

Запись через `verdin_content` пропускает хуки **«до»** всех плагинов, чтобы плагин не мог
зациклиться на собственных изменениях. Всё остальное применяется: валидация, этапы проверки,
вебхуки, история, журнал аудита и хуки **«после»** всех плагинов, включая тот, что выполняет
запись. Защитите хук «после», который пишет в тот же тип, на который подписан.

### `verdin_kv_get` и `verdin_kv_set`

Хранилище «ключ — значение» для каждого плагина в базе данных Verdin, общее для всех
экземпляров. Ключи — от 1 до 255 байт; значения — любой JSON. Установка `null` удаляет ключ.
Без возможности `kv` чтение возвращает `null`, а запись игнорируется.

### `verdin_config`

Возвращает настройки, сохранённые в **Настройки → Плагины**, где для отсутствующих ключей
подставлен `default` каждой объявленной настройки. `{}`, если ничего не сохранено.

### HTTP

Если хосты перечислены в `http`, используйте поддержку HTTP в Extism
(`extism_pdk::http::request` в Rust). Запросы к другим хостам завершаются ошибкой.

## Точки расширения админки

Админ-панель запрашивает у сервера расширения включённых плагинов и один раз импортирует
каждый `admin.script` как ES-модуль из `/admin/plugins/<name>/<script>` (относительно
`[admin].path`). Файлы из каталога `admin/` плагина отдаются там, пока плагин включён, с
`X-Content-Type-Options: nosniff` и `Cache-Control: no-cache`. Модуль должен определить
пользовательские элементы, названные в манифесте; элемент, не определённый в течение 3
секунд, пропускается.

### Виджеты

Каждая запись `[[admin.widgets]]` — это тип виджета, который администраторы могут добавить на
главную панель. Элемент получает свойство `context`:

| Свойство | Описание |
| --- | --- |
| `apiBase` | Базовый путь content API, например `/api`. |
| `adminApiBase` | Базовый путь admin API, например `/admin/api`. |
| `fetch(path, init)` | `fetch` с учётными данными вошедшего администратора. Относительные пути разрешаются относительно `adminApiBase`; пути под любым из базовых путей и абсолютные URL сохраняются. |

```js title="plugins/slugs/admin/index.js"
class SlugStats extends HTMLElement {
  set context(context) {
    // Admin API, with the admin's session.
    context.fetch('auth/me').then((response) => response.json())
      .then(({ data }) => { this.textContent = `Hello ${data.firstname ?? data.email}`; });
    // The plugin's own route, on the content API: sent without the admin's session.
    context.fetch(`${context.apiBase}/plugins/slugs/stats`).then((response) => response.json())
      .then((stats) => { this.title = JSON.stringify(stats); });
  }
}
customElements.define('slugs-stats', SlugStats);
```

`context.fetch` отправляет сессию администратора только с запросами к admin API. Пути под
`context.apiBase` (content API, включая маршруты вашего плагина) отправляются без неё,
поскольку content API не принимает сессии администраторов; на них отвечают с разрешениями
публичной роли. До 0.10 сессия отправлялась и туда, и такие запросы падали; виджеты,
написанные для 0.9, которые вызывают обычный `fetch`, продолжают работать.

### Пользовательские поля

Каждая запись `[[admin.fields]]` — это поле, которое атрибуты могут использовать через
`"customField": "plugin::<name>.<id>"`; `type` атрибута должен соответствовать тому, как поле
хранит значение. Его предлагает **Конструктор типов содержимого**. Элемент получает:

| Свойство | Описание |
| --- | --- |
| `value` | Текущее значение. |
| `disabled` | Выключено ли редактирование. |
| `attribute` | Определение атрибута из схемы. |
| `locale` | Редактируемая локаль. |

Новое значение элемент сообщает событием `change`, у которого `detail` — это значение (или,
без `detail`, через собственное свойство `value`). Если плагин выключен или его элемента нет,
редактор показывает обычное поле ввода для типа хранения. См.
[Типы атрибутов](/ru/reference/attribute-types/).

## Среда выполнения и ограничения

| Ограничение | Значение |
| --- | --- |
| Время на вызов | `[limits].timeout_ms`, по умолчанию 5000 мс |
| Память | `[limits].memory_mb`, по умолчанию 64 МБ |
| Параллелизм | Один вызов за раз на плагин; вызовы ждут друг друга |
| Экземпляр модуля | Один на плагин, создаётся при первом использовании; пересоздаётся после неудачного вызова (его память теряется) |
| Журнал | 200 сообщений на плагин, по 2000 символов, в памяти |
| Ключи KV | От 1 до 255 байт |
| Заголовки запроса маршрута | `content-type`, `accept`, `user-agent`, `accept-language` |
| Заголовки ответа маршрута | `content-type`, `cache-control`, `location`, `etag`, `last-modified`, `content-disposition` |

Изменения манифеста или модуля применяются после перезапуска; переключатели и настройки —
сразу. Для управления плагинами нужно `plugins.manage` (см.
[справочник по разрешениям](/ru/reference/permissions/)).
