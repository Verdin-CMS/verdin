В этом руководстве вы создадите статический блог на [Astro](https://astro.build), который
читает контент из Verdin: главную страницу со списком статей, отдельную страницу для каждой
статьи по адресу `/articles/<slug>/` с её категорией и, при желании, страницу, которая
показывает черновики по ссылке предпросмотра из админки. Вы будете использовать
типизированный клиент `@verdin/client` с типами, сгенерированными по схеме.

Написано для Astro 7.3 (`create-astro` 5.2) и Node.js 22.12 или новее, с Verdin и
`@verdin/client` 0.10. [Руководство по Next.js](/ru/start/tutorial-nextjs/) строит тот же блог
на Next.js.

## Перед началом

Вам нужны бинарник `verdin` в `PATH` (см. [Быстрый старт](/ru/start/quickstart/)), Node.js и
Git. В итоге у вас будут две папки рядом: `cms` — проект Verdin и `blog` — сайт на Astro.

## 1. Настройте Verdin со схемой блога

Проект [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) из
репозитория моделирует блог: статьи с заголовком, `slug`, кратким описанием, телом в Markdown
(`body`), категорией и тегами, а также одиночный тип главной страницы и несколько компонентов.

<Steps>

1. Создайте проект Verdin и скопируйте в него пример схемы:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Запустите его:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   Первый запуск создаёт таблицы для четырёх типов содержимого.

3. Откройте [http://localhost:1337/admin/](http://localhost:1337/admin/) и создайте первого
   администратора.

4. В разделе **Коллекции** откройте **Category**, выберите **Новая запись**, назовите её
   `News` и сохраните.

5. Откройте **Article**, выберите **Новая запись** и заполните заголовок, краткое описание и
   тело в Markdown. `slug` генерируется из заголовка. Выберите категорию `News` и нажмите
   **Опубликовать**. Добавьте так же вторую статью.

6. Откройте **Настройки → Публичный доступ**, разрешите **Найти** и **Найти одну** для
   **Article** и **Category** и выберите **Сохранить**.

</Steps>

Проверьте, что API отвечает:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Для подгрузки связи нужен доступ на чтение к её цели. Без **Найти** для **Category**
`populate=category` отвечает `400` с ``invalid key `category` in populate``.
</Aside>

## 2. Создайте проект Astro

В новом терминале рядом с `cms`:

```sh title="Terminal"
npm create astro@latest blog -- --template minimal --no-git --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) превращает Markdown из поля `body` в HTML.

## 3. Сгенерируйте типы

`verdin types` читает схему и записывает по одному TypeScript-интерфейсу на тип содержимого и
компонент, а также карту маршрутов `VerdinSchema` для клиента. Запустите команду из `blog`,
указав конфигурацию проекта Verdin:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

Среди прочего файл содержит:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

Связи, медиа и компоненты необязательны, потому что API возвращает их, только если вы их
подгружаете. Запускайте команду снова при каждом изменении схемы.

## 4. Подключитесь к Verdin

Объявите URL сервера и необязательный API-токен в типизированном окружении Astro:

```js title="astro.config.mjs"
// @ts-check
import { defineConfig, envField } from 'astro/config';

export default defineConfig({
  env: {
    schema: {
      VERDIN_URL: envField.string({ context: 'server', access: 'public', default: 'http://localhost:1337' }),
      VERDIN_TOKEN: envField.string({ context: 'server', access: 'secret', optional: true }),
    },
  },
});
```

Без токена клиент читает от имени публичной роли, которую вы открыли на шаге 1. Чтобы читать
с токеном, создайте токен **Только чтение** в **Настройки → API-токены** и запишите его в
`.env` как `VERDIN_TOKEN=…`.

Создайте клиент один раз и используйте его везде:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import { VERDIN_TOKEN, VERDIN_URL } from 'astro:env/server';
import type { VerdinSchema } from '../verdin-types';

export const verdin = createClient<VerdinSchema>({
  url: VERDIN_URL,
  token: VERDIN_TOKEN,
});
```

Теперь `verdin.collection('articles')` принимает только маршруты вашей схемы, а её результаты
имеют тип `Article`.

## 5. Добавьте макет

Замените HTML стартовой страницы макетом, общим для всех страниц:

```astro title="src/layouts/Layout.astro"
---
interface Props {
  title: string;
}

const { title } = Astro.props;
---

<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>{title}</title>
  </head>
  <body>
    <header><a href="/">My blog</a></header>
    <main>
      <slot />
    </main>
  </body>
</html>
```

## 6. Выведите список статей

```astro title="src/pages/index.astro"
---
import Layout from '../layouts/Layout.astro';
import { verdin } from '../lib/verdin';

const { data: articles } = await verdin.collection('articles').find({
  fields: ['title', 'slug', 'excerpt', 'publishedAt'],
  populate: { category: { fields: ['name'] } },
  sort: ['publishedAt:desc'],
});
---

<Layout title="My blog">
  <h1>Articles</h1>
  <ul>
    {articles.map((article) => (
      <li>
        <a href={`/articles/${article.slug}/`}>{article.title}</a>
        {article.category && <small> in {article.category.name}</small>}
        {article.excerpt && <p>{article.excerpt}</p>}
      </li>
    ))}
  </ul>
</Layout>
```

Этот запрос — REST-вызов
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`
в формате Strapi v5. `fields` делает ответ небольшим, а `populate` добавляет категорию только
с её названием. Публичная роль читает только опубликованные статьи.

## 7. Добавьте страницу для каждой статьи

Astro собирает по странице на статью. `getStaticPaths` запрашивает статьи с их категорией и
передаёт каждую на её страницу:

```astro title="src/pages/articles/[slug].astro"
---
import type { GetStaticPaths } from 'astro';
import { marked } from 'marked';
import Layout from '../../layouts/Layout.astro';
import { verdin } from '../../lib/verdin';

export const getStaticPaths = (async () => {
  const { data: articles } = await verdin.collection('articles').find({
    populate: { category: true },
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({
    params: { slug: article.slug },
    props: { article },
  }));
}) satisfies GetStaticPaths;

const { article } = Astro.props;
const html = await marked.parse(article.body ?? '');
---

<Layout title={article.title}>
  <article>
    <h1>{article.title}</h1>
    {article.category && <p>Category: {article.category.name}</p>}
    <Fragment set:html={html} />
  </article>
</Layout>
```

`pageSize` ограничен `[api].max_page_size` (по умолчанию 100). Если статей больше,
запрашивайте страницы в цикле, используя `meta.pagination.pageCount`.

<Aside type="caution">
`marked` не очищает HTML. Для Markdown, который пишут ваши собственные редакторы, это
нормально; если контент может приходить от недоверенных людей, очищайте HTML перед выводом.
</Aside>

## 8. Запустите

```sh title="Terminal"
npm run dev
```

Откройте [http://localhost:4321](http://localhost:4321): список показывает опубликованные
статьи, и каждая ведёт на свою страницу. `npm run build` записывает статический сайт в
`dist/`.

Статическая сборка читает контент один раз. Чтобы публиковать изменения, пересобирайте сайт
при изменении контента, например по вебхуку или хуку деплоя; см.
[Деплои и CDN](/ru/guides/integrations/deploys-and-cdn/).

Теперь проект выглядит так:

<FileTree>
- blog/
  - astro.config.mjs
  - src/
    - verdin-types.ts сгенерирован `verdin types`
    - lib/
      - verdin.ts
    - layouts/
      - Layout.astro
    - pages/
      - index.astro
      - articles/
        - [slug].astro
</FileTree>

## 9. Необязательно: предпросмотр черновиков

Админка может открыть черновик на вашем сайте с короткоживущим токеном предпросмотра. Токен
читает только этот один документ, включая черновики, и больше ничего. Поскольку черновики
меняются после сборки, страница предпросмотра рендерится при каждом запросе, а для этого
нужен адаптер:

```sh title="Terminal"
npx astro add node --yes
```

Добавьте клиент, который отправляет токен предпросмотра в заголовке `x-verdin-preview`:

```ts title="src/lib/verdin.ts" ins={10-16}
import { createClient } from '@verdin/client';
import { VERDIN_TOKEN, VERDIN_URL } from 'astro:env/server';
import type { VerdinSchema } from '../verdin-types';

export const verdin = createClient<VerdinSchema>({
  url: VERDIN_URL,
  token: VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url: VERDIN_URL,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Затем страница. `prerender = false` рендерит её по запросу; токен приходит в параметре
запроса `preview`:

```astro title="src/pages/preview/[documentId].astro"
---
import { VerdinError } from '@verdin/client';
import { marked } from 'marked';
import Layout from '../../layouts/Layout.astro';
import { previewClient } from '../../lib/verdin';

export const prerender = false;

const { documentId } = Astro.params;
const token = Astro.url.searchParams.get('preview');
if (!documentId || !token) {
  return new Response('Missing preview token', { status: 401 });
}

let article;
try {
  ({ data: article } = await previewClient(token)
    .collection('articles')
    .findOne(documentId, { status: 'draft', populate: { category: true } }));
} catch (error) {
  if (error instanceof VerdinError) {
    return new Response('This preview link has expired', { status: error.status });
  }
  throw error;
}
const html = await marked.parse(article.body ?? '');
Astro.response.headers.set('cache-control', 'no-store');
---

<Layout title={`Preview: ${article.title}`}>
  <p><strong>Draft preview</strong></p>
  <article>
    <h1>{article.title}</h1>
    {article.category && <p>Category: {article.category.name}</p>}
    <Fragment set:html={html} />
  </article>
</Layout>
```

Токен предпросмотра не может получать списки записей, поэтому страница ищет черновик по
`documentId`, а не по slug. Теперь сообщите Verdin, где находится страница:

<Steps>

1. В админке откройте **Настройки → Функции**, включите **Предпросмотр** и выберите
   **Настроить URL предпросмотра**.
2. Задайте шаблон URL для **Article** — `http://localhost:4321/preview/{documentId}` — и
   сохраните. Verdin добавит токен как `?preview=…`.
3. Откройте статью, измените её и выберите **Сохранить черновик**, затем **Открыть
   предпросмотр**.

</Steps>

Страница покажет черновик. По умолчанию ссылки действуют 60 минут. Подстановки и настройки
описаны в разделе [Предпросмотр](/ru/guides/content/preview/), а редактирование прямо из
предпросмотра — в разделе [Визуальное редактирование](/ru/guides/frontend/visual-editing/).
