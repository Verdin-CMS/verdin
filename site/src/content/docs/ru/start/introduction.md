Verdin — headless CMS с открытым исходным кодом, написанная на Rust. Вы моделируете типы
содержимого, редакторы пишут и публикуют в админ-панели, а ваши сайты и приложения читают
контент через REST или GraphQL API. Verdin не рендерит страницы: это делает ваш фронтенд.

Это переписанный [Strapi v5](https://strapi.io): формат схемы и content API устроены так же,
поэтому проект Strapi и его фронтенд можно перенести с небольшими изменениями.

## Для кого это

- **Разработчики сайтов и приложений**, которым нужна CMS, работающая одним процессом, с
  моделью контента в git и чтением из любого фронтенда: Astro, Next.js, мобильного
  приложения.
- **Команды на Strapi**, которым нужен тот же API с меньшим потреблением ресурсов или
  функции, которые Strapi оставляет для платных тарифов. У Verdin нет enterprise-редакции:
  SSO, журналы аудита, процессы проверки и релизы входят в проект с открытым исходным кодом.
- **Редакторы**, которые получают черновики, публикацию, историю и предпросмотр в
  админ-панели, доступной на 18 языках.

## Что внутри

Один исполняемый файл, `verdin`, — это и сервер, и инструмент командной строки, и
админ-панель. В продакшене нет ни среды выполнения Node.js, ни `node_modules`.

| Область | Что вы получаете |
| --- | --- |
| Базы данных | PostgreSQL 14+, MySQL 8.4+, MariaDB 10.11+ и SQLite, покрытые одним набором тестов. |
| Модель контента | Типы-коллекции, одиночные типы, компоненты, динамические зоны, связи, медиа, rich text в Markdown или в формате блоков Strapi. Схема — это JSON-файлы в вашем проекте. |
| Изменения схемы | Каждое изменение становится планом миграции с уровнем риска и точным SQL. Разрушительные шаги выполняются, только если вы их разрешите. |
| API | REST под `/api` с параметрами Strapi v5 (`filters`, `populate`, `sort`, `pagination`), необязательный эндпоинт GraphQL, документ OpenAPI и типизированный TypeScript-клиент. |
| Редактирование | Черновики и публикация, локализованный контент, история содержимого, релизы, процессы проверки, комментарии и задачи, присутствие в реальном времени, предпросмотр и визуальное редактирование на вашем собственном сайте. |
| Доступ | Роли администраторов вплоть до полей и локалей, API-токены, публичный доступ, SSO через OpenID Connect, двухфакторный вход с ключами доступа, журналы аудита. |
| Функции сайта | Полнотекстовый поиск, карта сайта, редиректы, меню и формы, вебхуки, обновления в реальном времени. |
| Расширение | Плагины WebAssembly, которые подключаются к записи данных, добавляют маршруты и задания, а также виджеты и пользовательские поля в админку — в пределах объявленных возможностей. |

## Как это соотносится со Strapi v5

**Что так же:**

- Файлы схемы используют формат Strapi: `schema/content-types/<singularName>.json` и
  `schema/components/<category>/<name>.json`.
- REST content API: маршруты, плоский формат ответов с `documentId`, параметры запроса и
  операторы, семантика записи (`POST` или `PUT` публикует, если не передать
  `?status=draft`), тела ошибок.
- Схема GraphQL устроена как в GraphQL-плагине Strapi v5.
- Конечные пользователи (регистрация, вход, OAuth, роли) следуют API `users-permissions`.

**Что иначе:**

- **Изменения схемы — это запланированные миграции.** Verdin сравнивает файлы схемы с базой
  данных и показывает шаги до их выполнения. `verdin start` не запускается, пока база данных
  отстаёт от схемы.
- **Конструктор типов содержимого работает только в режиме разработки.** В продакшене схема
  берётся из вашего репозитория.
- **Плагины — на WebAssembly, а не на JavaScript.** Плагины Strapi, а также собственные
  контроллеры, сервисы и файлы lifecycle в `src/` в Verdin не работают.
- **База данных не общая со Strapi.** Проект Strapi переносится командой
  `verdin import strapi`, которая даёт каждому документу новый id.
- **Несколько дополнений в REST**: действия публикации и снятия с публикации
  (`POST /api/<route>/<documentId>/actions/publish`), а подгруженный компонент возвращается
  целиком, включая вложенные компоненты.

Подробно отличия перечислены в разделе [Совместимость со Strapi](/ru/migrate/compatibility/).

## Когда им не стоит пользоваться

- **Вы зависите от плагинов Strapi или собственного серверного кода на JavaScript.** Verdin
  не может их запускать; их придётся переписать как плагины WebAssembly или перенести логику
  в другое место.
- **Вам нужна стабильная 1.0.** Verdin сейчас на версии 0.10: минорные релизы ещё могут
  менять конфигурацию и поведение. Перед каждым читайте [Обновление](/ru/migrate/upgrading/).
- **Вы хотите, чтобы CMS рендерила страницы.** Verdin — headless; используйте его вместе с
  фронтенд-фреймворком или генератором статических сайтов.
- **Вам нужен управляемый сервис.** Verdin размещается у вас: вы запускаете бинарник или
  образ Docker на своей инфраструктуре.
