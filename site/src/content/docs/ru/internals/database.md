На этой странице объясняется, как Verdin поддерживает четыре СУБД одним путём кода: крейт `verdin-db`, который подключается и выполняет запросы, построители SQL, которые ветвятся по СУБД, и различия диалектов, которые они учитывают. Прочитайте её, прежде чем писать SQL где-либо в сервере. Как устроены таблицы, описано в разделе [хранение](/ru/internals/storage/).

## Минимальные версии

`Database::connect` определяет СУБД и её версию и отказывается запускаться ниже этих минимумов (`Flavor::minimum_version` в `crates/verdin-db/src/lib.rs`):

| СУБД | Минимум | Причина |
|---|---|---|
| PostgreSQL | 14 | Самая старая версия, которая ещё поддерживается разработчиками |
| MySQL | 8.4 LTS | Срок поддержки 8.0 закончился в апреле 2026 |
| MariaDB | 10.11 LTS | Самый старый актуальный релиз с долгосрочной поддержкой; сопоставление `utf8mb4_uca1400_ai_ci`, пригодный JSON |
| SQLite | 3.35 | `ALTER TABLE … DROP COLUMN`; библиотека вкомпилирована в бинарник |

CI запускает все тесты на PostgreSQL 14 и 17, MySQL 8.4, MariaDB 10.11 и 11.4 и SQLite. См. [тестирование](/ru/internals/testing/).

## Подключение

`verdin-db` оборачивает по одному пулу `sqlx` на бэкенд:

```rust
pub enum Pool { Postgres(PgPool), MySql(MySqlPool), Sqlite(SqlitePool) }

pub enum Flavor { Postgres, MySql, MariaDb, Sqlite }

pub struct Database { pool: Pool, flavor: Flavor, version: Version }
```

- Схемы URL: `postgres://` или `postgresql://`, `mysql://`, `mariadb://` (псевдоним `mysql://`) и `sqlite:`. MySQL и MariaDB используют общий драйвер MySQL из `sqlx`; вариант определяется по `SELECT VERSION()`, который в MariaDB содержит `MariaDB`.
- Соединения MySQL и MariaDB используют `utf8mb4` и задают часовой пояс сессии `+00:00`, поэтому все временные метки хранятся в UTC.
- Соединения SQLite включают внешние ключи, используют журналирование WAL и тайм-аут занятости 5 секунд и создают файл базы данных (и его папку), если их нет. Базы данных в памяти получают одно соединение, потому что каждое соединение с `:memory:` открывало бы отдельную базу данных.
- `ConnectOptions` задаёт размер пула (`[database].pool_max`, по умолчанию 10) и время ожидания свободного соединения (10 секунд).

`Flavor` несёт несколько фактов, по которым ветвится остальной код: `transactional_ddl()` (PostgreSQL и SQLite), `is_mysql_family()`, `quote(identifier)` (обратные кавычки в MySQL и MariaDB, двойные кавычки в остальных) и `minimum_version()`.

Трейта диалекта нет. Код, который строит SQL, проверяет `Flavor` там, где СУБД различаются.

## Выполнение операторов

Три исполнителя имеют одни и те же методы (`execute`, `fetch_all`, `has_rows`, `insert_returning_id`):

| Исполнитель | Применение |
|---|---|
| `db.queries()` | Один оператор на любом соединении из пула |
| `db.acquire()` → `Conn` | Несколько операторов на одном соединении, например запуск миграции, держащий блокировку |
| `db.begin()` → `Tx` | Транзакция; если её отбросить без `commit()`, она откатывается |

Операторы пишутся с заполнителями `?`, которые для PostgreSQL переписываются в `$1, $2…`. Значения — это `SqlValue`, всегда передаваемые как параметры. Сам текст SQL может содержать только идентификаторы из проверенной схемы, поэтому он передаётся в `sqlx` как `AssertSqlSafe`.

**Декодирование по схеме.** При чтении передаётся `ColumnKind` каждой выбранной колонки, и значения декодируются по этому виду, а не по типу, который сообщает драйвер. Благодаря этому `JSON` в MariaDB (на самом деле `LONGTEXT`), логические значения `TINYINT(1)` в MySQL и текстовые даты и decimal в SQLite возвращаются одинаково во всех СУБД. См. `crates/verdin-db/src/value.rs`.

**Id вставленных строк.** `insert_returning_id` добавляет `RETURNING id` в PostgreSQL и читает id, который драйвер сообщает после вставки, в MySQL, MariaDB (`LAST_INSERT_ID`) и SQLite (`last_insert_rowid`).

**Нарушения уникальности.** `DbError::unique_violation()` извлекает из ошибки драйвера имя индекса (PostgreSQL, MySQL, MariaDB) или список колонок (SQLite), чтобы Document Service мог сообщить `ValidationError` для нужного атрибута.

## Построители SQL

Verdin строит SQL собственными небольшими построителями вместо ORM или `sea-query`, потому что таблицы существуют только во время выполнения (они берутся из схемы) и потому что преобладают детали отдельных диалектов: типизированные NULL, сопоставления, JSON-функции и текстовые форматы SQLite.

| Крейт | Строит |
|---|---|
| `verdin-migrate` (`sql.rs`, `Dialect`) | DDL: типы колонок, `CREATE TABLE`, `ALTER TABLE`, индексы, пересборку таблиц SQLite |
| `verdin-query` (`sql.rs`, `SqlBuilder`) | Условия `WHERE` для фильтров (включая подзапросы `EXISTS` по связям и JSON-пути) и `ORDER BY` |
| `verdin-content` (`service.rs`) | Чтение, вставку, обновление, удаление, запись в таблицы связей и пакетные запросы populate |

Построитель добавляет текст SQL и имена через `ident()` (с кавычками для нужного варианта) и собирает параметры через `param()`, поэтому построение SQL и привязка значений происходят в одном месте.

### Типы колонок по диалектам

| Тип модели | PostgreSQL | MySQL / MariaDB | SQLite |
|---|---|---|---|
| id | `bigint` identity | `bigint AUTO_INCREMENT` | `integer PRIMARY KEY AUTOINCREMENT` |
| integer, bigint, smallint | `integer`, `bigint`, `smallint` | `int`, `bigint`, `smallint` | `integer` |
| double | `double precision` | `double` | `real` |
| decimal | `numeric(p,s)` | `decimal(p,s)` | `text` |
| boolean | `boolean` | `tinyint(1)` | `integer` |
| char, varchar | `char(n)`, `varchar(n)` | `char(n)`, `varchar(n)` | `text` |
| text | `text` | `longtext` | `text` |
| date, time, datetime | `date`, `time(3)`, `timestamptz(3)` | `date`, `time(3)`, `datetime(3)` | `text` |
| json | `jsonb` | `json` | `text` |

SQLite хранит даты и время как текст фиксированного формата, поэтому текстовый порядок совпадает с хронологическим. Decimal он тоже хранит как текст, поэтому при сохранении ничего не округляется. Текстовый порядок для decimal не совпадает с числовым, поэтому фильтры и сортировки по decimal в SQLite приводят колонку к `REAL`. Такие сравнения точны примерно до 15 значащих цифр, а возвращаемые значения по-прежнему точны. Какой атрибут соответствует какому типу модели, описано в разделе [типы атрибутов](/ru/reference/attribute-types/).

Таблицы MySQL и MariaDB создаются с `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` и сопоставлением, не учитывающим регистр и диакритику: `utf8mb4_0900_ai_ci` в MySQL, `utf8mb4_uca1400_ai_ci` в MariaDB.

## Различия диалектов

| Тема | PostgreSQL | MySQL 8.4 | MariaDB | SQLite | Как это учитывает Verdin |
|---|---|---|---|---|---|
| Id вставленной строки | `RETURNING` | нет `RETURNING` | id от драйвера | id от драйвера | `insert_returning_id()` |
| Транзакционный DDL | да | нет (неявная фиксация) | нет | да | Журнал шагов в MySQL и MariaDB (см. [миграции](/ru/internals/migrations/)) |
| JSON | `jsonb` | `json` | псевдоним `LONGTEXT` | текст | Декодирование по схеме |
| Логические значения | `boolean` | `tinyint(1)` | `tinyint(1)` | integer | Декодирование по схеме |
| Дата и время | `timestamptz` | `datetime(3)` | `datetime(3)` | текст ISO | Всегда UTC; сессии семейства MySQL используют часовой пояс `+00:00` |
| Кодировка и сопоставление | UTF-8 | `utf8mb4`, `utf8mb4_0900_ai_ci` | `utf8mb4`, `utf8mb4_uca1400_ai_ci` | UTF-8, бинарное | Задаётся явно для каждой таблицы |
| Точное сравнение текста (`$eq`, `$in`…) | `=` | `COLLATE utf8mb4_bin` | так же | `=` | Одинаковые результаты во всех СУБД |
| `$contains`, `$startsWith`, `$endsWith` | `LIKE` | `LIKE … COLLATE utf8mb4_bin` | так же | `instr()` / `substr()` | `LIKE` в SQLite не учитывает регистр ASCII, поэтому для сравнений с учётом регистра он не используется |
| `$containsi` и другие операторы `…i` | `ILIKE` | `LIKE` (сопоставление без учёта регистра) | так же | `LIKE` | SQLite приводит к одному регистру только ASCII |
| Фильтры по JSON-путям | `#>>` | `JSON_VALUE` | так же | `json_extract` | Операнд для каждого диалекта |
| Фильтры по JSON-массивам | `jsonb_array_elements` | `JSON_TABLE` | так же | `json_each` | `EXISTS` по элементам |
| `ALTER COLUMN` | полностью | `MODIFY COLUMN` | так же | не поддерживается | SQLite: пересборка таблицы (создание, копирование, удаление, переименование) |
| Блокировки строк | `FOR UPDATE` | `FOR UPDATE` | `FOR UPDATE` | нет | В SQLite опускаются: его пишущие транзакции блокируют всю базу данных |
| Длина уникального текстового индекса | — | 3072 байта | так же | — | `varchar(255)` в `utf8mb4` — это 1020 байт; `text` не может быть уникальным |
| Размер строки | — | 65 535 байт | так же | — | Не больше 60 атрибутов `string`, `email`, `uid` или `enumeration` на тип |

Шаблоны `LIKE` экранируют во вводе пользователя `%`, `_` и сам символ экранирования (`!`). Сопоставления MySQL и MariaDB по умолчанию не учитывают регистр и диакритику, поэтому точные операторы добавляют бинарное сопоставление: `$eq` в MySQL означает то же, что и в PostgreSQL. С JSON-путями `JSON_VALUE` возвращает строку с бинарным сопоставлением, поэтому операторы без учёта регистра там сравнивают `LOWER()` с обеих сторон.

`ORDER BY` ставит NULL последними в обоих направлениях и всегда заканчивается на `id`, поэтому пагинация стабильна во всех СУБД.
