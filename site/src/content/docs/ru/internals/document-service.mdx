Document Service (`DocumentService` в `crates/verdin-content/src/service.rs`) — единственный код, который читает и записывает строки контента. Через него проходят content API, admin API, GraphQL, MCP, плагины, импорт и карта сайта, поэтому валидация, черновики и публикация, правила связей и события ведут себя одинаково, какой бы API ни сделал вызов. Как и Document Service в Strapi v5, он работает с документами (которые определяются по `documentId`), а не со строками.

## API

Основные методы (упрощённо; точные типы смотрите в исходном коде):

| Метод | Что делает |
|---|---|
| `find_many(uid, &Query) -> Page` | Страница документов с `meta` в постраничной форме или форме смещения |
| `find_one(uid, document_id, &Query) -> Option<Json>` | Один документ в статусе и локали запроса |
| `single_document_id(uid)` | Документ одиночного типа, если он существует |
| `create(uid, &data, WriteOptions) -> String` | Создаёт документ и возвращает его `documentId` |
| `update(uid, document_id, &data, WriteOptions)` | Частичное обновление черновика (или единственной версии); при необходимости создаёт версию новой локали |
| `delete(uid, document_id)` | Удаляет все версии документа в текущей локали |
| `publish(uid, document_id, actor)` | Копирует черновик в опубликованную версию |
| `unpublish(uid, document_id)` | Удаляет опубликованную версию |
| `discard_draft(uid, document_id)` | Заменяет черновик опубликованной версией |
| `uid_availability(…)` | Свободно ли значение `uid`, с предложением свободного |
| `document_locales`, `timeline`, `usage`… | Вспомогательные методы для админ-панели |

У `WriteOptions` два поля: `publish` (опубликовать после записи, для типов с черновиками и публикацией) и `actor` (администратор, записываемый в `created_by_id` / `updated_by_id`).

Сервис — это дешёвое для клонирования значение, настраиваемое методами-построителями: `in_locale(locale)` для локализованных типов, `with_listener`, `with_hook`, `dry_run()` (полностью проверить запись и откатить её — используется в пробных прогонах импорта) и `without_plugin_hooks()` (для записей, которые делают сами плагины).

Сервис не знает, кто его вызывает. Разрешения применяет слой API до вызова: он отклоняет действия, на которые у клиента нет прав, ограничивает, какие типы запрос может подгружать или использовать для фильтрации, и добавляет к запросу фильтры условий (например, условие «свои записи» роли администратора **Author** превращается в `created_by_id = <admin id>`). Фильтры — часть SQL, поэтому пагинация и подсчёт остаются точными.

## Что происходит при каждой записи

1. **Хуки.** Первыми по порядку выполняются `DocumentHook`: этапы процесса проверки, затем плагины. Хук может заменить данные или отклонить запись, что превращается в `400`. Они используют имена событий жизненного цикла Strapi (`beforeCreate`, `beforeUpdate`, `beforeDelete`, `beforePublish`, `beforeUnpublish`, `beforeDiscardDraft`).
2. **Валидация входных данных** (`input.rs`): неизвестные ключи, системные поля (`id`, `documentId`, временные метки) и обратные стороны связей (`mappedBy`) — ошибки; каждое значение проверяется по типу атрибута и ограничениям (`min`, `max`, `minLength`, `maxLength`, `regex`, значения перечислений, кратность связей, `allowedTypes` медиа); компоненты и динамические зоны проверяются рекурсивно; значения `password` хешируются argon2.
3. **Ссылки.** Связанные документы и медиафайлы должны существовать; это проверяется внутри транзакции.
4. **Строки и ссылки** в одной транзакции: строка вставляется или обновляется, затем переписываются её таблицы связей, полиморфных связей и медиа (позиции перенумеровываются 1..n). Связывание цели `oneToOne` или `oneToMany` забирает её у других документов в том же состоянии.
5. **Обязательные поля и правила.** Когда версия становится опубликованной или при каждой записи в типы без черновиков и публикации проверяются атрибуты `required` (включая атрибуты внутри компонентов и динамических зон) и правила валидации между полями. Сбой откатывает всю запись.
6. **Уникальность** обеспечивается уникальными индексами с областью действия. Нарушение сопоставляется с атрибутом и сообщается как `ValidationError`, без гонок.
7. **Фиксация, затем события.** После фиксации транзакции сервис вызывает каждый `DocumentListener` с `DocumentEvent` (`entry.create`, `entry.update`, `entry.publish`, `entry.unpublish`, `entry.discard-draft`, `entry.delete`), содержащим uid, `documentId`, локаль и исполнителя.

Ошибки валидации используют формат Strapi: список `{ path, message, name: "ValidationError" }`, где `path` указывает в данные (`["seo", "metaTitle"]`, `["blocks", 2, "text"]`). Админ-панель сопоставляет их со своими полями.

Слушатели поддерживают производное состояние в согласии с контентом без кода в каждом обработчике: вебхуки, история содержимого, кеш ответов, хуки плагинов «после записи», журнал аудита, события реального времени, комментарии и задачи, отметки «просмотрено», очистка CDN и поисковый индекс. Упавший слушатель записывает свою ошибку в лог; запись к этому моменту уже успешна. Поскольку слушатели выполняются после фиксации, пробный прогон до них никогда не доходит.

## Чтение

Чтение выбирает строки запрошенного статуса и локали, применяет фильтры и сортировку в SQL, а затем подгружает то, что было запрошено:

- **Связи** загружаются пакетными запросами, по одному на связь и уровень (`WHERE … IN (…)`, порциями по 500 id), и никогда — каскадными JOIN. Это позволяет избежать и декартова взрыва, и запросов N+1. На запись и связь подгружается не больше 1000 связанных записей; подсчёт остаётся точным.
- Цели читаются в той же версии, что и источник: опубликованные документы видят опубликованные цели, черновики — черновики.
- **Компоненты и динамические зоны** берутся из своей JSON-колонки; связи и медиа внутри них разрешаются теми же пакетными запросами.
- **Поиск `_q`** использует индекс Tantivy, когда включён `[search]`, а иначе — `$containsi` без учёта регистра по текстовым полям.

Как выглядит вывод (плоские документы, форматы значений, синтаксис `populate`, ограничения), описано в [REST API](/ru/api/rest/).

  L->>H: IP клиента, id запроса, CORS, лимиты, кеш
  H->>H: маршрут по pluralName, авторизация токена или публичной роли
  H->>Q: разбор и проверка по схеме
  Q-->>H: типизированный Query
  H->>D: find_many(uid, query)
  D->>DB: SELECT … WHERE … ORDER BY … LIMIT
  D->>DB: по одному пакетному запросу на подгружаемую связь
  D-->>H: документы и meta страницы
  H-->>C: { data, meta }`}
/>

1. **Общие слои** (начиная с внешнего): определяется адрес клиента (`X-Forwarded-For` используется только от `[server].trusted_proxies`), метрики считают запрос, если включены, задаётся id запроса, который передаётся как `x-request-id`, трассировка открывает span, а CORS применяется к content API и GraphQL, если задан `[api].cors_origins`.
2. **Слои content API**: ограничения частоты для каждого клиента, `ETag` и необязательный кеш анонимных чтений, ограничение размера тела (`[server].body_limit`) и тайм-аут запроса, теги кеша CDN в ответах.
3. **Маршрутизация.** Сегмент пути ищется среди `pluralName` типов содержимого (типы-коллекции) и `singularName` (одиночные типы). Неизвестные имена дают `404`.
4. **Авторизация** (`verdin-auth`). Отсутствие заголовка `Authorization` означает публичную роль; `Bearer vd_…` — это API-токен. Недействительный или просроченный токен даёт `401`, а не публичную роль. Действие маршрута (`find`, `findOne`, `create`, `update`, `delete`, `publish`) должно быть разрешено для типа, иначе ответ — `403`.
5. **Разбор запроса** (`verdin-query`). Сырая строка запроса разбирается в скобочное дерево (не больше 16 КБ, 12 уровней, 1000 пар), затем в типизированный `Query`, проверенный по полям типа: неизвестные и `private` поля дают `400`, а populate, фильтры и сортировка по связям ограничены типами, которые клиент может читать. Для чтения `?status=draft` нужно ещё `readDrafts`.
6. **Document Service.** Обработчик вызывает `find_many`, `find_one`, `create`, `update`, `delete` или действие. Запись без `?status=draft` публикует документ для типов с черновиками и публикацией (поведение Strapi v5) и перечитывает записанную версию для ответа.
7. **Ответ.** `{ "data": …, "meta": … }`. Ошибки используют ту же обёртку с `data: null` и объектом `error`.

Маршруты admin API проходят тот же путь, но с сессией администратора вместо API-токена, RBAC администраторов вместо прав content API и черновиками по умолчанию: они читают черновики и записывают только черновики, а публикация — явное действие. GraphQL переводит свои аргументы в то же дерево параметров перед шагом 5, поэтому использует тот же парсер, ограничения и правила разрешений.
