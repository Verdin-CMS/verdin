Эта страница для тех, кто вносит вклад в админ-панель в `admin/`: как организовано приложение Angular, как оно превращает схему контента в формы и списки и как оказывается внутри бинарника `verdin`. Как пользоваться панелью, описано в руководствах; как работает серверная часть admin API — в [справочнике по admin API](/ru/api/admin/).

Панель — это одностраничное приложение на Angular 22: standalone-компоненты, обнаружение изменений без zone.js (zoneless), сигналы, маршруты с ленивой загрузкой и компоненты spartan/ui на Tailwind CSS v4.

## Структура

```text
admin/
├── src/app/
│   ├── app.config.ts     # providers: router, HttpClient interceptors, Transloco, icons
│   ├── app.routes.ts     # lazy routes, guards (auth, permissions, unsaved changes)
│   ├── core/             # services and pure models: api, auth, schema, i18n, permissions…
│   ├── layout/           # the shell (sidebar, header), home, deploy button
│   ├── features/
│   │   ├── auth/         # login, first admin, invitations, password reset
│   │   ├── dashboard/    # home widgets
│   │   ├── content/      # lists, the entry editor, history, releases, review, import
│   │   │   ├── fields/   # schema-driven form controls and the form model
│   │   │   └── collab/   # comments and tasks
│   │   ├── builder/      # content-type builder (verdin dev only)
│   │   ├── media/        # media library
│   │   ├── releases/
│   │   ├── profile/      # own account, two-factor, passkeys, sessions
│   │   └── settings/     # users, roles, tokens, webhooks, locales, plugins, site features…
│   └── shared/
│       ├── ui/           # spartan helm components, owned by the project
│       └── components/   # app-level shared components (confirm dialog, page header…)
├── public/i18n/          # translation catalogs, one JSON file per language
├── scripts/check-i18n.mjs
└── e2e/                  # Playwright tests and the server they run against
```

**Состояние** хранится в сигналах внутри injectable-сервисов в `core/` (`Auth`, `Schema`, `I18n`, `Theme`…). Библиотеки хранилища состояния нет.

**Доступ к API** идёт через `core/api.ts` — небольшую обёртку на промисах над `HttpClient` из Angular, с типами, написанными вручную в `core/types.ts`. Конфигурация времени выполнения (путь админки, префикс API, режим, брендинг) берётся из тега `<meta name="verdin-config">`, который внедряет сервер.

**Сессия.** Токен доступа хранится только в памяти; refresh-токен — это cookie `HttpOnly`, ограниченная маршрутами аутентификации. HTTP-интерсептор добавляет bearer-токен и при `401` один раз обновляет его и повторяет запрос; если обновление не удалось, он отправляет пользователя на страницу входа. Запросы обновления и выхода несут заголовок `X-Verdin-CSRF`, которого требует сервер. Guards восстанавливают сессию из cookie при загрузке страницы. Ответ `403`, сообщающий, что роль требует двухфакторной аутентификации, отправляет пользователя её настраивать.

## Формы на основе схемы

В редакторе записи (`features/content/edit.ts`) нет кода для отдельных типов. Он читает типы содержимого и компоненты из `GET /admin/api/content-types` и `GET /admin/api/components`, а раскладку редактора — из настроек представления редактирования и строит форму во время выполнения с помощью **Signal Forms** (`@angular/forms/signals`):

- Модель документа — это сигнал обычного объекта (`FormModel` в `fields/model.ts`); дерево полей и его валидаторы выводятся из схемы.
- Рекурсивный компонент `vd-fields` (`fields/fields.ts`) выводит любую карту атрибутов по дереву полей. Текст, даты и время используют нативные поля ввода, привязанные через `[formField]`. Собственные `FormValueControl` обрабатывают числа (допускающие null; большие целые остаются строками), переключатели, перечисления, дату-время (локальное время в поле ввода, UTC в модели), JSON, Markdown, `blocks` (TipTap), медиа, связи (выбор с поиском по мере ввода и упорядочиванием) и полиморфные связи.
- Компоненты — это вложенные fieldset; повторяемые компоненты и динамические зоны — списки с изменяемым порядком. Плагины могут регистрировать собственные типы полей, которые выводятся как пользовательские элементы.
- `toModel` превращает подгруженный документ в модель формы (связи становятся значениями `documentId`, файлы — id), а `toPayload` превращает её обратно в полезную нагрузку `data`: пустые строки становятся `null`, ключи рендеринга (`__key`) и стороны только для чтения (`mappedBy`, `morphOne`, `morphMany`) отбрасываются. Обе функции покрыты модульными тестами в `fields/model.spec.ts`.
- Валидация, выведенная из схемы, даёт мгновенную обратную связь. Условные поля (`conditions.visible`) вычисляются в браузере портом серверного вычислителя JSON Logic (`core/logic.ts`). Правила валидации между полями проверяет только сервер. Последнее слово остаётся за сервером: его записи `details.errors[].path` сопоставляются с соответствующими полями.
- Сохранение явное, с отслеживанием изменений и предупреждением при уходе со страницы (route guard плюс `beforeunload`). Кнопки **Опубликовать**, **Снять с публикации** и **Discard** появляются в зависимости от состояния документа. Админка сохраняет только черновики; публикация — всегда отдельное действие.

Раскладка редактора (порядок полей, ширина, подписи, описания, поля только для чтения, поле, по которому называются связанные записи) общая для всех администраторов и хранится на сервере в `vd_settings`; она меняется на странице **Настроить представление** с разрешением `views.manage`.

## Списки

Списки контента (`features/content/list.ts`) используют таблицу spartan helm с серверной пагинацией, сортировкой и фильтрами. Фильтры, поиск (`_q`) и страница отражаются в URL, поэтому отфильтрованный список — это ссылка, которой можно поделиться. Каждый администратор выбирает видимые столбцы, сортировку по умолчанию и размер страницы для каждого типа (`list-view.ts`); эти настройки сохраняются в его собственных предпочтениях на сервере и следуют за ним между браузерами. Списки также обновляются в реальном времени из потока событий админки.

## Конструктор типов содержимого

**Конструктор типов содержимого** виден, только когда сервер работает в режиме разработки (`verdin dev`) и у администратора есть `schema.manage`. Он редактирует типы содержимого и компоненты в их файловом формате: поля, виды и цели связей (создавая обратный атрибут в целевом типе), компоненты, динамические зоны, длины, диапазоны и флаги `required`, `unique` и `private`.

Каждое изменение сначала отправляется в `POST /admin/api/schema/plan`, который проверяет будущую схему и возвращает шаги миграции с их риском, SQL и предложениями переименований, которые пользователь может принять. Подтверждение вызывает `POST /admin/api/schema/apply` с принятым уровнем риска и переименованиями. Сервер выполняет миграцию, записывает `schema/*.json` и подменяет работающее приложение новой схемой без перезапуска. Что при этом происходит на сервере, см. в разделе [движок миграций](/ru/internals/migrations/).

## Сборка и поставка

- `ng build` записывает продакшен-сборку в `admin/dist/admin/browser` с `<base href="/admin/">`.
- Сервер встраивает эту папку с помощью `rust-embed`, если он собран с feature `embed-admin`, которую используют релизные сборки и образ Docker. Без этой feature или при заданном `[admin].assets_dir` он отдаёт файлы с диска. `assets_dir` имеет приоритет над встроенной сборкой.
- Сервер переписывает `<base href>` на `[admin].path` и внедряет конфигурацию времени выполнения тегом `<meta>`, а не встроенным скриптом. Изменение `admin.path` никогда не требует пересборки панели.
- Неизвестные пути без расширения файла отдают `index.html` для маршрутизации на клиенте. Бандлы с отпечатком в имени (`main-ABC123.js`) кешируются как `immutable` на год; всё остальное — `no-cache`.
- Каждый ответ админки содержит строгую Content Security Policy (`script-src 'self'`, `frame-ancestors 'none'`, `base-uri 'self'`…), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` и `Referrer-Policy: strict-origin-when-cross-origin`. Встраивание критического CSS в Angular отключено в `angular.json`, потому что оно полагается на встроенные обработчики событий, которые запрещает политика.

Для работы над фронтендом запустите сервер, затем `npm start` в `admin/`: `ng serve` проксирует `/admin/api` и `/api` на `http://localhost:1337` (`admin/proxy.conf.json`).

## Переводы

Панель переводится во время выполнения с помощью Transloco, а не i18n Angular на этапе компиляции, поэтому одна сборка обслуживает все языки, а пользователи могут переключать язык без перезагрузки.

- Каталоги — это плоские JSON-файлы в `admin/public/i18n/` (`en.json` — исходный), загружаемые по требованию.
- Сообщения используют ICU MessageFormat (`{name}`, `{count, plural, one {# entry} other {# entries}}`), который интерпретирует FormatJS (`intl-messageformat`) через собственный транспайлер Transloco. FormatJS интерпретирует сообщения, а не компилирует их в функции, поэтому CSP не нужен `unsafe-eval`.
- Ключи сообщений типизируются по `en.json` (`core/i18n/keys.ts`): использование несуществующего ключа — ошибка компиляции.
- `npm run i18n:check` проверяет каждый каталог по `en.json`: те же ключи, корректный синтаксис ICU, те же аргументы и все категории множественного числа языка. CI запускает эту проверку.
- Сервис `I18n` также обеспечивает форматирование с учётом локали и первый день недели, взятые из региональных настроек браузера, с возможностью переопределения для каждого пользователя.

Как добавить или обновить язык, описано в разделе [перевод](/ru/project/translating/).
