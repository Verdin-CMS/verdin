Document Service(`crates/verdin-content/src/service.rs`의 `DocumentService`)는 콘텐츠 행을 읽고 쓰는 유일한 코드입니다. 콘텐츠 API, admin API, GraphQL, MCP, 플러그인, 가져오기, 사이트맵이 모두 이를 거치므로, 어떤 API가 호출하든 검증, 초안과 게시, 관계 규칙, 이벤트가 똑같이 동작합니다. Strapi v5의 Document Service처럼 행이 아니라 문서(`documentId`로 식별)를 다룹니다.

## API

주요 메서드(단순화함. 정확한 타입은 소스 참고):

| 메서드 | 하는 일 |
|---|---|
| `find_many(uid, &Query) -> Page` | 페이지 또는 오프셋 형식의 `meta`를 가진 문서 한 페이지 |
| `find_one(uid, document_id, &Query) -> Option<Json>` | 쿼리의 상태와 로케일로 문서 하나 |
| `single_document_id(uid)` | 싱글 타입의 문서(있다면) |
| `create(uid, &data, WriteOptions) -> String` | 문서를 만들고 `documentId`를 반환 |
| `update(uid, document_id, &data, WriteOptions)` | 초안(또는 유일한 버전)의 부분 업데이트. 필요하면 새 로케일 버전을 만듦 |
| `delete(uid, document_id)` | 현재 로케일에서 문서의 모든 버전 삭제 |
| `publish(uid, document_id, actor)` | 초안을 게시 버전으로 복사 |
| `unpublish(uid, document_id)` | 게시 버전 삭제 |
| `discard_draft(uid, document_id)` | 초안을 게시 버전으로 대체 |
| `uid_availability(…)` | `uid` 값이 비어 있는지와 비어 있는 제안값 |
| `document_locales`, `timeline`, `usage`… | 관리자 패널용 헬퍼 |

`WriteOptions`에는 필드가 두 개 있습니다: `publish`(초안과 게시를 쓰는 타입에서 쓴 뒤 게시)와 `actor`(`created_by_id` / `updated_by_id`에 기록되는 관리자).

서비스는 복제 비용이 싼 값이며 빌더 메서드로 설정합니다: 로컬라이즈된 타입용 `in_locale(locale)`, `with_listener`, `with_hook`, `dry_run()`(쓰기를 완전히 검증하고 롤백, 가져오기 시험 실행에서 사용), `without_plugin_hooks()`(플러그인이 직접 하는 쓰기용).

서비스는 누가 호출하는지 모릅니다. 권한은 호출 전에 API 계층이 적용합니다. 호출자에게 없는 작업을 거부하고, 쿼리가 populate하거나 필터링할 수 있는 타입을 제한하고, 쿼리에 조건 필터를 더합니다(예: 관리자 **Author** 역할의 "자신의 항목" 조건은 `created_by_id = <admin id>`가 됨). 필터는 SQL의 일부이므로 페이지네이션과 개수가 정확합니다.

## 모든 쓰기가 하는 일

1. **훅.** `DocumentHook`이 먼저 순서대로 실행됩니다: 검토 워크플로 단계, 그다음 플러그인. 훅은 데이터를 대체하거나 쓰기를 거부할 수 있으며, 거부는 `400`이 됩니다. Strapi의 라이프사이클 이름(`beforeCreate`, `beforeUpdate`, `beforeDelete`, `beforePublish`, `beforeUnpublish`, `beforeDiscardDraft`)을 씁니다.
2. **입력 검증**(`input.rs`): 알 수 없는 키, 시스템 필드(`id`, `documentId`, 타임스탬프), 역방향(`mappedBy`) 관계 쪽은 오류입니다. 모든 값은 속성 타입과 제약 조건(`min`, `max`, `minLength`, `maxLength`, `regex`, enumeration 값, 관계 cardinality, 미디어 `allowedTypes`)으로 검사하며, 컴포넌트와 다이나믹 존은 재귀적으로 검증하고, `password` 값은 argon2로 해싱합니다.
3. **참조.** 관련 문서와 미디어 파일이 존재해야 하며, 트랜잭션 안에서 확인합니다.
4. **행과 링크**를 트랜잭션 하나로 처리합니다. 행을 삽입하거나 수정한 뒤, 관계, 다형성, 미디어 링크 테이블을 다시 씁니다(위치는 1..n으로 다시 매김). `oneToOne`이나 `oneToMany` 대상을 연결하면 같은 상태의 다른 문서에서 옮겨집니다.
5. **필수 필드와 규칙.** 버전이 게시될 때, 또는 초안과 게시를 쓰지 않는 타입에서는 쓸 때마다 `required` 속성(컴포넌트와 다이나믹 존 안의 것 포함)과 필드 간 검증 규칙을 검사합니다. 실패하면 쓰기 전체를 롤백합니다.
6. **고유성**은 범위가 지정된 고유 인덱스로 강제합니다. 위반은 해당 속성으로 다시 매핑되어 경쟁 조건 없이 `ValidationError`로 보고됩니다.
7. **커밋 후 이벤트.** 트랜잭션이 커밋되면 서비스는 모든 `DocumentListener`를 uid, `documentId`, 로케일, actor를 담은 `DocumentEvent`(`entry.create`, `entry.update`, `entry.publish`, `entry.unpublish`, `entry.discard-draft`, `entry.delete`)로 호출합니다.

검증 오류는 Strapi의 형식을 씁니다. `{ path, message, name: "ValidationError" }`의 리스트이며, `path`는 데이터 안을 가리킵니다(`["seo", "metaTitle"]`, `["blocks", 2, "text"]`). 관리자 패널은 이를 필드에 다시 매핑합니다.

리스너는 핸들러별 코드 없이 파생 상태를 콘텐츠와 맞춥니다: 웹훅, 콘텐츠 기록, 응답 캐시, 플러그인의 쓰기 후 훅, 감사 로그, 실시간 이벤트, 댓글과 작업, "확인" 표시, CDN 퍼지, 검색 인덱스. 실패한 리스너는 자기 오류를 로그에 남기며, 쓰기는 이미 성공한 상태입니다. 리스너는 커밋 후에 실행되므로 시험 실행은 절대 리스너에 도달하지 않습니다.

## 읽기

읽기는 요청한 상태와 로케일의 행을 선택하고, SQL에서 필터와 정렬을 적용한 뒤, 요청한 것을 populate합니다.

- **관계**는 연쇄 조인이 아니라 관계와 단계마다 하나씩인 배치 쿼리(`WHERE … IN (…)`, id 500개 단위)로 로드합니다. 카테시안 폭발과 N+1 쿼리를 모두 피합니다. 항목과 관계당 관련 항목은 최대 1,000개까지 populate하며, 개수는 정확합니다.
- 대상은 원본과 같은 버전으로 읽습니다. 게시된 문서는 게시된 대상을, 초안은 초안을 봅니다.
- **컴포넌트와 다이나믹 존**은 JSON 컬럼에서 오며, 그 안의 관계와 미디어는 같은 배치 쿼리로 해석합니다.
- **`_q` 검색**은 `[search]`가 켜져 있으면 Tantivy 인덱스를, 아니면 텍스트 필드에 대한 대소문자 무시 `$containsi`를 씁니다.

출력 형태(평평한 문서, 값 형식, `populate` 문법, 한도)는 [REST API](/ko/api/rest/)에 문서화되어 있습니다.

## 콘텐츠 API 요청의 수명 주기

<Diagram
  caption="소켓에서 데이터베이스까지 GET /api/articles 요청"
  code={`sequenceDiagram
  participant C as 클라이언트
  participant L as 공유 계층
  participant H as handlers.rs
  participant Q as verdin-query
  participant D as Document Service
  participant DB as 데이터베이스
  C->>L: GET /api/articles?filters…
  L->>H: 클라이언트 IP, 요청 id, CORS, 한도, 캐시
  H->>H: pluralName으로 라우팅, 토큰 또는 공개 역할 인가
  H->>Q: 스키마와 대조해 파싱·검증
  Q-->>H: 타입 있는 Query
  H->>D: find_many(uid, query)
  D->>DB: SELECT … WHERE … ORDER BY … LIMIT
  D->>DB: populate한 관계마다 배치 쿼리 하나
  D-->>H: 문서와 페이지 meta
  H-->>C: { data, meta }`}
/>

1. **공유 계층**(바깥쪽부터): 클라이언트 주소를 해석하고(`[server].trusted_proxies`에서 온 경우에만 `X-Forwarded-For` 사용), 메트릭이 켜져 있으면 요청을 세고, 요청 id를 설정해 `x-request-id`로 전파하고, tracing이 span을 열고, `[api].cors_origins`가 설정되어 있으면 콘텐츠 API와 GraphQL에 CORS를 적용합니다.
2. **콘텐츠 API 계층**: 클라이언트별 요청 한도, `ETag`와 선택 사항인 익명 읽기 캐시, 본문 크기 한도(`[server].body_limit`)와 요청 타임아웃, 응답의 CDN 캐시 태그.
3. **라우팅.** 경로 세그먼트를 콘텐츠 타입의 `pluralName`(컬렉션 타입)과 `singularName`(싱글 타입)에서 찾습니다. 알 수 없는 이름은 `404`입니다.
4. **인가**(`verdin-auth`). `Authorization` 헤더가 없으면 공개 역할이고, `Bearer vd_…`는 API 토큰입니다. 잘못되었거나 만료된 토큰은 `401`이며 절대 공개 역할이 되지 않습니다. 라우트의 작업(`find`, `findOne`, `create`, `update`, `delete`, `publish`)이 그 타입에 허용되어 있어야 하며, 아니면 `403`으로 응답합니다.
5. **쿼리 파싱**(`verdin-query`). 원본 쿼리 문자열을 대괄호 트리(최대 16 KB, 12단계, 1,000쌍)로 파싱한 뒤, 타입의 필드와 대조해 검증한 타입 있는 `Query`로 만듭니다. 알 수 없는 필드와 `private` 필드는 `400`이며, populate, 관계 필터, 관계 정렬은 호출자가 읽을 수 있는 타입으로 제한됩니다. `?status=draft`를 읽으려면 `readDrafts`도 필요합니다.
6. **Document Service.** 핸들러가 `find_many`, `find_one`, `create`, `update`, `delete` 또는 액션을 호출합니다. `?status=draft` 없는 쓰기는 초안과 게시를 쓰는 타입에서 게시하며(Strapi v5 동작), 응답을 위해 쓴 버전을 다시 읽습니다.
7. **응답.** `{ "data": …, "meta": … }`. 오류는 `data: null`과 `error` 객체를 가진 같은 봉투를 씁니다.

admin API 라우트는 API 토큰 대신 관리자 세션, 콘텐츠 API 권한 대신 관리자 RBAC, 그리고 초안 우선 기본값으로 같은 경로를 따릅니다. 초안을 읽고 초안만 쓰며, 게시는 명시적인 작업입니다. GraphQL은 5단계 전에 인자를 같은 파라미터 트리로 변환하므로 파서, 한도, 권한 규칙을 공유합니다.
