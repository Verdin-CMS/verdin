API 토큰을 쓰면 사이트, 앱, 스크립트가 공개 접근보다 넓은 권한으로 콘텐츠 API를 호출할 수 있습니다. 이
가이드에서는 토큰을 만들고, 접근 범위를 고르고, 사용하고, 유출되었을 때 교체합니다. 토큰은 Strapi의 API 토큰처럼
동작합니다.

콘텐츠 API는 기본적으로 닫혀 있습니다. 토큰이 없는 요청은 **설정 → 공개 접근**이 허용하는 것만 받으며, 허용하기
전까지는 아무것도 없습니다.

## 시작하기 전에

- 토큰을 관리하려면 **API 토큰 관리**(`tokens.manage`)가 필요합니다. [권한](/ko/reference/permissions/)을
  참고하세요.
- `VERDIN_TOKEN_PEPPER`가 설정되어 있어야 합니다. [pepper가 중요한 곳](#pepper가-중요한-곳)을 참고하세요.

## 토큰 만들기

<Steps>

1. **설정 → API 토큰**을 열고 **토큰 만들기**를 선택합니다.
2. **이름**과, 선택적으로 **설명**을 입력합니다.
3. **타입**을 고릅니다.

   | 타입 | 허용하는 것 |
   | --- | --- |
   | **읽기 전용** | 모든 콘텐츠 타입에 대한 목록 조회와 단건 조회. 게시된 버전만. |
   | **전체 접근** | 모든 콘텐츠 타입과 미디어 라이브러리에 대한 모든 작업. |
   | **사용자 지정** | **권한**에서 체크한 작업만. |

4. **만료** 시점을 고릅니다: **없음**, 또는 7일, 30일, 90일 후.
5. 사용자 지정 토큰이면 **권한** 아래에서 콘텐츠 타입마다 작업을 체크합니다: **목록 조회**, **단건 조회**,
   **생성**, **수정**, **삭제**, **게시**, **초안 읽기**. **미디어 라이브러리** 행은 업로드를, **사용자** 행은
   [최종 사용자](/ko/guides/auth/end-users/)의 `/api/users` 라우트를 다룹니다.
6. **생성**을 선택한 뒤 토큰을 복사합니다. 토큰이 표시되는 것은 이때뿐입니다.

</Steps>

토큰은 `vd_`로 시작합니다. 목록에는 각 토큰의 앞 글자, 마지막 사용 시각, 만료 시각이 나옵니다.

## 토큰 사용

bearer 토큰으로 보냅니다.

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
curl -H "Authorization: Bearer $VERDIN_TOKEN" 'http://localhost:1337/api/articles?status=draft'
```

</TabItem>
<TabItem label="GraphQL">

```sh title="Terminal"
curl -X POST http://localhost:1337/graphql \
  -H "Authorization: Bearer $VERDIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"query":"{ articles { documentId title } }"}'
```

</TabItem>
<TabItem label="TypeScript">

```ts
import { createClient } from '@verdin/client';
import type { VerdinSchema } from './verdin-types';

const verdin = createClient<VerdinSchema>({
  url: 'http://localhost:1337',
  token: process.env.VERDIN_TOKEN,
});
```

</TabItem>
</Tabs>

- 토큰의 접근 권한은 공개 접근을 대체하며, 더해지지 않습니다. 어떤 타입에 **목록 조회**가 없는 사용자 지정
  토큰은 공개 접근이 허용하더라도 그 타입을 나열할 수 없습니다.
- 초안 읽기(`?status=draft`)에는 **초안 읽기**가 필요합니다. 읽기 전용 토큰은 절대 초안을 보지 못합니다.
- 알 수 없거나 만료된 토큰은 `401`을 받습니다. 토큰의 접근 범위를 벗어난 작업은 `403`을 받습니다.
- `[api].token_rate_limit`은 토큰별 분당 요청 수를 제한합니다(기본적으로 꺼짐).
- 같은 토큰으로 GraphQL과 [MCP 서버](/ko/guides/integrations/mcp/)도 인가됩니다.

<Aside type="caution">
브라우저에 있는 토큰은 모든 방문자에게 보입니다. 토큰은 서버, 빌드 단계, 비공개 앱에서만 쓰세요. 공개
페이지에는 **설정 → 공개 접근**에서 필요한 것을 허용하세요.
</Aside>

## 토큰 재생성 또는 삭제

- 토큰 행의 **재생성**은 같은 이름, 타입, 권한으로 새 키를 만듭니다. 현재 키는 즉시 동작을 멈추므로, 그 키를
  쓰는 앱은 업데이트할 때까지 오류를 받습니다.
- **삭제**는 토큰을 지웁니다. 그 토큰을 쓰는 클라이언트는 접근을 잃습니다.

토큰이 유출되었을 가능성이 있으면 바로 둘 중 하나를 하세요.

## pepper가 중요한 곳

Verdin은 토큰을 저장하지 않습니다. `VERDIN_TOKEN_PEPPER`를 키로 한 각 토큰의 키 해시(HMAC-SHA256)를 저장하므로,
데이터베이스 사본만으로는 누구도 토큰을 쓸 수 없습니다. 같은 pepper가 다음을 보호합니다.

- API 토큰.
- 관리자의 인증 앱 시크릿과 복구 코드([2단계 인증](/ko/guides/auth/two-factor/)).
- 폼 제출과 함께 저장되는 해시된 IP 주소.

pepper는 `verdin secrets`로 한 번 생성하고, `verdin.toml`과 데이터베이스 백업에 넣지 말고, 모든 인스턴스에 같은
값을 주세요.

<Aside type="caution" title="pepper 바꾸기">
pepper가 바뀌면 모든 API 토큰이 동작하지 않고, 모든 관리자의 인증 앱과 복구 코드도 동작하지 않습니다. 유출된
경우에만 바꾸고, 그 뒤 새 토큰을 만들고 모든 관리자의 2단계 인증을 재설정하세요. 패스키와 비밀번호는 영향을 받지
않습니다.
</Aside>

## Admin API

모든 라우트는 `/admin/api` 아래에 있으며 `tokens.manage`가 필요합니다.

```http
GET    /admin/api/api-tokens?page=1&pageSize=25
POST   /admin/api/api-tokens                  { "name": "Website", "kind": "custom", "expiresInDays": 90,
                                                "permissions": [{ "subject": "api::article", "action": "find" }] }
GET    /admin/api/api-tokens/{id}
PUT    /admin/api/api-tokens/{id}             { "name": "…", "description": null, "kind": "read-only", "permissions": [...] }
POST   /admin/api/api-tokens/{id}/regenerate
DELETE /admin/api/api-tokens/{id}
```

- `kind`는 `read-only`, `full-access`, `custom` 중 하나입니다. `expiresInDays`는 선택 사항이며(없으면 만료되지
  않음) 나중에 바꿀 수 없습니다.
- `permissions`는 `{ subject, action }` 쌍을 나열합니다. `subject`는 콘텐츠 타입 uid, `plugin::upload`(미디어
  라이브러리), `plugin::users-permissions.user` 중 하나이고, `action`은 `find`, `findOne`, `create`, `update`,
  `delete`, `publish`, `readDrafts` 중 하나입니다. `publish`와 `readDrafts`는 뒤의 두 subject에는 적용되지 않습니다.
- `POST /api-tokens`와 `/regenerate`는 키를 `accessKey`로 한 번만 반환합니다.

공개 접근도 같은 쌍을 씁니다: `PUT /admin/api/public-permissions` `{ "permissions": [...] }`이며,
**역할 관리**(`roles.manage`)가 필요합니다.
