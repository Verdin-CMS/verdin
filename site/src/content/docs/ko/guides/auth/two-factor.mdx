2단계 인증은 비밀번호 뒤에 두 번째 단계를 더합니다. 인증 앱의 6자리 코드, 또는 패스키(지문, 얼굴, 화면 잠금,
보안 키)입니다. 이 가이드에서는 둘 다 설정하고, 역할에 필수로 지정하고, 관리자가 인증 수단을 잃어버렸을 때 할
일을 다룹니다. Strapi에는 이에 해당하는 기본 기능이 없습니다.

2단계 인증은 관리자용입니다. [최종 사용자](/ko/guides/auth/end-users/)는 비밀번호나 OAuth 제공업체로 로그인합니다.

## 시작하기 전에

- 켜야 할 기능이 없습니다. 모든 관리자가 자기 프로필에서 두 번째 인증 수단을 설정할 수 있습니다.
- 패스키는 관리자 패널의 주소에 묶입니다. `[server].public_url`을 관리자가 여는 주소(예:
  `https://cms.example.com`)로 설정하세요. 브라우저는 `https://`(와 `localhost`)에서만 패스키를 제공합니다.
- `VERDIN_TOKEN_PEPPER`를 바꾸지 마세요. 인증 앱 시크릿과 복구 코드가 이 값으로 보호되며, 바꾸면 쓸 수 없게
  됩니다.

## 인증 앱 설정

<Steps>

1. **프로필**을 열고 **2단계 인증**을 찾습니다.
2. **인증 앱** 아래에서 **설정**을 선택하고 비밀번호를 확인합니다.
3. 1Password, Google Authenticator, Authy 같은 앱으로 QR 코드를 스캔합니다. 스캔할 수 없으면 아래에 표시된 설정
   키를 입력하세요.
4. 앱에 표시된 **6자리 코드**를 입력하고 **켜기**를 선택합니다.
5. Verdin이 보여 주는 **복구 코드**를 저장합니다. **다운로드**하거나 복사한 뒤 **저장했습니다**를 선택하세요.

</Steps>

코드는 표준 TOTP 방식(30초 간격, SHA-1, 6자리)을 따릅니다. 시계 오차를 감안해 바로 앞이나 뒤 간격의 코드도
받아들입니다. 코드가 거부되면 기기의 시간을 확인하세요.

## 패스키 추가

<Steps>

1. **패스키** 아래에서 **패스키 추가**를 선택합니다.
2. "MacBook Touch ID" 같은 **이름**을 주고 비밀번호를 확인합니다.
3. 브라우저의 안내를 따릅니다.

</Steps>

패스키는 최대 20개까지 등록할 수 있고 **제거**로 지울 수 있습니다. 패스키는 비밀번호 뒤의 두 번째 인증 수단이며,
비밀번호를 대체하지 않습니다.

## 복구 코드

첫 인증 수단을 설정하면 복구 코드 10개를 받습니다. 앱이나 패스키를 잃어버렸을 때 각 코드로 한 번 로그인할 수
있습니다. 프로필에 남은 개수가 표시되며, **새 코드 생성**은 전부 교체합니다(이전 코드는 동작하지 않음).

<Aside type="caution">
코드는 한 번만 표시됩니다. 인증 앱이 있는 기기 옆이 아니라 비밀번호 관리자나 오프라인 장소에 보관하세요.
</Aside>

## 두 번째 인증 수단으로 로그인

<Diagram
  caption="2단계 인증으로 로그인하기"
  code={`flowchart LR
  A[이메일과 비밀번호] --> B{두 번째 인증 수단?}
  B -->|없음| S[로그인됨]
  B -->|있음| C[코드, 패스키 또는 복구 코드]
  C -->|5분 안에| S`}
/>

비밀번호를 입력하면 로그인 페이지가 **인증 코드**를 요청합니다. 방법을 바꾸려면 **패스키 사용**이나
**복구 코드 사용**을 고르세요. 5분 안에 마쳐야 하며, 지나면 비밀번호를 다시 입력해야 합니다.

## 역할에 2단계 인증 요구

<Steps>

1. **설정 → 역할**을 열고 역할을 엽니다.
2. **2단계 인증 필수**를 켜고 저장합니다.

</Steps>

두 번째 인증 수단이 없는 구성원은 로그인할 때 설정을 요청받습니다. 설정하기 전까지는 자기 프로필만 열 수
있습니다. **설정 → 사용자**에서 이들의 행에는 **2FA 미설정**이, 두 번째 인증 수단을 가진 관리자에게는 **2FA**가
표시됩니다.

역할이 두 번째 인증 수단을 요구하는 동안 Verdin은 마지막 인증 수단의 제거를 거부합니다. 앱을 끄기 전에 패스키를
추가하거나, 유일한 패스키를 지우기 전에 다른 인증 수단을 추가하세요.

## 다른 관리자의 두 번째 인증 수단 재설정

관리자가 기기와 복구 코드를 모두 잃어버렸을 때:

<Steps>

1. **설정 → 사용자**를 열고 관리자를 찾습니다.
2. **2단계 인증 초기화**를 선택하고 확인합니다.

</Steps>

이렇게 하면 인증 앱, 패스키, 복구 코드가 제거되어 비밀번호만으로 로그인합니다. 역할이 2단계 인증을 요구하면 다시
설정해야 합니다. **사용자 관리**가 필요하며, 다른 Super Admin을 재설정할 수 있는 것은 Super Admin뿐입니다.

`verdin admin reset-password`는 비밀번호만 재설정하며 두 번째 인증 수단은 재설정하지 않습니다.

## 싱글 사인온

[싱글 사인온](/ko/guides/auth/sso/)으로 로그인하는 관리자도 Verdin의 두 번째 인증 수단을 요청받습니다. 단,
제공업체에 **공급자가 MFA를 강제함**이 표시되어 있으면 예외입니다.

## Admin API

모든 라우트는 `/admin/api` 아래에 있습니다. 인증 수단을 바꾸는 라우트는 `password`를 받습니다.

| 라우트 | 하는 일 |
| --- | --- |
| `POST /auth/login` | 두 번째 인증 수단이 있으면 세션 대신 `{ twoFactorRequired: true, twoFactorToken, methods }`로 응답합니다. |
| `POST /auth/login/two-factor` | `{ twoFactorToken, code }`(TOTP 또는 복구 코드), 또는 패스키라면 `{ twoFactorToken, challengeToken, credential }`. 세션으로 응답합니다. |
| `POST /auth/login/passkey/options` | `{ twoFactorToken }`: 패스키 챌린지. |
| `GET /auth/two-factor` | 자신의 인증 수단: `totp`, `passkeys`, `recoveryCodesLeft`, `required`. |
| `POST /auth/two-factor/totp/setup`, `/totp/enable`, `/totp/disable` | 인증 앱 설정(비밀번호), 켜기(코드), 끄기(비밀번호). |
| `POST /auth/two-factor/recovery-codes` | 새 복구 코드. |
| `POST /auth/two-factor/passkeys/options`, `POST /auth/two-factor/passkeys`, `DELETE /auth/two-factor/passkeys/{id}` | 패스키 등록과 제거. |
| `DELETE /users/{id}/two-factor` | 다른 관리자의 인증 수단 재설정(`users.manage`). |
