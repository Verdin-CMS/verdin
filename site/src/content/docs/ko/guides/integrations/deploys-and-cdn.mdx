Verdin이 제공하는 것을 캐시하는 사이트를 위한 두 가지 도구입니다.

- **배포**는 관리자 헤더에 **배포** 버튼을 둡니다. 버튼은 사이트의 빌드 훅(Netlify, Vercel, Cloudflare Pages 또는 아무
  CI)을 호출하고, 제공업체가 빌드 진행 상황을 다시 알려 줍니다.
- **CDN 퍼지**는 콘텐츠 API 응답에 콘텐츠 타입별 태그를 붙이고, 콘텐츠가 공개적으로 바뀌면 Cloudflare, Fastly 또는 자체
  엔드포인트에서 그 태그를 퍼지합니다.

둘 다 코어의 일부이므로 기능 스위치가 없습니다. 배포는 **설정 → 배포**에서, CDN은 `verdin.toml`에서 설정합니다.

## 배포

<Diagram code={`sequenceDiagram
  participant E as 편집자
  participant V as Verdin

  E->>V: 배포

  P-->>V: 콜백: building

### 대상 추가

<Steps>

1. 제공업체에서 사이트의 빌드 훅을 만들고 URL을 복사합니다(Netlify: **Build hooks**, Vercel: **Deploy Hooks**,
   Cloudflare Pages: **Deploy hooks**, CI: `POST`로 파이프라인을 시작하는 아무 URL).
2. Verdin에서 **설정 → 배포**로 가서 **대상 추가**를 선택합니다.
3. **이름**(예: **프로덕션 사이트**)을 주고 **빌드 훅 URL**을 붙여 넣습니다.
4. 저장합니다. 훅 URL은 비밀이므로 이제부터는 호스트만 표시됩니다. 대상이 다른 훅을 가리키게 하려면 **URL 바꾸기**를
   쓰세요.

</Steps>

배포할 수 있는 관리자는 이제 헤더에서 **배포**를 봅니다. 대상이 여러 개면 **배포 대상** 메뉴가 열립니다. 확인하면
Verdin이 다음을 보냅니다.

```http
POST <build hook URL>
content-type: application/json

{ "trigger": "verdin", "triggeredBy": "editor@example.com" }
```

대상은 최대 10초에 한 번 배포하므로 더블 클릭해도 빌드가 두 번 시작되지 않습니다. 요청은 15초 뒤에 타임아웃되며
리디렉션을 따라가지 않습니다. `2xx`가 아닌 것으로 응답하는 훅은 **거부됨**으로 기록됩니다.

### 빌드 상태 알리기

콜백이 없으면 배포는 **시작됨** 상태로 남습니다. 관리자 패널에서 **빌드 중**, **준비됨**, **오류**와 배포된 사이트
링크를 보려면 제공업체에 대상의 콜백 URL을 주세요. 대상의 **콜백 URL** 버튼을 선택해 복사합니다.

<Tabs syncKey="deploy-provider">
<TabItem label="Netlify">

**Site configuration → Build & deploy → Deploy notifications**에서 **Deploy started**, **Deploy succeeded**,
**Deploy failed**에 대해 콜백 URL로 outgoing webhook을 추가합니다.

</TabItem>
<TabItem label="Vercel">

**Team settings → Webhooks**에서 `deployment.created`, `deployment.succeeded`, `deployment.error` 이벤트에 대해 콜백
URL로 웹훅을 만듭니다.

</TabItem>
<TabItem label="기타 CI">

`status`(`building`, `ready`, `error`)와, 선택적으로 배포된 `url`과 `message`를 담은 JSON을 `POST`합니다.

```sh title="Terminal"
curl -X POST "$VERDIN_CALLBACK_URL" -H 'content-type: application/json' \
  -d '{ "status": "ready", "url": "https://www.example.com" }'
```

</TabItem>
</Tabs>

Verdin은 Netlify의 `state`, Vercel의 `type`, 일반 `status`를 이해하며, 대상의 최신 배포를 업데이트합니다. `204`로
응답하며, URL이 틀리면 `404`로 응답합니다. 콜백 URL은 `{public_url}{admin path}/api/deploy/callback/{id}/{secret}`이므로
[`[server].public_url`](/ko/reference/configuration/)을 제공업체가 접근할 수 있는 주소로 설정하세요.

<Aside type="caution">
콜백 URL에는 비밀이 들어 있습니다. 이를 가진 누구나 그 대상의 배포 상태를 보고할 수 있습니다. 배포를 시작하거나 무언가를
읽을 수는 없습니다.
</Aside>

**배포 기록**은 최신 배포 50개를 최신순으로, 대상, 시작 시각, 상태, 훅의 HTTP 상태, 제공업체의 메시지와 함께 나열합니다.
대상을 삭제하면 그 기록이 삭제되며, 빌드 훅은 삭제되지 않습니다.

### 권한

| 권한 | 허용하는 것 |
| --- | --- |
| **배포 실행** (`deploy.trigger`) | 헤더의 **배포** 버튼. 기본 제공 Editor 역할이 가지고 있습니다. |
| **배포 대상 및 CDN 관리** (`deploy.manage`) | **설정 → 배포**: 대상, 콜백 URL, CDN 퍼지. |

[권한](/ko/reference/permissions/)을 참고하세요. 빌드 훅 URL은 [웹훅](/ko/guides/integrations/webhooks/)과 같은 주소
규칙을 따릅니다. `verdin start`에서는 [`[webhooks].allow_private_networks`](/ko/reference/configuration/)가 허용하지 않는
한 사설 네트워크를 가리킬 수 없습니다.

### 대신 변경할 때마다 배포

버튼은 필요할 때 다시 빌드하는 사이트에 맞습니다. 게시할 때마다 다시 빌드하려면 빌드 훅을 URL로 하는 `entry.publish`와
`entry.unpublish`용 [웹훅](/ko/guides/integrations/webhooks/)을 만드세요. 예약된 변경 묶음이라면
[릴리스](/ko/guides/content/releases/)로 게시하고 웹훅을 `releases.publish`에 연결하세요.

## CDN 퍼지

CDN이 콘텐츠 API를 캐시하면 캐시가 만료될 때까지 오래된 콘텐츠를 제공합니다. `[cdn]`을 설정하면 Verdin이 응답에 태그를
붙이고 콘텐츠가 바뀔 때 알맞은 태그를 퍼지하므로, 오래 캐시할 수 있습니다.

### 태그 동작 방식

콘텐츠 API의 모든 성공한 `GET`에는 `vd`(전체), `vd-<singularName>`(콘텐츠 타입), 그리고 문서가 populate할 수 있는 모든
타입의 태그가 붙습니다. 관계 대상이며, 컴포넌트와 다이나믹 존 안의 관계도 포함하고, 그 대상의 관계까지 따라갑니다. blog
예제의 글에서는 두 헤더 형식으로 다음과 같습니다.

```http
Cache-Tag: vd,vd-article,vd-category,vd-tag
Surrogate-Key: vd vd-article vd-category vd-tag
```

다형성 관계를 가진 타입은 어떤 타입에든 닿을 수 있으므로, 그 응답에는 모든 타입의 태그가 붙습니다.

Cloudflare는 `Cache-Tag`를, Fastly는 `Surrogate-Key`를 읽습니다. 콘텐츠가 공개적으로 바뀌면 Verdin은 그 타입의 태그를
퍼지합니다.

- 항목의 게시, 게시 취소, 삭제.
- 초안과 게시를 쓰지 않는 타입에 대한 모든 쓰기(그 쓰기는 즉시 공개됨).

초안은 공개적으로 제공되지 않으므로 초안 저장은 아무것도 퍼지하지 않습니다. 1초(`debounce_ms`) 안의 변경은 퍼지 하나로
모으며, 실패한 퍼지는 두 번 다시 시도합니다.

### 설정

<Tabs syncKey="cdn">
<TabItem label="Cloudflare">

```toml title="verdin.toml"
[cdn]
provider = "cloudflare"
zone_id = "023e105f4ecef8ad9ca31a8372d0c353"
```

`VERDIN_CDN_TOKEN`은 zone에 **Cache Purge** 권한을 가진 API 토큰입니다.

</TabItem>
<TabItem label="Fastly">

```toml title="verdin.toml"
[cdn]
provider = "fastly"
service_id = "SU1Z0isxPaozGVKXdv0eY"
```

`VERDIN_CDN_TOKEN`은 서비스를 퍼지할 수 있는 Fastly API 토큰입니다.

</TabItem>
<TabItem label="Webhook">

```toml title="verdin.toml"
[cdn]
provider = "webhook"
url = "https://purge.example.com/verdin"
```

Verdin은 `POST { "tags": ["vd-article"] }`을 보내며, 토큰이 설정되어 있으면 `Authorization: Bearer <VERDIN_CDN_TOKEN>`도
보냅니다. 다른 CDN, 리버스 프록시, 프레임워크의 revalidation API에 쓰세요.

</TabItem>
</Tabs>

```sh title="Terminal"
export VERDIN_CDN_TOKEN=...
```

Verdin은 시작할 때 섹션을 확인하며, 제공업체에 필요한 `zone_id`, `service_id`, `url`, 토큰이 없으면 실행을 거부합니다.
[`[cdn]`](/ko/reference/configuration/)을 참고하세요.

무엇을 캐시할지는 여전히 CDN이 정합니다. API 경로에 대해 긴 엣지 TTL을 가진 캐시 규칙을 설정하세요(예: 익명 `GET`의
`/api/*`). 인증된 요청, 미리 보기 읽기, `/api/_events`는 캐시에서 제외하세요.

### 확인과 수동 퍼지

**설정 → 배포**의 **CDN** 섹션은 제공업체와 **최근 캐시 삭제**(**삭제됨** 또는 **실패**, 태그와 함께)를 보여 줍니다.
**전체 캐시 삭제**는 `vd` 태그가 붙은 모든 응답을 버립니다.

응답에는 populate할 수 있는 타입의 태그가 붙으므로, 카테고리 이름을 바꾸면 요청이 `populate`를 요청했는지와 상관없이
그 카테고리를 포함할 수 있는 캐시된 글 목록도 퍼지됩니다.

Verdin 자체의 메모리 캐시([`[api].cache_ttl_secs`](/ko/reference/configuration/))는 별개이며, 변경할 때마다 비워집니다.
