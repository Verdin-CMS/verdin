편집자 다이제스트는 각 관리자가 마지막으로 본 뒤 바뀐 항목 수를 콘텐츠 타입별로 알려 주는 일일 이메일입니다.
각 관리자가 직접 켜기 전까지는 모두에게 꺼져 있습니다. 이 가이드에서는 관리자 쪽 설정, 서버 설정, 여러
인스턴스에서의 동작을 다룹니다.

## "확인하지 않음"의 동작 방식

다른 사람이 어떤 API에서든 항목을 바꾸면 그 항목은 여러분에게 확인하지 않은 항목이 됩니다. 항목을 열면 다시 확인한
상태가 됩니다. 같은 표시가 사이드바의 **새 항목** 배지(**새 항목 배지 표시**로 끔)와 홈 페이지의
**아직 안 본 항목** 위젯을 움직입니다.

## 다이제스트 켜기

<Steps>

1. **프로필**(또는 상단 바의 환경설정 메뉴)을 엽니다.
2. **환경설정** 아래에서 **확인하지 않은 변경 사항 일일 이메일**을 켭니다.

</Steps>

이 스위치는 계정에 `"digest": "daily"` 환경설정을 설정합니다(`PUT /admin/api/users/me/preferences`). 같은
방법으로 끕니다.

받는 내용:

- 읽을 수 있는 콘텐츠 타입별 확인하지 않은 항목 수와 관리자 패널 링크가 담긴 메시지.
- 새로운 것이 없는 날에는 아무것도 없습니다.
- 계정이 활성 상태인 동안에만 받습니다.

## 서버 설정

다이제스트는 `[digest].hour_utc`에 `[email]`로 보냅니다.

```toml title="verdin.toml"
[email]
provider = "smtp"
from = "Verdin <no-reply@example.com>"

[email.smtp]
host = "smtp.example.com"

[digest]
hour_utc = 7    # 0–23, UTC; 8 by default
```

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `[digest].enabled` | `true` | 이 인스턴스에서 다이제스트를 보냅니다. |
| `[digest].hour_utc` | `8` | 다이제스트를 보내는 시각(UTC). |

이메일의 링크는 `[server].public_url`을 씁니다. Verdin이 프록시 뒤에서 실행되면 설정하세요. 기본 `log` 이메일
프로바이더에서는 메시지가 서버 로그에만 기록됩니다. [설정 레퍼런스](/ko/reference/configuration/)를 참고하세요.

## 여러 인스턴스

`[digest].enabled = true`인 모든 인스턴스가 설정한 시각에 다이제스트를 보내려고 시도합니다. 데이터베이스에서 그날을
먼저 가져간 인스턴스가 보내고, 나머지는 그날을 건너뛰므로 관리자는 이메일을 한 통만 받습니다. 작업을 정해진
인스턴스에서만 하려면 다른 인스턴스에 `enabled = false`를 설정하세요.

```sh title="Terminal"
VERDIN_DIGEST__ENABLED=false verdin start
```

<Aside type="note">
다이제스트는 Verdin이 추가한 기능이며, Strapi에는 이에 해당하는 기능이 없습니다.
</Aside>
