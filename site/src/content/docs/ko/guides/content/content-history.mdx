Verdin은 어떤 API에서든 항목이 생성, 저장, 게시, 게시 취소되거나 초안이 폐기될 때마다 버전을 보관합니다. 이
가이드에서는 이전 버전을 찾아 복원하는 방법, 보관되는 버전 수, 해당 admin API를 다룹니다.

콘텐츠 기록은 Strapi와 같은 방식으로 동작합니다. Strapi에서는 유료 기능입니다.

## 시작하기 전에

- **설정 → 기능 → 콘텐츠 기록**은 기본적으로 켜져 있습니다. 꺼져 있는 동안에는 버전이 기록되지 않고 기록을 볼 수
  없습니다.
- 항목의 기록을 읽으려면 항목에 대한 읽기 권한이, 복원하려면 수정 권한이 필요합니다. 필드 제한이 적용되므로 역할이
  읽거나 수정할 수 있는 필드만 보고 복원합니다. [권한](/ko/reference/permissions/)을 참고하세요.

## 버전 복원

<Steps>

1. 항목을 열고 **기록**을 선택합니다.
2. **버전** 목록은 각 버전을 이벤트(**생성**, **저장**, **게시**, **게시 취소**, **초안 폐기됨**), 날짜, 만든
   사람과 함께 보여 줍니다. 콘텐츠 API로 한 변경은 작성자가 **API**로 표시됩니다.
3. 버전을 선택해 필드를 봅니다.
4. **복원**을 선택하고 확인합니다.

</Steps>

선택한 버전이 현재 초안을 대체합니다. 준비가 되면 그 뒤에 게시하세요. 초안과 게시를 쓰지 않는 타입에서는 복원하면
항목이 바로 업데이트됩니다.

복원할 때 빠지는 것:

- 스키마에 더 이상 없는 필드는 목록에 표시되며 복원되지 않습니다.
- 삭제된 항목이나 파일에 대한 참조는 빠지며, 편집기가 어떤 필드에서 빠졌는지 알려 줍니다.

**편집기로 돌아가기**는 아무것도 바꾸지 않고 항목으로 돌아갑니다.

## 보관되는 버전 수

Verdin은 항목과 로케일마다 최신 `[history].max_versions`개(기본 50)의 버전을 보관하며, 새 버전이 들어오면 오래된
버전을 지웁니다.

```toml title="verdin.toml"
[history]
max_versions = 100
```

로컬라이즈된 항목은 로케일마다 자체 기록을 가집니다. 항목이나 그 로케일 하나를 삭제하면 해당 버전도 삭제됩니다.
[설정 레퍼런스](/ko/reference/configuration/)를 참고하세요.

<Aside type="note">
기록을 일정 일수 동안 보관하는 Strapi와 달리, Verdin은 오래되었는지와 상관없이 항목마다 일정 개수의 버전을
보관합니다.
</Aside>

## Admin API

모든 라우트는 `/admin/api` 아래에 있습니다.

| 라우트 | 권한 | 하는 일 |
| --- | --- | --- |
| `GET /history/{uid}/{documentId}?locale=&page=&pageSize=` | 항목 읽기 | 데이터 없이 최신순으로 버전(페이지당 20개, 최대 100개). |
| `GET /history/versions/{id}` | 항목 읽기 | 데이터를 포함한 버전 하나. |
| `POST /history/versions/{id}/restore` | 항목 수정 | 버전을 현재 초안으로 복원합니다. |

복원 응답에는 빠진 것이 나열됩니다.

```json
{
  "data": {
    "documentId": "k3v9…",
    "restored": 42,
    "dropped": [{ "field": "tags", "count": 1 }]
  }
}
```

기능이 꺼져 있는 동안 라우트는 `404`로 응답합니다.
