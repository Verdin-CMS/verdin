릴리스는 함께 공개되거나 함께 내려가는 항목을 묶습니다. 제품 출시, 캠페인, 번역 묶음 같은 경우입니다. 직접 게시하거나
날짜를 지정합니다. 이 가이드에서는 릴리스를 만들고, 항목을 추가하고, 실행하고, admin API를 보여 줍니다.

릴리스는 Strapi의 Releases처럼 동작하며, Strapi에서는 유료 플랜에 포함됩니다.

## 시작하기 전에

- **설정 → 기능 → 릴리스**는 기본적으로 켜져 있습니다. 꺼져 있는 동안에는 **릴리스** 페이지와 라우트를 쓸 수 없고,
  예약된 릴리스는 대기합니다.
- 릴리스를 관리하려면 **릴리스 관리**(`releases.manage`)가 필요합니다.
- 항목을 추가하려면 그 콘텐츠 타입에 대한 **게시** 권한도 필요하며, 타입이
  [초안과 게시](/ko/concepts/draft-and-publish/)를 써야 합니다.

## 릴리스 만들기

<Steps>

1. 사이드바에서 **릴리스**를 열고 **새 릴리스**를 선택합니다.
2. **이름**을 입력합니다.
3. 선택적으로 <strong>게시 일시(선택 사항)</strong>를 설정합니다. 릴리스가 실행될 날짜와 시각이며, 여러분의 시간대 기준입니다.
   날짜가 없으면 직접 게시할 때까지 대기합니다.
4. **만들기**를 선택합니다.

</Steps>

## 항목 추가

<Steps>

1. 편집기에서 항목을 엽니다. **릴리스** 패널에 항목이 들어 있는 릴리스가 나열됩니다.
2. **릴리스에 추가**를 선택합니다.
3. **릴리스**를 고르고, **릴리스 실행 시** 아래에서 **게시** 또는 **게시 취소**를 고릅니다.
4. **추가**를 선택합니다.

</Steps>

로컬라이즈된 타입에서는 편집기의 현재 로케일 버전만 추가됩니다. 릴리스할 로케일을 각각 추가하세요. 이미 릴리스에 있는
항목을 추가하면 작업이 대체됩니다.

릴리스 페이지는 항목을 콘텐츠 타입과 작업과 함께 나열합니다. 행의 버튼으로 항목을 제거할 수 있습니다.

## 릴리스 게시

- **즉시:** 릴리스를 열고 **지금 게시**를 선택합니다.
- **지정한 날짜에:** 백그라운드 작업이 30초마다 확인하며, 때가 된 릴리스를 그 릴리스를 만든 관리자 이름으로
  실행합니다.

<Diagram
  caption="릴리스 상태"
  code={`flowchart LR
  P[대기 중] -->|지금 게시 또는 날짜 도달| R[실행 중]
  R -->|모든 작업 성공| D[완료]
  R -->|일부 작업 실패| F[실패]`}
/>

각 작업은 성공 여부를 기록합니다. 항목이 삭제되었거나 검증을 통과하지 못해서 하나가 실패해도 다른 작업은 계속
실행되며, 릴리스는 **실패**로 끝나고 실패한 각 작업의 행에 오류가 표시됩니다.

<Aside type="caution">
실행된 릴리스는 더 이상 바꿀 수 없습니다. 실패한 작업을 다시 시도하려면 그 항목들을 새 릴리스에 추가하세요.
</Aside>

릴리스는 통째로 게시되며 [검토 단계](/ko/guides/content/review-workflows/)를 기다리지 않습니다. 워크플로가 게시에
특정 단계를 요구하면, 그 단계에 있지 않은 항목은 다른 게시와 마찬가지로 실패합니다.

웹훅은 릴리스가 실행될 때 보내는 **릴리스 게시**(`releases.publish`)를 구독할 수 있습니다.
[웹훅](/ko/guides/integrations/webhooks/)을 참고하세요.

## Admin API

모든 라우트는 `/admin/api` 아래에 있으며 `releases.manage`가 필요합니다.

```http
GET    /admin/api/releases?status=pending&page=1&pageSize=25
POST   /admin/api/releases                    { "name": "Launch", "scheduledAt": "2026-10-01T08:00:00Z" }
GET    /admin/api/releases/{id}
PUT    /admin/api/releases/{id}               { "name": "Launch", "scheduledAt": null }
DELETE /admin/api/releases/{id}
POST   /admin/api/releases/{id}/actions       { "uid": "api::article", "documentId": "…", "locale": "fr", "action": "publish" }
DELETE /admin/api/releases/{id}/actions/{actionId}
POST   /admin/api/releases/{id}/publish
GET    /admin/api/content/{uid}/{documentId}/releases
```

- `status`는 `pending`, `running`, `done`, `failed` 중 하나이며, 각 작업에는 자체 `status`와 `error`가 있습니다.
- 더 이상 대기 중이 아닌 릴리스를 바꾸거나, 추가하거나, 게시하면 `409`로 응답합니다.
- `action`은 `publish` 또는 `unpublish`입니다. 작업을 추가하려면 해당 타입에 `content.publish`도 필요합니다. 로케일은
  작업을 추가할 때 정해지므로, 나중에 기본 로케일이 바뀌어도 옮겨지지 않습니다.
- 릴리스를 삭제하면 항목 목록이 삭제됩니다. 항목 자체는 바뀌지 않습니다.
- `GET /content/{uid}/{documentId}/releases`는 항목에 대한 읽기 권한이 필요하며, `releases.manage`가 없는 관리자에게는
  빈 목록을 반환합니다.
