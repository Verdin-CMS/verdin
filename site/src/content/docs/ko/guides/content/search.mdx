콘텐츠 API와 관리자 패널은 Strapi처럼 `_q` 파라미터로 항목을 검색합니다. 기본적으로 `_q`는 단어가 들어 있는 텍스트
필드와 일치합니다. `[search]` 인덱스를 켜면 서버에 내장된 전문 검색 엔진(Tantivy)으로 결과를 정렬합니다. 이
가이드에서는 둘 다 보여 주고 언제 인덱스를 쓰는지 설명합니다.

## `_q`로 검색

```sh title="Terminal"
curl -G 'http://localhost:1337/api/articles' --data-urlencode '_q=rust cms'
```

`_q`는 다른 파라미터와 함께 씁니다: `filters`, `status`, `locale`, `pagination`, `fields`, `populate`. 관리자 목록의
검색 상자도 같은 파라미터를 보냅니다.

검색하는 필드:

- 텍스트 필드: `string`, `text`, `richtext`, `email`, `uid`, `enumeration`.
- 인덱스를 쓰면 `blocks`, 컴포넌트, 다이나믹 존 안의 텍스트도.
- private 필드와 비밀번호는 절대 검색하지 않습니다.

`_q`는 REST 파라미터입니다. GraphQL과 TypeScript 클라이언트의 쿼리 옵션에는 검색 인자가 없으니, 거기서는
`$containsi` 필터를 쓰세요.

## 인덱스 없이

`[search]`가 없으면 `_q`는 어떤 텍스트 필드든 검색어 전체를 대소문자 구분 없이 포함하는 항목과 일치하며, Strapi의
`$containsi`와 같습니다. 결과는 일반 정렬을 따릅니다. 설정이 필요 없고 모든 데이터베이스에서 동작하지만, 테이블을
스캔하며 관련도순으로 정렬하지 않습니다.

## 전문 검색 인덱스 켜기

<Steps>

1. `verdin.toml`에서 인덱스를 켭니다.

   ```toml title="verdin.toml"
   [search]
   enabled = true
   ```

2. Verdin을 재시작합니다. 모든 항목으로 백그라운드에서 인덱스를 만듭니다. 준비될 때까지 `_q`는 `$containsi`로
   대체됩니다.

</Steps>

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `enabled` | `false` | 전문 검색 인덱스로 `_q`를 정렬합니다. |
| `dir` | `"data/search"` | 프로젝트 기준 인덱스 디렉터리. |
| `memory_mb` | `50` | 인덱싱 메모리 예산(메가바이트). |

[설정 레퍼런스](/ko/reference/configuration/)를 참고하세요.

인덱스가 일치시키는 방식:

- 단어는 문자나 숫자가 아닌 모든 것을 기준으로 나누고, 소문자로 바꾸고, 악센트를 제거하므로 `cafe`로 `Café`를 찾을
  수 있습니다.
- 모든 단어가 일치해야 합니다. 마지막 단어는 접두사로도 일치하므로 입력하는 도중에 결과가 나타납니다.
- 제목(타입의 첫 번째 텍스트 필드)은 가중치가 두 배입니다.
- `sort`가 없으면 가장 잘 일치하는 결과가 먼저 옵니다. `sort`가 있으면 일치 항목을 지정한 방식으로 정렬합니다.
  검색 한 번에 최대 1,000개의 일치 항목을 고려합니다.
- 초안과 게시 버전, 그리고 각 로케일은 `status`와 `locale`에 따라 따로 검색합니다.

인덱스는 모든 API의 모든 쓰기를 따라갑니다. 스키마가 검색 가능한 필드를 바꾸거나 디렉터리가 없으면 다시 만들어집니다.

## 여러 인스턴스

인덱스는 인스턴스의 디스크에 있으며 그 인스턴스의 쓰기를 따라갑니다. 인스턴스를 여러 개 실행하면 한 인스턴스의 쓰기가
다른 인스턴스의 인덱스에 반영되지 않습니다. 검색을 인스턴스 하나에만 두거나, 배포 후 시작 전에 인덱스 디렉터리를
삭제해서 다시 만드세요. [확장](/ko/deploy/scaling/)을 참고하세요.

<Aside type="tip">
인덱스 디렉터리는 삭제해도 안전합니다. 백업과 버전 관리에서 제외하세요. Verdin이 데이터베이스로 다시 만듭니다.
</Aside>
