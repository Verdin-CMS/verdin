각 콘텐츠 타입의 관리자 목록은 항목을 CSV나 JSON으로 내보내고, 같은 종류의 파일에서 다시 가져옵니다. 스프레드시트에서
많은 항목을 고치거나, 상품 카탈로그를 불러오거나, 프로젝트 사이에 항목을 복사할 때 씁니다. 이 가이드에서는 양방향과
파일 형식을 다룹니다.

이 기능은 한 번에 한 콘텐츠 타입의 항목용입니다. 프로젝트 전체를 옮기려면
[`verdin export`와 `verdin import verdin`](/ko/reference/cli/)을 참고하세요. Strapi에서 옮겨 오려면
[Strapi에서 마이그레이션](/ko/migrate/from-strapi/)을 참고하세요.

## 시작하기 전에

- 내보내려면 콘텐츠 타입에 대한 읽기 권한이 필요합니다. 역할이 읽을 수 있는 필드만 내보냅니다.
- 가져오려면 생성 권한, 수정 권한, 또는 둘 다 필요합니다. 항목을 만드는 행에는 생성이, 수정하는 행에는 수정이
  필요합니다. 가져온 행을 게시하려면 게시 권한도 필요합니다. [권한](/ko/reference/permissions/)을 참고하세요.

## 항목 내보내기

<Steps>

1. 콘텐츠 타입의 목록을 열고 원하는 내보내기 형태로 설정합니다: 필터, 검색, 정렬, 상태, 로케일.
2. **내보내기**를 선택한 뒤 **CSV로 내보내기** 또는 **JSON으로 내보내기**를 선택합니다.

</Steps>

파일에는 목록이 필터, 검색, 정렬을 적용해 보여 주는 항목이 모든 페이지에 걸쳐 최대 50,000개까지 담깁니다. 각 행은
`documentId`로 시작하고 그 뒤에 필드가 옵니다.

## 항목 가져오기

<Steps>

1. 콘텐츠 타입의 목록을 열고 **가져오기**를 선택합니다.
2. **파일**을 고릅니다: 헤더 행이 있는 `.csv` 파일, 또는 객체 리스트를 담은 `.json` 파일, 최대 1 MB.
3. **열** 아래에서 각 열이 들어갈 필드를 고릅니다. 필드와 이름이 같은 열은 이미 매칭되어 있습니다. 열을 빼려면
   **건너뛰기**를, 기존 항목을 지정하는 열에는 <strong>문서 ID (수정)</strong>을 고르세요.
4. 선택적으로 **가져온 항목 게시**를 켭니다. 켜지 않으면 초안으로 저장됩니다.
5. **확인**을 선택합니다. Verdin은 아무것도 쓰지 않고 제약 조건과 참조를 포함해 모든 행을 검사하며, 만들 행, 수정할
   행, 거부할 행을 보고합니다.
6. 필요하면 파일을 고친 뒤 **가져오기**를 선택합니다.

</Steps>

행이 쓰이는 방식:

- `documentId`가 있는 행은 그 항목을 수정하고, 나머지는 새 항목을 만듭니다.
- 행은 하나씩 쓰입니다. 실패한 행은 필드와 문제와 함께 보고되고 건너뛰며, 나머지는 계속 쓰입니다.
- 보고서는 오류가 있는 행을 최대 100개, 그리고 어떤 필드와도 매칭되지 않은 열을 나열합니다.
- 가져오기 한 번에 최대 5,000행입니다. 더 큰 파일은 나누세요.
- 항목은 목록의 현재 로케일로 쓰입니다.

<Aside type="caution">
가져오기는 행을 편집기와 같은 검증에 통과시키지만, 되돌릴 수는 없습니다. 먼저 **확인**을 실행하고, 대규모 수정 전에는
복원할 수 있도록 목록을 내보내 두세요. [콘텐츠 기록](/ko/guides/content/content-history/)이 켜져 있으면 수정된 모든
항목이 이전 버전을 보관합니다.
</Aside>

## 파일 형식

필드는 콘텐츠 API의 쓰기 형식과 같은 형태를 씁니다.

| 필드 | 값 |
| --- | --- |
| 텍스트, 숫자, 불리언, 날짜 | API와 같음(`true`/`false`, ISO 8601 날짜). |
| 관계 | 관련 항목의 `documentId`. |
| 미디어 | 미디어 라이브러리의 파일 id. |
| 다형성 관계 | `uid:documentId`, 예: `api::article:k3v9…`. |
| 컴포넌트, 다이나믹 존, blocks, JSON | JSON. |

CSV에서 리스트(여러 관계나 파일)는 `|`로 이어 붙입니다.

```csv title="articles.csv"
documentId,title,slug,featured,tags
,Hello world,hello-world,true,t1a2b3|t4c5d6
k3v9x8…,Updated title,updated-title,false,
```

같은 행을 JSON으로 쓰면 다음과 같습니다.

```json title="articles.json"
[
  { "title": "Hello world", "slug": "hello-world", "featured": true, "tags": ["t1a2b3", "t4c5d6"] },
  { "documentId": "k3v9x8…", "title": "Updated title", "slug": "updated-title", "featured": false }
]
```

목록을 내보낸 파일은 항상 같은 콘텐츠 타입에 대해 유효한 가져오기 파일입니다.

## Admin API

- `GET /admin/api/content/{uid}/export?format=csv`(또는 `json`)는 목록의 쿼리 파라미터를 받습니다: `filters`,
  `_q`, `sort`, `status`, `locale`.
- `POST /admin/api/content/{uid}/import?locale=`는 파일 내용을 문자열로 받습니다.

```json
{
  "format": "csv",
  "data": "title,slug\nHello world,hello-world\n",
  "mapping": { "slug": "slug", "notes": null },
  "dryRun": true,
  "publish": false
}
```

`mapping`은 열을 필드에 매핑합니다. `null`은 열을 건너뛰고, 매핑하지 않은 열은 이름을 그대로 씁니다. 요청 본문은
`[server].body_limit`(기본 1 MB)으로 제한됩니다.
