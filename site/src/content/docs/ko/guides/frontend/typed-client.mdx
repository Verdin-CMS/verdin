`@verdin/client`는 콘텐츠 API(REST 문서, 미디어 라이브러리, GraphQL)를 위한 작은 TypeScript 클라이언트입니다. 콘텐츠
타입의 TypeScript 정의를 쓰는 `verdin types`와 함께 쓰면, 입력하는 동안 편집기가 라우트 이름, 필드, 쓰기 페이로드를
검사합니다.

클라이언트는 의존성이 없으며 `fetch`가 있는 곳이면 어디서든 실행됩니다: 브라우저, Node 20 이상, Deno, Bun, 엣지 워커.
선택 사항이며, 모든 호출은 [REST API](/ko/api/rest/)의 일반 HTTP 요청에 대응합니다.

## 설치와 타입 생성

<Steps>

1. 프런트엔드 프로젝트에 패키지를 설치합니다.

   ```sh title="Terminal"
   npm install @verdin/client
   ```

2. Verdin 프로젝트(`verdin.toml`이 있는 디렉터리)에서 타입을 생성합니다.

   ```sh title="Terminal"
   verdin types -o ../site/src/verdin-types.ts
   ```

   `-o`(`--out`)가 없으면 정의는 표준 출력으로 나갑니다. 이 명령은 스키마 파일만 읽으며 데이터베이스가 필요 없습니다.

3. 생성된 `VerdinSchema`로 클라이언트를 만듭니다.

   ```ts title="src/verdin.ts"
   import { createClient } from '@verdin/client';
   import type { VerdinSchema } from './verdin-types';

   export const verdin = createClient<VerdinSchema>({
     url: 'https://cms.example.com',
     token: process.env.VERDIN_TOKEN, // omit to use the public role
   });
   ```

</Steps>

스키마를 바꿀 때마다 `verdin types`를 다시 실행하세요. 파일의 첫 줄에도 그렇게 적혀 있습니다. 파일을 프런트엔드 코드
옆에 커밋하거나 CI에서 다시 생성하면 양쪽을 맞춰 둘 수 있습니다.

<Aside type="caution">
토큰은 소지자에게 토큰의 권한을 줍니다. 전체 접근과 사용자 지정 토큰은 서버(SSR, 빌드 스크립트, API 라우트)에 두세요.
브라우저 번들은 토큰 없이(공개 역할) 쓰거나 읽기 전용 토큰을 써야 합니다. [API 토큰](/ko/guides/auth/api-tokens/)을
참고하세요.
</Aside>

## `verdin types`가 생성하는 것

[예제 블로그](https://github.com/Verdin-CMS/verdin/blob/main/examples/blog/)(글, 카테고리, 태그, homepage 싱글 타입,
`shared.seo`, `blocks.hero`, `blocks.quote` 컴포넌트)의 경우 파일에는 다음이 들어 있습니다.

| 타입 | 설명 |
| --- | --- |
| `Article`, `Category`, `Tag`, `Homepage` | 콘텐츠 타입마다 `singularName`으로 이름 붙인 인터페이스 하나이며, `DocumentBase`(`id`, `documentId`, `createdAt`, `updatedAt`, `publishedAt`)를 확장합니다. private 속성은 빠집니다. |
| `ArticleInput`, … | 쓰기 타입: 모든 속성이 선택 사항이고, 관계는 `documentId` 문자열(또는 `connect` / `disconnect` / `set`), 미디어는 파일 id이며, 역방향 관계 쪽은 빠집니다. |
| `ComponentSharedSeo`, `ComponentBlocksHero`, … | 컴포넌트마다 인터페이스 하나와 그 `…Input` 타입. 다이나믹 존 항목은 타입이 지정된 `__component`를 가집니다. |
| `Media`, `MediaFormat`, `Blocks` | 미디어 라이브러리 파일, 그 반응형 포맷, 리치 텍스트 blocks 형식. |
| `Collections`, `Singles`, `VerdinSchema` | 클라이언트를 위해 라우트(`articles`, `homepage`)를 문서와 입력 타입에 매핑합니다. |

관계, 미디어, 컴포넌트, 다이나믹 존은 선택 속성(`category?:`)입니다. API는 `populate`했을 때만 이들을 반환하기
때문입니다. 큰 정수는 JavaScript 숫자에 맞지 않으므로 `string`입니다.

생성된 타입이 없어도 클라이언트는 동작합니다. 모든 라우트를 받아들이고 문서는 `Record<string, unknown>`입니다.

## 콘텐츠 읽기

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
curl -g 'https://cms.example.com/api/articles?filters[title][$containsi]=rust&populate[category]=true&populate[seo]=true&sort[0]=publishedAt:desc&pagination[page]=1&pagination[pageSize]=10' \
  -H "Authorization: Bearer $VERDIN_TOKEN"
```

</TabItem>
<TabItem label="GraphQL">

```graphql
query {
  articles(
    filters: { title: { containsi: "rust" } }
    sort: ["publishedAt:desc"]
    pagination: { page: 1, pageSize: 10 }
  ) {
    documentId
    title
    slug
    category { name }
    seo { metaTitle metaDescription }
  }
}
```

</TabItem>
<TabItem label="TypeScript">

```ts
import { verdin } from './verdin';

const { data, meta } = await verdin.collection('articles').find({
  filters: { title: { $containsi: 'rust' } },
  populate: { category: true, seo: true },
  sort: ['publishedAt:desc'],
  pagination: { page: 1, pageSize: 10 },
});

data[0].title; // string
data[0].category?.name; // string | null | undefined
meta.pagination.total;
```

</TabItem>
</Tabs>

쿼리 파라미터는 Strapi v5 형식을 쓰며 대괄호 표기법으로 직렬화되므로, REST API에서 동작하는 필터, 정렬, `fields`,
`populate`, `status`, `locale`은 여기서도 동작합니다. 전체 문법은 [REST API](/ko/api/rest/)를 참고하세요.

| 호출 | 요청 |
| --- | --- |
| `collection(route).find(params?)` | `GET /api/:route` |
| `collection(route).findOne(documentId, params?)` | `GET /api/:route/:documentId` |
| `collection(route).create(data, params?)` | `POST /api/:route` (`status: 'draft'`가 아니면 게시) |
| `collection(route).update(documentId, data, params?)` | `PUT /api/:route/:documentId` |
| `collection(route).delete(documentId)` | `DELETE /api/:route/:documentId` |
| `collection(route).publish(documentId)`, `unpublish`, `discardDraft` | `POST /api/:route/:documentId/actions/publish` (`unpublish`, `discard-draft`) |
| `single(route).find(params?)`, `update(data, params?)`, `delete()` | `GET`, `PUT`, `DELETE /api/:route` |
| `upload(files, info?)` | `POST /api/upload` (multipart) |
| `files(params?)` | `GET /api/upload/files` |
| `graphql(query, variables?)` | `POST /graphql` |

쿼리 문자열을 직접 만들 수 있도록(예: `<link rel="preload">`용) `stringify(params)`도 내보냅니다.

## 콘텐츠 쓰기

```ts
const { data: article } = await verdin.collection('articles').create(
  {
    title: 'Hello from TypeScript',
    category: 'hx2n8r3w0c1kq5v7m4j6b9a0',       // a category's documentId
    tags: { connect: ['t1…', 't2…'] },
    seo: { metaTitle: 'Hello', metaDescription: 'A first post' },
  },
  { status: 'draft' },
);

await verdin.collection('articles').publish(article.documentId);
```

Strapi v5처럼 초안과 게시를 쓰는 타입에서 `create`는 `status: 'draft'`를 넘기지 않으면 문서를 바로 게시합니다. 쓰기에는
해당 타입에 `create`, `update`, `publish` 권한을 가진 토큰이 필요합니다. [권한](/ko/reference/permissions/)을 참고하세요.

`upload`로 파일을 업로드한 뒤 id로 참조합니다.

```ts
const [cover] = await verdin.upload(file, { alternativeText: 'The team at the office' });
```

`file`은 `Blob`이나 `File`(또는 그 리스트)입니다. 업로드에는 미디어 라이브러리에 대한 `create` 권한이 필요합니다.

## GraphQL

`graphql()`은 `/graphql`로 POST하므로 **설정 → 기능**에서 **GraphQL** 기능이 켜져 있어야 합니다. 응답의 `data`를
반환하며, 첫 오류에서 예외를 던집니다.

```ts
const data = await verdin.graphql<{ articles: Array<{ title: string }> }>(
  `query ($q: String) { articles(filters: { title: { containsi: $q } }) { title } }`,
  { q: 'rust' },
);
```

생성된 타입은 REST API를 기술합니다. GraphQL에서는 위처럼 결과 타입을 직접 넘기거나, 엔드포인트를 대상으로 GraphQL 코드
생성기를 쓰세요. [GraphQL](/ko/api/graphql/)을 참고하세요.

## 오류

실패한 모든 요청은 API가 Strapi 형식으로 보낸 오류를 담은 `VerdinError`로 reject됩니다.

| 속성 | 예 |
| --- | --- |
| `status` | `400`, `401`, `403`, `404`, `429` |
| `name` | `ValidationError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError`, `RateLimitError`, `GraphQLError` |
| `message` | 읽을 수 있는 설명. |
| `details` | `ValidationError`의 잘못된 필드 목록 같은 오류 세부 정보. |

```ts
import { VerdinError } from '@verdin/client';

try {
  const { data } = await verdin.collection('articles').findOne(id);
  return data;
} catch (error) {
  if (error instanceof VerdinError && error.status === 404) return null;
  throw error;
}
```

## 옵션

| 옵션 | 설명 |
| --- | --- |
| `url` | `https://cms.example.com` 같은 서버 출처. 필수. |
| `token` | `Authorization: Bearer …`로 보내는 API 토큰이나 최종 사용자의 JWT. 공개 역할이라면 생략합니다. |
| `prefix` | 콘텐츠 API 접두사. 기본값 `/api`. 바꿨다면 [`[api].prefix`](/ko/reference/configuration/)와 맞추세요. |
| `fetch` | 전역 `fetch` 대신 쓸 `fetch` 구현. |
| `headers` | 모든 요청에 보낼 추가 헤더. |

## 서버 렌더링과 엣지 런타임

클라이언트는 `fetch`만 호출하므로 서버 컴포넌트, API 라우트, 빌드 스크립트, 엣지 함수에서 그대로 실행됩니다. 모든
요청에 프레임워크의 캐시 옵션을 더하려면 사용자 정의 `fetch`를 넘기세요. 예를 들어 Next.js에서는 다음과 같습니다.

```ts title="src/verdin.ts"
export const verdin = createClient<VerdinSchema>({
  url: process.env.VERDIN_URL!,
  token: process.env.VERDIN_TOKEN,
  fetch: (input, init) => fetch(input, { ...init, next: { revalidate: 60, tags: ['verdin'] } }),
});
```

미리 보기 페이지에서 초안을 읽으려면 관리자가 미리 보기 URL에 넣은 미리 보기 토큰을 헤더로 보내세요.

```ts
const preview = createClient<VerdinSchema>({
  url: process.env.VERDIN_URL!,
  headers: { 'x-verdin-preview': searchParams.get('preview') ?? '' },
});
const { data } = await preview.collection('articles').findOne(id, { status: 'draft' });
```

미리 보기 링크의 동작은 [미리 보기](/ko/guides/content/preview/)를, 같은 페이지에 클릭해서 편집하기를 추가하려면
[비주얼 에디팅](/ko/guides/frontend/visual-editing/)을 참고하세요.

다른 출처의 브라우저에서 API를 호출하려면 그 출처가 [`[api].cors_origins`](/ko/reference/configuration/)에 있어야 합니다.
