**리디렉션** 기능을 쓰면 편집자가 배포 없이 이전 경로를 새 경로로 보낼 수 있습니다. 편집자는 관리자 패널에서 목록을
관리하고, 사이트는 목록을 가져와 리디렉션으로 응답합니다. 방문자는 CMS가 아니라 여러분의 사이트에 접속하므로 Verdin이
직접 방문자를 리디렉션하지는 않습니다.

## 켜기

**설정 → 기능**에서 **리디렉션**을 켠 뒤 **리디렉션 관리**를 선택합니다(또는 **설정 → 리디렉션**으로 이동). 리디렉션을
관리하려면 기본 제공 Editor 역할이 가진 **SEO, 리디렉션, 메뉴, 폼 관리** 권한(`site.manage`)이 필요합니다.
[권한](/ko/reference/permissions/)을 참고하세요.

## 리디렉션 추가

<Steps>

1. **설정 → 리디렉션**에서 **리디렉션 추가**를 선택합니다.
2. **출발**: `/`로 시작하는 이전 경로(예: `/blog/2024/hello`).
3. **도착**: 새 경로, 또는 다른 사이트의 전체 `http(s)` URL.
4. **유형**: **301 · 영구**, **302 · 임시**, **307 · 임시(메서드 유지)**, **308 · 영구(메서드 유지)**.
5. 저장합니다.

</Steps>

Verdin은 절대 동작하지 않을 리디렉션을 거부합니다.

- 같은 경로에서 출발하는 두 번째 리디렉션.
- 자기 자신으로 리디렉션하는 경로.
- 순환하는 체인(`/a` → `/b` → `/a`).

한꺼번에 많은 리디렉션을 넣으려면 `source`, `destination`, `status` 열로 **CSV 가져오기**를 쓰세요. source가 이미
있는 행은 그 리디렉션을 수정합니다. **CSV 내보내기**는 같은 형식으로 쓰므로, 다른 CMS에서 마이그레이션하거나
스프레드시트로 검토할 때 편리합니다.

```csv title="redirects.csv"
source,destination,status
/blog/2024/hello,/blog/hello,301
/old-pricing,https://shop.example.com/pricing,302
```

## 사이트에서 적용

사이트는 토큰 없이 `GET /api/_redirects`에서 목록을 읽습니다.

```json
{
  "data": [
    { "source": "/blog/2024/hello", "destination": "/blog/hello", "status": 301 },
    { "source": "/old-pricing", "destination": "https://shop.example.com/pricing", "status": 302 }
  ]
}
```

응답은 `Cache-Control: public, max-age=60`과 함께 보내므로 변경은 약 1분 안에 사이트에 반영됩니다. 요청 경로를
`source`와 정확히 비교하세요.

<Tabs syncKey="framework">
<TabItem label="Next.js">

```js title="middleware.js"
import { NextResponse } from 'next/server';

export async function middleware(request) {
  const response = await fetch(`${process.env.VERDIN_URL}/api/_redirects`, { next: { revalidate: 60 } });
  const { data } = await response.json();
  const hit = data.find((redirect) => redirect.source === request.nextUrl.pathname);
  if (hit) return NextResponse.redirect(new URL(hit.destination, request.url), hit.status);
}
```

</TabItem>
<TabItem label="Astro">

```ts title="src/middleware.ts"
import { defineMiddleware } from 'astro:middleware';

let cache: { at: number; list: { source: string; destination: string; status: number }[] } | null = null;

export const onRequest = defineMiddleware(async (context, next) => {
  if (!cache || Date.now() - cache.at > 60_000) {
    const response = await fetch(`${import.meta.env.VERDIN_URL}/api/_redirects`);
    cache = { at: Date.now(), list: (await response.json()).data };
  }
  const hit = cache.list.find((redirect) => redirect.source === context.url.pathname);
  if (hit) return context.redirect(hit.destination, hit.status as 301 | 302 | 307 | 308);
  return next();
});
```

</TabItem>
</Tabs>

정적 사이트라면 빌드 시점에 목록을 가져와 호스트의 리디렉션 파일(Netlify의 `_redirects`, Vercel의 `vercel.json`, nginx
map)을 쓰세요. 편집자가 리디렉션을 바꾼 뒤 다시 빌드할 수 있도록 [배포 버튼](/ko/guides/integrations/deploys-and-cdn/)이나
[웹훅](/ko/guides/integrations/webhooks/)과 함께 쓰세요.

<Aside type="note">
API 접두사는 [`[api].prefix`](/ko/reference/configuration/)를 따릅니다. 기능이 꺼져 있으면 `/api/_redirects`는 `404`로
응답합니다.
</Aside>

## Admin API

관리자 패널은 관리자의 액세스 토큰과 `site.manage`로 `/admin/api/site/redirects`(`GET`, `POST`)와
`/admin/api/site/redirects/{id}`(`PUT`, `DELETE`)를 씁니다. 목록은 페이지로 나뉘며 `search`를 받습니다([목록](/ko/api/admin/#목록) 참고).
