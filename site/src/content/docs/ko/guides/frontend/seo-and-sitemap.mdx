**SEO 및 사이트맵** 기능은 각 항목이 사이트의 어디에 있는지 Verdin에 알려 줍니다. 이를 바탕으로 게시된 모든 항목의
`sitemap.xml`을 제공하고, [메뉴](/ko/guides/frontend/menus/)에 연결된 항목의 경로를 주고, 메타 태그용으로 미리 만든
`shared.seo` 컴포넌트를 제공합니다.

[리디렉션](/ko/guides/frontend/redirects/), [메뉴](/ko/guides/frontend/menus/), [폼](/ko/guides/frontend/forms/)과 함께
네 가지 사이트 기능 중 하나입니다. Strapi는 같은 영역을 커뮤니티 플러그인(SEO, sitemap)으로 다루지만, Verdin에는 기본으로
들어 있습니다.

## 켜기

<Steps>

1. **설정 → 기능**에서 **SEO 및 사이트맵**을 켭니다.
2. 카드에서 **SEO 설정**을 선택합니다.
3. **사이트 URL**을 입력합니다. `https://www.example.com` 같은 사이트의 출처이며, 사이트맵의 URL이 이것으로 시작합니다.
4. **콘텐츠 타입** 아래에서 페이지가 있는 각 타입에 **경로 패턴**을 줍니다. 패턴이 없는 타입은 사이트맵에서 빠집니다.
   선택적으로 사이트맵용 **변경 빈도**와 **우선순위**(0~1)를 설정합니다.
5. 저장한 뒤 **sitemap.xml 열기**로 결과를 확인합니다.

</Steps>

설정을 바꾸려면 **기능 관리** 권한(`features.manage`)이 필요합니다. [권한](/ko/reference/permissions/)을 참고하세요.

## 경로 패턴

패턴은 `/`로 시작하고 중괄호로 된 자리 표시자가 있는 경로입니다.

| 패턴 | 항목 | 경로 |
| --- | --- | --- |
| `/blog/{slug}` | slug가 `hello-world`인 Article | `/blog/hello-world` |
| `/{locale}/blog/{slug}` | 그 항목의 프랑스어 버전 | `/fr/blog/bonjour` |
| `/about` | Homepage 싱글 타입 | `/about` |

자리 표시자는 타입의 속성(보통 `slug` 같은 `uid`)과 `{locale}`입니다. 값은 URL 인코딩됩니다. 자리 표시자가 비어 있는
항목(예: slug가 없음)은 경로가 없으며, 사이트맵과 메뉴에서 빠집니다. 대화 상자는 넣을 수 있는 속성을 나열하고 알 수 없는
속성은 거부합니다.

설정은 기능의 설정으로 다음 형태로 저장됩니다.

```json
{
  "baseUrl": "https://www.example.com",
  "types": {
    "api::article": { "pattern": "/{locale}/blog/{slug}", "changefreq": "weekly", "priority": 0.7 },
    "api::category": { "pattern": "/{locale}/topics/{slug}" }
  }
}
```

`changefreq`는 `always`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`, `never` 중 하나입니다.

## 사이트맵

**사이트 URL**이 설정되어 있으면 Verdin은 자기 호스트의 루트(`https://cms.example.com/sitemap.xml`, API 접두사 밖)에서
`/sitemap.xml`을 제공하며, 다음을 담습니다.

- 패턴을 채우는, 설정된 타입의 모든 **게시된** 항목.
- 각 항목의 마지막 변경(`lastmod`), 그리고 타입의 `changefreq`와 `priority`.
- 로컬라이즈된 타입에서는 로케일마다 URL 하나이며, `<xhtml:link rel="alternate" hreflang="…">`로 서로 연결됩니다.
- 사이트맵 파일의 한도인 최대 50,000개의 URL.

```xml
<url>
  <loc>https://www.example.com/en/blog/hello-world</loc>
  <lastmod>2026-09-25T09:00:00.000Z</lastmod>
  <changefreq>weekly</changefreq>
  <priority>0.7</priority>
  <xhtml:link rel="alternate" hreflang="en" href="https://www.example.com/en/blog/hello-world"/>
  <xhtml:link rel="alternate" hreflang="fr" href="https://www.example.com/fr/blog/bonjour"/>
</url>
```

사이트맵은 최대 10분마다 만들어지며 `Cache-Control: public, max-age=600`과 함께 보내므로, 게시한 내용은 10분 안에
나타납니다.

검색 엔진은 사이트의 호스트에 사이트맵이 있기를 기대합니다. rewrite나 Verdin의 사이트맵을 가져오는 작은 라우트로
사이트에서 제공하세요.

```js title="Next.js: app/sitemap.xml/route.js"
export async function GET() {
  const response = await fetch('https://cms.example.com/sitemap.xml', { next: { revalidate: 600 } });
  return new Response(await response.text(), { headers: { 'content-type': 'application/xml' } });
}
```

그다음 `robots.txt`에 등록하세요: `Sitemap: https://www.example.com/sitemap.xml`.

## SEO 컴포넌트

Verdin은 Strapi의 SEO 플러그인과 같은 필드를 가진 `shared.seo` 컴포넌트를 제안합니다.

| 속성 | 타입 |
| --- | --- |
| `metaTitle` | string, 필수, 최대 60자 |
| `metaDescription` | text, 필수, 최대 160자 |
| `metaImage` | media (이미지) |
| `keywords` | text |
| `metaRobots` | string |
| `canonicalURL` | string |
| `structuredData` | JSON |

**SEO 설정** 대화 상자에서 **SEO 컴포넌트 추가**를 선택한 뒤 **컴포넌트 생성**을 선택합니다. 생성은 스키마를 바꾸므로,
이 버튼은 개발 모드(`verdin dev`)에서 **콘텐츠 타입 관리**를 가진 관리자에게만 있습니다. 그 밖의 경우 대화 상자는 대신
스키마 파일에 추가할 속성을 나열합니다. 그다음 콘텐츠 타입 빌더에서 페이지가 있는 각 콘텐츠 타입에 `shared.seo`를 쓰는
컴포넌트 필드를 추가하세요.

<Aside type="tip">
[AI 기능](/ko/guides/integrations/ai-actions/)이 켜져 있으면 `metaTitle`과 `metaDescription` 텍스트 속성을 가진
컴포넌트에 항목 내용으로 값을 채우는 **제안** 버튼이 생깁니다.
</Aside>

## 메타 태그 렌더링

컴포넌트를 populate하고 페이지의 head에 태그를 씁니다.

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
curl -g 'https://cms.example.com/api/articles?filters[slug][$eq]=hello-world&populate[seo][populate]=*'
```

</TabItem>
<TabItem label="GraphQL">

```graphql
query {
  articles(filters: { slug: { eq: "hello-world" } }) {
    title
    seo { metaTitle metaDescription metaRobots canonicalURL structuredData metaImage { url } }
  }
}
```

</TabItem>
<TabItem label="TypeScript">

```ts
const { data } = await verdin.collection('articles').find({
  filters: { slug: { $eq: 'hello-world' } },
  populate: { seo: { populate: '*' } },
});
const seo = data[0]?.seo;
```

</TabItem>
</Tabs>

```html
<title>{seo.metaTitle}</title>
<meta name="description" content="{seo.metaDescription}" />
<meta name="robots" content="{seo.metaRobots ?? 'index, follow'}" />
<link rel="canonical" href="{seo.canonicalURL ?? pageUrl}" />
<meta property="og:image" content="{cms + seo.metaImage.url}" />
<script type="application/ld+json">{JSON.stringify(seo.structuredData)}</script>
```

예제 블로그의 `shared.seo`에는 `metaTitle`과 `metaDescription`만 있고, 제안된 컴포넌트가 나머지를 추가합니다. 미리 보기
페이지가 [비주얼 에디팅](/ko/guides/frontend/visual-editing/)을 쓴다면, 메타 텍스트의 길이를 재거나 비교하기 전에 보이지
않는 표시를 제거하세요.
