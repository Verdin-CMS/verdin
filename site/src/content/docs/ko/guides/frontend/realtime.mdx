**실시간** 기능이 켜져 있으면 Verdin은 항목이나 미디어 파일이 바뀔 때마다 작은 이벤트를 스트리밍합니다. 프런트엔드는
스트림을 구독하고 바뀐 것을 다시 가져옵니다. 라이브 블로그, 점수판, 새로 고침이 필요 없는 대시보드 같은 경우입니다. 각
구독자는 자신이 읽을 수 있는 콘텐츠에 대한 이벤트만 받습니다.

이 페이지에서는 프런트엔드에서 스트림을 쓰는 방법을 보여 줍니다. 이벤트 이름, 페이로드, 규칙은
[Realtime API 레퍼런스](/ko/api/realtime/)에 있습니다. Strapi v5에는 이에 해당하는 기본 기능이 없습니다.

## 켜기

<Steps>

1. **설정 → 기능**에서 **실시간**을 켭니다.
2. 누가 구독할지 정합니다. 스트림은 콘텐츠 API의 권한을 씁니다.
   - 누구나 구독하게 하려면 **설정 → 공개 접근**에서 해당 타입에 **목록 조회** 또는 **단건 조회**를 허용합니다.
   - 서버나 앱이라면 그 권한(초안 전용 이벤트를 받으려면 **초안 읽기**도)을 가진 [API 토큰](/ko/guides/auth/api-tokens/)을
     만듭니다.
   - 로그인한 최종 사용자라면 그 JWT도 동작합니다([최종 사용자](/ko/guides/auth/end-users/) 참고).

</Steps>

스트림은 `GET /api/_events`입니다. 쉼표로 구분한 콘텐츠 타입 uid 목록을 `?types=`로 추가하면 그 타입의 이벤트만
받습니다(`plugin::upload`는 미디어 라이브러리).

```sh title="Terminal"
curl -N "https://cms.example.com/api/_events?types=api::article,api::category"
```

```
event: ready
data: {}

event: entry.publish
data: {"event":"entry.publish","uid":"api::article","documentId":"01j9…","locale":"en"}
```

## 브라우저에서 구독

이벤트에는 콘텐츠가 아니라 id가 담깁니다. 이벤트마다 보여 주는 것을 다른 읽기와 같은 API와 권한으로 다시 가져오세요.

<Tabs syncKey="auth">
<TabItem label="공개">

공개 역할이라면 브라우저의 `EventSource`로 충분하며, 스스로 다시 연결합니다.

```js
const CMS = 'https://cms.example.com';
const events = new EventSource(`${CMS}/api/_events?types=api::article`);

for (const name of ['entry.publish', 'entry.unpublish', 'entry.delete']) {
  events.addEventListener(name, (event) => {
    const { documentId } = JSON.parse(event.data);
    refreshArticle(documentId);
  });
}

events.addEventListener('lagged', () => refreshEverything());
```

</TabItem>
<TabItem label="토큰 사용">

`EventSource`는 `Authorization` 헤더를 보낼 수 없습니다. 대신 `fetch`로 스트림을 읽고, 끝나면 다시 연결하세요.

```js
async function subscribe(token, onEvent) {
  for (;;) {
    try {
      const response = await fetch(`${CMS}/api/_events?types=api::article`, {
        headers: { authorization: `Bearer ${token}` },
      });
      if (response.status === 401 || response.status === 403) return; // token refused
      const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
      let buffer = '';
      for (;;) {
        const { value, done } = await reader.read();
        if (done) break;
        buffer += value;
        let end;
        while ((end = buffer.indexOf('\n\n')) >= 0) {
          const block = buffer.slice(0, end);
          buffer = buffer.slice(end + 2);
          const name = block.match(/^event: (.*)$/m)?.[1];
          const data = block.match(/^data: (.*)$/m)?.[1];
          if (name && data) onEvent(name, JSON.parse(data));
        }
      }
    } catch {
      // network error: retry below
    }
    await new Promise((resolve) => setTimeout(resolve, 2000));
  }
}
```

헤더를 지원하는 SSE 클라이언트 라이브러리라면 무엇이든 동작합니다.

</TabItem>
</Tabs>

<Aside type="caution">
브라우저 코드에 있는 토큰은 페이지를 여는 누구나 읽을 수 있습니다. 페이지가 보여 주는 타입으로 범위를 제한한 읽기 전용
토큰만 배포하거나, 서버에서 구독하고 업데이트를 브라우저로 전달하세요.
</Aside>

다른 출처의 사이트에서 스트림을 호출하려면 그 출처가 [`[api].cors_origins`](/ko/reference/configuration/)에 있어야
합니다.

## 스트림을 건강하게 유지하기

- 첫 이벤트는 `ready`이며, 구독이 활성화되었다는 뜻입니다.
- 스트림은 1시간 뒤에 끝납니다. 그때 다시 연결하세요. `EventSource`는 자동으로 하며, 다시 연결할 때 토큰도 다시
  확인하므로 취소된 토큰은 이벤트를 더 받지 못합니다.
- `lagged` 이벤트는 클라이언트가 너무 느리게 읽어서 이벤트를 놓쳤다는 뜻입니다. 페이지가 보여 주는 것을 전부 다시
  가져오세요.
- 초안 전용 이벤트(초안과 게시를 쓰는 타입의 `entry.create`, `entry.update`, `entry.discard-draft`)는 **초안 읽기**를
  가진 호출자에게만 갑니다. 공개 사이트는 보통 `entry.publish`, `entry.unpublish`, `entry.delete`를 듣습니다.

## 로드 밸런서 뒤에서

인스턴스가 여러 개면 공유 이벤트 버스(`[cluster].bus = "database"`)를 켜세요. 그러면 어느 인스턴스에 연결된
클라이언트든 모든 인스턴스의 이벤트를 받습니다. 버스가 없으면 이벤트는 클라이언트가 연결된 인스턴스의 것입니다.
`/api/_events`에 sticky 세션을 쓰거나, 실시간 클라이언트를 인스턴스 하나로 보내세요.
[확장](/ko/deploy/scaling/#공유-이벤트-버스)을 참고하세요.

관리자 패널은 편집 중 실시간 업데이트, 프레즌스, 소프트 잠금을 위해 자체 스트림(`/admin/api/events`)을 씁니다.
[Realtime API 레퍼런스](/ko/api/realtime/)를 참고하세요.
