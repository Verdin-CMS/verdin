Verdin 프로젝트는 설정 파일과 스키마가 있는 디렉터리입니다. 이 페이지에서는 `verdin new`가 만드는 것, 서버가 실행되면서
추가하는 것, 커밋할 것을 나열합니다.

## `verdin new`가 만드는 것

```sh title="Terminal"
verdin new my-site
```

<FileTree>
- my-site/
  - verdin.toml 프로젝트 설정
  - .env 시크릿과 데이터베이스 URL, 본인만 읽을 수 있음
  - .gitignore
  - schema/
    - content-types/ 콘텐츠 타입마다 JSON 파일 하나
    - components/ 컴포넌트 범주마다 폴더 하나
  - data/ SQLite 데이터베이스(`--database sqlite`일 때만)
</FileTree>

디렉터리는 존재하지 않거나 비어 있어야 합니다. 데이터베이스 URL의 프로젝트 이름은 디렉터리 이름을 소문자로 바꾸고 그 밖의
문자를 `_`로 바꾼 것입니다(`My Site`는 `my_site`가 됨).

### `verdin.toml`

설정입니다. 생성된 파일은 포트, 콘텐츠 API 접두사와 페이지 크기, 관리자 경로를 설정합니다.

```toml title="verdin.toml"
[server]
port = 1337
# public_url = "https://cms.example.com"

[api]
prefix = "/api"
default_page_size = 25
max_page_size = 100

[admin]
path = "/admin"
# secure_cookies = true
```

모든 키에 기본값이 있으므로 파일이 비어 있거나 없어도 됩니다. 알 수 없는 키가 있으면 서버가 오류와 함께 멈춥니다. 모든 키는
환경 변수 `VERDIN_<SECTION>__<KEY>`로 재정의할 수 있습니다. 예: `VERDIN_SERVER__PORT=8080`. 명령은 현재 디렉터리의
`verdin.toml`을 읽습니다. 다른 파일을 쓰려면 `-c <path>`를 넘기거나 `VERDIN_CONFIG`를 설정하세요. 스키마나 업로드
디렉터리 같은 파일 안의 경로는 파일이 있는 디렉터리 기준입니다. 모든 설정은 [설정 레퍼런스](/ko/reference/configuration/)에
있습니다.

### `.env`

```sh title=".env"
# 로컬 시크릿: 이 파일은 버전 관리에서 제외하세요.
VERDIN_DATABASE_URL=sqlite://data/verdin.db
VERDIN_ADMIN_JWT_SECRET=…
VERDIN_TOKEN_PEPPER=…
```

`verdin new`는 무작위 시크릿 두 개와, `--database`로 고른 엔진용 데이터베이스 URL을 채웁니다.

| `--database` | 생성되는 `VERDIN_DATABASE_URL` |
| --- | --- |
| `sqlite` (기본값) | `sqlite://data/verdin.db` |
| `postgres` | `postgres://verdin:change-me@localhost:5432/<name>` |
| `mysql`, `mariadb` | `mysql://verdin:change-me@localhost:3306/<name>` |

PostgreSQL, MySQL, MariaDB에서는 사용자와 비밀번호를 바꾸세요. 상대 SQLite 경로는 명령을 실행한 디렉터리가 아니라 프로젝트
디렉터리 기준으로 해석합니다.

모든 명령은 `verdin.toml` 옆의 `.env`를 로드하며, 이미 환경에 설정된 변수가 우선합니다. Linux와 macOS에서 파일은 소유자만
읽을 수 있게 만들어집니다. 프로덕션에서는 `.env` 파일을 배포하지 말고 플랫폼의 시크릿 저장소에 이 변수들을 설정하세요.
[빠른 시작](/ko/start/quickstart/#2-시크릿)에서 두 시크릿을 설명합니다.

### `schema/`

Strapi의 스키마 형식으로 된 콘텐츠 모델입니다.

- `schema/content-types/<singularName>.json`: 컬렉션 타입이나 싱글 타입마다 파일 하나.
- `schema/components/<category>/<name>.json`: 컴포넌트마다 파일 하나. 컴포넌트의 uid는 `<category>.<name>`입니다.

콘텐츠 타입 빌더가 `verdin dev`에서 이 파일들을 쓰며, 직접 편집할 수도 있습니다. `verdin dev`는 파일이 바뀌면 다시
로드합니다. 예제 블로그의 스키마는 다음과 같습니다.

<FileTree>
- schema/
  - content-types/
    - article.json
    - category.json
    - homepage.json 싱글 타입
    - tag.json
  - components/
    - blocks/
      - hero.json `blocks.hero`
      - quote.json `blocks.quote`
    - shared/
      - seo.json `shared.seo`
</FileTree>

파일이 진실의 원천입니다. Verdin은 여기서 데이터베이스 테이블, 검증, REST와 GraphQL API, OpenAPI 문서, TypeScript 타입,
관리자 폼을 도출합니다. [콘텐츠 모델](/ko/concepts/content-model/)과 [스키마 마이그레이션](/ko/concepts/schema-migrations/)을
참고하세요. 스키마 디렉터리는 `verdin.toml`의 `[schema].path`이며 기본값은 `schema`입니다.

## Verdin이 실행되면 생기는 것

<FileTree>
- my-site/
  - verdin.toml
  - .env
  - schema/
  - data/
    - verdin.db SQLite 데이터베이스와 그 `-wal`, `-shm` 파일
    - search/ `[search].enabled`가 켜져 있을 때의 전문 검색 인덱스
  - public/
    - uploads/ `/uploads`에서 제공하는 미디어 라이브러리 파일
  - .cache/
    - transforms/ 크기를 조정한 이미지, 필요할 때 다시 만듦
  - plugins/ WebAssembly 플러그인, 플러그인마다 폴더 하나(직접 만듦)
  - strapi-id-map.json `verdin import strapi`가 씀
</FileTree>

| 경로 | 쓰는 주체 | 설정 |
| --- | --- | --- |
| `data/verdin.db` | SQLite를 쓰는 서버 | `VERDIN_DATABASE_URL` |
| `public/uploads/` | 로컬 프로바이더(기본값)로 한 업로드 | `[upload].provider` |
| `.cache/transforms/` | `/uploads`에서 요청한 이미지 변환 | `[upload.transforms].cache_dir` |
| `data/search/` | 전문 검색 인덱스 | `[search].dir` |
| `plugins/` | 여러분: 플러그인마다 자체 폴더 | `[plugins].path` |
| `strapi-id-map.json` | `verdin import strapi`: Strapi id를 Verdin id에 매핑 | — |

PostgreSQL, MySQL, MariaDB에서는 `data/verdin.db`가 없습니다. 콘텐츠는 데이터베이스 서버에 있습니다. S3 프로바이더에서는
미디어 파일이 버킷에 있고 `public/uploads`는 비어 있습니다.

## git에 넣을 것

| 커밋할 것 | git에서 제외할 것 |
| --- | --- |
| `verdin.toml` | `.env`(시크릿) |
| `schema/`(콘텐츠 타입과 컴포넌트) | `data/`(SQLite 데이터베이스, 검색 인덱스) |
| 플러그인을 쓴다면 `plugins/` | `public/uploads/`(미디어) |
| `.gitignore` | `.cache/` |

생성된 `.gitignore`가 모두 다룹니다.

```sh title=".gitignore"
.env
data/
*.db
*.db-*
.cache/
# Local media library ([upload.provider] dir).
public/uploads/
```

0.10 전에 만든 프로젝트에는 `public/uploads/` 줄이 없습니다. 추가하세요.

<Aside>
콘텐츠와 미디어는 코드가 아니라 데이터입니다. 커밋하지 말고 `verdin export`나 데이터베이스 자체 도구로 백업하세요.
[백업](/ko/deploy/backups/)을 참고하세요.
</Aside>

스키마는 프런트엔드의 생성된 타입처럼 스키마에 의존하는 코드와 함께 커밋하세요. 프로덕션에서는 커밋한 스키마를 배포하고
`verdin start --migrate`를 실행하세요. 콘텐츠 타입 빌더는 `verdin dev` 밖에서는 꺼져 있으므로 스키마는 저장소를 통해서만
바뀝니다.
