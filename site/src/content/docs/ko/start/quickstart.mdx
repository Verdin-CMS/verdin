import { Aside, Steps, Tabs, TabItem } from '@astrojs/starlight/components';

이 페이지에서는 약 10분 만에 아무것도 없는 상태에서 첫 API 응답까지 갑니다. Verdin을 시작하고, 첫 관리자를 만들고, 콘텐츠
타입을 모델링하고, 공개로 열고, REST, GraphQL, TypeScript 클라이언트로 읽습니다.

[Docker](https://docs.docker.com/get-docker/)나 `verdin` 바이너리를 실행할 수 있는 컴퓨터(x86-64의 Linux, macOS, Windows,
ARM64의 Linux, macOS)가 필요합니다.

## 1. Verdin 시작

<Tabs syncKey="install">
  <TabItem label="Docker">

시크릿을 한 번 생성한 뒤 개발 모드로 이미지를 시작합니다.

```sh title="Terminal"
docker run --rm ghcr.io/verdin-cms/verdin secrets > verdin.env
docker run -p 1337:1337 --env-file verdin.env -v verdin-data:/data ghcr.io/verdin-cms/verdin dev
```

`verdin-data` 볼륨에는 SQLite 데이터베이스(`/data/verdin.db`), 업로드한 미디어(`/data/uploads`), 그리고 `dev`에서는 콘텐츠
타입 빌더가 쓰는 스키마 파일(`/data/schema`)이 들어 있습니다.

  </TabItem>
  <TabItem label="Binary">

[릴리스 페이지](https://github.com/Verdin-CMS/verdin/releases)에서 플랫폼용 아카이브를 내려받아 압축을 풀고 `verdin`을
`PATH`에 두세요. 관리자 패널은 바이너리에 내장되어 있습니다.

프로젝트를 만들고 개발 모드로 시작합니다.

```sh title="Terminal"
verdin new my-site            # verdin.toml, schema/, 새 시크릿이 담긴 .env, SQLite
cd my-site
verdin dev
```

`verdin new`는 생성되는 `.env`가 가리킬 데이터베이스를 고르는 `--database sqlite|postgres|mysql|mariadb`(기본값 SQLite)를
받습니다. PostgreSQL, MySQL, MariaDB라면 `verdin dev`를 실행하기 전에 `.env`의 `VERDIN_DATABASE_URL`을 서버에 맞게
편집하세요. [프로젝트 구조](/ko/start/project-structure/)에서 만들어지는 모든 파일을 설명합니다.

  </TabItem>
</Tabs>

로그에 `verdin listening`이 나오면 서버가 포트 1337에서 응답합니다. 처음 시작할 때 데이터베이스 테이블이 만들어집니다.

## 2. 시크릿

Verdin에는 각각 최소 32바이트인 시크릿 두 개가 필요합니다.

| 변수 | 보호하는 것 |
| --- | --- |
| `VERDIN_ADMIN_JWT_SECRET` | 관리자 세션에 서명합니다. |
| `VERDIN_TOKEN_PEPPER` | API 토큰을 해싱하고 2단계 인증 시크릿과 복구 코드를 보호합니다. |

`verdin secrets`는 새 값을 출력하고, `verdin new`는 이를 `.env`에 씁니다. 시크릿은 `verdin.toml`이 아니라 환경 변수에서만
오며, 없으면 서버가 시작하지 않습니다. `verdin.toml` 옆의 `.env` 파일은 시작할 때 로드되며, 이미 환경에 설정된 변수가
우선합니다.

<Aside type="caution">
시크릿은 설치마다 한 번 생성하고 유지하세요. `VERDIN_ADMIN_JWT_SECRET`이 새로 바뀌면 현재 로그인 토큰, 열린 미리 보기 링크,
진행 중인 OAuth 로그인이 무효가 됩니다(관리자 패널은 스스로 세션을 갱신합니다). `VERDIN_TOKEN_PEPPER`가 새로 바뀌면 모든 API
토큰과 모든 2단계 인증 설정이 무효가 됩니다. `.env`와 `verdin.env`는 버전 관리에서 제외하세요.
</Aside>

## 3. 첫 관리자 만들기

[http://localhost:1337/admin/](http://localhost:1337/admin/)을 엽니다. 관리자가 없는 동안 관리자 패널은
**Verdin에 오신 것을 환영합니다**를 보여 줍니다. 이름, 이메일, 8자 이상의 비밀번호를 입력하고 **계정 만들기**를 선택하세요.
이 첫 계정은 모든 권한을 가진 Super Admin입니다.

명령줄에서도 관리자를 만들 수 있습니다. [명령줄에서 관리자 사용자 만들기](#명령줄에서-관리자-사용자-만들기)를 참고하세요.

## 4. 콘텐츠 타입 모델링

<Steps>

1. 사이드바에서 **콘텐츠 타입 빌더**를 열고 **새 콘텐츠 타입**을 선택합니다.
2. **표시 이름**을 `Article`로 설정합니다. Verdin이 <strong>단수형 이름 (API ID)</strong>을 `article`로, <strong>복수형 이름 (경로)</strong>을
   `articles`로 채웁니다. 경로는 API에서 이 타입의 URL입니다. **종류**는 **컬렉션**으로 둡니다.
3. **필드 추가**를 선택하고 **짧은 텍스트**를 고르고, 이름을 `title`로 한 뒤 **완료**를 선택합니다.
4. **저장**을 선택합니다. **마이그레이션 검토**가 데이터베이스 단계를 SQL과 함께 나열합니다. **적용**을 선택하세요.

</Steps>

Verdin이 타입을 `schema/content-types/article.json`에 쓰고 테이블을 만듭니다. 빌더는 `verdin dev`에서만 쓸 수 있으며,
프로덕션에서 스키마는 파일에서 옵니다. 필드 타입과 옵션은 [콘텐츠 모델](/ko/concepts/content-model/)을 참고하세요.

이제 항목을 추가하세요. **컬렉션** 아래의 **Article**을 열고, **새 항목**을 선택하고, 제목을 채운 뒤 **게시**를 선택합니다.
새 타입은 **초안 및 게시**가 켜져 있으므로, 항목은 게시될 때까지 공개 API에 보이지 않는 초안으로 남습니다.

## 5. 공개로 열기

콘텐츠 API는 공개 권한을 허용하거나 API 토큰을 만들기 전까지 닫혀 있습니다. **설정 → 공개 접근**을 열고 **Article**에 대해
**목록 조회**와 **단건 조회**를 허용한 뒤 **저장**을 선택하세요.

공개 접근 없이 읽으려면 **설정 → API 토큰**에서 토큰을 만들고 `Authorization: Bearer <token>`으로 보내세요.
[API 토큰](/ko/guides/auth/api-tokens/)과 [권한](/ko/concepts/permissions/)을 참고하세요.

## 6. 첫 요청 보내기

<Tabs syncKey="api">
  <TabItem label="REST">

```sh title="Terminal"
curl localhost:1337/api/articles
```

```json
{
  "data": [
    {
      "id": 2,
      "documentId": "01m3p88agn712n02wb8kkpe94p",
      "title": "Hello Verdin",
      "createdAt": "2026-09-29T09:34:39.637Z",
      "updatedAt": "2026-09-29T09:34:39.637Z",
      "publishedAt": "2026-09-29T09:34:39.637Z"
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 25, "pageCount": 1, "total": 1 } }
}
```

응답은 Strapi v5의 평평한 형태입니다. 필터, 정렬, 페이지네이션, `populate`는 같은 쿼리 파라미터를 씁니다.
[REST API](/ko/api/rest/)를 참고하세요.

  </TabItem>
  <TabItem label="GraphQL">

**설정 → 기능 → GraphQL**을 켭니다. 그러면 `POST /graphql`이 REST API와 같은 권한으로, 콘텐츠 타입에서 생성한 스키마를
제공합니다.

```sh title="Terminal"
curl localhost:1337/graphql -H 'content-type: application/json' \
  -d '{"query":"{ articles { documentId title } }"}'
```

```json
{ "data": { "articles": [{ "documentId": "01m3p88agn712n02wb8kkpe94p", "title": "Hello Verdin" }] } }
```

[GraphQL API](/ko/api/graphql/)를 참고하세요.

  </TabItem>
  <TabItem label="TypeScript">

스키마로 타입을 생성하고 프런트엔드 프로젝트에 클라이언트를 설치합니다.

```sh title="Terminal"
verdin types -o src/verdin-types.ts   # Verdin 프로젝트에서
npm install @verdin/client            # 프런트엔드 프로젝트에서
```

Docker에서는 이미지가 볼륨의 스키마로 타입을 출력할 수 있습니다:
`docker run --rm -v verdin-data:/data ghcr.io/verdin-cms/verdin types > src/verdin-types.ts`.

```ts title="src/articles.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from './verdin-types';

const verdin = createClient<VerdinSchema>({ url: 'http://localhost:1337' });

const { data } = await verdin.collection('articles').find({ sort: ['publishedAt:desc'] });
console.log(data.map((article) => article.title));
```

[타입 클라이언트](/ko/guides/frontend/typed-client/)를 참고하세요.

  </TabItem>
</Tabs>

여기서부터 [Astro](/ko/start/tutorial-astro/)와 [Next.js](/ko/start/tutorial-nextjs/) 튜토리얼이 같은 API로 블로그
프런트엔드를 만듭니다.

## 개발 모드와 프로덕션 모드

| 명령 | 용도 |
| --- | --- |
| `verdin dev` | 개발: safe 마이그레이션이 자동으로 적용되고, 콘텐츠 타입 빌더가 스키마 파일을 편집할 수 있으며, 파일이 바뀌면 서버가 다시 로드합니다. |
| `verdin start` | 프로덕션. 데이터베이스가 스키마보다 뒤처져 있으면 실행을 거부합니다. |
| `verdin start --migrate` | 프로덕션. 시작하기 전에 대기 중인 safe 마이그레이션을 적용합니다. Docker 이미지의 기본 명령입니다. |

리프레시 쿠키는 `verdin start`에서는 `Secure`이고 `verdin dev`에서는 아니므로, `start` 서버에 로그인하려면 HTTPS가
필요합니다. 일반 HTTP로 `start`를 시험하려면 `VERDIN_ADMIN__SECURE_COOKIES=false`를 설정하세요.

프로덕션에서는 스키마를 버전 관리에 두고 읽기 전용으로 마운트하세요. Docker에서는 다음과 같습니다.

```sh title="Terminal"
docker run -p 1337:1337 --env-file verdin.env \
  -e VERDIN_DATABASE_URL=postgres://user:pass@db:5432/verdin \
  -v ./schema:/data/schema:ro ghcr.io/verdin-cms/verdin
```

나머지는 [프로덕션 체크리스트](/ko/deploy/production-checklist/)에서 다룹니다.

## 스키마와 마이그레이션

콘텐츠 타입은 `schema/content-types/<singularName>.json`에, 컴포넌트는 `schema/components/<category>/<name>.json`에 Strapi
형식으로 있습니다. 파일이 바뀌면 Verdin이 마이그레이션을 계획합니다.

```sh title="Terminal"
verdin schema check                      # 모든 스키마 파일 검증
verdin migrate plan                      # 단계, 위험 수준, 정확한 SQL
verdin migrate apply                     # safe 단계만
verdin migrate apply --allow risky       # 타입 변경과 새 고유 제약 조건도
verdin migrate apply --allow destructive # 컬럼과 테이블 삭제도
verdin migrate apply --rename-column articles.title=headline --rename-table posts=articles
```

트랜잭션 DDL이 없는 MySQL과 MariaDB에서는 중단된 마이그레이션이 다음 `migrate apply`에서 실패한 단계부터 재개됩니다.
[스키마 마이그레이션](/ko/concepts/schema-migrations/)을 참고하세요.

## 명령줄에서 관리자 사용자 만들기

```sh title="Terminal"
verdin admin create --email other@example.com      # 비밀번호는 VERDIN_ADMIN_PASSWORD나 stdin에서
verdin admin reset-password --email you@example.com
```

`admin create`는 Super Admin을 만듭니다. `reset-password`는 계정 잠금도 풀고 세션을 끝냅니다. 둘 다 데이터베이스가
스키마와 맞는 최신 상태여야 합니다.

## 그 밖의 명령

| 명령 | 하는 일 |
| --- | --- |
| `verdin types -o src/verdin-types.ts` | 콘텐츠 API의 TypeScript 정의를 씁니다(`-o`가 없으면 표준 출력). |
| `verdin import strapi <export>` | Strapi 프로젝트를 가져옵니다. [Strapi에서 가져오기](/ko/migrate/from-strapi/)를 참고하세요. |
| `verdin export <file.tar.gz>` | 스키마, 콘텐츠, 미디어를 아카이브로 씁니다. `verdin import verdin`이 다시 읽습니다. |
| `verdin version` | 버전을 출력합니다. |

모든 명령은 `-c, --config <path>`(기본값 `verdin.toml`, 또는 `VERDIN_CONFIG`)를 받습니다. [CLI 레퍼런스](/ko/reference/cli/)에
모든 명령과 플래그가, [설정 레퍼런스](/ko/reference/configuration/)에 모든 설정이 있습니다.

## 헬스 체크

`GET /_health`는 프로세스가 살아 있는 동안 응답합니다. `GET /_ready`는 데이터베이스도 확인하며, 연결할 수 없으면 503으로
응답합니다. 로드 밸런서는 이것을 보게 하세요([확장](/ko/deploy/scaling/) 참고).
