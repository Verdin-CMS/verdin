플러그인은 서버를 바꾸거나 다시 빌드하지 않고 Verdin에 동작을 더합니다. 플러그인은 매니페스트를 가진
WebAssembly 모듈이며, 프로젝트의 `plugins/` 디렉터리에 넣습니다. 이 페이지에서는 플러그인이 할 수 있는 일과
설치 방법을 설명합니다. 직접 작성하려면 [플러그인 튜토리얼](/ko/extending/plugin-tutorial/)을 따라 하고, 세부
사항은 [플러그인 레퍼런스](/ko/extending/plugin-reference/)에서 찾아보세요.

## 플러그인이 할 수 있는 일

| 확장 지점 | 용도 |
| --- | --- |
| **쓰기 훅** | 항목을 생성, 수정, 게시, 게시 취소, 삭제하거나 초안을 폐기하기 전에 데이터를 바꾸거나 메시지와 함께 쓰기를 거부합니다. 쓰기 후에는 이에 반응합니다(로그, 알림, 동기화). |
| **라우트** | `/api/plugins/<name>/…` 아래에 HTTP 엔드포인트를 제공합니다: 웹훅 수신기, 계산된 피드, 다른 서비스로 가는 프록시. |
| **예약 작업** | cron 일정(UTC)에 따라 함수를 실행합니다. |
| **GraphQL 필드** | `Query`나 `Mutation`에 `name(args: JSON): JSON` 필드를 추가합니다. |
| **대시보드 위젯** | Web Components로 관리자 대시보드에 위젯 타입을 추가합니다. |
| **사용자 정의 필드** | Web Components로 관리자 패널에서 속성에 사용자 정의 편집기(색상 선택기, 지도)를 제공합니다. 값은 일반 속성 타입으로 저장됩니다. |
| **설정** | 관리자가 **설정 → 플러그인**에서 채우는 설정 폼을 선언합니다. |

플러그인은 관리자 패널과 API와 같은 Document Service로 콘텐츠를 읽고 쓰므로, 웹훅, 기록, 검토 단계, 검증이
플러그인의 쓰기에도 적용됩니다.

<Aside type="note">
Verdin 플러그인은 Strapi 플러그인이 아닙니다. Strapi 플러그인은 서버에 완전히 접근하는 Node.js 패키지이지만,
Verdin은 서버에서 JavaScript를 실행하지 않습니다. Strapi 스키마가 선언한 사용자 정의 필드(`customField` 속성)는
그대로 로드되며, Verdin 플러그인이 그 편집기를 제공할 수 있습니다.
</Aside>

## 샌드박스

플러그인은 WebAssembly 샌드박스([Extism](https://extism.org), Wasmtime 기반)에서 실행됩니다. 모듈에는 자체 파일,
소켓, 데이터베이스 연결이 없습니다. 자기 메모리 밖에서 하는 모든 일은 몇 가지 호스트 함수를 거치며, 서버는 각
호출을 매니페스트가 선언한 **기능**(capabilities)과 대조해 확인합니다.

| 기능 | 허용하는 것 |
| --- | --- |
| `read` | 나열한 콘텐츠 타입(또는 `*`)의 항목 읽기. |
| `write` | 나열한 타입의 항목 생성, 수정, 게시, 게시 취소, 삭제(읽기 포함). |
| `http` | 나열한 호스트(`api.example.com`, `*.example.com`)로 HTTP 요청. |
| `kv` | Verdin 데이터베이스 안의 자체 키-값 저장소. |

각 호출에는 한도도 있습니다. 시간 한도(기본 5초)와 메모리 한도(기본 64 MB)이며, 매니페스트에서 설정합니다.
트랩이 발생하거나 시간을 초과한 모듈은 그 호출만 실패하며, Verdin은 다음 호출에서 모듈을 다시 만듭니다.

샌드박스가 대신 결정해 주지 않는 것:

- **라우트는 공개입니다.** `/api/plugins/<name>/…`에 대한 요청은 **공개 접근**이나 API 토큰 권한으로 확인하지
  않습니다. 플러그인은 호출자가 누구인지(누구나, API 토큰, 최종 사용자) 전달받으며 직접 확인해야 합니다.
- **훅은 플러그인의 `read` 기능과 상관없이** 해당 타입에 대한 모든 쓰기를 봅니다.
- **실패한 before 훅은 쓰기를 막지 않습니다.** 모듈이 충돌하거나 시간을 초과하면 오류가 로그에 남고 쓰기가
  진행됩니다. 명시적으로 거부할 때만 멈춥니다.

## 플러그인 설치

<Steps>

1. `verdin.toml` 옆의 `plugins/` 아래에 플러그인 전용 디렉터리를 두고 플러그인을 넣습니다. 매니페스트, 모듈,
   그리고 선택적으로 관리자 패널 파일을 담습니다.

   <FileTree>
   - verdin.toml
   - plugins/
     - reading-time/
       - plugin.toml
       - plugin.wasm
       - admin/ 선택 사항: 관리자 패널용 Web Components
         - index.js
   - schema/
   </FileTree>

2. Verdin을 재시작합니다. 시작할 때 모든 `plugins/*/plugin.toml`을 로드하고 각각에 대해 `plugin found`를 로그에
   남깁니다. 로드에 실패한 플러그인(잘못된 매니페스트, 없는 모듈, 중복 이름)은 이유와 함께
   **설정 → 플러그인**에 나열됩니다.

3. 관리자 패널에서 **설정 → 플러그인**을 엽니다. **접근 권한**, **훅**, **라우트**, **작업** 아래에서 플러그인이
   요청하는 것을 검토한 뒤 켜세요.

4. 플러그인에 설정이 있으면 카드에서 **설정**을 열고, 값을 채우고, 저장합니다.

</Steps>

설치한 플러그인은 꺼진 상태로 시작합니다. 플러그인을 켜고 끄거나 설정을 편집하면 모든 인스턴스에서 즉시
적용됩니다(다른 인스턴스는 `[server].sync_interval_secs` 안에 변경을 가져갑니다). `plugin.toml`이나 모듈을
바꾸면 재시작이 필요합니다.

플러그인을 관리하려면 `plugins.manage` 권한(**플러그인 관리**)이 필요합니다.
[권한 레퍼런스](/ko/reference/permissions/)를 참고하세요.

## `[plugins]` 설정

```toml title="verdin.toml"
[plugins]
path = "plugins"   # directory of plugins, relative to verdin.toml
run_jobs = true    # run scheduled jobs on this instance
```

인스턴스가 여러 개면 하나를 뺀 모든 인스턴스에 `run_jobs = false`를 설정해 각 작업이 한 번만 실행되게 하세요.
[설정 레퍼런스](/ko/reference/configuration/)를 참고하세요.

## 운영

- **한 번에 호출 하나.** 각 플러그인은 인스턴스 하나를 가지고 한 번에 호출 하나를 처리하므로, 느린 라우트는 그
  플러그인의 훅을 지연시킵니다. 함수는 짧게 유지하세요.
- **로그.** 플러그인이 남기는 로그는 서버 로그와 **설정 → 플러그인 → 로그**(최근 200줄, 메모리에 보관)로
  갑니다.
- **배포.** 스키마처럼 플러그인도 프로젝트와 함께(이미지나 볼륨에) 배포하세요. 스위치와 설정은 데이터베이스에
  있습니다.
