Двофакторна автентифікація додає другий крок після пароля: 6-значний код із
застосунку-автентифікатора або ключ доступу (passkey: відбиток пальця, обличчя, блокування
екрана чи апаратний ключ). У цьому посібнику ви налаштуєте обидва способи, зробите їх
обов'язковими для ролі й дізнаєтеся, що робити, коли адміністратор їх втратив. У Strapi
вбудованого відповідника немає.

Двофакторна автентифікація призначена для адміністраторів. [Кінцеві користувачі](/uk/guides/auth/end-users/)
входять за паролем або через провайдера OAuth.

## Перш ніж почати

- Нічого вмикати не треба: кожен адміністратор може налаштувати другий фактор у своєму профілі.
- Ключі доступу прив'язані до адреси адмін-панелі. Задайте `[server].public_url` — адресу, яку
  відкривають адміністратори, наприклад `https://cms.example.com`. Браузери пропонують ключі
  доступу лише через `https://` (і на `localhost`).
- Не змінюйте `VERDIN_TOKEN_PEPPER`: ним захищено секрети автентифікаторів і коди
  відновлення, і його зміна робить їх непридатними.

## Налаштуйте застосунок-автентифікатор

<Steps>

1. Відкрийте свій **Профіль** і знайдіть **Двофакторна автентифікація**.
2. У розділі **Застосунок-автентифікатор** виберіть **Налаштувати** й підтвердьте пароль.
3. Відскануйте QR-код застосунком на кшталт 1Password, Google Authenticator чи Authy. Якщо
   відсканувати не вдається, введіть ключ налаштування, показаний під ним.
4. Введіть **6-значний код**, який показує застосунок, і виберіть **Увімкнути**.
5. Збережіть **Коди відновлення**, які показує Verdin: **Завантажити** їх або скопіюйте, а
   потім виберіть **Коди збережено**.

</Steps>

Коди відповідають стандартній схемі TOTP (кроки по 30 секунд, SHA-1, 6 цифр). Код із
попереднього чи наступного кроку теж приймається, щоб урахувати розбіжність годинників. Якщо
коди відхиляються, перевірте час на своєму пристрої.

## Додайте ключ доступу

<Steps>

1. У розділі **Ключі доступу** виберіть **Додати ключ доступу**.
2. Дайте йому **Назва**, наприклад «MacBook Touch ID», і підтвердьте пароль.
3. Дотримуйтеся підказки браузера.

</Steps>

Можна зареєструвати до 20 ключів доступу й видаляти їх через **Видалити**. Ключі доступу — це
другий фактор після пароля, а не його заміна.

## Коди відновлення

Під час налаштування першого фактора ви отримуєте 10 кодів відновлення. Кожен дає змогу один
раз увійти, якщо ви втратили застосунок чи ключі доступу. Профіль показує, скільки їх
лишилося; **Створити нові коди** замінює їх усі (старі перестають працювати).

<Aside type="caution">
Коди показуються один раз. Зберігайте їх у менеджері паролів або десь офлайн, а не поруч із
пристроєм, на якому ваш автентифікатор.
</Aside>

Після пароля сторінка входу просить **Код автентифікації**. Виберіть **Використати ключ
доступу** або **Використати код відновлення**, щоб змінити спосіб. На завершення є 5 хвилин;
після цього введіть пароль знову.

## Вимагайте двофакторну автентифікацію для ролі

<Steps>

1. Відкрийте **Налаштування → Ролі** і потрібну роль.
2. Увімкніть **Вимагати двофакторну автентифікацію** і збережіть.

</Steps>

Учасників без другого фактора під час входу просять його налаштувати. Доки вони цього не
зроблять, їм доступний лише профіль. У **Налаштування → Користувачі** їхній рядок показує
**Немає 2FA**; адміністратори з другим фактором показуються з **2FA**.

Поки ваша роль вимагає другого фактора, Verdin не дає видалити останній: додайте ключ доступу,
перш ніж вимикати застосунок, або інший фактор, перш ніж видаляти єдиний ключ доступу.

## Скидання другого фактора іншого адміністратора

Коли адміністратор втратив пристрій і коди відновлення:

<Steps>

1. Відкрийте **Налаштування → Користувачі** і знайдіть адміністратора.
2. Виберіть **Скинути двофакторну автентифікацію** і підтвердьте.

</Steps>

Це видаляє його застосунок-автентифікатор, ключі доступу й коди відновлення, тож він входить
лише за паролем. Якщо його роль вимагає двофакторної автентифікації, він має налаштувати її
знову. Для цього потрібен **Керування користувачами**; лише Super Admin може скинути іншого
Super Admin.

`verdin admin reset-password` скидає лише пароль, а не другий фактор.

## Єдиний вхід

В адміністраторів, які входять через [єдиний вхід](/uk/guides/auth/sso/), теж запитують другий
фактор Verdin, якщо провайдер не позначено як **Провайдер вимагає MFA**.

## Admin API

Усі маршрути розташовані під `/admin/api`. Ті, що змінюють фактори, приймають ваш `password`.

| Маршрут | Що робить |
| --- | --- |
| `POST /auth/login` | З другим фактором повертає `{ twoFactorRequired: true, twoFactorToken, methods }` замість сесії. |
| `POST /auth/login/two-factor` | `{ twoFactorToken, code }` (TOTP або код відновлення) чи `{ twoFactorToken, challengeToken, credential }` для ключа доступу. Повертає сесію. |
| `POST /auth/login/passkey/options` | `{ twoFactorToken }`: виклик для ключа доступу. |
| `GET /auth/two-factor` | Ваші фактори: `totp`, `passkeys`, `recoveryCodesLeft`, `required`. |
| `POST /auth/two-factor/totp/setup`, `/totp/enable`, `/totp/disable` | Налаштувати (пароль), увімкнути (код) і вимкнути (пароль) застосунок-автентифікатор. |
| `POST /auth/two-factor/recovery-codes` | Нові коди відновлення. |
| `POST /auth/two-factor/passkeys/options`, `POST /auth/two-factor/passkeys`, `DELETE /auth/two-factor/passkeys/{id}` | Зареєструвати й видалити ключі доступу. |
| `DELETE /users/{id}/two-factor` | Скинути фактори іншого адміністратора (`users.manage`). |
