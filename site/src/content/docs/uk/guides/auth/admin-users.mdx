Адміністратори — це люди, які входять в адмін-панель. Вони відокремлені від
[кінцевих користувачів](/uk/guides/auth/end-users/) ваших сайтів і застосунків. У цьому
посібнику ви створите першого адміністратора, запросите інших, призначите їм ролі й допоможете
повернутися, коли доступ заблоковано.

## Перш ніж почати

- Verdin потребує `VERDIN_ADMIN_JWT_SECRET` і `VERDIN_TOKEN_PEPPER` у середовищі. Згенеруйте
  їх один раз через `verdin secrets`.
- Керування адміністраторами потребує **Керування користувачами** (`users.manage`); керування
  ролями — **Керування ролями** (`roles.manage`). Див. [Дозволи](/uk/reference/permissions/).
- Запрошення й скидання паролів надсилаються поштою через `[email]`. З типовим провайдером
  `log` листи, разом із посиланнями, записуються в журнал сервера.

## Створіть першого адміністратора

Відкрийте адмін-панель (типово `http://localhost:1337/admin/`). Поки немає жодного
адміністратора, вона просить створити першого, який стає Super Admin. Паролі мають від 8 до
128 символів.

Без браузера використовуйте CLI або API:

<Tabs>
<TabItem label="CLI">

```sh title="Terminal"
verdin admin create --email you@example.com
```

Пароль береться з `VERDIN_ADMIN_PASSWORD` або читається зі стандартного вводу. Команда створює
Super Admin і працює будь-коли, а не лише для першого.

</TabItem>
<TabItem label="API">

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/register-first-admin \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a long password"}'
```

Цей маршрут працює, лише поки немає жодного адміністратора.

</TabItem>
</Tabs>

## Запросіть адміністратора

<Steps>

1. Відкрийте **Налаштування → Користувачі** і виберіть **Додати користувача**.
2. Введіть ел. пошту й, за бажання, **Ім’я** та **Прізвище**.
3. Виберіть одну чи кілька **Ролі**.
4. Залиште **Установити пароль зараз** вимкненим, щоб надіслати запрошення, або ввімкніть,
   щоб задати пароль самостійно.
5. Виберіть **Запросити** (або **Зберегти** з паролем).

</Steps>

Діалог **Посилання-запрошення** показує посилання й повідомляє, чи його надіслано поштою. Якщо
ні — поділіться ним самі; з провайдером `log` так завжди. Посилання спрацьовує один раз
протягом 7 днів; запрошений адміністратор відкриває його, вибирає пароль і входить.

Доки адміністратор жодного разу не входив, **Нове посилання-запрошення** в його рядку замінює
старе посилання. Після першого входу доступ відновлюють через скидання пароля.

## Ролі

Verdin створює три ролі, як Strapi:

| Роль | Може |
| --- | --- |
| **Super Admin** | Усе. Її дозволи не можна змінити. |
| **Editor** | Створювати, редагувати, публікувати й видаляти весь вміст; керувати медіатекою; запускати розгортання; керувати SEO, перенаправленнями, меню та формами. |
| **Author** | Створювати вміст, а також редагувати й видаляти власні записи й файли. Не може публікувати. |

Створюйте інші в **Налаштування → Ролі** через **Нова роль**. Для кожної ролі виберіть:

- **Вміст**: для кожного типу вмісту (або **Усі типи вмісту**) рівень для **Читання**,
  **Створення**, **Редагування**, **Видалення** і **Публікація**: **Немає доступу**,
  **Власні** (лише записи, створені адміністратором) або **Усі**. **Поля** обмежує дію
  певними полями, а **Мови** — певними локалями.
- **Медіатека**: дії з файлами для **Усі файли** або **Власні файли**.
- **Налаштування**: доступ до розділів адміністрування, як-от **Керування користувачами** чи
  **Читання журналів аудиту**.
- **Вимагати двофакторну автентифікацію**: див. [Двофакторна автентифікація](/uk/guides/auth/two-factor/).

Адміністратор із кількома ролями отримує об'єднання їхніх дозволів. Повний список — у
[довіднику дозволів](/uk/reference/permissions/).

Лише Super Admin може надавати роль Super Admin або редагувати, видаляти чи скидати іншого
Super Admin.

## Деактивуйте або видаліть адміністратора

Відредагуйте адміністратора в **Налаштування → Користувачі** й вимкніть **Активний**: неактивні
користувачі не можуть увійти. **Видалити** назавжди видаляє обліковий запис; тоді його
коментарі показуються як написані видаленим адміністратором.

## Скидання пароля

- **Адміністратор скидає сам:** **Забули пароль?** на сторінці входу надсилає поштою
  посилання, що діє годину. Після зміни пароля всі сесії облікового запису завершуються.
- **Інший адміністратор задає пароль:** відредагуйте адміністратора в
  **Налаштування → Користувачі** й введіть новий пароль. Залиште поле порожнім, щоб зберегти
  поточний.
- **Із сервера:** коли ніхто не може увійти, запустіть

  ```sh title="Terminal"
  verdin admin reset-password --email you@example.com
  ```

  з паролем у `VERDIN_ADMIN_PASSWORD` або на стандартному вводі. Команда задає пароль,
  розблоковує обліковий запис і завершує його сесії. Двофакторну автентифікацію вона не
  прибирає: адміністратору, який втратив другий фактор, потрібен інший адміністратор, щоб
  [скинути його](/uk/guides/auth/two-factor/).

## Захист входу

- Після 5 неправильних паролів поспіль обліковий запис блокується на 15 хвилин.
- Запити входу, реєстрації й оновлення обмежено для кожної IP-адреси клієнта параметром
  `[admin].auth_rate_limit` (типово 20 на хвилину).
- Сесія адміністратора — це access token на 15 хвилин, що оновлюється через refresh cookie,
  яка діє 30 днів. Cookie має `Secure` у `verdin start`; див. `[admin].secure_cookies`.

Кожен адміністратор бачить свої пристрої з виконаним входом у розділі **Сесії** свого
**Профіль** і може **Вийти** на одному або на всіх інших. Зміна пароля виводить із системи всі
інші пристрої.

## Admin API

Увійдіть, щоб отримати access token для admin API:

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → { "data": { "user": {…}, "accessToken": "…", "accessTokenExpiresAt": "…" } }
```

| Маршрут | Дозвіл | Що робить |
| --- | --- | --- |
| `GET /users`, `GET /users/{id}` | `users.manage` | Адміністратори з їхніми ролями. |
| `POST /users` | `users.manage` | `{ email, firstname?, lastname?, roles: [ids], isActive?, password? }`. Без `password` поле `meta` відповіді містить `inviteUrl` і `emailed`. |
| `PUT /users/{id}`, `DELETE /users/{id}` | `users.manage` | Змінити або видалити адміністратора. |
| `POST /users/{id}/invite` | `users.manage` | Нове посилання-запрошення для адміністраторів, які жодного разу не входили. |
| `GET /roles`, `POST /roles`, `PUT /roles/{id}`, `DELETE /roles/{id}` | `roles.manage` | Ролі та їхні дозволи. |
| `POST /auth/forgot-password` | публічний | `{ email }`. Завжди відповідає `204`. |
| `GET /auth/sessions`, `DELETE /auth/sessions/{id}` | виконано вхід | Ваші сесії. |

Усі маршрути розташовані під `/admin/api`. Див. [admin API](/uk/api/admin/).

<Aside type="caution">
Секрети ніколи не записуються у `verdin.toml`. Не змінюйте обидва секрети між перезапусками й
екземплярами: `VERDIN_ADMIN_JWT_SECRET` підписує access tokens, JWT кінцевих користувачів і
посилання попереднього перегляду, а `VERDIN_TOKEN_PEPPER` захищає API-токени та другі фактори
(див. [API-токени](/uk/guides/auth/api-tokens/)).
</Aside>
