Журнали аудиту фіксують, хто, що й коли змінив: вміст, медіа, входи та кожну зміну в
адмін-панелі. У цьому посібнику показано, що записується, як фільтрувати журнали і скільки
вони зберігаються.

У Strapi журнали аудиту — функція Enterprise. У Verdin вони є частиною ядра з відкритим кодом.

## Перш ніж почати

- **Налаштування → Функції → Журнали аудиту** типово ввімкнено. Вимкнення припиняє запис нових
  дій; наявні записи лишаються доступними для читання.
- Читання журналів потребує **Читання журналів аудиту** (`audit.read`). Див.
  [Дозволи](/uk/reference/permissions/).

## Що записується

| Область | Дії | Примітки |
| --- | --- | --- |
| Вміст | `entry.create`, `entry.update`, `entry.publish`, `entry.unpublish`, `entry.discard-draft`, `entry.delete` | З усіх API: адмін-панелі, REST, GraphQL і плагінів. Локаль — у подробицях. |
| Процеси перевірки | `entry.stage`, `entry.assign` | Зміни етапів і призначення. |
| Медіа | `media.create`, `media.update`, `media.delete` | Завантаження, зміни й видалення файлів. Назва файлу — у подробицях. |
| Входи | `admin.login` | Входи за паролем і вхід першого адміністратора (записуються після другого фактора, якщо обліковий запис його має), а також входи через SSO із зазначенням провайдера. |
| Зміни в адмінці | `{METHOD} {route}`, наприклад `PUT /roles/{id}` | Кожен успішний запис через admin API: користувачі, ролі, API-токени, налаштування, функції, вебхуки, локалі, плагіни, релізи… Параметри маршруту — у подробицях. |

Кожен запис має час, виконавця, дію, об'єкт (uid типу вмісту, `plugin::upload.file` або
ресурс адмінки, як-от `roles`), id об'єкта, подробиці та, для запитів, IP-адресу клієнта.

Виконавець — це одне з:

- **Адміністратор**: адміністратор, що увійшов, названий у журналі.
- **API**: зміна через API вмісту чи GraphQL з API-токеном, токеном кінцевого користувача або
  через публічний доступ.
- **Система**: запис через admin API без адміністратора, що увійшов.

За зворотним проксі задайте `[server].trusted_proxies`, щоб журнали показували адресу клієнта,
а не проксі. Див. [довідник конфігурації](/uk/reference/configuration/).

## Фільтрування журналів

<Steps>

1. Відкрийте **Налаштування → Журнали аудиту**.
2. Скористайтеся шаблоном із **Швидкі фільтри** (**Вміст**, **Медіафайли**, **Входи**) або
   заповніть фільтри:
   - **Дія**: точна дія, як-от `entry.publish`, або префікс, що закінчується на `*`, як-от
     `entry.*`.
   - **Виконавець**: один адміністратор або **Будь-хто**.
   - **Об’єкт**: uid типу вмісту, наприклад `api::article`.
   - **З** і **По**: діапазон дат. Дата без часу включає весь день.
3. Виберіть **Застосувати**. Відкрийте **Подробиці** в рядку, щоб побачити все, що для нього
   записано.

</Steps>

## Запити до API

```sh title="Terminal"
curl -G 'http://localhost:1337/admin/api/audit-logs' \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  --data-urlencode 'action=entry.*' \
  --data-urlencode 'subject=api::article' \
  --data-urlencode 'actor=3' \
  --data-urlencode 'from=2026-09-01' \
  --data-urlencode 'to=2026-09-30' \
  --data-urlencode 'page=1' --data-urlencode 'pageSize=50'
```

Записи йдуть від найновіших, типово 50 на сторінку, щонайбільше 200:

```json
{
  "data": [
    {
      "id": 812,
      "at": "2026-09-28T14:03:11.000Z",
      "action": "entry.publish",
      "subject": "api::article",
      "subjectId": "k3v9…",
      "details": { "locale": "fr" },
      "ip": null,
      "actor": { "kind": "admin", "id": 3, "email": "ana@example.com", "name": "Ana Ruiz" }
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 50, "total": 1, "pageCount": 1 } }
}
```

`from` і `to` приймають дати або дати з часом у форматі ISO 8601; усе інше — помилка `400`.

## Скільки зберігаються записи

Записи, старші за `[audit].retention_days`, видаляються раз на день. Типово — 90 днів.

```toml title="verdin.toml"
[audit]
retention_days = 365
```

<Aside type="tip">
Щоб зберігати записи аудиту довше, ніж варто тримати в базі даних, регулярно копіюйте їх у
власне сховище через наведений вище API.
</Aside>
