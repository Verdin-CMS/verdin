Реліз групує записи, які разом виходять у світ або разом зникають: запуск продукту, кампанія,
набір перекладів. Ви публікуєте його вручну або призначаєте дату. У цьому посібнику ви
створите реліз, додасте записи, виконаєте його та побачите admin API.

Релізи працюють як Releases у Strapi, що входять до платних планів Strapi.

## Перш ніж почати

- **Налаштування → Функції → Релізи** типово ввімкнено. Поки функцію вимкнено, сторінка
  **Релізи** і маршрути недоступні, а заплановані релізи чекають.
- Керування релізами потребує **Керування релізами** (`releases.manage`).
- Додавання запису також потребує **Публікація** для його типу вмісту, і тип має
  використовувати [чернетки й публікацію](/uk/concepts/draft-and-publish/).

## Створіть реліз

<Steps>

1. Відкрийте **Релізи** на бічній панелі й виберіть **Новий реліз**.
2. Введіть **Назва**.
3. За бажання задайте **Опублікувати (необов’язково)**: дату й час у вашому часовому поясі,
   коли реліз виконається. Без дати реліз чекає, доки ви його не опублікуєте.
4. Виберіть **Створити**.

</Steps>

## Додайте записи

<Steps>

1. Відкрийте запис у редакторі. Панель **Релізи** показує релізи, до яких він входить.
2. Виберіть **Додати до релізу**.
3. Виберіть **Реліз**, а в **Під час виконання релізу** виберіть **Опублікувати** або
   **Зняти з публікації**.
4. Виберіть **Додати**.

</Steps>

Для локалізованих типів додається лише версія в поточній локалі редактора. Додавайте кожну
локаль, яку хочете випустити. Додавання запису, що вже є в релізі, замінює його дію.

Сторінка релізу показує його записи з типом вмісту й дією. Видаліть запис кнопкою в його
рядку.

## Публікація релізу

- **Зараз:** відкрийте реліз і виберіть **Опублікувати зараз**.
- **У призначений час:** фонове завдання перевіряє кожні 30 секунд і виконує релізи, час яких
  настав, від імені адміністратора, який їх створив.

<Diagram
  caption="Статуси релізу"
  code={`flowchart LR
  P[Очікує] -->|Опублікувати зараз або настала дата| R[Виконується]
  R -->|усі дії успішні| D[Виконано]
  R -->|деякі дії не вдалися| F[Помилка]`}
/>

Кожна дія фіксує, чи вдалася вона. Коли одна не вдається — наприклад, бо запис видалено або він
не проходить валідацію, — інші дії однаково виконуються, а реліз завершується зі статусом
**Помилка** і помилкою кожної невдалої дії в її рядку.

<Aside type="caution">
Виконаний реліз більше не можна змінити. Щоб повторити невдалі дії, додайте ці записи до
нового релізу.
</Aside>

Реліз публікується цілком: він не чекає [етапів перевірки](/uk/guides/content/review-workflows/).
Якщо процес вимагає певного етапу для публікації, записи поза цим етапом не публікуються, як і
за будь-якої іншої публікації.

Вебхуки можуть підписатися на **Реліз опубліковано** (`releases.publish`), що надсилається під
час виконання релізу. Див. [Вебхуки](/uk/guides/integrations/webhooks/).

## Admin API

Усі маршрути розташовані під `/admin/api` і потребують `releases.manage`.

```http
GET    /admin/api/releases?status=pending&page=1&pageSize=25
POST   /admin/api/releases                    { "name": "Launch", "scheduledAt": "2026-10-01T08:00:00Z" }
GET    /admin/api/releases/{id}
PUT    /admin/api/releases/{id}               { "name": "Launch", "scheduledAt": null }
DELETE /admin/api/releases/{id}
POST   /admin/api/releases/{id}/actions       { "uid": "api::article", "documentId": "…", "locale": "fr", "action": "publish" }
DELETE /admin/api/releases/{id}/actions/{actionId}
POST   /admin/api/releases/{id}/publish
GET    /admin/api/content/{uid}/{documentId}/releases
```

- `status` — це `pending`, `running`, `done` або `failed`; кожна дія має власні `status` і
  `error`.
- Зміна, додавання до чи публікація релізу, який уже не очікує, відповідає `409`.
- `action` — це `publish` або `unpublish`. Додавання дії також потребує `content.publish` для
  типу. Локаль визначається під час додавання дії, тож пізніша зміна типової локалі її не
  зсуває.
- Видалення релізу видаляє його список записів. Самі записи не змінюються.
- `GET /content/{uid}/{documentId}/releases` потребує доступу на читання до запису й повертає
  порожній список адміністраторам без `releases.manage`.
