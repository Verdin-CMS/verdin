Verdin зберігає версію запису щоразу, коли його створено, збережено, опубліковано, знято з
публікації або відкинуто його чернетку, з будь-якого API. У цьому посібнику показано, як
знайти стару версію й відновити її, скільки версій зберігається, і відповідний admin API.

Історія вмісту працює так само, як у Strapi, де вона платна.

## Перш ніж почати

- **Налаштування → Функції → Історія вмісту** типово ввімкнено. Поки її вимкнено, версії не
  записуються, а історія недоступна.
- Читання історії запису потребує доступу на читання до запису; відновлення — доступу на
  оновлення. Діють обмеження за полями: ви бачите й відновлюєте лише поля, які ваша роль може
  читати чи оновлювати. Див. [Дозволи](/uk/reference/permissions/).

## Відновлення версії

<Steps>

1. Відкрийте запис і виберіть **Історія**.
2. Список **Версії** показує кожну версію з подією (**Створено**, **Збережено**,
   **Опубліковано**, **Знято з публікації**, **Чернетку скасовано**), датою й автором. Зміни,
   зроблені через API вмісту, показують **API** як автора.
3. Виберіть версію, щоб переглянути її поля.
4. Виберіть **Відновити** і підтвердьте.

</Steps>

Версія замінює поточну чернетку; опублікуйте її потім, коли будете готові. У типах без
чернеток і публікації відновлення одразу оновлює запис.

Що не відновлюється:

- Поля, яких більше немає в схемі, перелічуються й не відновлюються.
- Посилання на видалені записи чи файли відкидаються, а редактор повідомляє, які поля їх
  втратили.

**Повернутися до редактора** повертає до запису, нічого не змінюючи.

## Скільки версій зберігається

Verdin зберігає найновіші `[history].max_versions` версій кожного запису й локалі (типово 50)
і видаляє старіші, коли з'являються нові:

```toml title="verdin.toml"
[history]
max_versions = 100
```

Кожна локаль локалізованого запису має власну історію. Видалення запису або однієї з його
локалей видаляє й відповідні версії. Див. [довідник конфігурації](/uk/reference/configuration/).

<Aside type="note">
На відміну від Strapi, де історія зберігається певну кількість днів, Verdin зберігає певну
кількість версій на запис, хоч би які старі вони були.
</Aside>

## Admin API

Усі маршрути розташовані під `/admin/api`.

| Маршрут | Дозвіл | Що робить |
| --- | --- | --- |
| `GET /history/{uid}/{documentId}?locale=&page=&pageSize=` | читання запису | Версії від найновіших, без їхніх даних (20 на сторінку, щонайбільше 100). |
| `GET /history/versions/{id}` | читання запису | Одна версія з даними. |
| `POST /history/versions/{id}/restore` | оновлення запису | Відновлює версію як поточну чернетку. |

Відповідь на відновлення перелічує, що було відкинуто:

```json
{
  "data": {
    "documentId": "k3v9…",
    "restored": 42,
    "dropped": [{ "field": "tags", "count": 1 }]
  }
}
```

Поки функцію вимкнено, маршрути відповідають `404`.
