Локалізований тип вмісту зберігає одну версію кожного запису на локаль. У цьому посібнику ви
додасте локалі, якими публікуєте, увімкнете локалізацію для типу, перекладете записи в
адмін-панелі та читатимете чи записуватимете кожну локаль через API. Про модель, що стоїть за
цим (спільні поля, зв'язки між локалізованими типами), див.
[Інтернаціоналізація](/uk/concepts/internationalization/).

Локалізація — частина ядра: вмикати нічого не треба. Вона працює як плагін i18n у Strapi v5 і
приймає той самий параметр `locale`.

## Перш ніж почати

- Щоб додавати, перейменовувати чи видаляти локалі, потрібен **Керування мовами**
  (`locales.manage`).
- Щоб зробити тип локалізованим, редагуйте його схему в **Конструктор типів вмісту**
  (`verdin dev`) або в `schema/content-types/<name>.json`.
- Про дозволи на вміст, потрібні редакторам, див. [Дозволи](/uk/reference/permissions/).

## Додайте локалі

Перший запуск створює англійську (`en`) як типову локаль. Запити без локалі використовують
типову, і нові записи починаються в ній.

<Steps>

1. Відкрийте **Налаштування → Інтернаціоналізація** і виберіть **Додати мову**.
2. Введіть **Код**: код мови малими літерами, за бажання з регіоном чи письмом, наприклад `fr`,
   `pt-BR` або `zh-Hans`. Назва заповнюється автоматично, і її можна змінити.
3. Позначте **Зробити типовою мовою**, якщо запити без локалі мають використовувати її, і
   збережіть.

</Steps>

Щоб пізніше змінити типову, виберіть **Зробити типовою** для іншої локалі. Типову локаль не
можна видалити.

<Aside type="caution" title="Видалення локалі видаляє її записи">
Видалення локалі назавжди видаляє всі записи, написані нею, в усіх типах вмісту, включно з
опублікованими версіями. Діалог просить ввести код локалі для підтвердження.
</Aside>

## Зробіть тип вмісту локалізованим

У **Конструктор типів вмісту** відкрийте тип і ввімкніть **Локалізовано** в його
налаштуваннях. Потім вирішіть для кожного поля, які значення різняться між локалями: поле з
вимкненим **Локалізовано** має одне значення, спільне для всіх локалей.

Те саме у файлі схеми для типу `article` прикладу:

```json title="schema/content-types/article.json" {6,9}
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

Як поводяться спільні поля:

- Збереження спільного поля в одній локалі записує його в чернетки всіх локалей.
- Публікація локалі копіює її спільні поля в опубліковані версії інших локалей.
- Зв'язки й медіаполя теж можуть бути спільними.

Типи без `pluginOptions.i18n.localized` не локалізовані й ігнорують параметри `locale`. Зміна
локалізації типу — це зміна схеми: перегляньте міграцію через `verdin migrate plan` перед
розгортанням.

## Переклад запису в адмін-панелі

<Steps>

1. Відкрийте запис і виберіть цільову мову в перемикачі **Мова** вгорі редактора. Локалі без
   версії показують **Ще не створено**.
2. Редактор повідомляє, що запис ще не має версії в цій локалі і що збереження її створить.
   Спільні поля вже показують свої значення.
3. Щоб почати з наявного перекладу, виберіть **Заповнити з іншої мови** в цьому повідомленні.
   Виберіть джерело в **Копіювати з** і виберіть **Копіювати поля**. Це копіює локалізовані
   поля, включно зі зв'язками й медіа, у форму. Нічого ще не зберігається.
4. Відредагуйте поля, потім **Зберегти чернетку** або **Опублікувати**. Кожна локаль має власну
   чернетку й опубліковану версію.

</Steps>

Вигляд списку має такий самий перемикач **Мова**: він показує версії однієї локалі за раз.
Видалення з редактора видаляє лише версію в поточній локалі; інші локалі зберігаються.

Коли ввімкнено функцію **Дії ШІ**, редактор також може перекладати текстові поля з чернетки
іншої локалі. Див. [Дії ШІ](/uk/guides/integrations/ai-actions/).

## Обмеження редакторів певними локалями

Дозволи ролі на вміст можуть охоплювати лише деякі локалі. У **Налаштування → Ролі** відкрийте
роль, знайдіть тип вмісту й виберіть **Мови**. Виберіть **Лише ці мови** і позначте їх.
Адміністратори з цією роллю не можуть читати чи змінювати версії в інших локалях; перемикач
**Мова** показує такі локалі як «(немає доступу)».

## Читання й запис локалей через API

Додайте `locale` до будь-якого REST-запиту або передайте його як аргумент у GraphQL. Без нього
використовується типова локаль. Невідома локаль — це помилка `400`.

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
# Прочитати французькі версії
curl 'http://localhost:1337/api/articles?locale=fr'

# Створити або оновити французьку версію документа
curl -X PUT 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"data":{"title":"Bonjour"}}'

# Видалити лише французьку версію
curl -X DELETE 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN"
```

</TabItem>
<TabItem label="GraphQL">

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
    locale
  }
}
```

</TabItem>
<TabItem label="TypeScript">

```ts
const { data } = await verdin.collection('articles').find({ locale: 'fr' });
```

</TabItem>
</Tabs>

Чого очікувати:

- `PUT` з `locale` створює версію цієї локалі, коли документ її ще не має.
- Відповіді локалізованих типів містять `locale`. Усі версії мають спільний `documentId`.
- `DELETE` видаляє лише версію в запитаній локалі (у типовій, якщо локаль не вказано).
  Посилання на документ видаляються, коли не залишається жодної локалі.
- Коли локалізований тип посилається на інший локалізований тип, читання розв'язує ціль у тій
  самій локалі, і фільтри через зв'язки роблять так само. Нелокалізовані цілі спільні для всіх
  локалей.
- Payload вебхуків і версії історії фіксують локаль.

На відміну від Strapi, API вмісту не має маршруту `/api/i18n/locales`. Локалі перелічено в
admin API за адресою `GET /admin/api/i18n/locales`, а керують ними через `POST`,
`PUT /admin/api/i18n/locales/{code}` і `DELETE /admin/api/i18n/locales/{code}`
(`locales.manage`).
