Вебхуки надсилають HTTP `POST` на вашу URL, коли змінюється вміст або медіа: перезібрати
статичний сайт, очистити кеш, синхронізувати пошуковий індекс, написати в чат. Доставки
ставляться в чергу, підписуються, повторюються й журналюються.

На цій сторінці показано, як налаштувати вебхук і приймати його. Події, payload і заголовки
перелічено в [довіднику вебхуків](/uk/api/webhooks/).

## Увімкнення

Функцію **Вебхуки** типово ввімкнено; її можна вимкнути в **Налаштування → Функції**.
Керування вебхуками потребує дозволу **Керування вебхуками** (`webhooks.manage`). Див.
[Дозволи](/uk/reference/permissions/).

## Створіть вебхук

<Steps>

1. Перейдіть до **Налаштування → Вебхуки** і виберіть **Новий вебхук**.
2. У розділі **Загальне** задайте **Назва** і **URL**, яку має викликати Verdin.
3. У розділі **Події** виберіть події, що запускають доставку: **Записи** (створення,
   оновлення, публікація, зняття з публікації, відкидання чернетки, видалення), **Медіа**,
   **Релізи** (**Реліз опубліковано**) і **Процеси перевірки** (**Етап запису змінено**).
4. У розділі **Типи контенту** залиште **Усі типи контенту** або виберіть деякі. Це фільтрує
   лише події записів; медіаподії надсилаються в будь-якому разі.
5. У розділі **Заголовки** додайте потрібні вашому ендпоінту заголовки, наприклад токен
   `authorization` (**Додати заголовок**). `content-type`, `host` і заголовки `x-verdin-*`
   задає Verdin.
6. У розділі **Підписування** залиште **Підписувати доставки** ввімкненим (типово).
7. Виберіть **Створити**. Verdin один раз показує секрет підпису (`whsec_…`): скопіюйте його в
   конфігурацію свого ендпоінта.

</Steps>

**Увімкнено** вимикає вебхук без видалення. Вимкнені вебхуки не отримують подій, але їх
однаково можна тестувати.

## Перевірка

Виберіть **Надіслати тестову подію** на вебхуку. Verdin одразу надсилає:

```json
{ "event": "trigger-test", "createdAt": "2026-09-25T09:00:00.000Z" }
```

Доставка з'являється в **Журнал доставок** вебхука зі статусом, HTTP-статусом, тривалістю й
початком тіла відповіді. Відкрийте доставку, щоб побачити повний payload і помилку, якщо вона
є.

Щоб отримувати вебхуки на своїй машині під час розробки, запускайте сервер через `verdin dev`:
він дозволяє URL `localhost`, які `verdin start` відхиляє (див. [Безпека](#безпека)).

## Приймання доставки

Доставка — це `POST` з JSON-тілом і такими заголовками:

| Заголовок | Значення |
| --- | --- |
| `content-type` | `application/json` |
| `x-verdin-event` | Назва події, наприклад `entry.publish`. |
| `x-verdin-delivery` | Id доставки. Він не змінюється між повторними спробами: використовуйте його, щоб ігнорувати дублікати. |
| `x-verdin-signature` | `t=<unix seconds>,v1=<hex>` у підписаних вебхуках. |

```json
{
  "event": "entry.publish",
  "createdAt": "2026-09-25T09:00:00.000Z",
  "model": "article",
  "uid": "api::article",
  "entry": { "id": 3, "documentId": "01J…", "title": "Hello", "publishedAt": "2026-09-25T09:00:00.000Z" }
}
```

Відповідайте будь-яким статусом `2xx`, і швидко. Повільну роботу (повну перезбірку) робіть
після відповіді або ставте в чергу: доставка, що триває довше за тайм-аут (типово 10 секунд),
вважається невдалою.

### Перевірка підпису

`v1` — це HMAC-SHA256 від `"<t>.<raw body>"` з ключем — секретом вебхука. Щоб перевірити
доставку:

1. Обчисліть HMAC заново від **сирого** тіла запиту, а не від повторно серіалізованого JSON.
2. Порівняйте його з `v1` за сталий час.
3. Відхиляйте мітки часу, старші за кілька хвилин, щоб перехоплену доставку не можна було
   відтворити.

<Tabs syncKey="lang">
<TabItem label="Node.js">

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(secret, header, rawBody, toleranceSeconds = 300) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((part) => part.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > toleranceSeconds) return false;
  const expected = createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  return v1?.length === expected.length && timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}
```

З Express зберігайте сире тіло: `app.post('/hooks/verdin', express.raw({ type: 'application/json' }), …)`
і передавайте `req.body.toString()`.

</TabItem>
<TabItem label="Python">

```python
import hashlib, hmac, time

def verify(secret: str, header: str, raw_body: bytes, tolerance: int = 300) -> bool:
    parts = dict(part.split("=", 1) for part in header.split(","))
    if abs(time.time() - int(parts["t"])) > tolerance:
        return False
    expected = hmac.new(secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])
```

</TabItem>
<TabItem label="Edge (Web Crypto)">

```ts
export async function verify(secret: string, header: string, rawBody: string, tolerance = 300) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((part) => part.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > tolerance) return false;
  const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(secret),
    { name: 'HMAC', hash: 'SHA-256' }, false, ['verify']);
  const signature = new Uint8Array(v1.match(/../g)!.map((byte) => parseInt(byte, 16)));
  return crypto.subtle.verify('HMAC', key, signature, new TextEncoder().encode(`${t}.${rawBody}`));
}
```

`crypto.subtle.verify` порівнює за сталий час.

</TabItem>
</Tabs>

**Змінити секрет** видає новий секрет (показується один раз); старий одразу перестає
працювати. **Припинити підписування** видаляє секрет і надсилає доставки без підпису.

## Повторні спроби

Доставки зберігаються в базі даних у момент фіксації зміни й надсилаються фоновим воркером,
тож повільний ендпоінт ніколи не гальмує редакторів.

- **Успіх:** будь-яка відповідь `2xx`.
- **Невдача:** будь-що інше, зокрема перенаправлення (за ними не переходять), помилки
  з'єднання й тайм-аути.
- **Повторні спроби:** невдала доставка повторюється через 30 секунд, 2 хвилини, 10 хвилин,
  1 годину й 6 годин. Після цього її позначено як **Помилка**.

Виберіть **Повторити** для доставки в журналі, щоб надіслати її знову просто зараз. Журнал
зберігається 30 днів. Оскільки повторні спроби використовують той самий `x-verdin-delivery`,
зробіть свій обробник ідемпотентним: зберігайте оброблені id або робіть роботу безпечною для
повторення.

## Безпека

З `verdin start` URL вебхуків не можуть вказувати на loopback, приватні, link-local чи інші
зарезервовані адреси, включно з іменами хостів, що в них резолвляться. Це не дає
адміністратору використати вебхуки, щоб дістатися внутрішніх сервісів (SSRF). Облікові дані
в URL (`https://user:pass@…`) відхиляються; натомість надсилайте їх у заголовку.

```toml title="verdin.toml"
[webhooks]
allow_private_networks = false   # unset: false with `verdin start`, true with `verdin dev`
timeout_secs = 10
retention_days = 30
```

Див. [`[webhooks]`](/uk/reference/configuration/).

## Перехід зі Strapi

Вебхуки Verdin відповідають подіям і payload Strapi з такими відмінностями:

- доставки підписуються, повторюються й журналюються;
- вебхук можна обмежити певними типами вмісту;
- `entry.draft-discard` зі Strapi називається `entry.discard-draft`.

Щоб перезбирати статичний сайт з адмінки кнопкою, а не після кожної зміни, див.
[Розгортання і CDN](/uk/guides/integrations/deploys-and-cdn/).
