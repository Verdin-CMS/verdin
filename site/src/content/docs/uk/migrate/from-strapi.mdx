`verdin import strapi` переносить проєкт Strapi v4 чи v5 у Verdin: його типи вмісту й
компоненти стають файлами схеми, а записи, локалі, медіатека, зв'язки, кінцеві користувачі та
публічні дозволи імпортуються. На цій сторінці покроково описано міграцію й перелічено, що має
змінити ваш фронтенд. Порівняння за функціями див. у [Сумісність зі Strapi](/uk/migrate/compatibility/).

## Перш ніж почати

- Проєкт Strapi v4 чи v5, у якому ви можете запустити `strapi export`.
- Новий проєкт Verdin (`verdin new my-site`) або проєкт без файлів схеми з тими самими назвами.
  Див. [швидкий старт](/uk/start/quickstart/).
- За можливості — база даних і медіасховище, які проєкт Verdin використовуватиме в production:
  під час імпорту файли копіюються в налаштований провайдер завантажень.

## 1. Експорт зі Strapi

У проєкті Strapi:

```sh frame="terminal"
npx strapi export --no-encrypt -f my-export      # записує my-export.tar.gz
```

Verdin не може читати зашифровані експорти (`.tar.gz.enc`); експортуйте знову з
`--no-encrypt`. Нестиснуті експорти (`--no-compress`, `.tar`) і розпакований каталог експорту
теж працюють.

## 2. Імпорт у Verdin

<Steps>

1. Створіть проєкт та імпортуйте експорт:

   ```sh frame="terminal"
   verdin new my-site && cd my-site
   verdin import strapi ../my-export.tar.gz
   ```

2. Прочитайте підсумок. Імпортер виводить, скільки документів, версій, файлів, папок, локалей і
   посилань він імпортував, а потім по рядку на кожне попередження.

3. Запустіть сервер розробки й відкрийте адмін-панель:

   ```sh frame="terminal"
   verdin dev
   ```

</Steps>

Команда виконує такі кроки по черзі:

1. Записує в `schema/` по одному файлу схеми на кожен тип вмісту `api::` і кожен компонент.
   Якщо перетворена схема не проходить валідацію, нічого не записується.
2. Мігрує базу даних (безпечні кроки).
3. Імпортує локалі, медіапапки й файли, записи (кожну чернетку, опубліковану версію й локаль),
   зв'язки та медіа, прикріплені до записів і компонентів.
4. Імпортує кінцевих користувачів, їхні ролі, а також публічні й authenticated-дозволи.
5. Записує `strapi-id-map.json` у каталог проєкту.

| Параметр | Дія |
| --- | --- |
| `--schema-only` | Зупинитися після запису файлів схеми. Корисно, щоб спершу переглянути чи скоригувати схему. |
| `--force` | Перезаписати наявні файли схеми й імпортувати в типи вмісту, що вже мають записи. |

Без `--force` імпорт зупиняється, якщо файл схеми, який він записав би, уже існує або якщо тип
вмісту вже має записи.

## Що переноситься

| Strapi | Verdin |
| --- | --- |
| Типи вмісту `api::…` і компоненти | Файли схеми зі збереженням `collectionName`, чернеток і публікації, параметрів i18n і параметрів полів (`required`, `private`, `unique`, довжини, `regex`, типові значення…) |
| Зв'язки між типами `api::` | Ті самі зв'язки |
| Зв'язки всередині компонентів | Посилання `oneWay` / `manyWay` |
| Поліморфні зв'язки (`morphToOne`, `morphToMany`, `morphOne`, `morphMany`) | Ті самі, з посиланнями на імпортовані типи вмісту |
| Медіаполя (зокрема в компонентах) | Медіаполя |
| Рядки v5 (чернетки й опубліковані) | Чернетки й опубліковані версії |
| Рядки v4 | Чернетка плюс опублікована версія, коли задано `publishedAt`; `localizations` стають локалями одного документа |
| `plugin::i18n.locale` | Локалі (типова в Strapi лишається типовою) |
| `plugin::upload.file` і `folder` | Файли медіатеки (з їхніми форматами) і папки |
| Поля `password` | Поля `password` зі збереженими хешами bcrypt зі Strapi |
| Власні поля (`customField`) | Атрибут зі збереженим `customField`; див. нижче |
| Умовні поля (`conditions`, Strapi 5.17) | Зберігаються в схемі й застосовуються редактором |
| `plugin::users-permissions.user` | Кінцеві користувачі з паролями bcrypt (перехешовуються з Argon2id під час наступного входу), `confirmed` і `blocked` |
| Ролі Users & Permissions | Дозволи ролі Public стають публічними дозволами Verdin; Authenticated і власні ролі стають ролями кінцевих користувачів |
| Дозволи ролей на типи вмісту й завантаження | Дозволи `find`, `findOne`, `create`, `update` і `delete`; для завантажень — `find`, `findOne`, `upload` і `destroy` |

## Що не переноситься

Повідомляється як попередження:

- Зв'язки з адміністраторами, кінцевими користувачами чи типами інших плагінів (імпортуються
  лише цілі `api::`). Поля `createdBy` / `updatedBy` пропускаються.
- `unique` для атрибутів `text`, `richtext`, `blocks` і `json` (Verdin підтримує його для
  коротких текстових типів).
- Типи атрибутів, яких Verdin не знає, і типи зв'язків, які він не може зберігати всередині
  компонента.
- Половинки зв'язків, чиї `inversedBy` / `mappedBy` не збігаються з іншою стороною.
- Некоректні коди локалей.

Зовсім не імпортуються: адміністратори й ролі адміністраторів, API-токени, transfer tokens,
вебхуки, релізи, етапи процесів перевірки, історія вмісту й журнали аудиту, а також
налаштування плагінів Strapi. Ваш код Strapi — контролери, сервіси, маршрути, policies,
middlewares, хуки lifecycle, cron-завдання й налаштування адмінки — не має у Verdin
відповідника для перетворення; див. [Перепишіть власний код](#перепишіть-власний-код).

<Aside type="note">
Власні поля зберігають свою назву `customField`, наприклад `plugin::color-picker.color`.
Редактор показує їх за допомогою [плагіна](/uk/extending/plugins/), що надає це поле, а якщо
такого немає — звичайне поле введення для типу зберігання.
</Aside>

## Мапа id

Verdin генерує нові id документів: `documentId` у Strapi мають 24 символи, а у Verdin — 26, тож
кожен документ отримує новий. Числові `id` теж змінюються. `strapi-id-map.json` фіксує
відповідність:

```json title="strapi-id-map.json"
{
  "documents": {
    "api::article": {
      "hq7xw1c6m2vkn0f3t8ybz5sd": "01k6b3xg0r9m2m7c1d4e5f6g7h"
    }
  },
  "files": {
    "12": 3
  }
}
```

- `documents` має ключі за uid типу вмісту Verdin (`api::article`, у Strapi —
  `api::article.article`), а далі за `documentId` Strapi (v5) або за id рядка (v4: один id
  означає всі локалі документа).
- `files` зіставляє id файлів Strapi з id файлів Verdin.

Використовуйте її, щоб переписати id, збережені поза CMS: посилання в коді фронтенду, id в іншій
базі даних, аналітиці, закладках.

## Перевірте результат

1. `verdin schema check` проходить, а `verdin migrate plan` каже, що база даних актуальна.
2. В адмін-панелі відкрийте кожну колекцію й порівняйте кількість записів, чернеток і локалей зі
   Strapi.
3. Відкрийте кілька записів зі зв'язками, компонентами, динамічними зонами й медіа та
   перевірте, що посилання ведуть на правильні документи й файли.
4. Відкрийте **Медіатека** й перевірте, що папки й зображення (з їхніми форматами) на місці.
5. У **Налаштування → Публічний доступ** і **Налаштування → Кінцеві користувачі** перегляньте
   імпортовані дозволи й ролі.
6. Викличте свій API так, як це робить фронтенд, і порівняйте відповіді з відповідями Strapi.

Потім закомітьте `schema/`, створіть адміністраторів, API-токени й вебхуки та розгорніть (див.
[чекліст для production](/uk/deploy/production-checklist/)).

## Зміни у фронтенді

API вмісту відповідає формі REST і GraphQL Strapi v5, тож більшість запитів працюють як є.
Змініть таке:

- **Базова URL.** Спрямуйте фронтенд на сервер Verdin. API вмісту розташований під `/api`
  (`[api].prefix`), GraphQL — на `/graphql`, щойно ви ввімкнете його в **Налаштування → Функції**.
- **API-токени.** Токени не імпортуються: створіть нові в **Налаштування → API-токени** і
  замініть їх у середовищі фронтенду.
- **Id документів.** Кожен `documentId` і числовий `id` новий. Замініть id, зашиті у фронтенді,
  на ті, що в `strapi-id-map.json`, або, краще, шукайте записи за slug чи іншим полем `uid`.
- **URL медіа.** URL файлів вказують на новий провайдер: `/uploads/…` на сервері Verdin для
  локального провайдера або `[upload.provider].public_url` для S3. Оновіть домени зображень,
  дозволені вашим фреймворком (наприклад, `images.remotePatterns` у Next.js).
- **Кінцеві користувачі, що увійшли**, мають увійти знову: їхні паролі працюють, а JWT, видані
  Strapi, — ні.
- **CORS.** Якщо браузер викликає API з іншого origin, укажіть його в `[api].cors_origins`.
- **Вебхуки.** Створіть їх заново в **Налаштування → Вебхуки**. Подія Strapi
  `entry.draft-discard` називається `entry.discard-draft`, а доставки підписуються (див.
  [Вебхуки](/uk/guides/integrations/webhooks/)).
- **Фронтенди Strapi v4** потребують і змін v5: плоскі відповіді без `attributes`, `documentId`
  замість `id` в URL і `status=draft` замість `publicationState=preview`.

Для типізованого доступу згенеруйте TypeScript-типи через `verdin types` і використовуйте
[типізований клієнт](/uk/guides/frontend/typed-client/).

## Перепишіть власний код

| Strapi | Verdin |
| --- | --- |
| Хуки lifecycle, middlewares Document Service | Хуки плагінів (`beforeCreate`, `afterUpdate`…) у [плагіні WebAssembly](/uk/extending/plugins/) |
| Власні маршрути й контролери | Маршрути плагінів під `/api/plugins/<name>/` |
| Cron-завдання | Завдання плагінів (`[[jobs]]`) |
| Власні поля | Власні поля плагінів |
| Віджети адмінки | Віджети плагінів або вбудовані віджети панелі |
| Логотип, кольори й тексти адмінки | `[admin.branding]` у `verdin.toml` |
| `config/*.js` | `verdin.toml` і змінні середовища ([довідник конфігурації](/uk/reference/configuration/)) |
