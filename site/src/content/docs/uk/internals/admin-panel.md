Ця сторінка для контриб'юторів адмін-панелі в `admin/`: як організовано застосунок Angular, як він перетворює схему вмісту на форми й списки і як потрапляє всередину бінарника `verdin`. Як користуватися панеллю, описано в посібниках; як працює серверна частина admin API — у [довіднику admin API](/uk/api/admin/).

Панель — це односторінковий застосунок на Angular 22: standalone-компоненти, zoneless change detection, signals, маршрути з лінивим завантаженням і компоненти spartan/ui на Tailwind CSS v4.

## Структура

```text
admin/
├── src/app/
│   ├── app.config.ts     # providers: router, HttpClient interceptors, Transloco, icons
│   ├── app.routes.ts     # lazy routes, guards (auth, permissions, unsaved changes)
│   ├── core/             # services and pure models: api, auth, schema, i18n, permissions…
│   ├── layout/           # the shell (sidebar, header), home, deploy button
│   ├── features/
│   │   ├── auth/         # login, first admin, invitations, password reset
│   │   ├── dashboard/    # home widgets
│   │   ├── content/      # lists, the entry editor, history, releases, review, import
│   │   │   ├── fields/   # schema-driven form controls and the form model
│   │   │   └── collab/   # comments and tasks
│   │   ├── builder/      # content-type builder (verdin dev only)
│   │   ├── media/        # media library
│   │   ├── releases/
│   │   ├── profile/      # own account, two-factor, passkeys, sessions
│   │   └── settings/     # users, roles, tokens, webhooks, locales, plugins, site features…
│   └── shared/
│       ├── ui/           # spartan helm components, owned by the project
│       └── components/   # app-level shared components (confirm dialog, page header…)
├── public/i18n/          # translation catalogs, one JSON file per language
├── scripts/check-i18n.mjs
└── e2e/                  # Playwright tests and the server they run against
```

**Стан** живе в signals усередині injectable-сервісів у `core/` (`Auth`, `Schema`, `I18n`, `Theme`…). Бібліотеки store немає.

**Доступ до API** проходить через `core/api.ts` — невелику обгортку на промісах над `HttpClient` Angular, з написаними вручну типами в `core/types.ts`. Конфігурація часу виконання (шлях адмінки, префікс API, режим, брендинг) береться з тегу `<meta name="verdin-config">`, який вставляє сервер.

**Сесія.** Access token живе лише в пам'яті; refresh token — це cookie `HttpOnly`, обмежена маршрутами автентифікації. HTTP-перехоплювач додає bearer-токен і на `401` один раз оновлює токен і повторює запит; якщо оновлення не вдається, він відправляє користувача на сторінку входу. Запити оновлення й виходу містять заголовок `X-Verdin-CSRF`, якого вимагає сервер. Guards відновлюють сесію з cookie під час завантаження сторінки. `403`, що повідомляє, що роль вимагає двофакторної автентифікації, відправляє користувача її налаштувати.

## Форми на основі схеми

Редактор запису (`features/content/edit.ts`) не має коду для окремих типів. Він читає типи вмісту й компоненти з `GET /admin/api/content-types` і `GET /admin/api/components`, а макет редактора — з налаштувань edit view, і будує форму під час виконання за допомогою **Signal Forms** (`@angular/forms/signals`):

- Модель документа — це signal звичайного об'єкта (`FormModel` у `fields/model.ts`); дерево полів і його валідатори виводяться зі схеми.
- Рекурсивний компонент `vd-fields` (`fields/fields.ts`) відображає будь-яку мапу атрибутів на дереві полів. Текст, дати й час використовують нативні input, прив'язані через `[formField]`. Власні `FormValueControl` обробляють числа (nullable; великі цілі залишаються рядками), перемикачі, enumeration, дати з часом (локальний час в input, UTC у моделі), JSON, Markdown, `blocks` (TipTap), медіа, зв'язки (вибір із пошуком під час введення та впорядкуванням) і поліморфні зв'язки.
- Компоненти — вкладені fieldset; повторювані компоненти й динамічні зони — списки, які можна впорядковувати. Плагіни можуть реєструвати власні типи полів, що відображаються як custom elements.
- `toModel` перетворює заповнений документ на модель форми (зв'язки стають `documentId`, файли — id), а `toPayload` перетворює назад у payload `data`: порожні рядки стають `null`, ключі рендерингу (`__key`) і сторони лише для читання (`mappedBy`, `morphOne`, `morphMany`) відкидаються. Обидва покрито unit-тестами в `fields/model.spec.ts`.
- Валідація, виведена зі схеми, дає миттєвий зворотний зв'язок. Умовні поля (`conditions.visible`) обчислюються в браузері портом серверного обчислювача JSON Logic (`core/logic.ts`). Правила валідації між полями перевіряє лише сервер. Сервер лишається головним: його записи `details.errors[].path` зіставляються з відповідними полями.
- Збереження явне, з відстеженням змін і попередженням під час виходу зі сторінки (route guard плюс `beforeunload`). Кнопки **Опублікувати**, **Зняти з публікації** і **Скасувати зміни** з'являються залежно від стану документа. Адмінка зберігає лише чернетки; публікація — завжди окрема дія.

Макет редактора (порядок полів, ширини, підписи, описи, поля лише для читання, поле, що називає пов'язані записи) спільний для всіх адміністраторів і зберігається на сервері у `vd_settings`; його змінюють на сторінці **Налаштувати вигляд** з дозволом `views.manage`.

## Списки

Списки вмісту (`features/content/list.ts`) використовують таблицю spartan helm із серверною пагінацією, сортуванням і фільтрами. Фільтри, пошук (`_q`) і сторінка відображаються в URL, тож відфільтрований список — це посилання, яким можна поділитися. Кожен адміністратор вибирає видимі стовпці, типове сортування й розмір сторінки для кожного типу (`list-view.ts`); ці вибори зберігаються в його власних налаштуваннях на сервері, тож слідують за ним у різних браузерах. Списки також оновлюються наживо з потоку подій адмінки.

## Конструктор типів вмісту

**Конструктор типів вмісту** видно лише тоді, коли сервер працює в режимі розробки (`verdin dev`) і адміністратор має `schema.manage`. Він редагує типи вмісту й компоненти в їхньому файловому форматі: поля, види й цілі зв'язків (створюючи зворотний атрибут у цілі), компоненти, динамічні зони, довжини, діапазони та прапорці `required`, `unique` і `private`.

Кожна зміна спершу надсилається до `POST /admin/api/schema/plan`, що перевіряє майбутню схему й повертає кроки міграції з їхнім ризиком, SQL і пропозиціями перейменувань, які користувач може прийняти. Підтвердження викликає `POST /admin/api/schema/apply` з прийнятим рівнем ризику й перейменуваннями. Сервер мігрує, записує `schema/*.json` і підміняє запущений застосунок на нову схему без перезапуску. Що відбувається на сервері, див. у [рушій міграцій](/uk/internals/migrations/).

## Збірка й поширення

- `ng build` записує production-збірку в `admin/dist/admin/browser` з `<base href="/admin/">`.
- Сервер вбудовує цю папку через `rust-embed`, коли його скомпільовано з feature `embed-admin`, яку використовують релізні збірки й образ Docker. Без цієї feature або коли задано `[admin].assets_dir`, він віддає файли з диска. `assets_dir` має пріоритет над вбудованою збіркою.
- Сервер переписує `<base href>` на `[admin].path` і вставляє конфігурацію часу виконання як тег `<meta>`, а не як inline-скрипт. Зміна `admin.path` ніколи не потребує перезбирання панелі.
- Невідомі шляхи без розширення файлу відкочуються до `index.html` для клієнтської маршрутизації. Бандли з відбитком (`main-ABC123.js`) кешуються як `immutable` на рік; усе інше — `no-cache`.
- Кожна відповідь адмінки містить строгу Content Security Policy (`script-src 'self'`, `frame-ancestors 'none'`, `base-uri 'self'`…), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` і `Referrer-Policy: strict-origin-when-cross-origin`. Вбудовування critical CSS в Angular вимкнено в `angular.json`, бо воно покладається на inline-обробники подій, які політика забороняє.

Для роботи над фронтендом запустіть сервер, потім `npm start` в `admin/`: `ng serve` проксіює `/admin/api` і `/api` на `http://localhost:1337` (`admin/proxy.conf.json`).

## Переклади

Панель перекладається під час виконання за допомогою Transloco, а не i18n Angular під час компіляції, тож одна збірка обслуговує всі мови, а користувачі можуть перемикатися без перезавантаження.

- Каталоги — плоскі JSON-файли в `admin/public/i18n/` (`en.json` — джерело), що завантажуються на вимогу.
- Повідомлення використовують ICU MessageFormat (`{name}`, `{count, plural, one {# entry} other {# entries}}`), який інтерпретує FormatJS (`intl-messageformat`) через власний транспайлер Transloco. FormatJS інтерпретує повідомлення, а не компілює їх у функції, тож CSP не потребує `unsafe-eval`.
- Ключі повідомлень типізовано з `en.json` (`core/i18n/keys.ts`): використання неіснуючого ключа — помилка компіляції.
- `npm run i18n:check` перевіряє кожен каталог щодо `en.json`: ті самі ключі, коректний синтаксис ICU, ті самі аргументи й усі категорії множини мови. CI запускає цю перевірку.
- Сервіс `I18n` також надає форматування з урахуванням локалі й перший день тижня, узяті з регіональних налаштувань браузера з можливістю перевизначення для кожного користувача.

Як додати чи оновити мову, описано в [перекладі](/uk/project/translating/).
