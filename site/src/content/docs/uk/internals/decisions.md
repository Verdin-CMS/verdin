Цей журнал фіксує проєктні рішення, що сформували Verdin, у порядку їх ухвалення, щоб ви могли побачити, чому код саме такий, перш ніж пропонувати його змінити. Записи збережено такими, як їх написано, включно з назвами етапів (M2–M4 — це етапи перед першими релізами); пізніший запис може уточнювати попередній, як 28 уточнює 1. Додавайте новий рядок, коли ухвалюєте рішення, яке інакше комусь довелося б відновлювати з коду.

| № | Рішення | Результат | Обґрунтування |
|---|---|---|---|
| 1 | Компоненти: JSON чи таблиці | **JSON-колонка** ([сховище](/uk/internals/storage/#компоненти-й-динамічні-зони-json-колонка)) | Менше join-ів, тривіальні публікація й версіонування, простіші міграції. Фільтрування за повторюваними компонентами рідкісне; його можна додати пізніше через JSON-функції |
| 2 | JSON-кодування `decimal` | Типово **число**, `api.decimal_as_string` за бажанням | Сумісність зі Strapi максимізує прийняття; точні значення доступні, коли потрібні |
| 3 | Форми адмінки | **Signal Forms** | Пасує до zoneless-адмінки, побудованої передусім на signals; динамічні дерева форм виводяться зі схеми |
| 4 | Мова | **Англійська** для коду, документації й комітів | Охоплення відкритого коду |
| 5 | Сумісність із REST Strapi | **Ті самі параметри й формат відповіді**; розширення лише Verdin — під `actions/` | Фронтенди мігрують із мінімальними змінами |
| 6 | Алгоритм JWT адмінки | HS256 | Один секрет, просто; EdDSA, якщо колись з'являться зовнішні перевіряльники |
| 7 | ID документів | ULID (26 символів) | Сортовані й переносні; власні id Strapi — непрозорі рядки з 24 символів, клієнти їх ніколи не розбирають |
| 8 | Вміст знімка | Фізична модель, а не схема | Пізніші версії можуть виводити нові таблиці з незмінної схеми |
| 9 | Nullability атрибутів | Завжди nullable; `required` перевіряється під час публікації | Чернетки можуть бути неповними (поведінка Strapi v5); додавання обов'язкових полів безпечне |
| 10 | Забезпечення `unique` | Унікальний індекс за `(column, locale, publication_state)` | Без гонок; чернетки та їхня опублікована версія мають спільні значення |
| 11 | Назва колонки стану | `publication_state` | `state` — поширена назва атрибута |
| 12 | Зарезервовані слова SQL | Завжди брати ідентифікатори в лапки | Без довільного чорного списку назв атрибутів |
| 13 | Побудова DML | Власний білдер замість `sea-query` | Переважають подробиці діалектів (типізовані NULL, колації, формати SQLite); на одну абстракцію менше |
| 14 | Запис без `?status=draft` | Публікація (поведінка REST у Strapi v5) | Пряма сумісність для наявних клієнтів |
| 15 | Порівняння тексту | Типово точне в кожному рушії; оператори `…i` — без урахування регістру | Однакові результати в MySQL і PostgreSQL |
| 16 | Тимчасовий контроль доступу (M2–M3) | Перемикач `[api].open_access`, прибраний у M4 | Безпечно за замовчуванням, доки не з'явилися дозволи |
| 17 | «Ціль належить одному документу» | Забезпечується перенесенням цілі, для кожного стану | Унікальний індекс заборонив би чернетці та її опублікованій версії мати спільну ціль |
| 18 | Зворотні сторони (`mappedBy`) | Лише читання | Запис через них неоднозначний із чернетками й публікацією (яка версія власника?) |
| 19 | Позиції посилань | Перенумеровуються 1..n під час кожного запису | Без вичерпання float; списки невеликі |
| 20 | Рядки таблиць зв'язків | Зберігати первинний ключ `id` | Однорідні таблиці для рушія міграцій і перебудов SQLite |
| 21 | Бібліотека JWT | Власний HS256 (HMAC-SHA256, перевірка за сталий час, закріплений `alg`) | `jsonwebtoken` 11 потребує криптобекенду, що тягне RSA |
| 22 | Таблиці платформи | Виводяться разом із моделлю вмісту | Один механізм міграцій для всього |
| 23 | Повторне використання refresh token | Відкликати всю родину, без вікна поблажливості | Просто й суворо; адміністратор знову входить |
| 24 | Чернетки через API вмісту | Окремий дозвіл `readDrafts` | Токени, що читають опублікований вміст, не розкривають чернетки |
| 25 | Порядок застосування в конструкторі | Мігрувати, потім записати файли, потім гаряче підмінити застосунок | Невдала міграція не зачіпає файли й запущений застосунок |
| 26 | Записи з адмінки | Зберігати лише чернетки; публікація — явна дія | Відповідає очікуванням редакторів; API вмісту зберігає публікацію за замовчуванням, як у Strapi |
| 27 | Конфігурація адмінки під час виконання | Тег `<meta>`, а не inline-скрипт | CSP лишається без скриптів `unsafe-inline` |
| 28 | Фільтри за полями компонентів | Оператори JSON-шляхів для кожного діалекту (`#>>`, `JSON_VALUE`, `json_extract`); `EXISTS` за елементами масиву для повторюваних компонентів і динамічних зон (0.8) | Динамічні зони — лише за `__component`: їхні елементи мають різні поля |
| 29 | i18n адмінки | Transloco з плоскими JSON-каталогами (`admin/public/i18n`) і ICU MessageFormat через FormatJS (власний транспайлер) за невеликим фасадом `I18n`; не i18n Angular під час компіляції | Перемикання мови під час виконання; стандартні файли для Weblate/Crowdin; FormatJS інтерпретує повідомлення, тож строга CSP не потребує `unsafe-eval` (`@messageformat/core` компілює через `new Function`); ключі типізовано з `en.json`, повноту перевіряє `npm run i18n:check` |
| 30 | Початок тижня | `Intl.Locale#getWeekInfo` для регіонального тегу браузера (en-GB ≠ en-US), запасна таблиця регіонів, перевизначення користувачем | Відповідає регіону кожного користувача, навіть коли мова інтерфейсу спільна |
| 31 | Зберігання макета панелі | JSON-колонка `preferences` для кожного користувача у `vd_admin_users` (≤ 64 KiB) | Слідує за користувачем у різних браузерах; тема й мова лишаються в `localStorage`, бо застосовуються до входу |
| 32 | Типове `Secure` для refresh cookie | Увімкнено в `start`, вимкнено в `dev`, можна перевизначити | `verdin dev` через звичайний HTTP працює в кожному браузері; production лишається строгим |
| 33 | Профіль release | Thin LTO, 1 codegen unit, stripped; unwinding збережено | Обробник, що панікує, не має класти сервер |
| 34 | «Непереглянуті» документи | Рядки `vd_document_views` для кожного користувача, що видаляються для всіх, крім редактора, коли документ змінюється; фільтруються через `NOT EXISTS` у SQL | Пагінація й підрахунки лишаються точними; не треба порівнювати мітки часу для кожного рядка |
| 35 | Голосування й опитування | Таблиці співпраці лише для адмінки (`vd_document_votes`, `vd_polls`, `vd_poll_votes`), для будь-якого типу вмісту | Скриньки пропозицій і командні рішення без моделювання полів голосування в кожній схемі |
| 36 | Медіасховище | `object_store` для локального й S3 | Один шлях коду; потокові multipart-завантаження; RustFS у dev-стеку та CI |
| 37 | Медіапосилання | Таблиці зв'язків для кожного поля, як у зв'язків | Та сама семантика чернеток/публікації, що й у зв'язків; каскади тримають посилання узгодженими |
| 38 | Оновлення вбудованих дозволів | Маркер версії у `vd_settings`, доповнення застосовуються один раз | Наявні інсталяції отримують нові дозволи, не скасовуючи пізніших правок адміністратора |
| 39 | Функції під час виконання | Каталог у `verdin-api`, перемикачі у `vd_settings` (`features`), застосунок перебудовується на місці (ArcSwap) у кожному режимі | Перемикачі плагінів як у Strapi без перезапусків; недоступні функції перелічено з запланованою версією |
| 40 | UI довідника API | Scalar (`scalar_api_reference`, бандл вбудовано) на `{api}/docs`, лише коли документ публічний; CSP дозволяє його inline bootstrap за хешем | Самохостинг (без CDN, шрифтів, ШІ-агента чи телеметрії); документ типово лишається доступним лише з токеном |
| 41 | GraphQL | Динамічна схема `async-graphql`, що будується разом із застосунком; аргументи й вибірки перетворюються на дерево параметрів REST і розбираються тим самим парсером запитів | Один набір правил для фільтрів, пагінації, populate, валідації й дозволів у REST і GraphQL; populate, виведений із вибірки, зберігає пакетне завантаження |
| 42 | Події документів | Слухачі на Document Service, що викликаються після commit | Побічні ефекти (позначки перегляду, майбутні вебхуки) застосовуються до кожного API без хуків в окремих обробниках |
