Ця сторінка — повний контракт між Verdin і плагіном: маніфест, що Verdin надсилає кожній
експортованій функції й чого очікує у відповідь, а також функції хоста, які може викликати
модуль. Вступ див. у [Плагіни](/uk/extending/plugins/); розібраний приклад — у
[посібнику з плагінів](/uk/extending/plugin-tutorial/).

## Каталог плагіна

Кожен плагін — це каталог у `[plugins].path` (типово `plugins/`, поруч із `verdin.toml`):

| Файл | Обов'язковий | Вміст |
| --- | --- | --- |
| `plugin.toml` | так | Маніфест. |
| `plugin.wasm` | так | Модуль (інший шлях — через `wasm`). |
| `admin/` | ні | Файли, які завантажує адмін-панель: модуль `admin.script` і його ресурси. |

Під час запуску Verdin завантажує кожен каталог із `plugin.toml` в алфавітному порядку назв.
Каталог пропускається й показується з причиною в **Налаштування → Плагіни**, коли його маніфест
некоректний, модуля немає або інший плагін уже має таке `name`.

## Маніфест

```toml title="plugins/slugs/plugin.toml"
name = "slugs"
version = "1.0.0"
description = "Slugs from titles, and a color field"

[capabilities]
read = ["api::article"]
write = ["api::tag"]
http = ["api.example.com"]
kv = true

[limits]
timeout_ms = 5000
memory_mb = 64

[[hooks]]
on = "beforeCreate"
uid = "api::article"
function = "before_write"

[routes]
function = "handle"

[[jobs]]
schedule = "*/15 * * * *"
function = "refresh"

[[graphql]]
name = "slugStats"
function = "stats"

[admin]
script = "index.js"

[[admin.widgets]]
id = "stats"
title = "Slug stats"
element = "slugs-stats"

[[admin.fields]]
id = "color"
title = "Color"
element = "slugs-color"
type = "string"

[[settings]]
key = "separator"
label = "Separator"
type = "select"
options = ["-", "_"]
default = "-"
```

Невідомі ключі — помилки в усіх таблицях.

### Ключі верхнього рівня

| Ключ | Типово | Опис |
| --- | --- | --- |
| `name` | обов'язковий | Id плагіна в URL, налаштуваннях і власних полях: малі літери, цифри й `-`, починається з літери, щонайбільше 64 символи. |
| `version` | обов'язковий | Показується в адмінці та журналі. |
| `description` | не задано | Показується в **Налаштування → Плагіни**. |
| `wasm` | `"plugin.wasm"` | Модуль відносно каталогу плагіна (без `..`, не абсолютний). |
| `wasi` | `false` | Дати модулю WASI: годинник і випадкові числа. Файлів і сокетів немає в жодному разі. |

### `[capabilities]`

| Ключ | Типово | Опис |
| --- | --- | --- |
| `read` | `[]` | Типи вмісту, які може читати `verdin_content` (`findMany`, `findOne`): uid на кшталт `api::article` або `"*"` для всіх. |
| `write` | `[]` | Типи вмісту, для яких він може `create`, `update`, `delete`, `publish` і `unpublish`. Передбачає `read`. |
| `http` | `[]` | Хости, на які модуль може надсилати HTTP-запити: `api.example.com` або `*.example.com`. |
| `kv` | `false` | Власне сховище ключ-значення плагіна (`verdin_kv_get`, `verdin_kv_set`). |

Можливості обмежують лише виклики хоста. Хуки виконуються для названих у них типів незалежно
від `read`, а маршрути доступні будь-кому.

### `[limits]`

| Ключ | Типово | Опис |
| --- | --- | --- |
| `timeout_ms` | `5000` | Обмеження часу одного виклику в мілісекундах. |
| `memory_mb` | `64` | Найбільший обсяг пам'яті модуля в мегабайтах. |

Обидва мають бути додатними.

### `[[hooks]]`

| Ключ | Типово | Опис |
| --- | --- | --- |
| `on` | обов'язковий | Подія, див. нижче. |
| `uid` | `"*"` | Тип вмісту (`api::article`) або `"*"` для всіх. |
| `function` | обов'язковий | Експортована функція, яку треба викликати. |

Події:

| До запису | Після запису |
| --- | --- |
| `beforeCreate` | `afterCreate` |
| `beforeUpdate` | `afterUpdate` |
| `beforeDelete` | `afterDelete` |
| `beforePublish` | `afterPublish` |
| `beforeUnpublish` | `afterUnpublish` |
| `beforeDiscardDraft` | `afterDiscardDraft` |

Назви відповідають назвам lifecycle у Strapi. Хуки виконуються під час записів з адмін-панелі,
REST і GraphQL API та релізів, але не під час записів, зроблених плагінами (див.
[Записи, зроблені плагінами](#записи-зроблені-плагінами)), чи командами `verdin import`.

### `[routes]`

| Ключ | Опис |
| --- | --- |
| `function` | Експортована функція, що обслуговує кожен запит до `/api/plugins/<name>` і `/api/plugins/<name>/…` будь-яким методом. |

Шлях враховує `[api].prefix`.

### `[[jobs]]`

| Ключ | Опис |
| --- | --- |
| `schedule` | Cron-вираз в UTC з необов'язковими секундами: `*/15 * * * *`, `0 0 3 * * *`. |
| `function` | Експортована функція, яку треба викликати. |

### `[[graphql]]`

| Ключ | Типово | Опис |
| --- | --- | --- |
| `name` | обов'язковий | Назва поля: починається з малої літери, далі літери, цифри й `_`. |
| `function` | обов'язковий | Експортована функція, що його розв'язує. |
| `mutation` | `false` | Додати поле до `Mutation` замість `Query`. |
| `description` | не задано | Опис поля в схемі. |

Кожен запис додає `name(args: JSON): JSON`. Назва, яку вже використовує тип вмісту або яку
раніше зайняв інший плагін, пропускається з попередженням у журналі.

### `[admin]`

| Ключ | Опис |
| --- | --- |
| `script` | ES-модуль в `admin/`, що визначає custom elements (без `..`, не абсолютний). |
| `[[admin.widgets]]` | Типи віджетів панелі: `id`, `title`, `element`, необов'язковий `description`. |
| `[[admin.fields]]` | Власні поля: `id`, `title`, `element`, `type` (тип атрибута, у якому зберігається значення, наприклад `string` або `json`), необов'язковий `description`. |

`element` — це назва custom element: малі літери, цифри й `-`, щонайменше один `-`
(`slugs-color`).

### `[[settings]]`

Оголошує форму **Налаштування → Плагіни → Налаштування**. Без жодного запису налаштування — це
довільний JSON-об'єкт.

| Ключ | Типово | Опис |
| --- | --- | --- |
| `key` | обов'язковий | Ключ в об'єкті налаштувань: літери, цифри й `_`, не починається з цифри, унікальний. |
| `label` | обов'язковий | Підпис у формі. |
| `type` | `"string"` | `string`, `text`, `url`, `number`, `integer`, `boolean` або `select`. |
| `description` | не задано | Текст підказки під полем. |
| `required` | `false` | Потрібне значення (непорожнє для тексту), якщо немає `default`. |
| `options` | `[]` | Варіанти для `select` (для нього обов'язкові). |
| `default` | не задано | Використовується, коли ключа немає або він `null`. Має відповідати полю. |
| `min`, `max` | не задано | Межі значень `number` і `integer`; межі довжини `string` і `text`. |

Значення `url` порожні або є URL `http(s)://`. Коли є форма, сервер відхиляє налаштування з
невідомими ключами, неправильними типами, значеннями поза межами чи відсутніми обов'язковими
значеннями (400).

## Експортовані функції

Кожна експортована функція приймає один JSON-документ і повертає один (або нічого). Порожній
вивід вважається `null`; вивід, що не є JSON, вважається збоєм.

### Хуки before

Вхід:

```json
{
  "event": "beforeUpdate",
  "uid": "api::article",
  "documentId": "01m3p88ry359w82nsx496mep5t",
  "locale": "en",
  "data": { "title": "Hello" }
}
```

| Поле | Опис |
| --- | --- |
| `event` | Подія хука. |
| `uid` | Тип вмісту. |
| `documentId` | Документ або `null` у `beforeCreate`. |
| `locale` | У локалізованих типах — локаль запису (типова локаль, якщо запит її не назвав); `null` в інших типах. |
| `data` | Дані, що записуються, у тому вигляді, як їх надіслав запит: під час створення й оновлення. `null` для інших подій. Під час оновлення — лише надіслані поля. |

Вихід:

| Вихід | Результат |
| --- | --- |
| `{ "data": { … } }` | Замінює дані, що записуються. Вони валідуються так само, як оригінал. |
| `{ "error": "message" }` | Відхиляє запис: клієнт отримує 400 з повідомленням. |
| `{}` або будь-що інше | Запис продовжується без змін. |

Коли збігається кілька хуків, вони виконуються в порядку плагінів (назв каталогів), а потім у
порядку маніфесту; кожен бачить дані, які повернув попередній. Хук, що падає (trap, тайм-аут,
некоректний вивід), записується в журнал і пропускається: запис продовжується.

### Хуки after

Вхід: `{ "event", "uid", "documentId", "locale" }`, надсилається після фіксації запису. Вивід
ігнорується; збої записуються в журнал. Прочитайте запис через `verdin_content`, якщо потрібні
його поля (з можливістю `read`).

### Маршрути

Вхід:

```json
{
  "method": "GET",
  "path": "/stats",
  "query": "page=2&sort=title",
  "headers": { "accept": "application/json", "user-agent": "curl/8.7.1" },
  "body": "",
  "actor": { "kind": "public" }
}
```

| Поле | Опис |
| --- | --- |
| `method` | HTTP-метод. |
| `path` | Шлях після `/api/plugins/<name>`, що починається з `/` (`/` для кореня плагіна). |
| `query` | Сирий рядок запиту без `?` (порожній, якщо його немає). |
| `headers` | Лише `content-type`, `accept`, `user-agent` і `accept-language`, якщо вони є. |
| `body` | Тіло запиту як рядок (некоректний UTF-8 замінюється). |
| `actor` | Хто викликає: `{ "kind": "public" }`, `{ "kind": "token", "id": 3 }` (API-токен) або `{ "kind": "user", "id": 12 }` (кінцевий користувач, що увійшов). |

Заголовок `Authorization` з недійсним токеном відхиляється з 401 ще до виклику плагіна.
Дозволи публічного доступу й API-токенів не застосовуються: перевіряйте `actor` самі.

Вихід:

| Поле | Типово | Опис |
| --- | --- | --- |
| `status` | `200` | HTTP-статус. |
| `headers` | немає | Заголовки відповіді. Зберігаються лише `content-type`, `cache-control`, `location`, `etag`, `last-modified` і `content-disposition`. |
| `body` | порожнє | Рядок надсилається як є (`text/plain`, якщо ви не задали `content-type`); будь-яке інше JSON-значення надсилається як `application/json`. |

Вимкнений або невідомий плагін чи плагін без `[routes]` відповідає 404. Невдалий виклик
відповідає 502 з `{ "data": null, "error": { "status": 502, "name": "PluginError", … } }`.
Маршрути мають спільні з API вмісту `[server].body_limit` і `[server].request_timeout_secs`.

### Завдання

Вхід: `{ "scheduledAt": "2026-09-29T03:00:00+00:00" }` — час, на який запуск було заплановано.
Вивід ігнорується; збої записуються в журнал. Завдання виконуються лише тоді, коли плагін
увімкнено, і лише на екземплярах з `[plugins].run_jobs = true`. Запуск, пропущений, поки сервер
не працював, не надолужується.

### Поля GraphQL

Вхід: `{ "args": …, "actor": … }`, де `args` — аргумент `args` поля (будь-який JSON або `null`),
а `actor` — як для маршрутів. Вивід — значення поля. Збій або вимкнений плагін дає помилку
GraphQL з кодом `PLUGIN_ERROR`. Як і з маршрутами, доступ перевіряє плагін.

## Функції хоста

Імпортуйте їх із простору імен `extism:host/user` (`extern "ExtismHost"` у Rust). Вони
приймають і повертають JSON як рядки; `Json<Value>` в `extism-pdk` бере перетворення на себе.

| Функція | Вхід | Вихід |
| --- | --- | --- |
| `verdin_log` | `{ "level": "info" \| "warn" \| "error", "message": "…" }` | немає |
| `verdin_content` | Запит до вмісту (див. нижче) | Результат або `{ "error": "…" }` |
| `verdin_kv_get` | Ключ як звичайний рядок | Збережене JSON-значення або `null` |
| `verdin_kv_set` | `{ "key": "…", "value": … }` | немає |
| `verdin_config` | немає | Об'єкт налаштувань із заповненими оголошеними типовими значеннями |

### `verdin_log`

Пише в журнал сервера (з назвою плагіна) і в журнал плагіна в **Налаштування → Плагіни →
Журнал**. Інші рівні вважаються `info`. Журнал плагіна зберігає в пам'яті останні 200
повідомлень, кожне обрізане до 2 000 символів.

### `verdin_content`

```json
{ "op": "findMany", "uid": "api::article", "query": { "filters": { "title": { "$eq": "x" } }, "sort": ["title"] } }
```

| Поле | Використовують | Опис |
| --- | --- | --- |
| `op` | усі | `findMany`, `findOne`, `create`, `update`, `delete`, `publish` або `unpublish`. |
| `uid` | усі | Тип вмісту. Має бути в можливостях. |
| `documentId` | `findOne`, `update`, `delete`, `publish`, `unpublish` | Документ. |
| `query` | `findMany`, `findOne` | Параметри REST API як JSON-об'єкт: `filters`, `sort`, `fields`, `populate`, `pagination`, `status`. |
| `data` | `create`, `update` | Поля для запису, як у `data` REST-запиту. |
| `status` | `create`, `update` | `"draft"` зберігає чернетку. Інакше запис публікується, як REST-запис без `?status=draft`. |
| `locale` | усі | Локаль для читання чи запису. |

Результати:

| `op` | Результат |
| --- | --- |
| `findMany` | `{ "documents": [...], "meta": { "pagination": {…} } }` |
| `findOne` | `{ "document": {…} }` (`null`, якщо не знайдено) |
| `create`, `update` | `{ "documentId": "…" }` |
| `delete` | `{ "deleted": true }` |
| `publish` | `{ "published": true }` |
| `unpublish` | `{ "unpublished": true }` |

Виклик поза можливостями, невідома операція, помилка валідації чи відсутній документ натомість
дають `{ "error": "…" }`. Читання повертає опубліковані версії, якщо запит не просить
`"status": "draft"`.

#### Записи, зроблені плагінами

Записи через `verdin_content` пропускають хуки **before** усіх плагінів, тож плагін не може
зациклитися там на власних змінах. Усе інше діє: валідація, етапи перевірки, вебхуки, історія,
журнал аудиту й хуки **after** усіх плагінів, включно з тим, що пише. Захищайте хук after, який
пише в тип, за яким сам стежить.

### `verdin_kv_get` і `verdin_kv_set`

Сховище ключ-значення для кожного плагіна в базі даних Verdin, спільне для всіх екземплярів.
Ключі мають від 1 до 255 байтів; значення — будь-який JSON. Запис `null` видаляє ключ. Без
можливості `kv` читання повертає `null`, а записи ігноруються.

### `verdin_config`

Повертає налаштування, збережені в **Налаштування → Плагіни**, із заповненим `default` кожного
оголошеного налаштування для відсутніх ключів. `{}`, якщо нічого не збережено.

### HTTP

З хостами, переліченими в `http`, використовуйте HTTP-підтримку Extism
(`extism_pdk::http::request` у Rust). Запити до інших хостів не вдаються.

## Точки розширення адмінки

Адмін-панель запитує в сервера розширення ввімкнених плагінів і один раз імпортує кожен
`admin.script` як ES-модуль з `/admin/plugins/<name>/<script>` (під `[admin].path`). Файли з
каталогу `admin/` плагіна віддаються там, поки плагін увімкнено, з
`X-Content-Type-Options: nosniff` і `Cache-Control: no-cache`. Модуль має визначити custom
elements, які називає маніфест; елемент, не визначений протягом 3 секунд, пропускається.

### Віджети

Кожен запис `[[admin.widgets]]` — це тип віджета, який адміністратори можуть додати на панель.
Елемент отримує властивість `context`:

| Властивість | Опис |
| --- | --- |
| `apiBase` | Базова адреса API вмісту, наприклад `/api`. |
| `adminApiBase` | Базова адреса admin API, наприклад `/admin/api`. |
| `fetch(path, init)` | `fetch` з обліковими даними адміністратора, що увійшов. Відносні шляхи розв'язуються відносно `adminApiBase`; шляхи під будь-якою з баз і абсолютні URL залишаються як є. |

```js title="plugins/slugs/admin/index.js"
class SlugStats extends HTMLElement {
  set context(context) {
    // Admin API, with the admin's session.
    context.fetch('auth/me').then((response) => response.json())
      .then(({ data }) => { this.textContent = `Hello ${data.firstname ?? data.email}`; });
    // The plugin's own route, on the content API: sent without the admin's session.
    context.fetch(`${context.apiBase}/plugins/slugs/stats`).then((response) => response.json())
      .then((stats) => { this.title = JSON.stringify(stats); });
  }
}
customElements.define('slugs-stats', SlugStats);
```

`context.fetch` надсилає сесію адміністратора лише із запитами до admin API. Шляхи під
`context.apiBase` (API вмісту, включно з маршрутами вашого плагіна) йдуть без неї, бо API
вмісту не приймає сесії адміністраторів; на них відповідають із дозволами публічної ролі. До
0.10 сесія надсилалася й туди, і ці запити не вдавалися; віджети, написані для 0.9, що
викликають звичайний `fetch`, працюють і далі.

### Власні поля

Кожен запис `[[admin.fields]]` — це поле, яке атрибути можуть використовувати через
`"customField": "plugin::<name>.<id>"`; `type` атрибута має відповідати тому, як поле зберігає
значення. **Конструктор типів вмісту** пропонує його. Елемент отримує:

| Властивість | Опис |
| --- | --- |
| `value` | Поточне значення. |
| `disabled` | Чи вимкнено редагування. |
| `attribute` | Визначення атрибута зі схеми. |
| `locale` | Локаль, що редагується. |

Він повідомляє нове значення подією `change`, чий `detail` — це значення (або, без `detail`,
через власну властивість `value`). Коли плагін вимкнено або його елемента немає, редактор
показує звичайне поле для типу зберігання. Див. [Типи атрибутів](/uk/reference/attribute-types/).

## Середовище виконання й обмеження

| Обмеження | Значення |
| --- | --- |
| Час на виклик | `[limits].timeout_ms`, типово 5 000 мс |
| Пам'ять | `[limits].memory_mb`, типово 64 МБ |
| Паралельність | Один виклик одночасно на плагін; виклики чекають один на одного |
| Екземпляр модуля | Один на плагін, створюється під час першого використання; перестворюється після невдалого виклику (його пам'ять втрачається) |
| Журнал | 200 повідомлень на плагін, по 2 000 символів, у пам'яті |
| Ключі KV | Від 1 до 255 байтів |
| Заголовки запиту маршруту | `content-type`, `accept`, `user-agent`, `accept-language` |
| Заголовки відповіді маршруту | `content-type`, `cache-control`, `location`, `etag`, `last-modified`, `content-disposition` |

Зміни маніфесту чи модуля застосовуються після перезапуску; перемикачі й налаштування — одразу.
Керування плагінами потребує `plugins.manage` (див. [довідник дозволів](/uk/reference/permissions/)).
