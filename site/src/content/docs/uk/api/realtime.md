Verdin транслює зміни вмісту й медіа в момент їх фіксації через
[Server-Sent Events](https://developer.mozilla.org/docs/Web/API/Server-sent_events) (SSE).
Кожен підписник отримує лише події про те, що він має право читати. На цій сторінці описано
протокол; про використання у фронтенді див. [Оновлення в реальному часі](/uk/guides/frontend/realtime/).

## Увімкнення

Типово реальний час вимкнено. Увімкніть його в **Налаштування → Функції → У реальному часі**
(дозвіл `features.manage`). Поки функцію вимкнено, ендпоінти відповідають `404`.

## Потік вмісту

```
GET /api/_events
GET /api/_events?types=api::article,api::category
```

| Параметр | Опис |
| --- | --- |
| `types` | Необов'язковий, UID типів вмісту через кому; `plugin::upload` — це медіатека. Форма Strapi `api::article.article` теж працює. Без нього ви отримуєте всі типи, які маєте право читати. |

Автентифікуйтеся так само, як у REST API: API-токен або JWT кінцевого користувача в
`Authorization: Bearer …` чи без заголовка для публічного доступу. Недійсний токен дає `401`
ще до відкриття потоку.

```sh title="Terminal"
curl -N -H "Authorization: Bearer $VERDIN_TOKEN" \
  'https://cms.example.com/api/_events?types=api::article'
```

```text
event: ready
data: {}

event: entry.publish
data: {"event":"entry.publish","uid":"api::article","documentId":"k2m7q4dx8n5t1v3b9c0e6a2wfr","locale":"en"}

event: media.create
data: {"event":"media.create","uid":"plugin::upload","documentId":"v3k9…","fileId":5}
```

## Повідомлення

Перша подія — завжди `ready`. Далі кожна зміна — це SSE-подія з відповідною назвою, чиє поле
`data` є JSON-об'єктом:

| Поле | Присутнє | Опис |
| --- | --- | --- |
| `event` | завжди | Назва події, як у рядку SSE `event:`. |
| `uid` | завжди | UID типу вмісту або `plugin::upload` для медіа. |
| `documentId` | завжди | Змінений документ або файл. |
| `locale` | локалізовані типи | Локаль версії, яка змінилася. |
| `fileId` | медіаподії | Числовий id файлу, як у медіаполях. |
| `actorId` | потік адмін-панелі | Адміністратор, який зробив зміну, якщо її зробив адміністратор. |

| Події | Коли надсилаються | Хто їх отримує |
| --- | --- | --- |
| `entry.create`, `entry.update`, `entry.discard-draft` | Документ створено, збережено або його чернетку відкинуто | У типах із чернетками й публікацією — клієнти з `readDrafts` (ці події змінюють лише чернетки). В інших типах — клієнти з `find` або `findOne`. |
| `entry.publish`, `entry.unpublish`, `entry.delete` | Документ опубліковано, знято з публікації або видалено | Клієнти з `find` або `findOne` для типу |
| `media.create`, `media.update`, `media.delete` | Файл завантажено, відредаговано або видалено | Клієнти з `find` або `findOne` для медіатеки |

Події містять id, а не вміст. Щоб прочитати документ або файл, отримайте його через REST або
GraphQL API зі звичайними дозволами клієнта. Події надходять від усіх API: REST, GraphQL,
адмін-панелі, релізів і плагінів.

## Тривалість з'єднання

- Сервер надсилає keep-alive коментар кожні 15 секунд.
- Потік вмісту завершується через годину. Перепідключіться (`EventSource` у браузерах робить
  це сам) — при цьому токен перевіряється знову.
- Подія `lagged` з `data: {"missed": 12}` означає, що клієнт читав надто повільно і стільки
  подій було втрачено. Перезавантажте те, що показує клієнт.
- Повторного відтворення немає: події, що сталися, поки клієнт був відключений, пізніше не
  надсилаються.

`EventSource` у браузерах не вміє надсилати заголовок `Authorization`. Для публічного доступу
він працює як є; з токеном використовуйте `fetch` із потоковим читанням тіла або SSE-клієнт,
що підтримує заголовки.

## Потік адмін-панелі

Адмін-панель відкриває власний потік з access token адміністратора:

```
GET /admin/api/events?types=api::article
```

Він передає ті самі події вмісту й медіа для типів, які адміністратор може читати (з
`content.read` і `media.read`), включно з чернетками, а також:

- `actorId` у змінах, зроблених адміністраторами;
- події `presence` (див. нижче);
- `comment.create`, `comment.update`, `comment.delete`, `comment.resolve`,
  `comment.reopen`, `task.create`, `task.update` і `task.delete` з `uid`,
  `documentId` і `locale` запису.

Потік адмін-панелі завершується через 15 хвилин — стільки живе access token:
перепідключіться з новим.

### Присутність

Редактор запису повідомляє серверу, хто працює із записом:

```
POST /admin/api/presence
{ "uid": "api::article", "documentId": "k2m7q4…", "locale": "en", "editing": true }
```

- Надсилайте це приблизно кожні 20 секунд, поки редактор відкритий. `editing: true` означає,
  що в адміністратора є незбережені зміни. Надішліть `"leave": true`, коли редактор закривається.
- Присутність спливає через 45 секунд після останнього heartbeat.
- Відповідь перелічує, хто працює із записом: `{ "data": [{ "userId": 3, "name": "Ada Lovelace", "editing": true, "holdsLock": true }] }`.
- `GET /admin/api/presence?uid=&documentId=&locale=` читає той самий список.
- Коли список змінюється, потоки адмін-панелі отримують подію `presence` з `uid`,
  `documentId`, `locale` запису та списком у `presence`.

Перший адміністратор, який досі редагує, тримає м'яке блокування (`holdsLock`). Редактор
показує його іншим, але воно не заважає їм зберігати. Для читання присутності потрібен
`content.read` для типу.

## Кілька екземплярів

Події та присутність належать тому екземпляру, до якого підключено клієнт. За балансувальником
навантаження спрямовуйте `/api/_events` і `/admin/api/events` зі sticky sessions або
підключайте клієнтів реального часу до одного екземпляра. Див. [Масштабування](/uk/deploy/scaling/).
