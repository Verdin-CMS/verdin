У цьому посібнику ви створите блог на [Next.js](https://nextjs.org) з App Router, що читає вміст
із Verdin: домашню сторінку зі списком статей, окрему сторінку для кожної статті на
`/articles/<slug>` з її категорією і, за бажання, сторінку, що показує чернетки за посиланням
попереднього перегляду з адмінки. Ви використаєте типізований клієнт `@verdin/client` із
типами, згенерованими зі схеми, у Server Components.

Написано для Next.js 16.3 (`create-next-app` 16.3), React 19.2 і Node.js 20.9 або новішого, з
Verdin і `@verdin/client` 0.10. Використовується типове кешування Next.js, без
`cacheComponents`. [Посібник з Astro](/uk/start/tutorial-astro/) будує той самий блог на Astro.

## Перш ніж почати

Вам потрібні бінарник `verdin` у `PATH` (див. [Швидкий старт](/uk/start/quickstart/)), Node.js і
Git. У результаті матимете дві папки поруч: `cms` — проєкт Verdin і `blog` — застосунок
Next.js.

## 1. Налаштуйте Verdin зі схемою блогу

Проєкт [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog)
репозиторію моделює блог: статті із заголовком, `slug`, коротким описом, тілом `body` у
Markdown, категорією й тегами, а також поодинокий тип homepage і кілька компонентів.

<Steps>

1. Створіть проєкт Verdin і скопіюйте в нього схему прикладу:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Запустіть його:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   Перший запуск створює таблиці для чотирьох типів вмісту.

3. Відкрийте [http://localhost:1337/admin/](http://localhost:1337/admin/) і створіть першого
   адміністратора.

4. У розділі **Колекції** відкрийте **Category**, виберіть **Новий запис**, назвіть його `News`
   і збережіть.

5. Відкрийте **Article**, виберіть **Новий запис** і заповніть заголовок, короткий опис і тіло в
   Markdown. `slug` генерується із заголовка. Виберіть категорію `News` і виберіть
   **Опублікувати**. Додайте так само другу статтю.

6. Відкрийте **Налаштування → Публічний доступ**, дозвольте **Знайти** і **Знайти один** для
   **Article** і **Category** та виберіть **Зберегти**.

</Steps>

Перевірте, що API відповідає:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Заповнення зв'язку потребує доступу на читання до його цілі. Без **Знайти** для **Category**
`populate=category` відповідає `400` з ``invalid key `category` in populate``.
</Aside>

## 2. Створіть застосунок Next.js

У новому терміналі, поруч із `cms`:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) перетворює Markdown поля `body` на HTML.

## 3. Згенеруйте типи

`verdin types` читає схему й записує по TypeScript-інтерфейсу на кожен тип вмісту й компонент,
а також мапу маршрутів `VerdinSchema` для клієнта. Запустіть його з `blog`, вказавши на
конфігурацію проєкту Verdin:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

Файл містить, серед іншого:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

Зв'язки, медіа й компоненти необов'язкові, бо API повертає їх лише тоді, коли ви їх заповнюєте.
Запускайте команду знову щоразу, коли змінюється схема.

## 4. Підключіться до Verdin

Запишіть URL сервера в `.env.local`:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

Без токена клієнт читає як публічна роль — саме її ви відкрили на кроці 1. Щоб натомість
читати з токеном, створіть токен **Лише читання** в **Налаштування → API-токени** і задайте
`VERDIN_TOKEN`. Обидві змінні лишаються на сервері: вони не мають префікса `NEXT_PUBLIC_`, а
клієнт працює лише в Server Components.

Створіть клієнт один раз і використовуйте спільно:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

Тепер `verdin.collection('articles')` приймає лише маршрути вашої схеми, а його результати мають
тип `Article`.

## 5. Замініть макет

Замініть стартовий макет і видаліть `src/app/page.module.css`, який нові сторінки не
використовують:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import Link from 'next/link';

export const metadata: Metadata = {
  title: 'My blog',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. Виведіть список статей

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

Цей запит — це REST-виклик
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`
у форматі Strapi v5. `fields` тримає відповідь невеликою, а `populate` додає категорію лише з
її назвою. Публічна роль читає лише опубліковані статті.

`revalidate = 60` попередньо рендерить сторінку під час збірки й після цього оновлює її
щонайбільше раз на хвилину, тож опубліковані зміни з'являються без перезбирання.

## 7. Додайте сторінку для кожної статті

Сторінка статті знаходить свою статтю за slug через фільтр. `generateStaticParams` попередньо
рендерить наявні статті; статті, опубліковані пізніше, рендеряться під час першого відвідування.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

У Next.js 16 `params` — це проміс: дочекайтеся його, перш ніж читати slug. Невідомий slug не
знаходить статті й відповідає 404 через `notFound()`. `pageSize` обмежено `[api].max_page_size`
(типово 100).

<Aside type="caution">
`marked` не санітизує HTML. Для Markdown, який пишуть ваші власні редактори, це нормально; якщо
вміст може надходити від недовірених людей, санітизуйте HTML перед виведенням.
</Aside>

## 8. Запустіть

```sh title="Terminal"
npm run dev
```

Відкрийте [http://localhost:3000](http://localhost:3000): список показує опубліковані статті, і
кожна веде на свою сторінку. `npm run build` потребує запущеного Verdin, бо отримує статті для
попереднього рендерингу.

Щоб оновлювати сторінки одразу після зміни вмісту, а не протягом хвилини, викликайте
`revalidatePath` з обробника маршруту, який запускає вебхук Verdin; див.
[Вебхуки](/uk/guides/integrations/webhooks/).

Тепер ваш проєкт виглядає так:

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts згенеровано `verdin types`
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. Необов'язково: попередній перегляд чернеток

Адмінка може відкрити чернетку на вашому сайті з короткочасним токеном попереднього перегляду.
Токен читає цей один документ, включно з чернетками, і нічого більше.

Додайте клієнт, що надсилає токен попереднього перегляду в заголовку `x-verdin-preview`:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Потім сторінка. Вона читає `searchParams`, тож Next.js рендерить її на кожен запит; токен
надходить як параметр запиту `preview`:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Токен попереднього перегляду не може переглядати списки записів, тож сторінка шукає чернетку
за `documentId`, а не за slug. Тепер повідомте Verdin, де сторінка:

<Steps>

1. В адмінці відкрийте **Налаштування → Функції**, увімкніть **Попередній перегляд** і виберіть
   **Налаштувати URL попереднього перегляду**.
2. Задайте шаблон URL для **Article** як `http://localhost:3000/preview/{documentId}` і
   збережіть. Verdin додає токен як `?preview=…`.
3. Відкрийте статтю, змініть її й виберіть **Зберегти чернетку**, потім виберіть **Відкрити
   попередній перегляд**.

</Steps>

Сторінка показує чернетку. Посилання типово діють 60 хвилин. Про заповнювачі й налаштування
див. [Попередній перегляд](/uk/guides/content/preview/), а щоб редагувати з попереднього
перегляду — [Візуальне редагування](/uk/guides/frontend/visual-editing/).
