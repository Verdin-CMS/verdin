Verdin — headless CMS з відкритим кодом, написана на Rust. Ви моделюєте типи вмісту, ваші
редактори пишуть і публікують в адмін-панелі, а ваші сайти й застосунки читають вміст через
REST або GraphQL API. Verdin не рендерить сторінки: це робить ваш фронтенд.

Це переписаний [Strapi v5](https://strapi.io): формат схеми й API вмісту мають ту саму форму,
тож проєкт Strapi і його фронтенд можна перенести з мінімумом змін.

## Для кого вона

- **Розробники сайтів чи застосунків**, яким потрібна CMS, що працює як один процес, тримає
  модель вмісту в git і читається з будь-якого фронтенду: Astro, Next.js, мобільного
  застосунку.
- **Команди на Strapi**, яким потрібен той самий API з меншими вимогами до ресурсів або функції,
  які Strapi залишає для платних планів. У Verdin немає enterprise-версії: SSO, журнали аудиту,
  процеси перевірки й релізи — частина проєкту з відкритим кодом.
- **Редактори**, які отримують чернетки, публікацію, історію й попередній перегляд в
  адмін-панелі, доступній 18 мовами.

## Що в комплекті

Один виконуваний файл, `verdin`, — це сервер, інструмент командного рядка й адмін-панель. У
production немає ні середовища Node.js, ні `node_modules`.

| Область | Що ви отримуєте |
| --- | --- |
| Бази даних | PostgreSQL 14+, MySQL 8.4+, MariaDB 10.11+ і SQLite, покриті тим самим набором тестів. |
| Модель вмісту | Типи колекцій, поодинокі типи, компоненти, динамічні зони, зв'язки, медіа, rich text у Markdown або у форматі blocks Strapi. Схема — це JSON-файли у вашому проєкті. |
| Зміни схеми | Кожна зміна стає планом міграції з рівнем ризику й точним SQL. Деструктивні кроки виконуються, лише коли ви їх дозволите. |
| API | REST під `/api` з параметрами Strapi v5 (`filters`, `populate`, `sort`, `pagination`), необов'язковий GraphQL-ендпоінт, документ OpenAPI і типізований TypeScript-клієнт. |
| Редагування | Чернетки й публікація, локалізований вміст, історія вмісту, релізи, процеси перевірки, коментарі й завдання, присутність наживо, попередній перегляд і візуальне редагування на вашому власному сайті. |
| Доступ | Ролі адміністраторів аж до полів і локалей, API-токени, публічні дозволи, SSO з OpenID Connect, двофакторний вхід із passkeys, журнали аудиту. |
| Функції сайту | Повнотекстовий пошук, мапа сайту, перенаправлення, меню й форми, вебхуки, оновлення в реальному часі. |
| Розширення | Плагіни WebAssembly, що підключаються до записів, додають маршрути й завдання, а також віджети адмінки й власні поля, обмежені оголошеними можливостями. |

## Як вона співвідноситься зі Strapi v5

**Однаково:**

- Файли схеми використовують формат Strapi: `schema/content-types/<singularName>.json` і
  `schema/components/<category>/<name>.json`.
- REST API вмісту: маршрути, плоский формат відповідей із `documentId`, параметри й оператори
  запитів, семантика запису (`POST` чи `PUT` публікує, якщо не передати `?status=draft`), тіла
  помилок.
- Схема GraphQL має форму GraphQL-плагіна Strapi v5.
- Кінцеві користувачі (реєстрація, вхід, OAuth, ролі) відповідають API `users-permissions`.

**Інакше:**

- **Зміни схеми — це заплановані міграції.** Verdin порівнює файли схеми з базою даних і
  показує кроки, перш ніж їх виконати. `verdin start` відмовляється працювати, поки база даних
  відстає від схеми.
- **Конструктор типів вмісту працює лише в режимі розробки.** У production схема береться з
  вашого репозиторію.
- **Плагіни — WebAssembly, а не JavaScript.** Плагіни Strapi, а також власні контролери, сервіси
  чи файли lifecycle у `src/` у Verdin не працюють.
- **База даних не спільна зі Strapi.** Проєкт Strapi переносять через `verdin import strapi`,
  що дає кожному документу новий id.
- **Кілька доповнень до REST**: дії публікації й зняття з публікації
  (`POST /api/<route>/<documentId>/actions/publish`), а заповнений компонент повертається
  цілком, разом із вкладеними компонентами.

[Сумісність зі Strapi](/uk/migrate/compatibility/) детально перелічує відмінності.

## Коли її не варто використовувати

- **Ви залежите від плагінів Strapi чи власного серверного коду на JavaScript.** Verdin не може
  їх запускати; їх довелося б переписати як плагіни WebAssembly або перенести логіку деінде.
- **Вам потрібна стабільна 1.0.** Verdin має версію 0.10: мінорні релізи ще можуть змінювати
  конфігурацію й поведінку. Читайте [Оновлення](/uk/migrate/upgrading/) перед кожним.
- **Ви хочете, щоб CMS рендерила ваші сторінки.** Verdin — headless; поєднуйте її з
  фронтенд-фреймворком чи генератором статичних сайтів.
- **Вам потрібен керований сервіс.** Verdin розгортається самостійно: ви запускаєте бінарник
  чи образ Docker на власній інфраструктурі.
