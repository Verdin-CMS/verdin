Інтернаціоналізація (i18n) зберігає вміст документа кількома мовами. На цій сторінці пояснено
модель: локалі, локалізовані й спільні поля, а також як читання й запис вибирають локаль. Про
робочий процес редактора див. [Локалізація вмісту](/uk/guides/content/localizing-content/).

## Локалі

Локалі проєкту перелічено в **Налаштування → Інтернаціоналізація** (дозвіл `locales.manage`).
Під час першого запуску англійська (`en`) додається як типова локаль.

- Одна локаль завжди типова. Запити, що не називають локаль, використовують її, і її не можна
  видалити.
- Коди — це мова з двох або трьох малих літер, за якою можуть іти підтеги:
  `en`, `fr`, `pt-BR`, `zh-Hans`.

:::caution
Видалення локалі також видаляє всі версії, написані нею.
:::

## Локалізовані типи вмісту

Тип вмісту локалізований, коли про це сказано в його схемі. Тоді кожен документ має одну
версію на локаль, і всі вони мають спільний `documentId`:

```json title="schema/content-types/article.json (excerpt)"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

З [чернетками й публікацією](/uk/concepts/draft-and-publish/) кожна локаль має власну чернетку й
опубліковану версію, тож французький переклад можна опублікувати до або після англійського
тексту. Типи без `pluginOptions.i18n.localized` не локалізовані й ігнорують параметри `locale`.

## Що локалізується

У локалізованому типі кожен атрибут локалізований, якщо в ньому не вказано
`"pluginOptions": { "i18n": { "localized": false } }`. Таке **спільне** поле має одне значення
для всього документа:

- Збереження спільного поля в одній локалі записує його в чернетки всіх локалей.
- Публікація локалі копіює її спільні поля в опубліковані версії інших локалей.
- Це стосується й зв'язків та медіа: спільний зв'язок пов'язує ті самі документи в усіх локалях.

Системні поля слідують за версією: кожна локаль має власні `createdAt`, `updatedAt` і
`publishedAt`. Значення `unique` і `uid` унікальні в межах локалі, тож два переклади можуть
мати однаковий slug.

## Зв'язки між локалізованими типами

Зв'язки пов'язують документи, а не версії (див.
[Зв'язки](/uk/concepts/relations/#звязок-за-документом-а-не-за-рядком)), тож локаль вибирається
під час читання:

- Коли обидва типи локалізовані, французька стаття показує французьку версію своєї категорії.
  Фільтри через зв'язок шукають збіги в тій самій локалі.
- Коли цільовий тип не локалізований, усі локалі бачать ту саму ціль.

## Вибір локалі в API

REST і admin API приймають `locale` як параметр запиту у форматі Strapi v5; GraphQL приймає
аргумент `locale`:

```http
GET /api/articles?locale=fr
PUT /api/articles/{documentId}?locale=fr
DELETE /api/articles/{documentId}?locale=fr
```

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
  }
}
```

- Без `locale` запити читають і записують типову локаль.
- `PUT` у локалі, якої документ ще не має, створює цю версію.
- `DELETE` видаляє лише версію в запитаній локалі. Посилання на документ видаляються, коли не
  залишається жодної локалі.
- REST-відповіді локалізованих типів містять `locale`. Невідома локаль — це помилка `400`.
- Payload вебхуків, події реального часу та історія вмісту фіксують локаль версії, яка
  змінилася.

## Дозволи для локалей

Ролі адміністраторів можуть обмежувати дозволи на вміст певними локалями, тож французький
редактор може читати або змінювати лише французькі версії. Див.
[Дозволи](/uk/concepts/permissions/#дозволи-для-полів-і-локалей). Дозволи API вмісту
(публічний доступ, API-токени, ролі кінцевих користувачів) діють для всіх локалей.

## Порівняно зі Strapi

Модель і параметри відповідають i18n у Strapi v5: локалізовані типи, поля `localized: false`,
`?locale=` і типова локаль. У Verdin i18n — частина ядра й завжди ввімкнена: ви вмикаєте її для
типу вмісту в схемі.
