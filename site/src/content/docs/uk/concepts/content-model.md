Модель вмісту — це набір типів вмісту й компонентів, які визначає ваш проєкт. Verdin виводить
із неї все інше: таблиці бази даних, REST і GraphQL API, документ OpenAPI, валідацію та форми
адмін-панелі. На цій сторінці пояснено складові та правила, які до них застосовуються.

## Типи вмісту

Тип вмісту описує один різновид документа, наприклад статтю чи домашню сторінку. Він має
`kind`:

| Kind | Містить | REST-маршрути (приклад блогу) |
| --- | --- | --- |
| `collectionType` | Будь-яку кількість документів | `/api/articles`, `/api/articles/{documentId}` |
| `singleType` | Щонайбільше один документ | `/api/homepage` |

Типи колекцій доступні за їхнім `pluralName`, поодинокі типи — за `singularName`. Перший `PUT`
до поодинокого типу створює його документ. Усі маршрути описано в [REST API](/uk/api/rest/).

Кожен тип вмісту має UID `api::<singularName>` (`api::article`). Strapi записує той самий UID
як `api::article.article`; Verdin приймає цю форму у файлах схеми та в імпортері й
нормалізує її до `api::article`.

Кожен документ має системні поля, які ви не оголошуєте: `id`, `documentId` (ULID із 26
символів у нижньому регістрі, стабільний для чернеток, опублікованих версій і локалей),
`createdAt`, `updatedAt`, `publishedAt` і `locale` у [локалізованих типах](/uk/concepts/internationalization/).

## Файли схеми

Типи вмісту й компоненти — це JSON-файли в каталозі `schema/` вашого проєкту
(`[schema].path` у `verdin.toml`). Ви версіонуєте їх у git, як код.

```
schema/
├── content-types/
│   ├── article.json
│   ├── category.json
│   ├── tag.json
│   └── homepage.json
└── components/
    ├── blocks/
    │   ├── hero.json
    │   └── quote.json
    └── shared/
        └── seo.json
```

Формат — це `schema.json` Strapi, тож більшість схем Strapi завантажуються без змін. Ось тип
статті з [прикладу блогу](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog):

```json title="schema/content-types/article.json"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "attributes": {
    "title": { "type": "string", "required": true, "maxLength": 200 },
    "slug": { "type": "uid", "targetField": "title", "required": true },
    "excerpt": { "type": "text", "maxLength": 500 },
    "body": { "type": "richtext" },
    "readingTime": { "type": "integer", "min": 0 },
    "featured": { "type": "boolean", "default": false },
    "category": { "type": "relation", "relation": "manyToOne", "target": "category", "inversedBy": "articles" },
    "tags": { "type": "relation", "relation": "manyToMany", "target": "tag" },
    "seo": { "type": "component", "component": "shared.seo" },
    "blocks": { "type": "dynamiczone", "components": ["blocks.hero", "blocks.quote"] }
  }
}
```

| Ключ | Обов'язковий | Опис |
| --- | --- | --- |
| `kind` | так | `collectionType` або `singleType`. |
| `singularName` | так | Kebab-case. Має збігатися з назвою файлу (`article.json`). |
| `pluralName` | так | Kebab-case, відмінний від `singularName`. |
| `displayName` | так | Назва, яку показує адмін-панель. |
| `description` | ні | Показується в адмін-панелі. |
| `collectionName` | ні | Назва таблиці. Типово — `pluralName` у snake_case. |
| `options.draftAndPublish` | ні | Зберігати чернетку й опубліковану версію кожного документа. Типово `false`. Див. [Чернетки й публікація](/uk/concepts/draft-and-publish/). |
| `pluginOptions.i18n.localized` | ні | Одна версія на кожну локаль. Типово `false`. Див. [Інтернаціоналізація](/uk/concepts/internationalization/). |
| `attributes` | ні | Поля в тому порядку, у якому їх повертає API. |
| `validations` | ні | Правила для кількох полів; див. [нижче](#валідація-між-полями). |

Схеми суворі: невідомий ключ, параметр, який тип не підтримує, або посилання на відсутній тип
чи компонент — це помилка з назвою файлу й шляхом, і сервер не запускається. Запустіть
`verdin schema check`, щоб перевірити файли без запуску сервера.

Деякі назви зайняті:

- Назви атрибутів починаються з літери, далі йдуть літери, цифри й підкреслення, щонайбільше
  50 символів. Вони стають колонками в snake_case (`metaTitle` → `meta_title`).
- `id`, `documentId`, `locale`, `publicationState`, `publishedAt`, `createdAt`,
  `updatedAt`, `createdBy` і `updatedBy` зарезервовані в типах вмісту, а `id` — усередині
  компонентів.
- `upload`, `uploads`, `auth`, `users` і `connect` не можуть бути `singularName` чи
  `pluralName`: ці маршрути належать API.
- Тип вмісту має щонайбільше 60 атрибутів `string`, `email`, `uid` і `enumeration`, щоб рядки
  вкладалися в ліміт розміру рядка MySQL. Для деяких із них використовуйте `text`.

Файли редагують у **Конструктор типів вмісту** адмін-панелі, доступному, поки сервер працює з
`verdin dev`, або вручну. У будь-якому разі зміна стає [міграцією схеми](/uk/concepts/schema-migrations/).
Макет редактора (порядок полів, ширина, підписи) не є частиною схеми: адміністратори
налаштовують його в панелі, і він зберігається в базі даних.

## Компоненти

Компонент — це група полів для повторного використання, наприклад `shared.seo`
(мета-заголовок і мета-опис). Його UID — `<category>.<name>`, узятий зі шляху:
`schema/components/shared/seo.json` — це `shared.seo`. Файл компонента має `displayName`,
необов'язкові `description` та `icon`, а також `attributes`.

Динамічна зона — це список, що поєднує кілька компонентів, наприклад тіло статті з hero-блоків
і цитат. Обидва зберігаються всередині документа як JSON; див.
[Компоненти й динамічні зони](/uk/concepts/components-and-dynamic-zones/).

## Атрибути

Кожен атрибут має `type` і параметри, що від нього залежать. Повний список типів, їхніх
параметрів і типів колонок для кожної бази даних наведено в
[довіднику типів атрибутів](/uk/reference/attribute-types/).

| Категорія | Типи |
| --- | --- |
| Текст | `string`, `text`, `richtext` (Markdown), `blocks` (структурований rich text Strapi), `email`, `uid`, `password`, `enumeration` |
| Числа | `integer`, `biginteger`, `float`, `decimal` |
| Дати | `date`, `time`, `datetime` |
| Інші скалярні | `boolean`, `json` |
| Посилання | `relation` (див. [Зв'язки](/uk/concepts/relations/)), `media` (див. [Медіа](/uk/concepts/media/)) |
| Структура | `component`, `dynamiczone` |

Поширені параметри:

| Параметр | Дія |
| --- | --- |
| `required` | Значення має бути задане, коли версію публікують (або під час кожного запису для типів без чернеток і публікації). Чернетки можуть бути неповними. |
| `private` | API вмісту ніколи не повертає, не фільтрує, не сортує й не заповнює це поле. Атрибути `password` завжди приватні. |
| `default` | Значення, яке використовується, коли новий документ не містить поля. Перевіряється за власними правилами атрибута. |
| `unique` | Два документи не можуть мати однакове значення в межах локалі й версії. Доступно для `string`, `email`, числових типів, дат і часу; `uid` завжди унікальний. |
| `configurable` | `false` блокує атрибут у конструкторі типів вмісту: там його не можна редагувати, перейменувати чи видалити. |
| `pluginOptions.i18n.localized` | `false` робить значення спільним для всіх локалей. |

Кожна колонка атрибута в базі даних допускає null. Як і в Strapi v5, `required` забезпечує
Verdin під час публікації, а не обмеження `NOT NULL`, тож додавання обов'язкового атрибута до
типу, який уже має рядки, — безпечна зміна.

## Валідація

Кожен запис перевіряється за схемою, перш ніж щось потрапить у базу даних:

- **Типи й обмеження** — під час кожного запису: типи значень, `minLength`/`maxLength`,
  `min`/`max`, `regex`, значення `enum`, кількість елементів у повторюваних компонентах і
  динамічних зонах, типи компонентів, які дозволяє динамічна зона, і типи файлів, які приймає
  медіаполе. Невідомі ключі та системні поля у вхідних даних — помилки.
- **Обов'язкові поля й правила для кількох полів** — під час публікації версії та під час
  кожного запису в типи без чернеток і публікації. Вони діють і всередині компонентів та
  динамічних зон.
- **Унікальність** — через унікальні індекси в базі даних, тож два одночасні записи не можуть
  обидва завершитися успішно.

Невдала перевірка відповідає `400` з `ValidationError`, чий `details.errors` перелічує кожну
проблему з її шляхом, наприклад `["seo", "metaTitle"]` або `["blocks", 2, "text"]`. Див.
[Помилки](/uk/api/rest/#помилки).

### Валідація між полями

Тип вмісту може оголошувати правила, що порівнюють його власні поля, записані в
[JSON Logic](https://jsonlogic.com). Цей тип події вимагає, щоб дата завершення йшла після дати
початку, і обмежує кількість проданих квитків кількістю місць:

```json title="schema/content-types/event.json"
{
  "kind": "collectionType",
  "singularName": "event",
  "pluralName": "events",
  "displayName": "Event",
  "attributes": {
    "startDate": { "type": "date", "required": true },
    "endDate": { "type": "date" },
    "seats": { "type": "integer", "min": 0 },
    "sold": { "type": "integer", "min": 0 }
  },
  "validations": [
    {
      "rule": { "or": [{ "!": { "var": "endDate" } }, { "<=": [{ "var": "startDate" }, { "var": "endDate" }] }] },
      "message": "must be after the start date",
      "field": "endDate"
    },
    { "rule": { "<=": [{ "var": "sold" }, { "var": "seats" }] }, "message": "more tickets sold than seats" }
  ]
}
```

- Правило, яке не виконується, — це помилка валідації з `message`, прив'язана до `field`, якщо
  його задано, або до документа (`path: []`).
- Правила виконуються тоді ж, коли й `required`: під час публікації та під час кожного запису в
  типи без чернеток і публікації. Чернетки можуть їх порушувати.
- `var` читає власні поля документа, з крапковими шляхами всередину компонентів. Зв'язки й
  медіа правилам недоступні.
- Порівняння числові, коли обидві сторони — числа, і текстові, коли обидві — рядки, тож дати,
  час і дати з часом у форматі ISO порівнюються правильно. Порожнє поле — це `null`:
  захищайте необов'язкові поля, як це робить перше правило.
- Дозволені оператори: `var`, `==`, `!=`, `===`, `!==`, `<`, `>`, `<=`, `>=`, `!`, `!!`, `and`,
  `or`, `in`, `if`, `?:`, `+`, `-`, `*`, `/`, `%`, `min`, `max`, `cat`. Невідомий оператор,
  невідоме `field` або порожнє `message` — це помилка схеми.

Сервер перевіряє правила; адмін-панель показує їхні повідомлення біля полів, які вони
називають, коли публікація не вдається. У Strapi відповідника немає. Умовні поля Strapi
(`conditions`) приймаються у файлах схеми й зберігаються, але поки не застосовуються.
