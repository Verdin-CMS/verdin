Компоненти дають змогу повторно використовувати групу полів у різних типах вмісту, а динамічні
зони дозволяють редакторам збирати сторінку зі списку блоків. На цій сторінці пояснено, як
обидва моделюються й зберігаються і як це впливає на їх читання, запис і фільтрування. Сам
формат схеми описано в [Модель вмісту](/uk/concepts/content-model/).

## Компоненти

Компонент — це група полів із власним файлом у `schema/components/<category>/`. У прикладі
блогу `shared.seo` містить мета-заголовок і опис:

```json title="schema/components/shared/seo.json"
{
  "displayName": "SEO",
  "attributes": {
    "metaTitle": { "type": "string", "maxLength": 60 },
    "metaDescription": { "type": "text", "maxLength": 160 }
  }
}
```

Тип вмісту використовує його через атрибут `component`. `repeatable: true` робить його
списком, за бажання обмеженим кількістю елементів `min` і `max`:

```json
"seo": { "type": "component", "component": "shared.seo" },
"links": { "type": "component", "component": "shared.link", "repeatable": true, "max": 10 }
```

Компоненти можуть містити інші компоненти. Компонент не може містити сам себе — ні напряму,
ні через інші; перевірка схеми відхиляє такі цикли.

## Динамічні зони

Динамічна зона — це список, елементами якого може бути будь-який із названих у ній
компонентів. Тіло статті в блозі поєднує hero-блоки й цитати:

```json
"blocks": { "type": "dynamiczone", "components": ["blocks.hero", "blocks.quote"], "max": 20 }
```

Кожен елемент вказує в `__component`, який це компонент. `min` і `max` обмежують кількість
елементів. Динамічні зони бувають лише в типах вмісту: компонент не може її містити.

## Зберігаються як JSON

Verdin зберігає значення компонента або динамічної зони в одній JSON-колонці рядка документа
(`jsonb` у PostgreSQL, `json` у MySQL і MariaDB, текст у SQLite):

```json
// the "seo" column
{ "id": 1, "metaTitle": "Rust for CMS authors", "metaDescription": "…" }

// the "blocks" column
[
  { "__component": "blocks.hero", "id": 1, "title": "Hello", "subtitle": "…" },
  { "__component": "blocks.quote", "id": 2, "text": "…", "author": "Ferris" }
]
```

Strapi тримає кожен компонент в окремій таблиці, з'єднаній через поліморфні таблиці зв'язків.
Зберігання значення разом із документом означає ось що:

- Читання документа з компонентами не потребує join-ів, хоч як глибоко вони вкладені.
- Публікація, відкидання чернетки та [історія вмісту](/uk/guides/content/content-history/)
  копіюють значення як є.
- Додавання поля до компонента не змінює жодної таблиці: міграція порожня.
- Фільтрування за полями компонентів використовує JSON-функції кожної бази даних, і деякі
  фільтри недоступні (див. [Фільтрування](#фільтрування)).

Кожен елемент має `id` — додатне ціле число, унікальне в межах значення атрибута. Verdin
призначає його новим елементам; надсилайте `id` назад під час оновлення списку, щоб елементи
залишалися стабільними.

## Зв'язки й медіа всередині компонентів

Компонент може містити зв'язки й медіа, збережені в самому JSON: `documentId` для зв'язків і
id файлів для медіа.

- Зв'язки всередині компонентів мають бути `oneWay` або `manyWay`: вони вказують на свої цілі
  й не мають зворотної сторони. Див. [Зв'язки](/uk/concepts/relations/#звязки-всередині-компонентів).
- Кожне посилання перевіряється під час запису: цільовий документ або файл має існувати, а
  файли мають відповідати `allowedTypes` поля.
- Коли компонент заповнюється через populate, посилання розв'язуються пакетними запитами в
  тому самому статусі й локалі, що й документ. Ціль, яку видалено або яка не має версії в
  тій, що читається, пропускається.
- Поліморфні зв'язки (`morphToOne`, `morphToMany`) і поля `password` не можуть бути всередині
  компонентів.

## Читання

Компоненти й динамічні зони повертаються, лише коли ви заповнюєте їх через populate, як у Strapi:

```http
GET /api/articles?populate[0]=seo&populate[1]=blocks
GET /api/articles?populate=*
```

Заповнений компонент повертається повністю, разом із вкладеними компонентами та розв'язаними
зв'язками й медіа. Strapi потребує рівня `populate` для кожного вкладеного компонента; Verdin
приймає ці вкладені параметри для сумісності й ігнорує їх. Елементи динамічної зони
повертаються в збереженому порядку, кожен зі своїм `__component`.

У GraphQL компонент — це об'єктний тип, названий за його UID (`ComponentSharedSeo`), а
динамічна зона — union (`ArticleBlocksDynamicZone`), який запитують через фрагменти. Див.
[GraphQL API](/uk/api/graphql/).

## Запис

Надсилайте все значення атрибута. Воно замінює те, що було збережено:

```json
{
  "data": {
    "seo": { "metaTitle": "Rust for CMS authors" },
    "blocks": [
      { "__component": "blocks.hero", "title": "Hello" },
      { "__component": "blocks.quote", "text": "Fast and small.", "author": "Ferris" }
    ]
  }
}
```

Значення перевіряється за схемою компонента під час кожного запису: невідомі ключі, неправильні
типи та `__component`, який динамічна зона не дозволяє, — це помилки зі шляхами на кшталт
`["blocks", 1, "text"]`. Поля `required` усередині компонентів перевіряються під час публікації
документа, як і поля верхнього рівня.

## Фільтрування

| Що | Приклад | Примітки |
| --- | --- | --- |
| Поля компонента | `filters[seo][metaTitle][$containsi]=rust` | Скалярні поля, зокрема вкладених компонентів. |
| Поля повторюваного компонента | `filters[links][url][$contains]=github` | Збіг, коли збігається хоча б один елемент. |
| Динамічні зони | `filters[blocks][__component][$eq]=blocks.quote` | Лише за `__component`: елементи різних компонентів мають різні поля. |

Сортувати за полями компонентів не можна, а поля `json` усередині компонентів не можна
фільтрувати. Оператори описано в [REST API](/uk/api/rest/#фільтри).
