Чернетки й публікація дають редакторам змогу працювати над документом, не змінюючи того, що
показує ваш сайт, і опублікувати його, коли він готовий. На цій сторінці пояснено модель:
документи, версії, дії, що переміщують вміст між ними, і як кожен API з ними працює. Усе
працює так само, як у Strapi v5.

Увімкніть цю функцію для типу вмісту в його схемі:

```json title="schema/content-types/article.json (excerpt)"
"options": { "draftAndPublish": true }
```

Якщо `options.draftAndPublish` немає, функцію вимкнено.

## Документи й версії

**Документ** — це один запис, що ідентифікується своїм `documentId`. З чернетками й
публікацією документ має до двох **версій**:

- **чернетку**, яку змінює кожне редагування, і
- **опубліковану** версію, яку API вмісту віддає типово.

У [локалізованому](/uk/concepts/internationalization/) типі кожна локаль має власну чернетку й
опубліковану версію, і всі вони мають спільний `documentId`.

Типи без чернеток і публікації мають одну версію на локаль, яка завжди опублікована: кожен
запис змінює те, що бачать читачі.

## Стани

Адмін-панель показує стан кожного запису в списку та в редакторі:

| Стан | Чернетка | Опублікована версія | Що бачать читачі опублікованого вмісту |
| --- | --- | --- | --- |
| **Чернетка** | так | немає | Нічого: документ не видно. |
| **Опубліковано** | така сама, як опублікована | так | Опубліковану версію. |
| **Змінено** | змінена після останньої публікації | так | Опубліковану версію, без нових змін. |

Дії переміщують документ між цими станами:

| Дія | Результат | Звідки → куди |
| --- | --- | --- |
| Зберегти | Записує чернетку. | Чернетка → Чернетка, Опубліковано → Змінено |
| **Опублікувати** | Копіює чернетку в опубліковану версію, створюючи її за потреби. | Чернетка або Змінено → Опубліковано |
| **Зняти з публікації** | Видаляє опубліковану версію; чернетка залишається. | Опубліковано або Змінено → Чернетка |
| **Скасувати зміни** | Замінює чернетку копією опублікованої версії. | Змінено → Опубліковано |
| Видалити | Видаляє всі версії (у локалізованих типах — запитаної локалі). | будь-який → немає |

Публікація виконується в одній транзакції. Вона перевіряє поля `required` і
[правила для кількох полів](/uk/concepts/content-model/#валідація-між-полями) типу на чернетці;
якщо перевірка не проходить, нічого не публікується. До того чернетки можуть бути неповними й
порушувати ці правила.

У чернеток `publishedAt` дорівнює `null`. Опублікована версія містить час останньої публікації.

## Зв'язки й медіа слідують за версією

Кожна версія має власні зв'язки й медіапосилання, а публікація копіює посилання чернетки в
опубліковану версію. Посилання вказують на документи й розв'язуються у версії, що читається:
опублікована стаття показує опубліковану версію своєї категорії, а чернетка — чернетку
категорії. Якщо категорію знято з публікації, вона зникає з опублікованої статті, доки її не
опублікують знову, і жодне посилання при цьому не переписується. Див.
[Зв'язки](/uk/concepts/relations/#звязок-за-документом-а-не-за-рядком).

Компоненти й динамічні зони є частиною рядка, тож публікація копіює їх як є.

## Читання чернеток і опублікованого вмісту

| API | Типово читає | Щоб читати чернетки |
| --- | --- | --- |
| [REST](/uk/api/rest/#статус) | Опубліковані версії | `?status=draft`, для чого потрібен дозвіл **Читати чернетки** |
| [GraphQL](/uk/api/graphql/) | Опубліковані версії | `status: DRAFT`, з тим самим дозволом |
| [Admin API](/uk/api/admin/) | Чернетки | `?status=published` |

Читання чернеток — окремий дозвіл (`readDrafts`), щоб токен, який читає вміст вашого сайту, не
міг читати неопубліковану роботу. API-токени лише для читання ніколи не читають чернетки.

Щоб розрізняти документи за тим, чи їх коли-небудь публікували, фільтруйте за
`hasPublishedVersion`: `?status=draft&hasPublishedVersion=false` перелічує документи, які
ніколи не публікувалися.

## Запис через API

Під час запису API поводяться як у Strapi v5:

- `create` і `update` в **REST і GraphQL** записують чернетку **і публікують її**, якщо запит не
  просить `status=draft` (`status: DRAFT` у GraphQL). Невдала публікація відкочує весь запит.
- **Адмін-панель і admin API** зберігають лише чернетки. Публікація — це завжди окрема явна дія.

REST API також має явні дії, яких Strapi через REST не пропонує:

```http
POST /api/articles/{documentId}/actions/publish
POST /api/articles/{documentId}/actions/unpublish
POST /api/articles/{documentId}/actions/discard-draft
```

Їм потрібен дозвіл **Опублікувати** для типу. Див. [REST API](/uk/api/rest/#дії).

## Інші функції, що публікують

- [Релізи](/uk/guides/content/releases/) групують документи й публікують або знімають їх з
  публікації разом — одразу або в призначений час.
- [Процеси перевірки](/uk/guides/content/review-workflows/) можуть вимагати певного етапу, перш
  ніж документ можна буде опублікувати.
- Публікація та зняття з публікації надсилають [події вебхуків](/uk/api/webhooks/)
  `entry.publish` і `entry.unpublish` та [події реального часу](/uk/api/realtime/). Збереження
  чернетки надсилає `entry.update`, яку через реальний час отримують лише клієнти з правом
  читати чернетки.
