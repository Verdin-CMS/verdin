У репозиторії є файли розгортання для кількох платформ. Усі вони збирають
[`deploy/one-click/Dockerfile`](https://github.com/verdin-cms/verdin/blob/main/deploy/one-click/Dockerfile):
офіційний образ зі схемою [прикладу блогу](https://github.com/verdin-cms/verdin/tree/main/examples/blog)
і невеликою конфігурацією. Так ви за кілька хвилин отримуєте працюючий Verdin.

<Aside>
Розгорнутий сервер запускає `start --migrate`, тож конструктор типів вмісту вимкнено: схема
береться з образу. Для власного проєкту **зробіть форк репозиторію**, замініть
`examples/blog/schema` своєю схемою (або змініть рядок `COPY` у Dockerfile) і розгорніть форк.
Сторінки платформ ([Render](/uk/deploy/render/), [Railway](/uk/deploy/railway/),
[Fly.io](/uk/deploy/fly/)) показують те саме налаштування в репозиторії, який належить вам.
</Aside>

Файли перевірено за довідником кожної платформи 2026-09-30; жоден не розгортали на реальному
обліковому записі.

| Платформа | Файл | База даних | Медіа |
| --- | --- | --- | --- |
| Render | [`render.yaml`](https://github.com/verdin-cms/verdin/blob/main/render.yaml) | Render PostgreSQL | Диск 1 GB у `/data` |
| DigitalOcean | [`.do/deploy.template.yaml`](https://github.com/verdin-cms/verdin/blob/main/.do/deploy.template.yaml) | Dev PostgreSQL | Spaces (на App Platform немає дисків) |
| Railway | [`deploy/one-click/railway.json`](https://github.com/verdin-cms/verdin/blob/main/deploy/one-click/railway.json) | Railway PostgreSQL | Том у `/data` |
| Fly.io | [`deploy/one-click/fly.toml`](https://github.com/verdin-cms/verdin/blob/main/deploy/one-click/fly.toml) | SQLite на томі | Том у `/data` |
| Coolify | [`deploy/one-click/compose.coolify.yaml`](https://github.com/verdin-cms/verdin/blob/main/deploy/one-click/compose.coolify.yaml) | Сервіс PostgreSQL | Том у `/data` |

Dockerfile закінчується рядком `USER root`, бо ці платформи монтують томи, власником яких є
root, і користувач образу (uid `65532`) не міг би в них писати. Приберіть цей рядок, якщо ваш
том доступний для запису uid `65532` або якщо ви не зберігаєте стан на екземплярі.

## Render

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/verdin-cms/verdin)

Blueprint створює вебсервіс (тариф Starter, якого вимагають диски), базу даних PostgreSQL і два
секрети (генеруються один раз, потім зберігаються). Render запитує `VERDIN_SERVER__PUBLIC_URL`:
введіть адресу сервісу, `https://<name>.onrender.com`, або свій домен. Для форка використовуйте
`https://render.com/deploy?repo=<your fork's URL>`.

## DigitalOcean App Platform

[![Deploy to DigitalOcean](https://www.deploytodo.com/do-btn-blue.svg)](https://cloud.digitalocean.com/apps/new?repo=https://github.com/verdin-cms/verdin/tree/main)

Специфікація створює сервіс і базу даних для розробки. Вставте два значення з
`verdin secrets` у `VERDIN_ADMIN_JWT_SECRET` і `VERDIN_TOKEN_PEPPER`, коли буде запит:

```sh frame="terminal"
docker run --rm ghcr.io/verdin-cms/verdin:0.11 secrets
```

App Platform не має постійних дисків, тож завантажені файли втрачаються за кожного розгортання,
доки ви не додасте бакет Spaces: задайте `VERDIN_UPLOAD__PROVIDER__NAME=s3`,
`VERDIN_UPLOAD__PROVIDER__BUCKET`, `VERDIN_UPLOAD__PROVIDER__REGION`,
`VERDIN_UPLOAD__PROVIDER__ENDPOINT` (`https://<region>.digitaloceanspaces.com`),
`VERDIN_UPLOAD__PROVIDER__PUBLIC_URL`, `AWS_ACCESS_KEY_ID` і `AWS_SECRET_ACCESS_KEY` для
сервісу. Для форка змініть `repo_clone_url` у специфікації.

## Railway

1. Зробіть форк репозиторію, потім у Railway створіть проєкт із форка.
2. У налаштуваннях сервісу задайте шлях до файлу конфігурації
   `deploy/one-click/railway.json` (він вибирає Dockerfile і перевірку стану).
3. Додайте базу даних PostgreSQL і том, змонтований у `/data`, потім задайте змінні з
   [Railway](/uk/deploy/railway/#2-створіть-проєкт): `VERDIN_DATABASE_URL`, два секрети й
   `VERDIN_SERVER__PUBLIC_URL`. Згенеруйте домен із цільовим портом `1337`.

## Fly.io

З клону репозиторію (або вашого форка), з авторизованим `flyctl`:

```sh frame="terminal"
fly launch --no-deploy --copy-config --config deploy/one-click/fly.toml --ha=false
docker run --rm ghcr.io/verdin-cms/verdin:0.11 secrets | fly secrets import --config deploy/one-click/fly.toml
fly deploy --config deploy/one-click/fly.toml --dockerfile deploy/one-click/Dockerfile .
```

Це запускає одну Machine із SQLite і завантаженнями на томі 1 GB. Спершу змініть `app` і
`primary_region` у `fly.toml`. [Fly.io](/uk/deploy/fly/) натомість описує PostgreSQL і Tigris.

## Coolify

У Coolify додайте ресурс зі свого форка (або цього репозиторію) зі збіркою **Docker Compose**,
базовим каталогом `/` і файлом compose `/deploy/one-click/compose.coolify.yaml`. Coolify
заповнює в ньому змінні `SERVICE_*`:

| Змінна | Coolify генерує |
| --- | --- |
| `SERVICE_FQDN_VERDIN_1337` | Домен, який його проксі спрямовує на порт 1337 (також використовується як `VERDIN_SERVER__PUBLIC_URL`). |
| `SERVICE_BASE64_64_JWT`, `SERVICE_BASE64_64_PEPPER` | Два секрети, по 64 символи, що зберігаються між розгортаннями. |
| `SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_POSTGRES` | Облікові дані бази даних. |

Проксі Coolify завершує TLS, тож Caddy не потрібен. Для сервера, яким ви керуєте самі без
Coolify, використовуйте [Docker Compose у production](/uk/deploy/compose/).

## Після першого розгортання

Відкрийте `https://<your address>/admin/` і зареєструйте першого адміністратора. Потім
прочитайте [чекліст production](/uk/deploy/production-checklist/).
