На цій сторінці описано, що робить Verdin для захисту проєкту, і налаштування, які ви
контролюєте. Використовуйте її разом із [чеклістом для production](/uk/deploy/production-checklist/),
коли готуєте екземпляр до реального трафіку.

## Що закрито типово

- **API вмісту.** Анонімні запити нічого не отримують, доки ви не надасте публічні дозволи в
  **Налаштування → Публічний доступ**. Невідомий, прострочений або некоректний токен — це
  `401`, а не перехід до публічної ролі. Див. [Дозволи](/uk/concepts/permissions/).
- **Документ OpenAPI** за адресою `/api/_openapi.json` потребує дійсного API-токена, доки ви не
  зробите його публічним у **Налаштування → Функції → Документація API**.
- **Необов'язкові функції**, як-от GraphQL, кінцеві користувачі, SSO і MCP-сервер, вимкнені,
  доки адміністратор із дозволом `features.manage` не ввімкне їх у **Налаштування → Функції**.
- **Плагіни** вимкнені, доки адміністратор не ввімкне кожен у **Налаштування → Плагіни**.
- **Cross-origin виклики з браузера.** Жоден origin не може викликати будь-який API з браузера,
  доки ви не вкажете його в `[api].cors_origins`.

## Вхід адміністраторів

| Захист | Подробиці |
| --- | --- |
| Хешування паролів | Argon2id з параметрами OWASP; повторне хешування, коли вони змінюються. |
| Сесії | Access token на 15 хвилин у пам'яті сторінки (ніколи в `localStorage`) і refresh token на 30 днів у cookie `HttpOnly`, `SameSite=Strict`, обмеженій `/admin/api/auth`. Refresh token ротується після кожного використання; пред'явлення старого завершує всю сесію. |
| Secure cookies | Refresh cookie має `Secure` у `verdin start`. `[admin].secure_cookies = false` вимикає це й записує попередження. |
| CSRF | Оновлення й вихід потребують заголовка `X-Verdin-CSRF`, який не може надіслати форма з іншого сайту. |
| Блокування | П'ять невдалих спроб блокують обліковий запис на 15 хвилин. Невдачі рахуються разом для кроків пароля й другого фактора. Невідомі адреси й неправильні паролі отримують однакову відповідь за однаковий час. |
| Обмеження частоти | Вхід, реєстрація й оновлення: `[admin].auth_rate_limit` запитів на хвилину з однієї адреси клієнта (20). |
| Другий фактор | Застосунки-автентифікатори (TOTP) і passkeys з кодами відновлення. Роль може його вимагати (`requireTwoFactor`). Див. [Двофакторна автентифікація](/uk/guides/auth/two-factor/). |
| Super Admin | Лише Super Admin може створювати, редагувати, видаляти чи скидати Super Admin або надавати цю роль. Останнього активного Super Admin не можна видалити. |

Перший адміністратор реєструється через панель, поки немає жодного адміністратора. Зробіть це
одразу після першого запуску або створіть його через `verdin admin create --email …`, перш ніж
відкривати сервер.

## Адмін-панель і admin API

- Admin API (`/admin/api`) не надсилає заголовків CORS, хоч би що було в `[api].cors_origins`:
  браузери дозволяють читати його відповіді лише власному origin панелі.
- Панель віддається зі строгою Content Security Policy (скрипти лише з власного origin),
  `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` і
  `Referrer-Policy: strict-origin-when-cross-origin`.
- Verdin не надсилає `Strict-Transport-Security`. Додайте його на зворотному проксі, що
  термінує TLS.

## API вмісту

- **API-токени** показуються один раз. Verdin зберігає HMAC-SHA256 кожного токена з ключем
  `VERDIN_TOKEN_PEPPER` і тримає префікс із 10 символів для відображення. Токени можуть мати
  термін дії й можуть регенеруватися.
- **Дозволи для полів і локалей** обмежують, що роль читає й записує, а `populate`, фільтри й
  сортування за зв'язками доходять лише до типів, які клієнт може читати.
- **Обмеження запитів**: `pageSize` до `[api].max_page_size` (100), глибина `populate` до 5,
  щонайбільше 100 умов фільтра, рядки запиту до 16 КБ і щонайбільше 1 000 заповнених записів
  на зв'язок. Невідомі або приватні поля в запиті — це `400`.
- **GraphQL** має власні обмеження глибини й складності (`maxDepth`, `maxComplexity`) і
  перемикач інтроспекції в налаштуваннях функції.
- **Обмеження частоти**: `[api].public_rate_limit` для кожної адреси клієнта без токена і
  `[api].token_rate_limit` для кожного API-токена чи кінцевого користувача, у запитах на
  хвилину. Обидва типово вимкнені (`0`). Запити з невідомим bearer-токеном обмежуються за
  адресою.

### CORS

`[api].cors_origins` перелічує origin браузерів, яким дозволено викликати API вмісту й GraphQL:

```toml title="verdin.toml"
[api]
cors_origins = ["https://www.example.com", "https://preview.example.com"]
```

Кожен запис — це `scheme://host[:port]` без шляху й кінцевої скісної риски; `["*"]` дозволяє
будь-який origin і не поєднується з іншими. Дозволені методи — `GET`, `POST`, `PUT` і `DELETE`,
а дозволені заголовки запиту — `Authorization`, `Content-Type` і `If-None-Match`. Запуск
падає на записі, який не є origin.

Серверні фронтенди (Astro, Next.js на сервері) викликають API без браузера й не потребують
запису CORS.

## Запити й завантаження

| Налаштування | Типово | Захищає від |
| --- | --- | --- |
| `[server].body_limit` | `"1mb"` | Великих тіл запитів у звичайних API. |
| `[server].request_timeout_secs` | `30` | Повільних запитів, що тримають з'єднання. |
| `[upload].max_file_size` | 200 МБ | Великих завантажень (завантаження мають власний ліміт замість `body_limit`). |
| `[upload].max_image_megapixels` | `100` | Декомпресійних бомб. |

Тип завантаженого файлу визначається за його байтами, а не за типом, який надсилає клієнт;
назва файлу використовується лише як запасний варіант і ніколи — для типів, які браузери
активно виконують (такі файли зберігаються як `application/octet-stream`). Посилання в rich text
`blocks` мають бути `http(s)`, `mailto:` або відносними.

## Адреси клієнтів за проксі

Обмеження частоти й журнали аудиту використовують адресу клієнта. За зворотним проксі кожен
запит надходить від проксі, тож вкажіть проксі в `[server].trusted_proxies`:

```toml title="verdin.toml"
[server]
trusted_proxies = ["10.0.0.0/8"]   # the proxies' IPs or CIDR ranges
```

Тоді Verdin читає `X-Forwarded-For` справа наліво й бере першу адресу, яка не є довіреним
проксі. Запити з будь-якої іншої адреси зберігають адресу з'єднання, тож клієнт не може
підробити свою адресу, надіславши заголовок сам. Не вказуйте діапазони, з яких можуть
підключатися недовірені клієнти.

## Вихідні запити

Вебхуки, deploy hooks, вебхуки очищення CDN і завантаження за URL роблять запити, які вибирає
адміністратор. У `verdin start` вони відхиляють loopback, приватні й link-local адреси
(включно з формами IPv6, що містять приватні адреси IPv4), тож адміністратор не може
використати їх, щоб дістатися сервісів вашої внутрішньої мережі.
`[webhooks].allow_private_networks = true` знімає це обмеження; робіть так, лише якщо кожному
адміністратору можна довірити внутрішню мережу.

## Секрети

`VERDIN_ADMIN_JWT_SECRET` і `VERDIN_TOKEN_PEPPER` читаються лише із середовища, і кожен має
бути щонайменше 32 байти (`verdin secrets` виводить нові). Pepper також шифрує TOTP-секрети
адміністраторів і є основою ключа, що хешує адреси тих, хто надсилає форми. Зберігайте обидва
в менеджері секретів своєї платформи й ніколи не комітьте `.env`.

Журнали запитів приховують значення параметрів запиту, чиї назви схожі на секретні (`token`,
`code`, `password`, `key`, `signature`…), і секретну частину URL callbacks розгортання.

## Метрики

`/_metrics` вимкнено, якщо не задано `[metrics].enabled = true`. Коли його ввімкнено, а токен
не задано, його може читати будь-хто, хто дістається до порту. Задайте `VERDIN_METRICS_TOKEN`
(або `[metrics].token`) і збирайте з `Authorization: Bearer <token>` або заблокуйте шлях на
проксі. Див. [Моніторинг](/uk/deploy/monitoring/).

## Плагіни

Плагіни — це модулі WebAssembly, які Extism запускає в пісочниці. Модуль не має власної
файлової системи, мережі чи бази даних: усе йде через функції хоста, обмежені можливостями в
його `plugin.toml` (типи вмісту, які він читає чи записує, HTTP-хости, власне сховище
ключ-значення), з обмеженням часу й пам'яті на виклик (`[limits]`, 5 с і 64 МБ у прикладі
маніфесту). Адміністратори бачать, що просить плагін, перш ніж його ввімкнути. Адмін-скрипти
плагінів виконуються на сторінці панелі, тож встановлюйте лише плагіни, яким довіряєте. Див.
[Плагіни](/uk/extending/plugins/).

## Експорт і резервні копії

Архіви `verdin export` містять приватні поля й хеші паролів. Зберігайте їх так само, як дампи
бази даних. Див. [Резервні копії](/uk/deploy/backups/).

## Повідомлення про вразливість

Не відкривайте публічний issue для проблеми безпеки. Дотримуйтеся
[політики безпеки](https://github.com/Verdin-CMS/verdin/blob/main/SECURITY.md) репозиторію:
повідомте приватно через вкладку **Security**
[репозиторію](https://github.com/Verdin-CMS/verdin/security) (**Report a vulnerability**),
вказавши версію, кроки для відтворення й вплив, який ви бачите. Виправлення безпеки
перелічено в розділі **Security** у [changelog](/uk/project/changelog/).
