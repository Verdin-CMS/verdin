Дані проєкту Verdin зберігаються у двох місцях: у **базі даних** (вміст, адміністратори, ролі,
токени, налаштування, історія, журнали аудиту) і в **медіасховищі** (файли медіатеки на диску
або в бакеті). Файли схеми лежать у вашому репозиторії. Робіть резервні копії обох сховищ;
`verdin export` додає переносний архів вмісту.

| Спосіб | Містить | Для чого |
| --- | --- | --- |
| Дамп бази даних + копія медіа | Усе | Відновлення того самого проєкту після аварії |
| `verdin export` | Схема, локалі, медіа, усі версії всіх записів | Перенесення вмісту на інший екземпляр або рушій бази даних; додаткова переносна копія |

## Дампи бази даних

Використовуйте власні інструменти вашої бази даних або автоматичні резервні копії провайдера:

```sh frame="terminal"
# PostgreSQL
pg_dump --format=custom --file=verdin-$(date +%F).dump "$VERDIN_DATABASE_URL"

# MySQL / MariaDB
mysqldump --single-transaction --routines -h <host> -u <user> -p <database> > verdin-$(date +%F).sql

# SQLite: узгоджена копія під час роботи сервера
sqlite3 /data/verdin.db ".backup '/backups/verdin-$(date +%F).db'"
```

Не копіюйте робочий файл SQLite через `cp`: використовуйте `.backup` (або спершу зупиніть
сервер).

Дамп містить хеші паролів, хеші API-токенів і приватні поля. Шифруйте його й зберігайте окремо
від серверів, які він захищає. Щоб його відновити, потрібні також ті самі `VERDIN_TOKEN_PEPPER`
і `VERDIN_ADMIN_JWT_SECRET`: без pepper API-токени та коди застосунків-автентифікаторів
адміністраторів перестають працювати.

## Медіасховище

- **Локальний провайдер**: копіюйте каталог завантажень (`[upload].provider.dir`,
  `/data/uploads` в образі Docker) звичайним файловим резервним копіюванням, після дампу бази
  даних, щоб не бракувало жодного файлу, на який посилається дамп.
- **Провайдер S3**: увімкніть версіонування або реплікацію бакета чи копіюйте його
  інструментами провайдера.

Кеш трансформацій зображень і пошуковий індекс можна перебудувати, їм резервні копії не
потрібні.

## `verdin export`

`verdin export` записує схему, вміст і медіа проєкту в один `.tar.gz`, а `verdin import verdin`
відновлює його в той самий проєкт або на інший екземпляр, на будь-якому рушії бази даних.

```sh frame="terminal"
verdin export backup-2026-09-28.tar.gz            # схема, локалі, медіа й записи
verdin export content-only.tar.gz --no-media      # без медіафайлів
verdin import verdin backup-2026-09-28.tar.gz     # у цей проєкт
```

Запускайте їх із конфігурацією проєкту (тим самим `verdin.toml` і середовищем, що й сервер). У
контейнері: `docker compose exec verdin verdin export /data/backup.tar.gz`.

### Що входить

- **Файли схеми** як є.
- **Локалі.** Порожній проєкт отримує їх усі, включно з типовою. Проєкт, який уже має локалі,
  отримує лише відсутні.
- **Медіапапки й файли** з їхніми адаптивними форматами. Файли зберігають свій `documentId`;
  їхні числові id змінюються.
- **Усі версії всіх записів**: чернетки, опубліковані версії й усі локалі, з датами, зв'язками
  (за `documentId`) і медіа, включно зі зв'язками й медіа всередині компонентів і динамічних
  зон. Приватні поля й хеші паролів входять.

**Не входять**: адміністратори, ролі, API-токени, вебхуки, налаштування функцій, процеси
перевірки й релізи. Створіть їх заново на цільовому екземплярі або відновіть натомість дамп
бази даних.

:::caution
Експорт містить приватні поля й хеші паролів. Зберігайте його так само, як дамп бази даних.
:::

### Імпорт

1. Імпорт записує файли схеми й мігрує базу даних лише безпечними кроками.
2. Якщо файли схеми вже існують і відрізняються, він зупиняється, якщо не передати `--force`.
3. Якщо типи вмісту вже мають записи, він теж зупиняється, якщо не передати `--force`; тоді
   записи додаються поруч із наявними.
4. Імпортовані документи зберігають свій `documentId`, тож імпорт у проєкт, який уже має ті
   самі документи, не вдасться.

Імпорт не запускає вебхуки чи хуки плагінів і не записує історію.

### Формат архіву

Tar-архів, стиснутий gzip:

| Шлях | Вміст |
| --- | --- |
| `manifest.json` | `format: "verdin-export"`, версія формату, версія Verdin, кількість версій для кожного типу вмісту |
| `schema/…` | Файли схеми |
| `locales.json` | `{ default, locales: [{ code, name }] }` |
| `folders.json`, `files.jsonl` | Медіапапки й файли, один JSON-об'єкт на рядок |
| `assets/{hash}{ext}` | Збережені об'єкти файлів і їхніх форматів |
| `entries/{uid}.jsonl` | Одна версія на рядок: `documentId`, `locale`, `published`, дати, `data`, `relations`, `media` |

Щоб натомість перенести проєкт Strapi, див. [Міграція зі Strapi](/uk/migrate/from-strapi/).

## Перевіряйте відновлення

Час від часу відновлюйте копію в тестову базу даних, запускайте на ній Verdin через
`verdin start` і перевіряйте, що можете увійти й прочитати записи та медіа.
