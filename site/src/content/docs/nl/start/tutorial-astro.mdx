import { Aside, FileTree, Steps } from '@astrojs/starlight/components';

In deze tutorial bouw je een statische blog met [Astro](https://astro.build) die zijn content uit
Verdin leest: een startpagina die artikelen opsomt, één pagina per artikel op `/articles/<slug>/`
met zijn categorie, en, optioneel, een pagina die concepten toont vanuit de voorbeeldlink van het
beheerpaneel. Je gebruikt de getypeerde client `@verdin/client` met types die uit het schema zijn
gegenereerd.

Geschreven voor Astro 7.3 (`create-astro` 5.2) en Node.js 22.12 of later, met Verdin en
`@verdin/client` 0.10. De [Next.js-tutorial](/nl/start/tutorial-nextjs/) bouwt dezelfde blog met
Next.js.

## Voordat je begint

Je hebt de binary `verdin` in je `PATH` nodig (zie de [Quickstart](/nl/start/quickstart/)),
Node.js en Git. Je eindigt met twee mappen naast elkaar: `cms`, het Verdin-project, en `blog`, de
Astro-site.

## 1. Verdin opzetten met het blogschema

Het project [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) van
de repository modelleert een blog: artikelen met een titel, een `slug`, een samenvatting, een
Markdown-`body`, een categorie en tags, plus een enkel type homepage en een paar componenten.

<Steps>

1. Maak een Verdin-project aan en kopieer het voorbeeldschema erin:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Start het:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   De eerste start maakt de tabellen voor de vier contenttypes aan.

3. Open [http://localhost:1337/admin/](http://localhost:1337/admin/) en maak de eerste beheerder
   aan.

4. Open onder **Collecties** **Category**, kies **Nieuw item**, noem het `News` en sla op.

5. Open **Article**, kies **Nieuw item**, en vul een titel, een samenvatting en een body in
   Markdown in. De `slug` wordt uit de titel gegenereerd. Kies `News` als categorie en kies
   **Publiceren**. Voeg op dezelfde manier een tweede artikel toe.

6. Open **Instellingen → Openbare toegang**, sta **Zoeken** en **Eén zoeken** toe voor **Article**
   en **Category**, en kies **Opslaan**.

</Steps>

Controleer dat de API antwoordt:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Een relatie populeren vereist leestoegang tot het doel ervan. Zonder **Zoeken** op **Category**
antwoordt `populate=category` met `400` en ``invalid key `category` in populate``.
</Aside>

## 2. Het Astro-project aanmaken

In een nieuwe terminal, naast `cms`:

```sh title="Terminal"
npm create astro@latest blog -- --template minimal --no-git --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) zet de Markdown van het veld `body` om in HTML.

## 3. De types genereren

`verdin types` leest het schema en schrijft één TypeScript-interface per contenttype en
component, en een `VerdinSchema`-map van routes voor de client. Draai het vanuit `blog`, met een
verwijzing naar de configuratie van het Verdin-project:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

Het bestand bevat onder meer:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

Relaties, media en componenten zijn optioneel, omdat de API ze alleen teruggeeft als je ze
populeert. Draai het commando opnieuw telkens als het schema verandert.

## 4. Verbinden met Verdin

Declareer de URL van de server, en een optioneel API-token, in de getypeerde omgeving van Astro:

```js title="astro.config.mjs"
// @ts-check
import { defineConfig, envField } from 'astro/config';

export default defineConfig({
  env: {
    schema: {
      VERDIN_URL: envField.string({ context: 'server', access: 'public', default: 'http://localhost:1337' }),
      VERDIN_TOKEN: envField.string({ context: 'server', access: 'secret', optional: true }),
    },
  },
});
```

Zonder token leest de client als de openbare rol, die je in stap 1 hebt opengesteld. Om in plaats
daarvan met een token te lezen, maak je er een aan met **Alleen lezen** in
**Instellingen → API-tokens** en zet je het in `.env` als `VERDIN_TOKEN=…`.

Maak de client één keer aan en deel hem:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import { VERDIN_TOKEN, VERDIN_URL } from 'astro:env/server';
import type { VerdinSchema } from '../verdin-types';

export const verdin = createClient<VerdinSchema>({
  url: VERDIN_URL,
  token: VERDIN_TOKEN,
});
```

`verdin.collection('articles')` accepteert nu alleen de routes van je schema, en de resultaten
zijn getypeerd als `Article`.

## 5. Een lay-out toevoegen

Vervang de HTML van de startpagina door een lay-out die de pagina's delen:

```astro title="src/layouts/Layout.astro"
---
interface Props {
  title: string;
}

const { title } = Astro.props;
---

<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>{title}</title>
  </head>
  <body>
    <header><a href="/">My blog</a></header>
    <main>
      <slot />
    </main>
  </body>
</html>
```

## 6. De artikelen opsommen

```astro title="src/pages/index.astro"
---
import Layout from '../layouts/Layout.astro';
import { verdin } from '../lib/verdin';

const { data: articles } = await verdin.collection('articles').find({
  fields: ['title', 'slug', 'excerpt', 'publishedAt'],
  populate: { category: { fields: ['name'] } },
  sort: ['publishedAt:desc'],
});
---

<Layout title="My blog">
  <h1>Articles</h1>
  <ul>
    {articles.map((article) => (
      <li>
        <a href={`/articles/${article.slug}/`}>{article.title}</a>
        {article.category && <small> in {article.category.name}</small>}
        {article.excerpt && <p>{article.excerpt}</p>}
      </li>
    ))}
  </ul>
</Layout>
```

De query is de REST-aanroep
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`,
in het formaat van Strapi v5. `fields` houdt de response klein, en `populate` voegt de categorie
toe met alleen haar naam. De openbare rol leest alleen gepubliceerde artikelen.

## 7. Een pagina per artikel toevoegen

Astro bouwt één pagina per artikel. `getStaticPaths` haalt de artikelen met hun categorie op en
geeft elk artikel door aan zijn pagina:

```astro title="src/pages/articles/[slug].astro"
---
import type { GetStaticPaths } from 'astro';
import { marked } from 'marked';
import Layout from '../../layouts/Layout.astro';
import { verdin } from '../../lib/verdin';

export const getStaticPaths = (async () => {
  const { data: articles } = await verdin.collection('articles').find({
    populate: { category: true },
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({
    params: { slug: article.slug },
    props: { article },
  }));
}) satisfies GetStaticPaths;

const { article } = Astro.props;
const html = await marked.parse(article.body ?? '');
---

<Layout title={article.title}>
  <article>
    <h1>{article.title}</h1>
    {article.category && <p>Category: {article.category.name}</p>}
    <Fragment set:html={html} />
  </article>
</Layout>
```

`pageSize` is begrensd door `[api].max_page_size` (standaard 100). Met meer artikelen haal je de
pagina's in een lus op met `meta.pagination.pageCount`.

<Aside type="caution">
`marked` saneert geen HTML. Dat is prima voor Markdown die je eigen redacteuren schrijven; als de
content van onbetrouwbare mensen kan komen, saneer je de HTML voordat je hem toont.
</Aside>

## 8. Draaien

```sh title="Terminal"
npm run dev
```

Open [http://localhost:4321](http://localhost:4321): de lijst toont je gepubliceerde artikelen, en
elk artikel linkt naar zijn pagina. `npm run build` schrijft de statische site naar `dist/`.

Een statische build leest de content één keer. Om wijzigingen te publiceren, bouw je de site
opnieuw als content verandert, bijvoorbeeld vanuit een webhook of een deploy-hook; zie
[Deploys en CDN](/nl/guides/integrations/deploys-and-cdn/).

Je project ziet er nu zo uit:

<FileTree>
- blog/
  - astro.config.mjs
  - src/
    - verdin-types.ts gegenereerd door `verdin types`
    - lib/
      - verdin.ts
    - layouts/
      - Layout.astro
    - pages/
      - index.astro
      - articles/
        - [slug].astro
</FileTree>

## 9. Optioneel: voorbeeld van concepten

Het beheerpaneel kan een concept op je site openen met een kortlevend voorbeeldtoken. Het token
leest dat ene document, concepten inbegrepen, en verder niets. Omdat concepten na de build
veranderen, wordt de voorbeeldpagina bij elk request gerenderd, wat een adapter vereist:

```sh title="Terminal"
npx astro add node --yes
```

Voeg een client toe die het voorbeeldtoken in de header `x-verdin-preview` meestuurt:

```ts title="src/lib/verdin.ts" ins={10-16}
import { createClient } from '@verdin/client';
import { VERDIN_TOKEN, VERDIN_URL } from 'astro:env/server';
import type { VerdinSchema } from '../verdin-types';

export const verdin = createClient<VerdinSchema>({
  url: VERDIN_URL,
  token: VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url: VERDIN_URL,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Daarna de pagina. `prerender = false` rendert haar op aanvraag; het token komt binnen als de
queryparameter `preview`:

```astro title="src/pages/preview/[documentId].astro"
---
import { VerdinError } from '@verdin/client';
import { marked } from 'marked';
import Layout from '../../layouts/Layout.astro';
import { previewClient } from '../../lib/verdin';

export const prerender = false;

const { documentId } = Astro.params;
const token = Astro.url.searchParams.get('preview');
if (!documentId || !token) {
  return new Response('Missing preview token', { status: 401 });
}

let article;
try {
  ({ data: article } = await previewClient(token)
    .collection('articles')
    .findOne(documentId, { status: 'draft', populate: { category: true } }));
} catch (error) {
  if (error instanceof VerdinError) {
    return new Response('This preview link has expired', { status: error.status });
  }
  throw error;
}
const html = await marked.parse(article.body ?? '');
Astro.response.headers.set('cache-control', 'no-store');
---

<Layout title={`Preview: ${article.title}`}>
  <p><strong>Draft preview</strong></p>
  <article>
    <h1>{article.title}</h1>
    {article.category && <p>Category: {article.category.name}</p>}
    <Fragment set:html={html} />
  </article>
</Layout>
```

Een voorbeeldtoken kan geen items opsommen, dus de pagina zoekt het concept op via `documentId` in
plaats van via de slug. Vertel Verdin nu waar de pagina staat:

<Steps>

1. Open in het beheerpaneel **Instellingen → Functies**, zet **Voorbeeld** aan en kies
   **Voorbeeld-URL’s instellen**.
2. Stel het URL-sjabloon van **Article** in op `http://localhost:4321/preview/{documentId}` en sla
   op. Verdin voegt het token toe als `?preview=…`.
3. Open een artikel, wijzig het en kies **Concept opslaan**, en kies daarna **Voorbeeld openen**.

</Steps>

De pagina toont het concept. Links zijn standaard 60 minuten geldig. Zie
[Voorbeeld](/nl/guides/content/preview/) voor de placeholders en instellingen, en
[Visueel bewerken](/nl/guides/frontend/visual-editing/) om vanuit het voorbeeld te bewerken.
