import { Aside, FileTree, Steps } from '@astrojs/starlight/components';

Neste tutorial, você constrói um blog com [Next.js](https://nextjs.org) e o App Router que lê o
seu conteúdo do Verdin: uma página inicial que lista os artigos, uma página por artigo em
`/articles/<slug>` com a sua categoria e, opcionalmente, uma página que mostra os rascunhos a
partir do link de pré-visualização da administração. Você usa o cliente tipado `@verdin/client`
com tipos gerados a partir do schema, em Server Components.

Escrito para o Next.js 16.3 (`create-next-app` 16.3), o React 19.2 e o Node.js 20.9 ou posterior,
com o Verdin e o `@verdin/client` 0.10. Ele usa o cache padrão do Next.js, sem
`cacheComponents`. O [tutorial de Astro](/pt-br/start/tutorial-astro/) constrói o mesmo blog com
Astro.

## Antes de começar

Você precisa do binário `verdin` no seu `PATH` (veja o [Início rápido](/pt-br/start/quickstart/)),
do Node.js e do Git. No final, você terá duas pastas lado a lado: `cms`, o projeto Verdin, e
`blog`, o app Next.js.

## 1. Configure o Verdin com o schema do blog

O projeto [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) do
repositório modela um blog: artigos com um título, um `slug`, um resumo, um `body` em Markdown,
uma categoria e tags, além de um single type de página inicial e alguns componentes.

<Steps>

1. Crie um projeto Verdin e copie o schema de exemplo para ele:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Inicie-o:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   A primeira inicialização cria as tabelas dos quatro tipos de conteúdo.

3. Abra [http://localhost:1337/admin/](http://localhost:1337/admin/) e crie o primeiro
   administrador.

4. Em **Coleções**, abra **Category**, selecione **Nova entrada**, dê a ela o nome `News` e
   salve.

5. Abra **Article**, selecione **Nova entrada** e preencha um título, um resumo e um corpo em
   Markdown. O `slug` é gerado a partir do título. Escolha `News` como categoria e selecione
   **Publicar**. Adicione um segundo artigo da mesma forma.

6. Abra **Configurações → Acesso público**, permita **Buscar** e **Buscar um** para **Article** e
   **Category** e selecione **Salvar**.

</Steps>

Verifique se a API responde:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Popular uma relação exige acesso de leitura ao seu destino. Sem **Buscar** em **Category**,
`populate=category` responde `400` com ``invalid key `category` in populate``.
</Aside>

## 2. Crie o app Next.js

Em um novo terminal, ao lado de `cms`:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

O [`marked`](https://marked.js.org) transforma o Markdown do campo `body` em HTML.

## 3. Gere os tipos

O `verdin types` lê o schema e grava uma interface TypeScript por tipo de conteúdo e por
componente, e um mapa `VerdinSchema` das rotas para o cliente. Rode-o a partir de `blog`,
apontando para a configuração do projeto Verdin:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

O arquivo contém, entre outros:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

As relações, a mídia e os componentes são opcionais porque a API só os retorna quando você os
popula. Rode o comando de novo sempre que o schema mudar.

## 4. Conecte-se ao Verdin

Coloque a URL do servidor no `.env.local`:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

Sem token, o cliente lê como a função pública, que é o que você abriu no passo 1. Para ler com um
token, crie um **Somente leitura** em **Configurações → Tokens de API** e defina `VERDIN_TOKEN`.
As duas variáveis ficam no servidor: elas não têm o prefixo `NEXT_PUBLIC_`, e o cliente só roda
em Server Components.

Crie o cliente uma vez e compartilhe-o:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

O `verdin.collection('articles')` agora só aceita as rotas do seu schema, e os seus resultados
são tipados como `Article`.

## 5. Substitua o layout

Substitua o layout inicial e exclua `src/app/page.module.css`, que as novas páginas não usam:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import Link from 'next/link';

export const metadata: Metadata = {
  title: 'My blog',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. Liste os artigos

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

A consulta é a chamada REST
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`,
no formato do Strapi v5. O `fields` mantém a resposta pequena, e o `populate` adiciona a
categoria apenas com o seu nome. A função pública lê apenas os artigos publicados.

O `revalidate = 60` pré-renderiza a página no momento do build e a atualiza no máximo uma vez por
minuto depois disso, então as alterações publicadas aparecem sem um novo build.

## 7. Adicione uma página por artigo

A página do artigo encontra o seu artigo pelo slug com um filtro. O `generateStaticParams`
pré-renderiza os artigos existentes; os artigos publicados depois são renderizados na primeira
visita.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

No Next.js 16, `params` é uma promise: aguarde-a antes de ler o slug. Um slug desconhecido não
encontra nenhum artigo e responde 404 por meio de `notFound()`. O `pageSize` é limitado por
`[api].max_page_size` (100 por padrão).

<Aside type="caution">
O `marked` não sanitiza o HTML. Isso não é problema para o Markdown que os seus próprios editores
escrevem; se o conteúdo puder vir de pessoas não confiáveis, sanitize o HTML antes de
renderizá-lo.
</Aside>

## 8. Rode o app

```sh title="Terminal"
npm run dev
```

Abra [http://localhost:3000](http://localhost:3000): a lista mostra os seus artigos publicados, e
cada um leva à sua página. O `npm run build` precisa do Verdin rodando, porque busca os artigos
para pré-renderizá-los.

Para atualizar as páginas assim que o conteúdo mudar, em vez de em até um minuto, chame
`revalidatePath` a partir de um route handler disparado por um webhook do Verdin; veja
[Webhooks](/pt-br/guides/integrations/webhooks/).

O seu projeto agora fica assim:

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts gerado pelo `verdin types`
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. Opcional: pré-visualize os rascunhos

A administração pode abrir um rascunho no seu site com um token de pré-visualização de curta
duração. O token lê aquele único documento, rascunhos incluídos, e nada mais.

Adicione um cliente que envia o token de pré-visualização no cabeçalho `x-verdin-preview`:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Depois, a página. Ela lê `searchParams`, então o Next.js a renderiza a cada requisição; o token
chega como o parâmetro de consulta `preview`:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Um token de pré-visualização não consegue listar entradas, então a página busca o rascunho pelo
`documentId`, e não pelo slug. Agora diga ao Verdin onde a página fica:

<Steps>

1. Na administração, abra **Configurações → Recursos**, ative **Pré-visualização** e selecione
   **Configurar URLs de pré-visualização**.
2. Defina o modelo de URL de **Article** como `http://localhost:3000/preview/{documentId}` e
   salve. O Verdin acrescenta o token como `?preview=…`.
3. Abra um artigo, altere-o e selecione **Salvar rascunho**, e depois selecione **Abrir
   pré-visualização**.

</Steps>

A página mostra o rascunho. Os links duram 60 minutos por padrão. Veja
[Pré-visualização](/pt-br/guides/content/preview/) para os placeholders e as configurações, e
[Edição visual](/pt-br/guides/frontend/visual-editing/) para editar a partir da
pré-visualização.
