La funcionalitat **Redireccions** permet als editors enviar camins antics a camins nous sense cap
desplegament: mantenen la llista al tauler d'administració, i el teu lloc l'obté i respon amb la
redirecció. Verdin no redirigeix ell mateix els visitants, ja que aquests arriben al teu lloc, no
al CMS.

## Activa-la

A **Configuració → Funcionalitats**, activa **Redireccions** i després tria **Gestiona les
redireccions** (o ves a **Configuració → Redireccions**). Gestionar redireccions necessita el
permís **Gestiona el SEO, les redireccions, els menús i els formularis** (`site.manage`), que té el
rol integrat Editor. Consulta [Permisos](/ca/reference/permissions/).

## Afegeix redireccions

<Steps>

1. A **Configuració → Redireccions**, tria **Afegeix una redirecció**.
2. **Des de**: el camí antic, començant per `/` (per exemple `/blog/2024/hello`).
3. **Cap a**: el camí nou, o un URL `http(s)` complet d'un altre lloc.
4. **Tipus**: **301 · Permanent**, **302 · Temporal**, **307 · Temporal (manté el mètode)** o
   **308 · Permanent (manté el mètode)**.
5. Desa.

</Steps>

Verdin rebutja una redirecció que no funcionaria mai:

- una segona redirecció des del mateix camí;
- un camí que es redirigeix a si mateix;
- una cadena que fa un bucle (`/a` → `/b` → `/a`).

Per a moltes redireccions alhora, fes servir **Importa CSV** amb les columnes `source`,
`destination` i `status`. Les files l'origen de les quals ja existeix actualitzen aquella
redirecció. **Exporta CSV** escriu el mateix format, pràctic per a una migració des d'un altre CMS
o per revisar-les en un full de càlcul.

```csv title="redirects.csv"
source,destination,status
/blog/2024/hello,/blog/hello,301
/old-pricing,https://shop.example.com/pricing,302
```

## Aplica-les al teu lloc

Els llocs llegeixen la llista de `GET /api/_redirects`, sense token:

```json
{
  "data": [
    { "source": "/blog/2024/hello", "destination": "/blog/hello", "status": 301 },
    { "source": "/old-pricing", "destination": "https://shop.example.com/pricing", "status": 302 }
  ]
}
```

La resposta s'envia amb `Cache-Control: public, max-age=60`, de manera que un canvi arriba als
llocs en aproximadament un minut. Compara el camí de la petició exactament amb `source`:

<Tabs syncKey="framework">
<TabItem label="Next.js">

```js title="middleware.js"
import { NextResponse } from 'next/server';

export async function middleware(request) {
  const response = await fetch(`${process.env.VERDIN_URL}/api/_redirects`, { next: { revalidate: 60 } });
  const { data } = await response.json();
  const hit = data.find((redirect) => redirect.source === request.nextUrl.pathname);
  if (hit) return NextResponse.redirect(new URL(hit.destination, request.url), hit.status);
}
```

</TabItem>
<TabItem label="Astro">

```ts title="src/middleware.ts"
import { defineMiddleware } from 'astro:middleware';

let cache: { at: number; list: { source: string; destination: string; status: number }[] } | null = null;

export const onRequest = defineMiddleware(async (context, next) => {
  if (!cache || Date.now() - cache.at > 60_000) {
    const response = await fetch(`${import.meta.env.VERDIN_URL}/api/_redirects`);
    cache = { at: Date.now(), list: (await response.json()).data };
  }
  const hit = cache.list.find((redirect) => redirect.source === context.url.pathname);
  if (hit) return context.redirect(hit.destination, hit.status as 301 | 302 | 307 | 308);
  return next();
});
```

</TabItem>
</Tabs>

Per a un lloc estàtic, obtén la llista en temps de build i escriu el fitxer de redireccions del teu
allotjament (el `_redirects` de Netlify, el `vercel.json` de Vercel, un map d'nginx). Combina-ho
amb un [botó de desplegament](/ca/guides/integrations/deploys-and-cdn/) o un
[webhook](/ca/guides/integrations/webhooks/) perquè els editors puguin reconstruir el lloc després
de canviar les redireccions.

<Aside type="note">
El prefix de l'API segueix [`[api].prefix`](/ca/reference/configuration/). Amb la funcionalitat
desactivada, `/api/_redirects` respon `404`.
</Aside>

## API d'administració

El tauler d'administració fa servir `/admin/api/site/redirects` (`GET`, `POST`) i
`/admin/api/site/redirects/{id}` (`PUT`, `DELETE`), amb el token d'accés d'un administrador i
`site.manage`. La llista està paginada i accepta `search` (consulta [Llistes](/ca/api/admin/#llistes)).
