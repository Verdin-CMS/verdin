import { Aside, FileTree, Steps } from '@astrojs/starlight/components';

En aquest tutorial construeixes un blog amb [Next.js](https://nextjs.org) i l'App Router que llegeix
el contingut de Verdin: una pàgina d'inici que llista els articles, una pàgina per article a
`/articles/<slug>` amb la seva categoria i, opcionalment, una pàgina que mostra els esborranys des
de l'enllaç de previsualització de l'administració. Fas servir el client tipat `@verdin/client` amb
tipus generats a partir de l'esquema, en Server Components.

Escrit per a Next.js 16.3 (`create-next-app` 16.3), React 19.2 i Node.js 20.9 o posterior, amb
Verdin i `@verdin/client` 0.10. Fa servir la memòria cau per defecte de Next.js, sense
`cacheComponents`. El [tutorial d'Astro](/ca/start/tutorial-astro/) construeix el mateix blog amb
Astro.

## Abans de començar

Necessites el binari `verdin` al teu `PATH` (consulta l'[Inici ràpid](/ca/start/quickstart/)),
Node.js i Git. Acabaràs amb dues carpetes una al costat de l'altra: `cms`, el projecte Verdin, i
`blog`, l'aplicació Next.js.

## 1. Configura Verdin amb l'esquema del blog

El projecte [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) del
repositori modela un blog: articles amb un títol, un `slug`, un extracte, un `body` en Markdown, una
categoria i etiquetes, més un tipus únic homepage i uns quants components.

<Steps>

1. Crea un projecte Verdin i copia-hi l'esquema d'exemple:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Inicia'l:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   El primer inici crea les taules dels quatre tipus de contingut.

3. Obre [http://localhost:1337/admin/](http://localhost:1337/admin/) i crea el primer administrador.

4. A **Col·leccions**, obre **Category**, selecciona **Entrada nova**, anomena-la `News` i desa.

5. Obre **Article**, selecciona **Entrada nova** i omple un títol, un extracte i un cos en
   Markdown. L'`slug` es genera a partir del títol. Tria `News` com a categoria i selecciona
   **Publica**. Afegeix un segon article de la mateixa manera.

6. Obre **Configuració → Accés públic**, permet **Cerca** i **Cerca’n un** per a **Article** i
   **Category**, i selecciona **Desa**.

</Steps>

Comprova que l'API respon:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Poblar una relació necessita accés de lectura a la seva destinació. Sense **Cerca** sobre
**Category**, `populate=category` respon `400` amb ``invalid key `category` in populate``.
</Aside>

## 2. Crea l'aplicació Next.js

En un terminal nou, al costat de `cms`:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) converteix en HTML el Markdown del camp `body`.

## 3. Genera els tipus

`verdin types` llegeix l'esquema i escriu una interfície TypeScript per tipus de contingut i
component, i un mapa `VerdinSchema` de rutes per al client. Executa'l des de `blog`, apuntant a la
configuració del projecte Verdin:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

El fitxer conté, entre d'altres:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

Les relacions, la multimèdia i els components són opcionals perquè l'API només els retorna quan els
pobles. Torna a executar l'ordre cada vegada que canviï l'esquema.

## 4. Connecta't a Verdin

Posa l'URL del servidor a `.env.local`:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

Sense token, el client llegeix com a rol públic, que és el que has obert al pas 1. Per llegir amb
un token, crea'n un de **Només lectura** a **Configuració → Tokens d’API** i defineix
`VERDIN_TOKEN`. Totes dues variables es queden al servidor: no tenen el prefix `NEXT_PUBLIC_`, i el
client només s'executa en Server Components.

Crea el client un sol cop i comparteix-lo:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

Ara `verdin.collection('articles')` només accepta les rutes del teu esquema, i els seus resultats
tenen el tipus `Article`.

## 5. Substitueix la disposició

Substitueix la disposició inicial i elimina `src/app/page.module.css`, que les pàgines noves no fan
servir:

```tsx title="src/app/layout.tsx"
export const metadata: Metadata = {

export default function RootLayout({ children }: { children: React.ReactNode }) {

    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. Llista els articles

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

La consulta és la crida REST
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`,
en el format de Strapi v5. `fields` manté la resposta petita, i `populate` hi afegeix la categoria
només amb el seu nom. El rol públic només llegeix articles publicats.

`revalidate = 60` genera la pàgina en temps de build i després la refresca com a màxim un cop per
minut, de manera que els canvis publicats hi apareixen sense tornar a compilar.

## 7. Afegeix una pàgina per article

La pàgina d'article troba el seu article per slug amb un filtre. `generateStaticParams` genera
prèviament els articles existents; els articles publicats més tard es generen a la primera visita.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

A Next.js 16, `params` és una promesa: espera-la abans de llegir l'slug. Un slug desconegut no troba
cap article i respon 404 mitjançant `notFound()`. `pageSize` està limitat per
`[api].max_page_size` (100 per defecte).

<Aside type="caution">
`marked` no sanititza l'HTML. Això està bé per al Markdown que escriuen els teus propis editors; si
el contingut pot venir de persones que no són de confiança, sanititza l'HTML abans de mostrar-lo.
</Aside>

## 8. Executa-la

```sh title="Terminal"
npm run dev
```

Obre [http://localhost:3000](http://localhost:3000): la llista mostra els teus articles publicats, i
cadascun enllaça amb la seva pàgina. `npm run build` necessita que Verdin s'estigui executant,
perquè obté els articles per generar-los prèviament.

Per refrescar les pàgines tan bon punt canviï el contingut en lloc de fer-ho en un minut, crida
`revalidatePath` des d'un route handler que disparï un webhook de Verdin; consulta
[Webhooks](/ca/guides/integrations/webhooks/).

Ara el teu projecte té aquest aspecte:

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts generat per `verdin types`
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. Opcional: previsualitza els esborranys

L'administració pot obrir un esborrany al teu lloc amb un token de previsualització de curta
durada. El token llegeix aquell document concret, esborranys inclosos, i res més.

Afegeix un client que enviï el token de previsualització a la capçalera `x-verdin-preview`:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Després la pàgina. Llegeix `searchParams`, de manera que Next.js la genera a cada petició; el token
arriba com el paràmetre de consulta `preview`:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Un token de previsualització no pot llistar entrades, així que la pàgina busca l'esborrany per
`documentId` en lloc de per slug. Ara digues a Verdin on és la pàgina:

<Steps>

1. A l'administració, obre **Configuració → Funcionalitats**, activa **Previsualització** i
   selecciona **Configura els URL de previsualització**.
2. Defineix la plantilla d'URL d'**Article** com a `http://localhost:3000/preview/{documentId}` i
   desa. Verdin hi afegeix el token com a `?preview=…`.
3. Obre un article, canvia'l i selecciona **Desa l’esborrany**, i després selecciona **Obre la
   previsualització**.

</Steps>

La pàgina mostra l'esborrany. Els enllaços duren 60 minuts per defecte. Consulta
[Previsualització](/ca/guides/content/preview/) per als marcadors i les opcions, i
[Edició visual](/ca/guides/frontend/visual-editing/) per editar des de la previsualització.
