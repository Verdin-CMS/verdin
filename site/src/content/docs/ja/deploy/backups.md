Verdin プロジェクトのデータは 2 か所にあります。**データベース**（コンテンツ、管理者、ロール、トークン、設定、履歴、監査ログ）と、**メディアストレージ**（ディスクまたはバケット上の、メディアライブラリのファイル）です。スキーマファイルはリポジトリにあります。両方のストアをバックアップしてください。`verdin export` を使うと、コンテンツのポータブルなアーカイブも作れます。

| 方法 | 含まれるもの | 用途 |
| --- | --- | --- |
| データベースのダンプ + メディアのコピー | すべて | 同じプロジェクトの障害復旧 |
| `verdin export` | スキーマ、ロケール、メディア、すべてのエントリーのすべてのバージョン | 別のインスタンスや別のデータベースエンジンへのコンテンツの移行、ポータブルな追加のコピー |

## データベースのダンプ

データベース自身のツールか、プロバイダーの自動バックアップを使ってください。

```sh frame="terminal"
# PostgreSQL
pg_dump --format=custom --file=verdin-$(date +%F).dump "$VERDIN_DATABASE_URL"

# MySQL / MariaDB
mysqldump --single-transaction --routines -h <host> -u <user> -p <database> > verdin-$(date +%F).sql

# SQLite: サーバーの実行中に一貫性のあるコピーを作る
sqlite3 /data/verdin.db ".backup '/backups/verdin-$(date +%F).db'"
```

稼働中の SQLite ファイルを `cp` でコピーしないでください。`.backup` を使うか、先にサーバーを停止します。

ダンプには、パスワードのハッシュ、API トークンのハッシュ、private なフィールドが含まれます。暗号化し、保護対象のサーバーとは離れた場所に保管してください。リストアするには、同じ `VERDIN_TOKEN_PEPPER` と `VERDIN_ADMIN_JWT_SECRET` も必要です。pepper がないと、API トークンと、管理者の認証アプリのコードが使えなくなります。

## メディアストレージ

- **ローカルプロバイダー**: アップロードディレクトリ（`[upload].provider.dir`、Docker イメージでは `/data/uploads`）を、通常のファイルバックアップでコピーします。ダンプが参照するファイルが欠けないよう、データベースのダンプの後に行ってください。
- **S3 プロバイダー**: バケットでバージョニングかレプリケーションをオンにするか、プロバイダーのツールでコピーします。

画像変換のキャッシュと検索インデックスは再構築できるので、バックアップは不要です。

## `verdin export`

`verdin export` はプロジェクトのスキーマ、コンテンツ、メディアを 1 つの `.tar.gz` に書き出し、`verdin import verdin` はそれを同じプロジェクトや別のインスタンスに、どのデータベースエンジンでもリストアします。

```sh frame="terminal"
verdin export backup-2026-09-28.tar.gz            # スキーマ、ロケール、メディア、エントリー
verdin export content-only.tar.gz --no-media      # メディアファイルなし
verdin import verdin backup-2026-09-28.tar.gz     # このプロジェクトへ
```

プロジェクトの設定（サーバーと同じ `verdin.toml` と環境）で実行してください。コンテナでは次のようにします: `docker compose exec verdin verdin export /data/backup.tar.gz`。

### 含まれるもの

- **スキーマファイル**。そのままの形で含まれます。
- **ロケール。** 空のプロジェクトは、デフォルトのロケールを含めてすべてを取り込みます。すでにロケールがあるプロジェクトは、足りないものだけを取り込みます。
- **メディアのフォルダーとファイル**。レスポンシブなフォーマットも含みます。ファイルは `documentId` を保ちますが、数値の ID は変わります。
- **すべてのエントリーのすべてのバージョン**。下書き、公開バージョン、すべてのロケールが、日付、リレーション（`documentId` による）、メディアとともに含まれます。コンポーネントやダイナミックゾーン内のリレーションとメディアも含みます。private なフィールドとパスワードのハッシュも含まれます。

**含まれないもの**: 管理者ユーザー、ロール、API トークン、Webhook、機能の設定、レビューワークフロー、リリース。移行先で作り直すか、代わりにデータベースのダンプをリストアしてください。

:::caution
エクスポートには private なフィールドとパスワードのハッシュが含まれます。データベースのダンプと同じように保管してください。
:::

### インポート

1. インポートはスキーマファイルを書き込み、安全なステップだけでデータベースをマイグレーションします。
2. すでに存在し内容の異なるスキーマファイルがあると、`--force` を渡さない限り停止します。
3. すでにエントリーのあるコンテンツタイプがある場合も、`--force` を渡さない限り停止します。渡した場合は、既存のエントリーの隣にエントリーが追加されます。
4. インポートしたドキュメントは `documentId` を保つので、同じドキュメントがすでにあるプロジェクトへのインポートは失敗します。

インポートは Webhook やプラグインのフックを実行せず、履歴も書き込みません。

### アーカイブの形式

gzip で圧縮した tar アーカイブです。

| パス | 内容 |
| --- | --- |
| `manifest.json` | `format: "verdin-export"`、形式のバージョン、Verdin のバージョン、コンテンツタイプごとのバージョン数 |
| `schema/…` | スキーマファイル |
| `locales.json` | `{ default, locales: [{ code, name }] }` |
| `folders.json`、`files.jsonl` | メディアのフォルダーとファイル。1 行に 1 つの JSON オブジェクト |
| `assets/{hash}{ext}` | ファイルとそのフォーマットの保存済みオブジェクト |
| `entries/{uid}.jsonl` | 1 行に 1 つのバージョン: `documentId`、`locale`、`published`、日付、`data`、`relations`、`media` |

代わりに Strapi のプロジェクトを取り込む場合は、[Strapi からの移行](/ja/migrate/from-strapi/)を参照してください。

## リストアをテストする

ときどき使い捨てのデータベースにリストアし、`verdin start` で Verdin を起動して、ログインしてエントリーとメディアを読めることを確認してください。
