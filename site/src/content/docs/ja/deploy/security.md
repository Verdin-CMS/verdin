このページでは、Verdin がプロジェクトを守るために行っていることと、あなたが制御できる設定を説明します。インスタンスを実際のトラフィックに向けて準備するときは、[本番環境のチェックリスト](/ja/deploy/production-checklist/)と一緒に使ってください。

## デフォルトで閉じているもの

- **コンテンツ API。** **設定 → 公開アクセス**で公開の権限を許可するまで、匿名のリクエストには何も与えられません。不明なトークン、期限切れのトークン、不正な形式のトークンは `401` になり、公開ロールにフォールバックすることはありません。[権限](/ja/concepts/permissions/)を参照してください。
- `/api/_openapi.json` の **OpenAPI ドキュメント**は、**設定 → 機能 → APIドキュメント**で公開するまで、有効な API トークンが必要です。
- GraphQL、エンドユーザー、SSO、MCP サーバーなどの**オプション機能**は、`features.manage` 権限を持つ管理者が**設定 → 機能**でオンにするまでオフのままです。
- **プラグイン**は、管理者が**設定 → プラグイン**で 1 つずつオンにするまでオフのままです。
- **クロスオリジンのブラウザーからの呼び出し。** `[api].cors_origins` に登録するまで、どのオリジンもブラウザーから API を呼び出せません。

## 管理者のログイン

| 保護 | 詳細 |
| --- | --- |
| パスワードのハッシュ | OWASP のパラメーターによる Argon2id。パラメーターが変わると再ハッシュされます。 |
| セッション | ページのメモリに保持される（`localStorage` には決して保存されない）15 分のアクセストークンと、`/admin/api/auth` に限定された `HttpOnly`、`SameSite=Strict` の Cookie に入った 30 日のリフレッシュトークン。リフレッシュトークンは使うたびにローテーションされ、古いものを送るとセッション全体が終了します。 |
| セキュア Cookie | `verdin start` では、リフレッシュ Cookie は `Secure` です。`[admin].secure_cookies = false` でオフになり、警告がログに出ます。 |
| CSRF | リフレッシュとログアウトには `X-Verdin-CSRF` ヘッダーが必要で、クロスサイトのフォームからは送れません。 |
| ロックアウト | 5 回失敗すると、アカウントは 15 分間ロックされます。失敗はパスワードと第二要素の両方の段階で数えられます。存在しないメールアドレスと誤ったパスワードには、同じ時間で同じ応答を返します。 |
| レート制限 | ログイン、登録、リフレッシュ: クライアントのアドレスごとに 1 分あたり `[admin].auth_rate_limit` 回（20）。 |
| 第二要素 | 認証アプリ（TOTP）とパスキー、およびリカバリーコード。ロールで必須にできます（`requireTwoFactor`）。[二段階認証](/ja/guides/auth/two-factor/)を参照してください。 |
| Super Admin | Super Admin の作成、編集、削除、リセット、およびそのロールの付与ができるのは Super Admin だけです。最後の有効な Super Admin は削除できません。 |

最初の管理者は、管理者が存在しない間にパネルから登録します。最初の起動の直後に行うか、サーバーを公開する前に `verdin admin create --email …` で作成してください。

## 管理パネルと Admin API

- Admin API（`/admin/api`）は、`[api].cors_origins` の内容にかかわらず CORS ヘッダーを送りません。ブラウザーは、パネル自身のオリジンにしかその応答を読ませません。
- パネルは、厳格な Content Security Policy（スクリプトは自身のオリジンからのみ）、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin` 付きで提供されます。
- Verdin は `Strict-Transport-Security` を送りません。TLS を終端するリバースプロキシで追加してください。

## コンテンツ API

- **API トークン**は一度だけ表示されます。Verdin は `VERDIN_TOKEN_PEPPER` を鍵にした各トークンの HMAC-SHA256 を保存し、表示用に 10 文字のプレフィックスを保持します。トークンは期限切れにでき、再生成もできます。
- **フィールドとロケールの権限**はロールが読み書きできる範囲を制限し、`populate`、リレーションのフィルター、リレーションのソートは、呼び出し元が読み取れる型にしか届きません。
- **クエリの制限**: `pageSize` は最大 `[api].max_page_size`（100）、`populate` の深さは最大 5、フィルター条件は最大 100 個、クエリ文字列は最大 16 KB、リレーションごとに populate されるエントリーは最大 1,000 件です。クエリ内の不明なフィールドや private なフィールドは `400` になります。
- **GraphQL** には独自の深さと複雑さの制限（`maxDepth`、`maxComplexity`）があり、機能の設定にイントロスペクションの切り替えがあります。
- **レート制限**: トークンなしではクライアントのアドレスごとに `[api].public_rate_limit`、API トークンやエンドユーザーごとに `[api].token_rate_limit`（1 分あたりのリクエスト数）。どちらもデフォルトではオフ（`0`）です。不明な Bearer トークン付きのリクエストは、アドレスごとに制限されます。

### CORS

`[api].cors_origins` には、コンテンツ API と GraphQL の呼び出しを許可するブラウザーのオリジンを並べます。

```toml title="verdin.toml"
[api]
cors_origins = ["https://www.example.com", "https://preview.example.com"]
```

各エントリーは、パスや末尾のスラッシュを含まない `scheme://host[:port]` です。`["*"]` はすべてのオリジンを許可し、他のエントリーとは組み合わせられません。許可されるメソッドは `GET`、`POST`、`PUT`、`DELETE`、許可されるリクエストヘッダーは `Authorization`、`Content-Type`、`If-None-Match` です。オリジンでないエントリーがあると起動に失敗します。

サーバーサイドのフロントエンド（Astro、サーバー上の Next.js）はブラウザーを介さずに API を呼び出すので、CORS のエントリーは不要です。

## リクエストとアップロード

| 設定 | デフォルト | 防ぐもの |
| --- | --- | --- |
| `[server].body_limit` | `"1mb"` | 通常の API への大きなリクエストボディ。 |
| `[server].request_timeout_secs` | `30` | 接続を占有する遅いリクエスト。 |
| `[upload].max_file_size` | 200 MB | 大きなアップロード（アップロードには `body_limit` の代わりに独自の制限があります）。 |
| `[upload].max_image_megapixels` | `100` | 解凍爆弾。 |

アップロードされたファイルの種類は、クライアントが送る種類ではなく、ファイルのバイト列から判定します。ファイル名は代替手段にすぎず、ブラウザーが能動的に実行する種類には決して使いません（そのようなファイルは `application/octet-stream` として保存されます）。リッチテキストの `blocks` のリンクは、`http(s)`、`mailto:`、または相対パスでなければなりません。

## プロキシの背後でのクライアントのアドレス

レート制限と監査ログはクライアントのアドレスを使います。リバースプロキシの背後では、すべてのリクエストがプロキシから来るので、プロキシを `[server].trusted_proxies` に登録してください。

```toml title="verdin.toml"
[server]
trusted_proxies = ["10.0.0.0/8"]   # the proxies' IPs or CIDR ranges
```

すると Verdin は `X-Forwarded-For` を右から左に読み、信頼されたプロキシでない最初のアドレスを採用します。それ以外のアドレスからのリクエストは接続元のアドレスのままなので、クライアントが自分でヘッダーを送ってアドレスを偽ることはできません。信頼できないクライアントが接続できる範囲は登録しないでください。

## 外向きのリクエスト

Webhook、デプロイフック、CDN のパージ用 Webhook、URL からのアップロードは、管理者が選んだ宛先にリクエストを送ります。`verdin start` では、ループバック、プライベート、リンクローカルのアドレス（プライベートな IPv4 アドレスを埋め込んだ IPv6 の形式を含む）を拒否するので、管理者がこれらを使って内部ネットワーク上のサービスに到達することはできません。`[webhooks].allow_private_networks = true` でこの制限を外せます。すべての管理者に内部ネットワークを任せられる場合にだけ行ってください。

## シークレット

`VERDIN_ADMIN_JWT_SECRET` と `VERDIN_TOKEN_PEPPER` は環境変数からだけ読み込まれ、それぞれ 32 バイト以上である必要があります（`verdin secrets` が新しい値を出力します）。pepper は管理者の TOTP シークレットの封印にも使われ、フォーム送信者のアドレスをハッシュする鍵の導出にも使われます。どちらもプラットフォームのシークレットマネージャーに保管し、`.env` は決してコミットしないでください。

リクエストのログでは、名前がシークレットに見えるクエリパラメーター（`token`、`code`、`password`、`key`、`signature` など）の値と、デプロイのコールバック URL のシークレット部分が隠されます。

## メトリクス

`/_metrics` は、`[metrics].enabled = true` でない限りオフです。オンでトークンが設定されていない場合、ポートに到達できる誰もが読めます。`VERDIN_METRICS_TOKEN`（または `[metrics].token`）を設定して `Authorization: Bearer <token>` でスクレイプするか、プロキシでパスをブロックしてください。[監視](/ja/deploy/monitoring/)を参照してください。

## プラグイン

プラグインは、Extism がサンドボックス内で実行する WebAssembly モジュールです。モジュールは独自のファイルシステム、ネットワーク、データベースを持ちません。すべては、`plugin.toml` の機能（読み書きするコンテンツタイプ、HTTP のホスト、自身のキーバリューストア）で制限されたホスト関数を通じて行われ、呼び出しごとに時間とメモリの制限（`[limits]`、サンプルのマニフェストでは 5 秒と 64 MB）があります。管理者は、プラグインをオンにする前にそのプラグインが求めるものを確認できます。プラグインの管理画面用スクリプトはパネルのページ内で実行されるので、信頼できるプラグインだけをインストールしてください。[プラグイン](/ja/extending/plugins/)を参照してください。

## エクスポートとバックアップ

`verdin export` のアーカイブには、private なフィールドとパスワードのハッシュが含まれます。データベースのダンプと同じように保管してください。[バックアップ](/ja/deploy/backups/)を参照してください。

## 脆弱性の報告

セキュリティの問題について、公開の Issue を開かないでください。リポジトリの[セキュリティポリシー](https://github.com/Verdin-CMS/verdin/blob/main/SECURITY.md)に従い、[リポジトリ](https://github.com/Verdin-CMS/verdin/security)の **Security** タブ（**Report a vulnerability**）から非公開で報告してください。バージョン、再現手順、想定される影響を添えてください。セキュリティの修正は、[チェンジログ](/ja/project/changelog/)の **Security** に記載されます。
