多言語化されたコンテンツタイプは、各エントリーのバージョンをロケールごとに 1 つ保持します。このガイドでは、公開に使うロケールを追加し、型の多言語化をオンにし、管理パネルでエントリーを翻訳し、API で各ロケールを読み書きします。その背後にあるモデル（共有フィールド、多言語化された型の間のリレーション）については、[国際化](/ja/concepts/internationalization/)を参照してください。

多言語化はコアの一部で、オンにする機能はありません。Strapi v5 の i18n プラグインと同じように動き、同じ `locale` パラメーターを受け付けます。

## 始める前に

- ロケールの追加、名前の変更、削除には**言語の管理**（`locales.manage`）が必要です。
- 型を多言語化するには、**コンテンツタイプビルダー**（`verdin dev`）か `schema/content-types/<name>.json` でスキーマを編集します。
- 編集者に必要なコンテンツの権限については、[権限](/ja/reference/permissions/)を参照してください。

## ロケールを追加する

最初の起動で、英語（`en`）がデフォルトのロケールとして作成されます。ロケールを指定しないリクエストはデフォルトのロケールを使い、新しいエントリーはデフォルトのロケールで始まります。

<Steps>

1. **設定 → 国際化**を開き、**言語を追加**を選びます。
2. **コード**を入力します。小文字の言語コードで、`fr`、`pt-BR`、`zh-Hans` のように地域や文字体系を付けることもできます。名前は自動で入力され、変更もできます。
3. ロケールを指定しないリクエストでこのロケールを使う場合は**デフォルトの言語にする**にチェックを入れ、保存します。

</Steps>

後でデフォルトを変更するには、別のロケールで**デフォルトに設定**を選びます。デフォルトのロケールは削除できません。

<Aside type="caution" title="ロケールを削除するとそのエントリーも削除される">
ロケールを削除すると、そのロケールで書かれたすべてのエントリーが、公開バージョンを含め、すべてのコンテンツタイプで完全に削除されます。確認のため、ダイアログでロケールのコードの入力を求められます。
</Aside>

## コンテンツタイプを多言語化する

**コンテンツタイプビルダー**で型を開き、その設定で**多言語化**をオンにします。その後、フィールドごとに、ロケールによって異なる値を持つかどうかを決めます。**多言語化**をオフにしたフィールドは、すべてのロケールで共有される 1 つの値を持ちます。

サンプルプロジェクトの `article` 型について、スキーマファイルで同じことを書くと次のようになります。

```json title="schema/content-types/article.json" {6,9}
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

共有フィールドの動作:

- あるロケールで共有フィールドを保存すると、すべてのロケールの下書きに書き込まれます。
- あるロケールを公開すると、その共有フィールドが他のロケールの公開バージョンにコピーされます。
- リレーションとメディアのフィールドも共有できます。

`pluginOptions.i18n.localized` のない型は多言語化されず、`locale` パラメーターを無視します。型の多言語化を変更するのはスキーマの変更です。デプロイする前に `verdin migrate plan` でマイグレーションを確認してください。

## 管理パネルでエントリーを翻訳する

<Steps>

1. エントリーを開き、エディターの上部にある**言語**の切り替えで翻訳先の言語を選びます。バージョンのないロケールには**未作成**と表示されます。
2. エディターは、エントリーにまだそのロケールのバージョンがないこと、そして保存すると作成されることを知らせます。共有フィールドにはすでに値が表示されています。
3. 既存の翻訳から始めるには、その通知の**他の言語から入力**を選びます。**コピー元**でコピー元を選び、**フィールドをコピー**を選びます。リレーションとメディアを含む多言語化されたフィールドがフォームにコピーされます。まだ何も保存されていません。
4. フィールドを編集してから、**下書きを保存**または**公開**を選びます。各ロケールは独自の下書きと公開バージョンを持ちます。

</Steps>

一覧のビューにも同じ**言語**の切り替えがあり、一度に 1 つのロケールのバージョンを一覧にします。エディターから削除すると、現在のロケールのバージョンだけが削除され、他のロケールは残ります。

**AIアクション**の機能がオンの場合、エディターは別のロケールの下書きからテキストフィールドを翻訳することもできます。[AI アクション](/ja/guides/integrations/ai-actions/)を参照してください。

## 編集者を一部のロケールに限定する

ロールのコンテンツの権限は、一部のロケールだけを対象にできます。**設定 → ロール**でロールを開き、コンテンツタイプを探して**言語**を選びます。**これらの言語のみ**を選び、ロケールを選びます。そのロールを持つ管理者は、他のロケールのバージョンを読むことも変更することもできず、**言語**の切り替えではそれらのロケールが「（アクセス不可）」と表示されます。

## API でロケールを読み書きする

REST のリクエストに `locale` を付けるか、GraphQL で引数として渡します。指定しない場合はデフォルトのロケールが使われます。不明なロケールは `400` エラーになります。

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
# フランス語版を読む
curl 'http://localhost:1337/api/articles?locale=fr'

# ドキュメントのフランス語版を作成または更新する
curl -X PUT 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"data":{"title":"Bonjour"}}'

# フランス語版だけを削除する
curl -X DELETE 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN"
```

</TabItem>
<TabItem label="GraphQL">

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
    locale
  }
}
```

</TabItem>
<TabItem label="TypeScript">

```ts
const { data } = await verdin.collection('articles').find({ locale: 'fr' });
```

</TabItem>
</Tabs>

予想される動作:

- `locale` 付きの `PUT` は、ドキュメントにまだそのロケールのバージョンがなければ作成します。
- 多言語化された型のレスポンスには `locale` が含まれます。すべてのバージョンが同じ `documentId` を共有します。
- `DELETE` は、リクエストしたロケール（指定がなければデフォルトのロケール）のバージョンだけを削除します。そのドキュメントを指すリンクは、ロケールが 1 つも残らなくなった時点で削除されます。
- 多言語化された型が別の多言語化された型にリンクしている場合、読み取りでは同じロケールで対象が解決され、リレーションを介したフィルターも同じです。多言語化されていない対象は、すべてのロケールで共有されます。
- Webhook のペイロードと履歴のバージョンには、ロケールが記録されます。

Strapi と異なり、コンテンツ API には `/api/i18n/locales` のルートがありません。ロケールは Admin API の `GET /admin/api/i18n/locales` で一覧でき、`POST`、`PUT /admin/api/i18n/locales/{code}`、`DELETE /admin/api/i18n/locales/{code}`（`locales.manage`）で管理します。
