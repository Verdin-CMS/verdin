レビューワークフローは、*To do*、*In review*、*Ready* のような段階を順に並べたもので、一部のコンテンツタイプのエントリーは公開前にそれらを進んでいきます。このガイドでは、ワークフローを設定し、エントリーを移動・割り当てし、対応する Admin API を紹介します。

Strapi ではレビューワークフローは Enterprise の機能です。Verdin ではオープンソースのコアの一部です。

## 始める前に

- **設定 → 機能 → レビューワークフロー**をオンにします。デフォルトではオフです。
- ワークフローの設定には**レビューワークフローの管理**（`workflows.manage`）が必要です。
- エントリーの移動と割り当てには、そのエントリーへの更新権限が必要です。[権限](/ja/reference/permissions/)を参照してください。

## ワークフローを作成する

<Steps>

1. **設定 → レビューワークフロー**を開き、**新規ワークフロー**を選びます。
2. **名前**を付けます。
3. **コンテンツタイプ**で、エントリーがこのワークフローに従う型を選びます。1 つの型が従うワークフローは最大 1 つです。
4. **段階**で、段階を順に並べます。各段階には**段階名**と**色**があります。**段階を追加**で段階を増やし、矢印のボタンで並べ替えます。新しいエントリーは最初の段階から始まります。
5. 必要なら、段階ごとに**エントリーをこの段階に移動できるロール**を選びます。ロールを選ばない場合は、エントリーを更新できる人なら誰でも移動できます。
6. 必要なら、**公開に必要な段階**を設定します。すると、エントリーはその段階にある間だけ公開できるようになります。**どの段階でも**を選ぶと、公開には影響しません。
7. 保存します。

</Steps>

型がワークフローに加わる前から存在していたエントリーは、最初の段階にあります。

後でワークフローを変更した場合:

- 段階を削除すると、そのエントリーは最初の段階に戻ります。
- ワークフローからコンテンツタイプを外すと、そのエントリーの段階が消去されます。
- ワークフローを削除すると、そのエントリーの段階と担当者が消去されます。

## エントリーを移動・割り当てする

エントリーエディターには、**段階**と**担当者**を持つ**レビュー**のパネルが表示されます。

- 別の**段階**を選ぶと、エントリーが移動します。他のロール専用の段階は選べず、パネルにその旨が表示されます。**レビューワークフローの管理**を持つ管理者は、常にエントリーを移動できます。
- コンテンツタイプを読み取れる有効な管理者から**担当者**を選ぶか、**担当者を削除**を選びます。エントリーを更新できる人なら誰でも割り当てられます。
- ワークフローに必要な段階がある場合、パネルには、**公開**が使えるようになる前にエントリーがどの段階に達する必要があるかが表示されます。

一覧のビューには**段階**の列があり、ホームページには、あなたに割り当てられたエントリーが**自分への割り当て**に一覧されます。多言語化された型では、ロケールごとに段階が保持されます。

## 公開に必要な段階が止めるもの

必要な段階は、管理パネル、REST、GraphQL、リリース、プラグインなど、すべての公開方法に適用されます。その段階にないエントリーの公開は `400` で失敗します。

```text
the entry must be in the review stage `Ready` to be published
```

Strapi では、段階の要件は管理パネルにしか適用されません。段階のロールも異なります。Verdin では、段階のロールは、その段階*へ*エントリーを移動できる人を制限します。

## 監査ログと Webhook

- 段階の変更と割り当ては、`entry.stage` と `entry.assign` として[監査ログ](/ja/guides/content/audit-logs/)に記録されます。
- Webhook は**エントリーの段階変更**（`review-workflows.updateEntryStage`）を購読できます。[Webhook](/ja/guides/integrations/webhooks/) を参照してください。

## Admin API

すべてのルートは `/admin/api` 配下にあり、管理者のアクセストークンを受け取ります。

| ルート | 権限 | 動作 |
| --- | --- | --- |
| `GET /review-workflows`、`GET /review-workflows/{id}` | `workflows.manage` | 段階付きのワークフロー。 |
| `POST /review-workflows`、`PUT /review-workflows/{id}` | `workflows.manage` | ワークフローを作成または置き換えます（ボディは下記）。 |
| `DELETE /review-workflows/{id}` | `workflows.manage` | その型のエントリーは段階を失います。 |
| `GET /content/{uid}/{documentId}/review?locale=` | エントリーの読み取り | 段階、担当者、エントリーを移動できる段階（`canMoveTo`）。 |
| `PUT /content/{uid}/{documentId}/review?locale=` | エントリーの更新 | `{ "stageId": 3, "assigneeId": 7 }`。どちらのフィールドも任意です。`"assigneeId": null` で担当者を削除します。 |
| `GET /content/{uid}/review?documentIds=a,b` | 型の読み取り | 最大 200 件のエントリーの段階。ワークフローは `meta.workflow` に入ります。 |
| `GET /review/assigned` | ログイン済み | あなたに割り当てられたエントリー。 |
| `GET /review/assignees?uid=` | 型の更新 | その型を読み取れる有効な管理者。 |
| `GET /review/roles` | `workflows.manage` | 段階のロール用の、ロールのコードと名前。 |

`POST` と `PUT` に送るワークフロー:

```json
{
  "name": "Editorial",
  "contentTypes": ["api::article"],
  "stages": [
    { "id": 1, "name": "To do", "color": "#4945ff" },
    { "id": 2, "name": "In review", "color": "#ff8800" },
    { "name": "Ready", "color": "#2f9e44", "roles": ["editor"] }
  ],
  "publishStage": "Ready"
}
```

- ワークフローは、一意の名前と `#rrggbb` の色を持つ 1〜50 個の段階を持ちます。
- `publishStage` は段階の 1 つを指定します。指定しない場合は省略します。
- 既存の段階は `id` 付きで送ってください。そうすれば、そのエントリーは今の段階にとどまります。`id` のない段階は新しい段階です。

<Aside type="note">
機能をオフにすると、段階が非表示になり、公開に必要な段階の強制も止まります。ワークフローとエントリーの段階は、再びオンにするときのために保持されます。
</Aside>
