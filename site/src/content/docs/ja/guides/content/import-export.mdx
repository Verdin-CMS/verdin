各コンテンツタイプの管理画面の一覧では、エントリーを CSV や JSON にエクスポートし、同じ種類のファイルからインポートし直せます。スプレッドシートで多くのエントリーを修正したり、商品カタログを読み込んだり、プロジェクト間でエントリーをコピーしたりするのに使えます。このガイドでは、両方の方向とファイルの形式を説明します。

これは一度に 1 つのコンテンツタイプのエントリーを扱うためのものです。プロジェクト全体を移すには、[`verdin export` と `verdin import verdin`](/ja/reference/cli/) を参照してください。Strapi から移行する場合は、[Strapi からの移行](/ja/migrate/from-strapi/)を参照してください。

## 始める前に

- エクスポートには、コンテンツタイプへの読み取り権限が必要です。エクスポートされるのは、ロールが読み取れるフィールドだけです。
- インポートには、作成権限、更新権限、またはその両方が必要です。エントリーを作成する行には作成権限が、更新する行には更新権限が必要です。インポートした行を公開するには公開権限も必要です。[権限](/ja/reference/permissions/)を参照してください。

## エントリーをエクスポートする

<Steps>

1. コンテンツタイプの一覧を開き、エクスポートしたい状態に設定します。フィルター、検索、ソート、ステータス、ロケールです。
2. **エクスポート**を選び、続いて **CSVとしてエクスポート**または **JSONとしてエクスポート**を選びます。

</Steps>

ファイルには、一覧が表示しているエントリーが、そのフィルター、検索、ソートのまま、すべてのページにわたって最大 50,000 件入ります。各行は `documentId` で始まり、その後にフィールドが続きます。

## エントリーをインポートする

<Steps>

1. コンテンツタイプの一覧を開き、**インポート**を選びます。
2. **ファイル**を選びます。ヘッダー行のある `.csv` ファイルか、オブジェクトのリストを持つ `.json` ファイルで、最大 1 MB です。
3. **列**で、各列を入れるフィールドを選びます。フィールドと同じ名前の列はすでに対応付けられています。列を除外するには**スキップ**を、既存のエントリーを示す列には<strong>ドキュメントID（更新）</strong>を選びます。
4. 必要なら、**インポートしたエントリーを公開**をオンにします。オフの場合は下書きとして保存されます。
5. **確認**を選びます。Verdin は、制約や参照を含めてすべての行を何も書き込まずに確認し、作成、更新、拒否する行を報告します。
6. 必要ならファイルを修正してから、**インポート**を選びます。

</Steps>

行の書き込み方:

- `documentId` を持つ行はそのエントリーを更新し、それ以外の行は新しいエントリーを作成します。
- 行は 1 行ずつ書き込まれます。失敗した行はフィールドと問題とともに報告されてスキップされ、他の行は引き続き書き込まれます。
- 報告には、エラーのある行が最大 100 行と、どのフィールドにも対応しなかった列が並びます。
- 1 回のインポートは最大 5,000 行です。それより大きいファイルは分割してください。
- エントリーは、一覧の現在のロケールで書き込まれます。

<Aside type="caution">
インポートは、エディターと同じバリデーションで行を処理しますが、元に戻す機能はありません。先に**確認**を実行し、大きな更新の前には、元に戻せるように一覧をエクスポートしておいてください。[コンテンツ履歴](/ja/guides/content/content-history/)がオンなら、更新されたすべてのエントリーに以前のバージョンが残ります。
</Aside>

## ファイルの形式

フィールドは、コンテンツ API の書き込み形式と同じ形を使います。

| フィールド | 値 |
| --- | --- |
| テキスト、数値、ブール値、日付 | API と同じ（`true`/`false`、ISO 8601 の日付）。 |
| リレーション | 関連するエントリーの `documentId`。 |
| メディア | メディアライブラリのファイル ID。 |
| ポリモーフィックリレーション | `uid:documentId`。例: `api::article:k3v9…`。 |
| コンポーネント、ダイナミックゾーン、blocks、JSON | JSON。 |

CSV では、リスト（複数のリレーションやファイル）は `|` でつなぎます。

```csv title="articles.csv"
documentId,title,slug,featured,tags
,Hello world,hello-world,true,t1a2b3|t4c5d6
k3v9x8…,Updated title,updated-title,false,
```

同じ行を JSON で表すと次のようになります。

```json title="articles.json"
[
  { "title": "Hello world", "slug": "hello-world", "featured": true, "tags": ["t1a2b3", "t4c5d6"] },
  { "documentId": "k3v9x8…", "title": "Updated title", "slug": "updated-title", "featured": false }
]
```

一覧のエクスポートは、同じコンテンツタイプに対して常に有効なインポートファイルです。

## Admin API

- `GET /admin/api/content/{uid}/export?format=csv`（または `json`）は、一覧のクエリパラメーター `filters`、`_q`、`sort`、`status`、`locale` を受け付けます。
- `POST /admin/api/content/{uid}/import?locale=` は、ファイルの内容を文字列として受け取ります。

```json
{
  "format": "csv",
  "data": "title,slug\nHello world,hello-world\n",
  "mapping": { "slug": "slug", "notes": null },
  "dryRun": true,
  "publish": false
}
```

`mapping` は列をフィールドに対応付けます。`null` にするとその列をスキップし、対応付けていない列はその名前のまま使われます。リクエストボディは `[server].body_limit`（デフォルトは 1 MB）で制限されます。
