Verdin は、エントリーが作成、保存、公開、非公開にされるたびに、また下書きが破棄されるたびに、どの API からであってもバージョンを保持します。このガイドでは、古いバージョンを探して復元する方法、保持されるバージョンの数、対応する Admin API を説明します。

コンテンツ履歴は Strapi と同じように動きます。Strapi では有料の機能です。

## 始める前に

- **設定 → 機能 → コンテンツ履歴**はデフォルトでオンです。オフの間はバージョンが記録されず、履歴は使えません。
- エントリーの履歴を読むにはエントリーへの読み取り権限が、復元するには更新権限が必要です。フィールドの制限が適用されます。表示・復元できるのは、ロールが読み取り・更新できるフィールドだけです。[権限](/ja/reference/permissions/)を参照してください。

## バージョンを復元する

<Steps>

1. エントリーを開き、**履歴**を選びます。
2. **バージョン**の一覧に、各バージョンがイベント（**作成**、**保存**、**公開**、**非公開**、**下書きを破棄**）、日付、実行した人とともに表示されます。コンテンツ API を通じた変更では、作成者として **API** が表示されます。
3. バージョンを選ぶと、そのフィールドが表示されます。
4. **復元**を選び、確認します。

</Steps>

そのバージョンが現在の下書きを置き換えます。準備ができたら、後で公開してください。下書きと公開を使わない型では、復元するとエントリーが直接更新されます。

復元するときに除外されるもの:

- スキーマに存在しなくなったフィールドは一覧に表示され、復元されません。
- 削除されたエントリーやファイルへの参照は取り除かれ、エディターはどのフィールドで参照が失われたかを知らせます。

**エディターに戻る**を選ぶと、何も変更せずにエントリーに戻ります。

## 保持されるバージョンの数

Verdin は、エントリーとロケールごとに最新の `[history].max_versions` 個（デフォルトは 50）のバージョンを保持し、新しいバージョンが来ると古いものを削除します。

```toml title="verdin.toml"
[history]
max_versions = 100
```

多言語化されたエントリーでは、ロケールごとに独自の履歴があります。エントリーやそのロケールの 1 つを削除すると、そのバージョンも削除されます。[設定のリファレンス](/ja/reference/configuration/)を参照してください。

<Aside type="note">
履歴を日数で保持する Strapi とは異なり、Verdin はどれだけ古くても、エントリーごとに一定の数のバージョンを保持します。
</Aside>

## Admin API

すべてのルートは `/admin/api` 配下にあります。

| ルート | 権限 | 動作 |
| --- | --- | --- |
| `GET /history/{uid}/{documentId}?locale=&page=&pageSize=` | エントリーの読み取り | データを含まない、新しい順のバージョン（1 ページ 20 件、最大 100 件）。 |
| `GET /history/versions/{id}` | エントリーの読み取り | データ付きの 1 つのバージョン。 |
| `POST /history/versions/{id}/restore` | エントリーの更新 | そのバージョンを現在の下書きとして復元します。 |

復元の応答には、取り除かれたものが並びます。

```json
{
  "data": {
    "documentId": "k3v9…",
    "restored": 42,
    "dropped": [{ "field": "tags", "count": 1 }]
  }
}
```

機能がオフの間、ルートは `404` を返します。
