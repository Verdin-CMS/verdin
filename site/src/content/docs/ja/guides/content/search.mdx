コンテンツ API と管理パネルは、Strapi と同様に `_q` パラメーターでエントリーを検索します。デフォルトでは、`_q` は語句を含むテキストフィールドに一致します。`[search]` インデックスをオンにすると、サーバーに組み込まれた全文検索エンジン（Tantivy）で結果を順位付けします。このガイドでは、両方と、インデックスを使うべき場面を説明します。

## `_q` で検索する

```sh title="Terminal"
curl -G 'http://localhost:1337/api/articles' --data-urlencode '_q=rust cms'
```

`_q` は、他のパラメーター `filters`、`status`、`locale`、`pagination`、`fields`、`populate` と組み合わせられます。管理画面の一覧の検索ボックスも、同じパラメーターを送ります。

検索されるフィールド:

- テキストフィールド: `string`、`text`、`richtext`、`email`、`uid`、`enumeration`。
- インデックスがある場合は、`blocks`、コンポーネント、ダイナミックゾーン内のテキストも。
- private なフィールドとパスワードは決して検索されません。

`_q` は REST のパラメーターです。GraphQL と TypeScript クライアントのクエリオプションには検索の引数がないので、そこでは `$containsi` フィルターを使ってください。

## インデックスなし

`[search]` がない場合、`_q` は、Strapi の `$containsi` と同様に、いずれかのテキストフィールドが検索テキスト全体を大文字小文字を区別せずに含むエントリーに一致します。結果は通常のソートに従います。設定は不要でどのデータベースでも動きますが、テーブルを走査し、順位付けは行いません。

## 全文インデックスをオンにする

<Steps>

1. `verdin.toml` でインデックスを有効にします。

   ```toml title="verdin.toml"
   [search]
   enabled = true
   ```

2. Verdin を再起動します。バックグラウンドですべてのエントリーからインデックスを構築します。準備ができるまで、`_q` は `$containsi` にフォールバックします。

</Steps>

| キー | デフォルト | 説明 |
| --- | --- | --- |
| `enabled` | `false` | 全文インデックスで `_q` を順位付けします。 |
| `dir` | `"data/search"` | インデックスのディレクトリ。プロジェクトからの相対パス。 |
| `memory_mb` | `50` | インデックス作成に使うメモリの上限（メガバイト）。 |

[設定のリファレンス](/ja/reference/configuration/)を参照してください。

インデックスの照合方法:

- 語は英字や数字以外の文字で区切られ、小文字にされ、アクセントが除かれるので、`cafe` で `Café` が見つかります。
- すべての語が一致する必要があります。最後の語は前方一致でも一致するので、入力中に結果が表示されます。
- タイトル（型の最初のテキストフィールド）は 2 倍の重みを持ちます。
- `sort` がない場合、結果は一致度の高い順に並びます。`sort` がある場合は、一致したものが指定の順序で並びます。1 回の検索で考慮される一致は最大 1,000 件です。
- 下書きと公開バージョン、そして各ロケールは、`status` と `locale` に従って別々に検索されます。

インデックスは、どの API からの書き込みにも追従します。スキーマの変更で検索対象のフィールドが変わったときと、ディレクトリがないときに再構築されます。

## 複数のインスタンス

インデックスはインスタンスのディスクにあり、そのインスタンスの書き込みに追従します。インスタンスを複数実行すると、あるインスタンスでの書き込みは他のインスタンスのインデックスに届きません。検索を 1 つのインスタンスに限定するか、デプロイ後、起動前にインデックスのディレクトリを削除して再構築してください。[スケーリング](/ja/deploy/scaling/)を参照してください。

<Aside type="tip">
インデックスのディレクトリは削除しても安全です。バックアップとバージョン管理の対象外にしてください。Verdin はデータベースからインデックスを再構築します。
</Aside>
