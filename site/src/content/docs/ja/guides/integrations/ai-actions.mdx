AI アクションは、管理パネルに 4 つの補助機能を追加します。別のロケールからのエントリーの翻訳、画像の代替テキストの作成、長いテキストを短いフィールドに要約すること、SEO のメタデータの提案です。これらは、あなたが設定したモデルプロバイダー（Anthropic、OpenAI、または Ollama のようなローカルサーバー）を、あなた自身のキーで使います。

どのアクションもフォームを埋める提案を返します。編集者が確認して保存するまで何も保存されず、各アクションは元に戻せます。

## 設定する

AI アクションには、`verdin.toml` のプロバイダーと、機能のオンの両方が必要です。

<Steps>

1. `[ai]` セクションを追加し、`VERDIN_AI_KEY` でサーバーにキーを渡します。

   <Tabs syncKey="ai-provider">
   <TabItem label="Anthropic">

   ```toml title="verdin.toml"
   [ai]
   provider = "anthropic"
   # model = "claude-sonnet-5"   # the default
   ```

   </TabItem>
   <TabItem label="OpenAI">

   ```toml title="verdin.toml"
   [ai]
   provider = "openai"
   model = "gpt-4.1-mini"        # required: name the model you want
   ```

   </TabItem>
   <TabItem label="Local (Ollama)">

   ```toml title="verdin.toml"
   [ai]
   provider = "openai-compatible"
   base_url = "http://localhost:11434/v1"
   model = "llama3.2-vision"
   ```

   ローカルサーバーには `VERDIN_AI_KEY` は不要です。LM Studio、vLLM など、OpenAI 互換の API を持つサーバーも同じように動きます。

   </TabItem>
   </Tabs>

   ```sh title="Terminal"
   export VERDIN_AI_KEY=sk-...
   ```

2. Verdin を再起動します。キーがない場合や、プロバイダーが必要とする `model` や `base_url` がない場合など、セクションが不完全だと起動を拒否します。
3. **設定 → 機能**で **AIアクション**をオンにします。

</Steps>

| キー | デフォルト | 説明 |
| --- | --- | --- |
| `provider` | `"none"` | `anthropic`、`openai`、`openai-compatible` のいずれか。 |
| `model` | `anthropic` では `claude-sonnet-5` | モデル。その他のプロバイダーでは必須です。 |
| `base_url` | プロバイダーのもの | 別のエンドポイント。プロキシまたはローカルサーバー（`openai-compatible` では必須）。 |
| `max_tokens` | `2048` | 応答の最大長（トークン数）。 |

[`[ai]`](/ja/reference/configuration/) を参照してください。機能がオンでも `[ai]` セクションがない場合、管理画面には<strong>このサーバーではAIアクションを利用できません。</strong>と表示されます。

代替テキストのアクションは画像を送るので、使う場合は画像を受け付けるモデルを選んでください。

## アクションの内容

### エントリーを翻訳する

多言語化されたエントリーのエディターで、<strong>_locale_から翻訳…</strong>を選ぶと **AIで翻訳**が開きます。**翻訳元**のロケールを選び、**翻訳**を選びます。そのロケールの保存済みの下書きのテキストフィールド（文字列、テキスト、リッチテキスト、blocks、そしてコンポーネントとダイナミックゾーン内のテキスト）が現在のロケールに翻訳され、フォームのそれらのフィールドを置き換えます。

- ロケール間で共有されるフィールドは変更されません。
- 翻訳元のロケールの未保存の変更は含まれないので、先に保存してください。
- Markdown、HTML、URL、ID、ブロックの種類はそのまま保たれます。
- 翻訳されたフィールドには印が付きます。確認してから保存するか、**翻訳を元に戻す**を選んでください。

これには、翻訳先のロケールでエントリーを更新する権限と、翻訳元のロケールで読み取る権限が必要です。

### 代替テキストを作成する

メディアライブラリで画像を開き、**代替テキストを生成**を選びます。モデルは、デフォルトのロケールの言語で画像を説明し（最大約 125 文字）、キャプションが空ならキャプションも埋めます。JPEG、PNG、WebP、GIF の画像で使え、`small` または `medium` のフォーマットがあればそれを送るので、大きな元画像がプロバイダーにアップロードされることはありません。メディアライブラリの更新権限（**自分のファイル**の場合はそのファイルに対して）が必要です。

### フィールドに要約する

要約のような名前（`description`、`summary`、`excerpt`、`abstract`、`intro`、`introduction`、`lead`、`teaser`）のテキストフィールドには、エントリーにリッチテキストか blocks のフィールド、または `body`、`content`、`text`、`article` という名前のテキストフィールドがある場合、**_field_を要約**ボタンが付きます。ブログのサンプルでは、**Excerpt** に **Bodyを要約**が付きます。要約はフィールドの最大長に収まります。

### SEO のメタデータを提案する

[提案される `shared.seo`](/ja/guides/frontend/seo-and-sitemap/) のように、`metaTitle` と `metaDescription` のテキスト属性を持つコンポーネントには、**提案**ボタンが付きます。エントリーの保存済みの下書きから、メタタイトル、説明、そしてコンポーネントにあれば `keywords` を埋めます。

## 制限

- 各管理者は 1 分あたり 30 回まで AI のリクエストを送れます。それを超えると <strong>AIへのリクエストが多すぎます。しばらく待ってからもう一度お試しください。</strong>と表示されます。
- 要約と SEO の提案で送るテキストは最大 40,000 文字です。
- プロバイダーへのリクエストは 120 秒でタイムアウトします。

## プライバシー

<Aside type="caution">
AI アクションは、設定したプロバイダーにコンテンツを送ります。翻訳、要約、説明の対象のフィールドと、代替テキスト用の画像です。そのコンテンツについて組織が許可するプロバイダーとプランを選び、データの保持条件を確認し、ネットワークの外に出してはいけないコンテンツにはローカルのモデル（`openai-compatible`）を検討してください。
</Aside>

- リクエストは Verdin のサーバーからプロバイダーに送られ、キーがブラウザーに届くことはありません。
- 送られるのはアクションの入力だけです。エントリーのテキストフィールド、要約するテキスト、または 1 枚の画像とそのファイル名です。private な属性や他のエントリーは送られません。
- アクションが読むのは管理者がすでに読めるものだけで、提案は保存されません。

管理画面には、どのモデルが応答したかが表示されます（**_model_（_provider_）による提案です。**）。

管理画面の外の AI エージェントにコンテンツを読み書きさせるには、[MCP サーバー](/ja/guides/integrations/mcp/)を参照してください。
