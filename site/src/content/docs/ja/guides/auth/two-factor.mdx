二段階認証は、パスワードの後に 2 つ目の手順を加えます。認証アプリの 6 桁のコードか、パスキー（指紋、顔認証、画面ロック、セキュリティキー）です。このガイドでは両方を設定し、ロールで必須にし、管理者が要素を失ったときの対処を説明します。Strapi には対応する組み込みの機能がありません。

二段階認証は管理者のためのものです。[エンドユーザー](/ja/guides/auth/end-users/)は、パスワードか OAuth プロバイダーでログインします。

## 始める前に

- オンにする機能はありません。すべての管理者がプロフィールで第二要素を設定できます。
- パスキーは管理パネルのアドレスに結び付けられます。`[server].public_url` を、`https://cms.example.com` のような、管理者が開くアドレスに設定してください。ブラウザーがパスキーを提供するのは `https://`（と `localhost`）の場合だけです。
- `VERDIN_TOKEN_PEPPER` を変えないでください。認証アプリのシークレットとリカバリーコードはこれで保護されており、変更すると使えなくなります。

## 認証アプリを設定する

<Steps>

1. **プロフィール**を開き、**二段階認証**を探します。
2. **認証アプリ**で**設定する**を選び、パスワードを確認します。
3. 1Password、Google Authenticator、Authy などのアプリで QR コードをスキャンします。スキャンできない場合は、その下に表示されるセットアップキーを入力します。
4. アプリに表示される **6桁のコード**を入力し、**オンにする**を選びます。
5. Verdin が表示する**リカバリーコード**を保存します。**ダウンロード**するかコピーしてから、**保存しました**を選びます。

</Steps>

コードは標準の TOTP 方式（30 秒間隔、SHA-1、6 桁）に従います。時計のずれを許容するため、前後の間隔のコードも受け付けます。コードが拒否される場合は、デバイスの時刻を確認してください。

## パスキーを追加する

<Steps>

1. **パスキー**で**パスキーを追加**を選びます。
2. 「MacBook Touch ID」のような**名前**を付け、パスワードを確認します。
3. ブラウザーの案内に従います。

</Steps>

パスキーは最大 20 個登録でき、**削除**で削除できます。パスキーはパスワードの後の第二要素であり、パスワードの代わりではありません。

## リカバリーコード

最初の要素を設定すると、10 個のリカバリーコードが得られます。アプリやパスキーを失ったとき、各コードで 1 回ログインできます。プロフィールには残りの数が表示されます。**新しいコードを生成**するとすべてが置き換わります（古いコードは使えなくなります）。

<Aside type="caution">
コードは一度だけ表示されます。パスワードマネージャーかオフラインの場所に保管し、認証アプリの入ったデバイスの近くには置かないでください。
</Aside>

## 第二要素でログインする

<Diagram
  caption="二段階認証によるログイン"
  code={`flowchart LR
  A[メールアドレスとパスワード] --> B{第二要素あり?}
  B -->|いいえ| S[ログイン完了]
  B -->|はい| C[コード、パスキー、リカバリーコード]
  C -->|5 分以内| S`}
/>

パスワードの後、ログインページは**認証コード**を求めます。方法を切り替えるには、**パスキーを使う**か**リカバリーコードを使う**を選びます。5 分以内に完了する必要があり、それを過ぎたらもう一度パスワードを入力します。

## ロールで二段階認証を必須にする

<Steps>

1. **設定 → ロール**を開き、ロールを開きます。
2. **二段階認証を必須にする**をオンにして保存します。

</Steps>

第二要素を持たないメンバーは、ログイン時に設定を求められます。設定するまでは、自分のプロフィールしか開けません。**設定 → ユーザー**では、その行に **2FA未設定**と表示され、第二要素を持つ管理者には **2FA** と表示されます。

ロールで第二要素が必須になっている間、Verdin は最後の要素の削除を拒否します。アプリをオフにする前にパスキーを追加するか、唯一のパスキーを削除する前に別の要素を追加してください。

## 別の管理者の第二要素をリセットする

管理者がデバイスとリカバリーコードを失った場合:

<Steps>

1. **設定 → ユーザー**を開き、その管理者を探します。
2. **二段階認証をリセット**を選び、確認します。

</Steps>

これにより、その管理者の認証アプリ、パスキー、リカバリーコードが削除され、パスワードだけでログインするようになります。ロールで二段階認証が必須の場合は、もう一度設定する必要があります。この操作には**ユーザーの管理**が必要で、Super Admin をリセットできるのは Super Admin だけです。

`verdin admin reset-password` がリセットするのはパスワードだけで、第二要素はリセットしません。

## シングルサインオン

[シングルサインオン](/ja/guides/auth/sso/)でログインする管理者も、プロバイダーに**プロバイダーが MFA を必須にしている**が設定されていない限り、Verdin の第二要素を求められます。

## Admin API

すべてのルートは `/admin/api` 配下にあります。要素を変更するルートは `password` を受け取ります。

| ルート | 動作 |
| --- | --- |
| `POST /auth/login` | 第二要素がある場合、セッションの代わりに `{ twoFactorRequired: true, twoFactorToken, methods }` を返します。 |
| `POST /auth/login/two-factor` | `{ twoFactorToken, code }`（TOTP またはリカバリーコード）、パスキーの場合は `{ twoFactorToken, challengeToken, credential }`。セッションを返します。 |
| `POST /auth/login/passkey/options` | `{ twoFactorToken }`: パスキーのチャレンジ。 |
| `GET /auth/two-factor` | 自分の要素: `totp`、`passkeys`、`recoveryCodesLeft`、`required`。 |
| `POST /auth/two-factor/totp/setup`、`/totp/enable`、`/totp/disable` | 認証アプリの設定（パスワード）、オン（コード）、オフ（パスワード）。 |
| `POST /auth/two-factor/recovery-codes` | 新しいリカバリーコード。 |
| `POST /auth/two-factor/passkeys/options`、`POST /auth/two-factor/passkeys`、`DELETE /auth/two-factor/passkeys/{id}` | パスキーの登録と削除。 |
| `DELETE /users/{id}/two-factor` | 別の管理者の要素をリセットします（`users.manage`）。 |
