プラグインを使うと、サーバーを変更したりビルドし直したりせずに、Verdin に動作を追加できます。プラグインはマニフェスト付きの WebAssembly モジュールで、プロジェクトの `plugins/` ディレクトリに置きます。このページでは、プラグインでできることとインストールの方法を説明します。プラグインを書くには[プラグインのチュートリアル](/ja/extending/plugin-tutorial/)に従い、詳細は[プラグインのリファレンス](/ja/extending/plugin-reference/)で調べてください。

## プラグインでできること

| 拡張ポイント | 用途 |
| --- | --- |
| **書き込み時のフック** | エントリーの作成、更新、公開、非公開、削除、下書きの破棄の前に、データを変更したり、メッセージ付きで書き込みを拒否したりします。書き込みの後には、それに反応します（ログ、通知、同期）。 |
| **ルート** | `/api/plugins/<name>/…` 配下で HTTP エンドポイントを提供します。Webhook の受信、計算したフィード、別のサービスへのプロキシなどです。 |
| **スケジュールされたジョブ** | cron のスケジュール（UTC）で関数を実行します。 |
| **起動関数** | プラグインの開始時、オン切り替え時、設定の変更時に関数を実行します。シード投入や公開ロールの設定に使います（Strapi の `bootstrap`）。 |
| **GraphQL フィールド** | `Query` または `Mutation` に `name(args: JSON): JSON` フィールドを追加します。 |
| **ダッシュボードのウィジェット** | Web Components として、管理画面のダッシュボードにウィジェットの種類を追加します。 |
| **カスタムフィールド** | Web Components として、管理画面で属性に独自のエディター（カラーピッカー、地図など）を与えます。値は通常の属性の型で保存されます。 |
| **設定** | 管理者が**設定 → プラグイン**で入力する設定フォームを宣言します。 |

プラグインは、管理画面や API と同じ Document Service を通じてコンテンツを読み書きするので、その書き込みにも Webhook、履歴、レビューの段階、バリデーションが適用されます。

<Aside type="note">
Verdin のプラグインは Strapi のプラグインではありません。Strapi のプラグインはサーバーへの完全なアクセス権を持つ Node.js のパッケージですが、Verdin はサーバー上で JavaScript を一切実行しません。Strapi のスキーマが宣言するカスタムフィールド（`customField` 属性）はそのまま読み込まれ、Verdin のプラグインがそのエディターを提供できます。
</Aside>

## サンドボックス

プラグインは WebAssembly のサンドボックス（Wasmtime 上の [Extism](https://extism.org)）で実行されます。モジュールは独自のファイル、ソケット、データベース接続を持ちません。自身のメモリの外で行うことはすべて少数のホスト関数を通じて行われ、サーバーは各呼び出しをマニフェストが宣言した**機能**と照合します。

| 機能 | 許可されること |
| --- | --- |
| `read` | 指定したコンテンツタイプ（または `*`）のエントリーの読み取り。 |
| `write` | 指定した型のエントリーの作成、更新、公開、非公開、削除（読み取りも含む）。 |
| `http` | 指定したホスト（`api.example.com`、`*.example.com`）への HTTP リクエスト。 |
| `kv` | Verdin のデータベース内にある、プラグイン専用のキーバリューストア。 |
| `public_permissions` | 公開ロールのコンテンツ API の権限の読み取りと置き換え。 |

<Diagram
  caption="プラグインへの呼び出しと、そのホスト呼び出しが到達できる範囲"
  code={`flowchart LR
    W[書き込み] -->|フック| M
    R["/api/plugins/name/…"] --> M
    J[スケジュールされたジョブ] --> M
    M[WebAssembly モジュール] --> C{機能}
    C -->|read, write| D[(コンテンツ)]
    C -->|kv| K[(プラグインのストレージ)]
    C -->|http| H[指定したホスト]`}
/>

各呼び出しには制限もあります。マニフェストで設定する時間制限（デフォルトは 5 秒）とメモリ制限（デフォルトは 64 MB）です。トラップしたモジュールや時間切れになったモジュールは、その呼び出しだけが失敗し、Verdin は次の呼び出しでモジュールを作り直します。

サンドボックスが代わりに決めてくれないこと:

- **ルートは公開されています。** `/api/plugins/<name>/…` へのリクエストは、**公開アクセス**や API トークンの権限と照合されません。プラグインは呼び出し元（誰でも、API トークン、エンドユーザー）を受け取るので、それを確認する必要があります。
- **フックは、その型へのすべての書き込みを見ます。** プラグインの `read` の機能にはかかわりません。
- **失敗した before フックは書き込みを止めません。** モジュールがクラッシュしたりタイムアウトしたりすると、エラーがログに記録され、書き込みは続行されます。書き込みを止めるのは明示的な拒否だけです。

## プラグインをインストールする

<Steps>

1. `verdin.toml` の隣の `plugins/` 配下に、プラグイン専用のディレクトリを置きます。そこにはマニフェスト、モジュール、そして任意で管理パネル用のファイルが入ります。

   <FileTree>
   - verdin.toml
   - plugins/
     - reading-time/
       - plugin.toml
       - plugin.wasm
       - admin/ 任意: 管理パネル用の Web Components
         - index.js
   - schema/
   </FileTree>

2. Verdin を再起動します。起動時にすべての `plugins/*/plugin.toml` を読み込み、それぞれについて `plugin found` をログに出します。読み込みに失敗したプラグイン（無効なマニフェスト、モジュールの欠落、名前の重複）は、理由とともに**設定 → プラグイン**に表示されます。

3. 管理パネルで**設定 → プラグイン**を開きます。プラグインが要求するものを**アクセス**、**フック**、**ルート**、**ジョブ**で確認してから、オンにします。

4. プラグインに設定がある場合は、カードの**設定**を開き、入力して保存します。

</Steps>

インストールしたプラグインは、オフの状態で始まります。プラグインの切り替えと設定の編集は、すべてのインスタンスですぐに反映されます（他のインスタンスは `[server].sync_interval_secs` 以内に変更を取り込みます）。`plugin.toml` やモジュールの変更には再起動が必要です。

プラグインの管理には `plugins.manage` 権限（**プラグインの管理**）が必要です。[権限のリファレンス](/ja/reference/permissions/)を参照してください。

## `[plugins]` を設定する

```toml title="verdin.toml"
[plugins]
path = "plugins"   # directory of plugins, relative to verdin.toml
run_jobs = true    # run scheduled jobs on this instance
```

インスタンスが複数ある場合は、各ジョブが 1 回だけ実行されるように、1 つを除くすべてで `run_jobs = false` を設定してください。[設定のリファレンス](/ja/reference/configuration/)を参照してください。

## 運用

- **一度に 1 つの呼び出し。** 各プラグインにはインスタンスが 1 つしかなく、一度に 1 つの呼び出ししか処理しないので、遅いルートはそのプラグインのフックを遅らせます。関数は短く保ってください。
- **ログ。** プラグインが記録したものは、サーバーのログと**設定 → プラグイン → ログ**（直近の 200 行、メモリに保持）に出ます。
- **デプロイ。** スキーマと同様に、プラグインはプロジェクトと一緒に（イメージかボリュームに入れて）届けてください。切り替えと設定はデータベースにあります。
