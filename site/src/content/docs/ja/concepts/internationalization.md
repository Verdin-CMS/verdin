国際化（i18n）は、ドキュメントのコンテンツを複数の言語で保持します。このページでは、そのモデルを説明します。ロケール、多言語化されたフィールドと共有フィールド、そして読み書きでロケールがどう選ばれるかです。編集者のワークフローについては[コンテンツの多言語化](/ja/guides/content/localizing-content/)を参照してください。

## ロケール

プロジェクトのロケールは**設定 → 国際化**（権限 `locales.manage`）に一覧されます。初回起動時に、英語（`en`）がデフォルトのロケールとして追加されます。

- 常に 1 つのロケールがデフォルトです。ロケールを指定しないリクエストはデフォルトのロケールを使い、デフォルトのロケールは削除できません。
- コードは 2 文字か 3 文字の小文字の言語コードで、その後にサブタグを続けることもできます: `en`、`fr`、`pt-BR`、`zh-Hans`。

:::caution
ロケールを削除すると、そのロケールで書かれたすべてのバージョンも削除されます。
:::

## 多言語化されたコンテンツタイプ

スキーマで指定すると、コンテンツタイプは多言語化されます。すると各ドキュメントはロケールごとに 1 つのバージョンを持ち、すべてが同じ `documentId` を共有します。

```json title="schema/content-types/article.json (excerpt)"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

[下書きと公開](/ja/concepts/draft-and-publish/)を使うと、ロケールごとに下書きと公開バージョンがあるので、フランス語の翻訳は英語の本文より前でも後でも公開できます。`pluginOptions.i18n.localized` のない型は多言語化されず、`locale` パラメーターを無視します。

## 多言語化されるもの

多言語化された型では、`"pluginOptions": { "i18n": { "localized": false } }` を指定しない限り、すべての属性が多言語化されます。このような**共有**フィールドは、ドキュメント全体で 1 つの値を持ちます。

- あるロケールで共有フィールドを保存すると、すべてのロケールの下書きに書き込まれます。
- あるロケールを公開すると、その共有フィールドが他のロケールの公開バージョンにコピーされます。
- これはリレーションとメディアにも当てはまります。共有リレーションは、どのロケールでも同じドキュメントにリンクします。

システムフィールドはバージョンに従います。各ロケールが独自の `createdAt`、`updatedAt`、`publishedAt` を持ちます。`unique` と `uid` の値はロケールごとに一意なので、2 つの翻訳が同じスラッグを共有できます。

## 多言語化された型の間のリレーション

リレーションはバージョンではなくドキュメントをリンクするので（[リレーション](/ja/concepts/relations/#行ではなくドキュメントでリンクする)を参照）、ロケールは読み取り時に選ばれます。

- 両方の型が多言語化されている場合、フランス語の記事はカテゴリーのフランス語版を表示します。リレーションを介したフィルターも同じロケールで照合されます。
- 対象の型が多言語化されていない場合、どのロケールでも同じ対象が見えます。

## API でのロケールの選択

REST と Admin API は、Strapi v5 の形式でクエリパラメーター `locale` を受け取ります。GraphQL は `locale` 引数を受け取ります。

```http
GET /api/articles?locale=fr
PUT /api/articles/{documentId}?locale=fr
DELETE /api/articles/{documentId}?locale=fr
```

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
  }
}
```

- `locale` がない場合、リクエストはデフォルトのロケールを読み書きします。
- ドキュメントがまだ持っていないロケールへの `PUT` は、そのバージョンを作成します。
- `DELETE` は、リクエストしたロケールのバージョンだけを削除します。そのドキュメントを指すリンクは、ロケールが 1 つも残らなくなった時点で削除されます。
- 多言語化された型の REST レスポンスには `locale` が含まれます。不明なロケールは `400` エラーになります。
- Webhook のペイロード、リアルタイムイベント、コンテンツ履歴には、変更されたバージョンのロケールが記録されます。

## ロケールごとの権限

管理者のロールでは、コンテンツの権限を一部のロケールに限定できるので、フランス語の編集者がフランス語版だけを読んだり変更したりするようにできます。[権限](/ja/concepts/permissions/#フィールドとロケールの権限)を参照してください。コンテンツ API の許可（公開アクセス、API トークン、エンドユーザーのロール）は、すべてのロケールに適用されます。

## Strapi との比較

モデルとパラメーターは Strapi v5 の i18n と同じです。多言語化された型、`localized: false` のフィールド、`?locale=`、デフォルトのロケールです。Verdin では i18n はコアの一部で常に有効になっており、スキーマでコンテンツタイプごとにオンにします。
