下書きと公開を使うと、編集者はサイトの表示を変えずにドキュメントを編集し、準備ができたら公開できます。このページでは、そのモデルを説明します。ドキュメント、バージョン、コンテンツをバージョン間で移すアクション、そして各 API での扱いです。動作は Strapi v5 と同じです。

コンテンツタイプごとに、スキーマでオンにします。

```json title="schema/content-types/article.json (excerpt)"
"options": { "draftAndPublish": true }
```

`options.draftAndPublish` がない場合はオフです。

## ドキュメントとバージョン

**ドキュメント**は 1 件のエントリーで、`documentId` で識別されます。下書きと公開を使うと、ドキュメントは最大 2 つの**バージョン**を持ちます。

- **下書き**。編集するたびに変わります。
- **公開**バージョン。コンテンツ API がデフォルトで提供します。

[多言語化された](/ja/concepts/internationalization/)型では、ロケールごとに下書きと公開バージョンがあり、すべてが同じ `documentId` を共有します。

下書きと公開を使わない型では、ロケールごとにバージョンは 1 つだけで、常に公開されています。書き込むたびに、読み手に見える内容が変わります。

## 状態

管理パネルは、一覧とエディターで各エントリーの状態を表示します。

| 状態 | 下書き | 公開バージョン | 公開コンテンツの読み手に見えるもの |
| --- | --- | --- | --- |
| **下書き** | あり | なし | 何も見えません。ドキュメントは表示されません。 |
| **公開済み** | 公開バージョンと同じ | あり | 公開バージョン。 |
| **変更あり** | 前回の公開以降に変更あり | あり | 公開バージョン。新しい変更は含まれません。 |

アクションによって、ドキュメントはこれらの状態の間を移ります。

| アクション | 効果 | 移動前 → 移動後 |
| --- | --- | --- |
| 保存 | 下書きを書き込みます。 | 下書き → 下書き、公開済み → 変更あり |
| **公開** | 下書きを公開バージョンにコピーします。必要なら公開バージョンを作成します。 | 下書きまたは変更あり → 公開済み |
| **非公開にする** | 公開バージョンを削除します。下書きは残ります。 | 公開済みまたは変更あり → 下書き |
| **変更を破棄** | 下書きを公開バージョンのコピーで置き換えます。 | 変更あり → 公開済み |
| 削除 | すべてのバージョンを削除します（多言語化された型では、リクエストしたロケールのもの）。 | 任意 → なし |

公開は 1 つのトランザクションで実行されます。下書きに対して `required` フィールドと型の[フィールド間のルール](/ja/concepts/content-model/#フィールド間のバリデーション)を確認し、確認に失敗すると何も公開されません。それまでの間、下書きは未完成でも、それらのルールに反していてもかまいません。

下書きの `publishedAt` は `null` です。公開バージョンには、最後に公開された時刻が入ります。

## リレーションとメディアはバージョンに従う

各バージョンは独自のリレーションとメディアのリンクを持ち、公開すると下書きのリンクが公開バージョンにコピーされます。リンクはドキュメントを指し、読み取り中のバージョンで解決されます。公開された記事はカテゴリーの公開バージョンを表示し、下書きはカテゴリーの下書きを表示します。カテゴリーを非公開にすると、リンクを書き換えることなく、再び公開されるまで公開された記事からカテゴリーが消えます。[リレーション](/ja/concepts/relations/#行ではなくドキュメントでリンクする)を参照してください。

コンポーネントとダイナミックゾーンは行の一部なので、公開するとそのままコピーされます。

## 下書きと公開コンテンツの読み取り

| API | デフォルトで読み取るもの | 下書きを読むには |
| --- | --- | --- |
| [REST](/ja/api/rest/#ステータス) | 公開バージョン | `?status=draft`。**下書きの閲覧**権限が必要です |
| [GraphQL](/ja/api/graphql/) | 公開バージョン | `status: DRAFT`。同じ権限が必要です |
| [Admin API](/ja/api/admin/) | 下書き | `?status=published` |

下書きの読み取りは独立した権限（`readDrafts`）なので、サイトのコンテンツを読むトークンが未公開の作業を読むことはできません。読み取り専用の API トークンは下書きを読みません。

一度でも公開されたかどうかでドキュメントを区別するには、`hasPublishedVersion` でフィルターします。`?status=draft&hasPublishedVersion=false` は、一度も公開されていないドキュメントを一覧にします。

## API からの書き込み

書き込みでは、API は Strapi v5 に従います。

- **REST と GraphQL** の `create` と `update` は、リクエストで `status=draft`（GraphQL では `status: DRAFT`）を指定しない限り、下書きを書き込み、**さらに公開します**。公開に失敗すると、リクエスト全体がロールバックされます。
- **管理パネルと Admin API** は下書きだけを保存します。公開は常に明示的なアクションです。

REST API には、Strapi が REST では提供していない明示的なアクションもあります。

```http
POST /api/articles/{documentId}/actions/publish
POST /api/articles/{documentId}/actions/unpublish
POST /api/articles/{documentId}/actions/discard-draft
```

これらには、その型に対する**公開**権限が必要です。[REST API](/ja/api/rest/#アクション) を参照してください。

## 公開を行うその他の機能

- [リリース](/ja/guides/content/releases/)はドキュメントをまとめ、即時または指定日時に一緒に公開・非公開にします。
- [レビューワークフロー](/ja/guides/content/review-workflows/)では、ドキュメントを公開する前に特定の段階を必須にできます。
- 公開と非公開は、`entry.publish` と `entry.unpublish` の [Webhook イベント](/ja/api/webhooks/)と[リアルタイムイベント](/ja/api/realtime/)を送ります。下書きの保存は `entry.update` を送り、リアルタイムでは下書きの読み取りを許可された呼び出し元だけが受け取ります。
