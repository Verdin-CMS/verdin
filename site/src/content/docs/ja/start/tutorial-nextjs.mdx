このチュートリアルでは、Verdin からコンテンツを読むブログを [Next.js](https://nextjs.org) と App Router で作ります。記事を一覧にするホームページ、カテゴリー付きの `/articles/<slug>` の記事ごとのページ、そして任意で、管理画面のプレビューのリンクから下書きを表示するページです。Server Components で、スキーマから生成した型とともに型付きクライアント `@verdin/client` を使います。

Next.js 16.3（`create-next-app` 16.3）、React 19.2、Node.js 20.9 以降、Verdin と `@verdin/client` 0.10 向けに書いています。`cacheComponents` なしで、Next.js のデフォルトのキャッシュを使います。[Astro のチュートリアル](/ja/start/tutorial-astro/)では、同じブログを Astro で作ります。

## 始める前に

`PATH` 上の `verdin` のバイナリ（[クイックスタート](/ja/start/quickstart/)を参照）、Node.js、Git が必要です。最終的に、Verdin のプロジェクト `cms` と Next.js のアプリ `blog` の 2 つのフォルダーが並びます。

## 1. ブログのスキーマで Verdin を準備する

リポジトリの [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) プロジェクトはブログをモデル化しています。タイトル、`slug`、抜粋、Markdown の `body`、カテゴリー、タグを持つ記事に加えて、ホームページのシングルタイプといくつかのコンポーネントです。

<Steps>

1. Verdin のプロジェクトを作成し、サンプルのスキーマをコピーします。

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. 起動します。

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   最初の起動で、4 つのコンテンツタイプのテーブルが作成されます。

3. [http://localhost:1337/admin/](http://localhost:1337/admin/) を開き、最初の管理者を作成します。

4. **コレクション**で **Category** を開き、**新規エントリー**を選び、`News` と名前を付けて保存します。

5. **Article** を開き、**新規エントリー**を選んで、タイトル、抜粋、Markdown の本文を入力します。`slug` はタイトルから生成されます。カテゴリーに `News` を選び、**公開**を選びます。同じようにして 2 つ目の記事を追加します。

6. **設定 → 公開アクセス**を開き、**Article** と **Category** に**検索**と**1件取得**を許可して、**保存**を選びます。

</Steps>

API が応答することを確認します。

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
リレーションを populate するには、その対象への読み取り権限が必要です。**Category** に**検索**がないと、`populate=category` は ``invalid key `category` in populate`` とともに `400` を返します。
</Aside>

## 2. Next.js のアプリを作成する

新しいターミナルで、`cms` の隣に作成します。

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) は、`body` フィールドの Markdown を HTML に変えます。

## 3. 型を生成する

`verdin types` はスキーマを読み、コンテンツタイプとコンポーネントごとに 1 つの TypeScript のインターフェースと、クライアント用のルートのマップ `VerdinSchema` を書き出します。`blog` から、Verdin のプロジェクトの設定を指定して実行します。

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

ファイルには、特に次のものが含まれます。

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

リレーション、メディア、コンポーネントは、API が populate した場合にしか返さないので任意です。スキーマが変わるたびに、このコマンドを実行し直してください。

## 4. Verdin に接続する

サーバーの URL を `.env.local` に書きます。

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

トークンがない場合、クライアントは公開ロールとして読みます。これは手順 1 で公開したものです。代わりにトークンで読むには、**設定 → APIトークン**で**読み取り専用**のトークンを作成し、`VERDIN_TOKEN` を設定します。どちらの変数もサーバーにとどまります。`NEXT_PUBLIC_` のプレフィックスがなく、クライアントは Server Components でしか実行されないためです。

クライアントを一度作成し、共有します。

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

これで `verdin.collection('articles')` はスキーマのルートだけを受け付け、その結果は `Article` として型付けされます。

## 5. レイアウトを置き換える

スターターのレイアウトを置き換え、新しいページでは使わない `src/app/page.module.css` を削除します。

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import Link from 'next/link';

export const metadata: Metadata = {
  title: 'My blog',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. 記事を一覧にする

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

このクエリは、Strapi v5 の形式の REST の呼び出し `GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc` です。`fields` でレスポンスを小さく保ち、`populate` で名前だけを持つカテゴリーを加えます。公開ロールは公開された記事だけを読みます。

`revalidate = 60` は、ビルド時にページを事前描画し、その後は最大で 1 分に 1 回更新するので、公開した変更は再ビルドなしで表示されます。

## 7. 記事ごとのページを追加する

記事のページは、フィルターを使ってスラッグで記事を探します。`generateStaticParams` は既存の記事を事前描画し、後で公開された記事は最初の訪問時に描画されます。

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Next.js 16 では `params` は Promise なので、スラッグを読む前に await してください。不明なスラッグでは記事が見つからず、`notFound()` によって 404 を返します。`pageSize` の上限は `[api].max_page_size`（デフォルトは 100）です。

<Aside type="caution">
`marked` は HTML をサニタイズしません。自分の編集者が書く Markdown なら問題ありませんが、信頼できない人からコンテンツが来る可能性がある場合は、描画する前に HTML をサニタイズしてください。
</Aside>

## 8. 実行する

```sh title="Terminal"
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開くと、一覧に公開した記事が表示され、それぞれがそのページにリンクしています。`npm run build` は、事前描画のために記事を取得するので、Verdin が動いている必要があります。

1 分以内ではなく、コンテンツが変わったらすぐにページを更新するには、Verdin の Webhook が呼び出すルートハンドラーから `revalidatePath` を呼んでください。[Webhook](/ja/guides/integrations/webhooks/) を参照してください。

プロジェクトは次のようになります。

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts `verdin types` で生成
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. 任意: 下書きのプレビュー

管理画面は、有効期間の短いプレビュートークンを使って、サイト上で下書きを開けます。トークンはその 1 件のドキュメントを下書きを含めて読めるだけで、それ以外は読めません。

`x-verdin-preview` ヘッダーでプレビュートークンを送るクライアントを追加します。

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

次にページです。`searchParams` を読むので、Next.js はリクエストごとに描画します。トークンはクエリパラメーター `preview` として届きます。

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

プレビュートークンではエントリーを一覧できないので、このページはスラッグではなく `documentId` で下書きを探します。次に、ページの場所を Verdin に伝えます。

<Steps>

1. 管理画面で**設定 → 機能**を開き、**プレビュー**をオンにして、**プレビューURLを設定**を選びます。
2. **Article** の URL テンプレートを `http://localhost:3000/preview/{documentId}` にして保存します。Verdin はトークンを `?preview=…` として付け加えます。
3. 記事を開いて変更し、**下書きを保存**を選んでから、**プレビューを開く**を選びます。

</Steps>

ページに下書きが表示されます。リンクはデフォルトで 60 分間有効です。プレースホルダーと設定は[プレビュー](/ja/guides/content/preview/)を、プレビューから編集するには[ビジュアル編集](/ja/guides/frontend/visual-editing/)を参照してください。
