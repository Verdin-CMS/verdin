本页带你从零开始，大约十分钟即可拿到第一个 API 响应：启动 Verdin，创建第一个管理员，定义一个内容类型，将其开放给公众访问，然后通过 REST、GraphQL 或 TypeScript 客户端读取内容。

你需要 [Docker](https://docs.docker.com/get-docker/)，或者一台能够运行 `verdin` 二进制文件的机器（x86-64 上的 Linux、macOS 或 Windows，ARM64 上的 Linux 或 macOS）。

## 1. 启动 Verdin

<Tabs syncKey="install">
  <TabItem label="Docker">

先生成一次密钥，然后以开发模式启动镜像：

```sh title="Terminal"
docker run --rm ghcr.io/verdin-cms/verdin secrets > verdin.env
docker run -p 1337:1337 --env-file verdin.env -v verdin-data:/data ghcr.io/verdin-cms/verdin dev
```

`verdin-data` 卷中保存 SQLite 数据库（`/data/verdin.db`）、上传的媒体文件（`/data/uploads`），在 `dev` 模式下还保存内容类型构建器写入的 schema 文件（`/data/schema`）。

  </TabItem>
  <TabItem label="Binary">

从[发布页面](https://github.com/Verdin-CMS/verdin/releases)下载适合你平台的压缩包，解压后把 `verdin` 放到 `PATH` 中。管理后台已内置在二进制文件中。

创建项目骨架并以开发模式启动：

```sh title="Terminal"
verdin new my-site            # verdin.toml、schema/、带有新密钥的 .env、SQLite
cd my-site
verdin dev
```

`verdin new` 接受 `--database sqlite|postgres|mysql|mariadb` 参数（默认为 SQLite），用于选择生成的 `.env` 所指向的数据库。如果使用 PostgreSQL、MySQL 或 MariaDB，请在运行 `verdin dev` 之前修改 `.env` 中的 `VERDIN_DATABASE_URL`，使其指向你的数据库服务器。[项目结构](/zh-cn/start/project-structure/)介绍了它创建的每个文件。

  </TabItem>
</Tabs>

当日志中出现 `verdin listening` 时，服务器就会在 1337 端口响应请求。首次启动时会创建数据库表。

## 2. 密钥

Verdin 需要两个密钥，每个长度至少为 32 字节：

| 变量 | 用途 |
| --- | --- |
| `VERDIN_ADMIN_JWT_SECRET` | 为管理后台会话签名。 |
| `VERDIN_TOKEN_PEPPER` | 对 API 令牌做哈希，并保护双因素密钥和恢复码。 |

`verdin secrets` 会输出新生成的值，`verdin new` 会把它们写入 `.env`。密钥只从环境变量读取，绝不从 `verdin.toml` 读取；缺少密钥时服务器不会启动。启动时会加载与 `verdin.toml` 位于同一目录的 `.env` 文件，环境中已设置的变量优先。

<Aside type="caution">
每个安装只生成一次密钥，并妥善保存。更换 `VERDIN_ADMIN_JWT_SECRET` 会使当前的登录令牌、已打开的预览链接以及正在进行的 OAuth 登录失效（管理后台会自动续期其会话）；更换 `VERDIN_TOKEN_PEPPER` 会让所有 API 令牌和所有双因素设置失效。不要把 `.env` 和 `verdin.env` 提交到版本控制中。
</Aside>

## 3. 创建第一个管理员

打开 [http://localhost:1337/admin/](http://localhost:1337/admin/)。在还没有任何管理员时，管理后台会显示 **欢迎使用 Verdin**：输入你的姓名、邮箱和至少 8 个字符的密码，然后选择 **创建账户**。这个首个账户是拥有全部权限的 Super Admin。

也可以通过命令行创建管理员，参见[通过命令行管理管理员](#通过命令行管理管理员)。

## 4. 定义内容类型

<Steps>

1. 在侧边栏中打开 **内容类型构建器**，选择 **新建内容类型**。
2. 将 **显示名称** 设为 `Article`。Verdin 会把 **单数名称（API ID）** 填为 `article`，把 **复数名称（路由）** 填为 `articles`；路由就是该类型在 API 中的 URL。**种类** 保持为 **集合**。
3. 选择 **添加字段**，选择 **短文本**，将其命名为 `title`，然后选择 **完成**。
4. 选择 **保存**。**审查迁移** 会列出数据库步骤及对应的 SQL；选择 **应用**。

</Steps>

Verdin 会把该类型写入 `schema/content-types/article.json` 并创建对应的表。构建器只在 `verdin dev` 中可用：在生产环境中，schema 来自你的文件。字段类型和选项请参见[内容模型](/zh-cn/concepts/content-model/)。

接下来添加一个条目：打开 **集合** 下的 **Article**，选择 **新建条目**，填写标题后选择 **发布**。新类型默认开启 **草稿与发布**，因此条目在发布之前一直是草稿，公开 API 看不到它们。

## 5. 开放公开访问

在你授予公开权限或创建 API 令牌之前，内容 API 是关闭的。打开 **设置 → 公开访问**，为 **Article** 允许 **查询** 和 **查询单个**，然后选择 **保存**。

如果不想开放公开访问，也可以在 **设置 → API 令牌** 中创建令牌，并以 `Authorization: Bearer <token>` 的形式发送。参见 [API 令牌](/zh-cn/guides/auth/api-tokens/)和[权限](/zh-cn/concepts/permissions/)。

## 6. 发送第一个请求

<Tabs syncKey="api">
  <TabItem label="REST">

```sh title="Terminal"
curl localhost:1337/api/articles
```

```json
{
  "data": [
    {
      "id": 2,
      "documentId": "01m3p88agn712n02wb8kkpe94p",
      "title": "Hello Verdin",
      "createdAt": "2026-09-29T09:34:39.637Z",
      "updatedAt": "2026-09-29T09:34:39.637Z",
      "publishedAt": "2026-09-29T09:34:39.637Z"
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 25, "pageCount": 1, "total": 1 } }
}
```

响应采用 Strapi v5 的扁平结构。过滤、排序、分页和 `populate` 使用相同的查询参数，参见 [REST API](/zh-cn/api/rest/)。

  </TabItem>
  <TabItem label="GraphQL">

开启 **设置 → 功能 → GraphQL**。之后 `POST /graphql` 会提供一个根据内容类型生成的 schema，其权限与 REST API 相同：

```sh title="Terminal"
curl localhost:1337/graphql -H 'content-type: application/json' \
  -d '{"query":"{ articles { documentId title } }"}'
```

```json
{ "data": { "articles": [{ "documentId": "01m3p88agn712n02wb8kkpe94p", "title": "Hello Verdin" }] } }
```

参见 [GraphQL API](/zh-cn/api/graphql/)。

  </TabItem>
  <TabItem label="TypeScript">

根据 schema 生成类型，并在前端项目中安装客户端：

```sh title="Terminal"
verdin types -o src/verdin-types.ts   # 在 Verdin 项目中执行
npm install @verdin/client            # 在前端项目中执行
```

使用 Docker 时，可以让镜像根据卷中的 schema 输出类型：`docker run --rm -v verdin-data:/data ghcr.io/verdin-cms/verdin types > src/verdin-types.ts`。

```ts title="src/articles.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from './verdin-types';

const verdin = createClient<VerdinSchema>({ url: 'http://localhost:1337' });

const { data } = await verdin.collection('articles').find({ sort: ['publishedAt:desc'] });
console.log(data.map((article) => article.title));
```

参见[类型化客户端](/zh-cn/guides/frontend/typed-client/)。

  </TabItem>
</Tabs>

## 开发模式与生产模式

| 命令 | 用途 |
| --- | --- |
| `verdin dev` | 开发：安全的迁移会自动执行，内容类型构建器可以编辑 schema 文件，文件变更时服务器会重新加载。 |
| `verdin start` | 生产。数据库落后于 schema 时拒绝启动。 |
| `verdin start --migrate` | 生产，启动前先执行待处理的安全迁移。这是 Docker 镜像的默认命令。 |

刷新 cookie 在 `verdin start` 中带有 `Secure` 标记，在 `verdin dev` 中则没有，因此登录 `start` 模式的服务器需要 HTTPS。如果想通过普通 HTTP 试用 `start`，请设置 `VERDIN_ADMIN__SECURE_COOKIES=false`。

在生产环境中，请把 schema 纳入版本控制并以只读方式挂载。使用 Docker 时：

```sh title="Terminal"
docker run -p 1337:1337 --env-file verdin.env \
  -e VERDIN_DATABASE_URL=postgres://user:pass@db:5432/verdin \
  -v ./schema:/data/schema:ro ghcr.io/verdin-cms/verdin
```

其余事项请参见[生产环境检查清单](/zh-cn/deploy/production-checklist/)。

## Schema 与迁移

内容类型位于 `schema/content-types/<singularName>.json`，组件位于 `schema/components/<category>/<name>.json`，均采用 Strapi 格式。文件发生变化时，Verdin 会规划一次迁移：

```sh title="Terminal"
verdin schema check                      # 校验所有 schema 文件
verdin migrate plan                      # 步骤、风险等级和确切的 SQL
verdin migrate apply                     # 只执行安全步骤
verdin migrate apply --allow risky       # 同时执行类型变更和新增唯一约束
verdin migrate apply --allow destructive # 同时执行删除列和删除表
verdin migrate apply --rename-column articles.title=headline --rename-table posts=articles
```

MySQL 和 MariaDB 不支持事务性 DDL，迁移被中断后，下一次执行 `migrate apply` 时会从失败的步骤继续。参见 [Schema 迁移](/zh-cn/concepts/schema-migrations/)。

## 通过命令行管理管理员

```sh title="Terminal"
verdin admin create --email other@example.com      # 密码取自 VERDIN_ADMIN_PASSWORD 或标准输入
verdin admin reset-password --email you@example.com
```

`admin create` 会创建一个 Super Admin。`reset-password` 还会解锁该账户并结束其所有会话。两者都要求数据库与 schema 保持同步。

## 其他命令

| 命令 | 作用 |
| --- | --- |
| `verdin types -o src/verdin-types.ts` | 写出内容 API 的 TypeScript 类型定义（不带 `-o` 时输出到标准输出）。 |
| `verdin import strapi <export>` | 导入 Strapi 项目，参见[从 Strapi 导入](/zh-cn/migrate/from-strapi/)。 |
| `verdin export <file.tar.gz>` | 把 schema、内容和媒体写入一个归档文件；`verdin import verdin` 可以将其读回。 |
| `verdin version` | 输出版本号。 |

所有命令都接受 `-c, --config <path>`（默认为 `verdin.toml`，或 `VERDIN_CONFIG`）。[CLI 参考](/zh-cn/reference/cli/)列出了所有命令和参数，[配置参考](/zh-cn/reference/configuration/)列出了所有配置项。

## 健康检查

只要进程在运行，`GET /_health` 就会响应。`GET /_ready` 还会检查数据库，无法连接数据库时返回 503：请让负载均衡器指向它（参见[扩缩容](/zh-cn/deploy/scaling/)）。
