本部分面向参与开发 Verdin 本身的人。它介绍服务器和管理后台是如何组合在一起的、为什么要这样构建，以及从哪里开始阅读代码。如果只是使用 Verdin，请改从[快速开始](/zh-cn/start/quickstart/)入手。

Verdin 是一款用 Rust 编写、遵循 Strapi v5 的无头 CMS：你可以可视化地或在 JSON 文件中建模内容，并获得 REST 和 GraphQL API 以及一个管理后台。它以单个二进制文件发布，其中包含服务器、CLI 和 Angular 管理后台，并且可以运行在 PostgreSQL、MySQL、MariaDB 和 SQLite 上。

## 目标

- **一个二进制文件。** `verdin` 包含服务器、CLI 和嵌入的管理后台。生产环境不需要 Node.js，也不需要 `node_modules`。
- **启动快，内存占用小。**
- **四种数据库，一套测试。** PostgreSQL、MySQL、MariaDB 和 SQLite 都是一等公民，全部由同一套测试覆盖。
- **schema 即代码。** 内容类型是你用 git 进行版本管理的 JSON 文件。
- **与 Strapi v5 兼容的 REST API**，在合理的范围内尽量兼容，让现有前端只需少量改动即可迁移。
- **一切免费。** 没有企业版：SSO、审计日志、审核工作流、发布计划以及其他所有功能都面向所有人提供。

每个版本已发布的内容以及接下来的计划，请参见[路线图](/zh-cn/project/roadmap/)。

### 非目标

- 运行 Strapi 的 JavaScript 插件。Verdin 插件是 WebAssembly 模块（参见[插件](/zh-cn/extending/plugins/)）。
- 直接读取 Strapi 数据库。内容通过导入器迁移过来（参见[从 Strapi 迁移](/zh-cn/migrate/from-strapi/)）。
- 渲染页面。Verdin 是无头 CMS。

## 设计原则

1. **schema 是唯一的事实来源。** 表、校验、REST 和 GraphQL API、OpenAPI 文档以及管理后台表单都由它推导而来。
2. **SQL 标识符永远不来自请求。** 表名和列名只来自经过校验的 schema，每个值都是绑定参数。
3. **各方言都是一等公民。** 不存在“先支持 PostgreSQL，以后再支持 MySQL”。每个功能都在全部四种引擎上测试。
4. **默认安全。** 在你授予权限之前，内容 API 是关闭的，`private` 字段永远不会暴露，查询深度和大小限制始终开启。
5. **破坏性操作必须显式进行。** 删除列或表需要你的批准；它绝不会作为副作用发生。
6. **没有全局状态。** 服务通过 `axum` 状态和构造函数传递；没有单例。

## 整体架构

请求通过一小组共享层进入二进制文件，到达某个 API 路由器，最终进入 Document Service，由它为所连接的方言构建 SQL。从 `schema/*.json` 加载的 schema 注册表为每一步提供数据，迁移引擎则让数据库与之保持一致。

  Routers --> Auth["verdin-auth<br/>令牌、角色、授权"]

  Migrate --> Db`}

- **内容 API** 位于 `[api].prefix`（默认为 `/api`）下：每个内容类型的 REST 路由、上传以及 OpenAPI 文档。参见 [REST API](/zh-cn/api/rest/)。
- **管理 API** 位于 `{admin.path}/api`（默认为 `/admin/api`）下：管理后台所做的一切。参见[管理 API](/zh-cn/api/admin/)。
- **GraphQL** 位于 `/graphql`，**MCP** 位于 `/mcp`，在这些功能开启时可用。GraphQL 参数会被转换为 REST 解析器所读取的同一棵参数树，因此两种 API 共用过滤、分页、populate 和权限规则。
- **管理后台** 位于 `[admin].path`（默认为 `/admin`）下，从二进制文件或 `[admin].assets_dir` 提供。参见[管理后台内部原理](/zh-cn/internals/admin-panel/)。
- **运维路由**：`/_health`、`/_ready`，以及开启指标时的 `/_metrics`。参见[监控](/zh-cn/deploy/monitoring/)。

无论来自哪个 API，每次写入都会经过 [Document Service](/zh-cn/internals/document-service/)。它校验数据，在一个事务中写入行和链接表，然后通知监听器（webhook、搜索索引、历史记录、实时、审计日志）发生了什么变化。

当功能被开启或关闭，或者内容类型构建器在 `verdin dev` 中修改 schema 时，整个路由器会被重建并原地替换（一个 `ArcSwap`），无需重启。

## 技术栈

### 服务器（Rust，edition 2024）

| 领域 | 选择 | 原因 |
|---|---|---|
| 运行时 | `tokio` | 标准的异步运行时 |
| HTTP | `axum`、`tower`、`tower-http` | 用于 CORS、请求体限制、超时、请求 id、tracing 的中间件 |
| SQL 驱动 | `sqlx`（postgres、mysql、sqlite） | 异步、连接池、TLS；MySQL 和 MariaDB 共用一个驱动；SQLite 被编译进二进制文件 |
| SQL 构建 | Verdin 自己的构建器：DDL 位于 `verdin-migrate`，DML 位于 `verdin-query` 和 `verdin-content` | 表由 schema 定义，因此 SQL 在运行时构建。无论如何都需要对各方言进行精确控制（`jsonb`、`datetime(3)`、二进制排序规则、带类型的 NULL、SQLite 文本格式）。不使用 ORM，也不使用 `sea-query` |
| 查询字符串 | `verdin-query` 中自己实现的方括号写法解析器 | Strapi 风格的 `filters[title][$eq]=…`，带有深度、长度和键值对数量限制 |
| JSON | `serde`、`serde_json` | — |
| 小数 | `rust_decimal` | 服务器内部不丢失精度 |
| 日期 | `time` | — |
| 文档 id | `ulid` | 可排序，26 个字符，可移植 |
| OpenAPI | `verdin-api` 中自己实现的生成器 | 根据注册表为每个内容类型生成一个路径和 schema |
| GraphQL | `async-graphql`（动态 schema） | 根据内容 schema 构建 |
| 身份验证 | `argon2`（argon2id），基于 `hmac` + `sha2` 的 HS256 JWT | 几行 HS256 代码就能避免引入整个 RSA 技术栈 |
| 配置 | `figment`（TOML + 环境变量）、`dotenvy` | 分层和按环境覆盖 |
| CLI | `clap` | — |
| 日志 | `tracing`、`tracing-subscriber` | 默认便于阅读，设置 `[log].format = "json"` 时为 JSON |
| 速率限制 | `verdin-api` 中自己实现的固定窗口限流器 | 登录路由以及可选的内容 API 限制 |
| 媒体 | `object_store`、`image`、`infer` | 本地磁盘或 S3 兼容存储；格式和 MIME 嗅探 |
| 搜索 | `tantivy` | 二进制文件内置的可选全文索引 |
| 插件 | `extism` | WebAssembly 插件 |
| 邮件 | `lettre`、`reqwest` | SMTP、Resend、Postmark |
| 管理后台嵌入 | `rust-embed`（`embed-admin` feature） | 管理后台随二进制文件一起发布 |
| schema 监视 | `notify` | 在 `verdin dev` 中重新加载 |
| 错误 | 库中使用 `thiserror`，二进制文件中使用 `anyhow` | — |
| 测试 | `cargo test`、`insta`（DDL 快照） | 参见[测试](/zh-cn/internals/testing/) |

### 管理后台（Angular）

| 领域 | 选择 |
|---|---|
| 框架 | Angular 22：standalone 组件、zoneless、signal、懒加载路由 |
| 界面 | 基于 Tailwind CSS v4 的 spartan/ui（brain 基础组件，helm 组件复制到 `src/app/shared/ui` 中） |
| 图标 | `@ng-icons` 搭配 Lucide |
| 状态 | 可注入服务中的 signal（不使用状态管理库） |
| 表单 | Signal Forms（`@angular/forms/signals`） |
| API 客户端 | 手写的类型（`core/types.ts`）以及对 `HttpClient` 的小型封装（`core/api.ts`） |
| 翻译 | Transloco，通过 FormatJS 支持 ICU MessageFormat |
| 富文本 | 带预览的 Markdown 编辑器（`marked`、`DOMPurify`）；`blocks` 字段使用 TipTap |
| 测试 | 通过 Angular 单元测试构建器运行的 Vitest，以及端到端测试 Playwright |

### 文档

位于 `site/` 中的 Astro 加 Starlight。`site/scripts/sync-docs.mjs` 会在构建时把 `docs/` 中的几个 Markdown 文件（路线图、翻译指南）以及 `CHANGELOG.md` 复制到 **项目** 部分。

## 代码仓库布局

<FileTree>
- Cargo.toml 工作区（版本、edition、release 配置）
- crates/
  - verdin-schema/ schema 模型、JSON 解析器、校验、命名规则
  - verdin-db/ 连接池、flavor 和版本检测、类型化的值
  - verdin-migrate/ 物理模型、快照、diff、plan、带日志的 apply、平台表
  - verdin-query/ 把查询参数转为类型化查询，以及过滤和排序的 SQL
  - verdin-content/ Document Service：校验、草稿与发布、关联、组件、blocks、事件
  - verdin-auth/ 管理员用户、会话、双因素认证和通行密钥、API 令牌、RBAC、公开授权
  - verdin-upload/ 媒体库：存储提供方、文件元数据、图片格式
  - verdin-email/ 邮件投递：SMTP、Resend、Postmark 以及 log 提供方
  - verdin-search/ Tantivy 全文索引
  - verdin-plugins/ WebAssembly 插件（Extism）：文档钩子、路由、定时任务
  - verdin-graphql/ 根据 schema 生成的 GraphQL API
  - verdin-api/ axum 路由器：内容 API、管理 API、OpenAPI、MCP、实时、webhook……
  - verdin-testkit/ 测试辅助工具（每个测试一个全新的数据库）；不发布
  - verdin/ 二进制文件：配置、引导、CLI、指标、嵌入的管理后台
- admin/ Angular 管理后台
- packages/
  - client/ `@verdin/client`，类型化的 TypeScript 客户端
- examples/
  - blog/ 示例项目
- docker/ `compose.dev.yml`（数据库、RustFS、Mailpit）以及发布镜像
- site/ 本文档站点
- docs/ 路线图、翻译指南和设计笔记
</FileTree>

**依赖规则。** `verdin-schema` 和 `verdin-db` 是基础。`verdin-migrate` 和 `verdin-query` 构建在它们之上，`verdin-content` 构建在这两者之上，`verdin-auth`、`verdin-upload`、`verdin-search` 和 `verdin-plugins` 构建在它们下方的各层之上。`verdin-api` 和 `verdin-graphql` 位于接近顶层的位置，`verdin` 二进制文件依赖所有其他 crate。Cargo 禁止循环依赖，整个工作区都禁止使用 `unsafe` 代码。

## 从哪里开始阅读

| 想要了解 | 阅读 |
|---|---|
| 二进制文件如何启动并组装其路由器 | `crates/verdin/src/cli.rs`（`start`），然后是 `crates/verdin/src/app.rs` |
| schema 格式及其校验规则 | `crates/verdin-schema/src/raw.rs`、`validate.rs`、`naming.rs` |
| schema 如何变成表 | `crates/verdin-migrate/src/derive.rs`，然后是[存储](/zh-cn/internals/storage/) |
| 迁移 | `crates/verdin-migrate/src/diff.rs`、`plan.rs`、`apply.rs`，以及[迁移引擎](/zh-cn/internals/migrations/) |
| 内容 API 处理器 | `crates/verdin-api/src/handlers.rs` 和 `lib.rs` |
| 查询参数 | `crates/verdin-query/src/params.rs`（解析器）、`parse.rs`（校验）、`sql.rs`（SQL） |
| 读取和写入 | `crates/verdin-content/src/service.rs` 和 `input.rs`，以及 [Document Service](/zh-cn/internals/document-service/) |
| 管理后台 | `admin/src/app/app.routes.ts`，然后是 `features/content/` 以及[管理后台内部原理](/zh-cn/internals/admin-panel/) |

在 [GitHub](https://github.com/Verdin-CMS/verdin) 上浏览代码。本部分的其余页面介绍[存储](/zh-cn/internals/storage/)、[数据库层](/zh-cn/internals/database/)、[迁移](/zh-cn/internals/migrations/)、[Document Service](/zh-cn/internals/document-service/)、[管理后台](/zh-cn/internals/admin-panel/)、[测试](/zh-cn/internals/testing/)以及[决策日志](/zh-cn/internals/decisions/)。

面向用户的行为记录在其他地方：查询参数见 [REST API](/zh-cn/api/rest/)，设置项见[配置参考](/zh-cn/reference/configuration/)，命令见 [CLI 参考](/zh-cn/reference/cli/)，加固措施见[安全](/zh-cn/deploy/security/)。
