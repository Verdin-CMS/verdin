本日志按做出的先后顺序记录塑造了 Verdin 的设计选择，这样你在提议修改代码之前，就能了解代码为什么是现在这个样子。各条目保持撰写时的原貌，包括里程碑名称（M2–M4 是首次发布之前的里程碑）；后来的条目可能会细化之前的条目，比如第 28 条对第 1 条的细化。当你做出一个别人否则只能从代码中反推出来的决策时，请添加新的一行。

| # | 决策 | 结果 | 理由 |
|---|---|---|---|
| 1 | 组件：JSON 还是表 | **JSON 列**（[存储](/zh-cn/internals/storage/#组件和动态区域一个-json-列)） | 更少的 join，发布和版本管理变得简单，迁移更简单。对可重复组件的过滤很少见；以后可以用 JSON 函数添加 |
| 2 | `decimal` 的 JSON 编码 | 默认为 **number**，可选启用 `api.decimal_as_string` | 与 Strapi 兼容能最大化采用率；需要时可以获得精确值 |
| 3 | 管理后台表单 | **Signal Forms** | 契合以 signal 为先、zoneless 的管理后台；动态表单树由 schema 推导而来 |
| 4 | 语言 | 代码、文档和提交信息使用**英语** | 开源项目的覆盖面 |
| 5 | Strapi REST 兼容性 | **相同的参数和响应格式**；Verdin 独有的扩展位于 `actions/` 下 | 前端只需极少改动即可迁移 |
| 6 | 管理后台 JWT 算法 | HS256 | 单一密钥，简单；如果将来出现外部验证方，再改用 EdDSA |
| 7 | 文档 ID | ULID（26 个字符） | 可排序且可移植；Strapi 自己的 id 是不透明的 24 字符字符串，客户端从不解析它们 |
| 8 | 快照内容 | 物理模型，而不是 schema | 以后的版本可以从未改变的 schema 推导出新的表 |
| 9 | 属性可空性 | 始终可为空；`required` 在发布时检查 | 草稿可以不完整（Strapi v5 的行为）；添加必填字段是安全的 |
| 10 | `unique` 的强制执行 | 在 `(column, locale, publication_state)` 上建立唯一索引 | 没有竞态；草稿及其已发布版本共享值 |
| 11 | 状态列名 | `publication_state` | `state` 是一个常见的属性名 |
| 12 | SQL 保留字 | 始终为标识符加引号 | 无需对属性名设置任意的黑名单 |
| 13 | DML 构建 | 使用自己的构建器而不是 `sea-query` | 各方言的细节占主导（带类型的 NULL、排序规则、SQLite 格式）；少一层抽象 |
| 14 | 不带 `?status=draft` 的写入 | 发布（Strapi v5 的 REST 行为） | 对现有客户端即插即用地兼容 |
| 15 | 文本比较 | 在所有引擎上默认精确匹配；`…i` 运算符用于不区分大小写 | MySQL 与 PostgreSQL 上结果相同 |
| 16 | 临时访问控制（M2–M3） | `[api].open_access` 开关，已在 M4 中移除 | 在权限系统出现之前默认保持安全 |
| 17 | “目标属于一个文档” | 通过移动目标来强制执行，按状态分别处理 | 唯一索引会禁止草稿及其已发布版本共享同一个目标 |
| 18 | 反向（`mappedBy`）一侧 | 只读 | 在草稿与发布下通过它们写入存在歧义（写入拥有方的哪个版本？） |
| 19 | 链接位置 | 每次写入时重新编号为 1..n | 不会耗尽浮点精度；列表都很小 |
| 20 | 链接表的行 | 保留 `id` 主键 | 让迁移引擎和 SQLite 重建面对统一的表结构 |
| 21 | JWT 库 | 自己实现 HS256（HMAC-SHA256、恒定时间验证、固定 `alg`） | `jsonwebtoken` 11 需要一个会引入 RSA 的加密后端 |
| 22 | 平台表 | 与内容模型一起推导 | 所有内容使用同一种迁移机制 |
| 23 | 刷新令牌重复使用 | 吊销整个令牌家族，没有宽限期 | 简单且严格；管理员重新登录即可 |
| 24 | 通过内容 API 读取草稿 | 单独的 `readDrafts` 授权 | 读取已发布内容的令牌不会泄露草稿 |
| 25 | 构建器的应用顺序 | 先迁移，再写入文件，然后热替换应用 | 迁移失败时，文件和正在运行的应用都保持不变 |
| 26 | 管理后台写入 | 只保存草稿；发布是一个显式操作 | 符合编辑的预期；内容 API 保留 Strapi 默认发布的行为 |
| 27 | 管理后台运行时配置 | `<meta>` 标签，而不是内联脚本 | 让 CSP 无需允许 `unsafe-inline` 脚本 |
| 28 | 按组件字段过滤 | 按方言使用 JSON 路径运算符（`#>>`、`JSON_VALUE`、`json_extract`）；对可重复组件和动态区域的数组项使用 `EXISTS`（0.8） | 动态区域只能按 `__component` 过滤：其各项有不同的字段 |
| 29 | 管理后台 i18n | 使用 Transloco，配合扁平 JSON 语言包（`admin/public/i18n`）以及通过 FormatJS（一个自定义转译器）实现的 ICU MessageFormat，外面包一层小型 `I18n` 门面；不使用 Angular 的编译期 i18n | 运行时切换语言；适用于 Weblate/Crowdin 的标准文件；FormatJS 解释消息，因此严格的 CSP 无需 `unsafe-eval`（`@messageformat/core` 使用 `new Function` 编译）；键的类型由 `en.json` 生成，完整性由 `npm run i18n:check` 检查 |
| 30 | 一周的起始日 | 使用浏览器区域标签的 `Intl.Locale#getWeekInfo`（en-GB ≠ en-US），以地区表作为后备，用户可以覆盖 | 即使界面语言相同，也能跟随每个用户所在的地区 |
| 31 | 仪表盘布局的存储 | `vd_admin_users` 上按用户保存的 JSON `preferences` 列（≤ 64 KiB） | 跟随用户跨浏览器使用；主题和语言保留在 `localStorage` 中，因为它们在登录之前就要生效 |
| 32 | 刷新 cookie 的 `Secure` 默认值 | 在 `start` 中开启，在 `dev` 中关闭，可覆盖 | `verdin dev` 通过普通 HTTP 在所有浏览器中都能工作；生产环境保持严格 |
| 33 | Release 配置 | Thin LTO、1 个 codegen unit、去除符号；保留 unwinding | 发生 panic 的处理器不能让整个服务器宕机 |
| 34 | “未查看”的文档 | 按用户保存的 `vd_document_views` 行，文档变化时为除编辑者外的所有人删除；在 SQL 中用 `NOT EXISTS` 过滤 | 分页和计数保持精确；无需逐行比较时间戳 |
| 35 | 投票和调查 | 仅限管理后台的协作表（`vd_document_votes`、`vd_polls`、`vd_poll_votes`），适用于任何内容类型 | 无需在每个 schema 中建模投票字段，就能实现意见箱和团队决策 |
| 36 | 媒体存储 | 本地和 S3 都使用 `object_store` | 一条代码路径；流式 multipart 上传；开发环境和 CI 中使用 RustFS |
| 37 | 媒体链接 | 与关联一样使用按字段划分的链接表 | 与关联相同的草稿/发布语义；级联操作保持链接一致 |
| 38 | 内置权限升级 | `vd_settings` 中的版本标记，新增项只应用一次 | 已有安装可以获得新权限，而不会撤销管理员之后所做的修改 |
| 39 | 运行时功能 | 目录位于 `verdin-api`，开关位于 `vd_settings`（`features`），在所有模式下原地重建应用（ArcSwap） | 类似 Strapi 的插件开关，无需重启；不可用的功能会连同其计划版本一起列出 |
| 40 | API 参考界面 | 在 `{api}/docs` 使用 Scalar（`scalar_api_reference`，嵌入打包文件），仅在文档公开时提供；CSP 通过哈希允许其内联引导脚本 | 自托管（没有 CDN、字体、AI 智能体或遥测）；文档默认仍然只对令牌开放 |
| 41 | GraphQL | 随应用构建的 `async-graphql` 动态 schema；参数和选择集会被转换为 REST 参数树，并由同一个查询解析器解析 | REST 和 GraphQL 在过滤、分页、populate、校验和权限上使用同一套规则；由选择集推导的 populate 保留了批量加载 |
| 42 | 文档事件 | Document Service 上的监听器，在提交之后调用 | 副作用（已查看标记、未来的 webhook）适用于所有 API，无需在每个处理器中挂钩 |
