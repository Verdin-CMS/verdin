无论通过哪个 API，条目每次被创建、保存、发布、取消发布或丢弃草稿时，Verdin 都会保留一个版本。本指南介绍如何找到旧版本并恢复它、会保留多少个版本，以及对应的管理 API。

内容历史的工作方式与 Strapi 相同，只是在 Strapi 中这是付费功能。

## 开始之前

- **设置 → 功能 → 内容历史** 默认开启。关闭期间不会记录任何版本，历史记录也不可用。
- 读取条目的历史记录需要对该条目的读取权限；恢复需要更新权限。字段限制同样适用：你只能看到、也只能恢复你的角色可以读取或更新的字段。参见[权限](/zh-cn/reference/permissions/)。

## 恢复版本

<Steps>

1. 打开条目并选择 **历史记录**。
2. **版本** 列表显示每个版本及其事件（**已创建**、**已保存**、**已发布**、**已取消发布**、**已放弃草稿**）、日期和操作者。通过内容 API 所做的更改，作者显示为 **API**。
3. 选择一个版本以查看其字段。
4. 选择 **恢复** 并确认。

</Steps>

该版本会替换当前草稿；准备好之后再将其发布。在未启用草稿与发布的类型上，恢复会直接更新条目。

恢复时会被省略的内容：

- schema 中已不存在的字段会被列出，但不会被恢复。
- 指向已删除条目或文件的引用会被丢弃，编辑器会告诉你哪些字段丢失了这些引用。

**返回编辑器** 会回到该条目，不做任何更改。

## 保留多少个版本

Verdin 为每个条目的每个语言区域保留最新的 `[history].max_versions` 个版本（默认 50 个），并在新版本产生时删除更旧的版本：

```toml title="verdin.toml"
[history]
max_versions = 100
```

本地化条目的每个语言区域都有自己的历史记录。删除一个条目或其某个语言区域，也会删除相应的版本。参见[配置参考](/zh-cn/reference/configuration/)。

<Aside type="note">
Strapi 按天数保留历史记录，而 Verdin 为每个条目保留一定数量的版本，无论它们有多旧。
</Aside>

## 管理 API

所有路由都位于 `/admin/api` 下。

| 路由 | 权限 | 作用 |
| --- | --- | --- |
| `GET /history/{uid}/{documentId}?locale=&page=&pageSize=` | 读取该条目 | 各个版本，从新到旧，不含数据（每页 20 个，最多 100 个）。 |
| `GET /history/versions/{id}` | 读取该条目 | 一个版本及其数据。 |
| `POST /history/versions/{id}/restore` | 更新该条目 | 把该版本恢复为当前草稿。 |

恢复的响应会列出被丢弃的内容：

```json
{
  "data": {
    "documentId": "k3v9…",
    "restored": 42,
    "dropped": [{ "field": "tags", "count": 1 }]
  }
}
```

功能关闭时，这些路由返回 `404`。
