编辑摘要是一封每日邮件，按内容类型告诉每位管理员：自他们上次查看以来，有多少条目发生了变化。在每位管理员自行开启之前，它对所有人都是关闭的。本指南介绍管理员侧的设置、服务器设置，以及多个实例时的工作方式。

## “未查看”如何运作

当其他人通过任何 API 修改了某个条目时，该条目对你而言就变为未查看。你打开它之后，它就再次变为已查看。同样的标记也驱动着侧边栏中的 **新内容** 标记（可通过 **显示未读标记** 关闭）以及首页上的 **尚未查看** 小组件。

## 开启摘要

<Steps>

1. 打开你的 **个人资料**（或顶部栏中的偏好设置菜单）。
2. 在 **偏好设置** 下，开启 **未查看更改的每日邮件**。

</Steps>

该开关会在你的账户上设置偏好 `"digest": "daily"`（`PUT /admin/api/users/me/preferences`）。以同样的方式关闭它。

你会收到：

- 一封邮件，列出你可以读取的每种内容类型中未查看的条目数量，并附带管理后台的链接。
- 没有新内容的日子里，什么都不会收到。
- 只有在你的账户处于启用状态时才会收到。

## 服务器设置

摘要在 `[digest].hour_utc` 通过 `[email]` 发送：

```toml title="verdin.toml"
[email]
provider = "smtp"
from = "Verdin <no-reply@example.com>"

[email.smtp]
host = "smtp.example.com"

[digest]
hour_utc = 7    # 0–23, UTC; 8 by default
```

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `[digest].enabled` | `true` | 从此实例发送摘要。 |
| `[digest].hour_utc` | `8` | 摘要发出的时间（UTC 小时）。 |

邮件中的链接使用 `[server].public_url`；Verdin 运行在代理之后时请设置它。使用默认的 `log` 邮件提供方时，邮件只会写入服务器日志。参见[配置参考](/zh-cn/reference/configuration/)。

## 多个实例

每个设置了 `[digest].enabled = true` 的实例都会在设定的时间尝试发送摘要。第一个在数据库中领取当天任务的实例负责发送，其他实例跳过当天，因此管理员只会收到一封邮件。如果想让这项任务固定在某个已知实例上运行，请在其他实例上设置 `enabled = false`：

```sh title="Terminal"
VERDIN_DIGEST__ENABLED=false verdin start
```

<Aside type="note">
摘要是 Verdin 新增的功能；Strapi 没有对应功能。
</Aside>
