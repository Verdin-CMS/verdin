## 检查清单

- **共享的数据库。** PostgreSQL、MySQL 或 MariaDB。SQLite 是一台机器上的文件，无法用于多个实例。
- **所有实例使用相同的配置。** 每个实例都使用相同的 `verdin.toml`、schema 文件和密钥（`VERDIN_ADMIN_JWT_SECRET`、`VERDIN_TOKEN_PEPPER`、`VERDIN_SSO_<ID>_SECRET`……）。如果密钥不同，在一个实例上创建的会话和 API 令牌会被其他实例拒绝。
- **生产模式。** 运行 `verdin start`，而不是 `verdin dev`。在开发环境中修改 schema，提交后每次部署迁移一次。
- **共享的媒体存储。** 使用 S3 提供方（`[upload] provider = { name = "s3", … }`），或者在使用本地提供方时，把同一个卷挂载到每个实例上。
- **健康检查。** 让负载均衡器指向 `GET /_ready`，无法连接数据库时它会返回 `503`。`GET /_health` 只表示进程在运行；请将其用于存活检查。
- **共享事件总线。** 在每个实例上设置 `[cluster].bus = "database"`，这样实时事件、在线状态、缓存失效和搜索更新就会到达所有实例（参见[共享事件总线](#共享事件总线)）。
- **插件任务只在一个实例上运行。** 除一个实例外，在其他所有实例上设置 `[plugins].run_jobs = false`；否则每个实例都会运行定时任务。
- **按实例提供指标。** 设置 `[metrics].enabled = true` 后，每个实例都提供自己的 `/_metrics`；请逐个抓取。

## 多个实例时的迁移

在每个实例上同时运行 `verdin start --migrate` 是安全的。每次迁移运行都会在数据库中持有一个锁（PostgreSQL 上为 advisory lock，MySQL 和 MariaDB 上为 `GET_LOCK`，最多等待 60 秒），因此第一个实例执行这些步骤，其他实例会发现数据库已是最新状态。

滚动部署期间，旧版本的实例会在已迁移的数据库上继续运行一段时间。安全步骤只会创建表、添加可为空或带默认值的列和索引、加宽文本列或添加枚举值，旧版本察觉不到这些变化。有风险或破坏性的步骤（`verdin migrate apply --allow risky|destructive`）请在单独的一次部署中执行，等到没有任何旧 schema 的实例再需要那些数据时再进行。参见 [Schema 迁移](/zh-cn/concepts/schema-migrations/)。

## 共享的内容

| 内容 | 方式 |
| --- | --- |
| 管理后台会话、API 令牌、权限 | 存储在数据库中；无需会话保持。 |
| 功能开关、插件开关、语言区域、审核工作流 | 存储在数据库中。每个实例每隔 `[server].sync_interval_secs`（10 秒）重新读取一次，因此在一个实例上所做的更改会在这段时间内同步到其他实例。 |
| webhook 投递 | 数据库中的一个队列。实例在发送之前先领取投递，因此每次投递只发送一次。 |
| 定时发布计划 | 在执行前于数据库中领取，因此每个只执行一次。 |
| 每日摘要 | 每天的运行都会在数据库中领取，因此管理员只会收到一封邮件。 |
| 通行密钥质询 | 已使用的质询会记录在数据库中，因此在所有实例中每个质询只能响应一次。 |
| 审计日志清理 | 在每个实例上运行；重复删除旧行不会造成问题。 |
| 插件键值存储 | 存储在数据库中。 |
| 实时事件、在线状态和软锁 | 使用[事件总线](#共享事件总线)时：连接到任一实例的客户端都会收到所有实例的事件，并能看到正在编辑某个条目的每位管理员。 |
| 匿名响应缓存 | 使用事件总线时，在任一实例上的写入都会清空所有实例的缓存。 |
| 搜索索引 | 使用事件总线时，每个实例都会重新读取并索引其他实例所改动的条目。 |
| 转换后的图片 | 使用事件总线时，被修改或删除的文件会从每个实例的转换缓存中移除。 |

## 保留在各个实例中的内容

- **速率限制**由每个实例各自计数。有 `n` 个实例时，一个客户端每分钟最多可以发出 `[api].public_rate_limit` 的 `n` 倍请求。如果需要全局限制，请在负载均衡器上实施。
- **没有事件总线时**（`[cluster].bus = "none"`，默认值），实时事件和在线状态只属于客户端所连接的那个实例（请为事件流使用会话保持），写入只会清空自己所在实例的响应缓存（请把 `[api].cache_ttl_secs` 设为几秒，或者设为 `0`），搜索索引也只跟踪其所在实例执行的写入。
- **搜索索引**（`[search]`）位于每个实例的磁盘上。使用事件总线时，各实例会在其他实例发生变更时即时为其建立索引；以空索引目录启动的实例会从数据库重建索引。实例停机期间发生的变更，要等索引重建时才会进入它的索引：请在启动前删除该目录，或者在部署之后重建。
- **图片转换**（`[upload.transforms]`）按实例缓存在 `cache_dir` 下。在 `/uploads` 前放置 CDN 即可共享它们。
- **定时插件任务**：参见上文的 `run_jobs`。

## 共享事件总线

有些事情发生在内存中：实时事件流、谁在编辑哪个条目、匿名响应缓存、搜索索引。事件总线会把它们从发生的实例带到其他实例。

```toml title="verdin.toml"
[cluster]
bus = "database"
```

也可以在每个实例上设置 `VERDIN_CLUSTER__BUS=database`。总线使用项目的数据库，因此不需要其他服务：

- **PostgreSQL**：实例把每个事件写入 `vd_cluster_events` 表，并用 `NOTIFY` 唤醒其他实例。每个实例会从连接池中留出一个连接用于 `LISTEN`。通知只包含发送者的名字，因此任意大小的事件都不会超出 PostgreSQL 8000 字节的限制。如果连接断开，实例会重新连接并读取该表来追上进度。为防通知丢失，它还会每 30 秒读取一次该表。
- **MySQL、MariaDB 和 SQLite**：每个实例每隔 `poll_interval_ms`（默认 1000）读取 `vd_cluster_events` 的新行。查询使用主键，因此读取空表的开销很小。调低该间隔可以更快更新；一个实例的变更会在该间隔内到达其他实例。

传递的内容：内容写入（传给实时事件流、响应缓存和搜索索引，索引会重新读取被改动的条目）、媒体变更（事件流、缓存、转换缓存）、在线状态心跳，以及管理后台的评论和任务通知。每个实例会忽略自己的事件。webhook、CDN 清除、历史记录、审计日志和插件钩子不会传递：由做出变更的那个实例只运行一次。

行会在 10 分钟后删除。新实例从下一个事件开始，而不是从之前的事件开始。跟不上进度或丢失数据库连接的实例会丢弃事件，而不是卡住一次写入。`verdin_cluster_events_total` 指标统计已发送、已接收和已丢弃的事件（参见[监控](/zh-cn/deploy/monitoring/#prometheus-指标)）。

每个实例在总线上用每次启动时随机生成的 id 标识自己，如果设置了 `[cluster].instance_id`（例如使用 Pod 名称），则使用它。该 id 只用来区分各个实例，没有其他依赖它的地方。

只有一个实例时，请让 `bus` 保持为 `none`：事件留在内存中，不会写入任何内容。

Redis 和 NATS 后端暂不可用。数据库总线覆盖所有受支持的数据库，且无需运行其他服务。

## 设置

```toml title="verdin.toml"
[server]
# How often to read settings that other instances changed; 0 turns it off.
sync_interval_secs = 10

[plugins]
# Run the plugins' scheduled jobs here (true on one instance only).
run_jobs = true

[api]
# Emptied on every instance by the event bus; keep it short without it.
cache_ttl_secs = 60

[cluster]
# Share realtime events, presence, cache invalidation and search updates.
bus = "database"
# MySQL, MariaDB and SQLite: how often to read other instances' events.
poll_interval_ms = 1000
```

用 `VERDIN_PLUGINS__RUN_JOBS=false` 按实例设置 `run_jobs`。

## 数据库连接

每个实例最多打开 `[database].pool_max` 个连接（默认 10 个）。请让 `实例数 × pool_max` 低于数据库服务器的上限，并为迁移、备份和维护留出余量。PostgreSQL 的默认上限是 100 个连接。在 PostgreSQL 上，事件总线会为每个实例留出一个连接用于 `LISTEN`。
