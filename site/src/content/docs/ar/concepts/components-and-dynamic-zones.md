تتيح لك المكوّنات إعادة استخدام مجموعة من الحقول عبر أنواع المحتوى، وتتيح المناطق الديناميكية
للمحررين بناء صفحة من قائمة كتل. تشرح هذه الصفحة كيف يُنمذَج كلاهما ويُخزَّن،
وكيف يحدد ذلك طريقة قراءتهما وكتابتهما وتصفيتهما. أما صيغة المخطط نفسها
فهي في [نموذج المحتوى](/ar/concepts/content-model/).

## المكوّنات

المكوّن مجموعة من الحقول لها ملفها الخاص تحت `schema/components/<category>/`.
يحتوي `shared.seo` في مثال المدونة على عنوان وصفي ووصف:

```json title="schema/components/shared/seo.json"
{
  "displayName": "SEO",
  "attributes": {
    "metaTitle": { "type": "string", "maxLength": 60 },
    "metaDescription": { "type": "text", "maxLength": 160 }
  }
}
```

يستخدمه نوع المحتوى عبر سمة `component`. يجعله `repeatable: true` قائمة،
يمكن حدّها اختياريًا بعدد عناصر `min` و`max`:

```json
"seo": { "type": "component", "component": "shared.seo" },
"links": { "type": "component", "component": "shared.link", "repeatable": true, "max": 10 }
```

يمكن أن تحتوي المكوّنات على مكوّنات أخرى. لا يمكن أن يحتوي المكوّن على نفسه، مباشرة أو
عبر غيره؛ ويرفض التحقق من المخطط مثل هذه الحلقات.

## المناطق الديناميكية

المنطقة الديناميكية قائمة يمكن أن يكون كل عنصر فيها أيًا من المكوّنات التي تسمّيها.
يمزج جسم المقالة في المدونة بين كتل hero والاقتباسات:

```json
"blocks": { "type": "dynamiczone", "components": ["blocks.hero", "blocks.quote"], "max": 20 }
```

يذكر كل عنصر المكوّن الذي يمثّله في `__component`. ويحدّ `min` و`max` عدد
العناصر. المناطق الديناميكية خاصة بأنواع المحتوى فقط: لا يمكن أن يحتوي مكوّن على واحدة.

## مخزّنة بصيغة JSON

يخزّن Verdin قيمة المكوّن أو المنطقة الديناميكية في عمود JSON واحد من صف المستند
(`jsonb` على PostgreSQL، و`json` على MySQL وMariaDB، ونص على SQLite):

```json
// the "seo" column
{ "id": 1, "metaTitle": "Rust for CMS authors", "metaDescription": "…" }

// the "blocks" column
[
  { "__component": "blocks.hero", "id": 1, "title": "Hello", "subtitle": "…" },
  { "__component": "blocks.quote", "id": 2, "text": "…", "author": "Ferris" }
]
```

يحتفظ Strapi بكل مكوّن في جدوله الخاص، مربوطًا عبر جداول ربط متعددة الأشكال.
أما تخزين القيمة مع المستند فيعني:

- قراءة مستند مع مكوّناته لا تحتاج إلى أي join، مهما كان عمق تداخلها.
- النشر وتجاهل المسودة و[سجل المحتوى](/ar/guides/content/content-history/)
  تنسخ القيمة كما هي.
- إضافة حقل إلى مكوّن لا تغيّر أي جدول: يكون الترحيل فارغًا.
- تستخدم التصفية على حقول المكوّنات دوال JSON في كل قاعدة بيانات، وبعض عوامل التصفية
  غير متاح (راجع [التصفية](#التصفية)).

يحمل كل عنصر `id`، وهو عدد صحيح موجب فريد ضمن قيمة السمة. يخصص Verdin
واحدًا للعناصر الجديدة؛ أعِد إرسال `id` عند تحديث قائمة للحفاظ على استقرار العناصر.

## العلاقات والوسائط داخل المكوّنات

يمكن أن يحمل المكوّن علاقات ووسائط، مخزّنة في JSON نفسه: قيم `documentId` للعلاقات
ومعرّفات الملفات للوسائط.

- يجب أن تكون العلاقات داخل المكوّنات `oneWay` أو `manyWay`: فهي تشير إلى أهدافها
  وليس لها جانب عكسي. راجع [العلاقات](/ar/concepts/relations/#العلاقات-داخل-المكوّنات).
- يُتحقق من كل مرجع عند الكتابة: يجب أن يكون المستند أو الملف الهدف موجودًا، ويجب أن تطابق الملفات
  `allowedTypes` الخاص بالحقل.
- عند تعبئة المكوّن، تُحَلّ المراجع باستعلامات مجمّعة، بالحالة واللغة
  نفسيهما للمستند. يُستبعد الهدف المحذوف، أو الذي لا نسخة له
  في النسخة المقروءة.
- لا يمكن أن تكون العلاقات متعددة الأشكال (`morphToOne`، `morphToMany`) وحقول `password` داخل
  المكوّنات.

## القراءة

لا تُعاد المكوّنات والمناطق الديناميكية إلا عند تعبئتها، كما في Strapi:

```http
GET /api/articles?populate[0]=seo&populate[1]=blocks
GET /api/articles?populate=*
```

يعود المكوّن المُعبّأ كاملًا، بما فيه المكوّنات المتداخلة والعلاقات والوسائط
المحلولة. يحتاج Strapi إلى مستوى `populate` لكل مكوّن متداخل؛ أما Verdin فيقبل تلك
الخيارات المتداخلة من أجل التوافق ويتجاهلها. تعود عناصر المنطقة الديناميكية بترتيب
تخزينها، كل منها مع `__component` الخاص به.

في GraphQL، المكوّن نوع كائن يحمل اسم الـ UID الخاص به (`ComponentSharedSeo`)، والمنطقة
الديناميكية اتحاد (`ArticleBlocksDynamicZone`) تستعلم عنه بالأجزاء (fragments). راجع
[GraphQL API](/ar/api/graphql/).

## الكتابة

أرسل القيمة الكاملة للسمة. فهي تستبدل ما كان مخزّنًا:

```json
{
  "data": {
    "seo": { "metaTitle": "Rust for CMS authors" },
    "blocks": [
      { "__component": "blocks.hero", "title": "Hello" },
      { "__component": "blocks.quote", "text": "Fast and small.", "author": "Ferris" }
    ]
  }
}
```

يُتحقق من القيمة مقابل مخطط المكوّن في كل كتابة: المفاتيح غير المعروفة، والأنواع
الخاطئة، و`__component` لا تسمح به المنطقة الديناميكية، كلها أخطاء بمسارات مثل
`["blocks", 1, "text"]`. يُتحقق من حقول `required` داخل المكوّنات عند نشر
المستند، مثل حقول المستوى الأعلى.

## التصفية

| ماذا | مثال | ملاحظات |
| --- | --- | --- |
| حقول مكوّن | `filters[seo][metaTitle][$containsi]=rust` | الحقول البسيطة، بما فيها المكوّنات المتداخلة. |
| حقول مكوّن قابل للتكرار | `filters[links][url][$contains]=github` | يتطابق عندما يتطابق أحد العناصر. |
| المناطق الديناميكية | `filters[blocks][__component][$eq]=blocks.quote` | حسب `__component` فقط: لعناصر المكوّنات المختلفة حقول مختلفة. |

لا يمكنك الترتيب حسب حقول المكوّنات، ولا يمكن تصفية حقول `json` داخل المكوّنات.
راجع [REST API](/ar/api/rest/#التصفية) للاطلاع على العوامل.
