تربط العلاقة مستندات من نوعَي محتوى، مثل مقالة وتصنيفها. تشرح هذه
الصفحة أنواع العلاقات، وكيف تُخزَّن الروابط وتُحَلّ، وقواعد
كتابتها وترتيبها وقراءتها. لصيغة الطلبات، راجع
[REST API](/ar/api/rest/#الكتابة).

## الأنواع

العلاقة سمة من `type: "relation"` لها نوع `relation` ونوع محتوى
`target`:

| النوع | يرتبط المستند بـ | يُربط الهدف من | الجانب العكسي |
| --- | --- | --- | --- |
| `oneWay` | هدف واحد | أي عدد من المستندات | لا يوجد |
| `manyWay` | عدة أهداف | أي عدد من المستندات | لا يوجد |
| `manyToOne` | هدف واحد | أي عدد من المستندات | `oneToMany` |
| `oneToMany` | عدة أهداف | مستند واحد | `manyToOne` |
| `oneToOne` | هدف واحد | مستند واحد | `oneToOne` |
| `manyToMany` | عدة أهداف | أي عدد من المستندات | `manyToMany` |

يربط مثال المدونة المقالات بتصنيف (مع جانب عكسي) وبوسوم (بدون
جانب عكسي):

```json title="schema/content-types/article.json (excerpt)"
"category": { "type": "relation", "relation": "manyToOne", "target": "category", "inversedBy": "articles" },
"tags": { "type": "relation", "relation": "manyToMany", "target": "tag" }
```

```json title="schema/content-types/category.json (excerpt)"
"articles": { "type": "relation", "relation": "oneToMany", "target": "article", "mappedBy": "category" }
```

- الجانب الذي يحمل `inversedBy` (أو لا يحمل أيًا من المفتاحين) هو الجانب **المالك**: فهو يخزّن
  الروابط وهو الذي تكتبه.
- الجانب الذي يحمل `mappedBy` هو الجانب **العكسي**: يقرأ روابط المالك بشكل معكوس
  وهو للقراءة فقط. كتابته خطأ تحقق يسمّي السمة المالكة.
- يجب أن يتوافق الجانبان: يسمّي `mappedBy` سمة في الهدف تشير إلى الخلف
  بـ `inversedBy`، مع النوع العكسي المطابق من الجدول.
- ليس لـ `oneWay` و`manyWay` جانب عكسي أبدًا.

ينشئ منشئ أنواع المحتوى السمة العكسية على الهدف نيابةً عنك.

## مرتبطة بالمستند لا بالصف

للمستند عدة صفوف: مسودة ونسخة منشورة، وواحدة من كل منهما لكل لغة.
يخزّن Verdin العلاقة كرابط من **الصف** المصدر إلى **المستند** الهدف
(`documentId` الخاص به)، في جدول ربط اسمه `{table}_{field}_lnk`. يُختار الصف الهدف
عند قراءة العلاقة:

- ترى المقالة المنشورة النسخة المنشورة من تصنيفها؛ وترى مسودتها
  مسودة التصنيف. للأنواع التي لا تستخدم المسودة والنشر نسخة واحدة، يراها كل
  قارئ.
- عندما يكون الهدف مترجمًا أيضًا، تحلّه القراءة في اللغة نفسها. ونوع الهدف غير
  المترجم تتشاركه كل اللغات.
- إلغاء نشر تصنيف يخفيه عن المقالات المنشورة دون المساس بأي رابط؛
  ونشره من جديد يعيده.
- نشر مقالة لا ينسخ إلا روابطها الخاصة إلى النسخة المنشورة.

أما Strapi فيربط معرّفات الصفوف، لذا عليه إعادة كتابة الروابط كلما نُشرت مسودة.
لا يفعل Verdin ذلك أبدًا، ما يُبقي النشر نسخًا واحدًا لصف المسودة.

يحافظ Verdin على السلامة المرجعية بدلًا من المفاتيح الأجنبية: ربط مستند غير
موجود خطأ تحقق، وحذف مستند يزيل الروابط التي تشير إليه في
المعاملة نفسها.

### مستند واحد لكل هدف

في `oneToOne` و`oneToMany`، ينتمي الهدف إلى مستند مصدر واحد على الأكثر. ربط
هدف يملكه مستند آخر **ينقله**: يُزال رابط المستند الآخر في
الكتابة نفسها. هذا سلوك Strapi. ويُفرض لكل نسخة: يمكن لمسودة ونسختها
المنشورة أن تملكا الهدف نفسه.

## الكتابة

على الجانب المالك، تأخذ `data` قيمة `documentId`، أو قائمة منها، أو كائنًا يصف
تغييرًا:

| المدخل | الأثر |
| --- | --- |
| `"k2m…"` أو `{ "documentId": "k2m…" }` | ربط هدف واحد (العلاقات إلى واحد). |
| `["k2m…", "p9x…"]` | استبدال كل الروابط، بهذا الترتيب. |
| `null` أو `[]` | إزالة كل الروابط. |
| `{ "set": ["k2m…"] }` | استبدال كل الروابط. |
| `{ "connect": [...], "disconnect": [...] }` | إضافة روابط وإزالتها، مع الإبقاء على البقية. |

ربط هدف جديد بعلاقة إلى واحد يستبدل الهدف السابق. لا يمكن الجمع بين `set`
و`connect` أو `disconnect`.

في لوحة الإدارة، يسرد حقل العلاقة الإدخالات المرتبطة. يفتح **ربط إدخال** (أو
**ربط إدخالات** للعلاقات إلى متعدد) نافذة حوار تبحث في إدخالات نوع الهدف،
عبر حقولها النصية، وفي لغة الإدخال عندما يكون الهدف مترجمًا.
اختر إدخالًا واحدًا، أو حدّد عدة إدخالات وأضفها؛ الإدخالات المرتبطة بالفعل تكون مُعلَّمة.

## الترتيب

تحافظ العلاقات إلى متعدد على ترتيب روابطها. القائمة أو `set` تخزّن الترتيب الذي ترسله.
ويمكن لعناصر `connect` أن تحدد موضعها:

```json
{
  "data": {
    "tags": {
      "connect": [
        { "documentId": "k2m…", "position": { "before": "p9x…" } },
        { "documentId": "a7c…", "position": { "end": true } }
      ]
    }
  }
}
```

`position` هو `{ "before": documentId }` أو `{ "after": documentId }` أو `{ "start": true }` أو
`{ "end": true }`. يُعاد ترقيم المواضع في كل كتابة. تعيد القراءات المستندات المرتبطة
بترتيب الروابط ما لم تطلب التعبئة `sort`.

## القراءة

لا تُعاد العلاقات إلا عند تعبئتها:

```http
GET /api/articles?populate[category][fields][0]=name&populate[tags][sort]=label:asc
```

العلاقة إلى واحد كائن أو `null`؛ والعلاقة إلى متعدد مصفوفة. يمكن لكل علاقة مُعبّأة
أن تأخذ `fields` و`filters` و`sort` و`populate` و`count` الخاصة بها، حتى خمسة
مستويات عمقًا. كل مستوى استعلام واحد مجمَّع لكل علاقة (`WHERE … IN (…)`)، لا join،
فلا تضاعف التعبئات العميقة الصفوف. يُعاد 1,000 مستند مرتبط على الأكثر لكل
مستند وعلاقة؛ ويعطي `count` العدد الدقيق.

يمكنك التصفية عبر العلاقات (`filters[category][name][$eq]=News`)، من أي جانب، و
الترتيب حسب حقل في علاقة إلى واحد (`sort=category.name:asc`). تُرفض التعبئة أو التصفية أو
الترتيب عبر علاقة إلى نوع لا يستطيع المستدعي قراءته (ويتخطاه `populate=*`)،
فلا تكشف العلاقات أبدًا محتوى تخفيه
[صلاحيات](/ar/concepts/permissions/) المستدعي.

## العلاقات داخل المكوّنات

يمكن لـ[المكوّن](/ar/concepts/components-and-dynamic-zones/) أن يحمل علاقات، لكن `oneWay`
و`manyWay` فقط:

```json title="schema/components/shared/related.json"
{
  "displayName": "Related",
  "attributes": {
    "label": { "type": "string" },
    "articles": { "type": "relation", "relation": "manyWay", "target": "article" }
  }
}
```

يخزّن JSON المكوّن قيم `documentId` نفسها: سلسلة نصية لـ `oneWay`، ومصفوفة لـ
`manyWay`. لهذا لا يُسمح بالأنواع الأخرى هناك:

- سيضطر الجانب العكسي إلى البحث في JSON كل مستند ليعرف من يرتبط به.
- ولا يمكن فرض قاعدة "مستند واحد لكل هدف" (`oneToOne`، `oneToMany`) دون مثل هذا
  البحث أيضًا.

داخل المكوّنات، ترتيب قائمة `manyWay` هو ترتيب المصفوفة. يُتحقق من المراجع
عند الكتابة وتُحَلّ عند تعبئة المكوّن، بحالة المستند ولغته؛
وتُستبعد الأهداف التي لم تعد موجودة. ولا يمكن التصفية عليها.

## العلاقات متعددة الأشكال

تربط `morphToOne` و`morphToMany` مستندات من أي نوع محتوى. تخزّن روابطها
نوع الهدف بجوار `documentId` الخاص به، وتسمّي عمليات الكتابة كليهما:

```json
{ "data": { "related": [{ "__type": "api::article", "documentId": "k2m…" }, { "__type": "api::page", "documentId": "p9x…" }] } }
```

العناصر المُعبّأة هي المستندات الهدف مع `__type` الخاص بها، مقروءة بحالة الطلب
ولغته. يسمّي الجانبان العكسيان `morphOne` و`morphMany` نوع المالك (`target`)
وسمته (`morphBy`)، وهما للقراءة فقط. لا يمكن التصفية على العلاقات متعددة الأشكال أو
الترتيب حسبها، ولا يمكن أن تكون داخل المكوّنات.
