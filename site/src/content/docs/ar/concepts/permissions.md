يتحكم Verdin في جمهورين بشكل منفصل: **المسؤولون**، الذين يسجّلون الدخول إلى لوحة الإدارة، و
**مستدعو API المحتوى**، الذين يقرؤون المحتوى ويكتبونه من مواقعك وتطبيقاتك. تشرح هذه الصفحة
كيف يُفوَّض كل منهما وكيف تتكامل الأجزاء. القائمة الكاملة للإجراءات موجودة في
[مرجع الصلاحيات](/ar/reference/permissions/).

| من | يصادق بـ | تأتي الصلاحيات من | ينطبق على |
| --- | --- | --- | --- |
| المسؤول | البريد الإلكتروني وكلمة المرور (مع عامل ثانٍ أو SSO) | [أدواره](#أدوار-الإدارة) | لوحة الإدارة و[API الإدارة](/ar/api/admin/) |
| مستدعٍ مجهول | بلا ترويسة `Authorization` | [الوصول العام](#الوصول-العام) | REST وGraphQL والوقت الفعلي |
| خادم أو عملية بناء | `Authorization: Bearer vd_…` | نوع [رمز API](#رموز-api) | REST وGraphQL والوقت الفعلي |
| مستخدم نهائي مسجّل الدخول | `Authorization: Bearer <JWT>` | [دوره كمستخدم نهائي](#المستخدمون-النهائيون) | REST وGraphQL والوقت الفعلي |

كل شيء مغلق افتراضيًا: يجيب API المحتوى بـ `403` حتى تمنح الوصول، ولا
يستطيع المسؤول فعل إلا ما تسمح به أدواره.

## أدوار الإدارة

للمسؤول دور واحد أو أكثر؛ وتتراكم صلاحياتها. هناك ثلاثة أدوار مدمجة:

| الدور | يستطيع |
| --- | --- |
| **Super Admin** | كل شيء، بما في ذلك المستخدمون والأدوار ورموز API. لا يمكن تعديله. |
| **Editor** | قراءة كل المحتوى وإنشاءه وتحديثه وحذفه ونشره؛ واستخدام مكتبة الوسائط؛ وبدء عمليات النشر (deploy)؛ وإدارة SEO وإعادات التوجيه والقوائم والنماذج. |
| **Author** | إنشاء المحتوى، وقراءة وتحديث وحذف الإدخالات التي أنشأها فقط. لا يستطيع النشر. يرفع الملفات ويعدّل أو يحذف ملفاته فقط. |

تنشئ أدوارًا أخرى في **الإعدادات ← الأدوار** (الصلاحية `roles.manage`). لا يمكن تعطيل
آخر Super Admin نشط أو حذفه أو خفض رتبته، فلا تُغلق النسخة الباب على نفسها أبدًا.
ويمكن للدور أيضًا أن يشترط على أعضائه إعداد
[المصادقة الثنائية](/ar/guides/auth/two-factor/): وحتى يفعلوا، لا يصلون إلا إلى
ملفهم الشخصي.

### ما هي الصلاحية

الصلاحية **إجراء**، و**موضوع** لإجراءات المحتوى، و**شروط**
اختيارية:

- **إجراءات المحتوى**: `content.read` و`content.create` و`content.update` و
  `content.delete` و`content.publish`، على نوع محتوى واحد (`api::article`) أو على كل
  الأنواع (`*`).
- **إجراءات الوسائط**: `media.read` و`media.create` و`media.update` و`media.delete`، لـ
  مكتبة الوسائط.
- **إجراءات الإعدادات**، مثل `users.manage` أو `tokens.manage` أو `webhooks.manage` أو
  `features.manage`، التي تفتح الصفحات المقابلة في **الإعدادات**.
- **الشروط**: يحصر `is-creator` صلاحية المحتوى أو الوسائط فيما أنشأه
  المسؤول. هكذا يعمل دور Author.

تصبح الشروط جزءًا من استعلام قاعدة البيانات: القائمة المصفّاة بـ `is-creator` تعدّ
وتقسّم الصفحات بشكل صحيح، بدلًا من إخفاء الصفوف لاحقًا.

### صلاحيات الحقول واللغات

يمكن تضييق صلاحيات المحتوى أكثر:

- **الحقول.** يمكن لـ `content.read` و`content.create` و`content.update` أن تسرد السمات
  التي تشملها. الحقول خارج القائمة مخفية عن القراءة (بما في ذلك البحث والتصفية
  والترتيب والإدخالات المرتبطة) ومرفوضة عند الكتابة.
- **اللغات.** في [الأنواع المترجمة](/ar/concepts/internationalization/)، يمكن لصلاحيات المحتوى
  أن تسرد اللغات التي تشملها. لا يمكن قراءة النسخ في اللغات الأخرى أو تغييرها.

يُضبط كلاهما لكل نوع محتوى في محرر الدور، تحت **الحقول** و**اللغات**.

## API المحتوى

يُتحقق من مستدعي API المحتوى مقابل الصلاحيات الممنوحة: **إجراء** على **موضوع**.

| الإجراء | يسمح بـ |
| --- | --- |
| `find` | سرد المستندات (`GET /api/articles`)، أو قراءة نوع مفرد. |
| `findOne` | قراءة مستند واحد (`GET /api/articles/{documentId}`). |
| `create` | `POST` |
| `update` | `PUT` |
| `delete` | `DELETE` |
| `publish` | المسارات `actions/publish` و`actions/unpublish` و`actions/discard-draft`. |
| `readDrafts` | القراءة مع `status=draft`. |

المواضيع هي أنواع المحتوى، ومكتبة الوسائط (`plugin::upload`)، وحسابات المستخدمين النهائيين
(`plugin::users-permissions.user`) عندما تكون ميزة [المستخدمين النهائيين](/ar/guides/auth/end-users/) مفعّلة.

تنطبق بعض القواعد على كل مستدعٍ:

- تتطلب قراءة المسودات `readDrafts` إلى جانب `find` أو `findOne`. الصلاحية التي تقرأ
  محتوى موقعك لا يمكنها قراءة العمل غير المنشور عن طريق الخطأ.
- التعبئة أو التصفية أو الترتيب عبر علاقة تتطلب صلاحية القراءة على نوعها الهدف.
- لا تُعاد حقول `private` أبدًا، مهما كانت الصلاحيات.
- تعيد عملية الكتابة المستند المكتوب حتى بدون `find`، كما في Strapi.
- تنطبق الصلاحيات نفسها على [GraphQL](/ar/api/graphql/) وعلى
  [بث الوقت الفعلي](/ar/api/realtime/).

### الوصول العام

تحصل الطلبات التي لا تحمل ترويسة `Authorization` على الصلاحيات الممنوحة في **الإعدادات ← الوصول العام**.
لا يُمنح شيء افتراضيًا. الخيارات المعتادة هي `find` و`findOne` على الأنواع التي
يعرضها موقعك.

### رموز API

رموز API مخصصة للخوادم وخطوات البناء والسكربتات. أنشئها في
**الإعدادات ← رموز API** (الصلاحية `tokens.manage`):

| النوع | الصلاحيات |
| --- | --- |
| **للقراءة فقط** | `find` و`findOne` على كل نوع. بلا مسودات أبدًا. |
| **وصول كامل** | كل إجراء على كل نوع، بما في ذلك المسودات. |
| **مخصص** | الصلاحيات التي تختارها، مثل الوصول العام. |

- يبدأ الرمز بـ `vd_`. يُعرض سرّه مرة واحدة، عند إنشائه أو إعادة توليده؛
  ولا يخزّن Verdin إلا تجزئة (hash) بمفتاح له.
- قد تنتهي صلاحية الرموز. الرمز غير المعروف أو المنتهي أو المشوّه يعطي `401`: ولا يرجع أبدًا
  إلى الوصول العام.
- يمكن لأي رمز صالح قراءة مستند OpenAPI على `/api/_openapi.json`، ما لم تجعل
  التوثيق عامًا.

راجع [رموز API](/ar/guides/auth/api-tokens/) لإنشائها وتدويرها.

### المستخدمون النهائيون

المستخدمون النهائيون هم الأشخاص الذين يسجّلون الدخول إلى موقعك أو تطبيقك، كما في إضافة
users-permissions في Strapi. الميزة معطّلة افتراضيًا. لكل حساب دور واحد:

- **Public** هو دور الطلبات التي لا تحمل رمزًا: صلاحياته هي صلاحيات
  **الإعدادات ← الوصول العام**.
- **Authenticated** يُمنح للحسابات الجديدة افتراضيًا.
- تحمل الأدوار المخصصة أي مجموعة من الصلاحيات، بالإجراءات نفسها المذكورة أعلاه.

يرسل المستخدم النهائي الـ JWT الذي حصل عليه عند تسجيل الدخول على شكل `Authorization: Bearer <jwt>`. ويميّزه Verdin
عن رموز API بالبادئة `vd_`. راجع [المستخدمون النهائيون](/ar/guides/auth/end-users/).

## مقارنة مع Strapi

يتبع النموذج Strapi v5: RBAC للإدارة مع شروط `is-creator`، وAPI محتوى مع
الوصول العام ورموز API وأدوار users-permissions. الاختلافات:

- كل ميزة متاحة لكل مشروع: الأدوار المخصصة، وصلاحيات الحقول واللغات،
  و[SSO](/ar/guides/auth/sso/) و[سجلات التدقيق](/ar/guides/content/audit-logs/).
- قراءة المسودات عبر API المحتوى صلاحية مستقلة، `readDrafts`.
- للنشر عبر REST صلاحيته الخاصة، `publish`، ومساراته الخاصة.
