تجمع حزمة النشر الإدخالات التي تُطلق، أو تُسحب، معًا: إطلاق منتج، أو
حملة، أو مجموعة ترجمات. تنشرها يدويًا أو تمنحها تاريخًا. ينشئ هذا الدليل
حزمة نشر، ويضيف إدخالات، وينفّذها ويعرض API الإدارة.

تعمل حزم النشر مثل Releases في Strapi، وهي جزء من الخطط المدفوعة في Strapi.

## قبل أن تبدأ

- **الإعدادات ← الميزات ← حزم النشر** مفعّلة افتراضيًا. ما دامت معطّلة، تكون صفحة **حزم النشر**
  ومساراتها غير متاحة وتنتظر حزم النشر المجدولة.
- تتطلب إدارة حزم النشر **إدارة حزم النشر** (`releases.manage`).
- تتطلب إضافة إدخال أيضًا **نشر** على نوع محتواه، ويجب أن يستخدم النوع
  [المسودة والنشر](/ar/concepts/draft-and-publish/).

## أنشئ حزمة نشر

<Steps>

1. افتح **حزم النشر** في الشريط الجانبي واختر **حزمة نشر جديدة**.
2. أدخل **الاسم**.
3. اختياريًا، عيّن **النشر في (اختياري)**: التاريخ والوقت، بمنطقتك الزمنية، حين
   تُنفَّذ حزمة النشر. بدون تاريخ، تنتظر حزمة النشر حتى تنشرها بنفسك.
4. اختر **إنشاء**.

</Steps>

## أضف إدخالات

<Steps>

1. افتح إدخالًا في المحرر. تسرد لوحة **حزم النشر** الحزم التي يوجد فيها.
2. اختر **إضافة إلى حزمة نشر**.
3. اختر **حزمة النشر**، وتحت **عند تنفيذ حزمة النشر** اختر **نشر** أو
   **إلغاء النشر**.
4. اختر **إضافة**.

</Steps>

في الأنواع المترجمة، لا تُضاف إلا النسخة باللغة الحالية للمحرر. أضف كل
لغة تريد نشرها. إضافة إدخال موجود بالفعل في حزمة النشر تستبدل
إجراءه.

تسرد صفحة حزمة النشر إدخالاتها مع نوع المحتوى والإجراء. أزِل أحدها بـ
الزر في صفه.

## انشر حزمة النشر

- **الآن:** افتح حزمة النشر واختر **النشر الآن**.
- **في موعدها:** تتحقق مهمة في الخلفية كل 30 ثانية وتنفّذ حزم النشر التي
  حان موعدها، نيابةً عن المسؤول الذي أنشأها.

  R -->|نجحت كل الإجراءات| D[مكتملة]

يسجّل كل إجراء ما إذا كان قد نجح. عندما يفشل أحدها، مثلًا لأن الإدخال
حُذف أو لا يجتاز التحقق، تظل الإجراءات الأخرى تُنفَّذ وتنتهي حزمة النشر
بحالة **فشلت**، مع خطأ كل إجراء فاشل في صفه.

<Aside type="caution">
حزمة النشر التي نُفّذت لم يعد من الممكن تغييرها. لإعادة محاولة الإجراءات الفاشلة، أضف تلك الإدخالات إلى
حزمة نشر جديدة.
</Aside>

تُنشر حزمة النشر ككل: فهي لا تنتظر [مراحل
المراجعة](/ar/guides/content/review-workflows/). إذا اشترط مسار مراجعة مرحلة للنشر، فإن
الإدخالات الموجودة خارج تلك المرحلة تفشل مثل أي عملية نشر أخرى.

يمكن للـ webhooks الاشتراك في **تم نشر الحزمة** (`releases.publish`)، الذي يُرسل عند
تنفيذ حزمة نشر. راجع [Webhooks](/ar/guides/integrations/webhooks/).

## API الإدارة

كل المسارات تحت `/admin/api` وتحتاج إلى `releases.manage`.

```http
GET    /admin/api/releases?status=pending
POST   /admin/api/releases                    { "name": "Launch", "scheduledAt": "2026-10-01T08:00:00Z" }
GET    /admin/api/releases/{id}
PUT    /admin/api/releases/{id}               { "name": "Launch", "scheduledAt": null }
DELETE /admin/api/releases/{id}
POST   /admin/api/releases/{id}/actions       { "uid": "api::article", "documentId": "…", "locale": "fr", "action": "publish" }
DELETE /admin/api/releases/{id}/actions/{actionId}
POST   /admin/api/releases/{id}/publish
GET    /admin/api/content/{uid}/{documentId}/releases
```

- `status` هو `pending` أو `running` أو `done` أو `failed`؛ ولكل إجراء `status` و
  `error` خاصان به.
- تغيير حزمة نشر لم تعد قيد الانتظار، أو الإضافة إليها، أو نشرها، يجيب بـ `409`.
- `action` هو `publish` أو `unpublish`. تتطلب إضافة إجراء أيضًا `content.publish` على
  النوع. تُحَلّ اللغة عند إضافة الإجراء، فلا يؤدي تغيير لاحق للغة
  الافتراضية إلى نقله.
- حذف حزمة نشر يحذف قائمة إدخالاتها. أما الإدخالات نفسها فلا تتغير.
- يحتاج `GET /content/{uid}/{documentId}/releases` إلى صلاحية القراءة على الإدخال ويعيد
  قائمة فارغة للمسؤولين الذين لا يملكون `releases.manage`.
