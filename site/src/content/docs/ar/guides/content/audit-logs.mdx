تسجّل سجلات التدقيق من غيّر ماذا، ومتى: المحتوى، والوسائط، وعمليات تسجيل الدخول، وكل تغيير
يُجرى في لوحة الإدارة. يبيّن هذا الدليل ما يُسجَّل، وكيف تصفّي السجلات، وكم
يُحتفظ بها.

سجلات التدقيق ميزة للمؤسسات (Enterprise) في Strapi. أما في Verdin فهي جزء من النواة
مفتوحة المصدر.

## قبل أن تبدأ

- **الإعدادات ← الميزات ← سجلات التدقيق** مفعّلة افتراضيًا. إيقافها يوقف تسجيل الإجراءات
  الجديدة؛ وتبقى الإدخالات الموجودة قابلة للقراءة.
- تتطلب قراءة السجلات **قراءة سجلات التدقيق** (`audit.read`). راجع
  [الصلاحيات](/ar/reference/permissions/).

## ما الذي يُسجَّل

| المجال | الإجراءات | ملاحظات |
| --- | --- | --- |
| المحتوى | `entry.create`، `entry.update`، `entry.publish`، `entry.unpublish`، `entry.discard-draft`، `entry.delete` | من كل الواجهات: لوحة الإدارة وREST وGraphQL والإضافات. اللغة موجودة في التفاصيل. |
| مسارات المراجعة | `entry.stage`، `entry.assign` | تغييرات المراحل والتكليفات. |
| الوسائط | `media.create`، `media.update`، `media.delete` | رفع الملفات وتغييرها وحذفها. اسم الملف موجود في التفاصيل. |
| عمليات تسجيل الدخول | `admin.login` | تسجيلات الدخول بكلمة المرور وتسجيل المسؤول الأول (تُسجَّل بعد العامل الثاني عندما يكون للحساب عامل ثانٍ)، وتسجيلات الدخول عبر SSO مع الموفّر. |
| تغييرات الإدارة | `{METHOD} {route}`، مثل `PUT /roles/{id}` | كل عملية كتابة ناجحة على API الإدارة: المستخدمون، والأدوار، ورموز API، والإعدادات، والميزات، والـ webhooks، واللغات، والإضافات، وحزم النشر… معاملات المسار موجودة في التفاصيل. |

لكل إدخال وقت، ومنفّذ، وإجراء، وموضوع (uid نوع محتوى، أو `plugin::upload.file`،
أو مورد الإدارة مثل `roles`)، ومعرّف الموضوع، وتفاصيل، ولطلبات HTTP، عنوان IP
للعميل.

المنفّذ واحد مما يلي:

- **مسؤول**: مسؤول مسجّل الدخول، يُذكر اسمه في السجل.
- **API**: تغيير أُجري عبر API المحتوى أو GraphQL، برمز API، أو برمز مستخدم
  نهائي، أو بالوصول العام.
- **النظام**: عملية كتابة على API الإدارة دون مسؤول مسجّل الدخول.

خلف وكيل عكسي، عيّن `[server].trusted_proxies` حتى تعرض السجلات عنوان العميل
بدلًا من عنوان الوكيل. راجع [مرجع التهيئة](/ar/reference/configuration/).

## صفِّ السجلات

<Steps>

1. افتح **الإعدادات ← سجلات التدقيق**.
2. استخدم إعدادًا مسبقًا من **عوامل تصفية سريعة** (**المحتوى**، **الوسائط**، **عمليات تسجيل الدخول**)، أو املأ
   عوامل التصفية:
   - **الإجراء**: إجراء دقيق مثل `entry.publish`، أو بادئة تنتهي بـ `*`، مثل
     `entry.*`.
   - **المنفّذ**: مسؤول واحد، أو **أي شخص**.
   - **الموضوع**: uid نوع محتوى مثل `api::article`.
   - **من** و**إلى**: نطاق تاريخ. التاريخ بلا وقت يشمل ذلك اليوم كله.
3. اختر **تطبيق**. افتح **التفاصيل** على صف لترى كل ما سُجِّل له.

</Steps>

## استعلم عبر الـ API

```sh title="Terminal"
curl -G 'http://localhost:1337/admin/api/audit-logs' \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  --data-urlencode 'action=entry.*' \
  --data-urlencode 'subject=api::article' \
  --data-urlencode 'actor=3' \
  --data-urlencode 'from=2026-09-01' \
  --data-urlencode 'to=2026-09-30' \
  --data-urlencode 'page=1' --data-urlencode 'pageSize=50'
```

تأتي الإدخالات من الأحدث إلى الأقدم، 50 لكل صفحة افتراضيًا و200 على الأكثر:

```json
{
  "data": [
    {
      "id": 812,
      "at": "2026-09-28T14:03:11.000Z",
      "action": "entry.publish",
      "subject": "api::article",
      "subjectId": "k3v9…",
      "details": { "locale": "fr" },
      "ip": null,
      "actor": { "kind": "admin", "id": 3, "email": "ana@example.com", "name": "Ana Ruiz" }
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 50, "total": 1, "pageCount": 1 } }
}
```

يأخذ `from` و`to` تواريخ أو تواريخ مع أوقات بصيغة ISO 8601؛ وأي شيء آخر خطأ `400`.

## حدّد مدة الاحتفاظ بالإدخالات

تُحذف الإدخالات الأقدم من `[audit].retention_days` مرة يوميًا. القيمة الافتراضية 90 يومًا.

```toml title="verdin.toml"
[audit]
retention_days = 365
```

<Aside type="tip">
للاحتفاظ بإدخالات التدقيق مدةً أطول مما ينبغي لقاعدة بياناتك، انسخها بانتظام إلى
تخزينك الخاص عبر الـ API أعلاه.
</Aside>
