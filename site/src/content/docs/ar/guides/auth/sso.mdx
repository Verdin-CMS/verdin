يمكن للمسؤولين تسجيل الدخول عبر أي موفّر OpenID Connect: Microsoft Entra ID وGoogle Workspace و
Okta وAuth0 وKeycloak وAuthentik وGitLab وغيرها. يحصل كل موفّر على زر في
صفحة تسجيل الدخول، ويستمر تسجيل الدخول بكلمة المرور في العمل بجانبه. يسجّل هذا الدليل
تطبيقًا، ويهيّئ الموفّر في Verdin ويربط المجموعات بالأدوار.

SSO ميزة للمؤسسات (Enterprise) في Strapi. أما في Verdin فهي جزء من النواة مفتوحة المصدر.
للمستخدمين النهائيين لمواقعك، راجع [تسجيل الدخول عبر OAuth للمستخدمين النهائيين](/ar/guides/auth/end-users/)
بدلًا من ذلك.

## قبل أن تبدأ

- تتطلب تهيئة SSO **إدارة الميزات** (`features.manage`).
- عيّن `[server].public_url` إلى العنوان الذي يصل منه المسؤولون إلى Verdin، مثل
  `https://cms.example.com`. يُبنى منه عنوان URI لإعادة التوجيه.

## أعِدّه

<Steps>

1. **سجّل تطبيقًا** (عميل "web") لدى الموفّر، بعنوان URI لإعادة التوجيه هذا:

   ```text
   https://cms.example.com/admin/api/auth/sso/<id>/callback
   ```

   `<id>` هو معرّف الموفّر الذي تختاره في الخطوة 3، مثل `corp`. يتبع مسار الإدارة
   `[admin].path`.

2. **ضع سرّ العميل في البيئة** وأعِد تشغيل Verdin:

   ```sh title=".env"
   VERDIN_SSO_CORP_SECRET=…
   ```

   المتغير هو `VERDIN_SSO_<ID>_SECRET`، مع المعرّف بأحرف كبيرة والشرطات
   شرطات سفلية. العملاء العامون (PKCE فقط، بلا سرّ) لا يحتاجون إلى متغير.

3. **أضف الموفّر.** فعّل **الإعدادات ← الميزات ← تسجيل الدخول الموحّد**، واختر
   **إعداد الموفّرين**، ثم **إضافة موفّر** واملأ:

   - **المعرّف**: أحرف صغيرة وأرقام وشرطات، حتى 32 حرفًا.
   - **نص الزر**: يُعرض في صفحة تسجيل الدخول على شكل "المتابعة باستخدام …".
   - **عنوان URL للجهة المُصدِرة**: يقرأ Verdin المسار `/.well-known/openid-configuration` تحته. يجب أن يستخدم
     `https`، إلا على `localhost`.
   - **معرّف العميل** و**النطاقات** (`openid email profile` افتراضيًا؛ و`openid` مطلوب).

   تعرض نافذة الحوار **عنوان URI لإعادة التوجيه المطلوب تسجيله لدى الموفّر** واسم
   متغير السرّ. احفظ.

4. **جرّبه** في نافذة خاصة: تعرض صفحة تسجيل الدخول **المتابعة باستخدام Corp account**.

</Steps>

## من يمكنه تسجيل الدخول، وبأي أدوار

| الإعداد | مفتاح JSON | الأثر |
| --- | --- | --- |
| **نطاقات البريد المسموح بها** | `allowedDomains` | لا يمكن تسجيل الدخول إلا من نطاقات البريد هذه. الفارغ يعني أي نطاق. |
| **إنشاء الحسابات عند أول تسجيل دخول** | `autoCreate` | إنشاء حساب مسؤول في أول مرة يسجّل فيها شخص ما الدخول. بدونه، لا يمكن تسجيل الدخول إلا للعناوين التي لديها حساب بالفعل. |
| **الأدوار الافتراضية** | `defaultRoles` | رموز أدوار الحسابات المنشأة عندما لا يمنح ربط الأدوار أيًا منها. |
| **مطالبة الدور** | `roleClaim` | مطالبة (claim) في ID token تسرد مجموعات المستخدم، مثل `groups` أو `roles`. |
| **ربط الأدوار** | `roleMap` | رمز الدور الذي تمنحه كل قيمة مطالبة. |
| **الوثوق بالبريد غير المُتحقَّق منه** | `trustUnverifiedEmail` | قبول عناوين البريد التي لا يعلّمها الموفّر على أنها مُتحقَّق منها. |
| **المزوّد يفرض المصادقة متعددة العوامل** | `providerMfa` | عدم مطالبة المسؤولين بالعامل الثاني الخاص بـ Verdin بعد هذا الموفّر. |

- الموفّر الذي ينشئ حسابات يحتاج إلى أدوار افتراضية أو ربط للأدوار.
- لا يستطيع أي منهما منح دور Super Admin؛ رقِّ المسؤولين يدويًا في **الإعدادات ← المستخدمون**.
- لا تُعيَّن الأدوار إلا عند إنشاء الحساب. بعد ذلك، أدِرها في
  **الإعدادات ← المستخدمون**.
- يأتي الاسم الأول واسم العائلة للحساب المنشأ من المطالبتين `given_name` و`family_name`.

الموفّر نفسه بصيغة JSON، كما تخزّنه الميزة (`PUT /admin/api/features/sso`):

```json
{
  "enabled": true,
  "settings": {
    "providers": [
      {
        "id": "corp",
        "name": "Corp account",
        "issuer": "https://login.microsoftonline.com/<tenant>/v2.0",
        "clientId": "…",
        "scopes": ["openid", "email", "profile"],
        "autoCreate": true,
        "defaultRoles": ["author"],
        "roleClaim": "groups",
        "roleMap": { "<editors group id>": "editor" },
        "allowedDomains": ["corp.example"],
        "trustUnverifiedEmail": true,
        "providerMfa": true
      }
    ]
  }
}
```

## ملاحظات حول الموفّرين

- **Microsoft Entra ID** لا يضع `email_verified` في ID tokens الخاصة به: فعّل **الوثوق
  بالبريد غير المُتحقَّق منه** له. أضف المطالبة `groups` في إعدادات الرموز للتطبيق لربط
  المجموعات؛ وقيمها معرّفات المجموعات.
- **Google Workspace**: الجهة المُصدِرة هي `https://accounts.google.com`. احصر تسجيلات الدخول في
  نطاقك عبر **نطاقات البريد المسموح بها**.
- **Keycloak**: الجهة المُصدِرة هي عنوان URL الخاص بالـ realm، `https://<host>/realms/<realm>`.

## المصادقة الثنائية

افتراضيًا، يُطلب من المسؤول الذي لديه [عامل ثانٍ](/ar/guides/auth/two-factor/) في Verdin
تقديمه بعد أن يعيده الموفّر. عندما يفرض الموفّر المصادقة متعددة العوامل بالفعل، فعّل
**المزوّد يفرض المصادقة متعددة العوامل** حتى لا يُطلب منهم ذلك مرتين.

## كيف يعمل

<Diagram
  caption="تسجيل دخول عبر SSO"
  code={`sequenceDiagram
  participant B as المتصفح
  participant V as Verdin
  participant P as الموفّر
  B->>V: GET /admin/api/auth/sso/corp
  V-->>B: إعادة توجيه مع state وتحدّي PKCE
  B->>P: تسجيل الدخول
  P-->>B: إعادة توجيه إلى رد الاتصال مع code
  B->>V: GET /admin/api/auth/sso/corp/callback
  V->>P: تبادل code ‏(TLS)
  V-->>B: ملف تعريف ارتباط الجلسة، وإعادة توجيه إلى /admin/`}
/>

- يستخدم Verdin تدفق authorization code مع PKCE (S256). قيمة `state` موقّعة ومربوطة
  بملف تعريف ارتباط `HttpOnly` قصير الأمد، وتُشتق قيمة `nonce` منها.
- يتحقق من الجهة المُصدِرة لـ ID token، والجمهور (و`azp` عند وجود عدة جماهير)، وانتهاء الصلاحية
  والـ nonce. ويحتاج إلى مطالبة `email` مع `email_verified: true`، ما لم يكن **الوثوق بالبريد غير
  المُتحقَّق منه** مفعّلًا.
- يجب أن تستخدم نقاط نهاية الموفّر `https`.
- يُسجَّل كل تسجيل دخول عبر SSO في [سجلات التدقيق](/ar/guides/content/audit-logs/) على شكل
  `admin.login`، مع الموفّر.

عندما يفشل تسجيل دخول، يعود المتصفح إلى صفحة تسجيل الدخول مع السبب ("Single
sign-on failed")، ويُكتب السبب في سجل الخادم. الأسباب الشائعة:

| السبب | الإصلاح |
| --- | --- |
| the provider did not verify the email | فعّل **الوثوق بالبريد غير المُتحقَّق منه**، أو أصلح مطالبة الموفّر. |
| this email domain may not sign in | أضف النطاق إلى **نطاقات البريد المسموح بها**. |
| no admin account for this identity | فعّل **إنشاء الحسابات عند أول تسجيل دخول**، أو أنشئ المسؤول أولًا. |
| the sign-in request expired or was not started here | ابدأ من جديد من صفحة تسجيل الدخول، في المتصفح نفسه. |

<Aside type="note">
لا يستطيع المسؤول المعطّل تسجيل الدخول عبر SSO أيضًا.
</Aside>
