المسؤولون هم الأشخاص الذين يسجّلون الدخول إلى لوحة الإدارة. وهم منفصلون عن
[المستخدمين النهائيين](/ar/guides/auth/end-users/) لمواقعك وتطبيقاتك. ينشئ هذا الدليل المسؤول
الأول، ويدعو الآخرين، ويمنحهم أدوارًا، ويساعدهم على العودة عندما يُقفل
حسابهم.

## قبل أن تبدأ

- يحتاج Verdin إلى `VERDIN_ADMIN_JWT_SECRET` و`VERDIN_TOKEN_PEPPER` في البيئة. ولّدهما
  مرة واحدة بـ `verdin secrets`.
- تتطلب إدارة المسؤولين **إدارة المستخدمين** (`users.manage`)؛ وتتطلب إدارة الأدوار **إدارة
  الأدوار** (`roles.manage`). راجع [الصلاحيات](/ar/reference/permissions/).
- تُرسل الدعوات وإعادات تعيين كلمات المرور بالبريد عبر `[email]`. مع الموفّر الافتراضي `log`،
  تُكتب الرسائل، بما فيها الروابط، في سجل الخادم.

## أنشئ المسؤول الأول

افتح لوحة الإدارة (`http://localhost:1337/admin/` افتراضيًا). ما دام لا يوجد أي مسؤول،
تطلب المسؤول الأول، الذي يصبح Super Admin. تتكون كلمات المرور من 8 إلى 128 حرفًا.

بدون متصفح، استخدم CLI أو الـ API:

<Tabs>
<TabItem label="CLI">

```sh title="Terminal"
verdin admin create --email you@example.com
```

تأتي كلمة المرور من `VERDIN_ADMIN_PASSWORD`، أو تُقرأ من الإدخال القياسي. ينشئ الأمر
Super Admin ويعمل في أي وقت، لا للمسؤول الأول فقط.

</TabItem>
<TabItem label="API">

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/register-first-admin \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a long password"}'
```

لا يعمل هذا المسار إلا ما دام لا يوجد أي مسؤول.

</TabItem>
</Tabs>

## ادعُ مسؤولًا

<Steps>

1. افتح **الإعدادات ← المستخدمون** واختر **إضافة مستخدم**.
2. أدخل البريد الإلكتروني، واختياريًا **الاسم الأول** و**اسم العائلة**.
3. اختر دورًا واحدًا أو أكثر في **الأدوار**.
4. اترك **تعيين كلمة مرور الآن** معطّلًا لإرسال دعوة، أو فعّله لتعيين كلمة المرور
   بنفسك.
5. اختر **دعوة** (أو **حفظ** مع كلمة مرور).

</Steps>

تعرض نافذة **رابط الدعوة** الرابط وتقول ما إذا كان قد أُرسل بالبريد. شاركه
بنفسك عندما لا يكون كذلك، وهو ما يحدث دائمًا مع الموفّر `log`. يعمل الرابط مرة واحدة، لمدة 7 أيام؛ يفتحه المسؤول المدعو،
ويختار كلمة مرور ويُسجَّل دخوله.

ما دام المسؤول لم يسجّل الدخول قط، يستبدل **رابط دعوة جديد** في صفه
الرابط القديم. وبعد أن يسجّل الدخول، يستعيد الوصول بإعادة تعيين كلمة المرور بدلًا من ذلك.

## الأدوار

ينشئ Verdin ثلاثة أدوار، مثل Strapi:

| الدور | يستطيع |
| --- | --- |
| **Super Admin** | كل شيء. لا يمكن تغيير صلاحياته. |
| **Editor** | إنشاء كل المحتوى وتعديله ونشره وحذفه؛ وإدارة مكتبة الوسائط؛ وبدء عمليات النشر (deploy)؛ وإدارة SEO وإعادات التوجيه والقوائم والنماذج. |
| **Author** | إنشاء المحتوى، وتعديل وحذف إدخالاته وملفاته الخاصة. لا يستطيع النشر. |

أنشئ المزيد في **الإعدادات ← الأدوار** عبر **دور جديد**. لكل دور، اختر:

- **المحتوى**: لكل نوع محتوى (أو **جميع أنواع المحتوى**)، مستوى **قراءة**
  و**إنشاء** و**تحديث** و**حذف** و**نشر**: **بلا وصول**، أو **الخاصة به** (الإدخالات
  التي أنشأها المسؤول فقط) أو **الكل**. تحصر **الحقول** الإجراء في بعض الحقول، وتحصره **اللغات**
  في بعض اللغات.
- **مكتبة الوسائط**: إجراءات الملفات، لـ **جميع الملفات** أو **ملفاته الخاصة**.
- **الإعدادات**: الوصول إلى مناطق الإدارة، مثل **إدارة المستخدمين** أو **قراءة سجلات
  التدقيق**.
- **طلب المصادقة الثنائية**: راجع [المصادقة الثنائية](/ar/guides/auth/two-factor/).

يحصل المسؤول الذي لديه عدة أدوار على اتحاد صلاحياتها. القائمة الكاملة موجودة في
[مرجع الصلاحيات](/ar/reference/permissions/).

لا يستطيع إلا Super Admin منح دور Super Admin، أو تعديل Super Admin آخر أو حذفه أو
إعادة تعيينه.

## عطّل مسؤولًا أو أزِله

عدّل المسؤول في **الإعدادات ← المستخدمون** وأوقف **نشط**: لا يستطيع المستخدمون غير النشطين تسجيل
الدخول. يزيل **حذف** الحساب نهائيًا؛ فتظهر تعليقاته حينها على أنها كتبها مسؤول
محذوف.

## أعِد تعيين كلمة مرور

- **يعيد المسؤول تعيينها بنفسه:** يرسل **نسيت كلمة المرور؟** في صفحة تسجيل الدخول رابطًا بالبريد يعمل
  لمدة ساعة. تنتهي كل جلسات الحساب بمجرد تغيير كلمة المرور.
- **يعيّنها مسؤول آخر:** عدّل المسؤول في **الإعدادات ← المستخدمون** واكتب كلمة مرور جديدة.
  اترك الحقل فارغًا للإبقاء على الحالية.
- **من الخادم:** عندما لا يستطيع أحد تسجيل الدخول، شغّل

  ```sh title="Terminal"
  verdin admin reset-password --email you@example.com
  ```

  مع كلمة المرور في `VERDIN_ADMIN_PASSWORD` أو في الإدخال القياسي. يعيّن كلمة المرور،
  ويفتح قفل الحساب وينهي جلساته. لا يزيل المصادقة الثنائية:
  المسؤول الذي فقد عامله الثاني يحتاج إلى مسؤول آخر
  [لإعادة تعيينها](/ar/guides/auth/two-factor/).

## حماية تسجيل الدخول

- بعد 5 كلمات مرور خاطئة متتالية، يُقفل الحساب لمدة 15 دقيقة.
- تُحدّ طلبات تسجيل الدخول والتسجيل والتجديد لكل عنوان IP للعميل عبر
  `[admin].auth_rate_limit` (20 في الدقيقة افتراضيًا).
- جلسة المسؤول رمز وصول مدته 15 دقيقة يُجدَّد بملف تعريف ارتباط للتجديد يدوم 30
  يومًا. ملف تعريف الارتباط `Secure` في `verdin start`؛ راجع `[admin].secure_cookies`.

يرى كل مسؤول أجهزته المسجّل دخولها تحت **الجلسات** في **الملف الشخصي**، ويمكنه
**تسجيل الخروج** من واحد منها أو من كل الأجهزة الأخرى. تغيير كلمة المرور يسجّل الخروج من كل جهاز آخر.

## API الإدارة

سجّل الدخول للحصول على رمز وصول لـ API الإدارة:

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → { "data": { "user": {…}, "accessToken": "…", "accessTokenExpiresAt": "…" } }
```

| المسار | الصلاحية | يفعل |
| --- | --- | --- |
| `GET /users`، `GET /users/{id}` | `users.manage` | المسؤولون مع أدوارهم. |
| `POST /users` | `users.manage` | `{ email, firstname?, lastname?, roles: [ids], isActive?, password? }`. بدون `password`، يحتوي `meta` في الإجابة على `inviteUrl` و`emailed`. |
| `PUT /users/{id}`، `DELETE /users/{id}` | `users.manage` | تغيير مسؤول أو إزالته. |
| `POST /users/{id}/invite` | `users.manage` | رابط دعوة جديد، للمسؤولين الذين لم يسجّلوا الدخول قط. |
| `GET /roles`، `POST /roles`، `PUT /roles/{id}`، `DELETE /roles/{id}` | `roles.manage` | الأدوار وصلاحياتها. |
| `POST /auth/forgot-password` | عام | `{ email }`. يجيب دائمًا بـ `204`. |
| `GET /auth/sessions`، `DELETE /auth/sessions/{id}` | مسجّل الدخول | جلساتك. |

كل المسارات تحت `/admin/api`. راجع [API الإدارة](/ar/api/admin/).

<Aside type="caution">
لا توضع الأسرار أبدًا في `verdin.toml`. حافظ على ثبات السرّين عبر إعادات التشغيل والنسخ:
يوقّع `VERDIN_ADMIN_JWT_SECRET` رموز الوصول، وJWT الخاصة بالمستخدمين النهائيين وروابط المعاينة، و
يحمي `VERDIN_TOKEN_PEPPER` رموز API والعوامل الثانية (راجع
[رموز API](/ar/guides/auth/api-tokens/)).
</Aside>
