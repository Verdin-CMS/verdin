المستخدمون النهائيون هم الأشخاص الذين يسجّلون الدخول إلى موقعك أو تطبيقك، لا إلى لوحة الإدارة. يمنحهم Verdin
التسجيل، وتسجيل الدخول، وتأكيد البريد الإلكتروني، وإعادة تعيين كلمة المرور، وموفّري OAuth، وأدوارًا
تحدد ما يمكنهم فعله في API المحتوى. المسارات والحمولات هي تلك الخاصة بإضافة
users-permissions في Strapi v5، لذا تستمر الواجهات الأمامية الموجودة في العمل.

## قبل أن تبدأ

<Steps>

1. فعّل **الإعدادات ← الميزات ← المستخدمون والصلاحيات** (معطّلة افتراضيًا)، أو فعّل
   **المستخدمون النهائيون** في **الإعدادات ← المستخدمون النهائيون ← الإعدادات**.
2. هيّئ `[email]` إن كنت تستخدم تأكيد البريد الإلكتروني أو إعادة تعيين كلمة المرور:

   ```toml title="verdin.toml"
   [email]
   provider = "smtp"          # log (default), smtp, resend or postmark
   from = "My site <no-reply@example.com>"

   [email.smtp]
   host = "smtp.example.com"
   port = 587
   username = "apikey"        # password in VERDIN_EMAIL_SMTP_PASSWORD
   ```

   يقرأ Resend وPostmark مفتاحهما من `VERDIN_EMAIL_API_KEY`. في **الإعدادات ← الميزات ←
   البريد الإلكتروني** يوجد **إرسال بريد تجريبي**. للعمل المحلي، يتضمن `docker/compose.dev.yml`
   Mailpit (SMTP على المنفذ 1025، وصندوق الوارد على `http://localhost:8025`).

3. عيّن `[server].public_url`: تستخدمه الروابط في رسائل البريد واستدعاءات OAuth.

</Steps>

تتطلب إدارة الحسابات والأدوار **إدارة المستخدمين النهائيين** (`endusers.manage`). ويتطلب تغيير
تبويب الإعدادات (التسجيل، والموفّرون، والقوالب) **إدارة الميزات** (`features.manage`).

## هيّئ التسجيل والجلسات

في **الإعدادات ← المستخدمون النهائيون ← الإعدادات**، تحت **التسجيل والجلسات**:

| الإعداد | الافتراضي | الأثر |
| --- | --- | --- |
| **السماح بالتسجيل** | مفعّل | يستطيع أي شخص إنشاء حساب عبر API المحتوى. عند التعطيل: يجيب `register` بـ `400`. |
| **تأكيد عناوين البريد الإلكتروني** | معطّل | يجب على المستخدمين الجدد فتح رابط مُرسل بالبريد قبل أن يتمكنوا من تسجيل الدخول. |
| **الدور الافتراضي** | Authenticated | دور الحسابات الجديدة. |
| **الجلسات** | رمز واحد طويل الأمد | **رمز واحد طويل الأمد** (الوضع القديم في Strapi) أو **رموز قصيرة مع تجديد**. |
| **مدة الجلسة (بالأيام)** | 30 | مدة صلاحية الرمز طويل الأمد. |
| **مدة صلاحية رمز الوصول (بالدقائق)**، **مدة صلاحية رمز التجديد (بالأيام)** | 30، 30 | مع رموز التجديد. |

تحت **صفحات تطبيقك**، عيّن **بعد تأكيد البريد الإلكتروني** (حيث يصل المستخدمون بعد
تأكيد عنوانهم) و**صفحة إعادة تعيين كلمة المرور** (صفحتك التي تستقبل `?code=` وتطلب
كلمة مرور جديدة). تحتاج إعادة تعيين كلمة المرور إلى صفحة إعادة التعيين.

## أعِدّ الأدوار

يُجرى كل طلب بصفة أحد ما يلي:

- **Public**: الطلبات التي لا تحمل رمزًا. صلاحياته هي صلاحيات **الإعدادات ← الوصول
  العام**.
- **Authenticated**: الدور المدمج الذي يُمنح للحسابات الجديدة. لا يمكن حذفه.
- **الأدوار المخصصة**: أنشئها في **الإعدادات ← المستخدمون النهائيون ← الأدوار** عبر **إنشاء دور**.

تستخدم **الصلاحيات** الخاصة بالدور المصفوفة نفسها التي يستخدمها الوصول العام ورموز API: **بحث**،
و**بحث عن واحد**، و**إنشاء**، و**تحديث**، و**حذف**، و**نشر** و**قراءة المسودات** لكل
نوع محتوى، و**مكتبة الوسائط**، و**المستخدمون** (مسارات `/api/users`). يحصل المستخدم
المسجّل الدخول على صلاحيات دوره فقط، لا على الوصول العام أيضًا: امنح القراءة العامة
للدور أيضًا عندما يحتاج إليها المستخدمون المسجّلو الدخول. حذف دور ينقل مستخدميه إلى
Authenticated.

للتصرف بصفة مستخدم، ترسل الواجهة الأمامية الـ JWT الخاص به على شكل `Authorization: Bearer <jwt>`. تبدأ رموز API
بـ `vd_`، وبهذا يميّز Verdin بينهما.

## التسجيل وتسجيل الدخول

<Tabs>
<TabItem label="التسجيل">

```sh title="Terminal"
curl -X POST http://localhost:1337/api/auth/local/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"ana","email":"ana@example.com","password":"a long password"}'
# ← { "jwt": "…", "user": { "id": 1, "username": "ana", … } }
#   أو { "user": … } عندما يكون تأكيد البريد الإلكتروني مفعّلًا
```

</TabItem>
<TabItem label="تسجيل الدخول">

```sh title="Terminal"
curl -X POST http://localhost:1337/api/auth/local \
  -H 'Content-Type: application/json' \
  -d '{"identifier":"ana@example.com","password":"a long password"}'
# ← { "jwt": "…", "user": {…} }
```

`identifier` هو البريد الإلكتروني أو اسم المستخدم.

</TabItem>
<TabItem label="القراءة بصفة المستخدم">

```sh title="Terminal"
curl -H "Authorization: Bearer $JWT" http://localhost:1337/api/users/me
curl -H "Authorization: Bearer $JWT" http://localhost:1337/api/articles
```

</TabItem>
</Tabs>

يُرفض تسجيل الدخول للمستخدمين المحظورين ("Your account has been blocked by an administrator")
و، عند تفعيل التأكيد، لغير المؤكَّدين ("Your account email is not confirmed").

## الرموز والجلسات

- **رمز واحد طويل الأمد** (`jwtManagement: "legacy-support"`): يدوم الـ JWT
  **مدة الجلسة (بالأيام)**.
- **رموز قصيرة مع تجديد** (`jwtManagement: "refresh"`، كما في Strapi 5): يدوم الـ JWT
  **مدة صلاحية رمز الوصول (بالدقائق)**، وتحمل إجابات تسجيل الدخول أيضًا `refreshToken`. استدعِ
  `POST /api/auth/refresh` مع `{ refreshToken }` للحصول على زوج جديد. يعمل كل رمز تجديد
  مرة واحدة؛ وتقديم رمز مستخدَم ينهي الجلسة بأكملها. ينهيها `POST /api/auth/logout` مع
  `{ refreshToken }` عمدًا.
- تغيير كلمة المرور أو إعادة تعيينها يلغي الرموز السابقة للمستخدم، وكذلك حظر
  المستخدم.
- تُحدّ طلبات تسجيل الدخول والتسجيل وإعادة التعيين بـ 20 في الدقيقة لكل عنوان IP للعميل.
- تُخزَّن كلمات المرور بـ Argon2id. تحتفظ الحسابات المستوردة من Strapi بتجزئة bcrypt الخاصة بها
  حتى تسجيل دخولها التالي، حين تُعاد تجزئتها.

## تأكيد عناوين البريد الإلكتروني وإعادة تعيين كلمات المرور

مع تفعيل **تأكيد عناوين البريد الإلكتروني**، يرسل التسجيل بالبريد رابطًا إلى
`/api/auth/email-confirmation?confirmation=…`. فتحه يؤكد الحساب ويعيد التوجيه
إلى **بعد تأكيد البريد الإلكتروني**. يرسل `POST /api/auth/send-email-confirmation` مع `{ email }`
رابطًا جديدًا.

لكلمة مرور منسية:

<Steps>

1. يستدعي تطبيقك `POST /api/auth/forgot-password` مع `{ email }`. تكون الإجابة نفسها
   سواء كان الحساب موجودًا أم لا.
2. يتلقى المستخدم بريدًا فيه رابط إلى **صفحة إعادة تعيين كلمة المرور** الخاصة بك، مع `?code=…`.
   يعمل الرمز لمدة ساعة.
3. تستدعي صفحتك `POST /api/auth/reset-password` مع
   `{ code, password, passwordConfirmation }` وتحصل على `{ jwt, user }`.

</Steps>

يغيّر المستخدمون المسجّلو الدخول كلمة مرورهم عبر `POST /api/auth/change-password`
(`{ currentPassword, password, passwordConfirmation }`).

تُحرَّر رسائل البريد في **الإعدادات ← المستخدمون النهائيون ← الإعدادات ← قوالب البريد الإلكتروني**:
**الموضوع**، و**الرسالة**، و**نص HTML (اختياري)** لـ **تأكيد البريد الإلكتروني**
و**إعادة تعيين كلمة المرور**. تقبل العناصر النائبة `{{username}}` و`{{email}}` و`{{url}}`؛
وتُهرَّب القيم (HTML-escaped) في نص HTML.

## تسجيل الدخول بموفّري OAuth

توجد إعدادات مسبقة مدمجة لـ GitHub وGoogle وMicrosoft وDiscord وFacebook وGitLab وLinkedIn.
أي اسم آخر هو موفّر OAuth 2 عام يحتاج إلى **عنوان URL للتفويض** و**Token
URL** و**عنوان URL لمعلومات المستخدم**: تعمل Keycloak وAuth0 وOkta بهذه الطريقة بعناوين URL
الخاصة بمساحتك أو مستأجرك. تسجيل الدخول بـ Apple غير مدعوم.

<Steps>

1. في **الإعدادات ← المستخدمون النهائيون ← الإعدادات ← موفّرو تسجيل الدخول**، اختر **Add GitHub** (أو
   إعدادًا مسبقًا آخر، أو **إضافة موفّر OAuth 2**).
2. لدى الموفّر، سجّل **عنوان URL لرد الاتصال المطلوب تسجيله لدى الموفّر** المعروض في
   نافذة الحوار: `https://cms.example.com/api/connect/github/callback`.
3. أدخل **معرّف العميل**، و**النطاقات** الاختيارية، و**إعادة التوجيه إلى تطبيقك**: صفحة
   الواجهة الأمامية التي تستقبل `?access_token=` بعد تسجيل الدخول. فعّل **مفعّل**.
4. ضع سرّ العميل في بيئة الخادم وأعِد التشغيل:

   ```sh title=".env"
   VERDIN_OAUTH_GITHUB_SECRET=…
   ```

   المتغير هو `VERDIN_OAUTH_<PROVIDER>_SECRET`. لا تُخزَّن الأسرار أبدًا في
   قاعدة البيانات.

</Steps>

يتبع تسجيل الدخول تدفق Strapi:

<Diagram
  caption="تسجيل الدخول عبر OAuth للمستخدمين النهائيين"
  code={`sequenceDiagram
  participant B as المتصفح
  participant V as Verdin
  participant P as الموفّر
  B->>V: GET /api/connect/github
  V-->>B: إعادة توجيه إلى الموفّر
  B->>P: الموافقة
  P-->>B: إعادة توجيه إلى /api/connect/github/callback
  B->>V: رد الاتصال
  V-->>B: إعادة توجيه إلى صفحتك ?access_token=…
  B->>V: GET /api/auth/github/callback?access_token=…
  V-->>B: { jwt, user }`}
/>

قيمة `state` في OAuth موقّعة ومربوطة بالمتصفح عبر ملف تعريف ارتباط. تُطابَق الحسابات حسب
البريد الإلكتروني؛ والبريد المستخدَم بالفعل لدى موفّر آخر، أو في حساب بالبريد وكلمة المرور،
يُرفض ("Email is already taken.").

## إدارة الحسابات في لوحة الإدارة

تسرد **الإعدادات ← المستخدمون النهائيون ← المستخدمون** الحسابات، مع البحث باسم المستخدم أو البريد الإلكتروني. يمكنك
**إضافة مستخدم**، وتعديل حساب (اسم المستخدم، والبريد الإلكتروني، وكلمة المرور، والدور، و**مؤكَّد**، و**محظور**)،
و**حظره** أو **إلغاء حظره**، وحذفه.

## المسارات

تعيش المسارات تحت بادئة API المحتوى، `/api` افتراضيًا. تتبع أشكال الطلبات والاستجابات
Strapi v5.

| المسار | يفعل |
| --- | --- |
| `POST /auth/local/register` | `{ username, email, password }` ← `{ jwt, user }`، أو `{ user }` مع تفعيل تأكيد البريد الإلكتروني. |
| `POST /auth/local` | `{ identifier, password }` ← `{ jwt, user }`. |
| `GET /auth/email-confirmation?confirmation=` | يؤكد البريد الإلكتروني، ثم يعيد التوجيه أو يعيد المستخدم. |
| `POST /auth/send-email-confirmation` | `{ email }`: رابط تأكيد جديد. |
| `POST /auth/forgot-password` | `{ email }`: يرسل رابط إعادة التعيين بالبريد. |
| `POST /auth/reset-password` | `{ code, password, passwordConfirmation }` ← `{ jwt, user }`. |
| `POST /auth/change-password` | مسجّل الدخول. `{ currentPassword, password, passwordConfirmation }` ← `{ jwt, user }`. |
| `POST /auth/refresh`، `POST /auth/logout` | وضع التجديد فقط: `{ refreshToken }`. |
| `GET /users/me` | المستخدم المسجّل الدخول. |
| `GET /users`، `GET /users/count`، `GET /users/{id}` | يحتاج إلى بحث / بحث عن واحد على المستخدمين. JSON عادي، بلا غلاف `data`، كما في Strapi. يضيف `populate=role` الدور، ويبحث `_q=` في أسماء المستخدمين والبريد الإلكتروني، ويقسّم `pagination[page]` و`pagination[pageSize]` (100 على الأكثر) إلى صفحات. |
| `POST /users`، `PUT /users/{id}`، `DELETE /users/{id}` | يحتاج إلى إنشاء / تحديث / حذف على المستخدمين. `{ username, email, password, confirmed, blocked, role }`، مع `role` كمعرّف دور. |
| `GET /connect/{provider}` | يبدأ تسجيل دخول عبر OAuth. |
| `GET /auth/{provider}/callback?access_token=` | يستبدل رمز الموفّر بـ `{ jwt, user }`. |

ينقل `verdin import strapi` المستخدمين النهائيين مع كلمات مرورهم، والأدوار المخصصة، و
صلاحيات الأدوار العامة والموثّقة والمخصصة. راجع
[الترحيل من Strapi](/ar/migrate/from-strapi/).

<Aside type="caution">
الدور الذي لديه إنشاء أو تحديث أو حذف على **المستخدمون** يتيح لأعضائه إدارة كل حساب
مستخدم نهائي. امنحه فقط للأدوار الموثوقة أو رموز API.
</Aside>
