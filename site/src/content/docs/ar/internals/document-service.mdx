خدمة المستندات (`DocumentService` في `crates/verdin-content/src/service.rs`) هي الشيفرة الوحيدة التي تقرأ صفوف المحتوى وتكتبها. يمر عبرها API المحتوى، وAPI الإدارة، وGraphQL، وMCP، والإضافات، وعمليات الاستيراد، وخريطة الموقع، لذا يتصرف التحقق، والمسودة والنشر، وقواعد العلاقات، والأحداث بالطريقة نفسها أيًا كان الـ API الذي أجرى الاستدعاء. ومثل Document Service في Strapi v5، تعمل على المستندات (المعرَّفة بـ `documentId`)، لا على الصفوف.

## الـ API

الطرق الرئيسية (مبسّطة؛ راجع المصدر للأنواع الدقيقة):

| الطريقة | تفعل |
|---|---|
| `find_many(uid, &Query) -> Page` | صفحة من المستندات، مع `meta` بصيغة الصفحة أو الإزاحة |
| `find_one(uid, document_id, &Query) -> Option<Json>` | مستند واحد بحالة الاستعلام ولغته |
| `single_document_id(uid)` | مستند نوع مفرد، إن وُجد |
| `create(uid, &data, WriteOptions) -> String` | تنشئ مستندًا وتعيد `documentId` الخاص به |
| `update(uid, document_id, &data, WriteOptions)` | تحديث جزئي للمسودة (أو للنسخة الوحيدة)؛ وتنشئ نسخة لغة جديدة عند الحاجة |
| `delete(uid, document_id)` | تحذف كل نسخ المستند في اللغة الحالية |
| `publish(uid, document_id, actor)` | تنسخ المسودة إلى النسخة المنشورة |
| `unpublish(uid, document_id)` | تحذف النسخة المنشورة |
| `discard_draft(uid, document_id)` | تستبدل المسودة بالنسخة المنشورة |
| `uid_availability(…)` | ما إذا كانت قيمة `uid` متاحة، مع اقتراح متاح |
| `document_locales`، `timeline`، `usage`… | دوال مساعدة للوحة الإدارة |

لـ `WriteOptions` حقلان: `publish` (النشر بعد الكتابة، في أنواع المسودة والنشر) و`actor` (المسؤول المسجَّل في `created_by_id` / `updated_by_id`).

الخدمة قيمة رخيصة النسخ تُهيّأ بطرق بنّاءة: `in_locale(locale)` للأنواع المترجمة، و`with_listener`، و`with_hook`، و`dry_run()` (التحقق من كتابة بالكامل ثم التراجع عنها، ويُستخدم في التشغيل التجريبي للاستيراد) و`without_plugin_hooks()` (لعمليات الكتابة التي تجريها الإضافات بنفسها).

لا تعرف الخدمة من يستدعيها. تطبّق طبقة الـ API الصلاحيات قبل الاستدعاء: ترفض الإجراءات التي يفتقر إليها المستدعي، وتحصر الأنواع التي يمكن للاستعلام التعبئة أو التصفية عبرها، وتضيف عوامل تصفية الشروط إلى الاستعلام (مثلًا يصبح شرط "الإدخالات الخاصة" لدور الإدارة **Author** هو `created_by_id = <admin id>`). عوامل التصفية جزء من SQL، فيبقى التقسيم إلى صفحات والعدّ دقيقين.

## ما تفعله كل عملية كتابة

1. **الخطافات.** تُنفَّذ `DocumentHook` أولًا، بالترتيب: مراحل مسارات المراجعة، ثم الإضافات. يمكن للخطاف أن يستبدل البيانات أو يرفض الكتابة، فيصبح ذلك `400`. وتستخدم أسماء دورة الحياة في Strapi (`beforeCreate`، `beforeUpdate`، `beforeDelete`، `beforePublish`، `beforeUnpublish`، `beforeDiscardDraft`).
2. **التحقق من المدخل** (`input.rs`): المفاتيح غير المعروفة، وحقول النظام (`id`، `documentId`، الطوابع الزمنية) والجوانب العكسية (`mappedBy`) للعلاقات أخطاء؛ ويُتحقق من كل قيمة مقابل نوع سمتها وقيودها (`min`، `max`، `minLength`، `maxLength`، `regex`، قيم التعداد، وعدد عناصر العلاقة، و`allowedTypes` للوسائط)؛ ويُتحقق من المكوّنات والمناطق الديناميكية تكراريًا؛ وتُجزّأ قيم `password` بـ argon2.
3. **المراجع.** يجب أن تكون المستندات المرتبطة وملفات الوسائط موجودة، ويُتحقق من ذلك داخل المعاملة.
4. **الصفوف والروابط**، في معاملة واحدة: يُدرج الصف أو يُحدَّث، ثم تُعاد كتابة جداول الربط الخاصة بالعلاقات والعلاقات متعددة الأشكال والوسائط (مع إعادة ترقيم المواضع 1..n). ربط هدف `oneToOne` أو `oneToMany` ينقله بعيدًا عن المستندات الأخرى في الحالة نفسها.
5. **الحقول المطلوبة والقواعد.** عندما تصبح نسخة منشورة، أو في كل كتابة للأنواع التي لا تستخدم المسودة والنشر، يُتحقق من سمات `required` (بما فيها داخل المكوّنات والمناطق الديناميكية) ومن قواعد التحقق عبر الحقول. الإخفاق يتراجع عن الكتابة كلها.
6. **التفرّد** تفرضه الفهارس الفريدة المحصورة. يُربط الانتهاك بسمته ويُبلَّغ عنه كـ `ValidationError`، بلا حالات سباق.
7. **الاعتماد، ثم الأحداث.** بعد اعتماد المعاملة، تستدعي الخدمة كل `DocumentListener` مع `DocumentEvent` (`entry.create`، `entry.update`، `entry.publish`، `entry.unpublish`، `entry.discard-draft`، `entry.delete`)، يحمل الـ uid و`documentId` واللغة والمنفّذ.

تستخدم أخطاء التحقق صيغة Strapi: قائمة من `{ path, message, name: "ValidationError" }`، حيث يشير `path` إلى موضع في البيانات (`["seo", "metaTitle"]`، `["blocks", 2, "text"]`). وتربطها لوحة الإدارة بحقولها.

يُبقي المستمعون الحالة المشتقة متوافقة مع المحتوى دون شيفرة لكل معالج: الـ webhooks، وسجل المحتوى، وذاكرة الاستجابات المؤقتة، وخطافات after في الإضافات، وسجل التدقيق، وأحداث الوقت الفعلي، والتعليقات والمهام، وعلامات "تم الاطلاع"، وعمليات تفريغ CDN، وفهرس البحث. المستمع الذي يفشل يسجّل خطأه الخاص؛ فالكتابة قد نجحت بالفعل. ولأن المستمعين يعملون بعد الاعتماد، لا يصل إليهم التشغيل التجريبي أبدًا.

## القراءات

تحدد القراءة صفوف الحالة واللغة المطلوبتين، وتطبّق عوامل التصفية والترتيب في SQL، ثم تعبّئ ما طُلب:

- **العلاقات** تُحمَّل باستعلامات مجمّعة، واحد لكل علاقة ومستوى (`WHERE … IN (…)`، على دفعات من 500 معرّف)، لا بعمليات join متتالية أبدًا. يتجنب ذلك الانفجارات الديكارتية واستعلامات N+1 معًا. يُعبَّأ 1,000 إدخال مرتبط على الأكثر لكل إدخال وعلاقة؛ ويبقى العدّ دقيقًا.
- تُقرأ الأهداف بالنسخة نفسها للمصدر: ترى المستندات المنشورة أهدافًا منشورة، وترى المسودات مسودات.
- **المكوّنات والمناطق الديناميكية** تأتي من عمود JSON الخاص بها؛ وتُحَلّ العلاقات والوسائط داخلها بالاستعلامات المجمّعة نفسها.
- **البحث بـ `_q`** يستخدم فهرس Tantivy عندما يكون `[search]` مفعّلًا، وإلا فـ `$containsi` غير حساس لحالة الأحرف على الحقول النصية.

شكل المخرجات (المستندات المسطّحة، وصيغ القيم، وصيغة `populate`، والحدود) موثّق في [REST API](/ar/api/rest/).

## دورة حياة طلب API المحتوى

1. **الطبقات المشتركة** (من الخارج إلى الداخل): يُحَلّ عنوان العميل (باستخدام `X-Forwarded-For` فقط من `[server].trusted_proxies`)، وتعدّ المقاييس الطلب عند تفعيلها، ويُعيَّن معرّف طلب ويُمرَّر كـ `x-request-id`، ويفتح التتبع (tracing) نطاقًا، ويُطبَّق CORS على API المحتوى وGraphQL عند تعيين `[api].cors_origins`.
2. **طبقات API المحتوى**: حدود المعدل لكل عميل، وقيم `ETag` والذاكرة المؤقتة الاختيارية للقراءات المجهولة، وحد حجم الجسم (`[server].body_limit`) ومهلة الطلب، ووسوم ذاكرة CDN المؤقتة على الاستجابات.
3. **التوجيه.** يُبحث عن مقطع المسار بين قيم `pluralName` لأنواع المحتوى (أنواع المجموعات) و`singularName` (الأنواع المفردة). الأسماء غير المعروفة تعطي `404`.
4. **التفويض** (`verdin-auth`). غياب ترويسة `Authorization` يعني الدور العام؛ و`Bearer vd_…` رمز API. الرمز غير الصالح أو المنتهي يعطي `401`، لا الدور العام أبدًا. يجب أن يكون إجراء المسار (`find`، `findOne`، `create`، `update`، `delete`، `publish`) ممنوحًا للنوع، وإلا فالإجابة `403`.
5. **تحليل الاستعلام** (`verdin-query`). تُحلَّل سلسلة الاستعلام الخام إلى شجرة أقواس (16 KB على الأكثر، و12 مستوى، و1,000 زوج)، ثم إلى `Query` مُنمَّط يُتحقق منه مقابل حقول النوع: الحقول غير المعروفة و`private` تعطي `400`، وتُحصر التعبئة وعوامل التصفية والترتيب عبر العلاقات في الأنواع التي يُسمح للمستدعي بقراءتها. وتحتاج قراءة `?status=draft` أيضًا إلى `readDrafts`.
6. **خدمة المستندات.** يستدعي المعالج `find_many` أو `find_one` أو `create` أو `update` أو `delete` أو إجراءً. عمليات الكتابة دون `?status=draft` تنشر في أنواع المسودة والنشر (سلوك Strapi v5)، وتعيد قراءة النسخة المكتوبة للاستجابة.
7. **الاستجابة.** `{ "data": …, "meta": … }`. تستخدم الأخطاء الغلاف نفسه مع `data: null` وكائن `error`.

تتبع مسارات API الإدارة المسار نفسه مع جلسة مسؤول بدلًا من رمز API، وRBAC للإدارة بدلًا من صلاحيات API المحتوى، وقيم افتراضية تبدأ بالمسودة: فهي تقرأ المسودات ولا تكتب إلا المسودات، والنشر إجراء صريح. يترجم GraphQL وسائطه إلى شجرة المعاملات نفسها قبل الخطوة 5، فيشارك المحلل والحدود وقواعد الصلاحيات.
