تضيف الإضافات سلوكًا إلى Verdin دون تغيير الخادم أو إعادة بنائه. الإضافة
وحدة WebAssembly مع ملف manifest، تُوضع في مجلد `plugins/` الخاص بالمشروع. تشرح هذه
الصفحة ما يمكن للإضافات فعله وكيفية تثبيت إحداها؛ ولكتابة إضافة، اتبع
[درس الإضافات](/ar/extending/plugin-tutorial/)، وابحث عن التفاصيل في
[مرجع الإضافات](/ar/extending/plugin-reference/).

## ما يمكن للإضافة فعله

| نقطة التوسيع | الغرض منها |
| --- | --- |
| **خطافات على عمليات الكتابة** | قبل إنشاء إدخال، أو تحديثه، أو نشره، أو إلغاء نشره، أو حذفه، أو تجاهل مسودته، غيّر البيانات أو ارفض الكتابة برسالة. وبعد الكتابة، تفاعل معها (سجّل، أو أشعِر، أو زامن). |
| **المسارات** | قدّم نقاط نهاية HTTP تحت `/api/plugins/<name>/…`: مستقبِل webhook، أو خلاصة محسوبة، أو وكيل إلى خدمة أخرى. |
| **المهام المجدولة** | شغّل دالة وفق جدول cron (بتوقيت UTC). |
| **حقول GraphQL** | أضف حقول `name(args: JSON): JSON` إلى `Query` أو `Mutation`. |
| **أدوات لوحة المعلومات** | أضف أنواع أدوات إلى لوحة معلومات الإدارة، كـ Web Components. |
| **الحقول المخصصة** | امنح السمات محررًا مخصصًا في لوحة الإدارة (منتقي ألوان، خريطة)، كـ Web Components؛ وتُخزَّن القيمة كنوع سمة عادي. |
| **الإعدادات** | أعلن نموذج إعدادات يملؤه المسؤولون في **الإعدادات ← الإضافات**. |

تقرأ الإضافة المحتوى وتكتبه عبر خدمة المستندات (Document Service) نفسها التي تستخدمها لوحة الإدارة و
الـ API، لذا تنطبق الـ webhooks والسجل ومراحل المراجعة والتحقق على عمليات الكتابة التي تجريها.

<Aside type="note">
إضافات Verdin ليست إضافات Strapi. إضافات Strapi حزم Node.js لها وصول كامل
إلى الخادم؛ أما Verdin فلا يشغّل أي JavaScript على الخادم. الحقول المخصصة المعلنة في مخططات
Strapi (سمات `customField`) تُحمَّل كما هي، ويمكن لإضافة Verdin أن توفّر
محررها.
</Aside>

## البيئة المعزولة

تعمل الإضافات في بيئة WebAssembly معزولة ([Extism](https://extism.org)، على Wasmtime). ليس للوحدة
ملفات ولا مقابس ولا اتصال خاص بقاعدة البيانات. كل ما تفعله خارج
ذاكرتها يمر عبر بضع دوال مضيف، ويتحقق الخادم من كل استدعاء مقابل
**القدرات** التي يعلنها ملف manifest:

| القدرة | تمنح |
| --- | --- |
| `read` | قراءة إدخالات أنواع المحتوى المدرجة (أو `*`). |
| `write` | إنشاء إدخالات الأنواع المدرجة وتحديثها ونشرها وإلغاء نشرها وحذفها (وقراءتها أيضًا). |
| `http` | طلبات HTTP إلى المضيفين المدرجين (`api.example.com`، `*.example.com`). |
| `kv` | مخزن مفتاح-قيمة خاص بها، في قاعدة بيانات Verdin. |

لكل استدعاء أيضًا حدود: حد زمني (5 ثوانٍ افتراضيًا) وحد للذاكرة (64 MB
افتراضيًا)، يُعيَّنان في ملف manifest. الوحدة التي تقع في trap أو ينفد وقتها تفشل في ذلك الاستدعاء
فقط؛ ويعيد Verdin بناءها في الاستدعاء التالي.

ما لا تقرره البيئة المعزولة نيابةً عنك:

- **المسارات عامة.** لا يُتحقق من الطلبات إلى `/api/plugins/<name>/…` مقابل
  **الوصول العام** أو صلاحيات رموز API. تتلقى الإضافة هوية المستدعي (أي شخص،
  أو رمز API، أو مستخدم نهائي) ويجب أن تتحقق منها.
- **ترى الخطافات كل عمليات الكتابة على أنواعها**، مهما كانت قدرة `read` لدى الإضافة.
- **خطاف before الفاشل لا يمنع الكتابة.** إذا تعطّلت الوحدة أو انتهت مهلتها،
  يُسجَّل الخطأ وتستمر الكتابة. الرفض الصريح وحده يوقفها.

## ثبّت إضافة

<Steps>

1. ضع الإضافة في مجلدها الخاص تحت `plugins/`، بجوار `verdin.toml`. يحتوي على
   ملف manifest، والوحدة، واختياريًا ملفات لوحة الإدارة:

   <FileTree>
   - verdin.toml
   - plugins/
     - reading-time/
       - plugin.toml
       - plugin.wasm
       - admin/ اختياري: Web Components للوحة الإدارة
         - index.js
   - schema/
   </FileTree>

2. أعِد تشغيل Verdin. يحمّل كل `plugins/*/plugin.toml` عند بدء التشغيل ويسجّل
   `plugin found` لكل منها. الإضافة التي تفشل في التحميل (ملف manifest غير صالح، أو وحدة مفقودة،
   أو اسم مكرر) تُدرج في **الإعدادات ← الإضافات** مع السبب.

3. في لوحة الإدارة، افتح **الإعدادات ← الإضافات**. راجع ما تطلبه الإضافة تحت
   **الوصول** و**الخطافات** و**المسارات** و**المهام**، ثم فعّلها.

4. إذا كانت للإضافة إعدادات، افتح **الإعدادات** على بطاقتها، واملأها واحفظ.

</Steps>

تبدأ الإضافات المثبّتة معطّلة. يسري تفعيل الإضافة وتعديل إعداداتها
فورًا، على كل نسخة (تلتقط النسخ الأخرى التغيير خلال
`[server].sync_interval_secs`). أما التغييرات على `plugin.toml` أو الوحدة فتحتاج إلى إعادة تشغيل.

تتطلب إدارة الإضافات الصلاحية `plugins.manage` (**إدارة الإضافات**). راجع
[مرجع الصلاحيات](/ar/reference/permissions/).

## هيّئ `[plugins]`

```toml title="verdin.toml"
[plugins]
path = "plugins"   # directory of plugins, relative to verdin.toml
run_jobs = true    # run scheduled jobs on this instance
```

مع عدة نسخ، عيّن `run_jobs = false` على كل النسخ ما عدا واحدة، حتى تُنفَّذ كل مهمة مرة واحدة. راجع
[مرجع التهيئة](/ar/reference/configuration/).

## التشغيل

- **استدعاء واحد في كل مرة.** لكل إضافة نسخة واحدة وتعالج استدعاءً واحدًا في كل مرة، لذا
  يؤخّر المسار البطيء خطافات تلك الإضافة. أبقِ الدوال قصيرة.
- **السجلات.** ما تسجّله الإضافة يذهب إلى سجل الخادم وإلى **الإعدادات ← الإضافات ←
  السجلات** (آخر 200 سطر، محفوظة في الذاكرة).
- **النشر (deploy).** اشحن الإضافات مع المشروع (في الصورة أو وحدة التخزين)، مثل
  المخطط. تعيش المفاتيح والإعدادات في قاعدة البيانات.
