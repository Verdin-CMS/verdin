يبني [`deploy/playground/`](https://github.com/verdin-cms/verdin/tree/main/deploy/playground)
حاوية لعرض تجريبي عام: [مثال المدونة](https://github.com/verdin-cms/verdin/tree/main/examples/blog)
على SQLite، مع بضع مقالات منشورة وحساب تجريبي يستطيع الزوار تسجيل الدخول به.
وكل ساعة يتخلص من قاعدة البيانات ويبدأ من جديد. لا تحتاج الحاوية إلى وحدة تخزين
ولا إلى خادم قاعدة بيانات ولا إلى أسرار منك. أما أين تستضيفها فالأمر لك؛ تصلح أي منصة
تشغّل حاوية واحدة بعنوان HTTPS عام.

شُغّلت السكربتات على بناء محلي في 2026-09-30 (ثلاث دورات إعادة ضبط)؛ وبُنيت الصورة
لكنها لم تُشغَّل من إصدار منشور.

## ما الذي يحصل عليه الزوار

- لوحة الإدارة على `/admin/`، مع تسجيل الدخول بـ **demo@example.com** / **verdin-demo-1234**.
  للحساب الدور **Editor**: يستطيع إنشاء المحتوى وتعديله ونشره وحذفه
  ورفع الوسائط، لكنه لا يستطيع إدارة المستخدمين والأدوار ورموز API وwebhooks والإعدادات.
- وصول قراءة عام إلى المقالات والتصنيفات والوسوم والصفحة الرئيسية عبر REST
  (`/api/articles?populate=*`) وGraphQL.
- مقالتان منشورتان، ومسودة، وتصنيفان، ووسمان، والصفحة الرئيسية.

ويوجد أيضًا Super Admin، بكلمة مرور عشوائية لا يعرفها أحد.

## كيف يعمل

يكرّر `run.sh` ما يلي في حلقة:

1. يحذف `/var/lib/verdin-playground` (قاعدة البيانات والرفوعات وفهرس البحث
   وذاكرة الصور المؤقتة) ويولّد أسرارًا جديدة، فتنتهي جلسات الدورة السابقة.
2. يبدأ `verdin start --migrate` وينتظر `/_ready`.
3. يشغّل `seed.sh`: ينشئ الحسابات عبر CLI وAPI الإدارة، ويفتح وصول القراءة
   العام وينشئ المحتوى.
4. ينتظر `PLAYGROUND_RESET_SECONDS` (3600)، ويوقف الخادم ويبدأ من جديد. وإن توقف
   الخادم من تلقاء نفسه، يبدأ من جديد فورًا.

تحدّ التهيئة (`deploy/playground/verdin.toml`) الرفوعات بـ 2 MB، وتحدّ معدل
الطلبات المجهولة بـ 300 في الدقيقة لكل عنوان، وتبعد تسليمات webhook
عن العناوين الخاصة، وتفعّل البحث.

## ابنِه وشغّله

من جذر المستودع:

```sh frame="terminal"
docker build -f deploy/playground/Dockerfile -t verdin-playground .
docker run -p 1337:1337 --tmpfs /var/lib/verdin-playground:uid=65532,gid=65532 verdin-playground
```

الصورة Alpine مع `curl` و`jq` (تحتاج السكربتات إلى shell، وليس في الصورة
الرسمية واحد) والملف التنفيذي الساكن المنسوخ من `ghcr.io/verdin-cms/verdin`. مرّر
`--build-arg VERDIN_IMAGE=ghcr.io/verdin-cms/verdin:<version>` لاختيار الإصدار.
يُبقي `tmpfs` البيانات في الذاكرة؛ وبدونه تعيش البيانات في نظام ملفات
الحاوية، وهذا يعمل أيضًا.

| المتغير | الافتراضي | ماذا |
| --- | --- | --- |
| `PLAYGROUND_RESET_SECONDS` | `3600` | الوقت بين عمليات إعادة الضبط. |
| `PLAYGROUND_EMAIL`، `PLAYGROUND_PASSWORD` | `demo@example.com`، `verdin-demo-1234` | الحساب التجريبي. |
| `VERDIN_SERVER__PUBLIC_URL` | | العنوان العام لبيئة التجربة. |
| `VERDIN_SERVER__TRUSTED_PROXIES` | | نطاق وكيل المنصة، لكي تنطبق حدود المعدل لكل زائر. |

## استضافته

شغّل نسخة واحدة بالضبط (قاعدة البيانات محلية)، وأبقِها تعمل (بلا تقليص إلى الصفر:
فمؤقت إعادة الضبط يعيش في العملية) وضع HTTPS أمامها: فكعكة جلسة لوحة الإدارة
تكون `Secure` في وضع `start`، فيتطلب تسجيل الدخول HTTPS. يستطيع أي شخص كتابة المحتوى ورفع
الصور لمدة تصل إلى ساعة، فأشر في الصفحة التي تربط إليها إلى جدول إعادة
الضبط، وأبقِ النسخة على نطاق منفصل عن أي شيء يتشارك الكعكات.
