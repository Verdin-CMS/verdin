تصف هذه الصفحة ما يفعله Verdin لحماية المشروع والإعدادات التي تتحكم فيها.
استخدمها مع [قائمة التحقق للإنتاج](/ar/deploy/production-checklist/) عندما تجهّز
نسخة لحركة حقيقية.

## ما هو مغلق افتراضيًا

- **API المحتوى.** لا تحصل الطلبات المجهولة على شيء حتى تمنح صلاحيات
  عامة في **الإعدادات ← الوصول العام**. الرمز غير المعروف أو المنتهي أو المشوّه
  يعطي `401`، ولا يرجع أبدًا إلى الدور العام. راجع [الصلاحيات](/ar/concepts/permissions/).
- **مستند OpenAPI** على `/api/_openapi.json` يحتاج إلى رمز API صالح حتى تجعله
  عامًا في **الإعدادات ← الميزات ← توثيق الـ API**.
- **الميزات الاختيارية** مثل GraphQL والمستخدمين النهائيين وSSO وخادم MCP تبقى معطّلة حتى
  يفعّلها مسؤول لديه الصلاحية `features.manage` في
  **الإعدادات ← الميزات**.
- **الإضافات** تبقى معطّلة حتى يفعّل مسؤول كل واحدة منها في **الإعدادات ← الإضافات**.
- **استدعاءات المتصفح عبر المصادر.** لا يجوز لأي مصدر استدعاء أي API من متصفح حتى
  تدرجه في `[api].cors_origins`.

## تسجيل دخول المسؤولين

| الحماية | التفاصيل |
| --- | --- |
| تجزئة كلمات المرور | Argon2id بمعاملات OWASP، مع إعادة التجزئة عند تغيّرها. |
| الجلسات | رمز وصول مدته 15 دقيقة يُحفظ في ذاكرة الصفحة (لا في `localStorage` أبدًا)، ورمز تجديد مدته 30 يومًا في ملف تعريف ارتباط `HttpOnly` و`SameSite=Strict` محصور في `/admin/api/auth`. يتدوّر رمز التجديد مع كل استخدام؛ وتقديم رمز قديم ينهي الجلسة بأكملها. |
| ملفات تعريف الارتباط الآمنة | ملف تعريف ارتباط التجديد `Secure` في `verdin start`. يعطّل `[admin].secure_cookies = false` ذلك ويسجّل تحذيرًا. |
| CSRF | يحتاج التجديد وتسجيل الخروج إلى ترويسة `X-Verdin-CSRF`، التي لا يستطيع نموذج من موقع آخر إرسالها. |
| القفل | خمس محاولات فاشلة تقفل الحساب لمدة 15 دقيقة. تُحسب الإخفاقات عبر خطوتي كلمة المرور والعامل الثاني. تحصل عناوين البريد غير المعروفة وكلمات المرور الخاطئة على الإجابة نفسها، في الزمن نفسه. |
| حد المعدل | تسجيل الدخول والتسجيل والتجديد: `[admin].auth_rate_limit` طلبًا في الدقيقة لكل عنوان عميل (20). |
| العامل الثاني | تطبيقات المصادقة (TOTP) ومفاتيح المرور، مع رموز الاسترداد. يمكن للدور أن يشترطه (`requireTwoFactor`). راجع [المصادقة الثنائية](/ar/guides/auth/two-factor/). |
| Super Admin | لا يستطيع إلا Super Admin إنشاء Super Admin أو تعديله أو حذفه أو إعادة تعيينه، أو منح ذلك الدور. لا يمكن إزالة آخر Super Admin نشط. |

يُسجَّل المسؤول الأول عبر اللوحة ما دام لا يوجد أي مسؤول. افعل ذلك مباشرة بعد
التشغيل الأول، أو أنشئه بـ `verdin admin create --email …` قبل كشف
الخادم.

## لوحة الإدارة وAPI الإدارة

- لا يرسل API الإدارة (`/admin/api`) أي ترويسات CORS، مهما قال `[api].cors_origins`:
  لا تسمح المتصفحات بقراءة إجاباته إلا لمصدر اللوحة نفسه.
- تُقدَّم اللوحة بسياسة أمان محتوى (Content Security Policy) صارمة (السكربتات من مصدرها
  فقط)، و`X-Frame-Options: DENY`، و`X-Content-Type-Options: nosniff` و
  `Referrer-Policy: strict-origin-when-cross-origin`.
- لا يرسل Verdin الترويسة `Strict-Transport-Security`. أضفها عند الوكيل العكسي الذي
  ينهي TLS.

## API المحتوى

- **رموز API** تُعرض مرة واحدة. يخزّن Verdin قيمة HMAC-SHA256 لكل رمز، بمفتاح هو
  `VERDIN_TOKEN_PEPPER`، ويحتفظ ببادئة من 10 أحرف للعرض. يمكن أن تنتهي صلاحية الرموز
  ويمكن إعادة توليدها.
- **صلاحيات الحقول واللغات** تحدّ ما يقرؤه الدور ويكتبه، ولا تصل `populate`
  وعوامل التصفية والترتيب عبر العلاقات إلا إلى الأنواع التي يُسمح للمستدعي بقراءتها.
- **حدود الاستعلام**: `pageSize` حتى `[api].max_page_size` (100)، وعمق `populate` حتى
  5، و100 شرط تصفية على الأكثر، وسلاسل استعلام حتى 16 KB، و1,000
  إدخال مُعبّأ على الأكثر لكل علاقة. الحقول غير المعروفة أو الخاصة في استعلام تعطي `400`.
- **GraphQL** له حدوده الخاصة للعمق والتعقيد (`maxDepth`، `maxComplexity`) و
  مفتاح للاستبطان في إعدادات الميزة.
- **حدود المعدل**: `[api].public_rate_limit` لكل عنوان عميل بدون رمز و
  `[api].token_rate_limit` لكل رمز API أو مستخدم نهائي، بالطلبات في الدقيقة. كلاهما
  معطّل (`0`) افتراضيًا. تُحدّ الطلبات التي تحمل رمز bearer غير معروف لكل عنوان.

### CORS

يسرد `[api].cors_origins` مصادر المتصفح المسموح لها باستدعاء API المحتوى و
GraphQL:

```toml title="verdin.toml"
[api]
cors_origins = ["https://www.example.com", "https://preview.example.com"]
```

كل مدخل بالشكل `scheme://host[:port]` دون مسار أو شرطة مائلة في النهاية؛ و`["*"]` يسمح بأي
مصدر ولا يمكن جمعه مع غيره. الطرق المسموح بها هي `GET` و`POST` و`PUT` و
`DELETE`، وترويسات الطلب المسموح بها `Authorization` و`Content-Type` و
`If-None-Match`. يفشل البدء عند وجود مدخل ليس مصدرًا.

الواجهات الأمامية التي تعمل على الخادم (Astro، وNext.js على الخادم) تستدعي الـ API دون متصفح و
لا تحتاج إلى مدخل CORS.

## الطلبات والملفات المرفوعة

| الإعداد | الافتراضي | يحمي من |
| --- | --- | --- |
| `[server].body_limit` | `"1mb"` | أجسام الطلبات الكبيرة على الواجهات العادية. |
| `[server].request_timeout_secs` | `30` | الطلبات البطيئة التي تحتجز الاتصالات. |
| `[upload].max_file_size` | 200 MB | عمليات الرفع الكبيرة (لعمليات الرفع حدها الخاص بدلًا من `body_limit`). |
| `[upload].max_image_megapixels` | `100` | قنابل فك الضغط. |

يأتي نوع الملف المرفوع من بايتاته، لا من النوع الذي يرسله العميل؛
واسم الملف مجرد احتياط، ولا يُعتمد عليه أبدًا للأنواع التي تشغّلها المتصفحات بشكل نشط (تُخزَّن مثل هذه
الملفات بنوع `application/octet-stream`). يجب أن تكون روابط النص المنسّق `blocks` من نوع `http(s)` أو `mailto:` أو نسبية.

## عناوين العملاء خلف وكيل

تستخدم حدود المعدل وسجلات التدقيق عنوان العميل. خلف وكيل عكسي يأتي كل
طلب من الوكيل، لذا أدرج الوكيل في `[server].trusted_proxies`:

```toml title="verdin.toml"
[server]
trusted_proxies = ["10.0.0.0/8"]   # the proxies' IPs or CIDR ranges
```

عندئذ يقرأ Verdin `X-Forwarded-For` من اليمين إلى اليسار ويأخذ أول عنوان
ليس وكيلًا موثوقًا. تحتفظ الطلبات من أي عنوان آخر بعنوان اتصالها،
فلا يستطيع العميل تزوير عنوانه بإرسال الترويسة بنفسه. لا تدرج نطاقات
يمكن لعملاء غير موثوقين الاتصال منها.

## الطلبات الصادرة

تُجري الـ webhooks وروابط النشر (deploy hooks) وwebhooks تفريغ CDN والرفع من عنوان URL طلبات يختارها
المسؤول. في `verdin start` ترفض عناوين loopback والعناوين الخاصة وlink-local
(بما في ذلك صيغ IPv6 التي تضمّن عناوين IPv4 خاصة)، فلا يستطيع المسؤول استخدامها
للوصول إلى خدمات على شبكتك الداخلية. يرفع `[webhooks].allow_private_networks = true`
هذا القيد؛ افعل ذلك فقط عندما يكون كل مسؤول موثوقًا بالوصول إلى الشبكة الداخلية.

## الأسرار

يُقرأ `VERDIN_ADMIN_JWT_SECRET` و`VERDIN_TOKEN_PEPPER` من البيئة فقط
ويجب أن يكون طول كل منهما 32 بايت على الأقل (يطبع `verdin secrets` قيمًا جديدة). يختم الـ pepper أيضًا
أسرار TOTP الخاصة بالمسؤولين ويشتق المفتاح الذي تُجزّأ به عناوين مرسلي النماذج.
خزّن كليهما في مدير الأسرار لدى منصتك ولا تعتمد `.env` أبدًا.

تُخفي سجلات الطلبات قيم معاملات الاستعلام التي تبدو أسماؤها سرية (`token`،
`code`، `password`، `key`، `signature`…) والجزء السري من عناوين URL لاستدعاءات النشر.

## المقاييس

`/_metrics` معطّل ما لم يكن `[metrics].enabled = true`. عندما يكون مفعّلًا دون تعيين رمز،
يستطيع أي شخص يصل إلى المنفذ قراءته. عيّن `VERDIN_METRICS_TOKEN` (أو
`[metrics].token`) واجمع مع `Authorization: Bearer <token>`، أو احجب المسار عند
الوكيل. راجع [المراقبة](/ar/deploy/monitoring/).

## الإضافات

الإضافات وحدات WebAssembly يشغّلها Extism في بيئة معزولة (sandbox). ليس للوحدة نظام ملفات
أو شبكة أو قاعدة بيانات خاصة بها: كل شيء يمر عبر دوال المضيف المحدودة بـ
القدرات الواردة في `plugin.toml` الخاص بها (أنواع المحتوى التي تقرؤها أو تكتبها، ومضيفو HTTP، ومخزن
المفتاح-القيمة الخاص بها)، مع حد للوقت والذاكرة لكل استدعاء (`[limits]`، 5 ثوانٍ و64 MB في
ملف manifest المثالي). يرى المسؤولون ما تطلبه الإضافة قبل تفعيلها. تعمل سكربتات
الإدارة الخاصة بالإضافات في صفحة اللوحة، لذا لا تثبّت إلا الإضافات التي تثق بها. راجع
[الإضافات](/ar/extending/plugins/).

## عمليات التصدير والنسخ الاحتياطية

تحتوي أرشيفات `verdin export` على حقول خاصة وتجزئات كلمات المرور. خزّنها كما تخزّن
تفريغات قاعدة البيانات. راجع [النسخ الاحتياطية](/ar/deploy/backups/).

## الإبلاغ عن ثغرة

لا تفتح issue عامة لمشكلة أمنية. اتبع
[سياسة الأمان](https://github.com/Verdin-CMS/verdin/blob/main/SECURITY.md) في المستودع: أبلغ عنها
بشكل خاص عبر تبويب **Security** في
[المستودع](https://github.com/Verdin-CMS/verdin/security) (**Report a
vulnerability**)، مع الإصدار، وخطوات إعادة الإنتاج، والأثر الذي تلاحظه.
تُسرد الإصلاحات الأمنية تحت **Security** في [سجل التغييرات](/ar/project/changelog/).
