راجع هذه القائمة قبل أن تضع مشروع Verdin أمام مستخدمين حقيقيين. كل عنصر
يرتبط بالصفحة التي تشرحه. تطبّق صفحات المنصات ([Docker](/ar/deploy/docker/)،
[Fly.io](/ar/deploy/fly/)، [Render](/ar/deploy/render/)، [Railway](/ar/deploy/railway/)،
[Kubernetes](/ar/deploy/kubernetes/)) هذه الإعدادات نيابةً عنك حيثما أمكن.

## شغّل خادم الإنتاج

- [ ] **استخدم `verdin start`، لا `verdin dev`.** يسمح `dev` لمنشئ أنواع المحتوى
      بإعادة كتابة ملفات المخطط، ويطبّق الترحيلات مع كل تغيير، ويخفف قواعد ملفات تعريف الارتباط
      والـ webhooks للعمل المحلي. غيّر المخطط في بيئة التطوير، واعتمد الملفات،
      ثم انشرها.
- [ ] **طبّق الترحيلات وقت النشر.** يرفض `verdin start` العمل ما دامت
      قاعدة البيانات متأخرة عن المخطط. يطبّق `verdin start --migrate` الخطوات *الآمنة*
      المعلّقة أولًا (وهو الأمر الافتراضي لصورة Docker). أما الخطوات المحفوفة بالمخاطر أو المُدمِّرة
      (تغييرات الأنواع، والقيود الفريدة الجديدة، والأعمدة المحذوفة) فتحتاج إلى
      `verdin migrate apply --allow risky|destructive`، تشغّله أنت مرة واحدة. راجع
      [ترحيلات المخطط](/ar/concepts/schema-migrations/).
- [ ] **اشحن المخطط مع الخادم.** ركّب مجلد `schema/` للقراءة فقط، أو
      ضمّنه في صورتك، حتى يكون ما يعمل هو ما اعتمدته.

## الأسرار

- [ ] **ولّد السرّين المطلوبين مرة واحدة** بـ `verdin secrets` واحفظهما في
      مخزن الأسرار لدى منصتك: يوقّع `VERDIN_ADMIN_JWT_SECRET` رموز الجلسات، و
      يُستخدم `VERDIN_TOKEN_PEPPER` مفتاحًا لتجزئات رموز API والأسرار المخزّنة الأخرى.
      يفشل `verdin start` إذا كان أيٌّ منهما مفقودًا أو أقصر من 32 بايت. تُقرأ الأسرار
      من البيئة فقط، ولا تُقرأ أبدًا من `verdin.toml`.
- [ ] **حافظ على ثباتهما.** تغيير `VERDIN_TOKEN_PEPPER` يجعل كل رمز API يتوقف
      عن العمل، وكذلك رموز تطبيقات المصادقة ورموز الاسترداد الخاصة بالمسؤولين. وتغيير
      `VERDIN_ADMIN_JWT_SECRET` يبطل رموز الوصول قصيرة الأمد للمسؤولين والمستخدمين
      النهائيين، وروابط المعاينة المفتوحة، وتسجيلات الدخول عبر OAuth الجارية (تجدّدها لوحة الإدارة
      والعملاء الذين يستخدمون رموز التجديد تلقائيًا). تحتاج كل
      نسخة من المشروع إلى القيم نفسها.
- [ ] ضع الأسرار الأخرى التي تستخدمها في البيئة أيضًا: `VERDIN_EMAIL_SMTP_PASSWORD`
      أو `VERDIN_EMAIL_API_KEY`، و`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`،
      و`VERDIN_METRICS_TOKEN`، و`VERDIN_SSO_<ID>_SECRET`، و`VERDIN_IMAGE_SECRET`. القائمة
      الكاملة موجودة في [مرجع التهيئة](/ar/reference/configuration/).

## قاعدة البيانات

- [ ] **اختر المحرك.** PostgreSQL (الإصدار 14 أو أحدث) هو الخيار المعتاد والذي يجب
      اختياره إن كنت ستشغّل [عدة نسخ](/ar/deploy/scaling/). يعمل MySQL 8.4+ وMariaDB
      10.11+ بالطريقة نفسها. ويناسب SQLite نسخة واحدة مع قرص دائم.
- [ ] **عيّن `VERDIN_DATABASE_URL`**: `postgres://…` أو `mysql://…` (MySQL وMariaDB) أو
      `sqlite:///data/verdin.db`. أضف `?sslmode=require` لخوادم PostgreSQL التي تحتاج
      إلى TLS.
- [ ] **حدّد حجم مجمّع الاتصالات.** تفتح كل نسخة حتى `[database].pool_max` اتصالًا (10).
      أبقِ `instances × pool_max` أقل من حد الاتصالات في الخادم.

## عناوين URL والوكلاء وملفات تعريف الارتباط

- [ ] **قدّم عبر HTTPS.** يتحدث Verdin بـ HTTP العادي؛ أنهِ TLS عند وكيل عكسي،
      أو موازن أحمال، أو حافة منصتك.
- [ ] **عيّن `[server].public_url`** (`VERDIN_SERVER__PUBLIC_URL`) إلى العنوان الذي تستخدمه
      المتصفحات، مثل `https://cms.example.com`. تعتمد عليه الروابط في رسائل البريد، واستدعاءات SSO، والملخص
      اليومي، ومفاتيح المرور؛ فمفاتيح المرور مرتبطة بمضيفه.
- [ ] **عيّن `[server].trusted_proxies`** إلى عناوين وكلائك العكسيين (عناوين IP أو
      نطاقات CIDR). عندها فقط يقرأ Verdin عنوان العميل من
      `X-Forwarded-For`؛ وبدونه، يتشارك كل العملاء خلف الوكيل عنوانًا واحدًا في
      حدود المعدل وسجلات التدقيق.
- [ ] **أبقِ ملفات تعريف الارتباط الآمنة مفعّلة.** في `verdin start` يكون ملف تعريف ارتباط التجديد للإدارة `Secure`
      افتراضيًا. اترك `[admin].secure_cookies` دون تعيين؛ فتعيينه إلى `false` في
      الإنتاج يسجّل تحذيرًا عند البدء.

## الواجهات البرمجية

- [ ] **امنح فقط ما يحتاجه العامة.** يبقى API المحتوى مغلقًا حتى تمنح
      صلاحيات عامة (**الإعدادات ← الوصول العام**) أو تنشئ رموز API. راجع
      [الصلاحيات](/ar/concepts/permissions/).
- [ ] **عيّن `[api].cors_origins`** إذا كان متصفح من مصدر آخر يستدعي API المحتوى
      أو GraphQL، مثلًا `["https://www.example.com"]`. بدونه، لا تستطيع استدعاءهما من متصفح إلا
      الصفحات من المصدر نفسه. لا يجيب API الإدارة أبدًا على الطلبات
      عبر المصادر.
- [ ] **فكّر في حدود المعدل** للحركة المجهولة: `[api].public_rate_limit` و
      `[api].token_rate_limit` (طلبات في الدقيقة؛ `0`، وهو الافتراضي، يعني بلا حد).

## الوسائط

- [ ] **خزّن الملفات المرفوعة حيث تصمد أمام إعادة النشر.** يكتب الموفّر المحلي الافتراضي
      على القرص: امنحه وحدة تخزين دائمة، أو استخدم موفّر S3 (AWS S3 وCloudflare
      R2 وBackblaze B2 وMinIO وTigris…). على المنصات ذات الأقراص المؤقتة، ومع
      عدة نسخ، استخدم S3. راجع [الوسائط](/ar/concepts/media/).

## البريد الإلكتروني

- [ ] **هيّئ موفّرًا حقيقيًا.** الإعداد الافتراضي `[email].provider = "log"` يكتب
      الرسائل في السجل، ويحذّر `verdin start` من ذلك. تحتاج الدعوات، وإعادة تعيين كلمات المرور،
      وتأكيدات المستخدمين النهائيين، والإشارات في التعليقات، والملخص إلى `smtp` أو `resend` أو
      `postmark`، مع تعيين `[email].from` إلى عنوان يقبله موفّرك.

## النسخ الاحتياطية والمراقبة

- [ ] **انسخ قاعدة البيانات وتخزين الوسائط احتياطيًا** وفق جدول، وجرّب الاستعادة.
      راجع [النسخ الاحتياطية](/ar/deploy/backups/).
- [ ] **وجّه فحوص السلامة إلى `/_ready`** وفحوص الحياة إلى `/_health`.
- [ ] **سجّل بصيغة JSON** (`[log].format = "json"`، الافتراضي في صورة Docker) واجمع
      الخطأ القياسي.
- [ ] **اجمع `/_metrics`** إن كنت تستخدم Prometheus، مع `VERDIN_METRICS_TOKEN`. راجع
      [المراقبة](/ar/deploy/monitoring/).

## قبل الإطلاق

- [ ] سجّل المسؤول الأول بنفسك مباشرة بعد التشغيل الأول: إلى أن يوجد مسؤول،
      يستطيع أي شخص يصل إلى `/admin/` التسجيل بصفة Super Admin. يمكنك أيضًا
      إنشاؤه من سطر الأوامر بـ `verdin admin create --email …`.
- [ ] راجع [نموذج الأمان](/ar/deploy/security/) وفعّل
      [المصادقة الثنائية](/ar/guides/auth/two-factor/) لحسابات Super Admin.
