W tym samouczku zbudujesz blog w [Next.js](https://nextjs.org) z App Routerem, który czyta
treść z Verdin: stronę główną z listą artykułów, jedną stronę na artykuł pod
`/articles/<slug>` z jego kategorią i, opcjonalnie, stronę pokazującą szkice z linku podglądu
w panelu. Użyjesz typowanego klienta `@verdin/client` z typami wygenerowanymi ze schematu,
w Server Components.

Napisane dla Next.js 16.3 (`create-next-app` 16.3), React 19.2 i Node.js 20.9 lub nowszego,
z Verdin i `@verdin/client` 0.10. Używa domyślnego cache'owania Next.js, bez
`cacheComponents`. [Samouczek Astro](/pl/start/tutorial-astro/) buduje ten sam blog w Astro.

## Zanim zaczniesz

Potrzebujesz binarki `verdin` w `PATH` (zobacz [Szybki start](/pl/start/quickstart/)),
Node.js i Git. Na końcu będziesz mieć dwa foldery obok siebie: `cms`, projekt Verdin,
i `blog`, aplikację Next.js.

## 1. Skonfiguruj Verdin ze schematem bloga

Projekt [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog)
z repozytorium modeluje blog: artykuły z tytułem, `slug`, zajawką, `body` w Markdown,
kategorią i tagami, a do tego pojedynczy typ homepage i kilka komponentów.

<Steps>

1. Utwórz projekt Verdin i skopiuj do niego przykładowy schemat:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Uruchom go:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   Pierwsze uruchomienie tworzy tabele dla czterech typów zawartości.

3. Otwórz [http://localhost:1337/admin/](http://localhost:1337/admin/) i utwórz pierwszego
   administratora.

4. W sekcji **Kolekcje** otwórz **Category**, wybierz **Nowy wpis**, nazwij go `News`
   i zapisz.

5. Otwórz **Article**, wybierz **Nowy wpis** i wypełnij tytuł, zajawkę i treść w Markdown.
   `slug` jest generowany z tytułu. Wybierz `News` jako kategorię i wybierz **Opublikuj**.
   Dodaj w ten sam sposób drugi artykuł.

6. Otwórz **Ustawienia → Dostęp publiczny**, zezwól na **Wyszukaj** i **Pobierz jeden** dla
   **Article** i **Category** i wybierz **Zapisz**.

</Steps>

Sprawdź, czy API odpowiada:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Wypełnienie relacji wymaga dostępu do odczytu jej celu. Bez **Wyszukaj** na **Category**
`populate=category` odpowiada `400` z ``invalid key `category` in populate``.
</Aside>

## 2. Utwórz aplikację Next.js

W nowym terminalu, obok `cms`:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) zamienia Markdown z pola `body` na HTML.

## 3. Wygeneruj typy

`verdin types` czyta schemat i zapisuje jeden interfejs TypeScript na typ zawartości
i komponent oraz mapę tras `VerdinSchema` dla klienta. Uruchom je z `blog`, wskazując
konfigurację projektu Verdin:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

Plik zawiera między innymi:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

Relacje, multimedia i komponenty są opcjonalne, bo API zwraca je tylko wtedy, gdy je
wypełnisz przez populate. Uruchamiaj polecenie ponownie przy każdej zmianie schematu.

## 4. Połącz się z Verdin

Umieść URL serwera w `.env.local`:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

Bez tokenu klient czyta jako rola publiczna, którą udostępniłeś w kroku 1. Aby zamiast tego
czytać z tokenem, utwórz token **Tylko odczyt** w **Ustawienia → Tokeny API** i ustaw
`VERDIN_TOKEN`. Obie zmienne zostają na serwerze: nie mają prefiksu `NEXT_PUBLIC_`, a klient
działa tylko w Server Components.

Utwórz klienta raz i go współdziel:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

`verdin.collection('articles')` akceptuje teraz tylko trasy twojego schematu, a jego wyniki
są typowane jako `Article`.

## 5. Zastąp layout

Zastąp layout startowy i usuń `src/app/page.module.css`, którego nowe strony nie używają:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import Link from 'next/link';

export const metadata: Metadata = {
  title: 'My blog',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. Wylistuj artykuły

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

Zapytanie to wywołanie REST
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`,
w formacie Strapi v5. `fields` utrzymuje małą odpowiedź, a `populate` dodaje kategorię tylko
z jej nazwą. Rola publiczna czyta tylko opublikowane artykuły.

`revalidate = 60` prerenderuje stronę w czasie buildu, a potem odświeża ją najwyżej raz na
minutę, więc opublikowane zmiany pojawiają się bez przebudowy.

## 7. Dodaj stronę dla każdego artykułu

Strona artykułu znajduje swój artykuł po slugu filtrem. `generateStaticParams` prerenderuje
istniejące artykuły; artykuły opublikowane później renderują się przy pierwszej wizycie.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

W Next.js 16 `params` to obietnica: poczekaj na nią (`await`), zanim odczytasz slug. Nieznany
slug nie znajduje artykułu i odpowiada 404 przez `notFound()`. `pageSize` jest ograniczone
przez `[api].max_page_size` (domyślnie 100).

<Aside type="caution">
`marked` nie sanityzuje HTML. To w porządku dla Markdown pisanego przez twoich redaktorów;
jeśli treść może pochodzić od niezaufanych osób, sanityzuj HTML przed renderowaniem.
</Aside>

## 8. Uruchom

```sh title="Terminal"
npm run dev
```

Otwórz [http://localhost:3000](http://localhost:3000): lista pokazuje opublikowane artykuły,
a każdy prowadzi do swojej strony. `npm run build` wymaga działającego Verdin, bo pobiera
artykuły, aby je prerenderować.

Aby odświeżać strony od razu po zmianie treści, a nie w ciągu minuty, wywołuj
`revalidatePath` z route handlera wyzwalanego przez webhook Verdin; zobacz
[Webhooki](/pl/guides/integrations/webhooks/).

Twój projekt wygląda teraz tak:

        - [slug]/
          - page.tsx
</FileTree>

## 9. Opcjonalnie: podgląd szkiców

Panel może otworzyć szkic w twojej witrynie z krótkotrwałym tokenem podglądu. Token czyta ten
jeden dokument, łącznie ze szkicami, i nic więcej.

Dodaj klienta, który wysyła token podglądu w nagłówku `x-verdin-preview`:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Potem strona. Czyta `searchParams`, więc Next.js renderuje ją przy każdym żądaniu; token
przychodzi jako parametr zapytania `preview`:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Token podglądu nie może listować wpisów, więc strona wyszukuje szkic po `documentId`, a nie
po slugu. Teraz powiedz Verdin, gdzie jest strona:

<Steps>

1. W panelu otwórz **Ustawienia → Funkcje**, włącz **Podgląd** i wybierz **Skonfiguruj
   adresy URL podglądu**.
2. Ustaw szablon URL dla **Article** na `http://localhost:3000/preview/{documentId}`
   i zapisz. Verdin dopisuje token jako `?preview=…`.
3. Otwórz artykuł, zmień go i wybierz **Zapisz szkic**, a potem **Otwórz podgląd**.

</Steps>

Strona pokazuje szkic. Linki są domyślnie ważne 60 minut. Symbole zastępcze i ustawienia
opisuje [Podgląd](/pl/guides/content/preview/), a edycję z podglądu
[Edycja wizualna](/pl/guides/frontend/visual-editing/).
