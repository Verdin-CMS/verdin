תוספים מוסיפים התנהגות ל-Verdin בלי לשנות או לבנות מחדש את השרת. תוסף הוא מודול
WebAssembly עם מניפסט, שמונח בתיקייה `plugins/` של הפרויקט. העמוד הזה מסביר מה תוספים יכולים
לעשות ואיך מתקינים אחד; כדי לכתוב אחד, עקבו אחרי [מדריך התוספים](/he/extending/plugin-tutorial/),
וחפשו את הפרטים ב[תיעוד התוספים](/he/extending/plugin-reference/).

## מה תוסף יכול לעשות

| נקודת הרחבה | למה היא משמשת |
| --- | --- |
| **Hooks על כתיבות** | לפני שרשומה נוצרת, מתעדכנת, מתפרסמת, פרסומה מבוטל, נמחקת או שהטיוטה שלה נמחקת, לשנות את הנתונים או לדחות את הכתיבה עם הודעה. אחרי הכתיבה, להגיב לה (רישום ביומן, התראה, סנכרון). |
| **נתיבים** | להגיש נקודות קצה של HTTP תחת `/api/plugins/<name>/…`: מקלט webhooks, פיד מחושב, proxy לשירות אחר. |
| **משימות מתוזמנות** | להריץ פונקציה לפי לוח זמנים של cron (UTC). |
| **פונקציית הפעלה** | להריץ פונקציה כשהתוסף עולה, מופעל או כשההגדרות שלו משתנות: זריעה, הגדרת התפקיד הציבורי (ה-`bootstrap` של Strapi). |
| **שדות GraphQL** | להוסיף שדות `name(args: JSON): JSON` ל-`Query` או ל-`Mutation`. |
| **ווידג'טים ללוח הבקרה** | להוסיף סוגי ווידג'טים ללוח הבקרה של פאנל הניהול, כ-Web Components. |
| **שדות מותאמים אישית** | לתת למאפיינים עורך מותאם בפאנל הניהול (בורר צבעים, מפה), כ-Web Components; הערך נשמר כטיפוס מאפיין רגיל. |
| **הגדרות** | להצהיר על טופס הגדרות שמנהלים ממלאים ב-**הגדרות ← תוספים**. |

תוסף קורא וכותב תוכן דרך אותו Document Service כמו פאנל הניהול וה-API, כך ש-webhooks,
היסטוריה, שלבי בקרה ואימות חלים על הכתיבות שלו.

<Aside type="note">
תוספי Verdin אינם תוספי Strapi. תוספי Strapi הם חבילות Node.js עם גישה מלאה לשרת; Verdin לא
מריץ JavaScript בשרת. שדות מותאמים שמוצהרים בסכמות של Strapi (מאפייני `customField`) נטענים
כמו שהם, ותוסף Verdin יכול לספק את העורך שלהם.
</Aside>

## ה-sandbox

תוספים רצים ב-sandbox של WebAssembly ([Extism](https://extism.org), על Wasmtime). למודול אין
קבצים, אין sockets ואין חיבור משלו למסד נתונים. כל מה שהוא עושה מחוץ לזיכרון שלו עובר דרך
כמה פונקציות מארח, והשרת בודק כל קריאה מול ה**יכולות** שהמניפסט מצהיר עליהן:

| יכולת | מעניקה |
| --- | --- |
| `read` | קריאת רשומות של סוגי התוכן שצוינו (או `*`). |
| `write` | יצירה, עדכון, פרסום, ביטול פרסום ומחיקה של רשומות מהסוגים שצוינו (וגם קריאתן). |
| `http` | בקשות HTTP למארחים שצוינו (`api.example.com`, `*.example.com`). |
| `kv` | מאגר key-value משלו, במסד הנתונים של Verdin. |
| `public_permissions` | קריאה והחלפה של הרשאות ה-API של התפקיד הציבורי. |

לכל קריאה יש גם מגבלות: מגבלת זמן (5 שניות כברירת מחדל) ומגבלת זיכרון (64 MB כברירת מחדל),
שמוגדרות במניפסט. מודול שמבצע trap או שנגמר לו הזמן מכשיל רק את הקריאה הזו; Verdin בונה
אותו מחדש בקריאה הבאה.

מה ה-sandbox לא מחליט בשבילכם:

- **נתיבים הם ציבוריים.** בקשות ל-`/api/plugins/<name>/…` לא נבדקות מול **גישה ציבורית** או
  מול הרשאות של אסימוני API. התוסף מקבל את זהות הקורא (כל אחד, אסימון API או משתמש קצה)
  וחייב לבדוק אותה.
- **Hooks רואים את כל הכתיבות לסוגים שלהם**, בלי קשר ליכולת ה-`read` של התוסף.
- **before hook שנכשל לא חוסם את הכתיבה.** אם המודול קורס או חורג מהזמן, השגיאה נרשמת ביומן
  והכתיבה ממשיכה. רק דחייה מפורשת עוצרת אותה.

## התקנת תוסף

<Steps>

1. שימו את התוסף בתיקייה משלו תחת `plugins/`, ליד `verdin.toml`. היא מחזיקה את המניפסט, את
   המודול ובאופן אופציונלי את קובצי פאנל הניהול:

   <FileTree>
   - verdin.toml
   - plugins/
     - reading-time/
       - plugin.toml
       - plugin.wasm
       - admin/ אופציונלי: Web Components לפאנל הניהול
         - index.js
   - schema/
   </FileTree>

2. הפעילו מחדש את Verdin. הוא טוען כל `plugins/*/plugin.toml` בהפעלה ורושם `plugin found`
   לכל אחד. תוסף שנכשל בטעינה (מניפסט לא תקין, מודול חסר, שם כפול) מופיע ב-**הגדרות ←
   תוספים** עם הסיבה.

3. בפאנל הניהול, פתחו את **הגדרות ← תוספים**. עברו על מה שהתוסף מבקש תחת **גישה**,
   **Hooks**, **נתיבים** ו**משימות**, ואז הפעילו אותו.

4. אם לתוסף יש הגדרות, פתחו את **הגדרות** בכרטיס שלו, מלאו אותן ושמרו.

</Steps>

תוספים מותקנים מתחילים כבויים. הפעלה של תוסף ועריכת ההגדרות שלו חלות מיד, בכל המופעים
(מופעים אחרים קולטים את השינוי בתוך `[server].sync_interval_secs`). שינויים ב-`plugin.toml` או
במודול דורשים הפעלה מחדש.

ניהול תוספים דורש את ההרשאה `plugins.manage` (**ניהול תוספים**). ראו את
[תיעוד ההרשאות](/he/reference/permissions/).

## הגדרת `[plugins]`

```toml title="verdin.toml"
[plugins]
path = "plugins"   # directory of plugins, relative to verdin.toml
run_jobs = true    # run scheduled jobs on this instance
```

עם כמה מופעים, הגדירו `run_jobs = false` בכולם חוץ מאחד, כדי שכל משימה תרוץ פעם אחת. ראו את
[תיעוד התצורה](/he/reference/configuration/).

## תפעול

- **קריאה אחת בכל פעם.** לכל תוסף יש מופע אחד והוא מטפל בקריאה אחת בכל פעם, כך שנתיב איטי
  מעכב את ה-hooks של אותו תוסף. שמרו על פונקציות קצרות.
- **יומנים.** מה שתוסף רושם ביומן הולך ליומן השרת ול-**הגדרות ← תוספים ← יומנים** (200
  השורות האחרונות, שנשמרות בזיכרון).
- **פריסות.** שלחו את התוספים עם הפרויקט (באימג' או ב-volume), כמו את הסכמה. המתגים וההגדרות
  נמצאים במסד הנתונים.
