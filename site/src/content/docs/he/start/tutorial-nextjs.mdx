במדריך הזה תבנו בלוג עם [Next.js](https://nextjs.org) וה-App Router שקורא את התוכן שלו
מ-Verdin: דף בית שמציג מאמרים, דף אחד לכל מאמר ב-`/articles/<slug>` עם הקטגוריה שלו, ובאופן
אופציונלי דף שמציג טיוטות מקישור התצוגה המקדימה של פאנל הניהול. תשתמשו בלקוח עם הטיפוסים
`@verdin/client` עם טיפוסים שנוצרו מהסכמה, ב-Server Components.

נכתב עבור Next.js 16.3 (`create-next-app` 16.3), React 19.2 ו-Node.js 20.9 ומעלה, עם Verdin
ו-`@verdin/client` 0.10. הוא משתמש ב-caching של ברירת המחדל של Next.js, בלי `cacheComponents`.
[המדריך של Astro](/he/start/tutorial-astro/) בונה את אותו בלוג עם Astro.

## לפני שמתחילים

צריך את הקובץ הבינארי `verdin` ב-`PATH` שלכם (ראו את [ההתחלה המהירה](/he/start/quickstart/)),
Node.js ו-Git. בסוף יהיו לכם שתי תיקיות זו לצד זו: `cms`, פרויקט ה-Verdin, ו-`blog`, אפליקציית
ה-Next.js.

## 1. הגדרת Verdin עם סכמת הבלוג

הפרויקט [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) של
המאגר ממדל בלוג: מאמרים עם כותרת, `slug`, תקציר, `body` ב-Markdown, קטגוריה ותגיות, ועוד סוג
יחיד של דף בית וכמה רכיבים.

<Steps>

1. צרו פרויקט Verdin והעתיקו לתוכו את סכמת הדוגמה:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. הפעילו אותו:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   ההפעלה הראשונה יוצרת את הטבלאות לארבעת סוגי התוכן.

3. פתחו את [http://localhost:1337/admin/](http://localhost:1337/admin/) וצרו את המנהל הראשון.

4. תחת **אוספים**, פתחו את **Category**, בחרו **רשומה חדשה**, תנו לה את השם `News` ושמרו.

5. פתחו את **Article**, בחרו **רשומה חדשה**, ומלאו כותרת, תקציר וגוף ב-Markdown. ה-`slug`
   נוצר מהכותרת. בחרו `News` כקטגוריה ובחרו **פרסום**. הוסיפו מאמר שני באותה דרך.

6. פתחו את **הגדרות ← גישה ציבורית**, אפשרו **חיפוש** ו**חיפוש פריט אחד** עבור **Article**
   ו-**Category**, ובחרו **שמירה**.

</Steps>

בדקו שה-API עונה:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
populate של קשר דורש הרשאת קריאה ליעד שלו. בלי **חיפוש** על **Category**, `populate=category`
עונה `400` עם ``invalid key `category` in populate``.
</Aside>

## 2. יצירת אפליקציית ה-Next.js

בטרמינל חדש, ליד `cms`:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org) הופך את ה-Markdown של השדה `body` ל-HTML.

## 3. יצירת הטיפוסים

`verdin types` קורא את הסכמה וכותב ממשק TypeScript אחד לכל סוג תוכן ורכיב, ומפת נתיבים
`VerdinSchema` עבור הלקוח. הריצו אותו מ-`blog`, כשהוא מצביע לתצורה של פרויקט ה-Verdin:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

הקובץ מכיל, בין השאר:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

קשרים, מדיה ורכיבים הם אופציונליים כי ה-API מחזיר אותם רק כשמבצעים להם populate. הריצו שוב
את הפקודה בכל פעם שהסכמה משתנה.

## 4. חיבור ל-Verdin

שימו את כתובת השרת ב-`.env.local`:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

בלי אסימון הלקוח קורא כתפקיד הציבורי, וזה מה שפתחתם בשלב 1. כדי לקרוא עם אסימון במקום זאת,
צרו אסימון **קריאה בלבד** ב-**הגדרות ← אסימוני API** והגדירו את `VERDIN_TOKEN`. שני המשתנים
נשארים בשרת: אין להם קידומת `NEXT_PUBLIC_`, והלקוח רץ רק ב-Server Components.

צרו את הלקוח פעם אחת ושתפו אותו:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

עכשיו `verdin.collection('articles')` מקבל רק את הנתיבים של הסכמה שלכם, והתוצאות שלו מקבלות
את הטיפוס `Article`.

## 5. החלפת ה-layout

החליפו את ה-layout ההתחלתי, ומחקו את `src/app/page.module.css`, שהדפים החדשים לא משתמשים בו:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';

```

## 6. הצגת רשימת המאמרים

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

השאילתה היא קריאת ה-REST
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`,
בפורמט של Strapi v5. `fields` שומר על תגובה קטנה, ו-`populate` מוסיף את הקטגוריה עם השם שלה
בלבד. התפקיד הציבורי קורא רק מאמרים מפורסמים.

`revalidate = 60` מרנדר את הדף מראש בזמן הבנייה ומרענן אותו לכל היותר פעם בדקה אחר כך, כך
ששינויים שפורסמו מופיעים בלי בנייה מחדש.

## 7. הוספת דף לכל מאמר

דף המאמר מוצא את המאמר שלו לפי slug עם מסנן. `generateStaticParams` מרנדר מראש את המאמרים
הקיימים; מאמרים שמתפרסמים מאוחר יותר מתרנדרים בביקור הראשון שלהם.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

ב-Next.js 16, `params` הוא promise: המתינו לו לפני שאתם קוראים את ה-slug. slug לא מוכר לא מוצא
אף מאמר ועונה 404 דרך `notFound()`. `pageSize` מוגבל על ידי `[api].max_page_size` (100 כברירת
מחדל).

<Aside type="caution">
`marked` לא מנקה (sanitize) HTML. זה בסדר עבור Markdown שהעורכים שלכם כותבים; אם התוכן יכול
להגיע מאנשים לא מהימנים, נקו את ה-HTML לפני שאתם מציגים אותו.
</Aside>

## 8. הרצה

```sh title="Terminal"
npm run dev
```

פתחו את [http://localhost:3000](http://localhost:3000): הרשימה מציגה את המאמרים המפורסמים שלכם,
וכל אחד מקשר לדף שלו. `npm run build` צריך ש-Verdin ירוץ, כי הוא שולף את המאמרים כדי לרנדר
אותם מראש.

כדי לרענן דפים ברגע שהתוכן משתנה במקום בתוך דקה, קראו ל-`revalidatePath` מ-route handler
ש-webhook של Verdin מפעיל; ראו [Webhooks](/he/guides/integrations/webhooks/).

עכשיו הפרויקט שלכם נראה כך:

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts נוצר על ידי `verdin types`
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. אופציונלי: תצוגה מקדימה של טיוטות

פאנל הניהול יכול לפתוח טיוטה באתר שלכם עם אסימון תצוגה מקדימה קצר מועד. האסימון קורא את
המסמך הזה בלבד, כולל טיוטות, ושום דבר אחר.

הוסיפו לקוח ששולח את אסימון התצוגה המקדימה בכותרת `x-verdin-preview`:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

אחר כך הדף. הוא קורא את `searchParams`, ולכן Next.js מרנדר אותו בכל בקשה; האסימון מגיע
כפרמטר השאילתה `preview`:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

אסימון תצוגה מקדימה לא יכול להציג רשימות של רשומות, ולכן הדף מחפש את הטיוטה לפי `documentId`
ולא לפי slug. עכשיו אמרו ל-Verdin היכן הדף נמצא:

<Steps>

1. בפאנל הניהול, פתחו את **הגדרות ← תכונות**, הפעילו את **תצוגה מקדימה** ובחרו **הגדרת
   כתובות תצוגה מקדימה**.
2. הגדירו את תבנית ה-URL של **Article** ל-`http://localhost:3000/preview/{documentId}` ושמרו.
   Verdin מוסיף את האסימון כ-`?preview=…`.
3. פתחו מאמר, שנו אותו ובחרו **שמירת טיוטה**, ואז בחרו **פתיחת תצוגה מקדימה**.

</Steps>

הדף מציג את הטיוטה. הקישורים תקפים 60 דקות כברירת מחדל. ראו
[תצוגה מקדימה](/he/guides/content/preview/) לממלאי המקום ולהגדרות, ו
[עריכה חזותית](/he/guides/frontend/visual-editing/) כדי לערוך מתוך התצוגה המקדימה.
