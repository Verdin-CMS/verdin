Verdin הוא CMS headless בקוד פתוח שנכתב ב-Rust. אתם ממדלים סוגי תוכן, העורכים שלכם כותבים
ומפרסמים בפאנל ניהול, והאתרים והאפליקציות שלכם קוראים את התוכן דרך REST או GraphQL API.
Verdin לא מרנדר דפים: הפרונטאנד שלכם עושה זאת.

זו כתיבה מחדש של [Strapi v5](https://strapi.io): לפורמט הסכמה ול-API התוכן יש אותו מבנה, כך
שפרויקט Strapi והפרונטאנד שלו יכולים לעבור עם מעט שינויים.

## למי זה מיועד

- **מפתחים שבונים אתר או אפליקציה** שרוצים CMS שאפשר להריץ כתהליך אחד, לשמור את מודל התוכן
  ב-git, ולקרוא ממנו מכל פרונטאנד: Astro, Next.js, אפליקציית מובייל.
- **צוותים על Strapi** שרוצים את אותו API עם טביעת רגל קטנה יותר, או צריכים תכונות ש-Strapi
  שומר לתוכניות בתשלום. ל-Verdin אין מהדורת Enterprise: SSO, יומני ביקורת, תהליכי בקרה
  ומהדורות הם חלק מפרויקט הקוד הפתוח.
- **עורכים**, שמקבלים טיוטות, פרסום, היסטוריה ותצוגות מקדימות בפאנל ניהול שזמין ב-18 שפות.

## מה בקופסה

קובץ הרצה אחד, `verdin`, הוא השרת, כלי שורת הפקודה ופאנל הניהול. אין runtime של Node.js
ואין `node_modules` בייצור.

| תחום | מה מקבלים |
| --- | --- |
| מסדי נתונים | PostgreSQL 14+, MySQL 8.4+, MariaDB 10.11+ ו-SQLite, שמכוסים על ידי אותה חבילת בדיקות. |
| מודל תוכן | סוגי אוסף, סוגים יחידים, רכיבים, אזורים דינמיים, קשרים, מדיה, טקסט עשיר ב-Markdown או בפורמט ה-blocks של Strapi. הסכמה היא קובצי JSON בפרויקט שלכם. |
| שינויי סכמה | כל שינוי הופך לתוכנית הגירה עם רמת סיכון וה-SQL המדויק. שלבים הרסניים רצים רק כשאתם מתירים אותם. |
| APIs | REST תחת `/api` עם הפרמטרים של Strapi v5 (`filters`, `populate`, `sort`, `pagination`), נקודת קצה אופציונלית של GraphQL, מסמך OpenAPI, ולקוח TypeScript עם טיפוסים. |
| עריכה | טיוטה ופרסום, תוכן מתורגם, היסטוריית תוכן, מהדורות, תהליכי בקרה, תגובות ומשימות, נוכחות חיה, תצוגה מקדימה ועריכה חזותית באתר שלכם. |
| גישה | תפקידי ניהול עד רמת השדות והשפות, אסימוני API, הרשאות גישה ציבורית, SSO עם OpenID Connect, התחברות דו-שלבית עם מפתחות גישה, יומני ביקורת. |
| תכונות אתר | חיפוש טקסט מלא, מפת אתר, הפניות, תפריטים וטפסים, webhooks, עדכונים בזמן אמת. |
| הרחבה | תוספי WebAssembly שמתחברים לכתיבות, מוסיפים נתיבים ומשימות, ומביאים ווידג'טים לפאנל הניהול ושדות מותאמים, מוגבלים ליכולות שהם מצהירים עליהן. |

## הקשר ל-Strapi v5

**אותו דבר:**

- קובצי הסכמה משתמשים בפורמט של Strapi: `schema/content-types/<singularName>.json`
  ו-`schema/components/<category>/<name>.json`.
- ה-REST API של התוכן: נתיבים, פורמט התגובה השטוח עם `documentId`, פרמטרי שאילתה ואופרטורים,
  סמנטיקת הכתיבה (`POST` או `PUT` מפרסמים אלא אם מעבירים `?status=draft`), גופי שגיאות.
- סכמת ה-GraphQL בנויה כמו תוסף ה-GraphQL של Strapi v5.
- משתמשי קצה (הרשמה, התחברות, OAuth, תפקידים) עוקבים אחרי ה-API של `users-permissions`.

**שונה:**

- **שינויי סכמה הם הגירות מתוכננות.** Verdin משווה את קובצי הסכמה למסד הנתונים ומראה לכם את
  השלבים לפני שהוא מריץ אותם. `verdin start` מסרב לרוץ כשמסד הנתונים מפגר אחרי הסכמה.
- **בונה סוגי התוכן רץ רק במצב פיתוח.** בייצור הסכמה מגיעה מהמאגר שלכם.
- **התוספים הם WebAssembly, לא JavaScript.** תוספי Strapi, ו-controllers, services או קובצי
  lifecycle מותאמים ב-`src/`, לא רצים ב-Verdin.
- **מסד הנתונים לא משותף עם Strapi.** מביאים פרויקט Strapi עם `verdin import strapi`, שנותן
  לכל מסמך מזהה חדש.
- **כמה תוספות מעבר ל-REST**: פעולות פרסום וביטול פרסום
  (`POST /api/<route>/<documentId>/actions/publish`), ורכיב שעבר populate חוזר בשלמותו, כולל
  רכיבים מקוננים.

[תאימות ל-Strapi](/he/migrate/compatibility/) מפרט את ההבדלים בפירוט.

## מתי לא להשתמש בו

- **אתם תלויים בתוספי Strapi או בקוד שרת מותאם ב-JavaScript.** Verdin לא יכול להריץ אותם;
  תצטרכו לכתוב אותם מחדש כתוספי WebAssembly או להעביר את הלוגיקה למקום אחר.
- **אתם צריכים 1.0 יציבה.** Verdin נמצא ב-0.10: גרסאות משניות עדיין יכולות לשנות תצורה
  והתנהגות. קראו את [שדרוג](/he/migrate/upgrading/) לפני כל אחת.
- **אתם רוצים שה-CMS ירנדר את הדפים שלכם.** Verdin הוא headless; שלבו אותו עם framework
  לפרונטאנד או עם מחולל אתרים סטטיים.
- **אתם רוצים שירות מנוהל.** Verdin מתארח עצמאית: אתם מריצים את הקובץ הבינארי או את האימג' של
  Docker בתשתית שלכם.
