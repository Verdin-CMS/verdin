בינאום (i18n) שומר את התוכן של מסמך בכמה שפות. העמוד הזה מסביר את המודל: שפות (locales),
שדות מתורגמים ומשותפים, ואיך קריאות וכתיבות בוחרות שפה. לתהליך העבודה של העורך, ראו
[תרגום תוכן](/he/guides/content/localizing-content/).

## שפות

השפות של הפרויקט מפורטות ב-**הגדרות ← בינאום** (הרשאה `locales.manage`). בהפעלה הראשונה
נוספת אנגלית (`en`) כשפת ברירת המחדל.

- שפה אחת היא תמיד ברירת המחדל. בקשות שלא מציינות שפה משתמשות בה, ואי אפשר למחוק אותה.
- הקודים הם שפה של שתיים או שלוש אותיות קטנות, ואחריה אופציונלית תגיות משנה:
  `en`, `fr`, `pt-BR`, `zh-Hans`.

:::caution
מחיקת שפה מוחקת גם כל גרסה שנכתבה בה.
:::

## סוגי תוכן מתורגמים

סוג תוכן מתורגם כשהסכמה שלו אומרת זאת. אז לכל מסמך יש גרסה אחת לכל שפה, וכולן חולקות את
ה-`documentId`:

```json title="schema/content-types/article.json (excerpt)"
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "options": { "draftAndPublish": true },
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

עם [טיוטה ופרסום](/he/concepts/draft-and-publish/), לכל שפה יש טיוטה וגרסה מפורסמת משלה,
כך שתרגום לצרפתית יכול להתפרסם לפני הטקסט באנגלית או אחריו. סוגים בלי
`pluginOptions.i18n.localized` אינם מתורגמים ומתעלמים מפרמטרי `locale`.

## מה מתורגם

בסוג מתורגם, כל מאפיין מתורגם אלא אם הוא אומר
`"pluginOptions": { "i18n": { "localized": false } }`. לשדה **משותף** כזה יש ערך אחד לכל
המסמך:

- שמירת שדה משותף בשפה אחת כותבת אותו לטיוטות של כל השפות.
- פרסום של שפה מעתיק את השדות המשותפים שלה לגרסאות המפורסמות של השפות האחרות.
- זה חל גם על קשרים ומדיה: קשר משותף מקשר לאותם מסמכים בכל שפה.

שדות מערכת עוקבים אחרי הגרסה: לכל שפה יש `createdAt`, `updatedAt` ו-`publishedAt` משלה.
ערכי `unique` ו-`uid` ייחודיים לכל שפה, כך ששני תרגומים יכולים לחלוק slug.

## קשרים בין סוגים מתורגמים

קשרים מקשרים מסמכים, לא גרסאות (ראו
[קשרים](/he/concepts/relations/#מקושר-לפי-מסמך-לא-לפי-שורה)), ולכן השפה נבחרת בזמן
הקריאה:

- כששני הסוגים מתורגמים, המאמר בצרפתית מציג את הגרסה הצרפתית של הקטגוריה שלו. מסננים דרך
  הקשר מתאימים באותה שפה.
- כשסוג היעד אינו מתורגם, כל השפות רואות את אותו יעד.

## בחירת שפה ב-APIs

REST ו-API הניהול מקבלים את `locale` כפרמטר שאילתה, בפורמט של Strapi v5; GraphQL מקבל
ארגומנט `locale`:

```http
GET /api/articles?locale=fr
PUT /api/articles/{documentId}?locale=fr
DELETE /api/articles/{documentId}?locale=fr
```

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
  }
}
```

- בלי `locale`, הבקשות קוראות וכותבות את שפת ברירת המחדל.
- `PUT` בשפה שעדיין אין למסמך יוצר את הגרסה הזו.
- `DELETE` מסיר רק את הגרסה בשפה המבוקשת. קישורים שמצביעים על המסמך מוסרים כשלא נשארת אף
  שפה.
- תגובות REST של סוגים מתורגמים כוללות `locale`. שפה לא מוכרת היא שגיאת `400`.
- payloads של webhooks, אירועי זמן אמת והיסטוריית התוכן רושמים את השפה של הגרסה שהשתנתה.

## הרשאות לפי שפה

תפקידי ניהול יכולים להגביל הרשאות תוכן לחלק מהשפות, כך שעורך צרפתית יוכל לקרוא או לשנות
רק גרסאות בצרפתית. ראו [הרשאות](/he/concepts/permissions/#הרשאות-שדה-ושפה).
ההרשאות של API התוכן (גישה ציבורית, אסימוני API, תפקידי משתמשי קצה) חלות על כל השפות.

## בהשוואה ל-Strapi

המודל והפרמטרים תואמים ל-i18n של Strapi v5: סוגים מתורגמים, שדות `localized: false`,
`?locale=` ושפת ברירת המחדל. ב-Verdin, i18n הוא חלק מהליבה ותמיד פעיל: מפעילים אותו לכל
סוג תוכן בסכמה.
