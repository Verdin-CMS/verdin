רכיבים מאפשרים לעשות שימוש חוזר בקבוצת שדות בכמה סוגי תוכן, ואזורים דינמיים מאפשרים
לעורכים לבנות דף מרשימה של בלוקים. העמוד הזה מסביר איך שניהם ממודלים ונשמרים, ואיך זה
משפיע על הקריאה, הכתיבה והסינון שלהם. פורמט הסכמה עצמו נמצא ב[מודל התוכן](/he/concepts/content-model/).

## רכיבים

רכיב הוא קבוצת שדות עם קובץ משלה תחת `schema/components/<category>/`. הרכיב
`shared.seo` של דוגמת הבלוג מחזיק כותרת ותיאור meta:

```json title="schema/components/shared/seo.json"
{
  "displayName": "SEO",
  "attributes": {
    "metaTitle": { "type": "string", "maxLength": 60 },
    "metaDescription": { "type": "text", "maxLength": 160 }
  }
}
```

סוג תוכן משתמש בו דרך מאפיין `component`. `repeatable: true` הופך אותו לרשימה, עם גבול
אופציונלי של `min` ו-`max` פריטים:

```json
"seo": { "type": "component", "component": "shared.seo" },
"links": { "type": "component", "component": "shared.link", "repeatable": true, "max": 10 }
```

רכיבים יכולים להכיל רכיבים אחרים. רכיב לא יכול להכיל את עצמו, ישירות או דרך אחרים;
בדיקת הסכמה דוחה מעגלים כאלה.

## אזורים דינמיים

אזור דינמי הוא רשימה שהפריטים שלה יכולים להיות כל אחד מהרכיבים שהוא מציין. גוף המאמר
בבלוג משלב heroes וציטוטים:

```json
"blocks": { "type": "dynamiczone", "components": ["blocks.hero", "blocks.quote"], "max": 20 }
```

כל פריט מציין ב-`__component` איזה רכיב הוא. `min` ו-`max` מגבילים את מספר הפריטים.
אזורים דינמיים שייכים לסוגי תוכן בלבד: רכיב לא יכול להכיל אזור דינמי.

## נשמרים כ-JSON

Verdin שומר ערך של רכיב או של אזור דינמי בעמודת JSON אחת בשורה של המסמך
(`jsonb` ב-PostgreSQL, `json` ב-MySQL וב-MariaDB, טקסט ב-SQLite):

```json
// the "seo" column
{ "id": 1, "metaTitle": "Rust for CMS authors", "metaDescription": "…" }

// the "blocks" column
[
  { "__component": "blocks.hero", "id": 1, "title": "Hello", "subtitle": "…" },
  { "__component": "blocks.quote", "id": 2, "text": "…", "author": "Ferris" }
]
```

Strapi שומר כל רכיב בטבלה משלו, שמצורפת דרך טבלאות קישור פולימורפיות. שמירת הערך עם
המסמך במקום זאת אומרת:

- קריאת מסמך עם הרכיבים שלו לא דורשת joins, לא משנה כמה עמוק הם מקוננים.
- פרסום, מחיקת טיוטה ו[היסטוריית תוכן](/he/guides/content/content-history/) מעתיקים את
  הערך כמו שהוא.
- הוספת שדה לרכיב לא משנה אף טבלה: ההגירה ריקה.
- סינון לפי שדות של רכיבים משתמש בפונקציות ה-JSON של כל מסד נתונים, וחלק מהמסננים אינם
  זמינים (ראו [סינון](#סינון)).

כל פריט נושא `id`, מספר שלם חיובי שייחודי בתוך הערך של המאפיין. Verdin מקצה מזהה לפריטים
חדשים; שלחו את ה-`id` בחזרה כשאתם מעדכנים רשימה כדי שהפריטים יישארו יציבים.

## קשרים ומדיה בתוך רכיבים

רכיב יכול להחזיק קשרים ומדיה, שנשמרים ב-JSON עצמו: ערכי `documentId` לקשרים ומזהי קבצים
למדיה.

- קשרים בתוך רכיבים חייבים להיות `oneWay` או `manyWay`: הם מצביעים על היעדים שלהם ואין להם
  צד הפוך. ראו [קשרים](/he/concepts/relations/#קשרים-בתוך-רכיבים).
- כל הפניה נבדקת בכתיבה: מסמך היעד או הקובץ חייבים להתקיים, והקבצים חייבים להתאים ל-
  `allowedTypes` של השדה.
- כשהרכיב עובר populate, ההפניות נפתרות בשאילתות מקובצות, באותו סטטוס ובאותה שפה כמו
  המסמך. יעד שנמחק, או שאין לו גרסה במה שנקרא, מושמט.
- קשרים פולימורפיים (`morphToOne`, `morphToMany`) ושדות `password` לא יכולים להיות בתוך
  רכיבים.

## קריאה

רכיבים ואזורים דינמיים מוחזרים רק כשמבצעים להם populate, כמו ב-Strapi:

```http
GET /api/articles?populate[0]=seo&populate[1]=blocks
GET /api/articles?populate=*
```

רכיב שעבר populate חוזר בשלמותו, כולל רכיבים מקוננים וקשרים ומדיה שנפתרו. Strapi צריך רמת
`populate` לכל רכיב מקונן; Verdin מקבל את האפשרויות המקוננות האלה לשם תאימות ומתעלם מהן.
פריטי אזור דינמי חוזרים בסדר שבו נשמרו, כל אחד עם ה-`__component` שלו.

ב-GraphQL, רכיב הוא טיפוס אובייקט שנקרא על שם ה-UID שלו (`ComponentSharedSeo`) ואזור דינמי
הוא union (`ArticleBlocksDynamicZone`) שמבצעים עליו שאילתה עם fragments. ראו
[GraphQL API](/he/api/graphql/).

## כתיבה

שלחו את כל הערך של המאפיין. הוא מחליף את מה שנשמר:

```json
{
  "data": {
    "seo": { "metaTitle": "Rust for CMS authors" },
    "blocks": [
      { "__component": "blocks.hero", "title": "Hello" },
      { "__component": "blocks.quote", "text": "Fast and small.", "author": "Ferris" }
    ]
  }
}
```

הערך מאומת מול הסכמה של הרכיב בכל כתיבה: מפתחות לא מוכרים, טיפוסים שגויים ו-
`__component` שהאזור הדינמי לא מתיר הם שגיאות עם נתיבים כמו
`["blocks", 1, "text"]`. שדות `required` בתוך רכיבים נבדקים כשהמסמך מתפרסם, כמו שדות
ברמה העליונה.

## סינון

| מה | דוגמה | הערות |
| --- | --- | --- |
| שדות של רכיב | `filters[seo][metaTitle][$containsi]=rust` | שדות סקלריים, כולל רכיבים מקוננים. |
| שדות של רכיב חוזר | `filters[links][url][$contains]=github` | מתאים כשפריט כלשהו מתאים. |
| אזורים דינמיים | `filters[blocks][__component][$eq]=blocks.quote` | רק לפי `__component`: לפריטים של רכיבים שונים יש שדות שונים. |

אי אפשר למיין לפי שדות של רכיבים, ואי אפשר לסנן שדות `json` בתוך רכיבים. לאופרטורים, ראו
[REST API](/he/api/rest/#מסננים).
