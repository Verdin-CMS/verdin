טיוטה ופרסום מאפשרים לעורכים לעבוד על מסמך בלי לשנות את מה שהאתר שלכם מציג, ולפרסם כשהוא
מוכן. העמוד הזה מסביר את המודל: מסמכים, גרסאות, הפעולות שמעבירות תוכן ביניהן, ואיך כל API
מתייחס אליהן. זה עובד כמו ב-Strapi v5.

מפעילים את זה לכל סוג תוכן בסכמה שלו:

```json title="schema/content-types/article.json (excerpt)"
"options": { "draftAndPublish": true }
```

זה כבוי כש-`options.draftAndPublish` חסר.

## מסמכים וגרסאות

**מסמך** הוא רשומה אחת, שמזוהה לפי ה-`documentId` שלה. עם טיוטה ופרסום, למסמך יש עד שתי
**גרסאות**:

- **טיוטה**, שכל עריכה משנה, ו-
- גרסה **מפורסמת**, ש-API התוכן מגיש כברירת מחדל.

בסוג [מתורגם](/he/concepts/internationalization/), לכל שפה יש טיוטה וגרסה מפורסמת משלה,
וכולן חולקות את ה-`documentId`.

לסוגים בלי טיוטה ופרסום יש גרסה אחת לכל שפה, שתמיד מפורסמת: כל כתיבה משנה את מה שהקוראים
רואים.

## מצבים

פאנל הניהול מציג את המצב של כל רשומה ברשימה ובעורך:

| מצב | טיוטה | גרסה מפורסמת | מה רואים קוראי התוכן המפורסם |
| --- | --- | --- | --- |
| **טיוטה** | כן | אין | כלום: המסמך אינו גלוי. |
| **פורסם** | זהה לגרסה המפורסמת | כן | הגרסה המפורסמת. |
| **שונה** | השתנתה מאז הפרסום האחרון | כן | הגרסה המפורסמת, בלי השינויים החדשים. |

הפעולות מעבירות מסמך בין המצבים האלה:

| פעולה | השפעה | ממצב ← למצב |
| --- | --- | --- |
| שמירה | כותבת את הטיוטה. | טיוטה ← טיוטה, פורסם ← שונה |
| **פרסום** | מעתיקה את הטיוטה לגרסה המפורסמת, ויוצרת אותה אם צריך. | טיוטה או שונה ← פורסם |
| **ביטול פרסום** | מוחקת את הגרסה המפורסמת; הטיוטה נשארת. | פורסם או שונה ← טיוטה |
| **ביטול השינויים** | מחליפה את הטיוטה בעותק של הגרסה המפורסמת. | שונה ← פורסם |
| מחיקה | מסירה את כל הגרסאות (של השפה המבוקשת, בסוגים מתורגמים). | כל מצב ← נעלם |

הפרסום רץ בטרנזקציה אחת. הוא בודק את שדות ה-`required` ואת
[הכללים בין השדות](/he/concepts/content-model/#אימותים-בין-שדות) של הסוג על הטיוטה; בדיקה
שנכשלה לא מפרסמת כלום. עד אז טיוטות יכולות להיות חלקיות ולהפר את הכללים האלה.

`publishedAt` הוא `null` בטיוטות. הגרסה המפורסמת נושאת את הזמן שבו פורסמה לאחרונה.

## קשרים ומדיה עוקבים אחרי הגרסה

לכל גרסה יש קישורי קשרים ומדיה משלה, והפרסום מעתיק את הקישורים של הטיוטה לגרסה המפורסמת.
הקישורים מצביעים על מסמכים, ונפתרים בגרסה שנקראת: מאמר מפורסם מציג את הגרסה המפורסמת של
הקטגוריה שלו, וטיוטה מציגה את הטיוטה של הקטגוריה. אם פרסום הקטגוריה מבוטל, היא נעלמת
מהמאמר המפורסם עד שתפורסם שוב, בלי שאף קישור ייכתב מחדש. ראו
[קשרים](/he/concepts/relations/#מקושר-לפי-מסמך-לא-לפי-שורה).

רכיבים ואזורים דינמיים הם חלק מהשורה, כך שהפרסום מעתיק אותם כמו שהם.

## קריאת טיוטות ותוכן מפורסם

| API | קורא כברירת מחדל | כדי לקרוא טיוטות |
| --- | --- | --- |
| [REST](/he/api/rest/#סטטוס) | גרסאות מפורסמות | `?status=draft`, שדורש את ההרשאה **קריאת טיוטות** |
| [GraphQL](/he/api/graphql/) | גרסאות מפורסמות | `status: DRAFT`, עם אותה הרשאה |
| [API הניהול](/he/api/admin/) | טיוטות | `?status=published` |

קריאת טיוטות היא הרשאה נפרדת (`readDrafts`), כדי שאסימון שקורא את התוכן של האתר שלכם לא
יוכל לקרוא עבודה שלא פורסמה. אסימוני API לקריאה בלבד אף פעם לא קוראים טיוטות.

כדי להבדיל בין מסמכים לפי השאלה אם פורסמו אי פעם, סננו עם `hasPublishedVersion`:
`?status=draft&hasPublishedVersion=false` מפרט מסמכים שמעולם לא פורסמו.

## כתיבה דרך ה-APIs

בכתיבות, ה-APIs עוקבים אחרי Strapi v5:

- **REST ו-GraphQL**: `create` ו-`update` כותבים את הטיוטה **ומפרסמים אותה**, אלא אם
  הבקשה מבקשת `status=draft` (`status: DRAFT` ב-GraphQL). פרסום שנכשל מבטל את כל הבקשה.
- **פאנל הניהול ו-API הניהול** שומרים טיוטות בלבד. פרסום הוא תמיד פעולה מפורשת.

ל-REST API יש גם פעולות מפורשות, ש-Strapi לא מציע ב-REST:

```http
POST /api/articles/{documentId}/actions/publish
POST /api/articles/{documentId}/actions/unpublish
POST /api/articles/{documentId}/actions/discard-draft
```

הן דורשות את ההרשאה **פרסום** על הסוג. ראו [REST API](/he/api/rest/#פעולות).

## תכונות נוספות שמפרסמות

- [מהדורות](/he/guides/content/releases/) מקבצות מסמכים ומפרסמות אותם או מבטלות את
  פרסומם יחד, מיד או במועד מסוים.
- [תהליכי בקרה](/he/guides/content/review-workflows/) יכולים לדרוש שלב מסוים לפני שמותר
  לפרסם מסמך.
- פרסום וביטול פרסום שולחים את [אירועי ה-webhook](/he/api/webhooks/) `entry.publish`
  ו-`entry.unpublish` ואת [אירועי הזמן האמת](/he/api/realtime/). שמירות של טיוטה שולחות
  `entry.update`, שרק מבקשים שמורשים לקרוא טיוטות מקבלים בזמן אמת.
