`verdin import strapi` מביא פרויקט Strapi v4 או v5 לתוך Verdin: סוגי התוכן והרכיבים שלו הופכים
לקובצי סכמה, והרשומות, השפות, ספריית המדיה, הקשרים, משתמשי הקצה וההרשאות הציבוריות שלו
מיובאים. העמוד הזה מלווה אתכם בהגירה ומפרט מה הפרונטאנד שלכם צריך לשנות. להשוואה תכונה אחר
תכונה, ראו [תאימות ל-Strapi](/he/migrate/compatibility/).

## לפני שמתחילים

- פרויקט Strapi v4 או v5 שבו אפשר להריץ `strapi export`.
- פרויקט Verdin חדש (`verdin new my-site`), או כזה שאין בו קובצי סכמה עם אותם שמות. ראו את
  [ההתחלה המהירה](/he/start/quickstart/).
- מסד הנתונים ואחסון המדיה שפרויקט ה-Verdin ישתמש בהם בייצור, אם אפשר: הקבצים מועתקים לספק
  ההעלאות שהוגדר במהלך הייבוא.

## 1. ייצוא מ-Strapi

בפרויקט ה-Strapi:

```sh frame="terminal"
npx strapi export --no-encrypt -f my-export      # כותב את my-export.tar.gz
```

Verdin לא יכול לקרוא ייצואים מוצפנים (`.tar.gz.enc`); ייצאו שוב עם `--no-encrypt`. גם ייצואים
לא דחוסים (`--no-compress`, קובץ `.tar`) ותיקיית ייצוא פרוסה עובדים.

## 2. ייבוא ל-Verdin

<Steps>

1. צרו את הפרויקט וייבאו את הייצוא:

   ```sh frame="terminal"
   verdin new my-site && cd my-site
   verdin import strapi ../my-export.tar.gz
   ```

2. קראו את הסיכום. המייבא מדפיס כמה מסמכים, גרסאות, קבצים, תיקיות, שפות וקישורים הוא ייבא,
   ואז שורה אחת לכל אזהרה.

3. הפעילו את שרת הפיתוח ופתחו את פאנל הניהול:

   ```sh frame="terminal"
   verdin dev
   ```

</Steps>

הפקודה מריצה את השלבים האלה לפי הסדר:

1. כותבת קובץ סכמה אחד לכל סוג תוכן `api::` ולכל רכיב ל-`schema/`. אם הסכמה שהומרה לא עוברת
   אימות, שום דבר לא נכתב.
2. מבצעת הגירה של מסד הנתונים (שלבים בטוחים).
3. מייבאת שפות, תיקיות וקובצי מדיה, רשומות (כל טיוטה, גרסה מפורסמת ושפה), קשרים, ואת המדיה
   שמצורפת לרשומות ולרכיבים.
4. מייבאת משתמשי קצה, את התפקידים שלהם ואת ההרשאות של public ו-authenticated.
5. כותבת את `strapi-id-map.json` בתיקיית הפרויקט.

| אפשרות | השפעה |
| --- | --- |
| `--schema-only` | עצירה אחרי כתיבת קובצי הסכמה. שימושי כדי לסקור או להתאים קודם את הסכמה. |
| `--force` | דריסה של קובצי סכמה קיימים, וייבוא לסוגי תוכן שכבר יש להם רשומות. |

בלי `--force`, הייבוא עוצר אם קובץ סכמה שהוא היה כותב כבר קיים, או אם לסוג תוכן כבר יש רשומות.

## מה עובר

| Strapi | Verdin |
| --- | --- |
| סוגי תוכן `api::…` ורכיבים | קובצי סכמה, תוך שמירה על `collectionName`, טיוטה ופרסום, אפשרויות i18n ואפשרויות שדות (`required`, `private`, `unique`, אורכים, `regex`, ברירות מחדל…) |
| קשרים בין סוגי `api::` | אותם קשרים |
| קשרים בתוך רכיבים | הפניות `oneWay` / `manyWay` |
| קשרים פולימורפיים (`morphToOne`, `morphToMany`, `morphOne`, `morphMany`) | אותו הדבר, עם הקישורים שלהם לסוגי תוכן מיובאים |
| שדות מדיה (גם ברכיבים) | שדות מדיה |
| שורות v5 (טיוטה ומפורסמת) | גרסאות טיוטה ומפורסמות |
| שורות v4 | טיוטה, ועוד גרסה מפורסמת כש-`publishedAt` מוגדר; `localizations` הופכים לשפות של מסמך אחד |
| `plugin::i18n.locale` | שפות (ברירת המחדל של Strapi נשארת ברירת המחדל) |
| `plugin::upload.file` ו-`folder` | קבצים (עם הפורמטים שלהם) ותיקיות של ספריית המדיה |
| שדות `password` | שדות `password`, תוך שמירה על ה-hashes של bcrypt של Strapi |
| שדות מותאמים (`customField`) | המאפיין עם ה-`customField` שלו נשמר; ראו בהמשך |
| שדות מותנים (`conditions`, Strapi 5.17) | נשמרים בסכמה ומוחלים על ידי העורך |
| `plugin::users-permissions.user` | משתמשי קצה, עם סיסמאות ה-bcrypt שלהם (מגובבות מחדש עם Argon2id בהתחברות הבאה), `confirmed` ו-`blocked` |
| תפקידי Users & Permissions | ההרשאות של התפקיד Public הופכות להרשאות הציבוריות של Verdin; Authenticated ותפקידים מותאמים הופכים לתפקידי משתמשי קצה |
| הרשאות תפקידים על סוגי תוכן ועל העלאות | הרשאות `find`, `findOne`, `create`, `update` ו-`delete`; ובהעלאות `find`, `findOne`, `upload` ו-`destroy` |

## מה לא עובר

מדווח כאזהרות:

- קשרים למשתמשי ניהול, למשתמשי קצה או לסוגים של תוספים אחרים (רק יעדי `api::` מיובאים).
  השדות `createdBy` / `updatedBy` מושמטים.
- `unique` על מאפייני `text`, `richtext`, `blocks` ו-`json` (Verdin תומך בו בטיפוסי טקסט
  קצרים).
- טיפוסי מאפיינים ש-Verdin לא מכיר, וסוגי קשרים שהוא לא יכול לשמור בתוך רכיב.
- חצאי קשרים שה-`inversedBy` / `mappedBy` שלהם לא מתאימים לצד השני.
- קודי שפה לא תקינים.

לא מיובאים בכלל: משתמשי ניהול ותפקידי ניהול, אסימוני API, transfer tokens, webhooks, מהדורות,
שלבי תהליכי בקרה, היסטוריית תוכן ויומני ביקורת, וההגדרות של תוספי Strapi. לקוד ה-Strapi
שלכם — controllers, services, נתיבים, policies, middlewares, lifecycle hooks, משימות cron
והתאמות אישיות של פאנל הניהול — אין מקבילה ב-Verdin להמיר אליה; ראו
[בנייה מחדש של קוד מותאם](#בנייה-מחדש-של-קוד-מותאם).

<Aside type="note">
שדות מותאמים שומרים על שם ה-`customField` שלהם, כמו `plugin::color-picker.color`. העורך מציג
אותם עם [תוסף](/he/extending/plugins/) שמספק את השדה הזה, ונופל חזרה לקלט של הטיפוס השמור
כשאין כזה.
</Aside>

## מפת המזהים

Verdin מייצר מזהי מסמכים חדשים: ל-`documentId`s של Strapi יש 24 תווים ולאלה של Verdin 26,
ולכן כל מסמך מקבל מזהה חדש. גם ה-`id`s המספריים משתנים. `strapi-id-map.json` מתעד את המיפוי:

```json title="strapi-id-map.json"
{
  "documents": {
    "api::article": {
      "hq7xw1c6m2vkn0f3t8ybz5sd": "01k6b3xg0r9m2m7c1d4e5f6g7h"
    }
  },
  "files": {
    "12": 3
  }
}
```

- `documents` ממופתח לפי ה-uid של סוג התוכן ב-Verdin (`api::article`, ב-Strapi
  `api::article.article`), ואז לפי ה-`documentId` של Strapi (v5) או לפי מזהה שורה (v4: מזהה
  אחד מייצג את כל השפות של מסמך).
- `files` ממפה מזהי קבצים של Strapi למזהי קבצים של Verdin.

השתמשו בה כדי לשכתב מזהים שנשמרים מחוץ ל-CMS: קישורים בקוד של הפרונטאנד, מזהים במסד נתונים
אחר, אנליטיקה, סימניות.

## בדיקת התוצאה

1. `verdin schema check` עובר, ו-`verdin migrate plan` אומר שמסד הנתונים מעודכן.
2. בפאנל הניהול, פתחו כל אוסף והשוו את מספר הרשומות, הטיוטות והשפות ל-Strapi.
3. פתחו כמה רשומות עם קשרים, רכיבים, אזורים דינמיים ומדיה, ובדקו שהקישורים מצביעים למסמכים
   ולקבצים הנכונים.
4. פתחו את **ספריית המדיה** ובדקו שהתיקיות והתמונות (עם הפורמטים שלהן) שם.
5. ב-**הגדרות ← גישה ציבורית** וב-**הגדרות ← משתמשי קצה**, עברו על ההרשאות והתפקידים שיובאו.
6. קראו ל-API שלכם כמו שהפרונטאנד עושה והשוו את התגובות לאלה של Strapi.

אחר כך עשו commit ל-`schema/`, צרו את המנהלים, אסימוני ה-API וה-webhooks שלכם, ופרסו (ראו את
[רשימת הבדיקה לייצור](/he/deploy/production-checklist/)).

## שינויים בפרונטאנד

API התוכן עוקב אחרי מבני ה-REST וה-GraphQL של Strapi v5, כך שרוב הבקשות עובדות כמו שהן. שנו
את אלה:

- **כתובת בסיס.** כוונו את הפרונטאנד לשרת ה-Verdin. API התוכן נמצא תחת `/api`
  (`[api].prefix`), ו-GraphQL ב-`/graphql` ברגע שמפעילים אותו ב-**הגדרות ← תכונות**.
- **אסימוני API.** אסימונים לא מיובאים: צרו חדשים ב-**הגדרות ← אסימוני API** והחליפו אותם
  בסביבה של הפרונטאנד.
- **מזהי מסמכים.** כל `documentId` ו-`id` מספרי הם חדשים. החליפו מזהים שקודדו בפרונטאנד
  באלה שב-`strapi-id-map.json`, או טוב יותר, חפשו רשומות לפי slug או שדה `uid` אחר.
- **כתובות מדיה.** כתובות הקבצים מצביעות לספק החדש: `/uploads/…` בשרת ה-Verdin עבור הספק
  המקומי, או `[upload.provider].public_url` עבור S3. עדכנו את דומייני התמונות שה-framework
  שלכם מתיר (למשל `images.remotePatterns` ב-Next.js).
- **משתמשי קצה מחוברים** חייבים להתחבר שוב: הסיסמאות שלהם עובדות, אבל JWTs שהונפקו על ידי
  Strapi לא.
- **CORS.** אם דפדפן קורא ל-API ממקור אחר, ציינו אותו ב-`[api].cors_origins`.
- **Webhooks.** צרו אותם מחדש ב-**הגדרות ← Webhooks**. האירוע `entry.draft-discard` של Strapi
  נקרא `entry.discard-draft`, והשליחות חתומות (ראו [Webhooks](/he/guides/integrations/webhooks/)).
- **פרונטאנדים של Strapi v4** צריכים גם את השינויים של v5: תגובות שטוחות בלי `attributes`,
  `documentId` במקום `id` בכתובות, ו-`status=draft` במקום `publicationState=preview`.

לגישה עם טיפוסים, צרו טיפוסי TypeScript עם `verdin types` והשתמשו ב
[לקוח עם הטיפוסים](/he/guides/frontend/typed-client/).

## בנייה מחדש של קוד מותאם

| Strapi | Verdin |
| --- | --- |
| Lifecycle hooks, middlewares של document service | hooks של תוספים (`beforeCreate`, `afterUpdate`…) ב[תוסף WebAssembly](/he/extending/plugins/) |
| נתיבים ו-controllers מותאמים | נתיבי תוספים תחת `/api/plugins/<name>/` |
| משימות cron | משימות של תוספים (`[[jobs]]`) |
| שדות מותאמים | שדות מותאמים של תוספים |
| ווידג'טים לפאנל הניהול | ווידג'טים של תוספים, או הווידג'טים המובנים של לוח הבקרה |
| לוגו, צבעים וטקסטים של פאנל הניהול | `[admin.branding]` ב-`verdin.toml` |
| `config/*.js` | `verdin.toml` ומשתני סביבה ([תיעוד התצורה](/he/reference/configuration/)) |
