פעולות AI מוסיפות ארבעה עוזרים לפאנל הניהול: תרגום רשומה משפה אחרת, כתיבת טקסט חלופי לתמונה,
סיכום טקסט ארוך לשדה קצר, והצעת מטא-נתונים של SEO. הן משתמשות בספק מודלים שאתם מגדירים
(Anthropic, OpenAI, או שרת מקומי כמו Ollama), עם המפתח שלכם.

כל פעולה מחזירה הצעה שממלאת את הטופס. שום דבר לא נשמר עד שהעורך בודק אותה ושומר, ואפשר לבטל
כל פעולה.

## הגדרה

פעולות AI דורשות גם ספק ב-`verdin.toml` וגם שהתכונה תהיה פעילה.

<Steps>

1. הוסיפו קטע `[ai]` ותנו לשרת את המפתח ב-`VERDIN_AI_KEY`:

   <Tabs syncKey="ai-provider">
   <TabItem label="Anthropic">

   ```toml title="verdin.toml"
   [ai]
   provider = "anthropic"
   # model = "claude-sonnet-5"   # the default
   ```

   </TabItem>
   <TabItem label="OpenAI">

   ```toml title="verdin.toml"
   [ai]
   provider = "openai"
   model = "gpt-4.1-mini"        # required: name the model you want
   ```

   </TabItem>
   <TabItem label="מקומי (Ollama)">

   ```toml title="verdin.toml"
   [ai]
   provider = "openai-compatible"
   base_url = "http://localhost:11434/v1"
   model = "llama3.2-vision"
   ```

   שרתים מקומיים לא צריכים `VERDIN_AI_KEY`. LM Studio, vLLM ושרתים אחרים עם API תואם OpenAI
   עובדים באותה דרך.

   </TabItem>
   </Tabs>

   ```sh title="Terminal"
   export VERDIN_AI_KEY=sk-...
   ```

2. הפעילו מחדש את Verdin. הוא מסרב לעלות כשהקטע חלקי: מפתח חסר, או `model` או `base_url`
   חסרים היכן שהספק צריך אותם.
3. ב-**הגדרות ← תכונות**, הפעילו את **פעולות AI**.

</Steps>

| מפתח | ברירת מחדל | תיאור |
| --- | --- | --- |
| `provider` | `"none"` | `anthropic`, `openai` או `openai-compatible`. |
| `model` | `claude-sonnet-5` עבור `anthropic` | המודל. חובה עבור הספקים האחרים. |
| `base_url` | של הספק | נקודת קצה אחרת: proxy, או שרת מקומי (חובה עבור `openai-compatible`). |
| `max_tokens` | `2048` | התשובה הארוכה ביותר, ב-tokens. |

ראו את [`[ai]`](/he/reference/configuration/). כשהתכונה פעילה אבל אין קטע `[ai]`, פאנל הניהול
מציג **פעולות AI אינן זמינות בשרת זה.**

פעולת הטקסט החלופי שולחת תמונות, אז בחרו מודל שמקבל תמונות אם אתם רוצים אותה.

## מה הפעולות עושות

### תרגום רשומה

בעורך של רשומה מתורגמת, **תרגום מ-_שפה_…** פותח את **תרגום עם AI**. בחרו את השפה ב**תרגום
מ** ובחרו **תרגום**. שדות הטקסט של הטיוטה השמורה של השפה הזו (מחרוזות, טקסטים, טקסט עשיר,
blocks, והטקסט שבתוך רכיבים ואזורים דינמיים) מתורגמים לשפה הנוכחית ומחליפים את השדות האלה
בטופס.

- שדות שמשותפים בין שפות לא מושפעים.
- שינויים שלא נשמרו בשפת המקור לא נכללים: שמרו אותה קודם.
- Markdown, HTML, כתובות URL, מזהים וסוגי בלוקים נשמרים כמו שהם.
- השדות שתורגמו מסומנים; בדקו אותם, ואז שמרו, או בחרו **ביטול התרגום**.

זה דורש הרשאה לעדכן את הרשומה בשפת היעד ולקרוא אותה בשפת המקור.

### כתיבת טקסט חלופי

בספריית המדיה, פתחו תמונה ובחרו **יצירת טקסט חלופי**. המודל מתאר את התמונה (עד כ-125 תווים)
בשפה של שפת ברירת המחדל, וממלא את הכיתוב כשהוא ריק. זה עובד על תמונות JPEG, PNG, WebP ו-GIF,
ושולח את הפורמט `small` או `medium` כשיש כזה, כך שמקורות גדולים לא מועלים לספק. דורש את
הרשאת העדכון של ספריית המדיה (על הקובץ, עבור **הקבצים שלי**).

### סיכום לתוך שדה

שדות טקסט ששמם כשל סיכום (`description`, `summary`, `excerpt`, `abstract`, `intro`,
`introduction`, `lead`, `teaser`) מקבלים כפתור **סיכום _שדה_** כשלרשומה יש שדה טקסט עשיר או
blocks, או שדה טקסט בשם `body`, `content`, `text` או `article`. בבלוג לדוגמה, **Excerpt** מקבל
**סיכום Body**. הסיכום נכנס באורך המרבי של השדה.

### הצעת מטא-נתונים של SEO

רכיב עם מאפייני טקסט `metaTitle` ו-`metaDescription`, כמו
[`shared.seo` המוצע](/he/guides/frontend/seo-and-sitemap/), מקבל כפתור **הצעה**. הוא ממלא את
כותרת ה-meta, התיאור, וכשיש לרכיב, גם את `keywords`, מתוך הטיוטה השמורה של הרשומה.

## מגבלות

- כל מנהל רשאי לבצע 30 בקשות AI בדקה; בקשות נוספות עונות **יותר מדי בקשות AI. המתינו דקה
  ונסו שוב.**
- סיכומים והצעות SEO שולחים לכל היותר 40,000 תווים של טקסט.
- בקשה לספק חורגת מהזמן אחרי 120 שניות.

## פרטיות

<Aside type="caution">
פעולות AI שולחות תוכן לספק שאתם מגדירים: השדות שמתורגמים, מסוכמים או מתוארים, והתמונות עבור
טקסט חלופי. בחרו ספק ותוכנית שהארגון שלכם מתיר עבור התוכן הזה, בדקו את תנאי שמירת הנתונים
שלו, ושקלו מודל מקומי (`openai-compatible`) לתוכן שאסור לו לצאת מהרשת שלכם.
</Aside>

- הבקשות יוצאות משרת ה-Verdin לספק; המפתח אף פעם לא מגיע לדפדפן.
- רק הקלט של הפעולה נשלח: שדות הטקסט של הרשומה, הטקסט לסיכום, או תמונה אחת ושם הקובץ שלה.
  מאפיינים פרטיים ורשומות אחרות לא נשלחים.
- הפעולות קוראות רק את מה שהמנהל כבר יכול לקרוא, וההצעות לא נשמרות.

פאנל הניהול מציג איזה מודל ענה (**הצעות מאת _מודל_ (_ספק_).**).

כדי לאפשר לסוכני AI מחוץ לפאנל הניהול לקרוא ולכתוב תוכן, ראו [שרת MCP](/he/guides/integrations/mcp/).
