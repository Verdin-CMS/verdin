יומני הביקורת מתעדים מי שינה מה, ומתי: תוכן, מדיה, התחברויות וכל שינוי שבוצע בפאנל הניהול.
המדריך הזה מראה מה מתועד, איך מסננים את היומנים, וכמה זמן הם נשמרים.

ב-Strapi, יומני ביקורת הם תכונת Enterprise. ב-Verdin הם חלק מליבת הקוד הפתוח.

## לפני שמתחילים

- **הגדרות ← תכונות ← יומני ביקורת** פעיל כברירת מחדל. כיבוי שלו מפסיק את תיעוד הפעולות
  החדשות; הרשומות הקיימות נשארות קריאות.
- קריאת היומנים דורשת **קריאת יומני ביקורת** (`audit.read`). ראו
  [הרשאות](/he/reference/permissions/).

## מה מתועד

| תחום | פעולות | הערות |
| --- | --- | --- |
| תוכן | `entry.create`, `entry.update`, `entry.publish`, `entry.unpublish`, `entry.discard-draft`, `entry.delete` | מכל API: פאנל הניהול, REST, GraphQL ותוספים. השפה מופיעה בפרטים. |
| תהליכי בקרה | `entry.stage`, `entry.assign` | שינויי שלב והקצאות. |
| מדיה | `media.create`, `media.update`, `media.delete` | העלאות, שינויים ומחיקות של קבצים. שם הקובץ מופיע בפרטים. |
| התחברויות | `admin.login` | התחברויות עם סיסמה ושל המנהל הראשון (מתועדות אחרי הגורם השני כשלחשבון יש כזה), והתחברויות SSO עם הספק. |
| שינויי ניהול | `{METHOD} {route}`, למשל `PUT /roles/{id}` | כל כתיבה מוצלחת ל-API הניהול: משתמשים, תפקידים, אסימוני API, הגדרות, תכונות, webhooks, שפות, תוספים, מהדורות… הפרמטרים של הנתיב מופיעים בפרטים. |

לכל רשומה יש זמן, מבצע, פעולה, נושא (UID של סוג תוכן, `plugin::upload.file`, או משאב הניהול
כמו `roles`), המזהה של הנושא, פרטים, ועבור בקשות, כתובת ה-IP של הלקוח.

המבצע הוא אחד מהבאים:

- **מנהל מערכת**: מנהל מחובר, שמופיע בשמו ביומן.
- **API**: שינוי שבוצע דרך API התוכן או GraphQL, עם אסימון API, אסימון של משתמש קצה או גישה
  ציבורית.
- **מערכת**: כתיבה ל-API הניהול בלי מנהל מחובר.

מאחורי reverse proxy, הגדירו את `[server].trusted_proxies` כדי שהיומנים יציגו את הכתובת של
הלקוח במקום זו של ה-proxy. ראו את [תיעוד התצורה](/he/reference/configuration/).

## סינון היומנים

<Steps>

1. פתחו את **הגדרות ← יומני ביקורת**.
2. השתמשו בהגדרה מוכנה של **מסננים מהירים** (**תוכן**, **מדיה**, **כניסות**), או מלאו את
   המסננים:
   - **פעולה**: פעולה מדויקת כמו `entry.publish`, או קידומת שמסתיימת ב-`*`, כמו `entry.*`.
   - **מבצע**: מנהל אחד, או **כל אחד**.
   - **נושא**: UID של סוג תוכן כמו `api::article`.
   - **מתאריך** ו**עד תאריך**: טווח תאריכים. תאריך בלי שעה כולל את כל היום.
3. בחרו **החלה**. פתחו את **פרטים** בשורה כדי לראות את כל מה שתועד עבורה.

</Steps>

## שאילתה דרך ה-API

```sh title="Terminal"
curl -G 'http://localhost:1337/admin/api/audit-logs' \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  --data-urlencode 'action=entry.*' \
  --data-urlencode 'subject=api::article' \
  --data-urlencode 'actor=3' \
  --data-urlencode 'from=2026-09-01' \
  --data-urlencode 'to=2026-09-30' \
  --data-urlencode 'page=1' --data-urlencode 'pageSize=50'
```

הרשומות מגיעות מהחדשה לישנה, 50 לעמוד כברירת מחדל ולכל היותר 200:

```json
{
  "data": [
    {
      "id": 812,
      "at": "2026-09-28T14:03:11.000Z",
      "action": "entry.publish",
      "subject": "api::article",
      "subjectId": "k3v9…",
      "details": { "locale": "fr" },
      "ip": null,
      "actor": { "kind": "admin", "id": 3, "email": "ana@example.com", "name": "Ana Ruiz" }
    }
  ],
  "meta": { "pagination": { "page": 1, "pageSize": 50, "total": 1, "pageCount": 1 } }
}
```

`from` ו-`to` מקבלים תאריכים או תאריך-שעה בפורמט ISO 8601; כל דבר אחר הוא שגיאת `400`.

## כמה זמן נשמרות הרשומות

רשומות ישנות מ-`[audit].retention_days` נמחקות פעם ביום. ברירת המחדל היא 90 ימים.

```toml title="verdin.toml"
[audit]
retention_days = 365
```

<Aside type="tip">
כדי לשמור רשומות ביקורת זמן רב יותר ממה שמסד הנתונים שלכם צריך, העתיקו אותן באופן קבוע
לאחסון משלכם עם ה-API שלמעלה.
</Aside>
