מהדורה מקבצת רשומות שעולות לאוויר, או יורדות ממנו, יחד: השקת מוצר, קמפיין, סט של תרגומים.
מפרסמים אותה ידנית או נותנים לה תאריך. המדריך הזה יוצר מהדורה, מוסיף רשומות, מריץ אותה ומציג
את API הניהול.

המהדורות עובדות כמו ה-Releases של Strapi, שהן חלק מהתוכניות בתשלום של Strapi.

## לפני שמתחילים

- **הגדרות ← תכונות ← מהדורות** פעיל כברירת מחדל. כל עוד הוא כבוי, הדף **מהדורות** והנתיבים
  אינם זמינים ומהדורות מתוזמנות ממתינות.
- ניהול מהדורות דורש **ניהול מהדורות** (`releases.manage`).
- הוספת רשומה דורשת גם **פרסום** על סוג התוכן שלה, והסוג חייב להשתמש ב
  [טיוטה ופרסום](/he/concepts/draft-and-publish/).

## יצירת מהדורה

<Steps>

1. פתחו את **מהדורות** בסרגל הצד ובחרו **מהדורה חדשה**.
2. הזינו **שם**.
3. באופן אופציונלי, הגדירו **פרסום בתאריך (אופציונלי)**: התאריך והשעה, באזור הזמן שלכם,
   שבהם המהדורה רצה. בלי תאריך, המהדורה ממתינה עד שתפרסמו אותה.
4. בחרו **יצירה**.

</Steps>

## הוספת רשומות

<Steps>

1. פתחו רשומה בעורך. החלונית **מהדורות** מפרטת את המהדורות שהיא נמצאת בהן.
2. בחרו **הוספה למהדורה**.
3. בחרו את ה**מהדורה**, ותחת **כאשר המהדורה מבוצעת** בחרו **פרסום** או **ביטול פרסום**.
4. בחרו **הוספה**.

</Steps>

בסוגים מתורגמים, רק הגרסה בשפה הנוכחית של העורך מתווספת. הוסיפו כל שפה שאתם רוצים לכלול
במהדורה. הוספת רשומה שכבר נמצאת במהדורה מחליפה את הפעולה שלה.

דף המהדורה מפרט את הרשומות שלה עם סוג התוכן והפעולה שלהן. הסירו אחת עם הכפתור שבשורה שלה.

## פרסום המהדורה

- **עכשיו:** פתחו את המהדורה ובחרו **פרסום עכשיו**.
- **במועד שלה:** משימת רקע בודקת כל 30 שניות ומריצה את המהדורות שהגיע זמנן, בשם המנהל
  שיצר אותן.

  caption="הסטטוסים של מהדורה"
  code={`flowchart LR

  R -->|חלק מהפעולות נכשלו| F[נכשלה]`}

כל פעולה רושמת אם הצליחה. כשאחת נכשלת, למשל כי הרשומה נמחקה או שהיא לא עוברת אימות, הפעולות
האחרות עדיין רצות והמהדורה מסתיימת כ**נכשלה**, עם השגיאה של כל פעולה שנכשלה בשורה שלה.

<Aside type="caution">
מהדורה שרצה כבר לא ניתנת לשינוי. כדי לנסות שוב פעולות שנכשלו, הוסיפו את הרשומות האלה למהדורה
חדשה.
</Aside>

מהדורה מתפרסמת כיחידה אחת: היא לא מחכה ל[שלבי בקרה](/he/guides/content/review-workflows/).
אם תהליך דורש שלב מסוים כדי לפרסם, הרשומות שמחוץ לשלב הזה נכשלות כמו בכל פרסום אחר.

Webhooks יכולים להירשם ל-**מהדורה פורסמה** (`releases.publish`), שנשלח כשמהדורה רצה. ראו
[Webhooks](/he/guides/integrations/webhooks/).

## API הניהול

כל הנתיבים נמצאים תחת `/admin/api` ודורשים `releases.manage`.

```http
GET    /admin/api/releases?status=pending
POST   /admin/api/releases                    { "name": "Launch", "scheduledAt": "2026-10-01T08:00:00Z" }
GET    /admin/api/releases/{id}
PUT    /admin/api/releases/{id}               { "name": "Launch", "scheduledAt": null }
DELETE /admin/api/releases/{id}
POST   /admin/api/releases/{id}/actions       { "uid": "api::article", "documentId": "…", "locale": "fr", "action": "publish" }
DELETE /admin/api/releases/{id}/actions/{actionId}
POST   /admin/api/releases/{id}/publish
GET    /admin/api/content/{uid}/{documentId}/releases
```

- `status` הוא `pending`, `running`, `done` או `failed`; לכל פעולה יש `status` ו-`error`
  משלה.
- שינוי, הוספה או פרסום של מהדורה שכבר אינה ממתינה עונים `409`.
- `action` הוא `publish` או `unpublish`. הוספת פעולה דורשת גם `content.publish` על הסוג. השפה
  נקבעת כשהפעולה מתווספת, כך ששינוי מאוחר של שפת ברירת המחדל לא מזיז אותה.
- מחיקת מהדורה מוחקת את רשימת הרשומות שלה. הרשומות עצמן לא משתנות.
- `GET /content/{uid}/{documentId}/releases` דורש הרשאת קריאה לרשומה ומחזיר רשימה ריקה
  למנהלים בלי `releases.manage`.
