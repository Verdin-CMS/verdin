API התוכן ופאנל הניהול מחפשים רשומות עם הפרמטר `_q`, כמו ב-Strapi. כברירת מחדל `_q` מתאים
לשדות טקסט שמכילים את המילים. הפעילו את אינדקס `[search]` כדי לדרג את התוצאות עם מנוע טקסט
מלא (Tantivy) שמובנה בשרת. המדריך הזה מציג את שניהם ומתי להשתמש באינדקס.

## חיפוש עם `_q`

```sh title="Terminal"
curl -G 'http://localhost:1337/api/articles' --data-urlencode '_q=rust cms'
```

`_q` משתלב עם שאר הפרמטרים: `filters`, `status`, `locale`, `pagination`, `fields`
ו-`populate`. תיבת החיפוש של רשימת הניהול שולחת את אותו פרמטר.

באילו שדות מחפשים:

- שדות טקסט: `string`, `text`, `richtext`, `email`, `uid` ו-`enumeration`.
- עם האינדקס, גם הטקסט שבתוך `blocks`, רכיבים ואזורים דינמיים.
- אף פעם לא שדות פרטיים או סיסמאות.

`_q` הוא פרמטר של REST. ל-GraphQL ולאפשרויות השאילתה של לקוח ה-TypeScript אין ארגומנט חיפוש;
השתמשו שם במסנן `$containsi`.

## בלי האינדקס

בלי `[search]`, `_q` מתאים לרשומות שבהן שדה טקסט כלשהו מכיל את כל טקסט החיפוש, בלי תלות
ברישיות, כמו `$containsi` של Strapi. התוצאות עוקבות אחרי המיון הרגיל. זה לא דורש הגדרה ועובד
בכל מסד נתונים, אבל זה סורק את הטבלה ולא מדרג.

## הפעלת אינדקס הטקסט המלא

<Steps>

1. הפעילו את האינדקס ב-`verdin.toml`:

   ```toml title="verdin.toml"
   [search]
   enabled = true
   ```

2. הפעילו מחדש את Verdin. הוא בונה את האינדקס ברקע מכל הרשומות; עד שהוא מוכן, `_q` נופל
   חזרה ל-`$containsi`.

</Steps>

| מפתח | ברירת מחדל | תיאור |
| --- | --- | --- |
| `enabled` | `false` | מדרג את `_q` עם אינדקס הטקסט המלא. |
| `dir` | `"data/search"` | תיקיית האינדקס, יחסית לפרויקט. |
| `memory_mb` | `50` | תקציב הזיכרון לאינדוקס, במגה-בייטים. |

ראו את [תיעוד התצורה](/he/reference/configuration/).

איך האינדקס מתאים:

- מילים מפוצלות לפי כל מה שאינו אות או ספרה, מומרות לאותיות קטנות ומנוקות מסימני הטעמה, כך
  ש-`cafe` מוצא את `Café`.
- כל מילה חייבת להתאים. המילה האחרונה מתאימה גם כקידומת, כך שתוצאות מופיעות תוך כדי הקלדה.
- לכותרת (שדה הטקסט הראשון של הסוג) יש משקל כפול.
- בלי `sort`, התוצאות מגיעות מההתאמה הטובה ביותר. עם `sort`, ההתאמות ממוינות לפי הדרך שלכם.
  לכל היותר 1,000 התאמות נלקחות בחשבון בכל חיפוש.
- טיוטות וגרסאות מפורסמות, וכל שפה, נבדקות בנפרד, לפי `status` ו-`locale`.

האינדקס עוקב אחרי כל כתיבה מכל API. הוא נבנה מחדש כשהסכמה משנה את השדות שניתן לחפש בהם,
וכשהתיקייה שלו חסרה.

## כמה מופעים

האינדקס נמצא בדיסק של המופע ועוקב אחרי הכתיבות של אותו מופע. כשמריצים כמה מופעים, כתיבות
באחד לא מגיעות לאינדקס של האחרים. השאירו את החיפוש במופע יחיד, או בנו מחדש אחרי פריסה על ידי
מחיקת תיקיית האינדקס לפני ההפעלה. ראו [הרצת כמה מופעים](/he/deploy/scaling/).

<Aside type="tip">
בטוח למחוק את תיקיית האינדקס. השאירו אותה מחוץ לגיבויים ולניהול הגרסאות; Verdin בונה אותה
מחדש ממסד הנתונים.
</Aside>
