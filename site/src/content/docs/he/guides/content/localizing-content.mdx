סוג תוכן מתורגם שומר גרסה אחת של כל רשומה לכל שפה. המדריך הזה מוסיף את השפות שבהן אתם
מפרסמים, מפעיל תרגום לסוג, מתרגם רשומות בפאנל הניהול וקורא או כותב כל שפה דרך ה-API. למודל
שמאחורי זה (שדות משותפים, קשרים בין סוגים מתורגמים), ראו
[בינאום](/he/concepts/internationalization/).

התרגום הוא חלק מהליבה: אין תכונה להפעיל. הוא עובד כמו תוסף ה-i18n של Strapi v5 ומקבל את אותו
פרמטר `locale`.

## לפני שמתחילים

- כדי להוסיף, לשנות שם או למחוק שפות צריך **ניהול שפות** (`locales.manage`).
- כדי להפוך סוג למתורגם עורכים את הסכמה שלו, ב**בונה סוגי התוכן** (`verdin dev`) או
  ב-`schema/content-types/<name>.json`.
- ראו [הרשאות](/he/reference/permissions/) עבור הרשאות התוכן שעורכים צריכים.

## הוספת השפות

ההפעלה הראשונה יוצרת אנגלית (`en`) כשפת ברירת המחדל. בקשות שלא מציינות שפה משתמשות בשפת
ברירת המחדל, ורשומות חדשות מתחילות בה.

<Steps>

1. פתחו את **הגדרות ← בינאום** ובחרו **הוספת שפה**.
2. הזינו **קוד**: קוד שפה באותיות קטנות, אופציונלית עם אזור או כתב, כמו `fr`, `pt-BR` או
   `zh-Hans`. השם ממולא בשבילכם ואפשר לשנות אותו.
3. סמנו **הגדרה כשפת ברירת המחדל** אם בקשות בלי שפה צריכות להשתמש בה, ואז שמרו.

</Steps>

כדי לשנות את ברירת המחדל מאוחר יותר, בחרו **הגדרה כברירת מחדל** בשפה אחרת. אי אפשר למחוק את
שפת ברירת המחדל.

<Aside type="caution" title="מחיקת שפה מוחקת את הרשומות שלה">
מחיקת שפה מוחקת לצמיתות כל רשומה שנכתבה בה, בכל סוג תוכן, כולל גרסאות מפורסמות. החלון מבקש
מכם להקליד את קוד השפה כדי לאשר.
</Aside>

## הפיכת סוג תוכן למתורגם

ב**בונה סוגי התוכן**, פתחו את הסוג והפעילו את **מתורגם** בהגדרות שלו. אחר כך החליטו, שדה אחר
שדה, אילו ערכים שונים בכל שפה: שדה שבו **מתורגם** כבוי מחזיק ערך אחד שמשותף לכל השפות.

אותו דבר בקובץ הסכמה, עבור הסוג `article` של פרויקט הדוגמה:

```json title="schema/content-types/article.json" {6,9}
{
  "kind": "collectionType",
  "singularName": "article",
  "pluralName": "articles",
  "displayName": "Article",
  "pluginOptions": { "i18n": { "localized": true } },
  "attributes": {
    "title": { "type": "string", "required": true },
    "readingTime": { "type": "integer", "pluginOptions": { "i18n": { "localized": false } } }
  }
}
```

איך שדות משותפים מתנהגים:

- שמירת שדה משותף בשפה אחת כותבת אותו לטיוטות של כל השפות.
- פרסום של שפה מעתיק את השדות המשותפים שלה לגרסאות המפורסמות של השפות האחרות.
- גם שדות קשר ומדיה יכולים להיות משותפים.

סוגים בלי `pluginOptions.i18n.localized` אינם מתורגמים ומתעלמים מפרמטרי `locale`. שינוי
התרגום של סוג הוא שינוי סכמה: עברו על ההגירה עם `verdin migrate plan` לפני שאתם פורסים אותה.

## תרגום רשומה בפאנל הניהול

<Steps>

1. פתחו את הרשומה ובחרו את שפת היעד בבורר **שפה** בראש העורך. שפות בלי גרסה מציגות
   **עדיין לא נוצר**.
2. העורך אומר שלרשומה עדיין אין גרסה בשפה הזו ושהשמירה תיצור אותה. שדות משותפים כבר מציגים
   את הערכים שלהם.
3. כדי להתחיל מתרגום קיים, בחרו **מילוי משפה אחרת** בהודעה הזו. בחרו את המקור ב**העתקה מ־**
   ובחרו **העתקת שדות**. זה מעתיק לטופס את השדות המתורגמים, כולל קשרים ומדיה. שום דבר עוד לא
   נשמר.
4. ערכו את השדות, ואז **שמירת טיוטה** או **פרסום**. לכל שפה יש טיוטה וגרסה מפורסמת משלה.

</Steps>

לתצוגת הרשימה יש אותו בורר **שפה**: היא מציגה את הגרסאות בשפה אחת בכל פעם. מחיקה מהעורך
מסירה רק את הגרסה בשפה הנוכחית; השפות האחרות נשמרות.

כשהתכונה **פעולות AI** פעילה, העורך יכול גם לתרגם את שדות הטקסט מהטיוטה של שפה אחרת. ראו
[פעולות AI](/he/guides/integrations/ai-actions/).

## הגבלת עורכים לחלק מהשפות

הרשאות התוכן של תפקיד יכולות לכסות רק חלק מהשפות. ב-**הגדרות ← תפקידים**, פתחו את התפקיד,
מצאו את סוג התוכן ובחרו **שפות**. בחרו **רק השפות האלה** וסמנו אותן. מנהלים עם התפקיד הזה
לא יכולים לקרוא או לשנות גרסאות בשפות האחרות; הבורר **שפה** מציג את השפות האלה כ-"(אין
גישה)".

## קריאה וכתיבה של שפות דרך ה-API

הוסיפו `locale` לכל בקשת REST, או העבירו אותו כארגומנט ב-GraphQL. בלעדיו, משתמשים בשפת ברירת
המחדל. שפה לא מוכרת היא שגיאת `400`.

<Tabs syncKey="api">
<TabItem label="REST">

```sh title="Terminal"
# קריאת הגרסאות בצרפתית
curl 'http://localhost:1337/api/articles?locale=fr'

# יצירה או עדכון של הגרסה הצרפתית של מסמך
curl -X PUT 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"data":{"title":"Bonjour"}}'

# מחיקה של הגרסה הצרפתית בלבד
curl -X DELETE 'http://localhost:1337/api/articles/<documentId>?locale=fr' \
  -H "Authorization: Bearer $TOKEN"
```

</TabItem>
<TabItem label="GraphQL">

```graphql
query {
  articles(locale: "fr") {
    documentId
    title
    locale
  }
}
```

</TabItem>
<TabItem label="TypeScript">

```ts
const { data } = await verdin.collection('articles').find({ locale: 'fr' });
```

</TabItem>
</Tabs>

למה לצפות:

- `PUT` עם `locale` יוצר את הגרסה של השפה הזו כשעדיין אין למסמך כזו.
- תגובות של סוגים מתורגמים כוללות `locale`. כל הגרסאות חולקות את אותו `documentId`.
- `DELETE` מסיר רק את הגרסה בשפה המבוקשת (שפת ברירת המחדל כשלא צוינה). קישורים שמצביעים על
  המסמך מוסרים כשלא נשארת אף שפה.
- כשסוג מתורגם מקשר לסוג מתורגם אחר, הקריאות פותרות את היעד באותה שפה, וכך גם מסננים דרך
  קשרים. יעדים שאינם מתורגמים משותפים לכל השפות.
- payloads של webhooks וגרסאות היסטוריה רושמים את השפה.

בניגוד ל-Strapi, ל-API התוכן אין נתיב `/api/i18n/locales`. השפות מפורטות ב-API הניהול
ב-`GET /admin/api/i18n/locales`, ומנוהלות עם `POST`, `PUT /admin/api/i18n/locales/{code}`
ו-`DELETE /admin/api/i18n/locales/{code}` (`locales.manage`).
