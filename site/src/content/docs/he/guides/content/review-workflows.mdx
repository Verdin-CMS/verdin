תהליך בקרה הוא רשימה מסודרת של שלבים, כמו *To do*, *In review* ו-*Ready*, שהרשומות של חלק
מסוגי התוכן עוברות בהם לפני שהן מתפרסמות. המדריך הזה מגדיר תהליך, מעביר ומקצה רשומות, ומציג
את API הניהול המתאים.

ב-Strapi, תהליכי בקרה הם תכונת Enterprise. ב-Verdin הם חלק מליבת הקוד הפתוח.

## לפני שמתחילים

- הפעילו את **הגדרות ← תכונות ← תהליכי בקרה**. הוא כבוי כברירת מחדל.
- הגדרת תהליכים דורשת **ניהול תהליכי בקרה** (`workflows.manage`).
- העברה והקצאה של רשומה דורשות הרשאת עדכון עליה. ראו [הרשאות](/he/reference/permissions/).

## יצירת תהליך

<Steps>

1. פתחו את **הגדרות ← תהליכי בקרה** ובחרו **תהליך חדש**.
2. תנו לו **שם**.
3. תחת **סוגי תוכן**, בחרו את הסוגים שהרשומות שלהם עוקבות אחריו. סוג עוקב אחרי תהליך אחד לכל
   היותר.
4. תחת **שלבים**, פרטו את השלבים לפי הסדר. לכל אחד יש **שם השלב** ו**צבע**. השתמשו ב**הוספת
   שלב** לעוד שלבים, ובכפתורי החצים כדי לסדר אותם מחדש. רשומות חדשות מתחילות בשלב הראשון.
5. באופן אופציונלי, בחרו בשלב **תפקידים שיכולים להעביר רשומות לשלב זה**. בלי תפקידים
   שנבחרו, כל מי שיכול לעדכן את הרשומה יכול.
6. באופן אופציונלי, הגדירו **השלב הנדרש לפרסום**. אז אפשר לפרסם רשומות רק כשהן בשלב הזה.
   **כל שלב** לא מתערב בפרסום.
7. שמרו.

</Steps>

רשומות שהיו קיימות לפני שהסוג שלהן הצטרף לתהליך נמצאות בשלב הראשון.

כשמשנים תהליך מאוחר יותר:

- הסרת שלב מחזירה את הרשומות שלו לשלב הראשון.
- הסרת סוג תוכן מהתהליך מנקה את השלבים של הרשומות שלו.
- מחיקת התהליך מנקה את השלבים ואת האחראים של הרשומות שלו.

## העברה והקצאה של רשומות

עורך הרשומות מציג חלונית **בקרה** עם ה**שלב** וה**אחראי**.

- בחרו **שלב** אחר כדי להעביר את הרשומה. אי אפשר לבחור שלבים ששמורים לתפקידים אחרים, והחלונית
  אומרת זאת. מנהלים עם **ניהול תהליכי בקרה** תמיד יכולים להעביר רשומות.
- בחרו **אחראי** מבין המנהלים הפעילים שיכולים לקרוא את סוג התוכן, או בחרו **הסרת האחראי**. כל
  מי שיכול לעדכן את הרשומה יכול להקצות אותה.
- כשלתהליך יש שלב נדרש, החלונית אומרת לאיזה שלב הרשומה חייבת להגיע לפני ש**פרסום** יעבוד.

תצוגת הרשימה מציגה עמודת **שלב**, ודף הבית מפרט את הרשומות שהוקצו לכם תחת **הוקצו אליי**.
סוגים מתורגמים שומרים שלב לכל שפה.

## מה שלב הפרסום חוסם

השלב הנדרש חל על כל דרך לפרסם: פאנל הניהול, REST, GraphQL, מהדורות ותוספים. פרסום של רשומה
מחוץ לשלב הזה נכשל עם `400`:

```text
the entry must be in the review stage `Ready` to be published
```

ב-Strapi דרישת השלב חלה רק על פאנל הניהול. גם תפקידי השלבים שונים: ב-Verdin הם מגבילים מי
מעביר רשומות *לתוך* שלב.

## יומני ביקורת ו-webhooks

- שינויי שלב והקצאות מתועדים ב[יומני הביקורת](/he/guides/content/audit-logs/) כ-`entry.stage`
  ו-`entry.assign`.
- Webhooks יכולים להירשם ל-**שלב הרשומה השתנה** (`review-workflows.updateEntryStage`). ראו
  [Webhooks](/he/guides/integrations/webhooks/).

## API הניהול

כל הנתיבים נמצאים תחת `/admin/api` ומקבלים אסימון גישה של מנהל.

| נתיב | הרשאה | עושה |
| --- | --- | --- |
| `GET /review-workflows`, `GET /review-workflows/{id}` | `workflows.manage` | תהליכים עם השלבים שלהם. |
| `POST /review-workflows`, `PUT /review-workflows/{id}` | `workflows.manage` | יצירה או החלפה של תהליך (הגוף בהמשך). |
| `DELETE /review-workflows/{id}` | `workflows.manage` | הרשומות של הסוגים שלו מאבדות את השלבים שלהן. |
| `GET /content/{uid}/{documentId}/review?locale=` | קריאת הרשומה | השלב, האחראי, והשלבים שאפשר להעביר אליהם את הרשומה (`canMoveTo`). |
| `PUT /content/{uid}/{documentId}/review?locale=` | עדכון הרשומה | `{ "stageId": 3, "assigneeId": 7 }`. שני השדות אופציונליים; `"assigneeId": null` מסיר את האחראי. |
| `GET /content/{uid}/review?documentIds=a,b` | קריאת הסוג | השלבים של עד 200 רשומות, עם התהליך ב-`meta.workflow`. |
| `GET /review/assigned` | מחובר | רשומות שהוקצו לכם. |
| `GET /review/assignees?uid=` | עדכון הסוג | מנהלים פעילים שיכולים לקרוא את הסוג. |
| `GET /review/roles` | `workflows.manage` | קודי ושמות תפקידים, עבור תפקידי שלבים. |

תהליך כפי שהוא נשלח ל-`POST` ול-`PUT`:

```json
{
  "name": "Editorial",
  "contentTypes": ["api::article"],
  "stages": [
    { "id": 1, "name": "To do", "color": "#4945ff" },
    { "id": 2, "name": "In review", "color": "#ff8800" },
    { "name": "Ready", "color": "#2f9e44", "roles": ["editor"] }
  ],
  "publishStage": "Ready"
}
```

- לתהליך יש 1 עד 50 שלבים עם שמות ייחודיים וצבעי `#rrggbb`.
- `publishStage` מציין אחד מהשלבים; השמיטו אותו כדי לא לדרוש שלב.
- שלחו שלבים קיימים עם ה-`id` שלהם כדי שהרשומות שלהם יישארו במקומן. שלבים בלי `id` הם חדשים.

<Aside type="note">
כיבוי התכונה מסתיר את השלבים ומפסיק לאכוף את שלב הפרסום. התהליכים והשלבים של הרשומות נשמרים
לפעם שתפעילו אותה מחדש.
</Aside>
