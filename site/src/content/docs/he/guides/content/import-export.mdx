רשימת הניהול של כל סוג תוכן מייצאת את הרשומות שלו ל-CSV או ל-JSON, ומייבאת אותן בחזרה מאותו
סוג קובץ: כדי לתקן הרבה רשומות בגיליון אלקטרוני, לטעון קטלוג מוצרים, או להעתיק רשומות בין
פרויקטים. המדריך הזה מכסה את שני הכיוונים ואת פורמט הקובץ.

זה מיועד לרשומות של סוג תוכן אחד בכל פעם. כדי להעביר פרויקט שלם, ראו את
[`verdin export` ו-`verdin import verdin`](/he/reference/cli/). כדי לעבור מ-Strapi, ראו
[מעבר מ-Strapi](/he/migrate/from-strapi/).

## לפני שמתחילים

- ייצוא דורש הרשאת קריאה לסוג התוכן. רק השדות שהתפקיד שלכם יכול לקרוא מיוצאים.
- ייבוא דורש הרשאת יצירה, הרשאת עדכון, או את שתיהן: שורות שיוצרות רשומות צריכות יצירה,
  שורות שמעדכנות אותן צריכות עדכון. פרסום השורות המיובאות דורש גם פרסום. ראו
  [הרשאות](/he/reference/permissions/).

## ייצוא רשומות

<Steps>

1. פתחו את הרשימה של סוג התוכן והגדירו אותה כפי שאתם רוצים את הייצוא: מסננים, חיפוש, מיון,
   סטטוס ושפה.
2. בחרו **ייצוא**, ואז **ייצוא כ-CSV** או **ייצוא כ-JSON**.

</Steps>

הקובץ מחזיק את הרשומות שהרשימה מציגה, עם המסננים, החיפוש והמיון שלה, בכל העמודים, עד 50,000
רשומות. כל שורה מתחילה ב-`documentId`, ואחריו השדות.

## ייבוא רשומות

<Steps>

1. פתחו את הרשימה של סוג התוכן ובחרו **ייבוא**.
2. בחרו **קובץ**: קובץ `.csv` עם שורת כותרת, או קובץ `.json` שמחזיק רשימה של אובייקטים, עד
   1 MB.
3. תחת **עמודות**, בחרו את השדה שאליו כל עמודה נכנסת. עמודות ששמן כשם של שדה כבר מותאמות.
   בחרו **דילוג** כדי להשמיט עמודה, ו**מזהה מסמך (עדכון)** לעמודה שמציינת רשומות קיימות.
4. באופן אופציונלי, הפעילו את **פרסום הרשומות המיובאות**. אחרת הן נשמרות כטיוטות.
5. בחרו **בדיקה**. Verdin בודק כל שורה, כולל אילוצים והפניות, בלי לכתוב כלום, ומדווח על
   השורות שהוא היה יוצר, מעדכן או דוחה.
6. תקנו את הקובץ אם צריך, ואז בחרו **ייבוא**.

</Steps>

איך השורות נכתבות:

- שורה עם `documentId` מעדכנת את הרשומה הזו; האחרות יוצרות רשומות חדשות.
- השורות נכתבות אחת אחת. שורה שנכשלת מדווחת עם השדה והבעיה, ומדולגת; האחרות עדיין נכתבות.
- הדוח מפרט עד 100 שורות עם שגיאות, ואת העמודות שלא התאימו לאף שדה.
- ייבוא מקבל לכל היותר 5,000 שורות. פצלו קבצים גדולים יותר.
- הרשומות נכתבות בשפה הנוכחית של הרשימה.

<Aside type="caution">
ייבוא מעביר את השורות שלכם דרך אותו אימות כמו העורך, אבל אין ביטול. הריצו קודם **בדיקה**,
וייצאו את הרשימה לפני עדכון גדול כדי שתוכלו לשחזר אותה. כש[היסטוריית התוכן](/he/guides/content/content-history/)
פעילה, כל רשומה שעודכנה שומרת את הגרסה הקודמת שלה.
</Aside>

## פורמט הקובץ

השדות משתמשים באותם מבנים כמו פורמט הכתיבה של API התוכן:

| שדה | ערך |
| --- | --- |
| טקסט, מספרים, בוליאניים, תאריכים | כמו ב-API (`true`/`false`, תאריכים ב-ISO 8601). |
| קשרים | ערכי `documentId` של הרשומות הקשורות. |
| מדיה | מזהי קבצים מספריית המדיה. |
| קשרים פולימורפיים | `uid:documentId`, למשל `api::article:k3v9…`. |
| רכיבים, אזורים דינמיים, blocks ו-JSON | JSON. |

ב-CSV, רשימות (כמה קשרים או קבצים) מחוברות עם `|`.

```csv title="articles.csv"
documentId,title,slug,featured,tags
,Hello world,hello-world,true,t1a2b3|t4c5d6
k3v9x8…,Updated title,updated-title,false,
```

אותן שורות כ-JSON:

```json title="articles.json"
[
  { "title": "Hello world", "slug": "hello-world", "featured": true, "tags": ["t1a2b3", "t4c5d6"] },
  { "documentId": "k3v9x8…", "title": "Updated title", "slug": "updated-title", "featured": false }
]
```

ייצוא של רשימה הוא תמיד קובץ ייבוא תקין עבור אותו סוג תוכן.

## API הניהול

- `GET /admin/api/content/{uid}/export?format=csv` (או `json`) מקבל את פרמטרי השאילתה של
  הרשימה: `filters`, `_q`, `sort`, `status` ו-`locale`.
- `POST /admin/api/content/{uid}/import?locale=` מקבל את תוכן הקובץ כמחרוזת:

```json
{
  "format": "csv",
  "data": "title,slug\nHello world,hello-world\n",
  "mapping": { "slug": "slug", "notes": null },
  "dryRun": true,
  "publish": false
}
```

`mapping` ממפה עמודה לשדה; `null` מדלג על העמודה, ועמודות שלא מופו שומרות על השם שלהן. גוף
הבקשה מוגבל על ידי `[server].body_limit` (1 MB כברירת מחדל).
