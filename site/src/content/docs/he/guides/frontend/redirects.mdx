התכונה **הפניות** מאפשרת לעורכים לשלוח נתיבים ישנים לחדשים בלי פריסה: הם מנהלים את הרשימה
בפאנל הניהול, והאתר שלכם שולף אותה ועונה עם ההפניה. Verdin לא מפנה מבקרים בעצמו, כי הם
מגיעים לאתר שלכם, לא ל-CMS.

## הפעלה

ב-**הגדרות ← תכונות**, הפעילו את **הפניות**, ואז בחרו **ניהול הפניות** (או עברו ל-**הגדרות ←
הפניות**). ניהול הפניות דורש את ההרשאה **ניהול SEO, הפניות, תפריטים וטפסים** (`site.manage`),
שיש לתפקיד המובנה Editor. ראו [הרשאות](/he/reference/permissions/).

## הוספת הפניות

<Steps>

1. ב-**הגדרות ← הפניות**, בחרו **הוספת הפניה**.
2. **מ**: הנתיב הישן, שמתחיל ב-`/` (למשל `/blog/2024/hello`).
3. **אל**: הנתיב החדש, או כתובת `http(s)` מלאה באתר אחר.
4. **סוג**: **301 · קבועה**, **302 · זמנית**, **307 · זמנית (שומרת על השיטה)** או
   **308 · קבועה (שומרת על השיטה)**.
5. שמרו.

</Steps>

Verdin דוחה הפניה שלעולם לא תעבוד:

- הפניה שנייה מאותו נתיב;
- נתיב שמפנה לעצמו;
- שרשרת שנסגרת במעגל (`/a` → `/b` → `/a`).

להפניות רבות בבת אחת, השתמשו ב**ייבוא CSV** עם העמודות `source`, `destination` ו-`status`.
שורות שהמקור שלהן כבר קיים מעדכנות את ההפניה הזו. **ייצוא CSV** כותב את אותו פורמט, שימושי
להגירה מ-CMS אחר או לסקירה בגיליון אלקטרוני.

```csv title="redirects.csv"
source,destination,status
/blog/2024/hello,/blog/hello,301
/old-pricing,https://shop.example.com/pricing,302
```

## החלה באתר שלכם

אתרים קוראים את הרשימה מ-`GET /api/_redirects`, בלי אסימון:

```json
{
  "data": [
    { "source": "/blog/2024/hello", "destination": "/blog/hello", "status": 301 },
    { "source": "/old-pricing", "destination": "https://shop.example.com/pricing", "status": 302 }
  ]
}
```

התגובה נשלחת עם `Cache-Control: public, max-age=60`, כך ששינוי מגיע לאתרים תוך כדקה. התאימו
את נתיב הבקשה בדיוק מול `source`:

<Tabs syncKey="framework">
<TabItem label="Next.js">

```js title="middleware.js"
import { NextResponse } from 'next/server';

export async function middleware(request) {
  const response = await fetch(`${process.env.VERDIN_URL}/api/_redirects`, { next: { revalidate: 60 } });
  const { data } = await response.json();
  const hit = data.find((redirect) => redirect.source === request.nextUrl.pathname);
  if (hit) return NextResponse.redirect(new URL(hit.destination, request.url), hit.status);
}
```

</TabItem>
<TabItem label="Astro">

```ts title="src/middleware.ts"
import { defineMiddleware } from 'astro:middleware';

let cache: { at: number; list: { source: string; destination: string; status: number }[] } | null = null;

export const onRequest = defineMiddleware(async (context, next) => {
  if (!cache || Date.now() - cache.at > 60_000) {
    const response = await fetch(`${import.meta.env.VERDIN_URL}/api/_redirects`);
    cache = { at: Date.now(), list: (await response.json()).data };
  }
  const hit = cache.list.find((redirect) => redirect.source === context.url.pathname);
  if (hit) return context.redirect(hit.destination, hit.status as 301 | 302 | 307 | 308);
  return next();
});
```

</TabItem>
</Tabs>

לאתר סטטי, שלפו את הרשימה בזמן ה-build וכתבו את קובץ ההפניות של המארח שלכם (`_redirects` של
Netlify, `vercel.json` של Vercel, map של nginx). שלבו את זה עם
[כפתור פריסה](/he/guides/integrations/deploys-and-cdn/) או עם [webhook](/he/guides/integrations/webhooks/)
כדי שעורכים יוכלו לבנות מחדש אחרי שינוי הפניות.

<Aside type="note">
קידומת ה-API עוקבת אחרי [`[api].prefix`](/he/reference/configuration/). כשהתכונה כבויה,
`/api/_redirects` עונה `404`.
</Aside>

## API הניהול

פאנל הניהול משתמש ב-`/admin/api/site/redirects` (`GET`, `POST`) וב-
`/admin/api/site/redirects/{id}` (`PUT`, `DELETE`), עם אסימון גישה של מנהל ו-`site.manage`.
הרשימה מחולקת לעמודים ותומכת ב-`search` (ראו [רשימות](/he/api/admin/#רשימות)).
