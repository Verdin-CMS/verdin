מנהלים הם האנשים שמתחברים לפאנל הניהול. הם נפרדים מ[משתמשי הקצה](/he/guides/auth/end-users/)
של האתרים והאפליקציות שלכם. המדריך הזה יוצר את המנהל הראשון, מזמין את האחרים, נותן להם
תפקידים ועוזר להם לחזור פנימה כשהם ננעלים בחוץ.

## לפני שמתחילים

- Verdin צריך את `VERDIN_ADMIN_JWT_SECRET` ואת `VERDIN_TOKEN_PEPPER` בסביבה. צרו אותם פעם
  אחת עם `verdin secrets`.
- ניהול מנהלים דורש **ניהול משתמשים** (`users.manage`); ניהול תפקידים דורש **ניהול
  תפקידים** (`roles.manage`). ראו [הרשאות](/he/reference/permissions/).
- הזמנות ואיפוסי סיסמה נשלחים בדוא"ל דרך `[email]`. עם ספק ברירת המחדל `log`, הודעות
  הדוא"ל, כולל הקישורים, נכתבות ליומן השרת.

## יצירת המנהל הראשון

פתחו את פאנל הניהול (`http://localhost:1337/admin/` כברירת מחדל). כל עוד אין אף מנהל, הוא
מבקש את הראשון, שהופך ל-Super Admin. לסיסמאות יש 8 עד 128 תווים.

בלי דפדפן, השתמשו ב-CLI או ב-API:

<Tabs>
<TabItem label="CLI">

```sh title="Terminal"
verdin admin create --email you@example.com
```

הסיסמה מגיעה מ-`VERDIN_ADMIN_PASSWORD`, או נקראת מ-standard input. הפקודה יוצרת Super Admin
ועובדת בכל זמן, לא רק עבור הראשון.

</TabItem>
<TabItem label="API">

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/register-first-admin \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a long password"}'
```

הנתיב הזה עובד רק כל עוד אין אף מנהל.

</TabItem>
</Tabs>

## הזמנת מנהל

<Steps>

1. פתחו את **הגדרות ← משתמשים** ובחרו **הוספת משתמש**.
2. הזינו את כתובת הדוא"ל, ובאופן אופציונלי את **שם פרטי** ו**שם משפחה**.
3. בחרו **תפקידים** אחד או יותר.
4. השאירו את **קביעת סיסמה עכשיו** כבוי כדי לשלוח הזמנה, או הפעילו אותו כדי לקבוע את
   הסיסמה בעצמכם.
5. בחרו **הזמנה** (או **שמירה** עם סיסמה).

</Steps>

החלון **קישור הזמנה** מציג את הקישור ואומר אם הוא נשלח בדוא"ל. שתפו אותו בעצמכם כשלא נשלח,
וזה תמיד המצב עם הספק `log`. הקישור עובד פעם אחת, למשך 7 ימים; המנהל המוזמן פותח אותו, בוחר
סיסמה ומתחבר.

כל עוד המנהל לא התחבר אף פעם, **קישור הזמנה חדש** בשורה שלו מחליף את הקישור הישן. אחרי
שהתחבר, הוא משחזר את הגישה עם איפוס סיסמה.

## תפקידים

Verdin יוצר שלושה תפקידים, כמו Strapi:

| תפקיד | יכול |
| --- | --- |
| **Super Admin** | הכול. אי אפשר לשנות את ההרשאות שלו. |
| **Editor** | ליצור, לערוך, לפרסם ולמחוק את כל התוכן; לנהל את ספריית המדיה; להפעיל פריסות; לנהל SEO, הפניות, תפריטים וטפסים. |
| **Author** | ליצור תוכן, ולערוך ולמחוק את הרשומות והקבצים שלו. לא יכול לפרסם. |

צרו תפקידים נוספים ב-**הגדרות ← תפקידים** עם **תפקיד חדש**. לכל תפקיד, בחרו:

- **תוכן**: לכל סוג תוכן (או **כל סוגי התוכן**), את הרמה של **קריאה**, **יצירה**,
  **עדכון**, **מחיקה** ו**פרסום**: **ללא גישה**, **שלי** (רק רשומות שהמנהל יצר) או
  **הכול**. **שדות** מגביל פעולה לחלק מהשדות, ו**שפות** לחלק מהשפות.
- **ספריית המדיה**: פעולות הקבצים, עבור **כל הקבצים** או **הקבצים שלי**.
- **הגדרות**: גישה לאזורי הניהול, כמו **ניהול משתמשים** או **קריאת יומני ביקורת**.
- **דרישת אימות דו-שלבי**: ראו [אימות דו-שלבי](/he/guides/auth/two-factor/).

מנהל עם כמה תפקידים מקבל את האיחוד של ההרשאות שלהם. הרשימה המלאה נמצאת ב
[תיעוד ההרשאות](/he/reference/permissions/).

רק Super Admin יכול להעניק את התפקיד Super Admin, או לערוך, למחוק או לאפס Super Admin אחר.

## השבתה או הסרה של מנהל

ערכו את המנהל ב-**הגדרות ← משתמשים** וכבו את **פעיל**: משתמשים לא פעילים לא יכולים להתחבר.
**מחיקה** מסירה את החשבון לתמיד; התגובות שלו יוצגו אז ככאלה שנכתבו על ידי מנהל שנמחק.

## איפוס סיסמה

- **המנהל מאפס אותה:** **שכחתם סיסמה?** בדף ההתחברות שולח בדוא"ל קישור שעובד למשך שעה. כל
  הסשנים של החשבון מסתיימים ברגע שהסיסמה משתנה.
- **מנהל אחר קובע אותה:** ערכו את המנהל ב-**הגדרות ← משתמשים** והקלידו סיסמה חדשה. השאירו
  את השדה ריק כדי לשמור על הנוכחית.
- **מהשרת:** כשאף אחד לא יכול להתחבר, הריצו

  ```sh title="Terminal"
  verdin admin reset-password --email you@example.com
  ```

  עם הסיסמה ב-`VERDIN_ADMIN_PASSWORD` או ב-standard input. הפקודה קובעת את הסיסמה, משחררת
  את נעילת החשבון ומסיימת את הסשנים שלו. היא לא מסירה את האימות הדו-שלבי: מנהל שאיבד את
  הגורם השני שלו צריך מנהל אחר ש[יאפס אותו](/he/guides/auth/two-factor/).

## הגנה על ההתחברות

- אחרי 5 סיסמאות שגויות ברצף, החשבון ננעל ל-15 דקות.
- בקשות התחברות, הרשמה ורענון מוגבלות לכל IP של לקוח באמצעות `[admin].auth_rate_limit` (20
  בדקה כברירת מחדל).
- סשן ניהול הוא אסימון גישה ל-15 דקות שמתחדש עם עוגיית רענון שתקפה ל-30 ימים. העוגייה היא
  `Secure` ב-`verdin start`; ראו `[admin].secure_cookies`.

כל מנהל רואה את המכשירים שהוא מחובר בהם תחת **הפעלות** ב**פרופיל** שלו, ויכול לבצע
**התנתקות** של אחד מהם או של כל האחרים. שינוי הסיסמה מנתק כל מכשיר אחר.

## API הניהול

התחברו כדי לקבל אסימון גישה ל-API הניהול:

```sh title="Terminal"
curl -X POST http://localhost:1337/admin/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → { "data": { "user": {…}, "accessToken": "…", "accessTokenExpiresAt": "…" } }
```

| נתיב | הרשאה | עושה |
| --- | --- | --- |
| `GET /users`, `GET /users/{id}` | `users.manage` | מנהלים עם התפקידים שלהם. |
| `POST /users` | `users.manage` | `{ email, firstname?, lastname?, roles: [ids], isActive?, password? }`. בלי `password`, ה-`meta` של התשובה כולל `inviteUrl` ו-`emailed`. |
| `PUT /users/{id}`, `DELETE /users/{id}` | `users.manage` | שינוי או הסרה של מנהל. |
| `POST /users/{id}/invite` | `users.manage` | קישור הזמנה חדש, למנהלים שמעולם לא התחברו. |
| `GET /roles`, `POST /roles`, `PUT /roles/{id}`, `DELETE /roles/{id}` | `roles.manage` | תפקידים וההרשאות שלהם. |
| `POST /auth/forgot-password` | ציבורי | `{ email }`. תמיד עונה `204`. |
| `GET /auth/sessions`, `DELETE /auth/sessions/{id}` | מחובר | הסשנים שלכם. |

כל הנתיבים נמצאים תחת `/admin/api`. ראו את [API הניהול](/he/api/admin/).

<Aside type="caution">
סודות אף פעם לא נכנסים ל-`verdin.toml`. שמרו על שני הסודות יציבים בין הפעלות מחדש ובין
מופעים: `VERDIN_ADMIN_JWT_SECRET` חותם על אסימוני גישה, על ה-JWTs של משתמשי קצה ועל קישורי
תצוגה מקדימה, ו-`VERDIN_TOKEN_PEPPER` מגן על אסימוני API ועל גורמים שניים (ראו
[אסימוני API](/he/guides/auth/api-tokens/)).
</Aside>
