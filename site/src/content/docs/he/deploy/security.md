העמוד הזה מתאר מה Verdin עושה כדי להגן על פרויקט ואת ההגדרות שבשליטתכם. השתמשו בו יחד עם
[רשימת הבדיקה לייצור](/he/deploy/production-checklist/) כשאתם מכינים מופע לתעבורה אמיתית.

## מה סגור כברירת מחדל

- **API התוכן.** בקשות אנונימיות לא מקבלות כלום עד שתעניקו הרשאות ציבוריות ב-
  **הגדרות ← גישה ציבורית**. אסימון לא מוכר, שפג תוקפו או פגום הוא `401`, אף פעם לא נפילה
  חזרה לתפקיד הציבורי. ראו [הרשאות](/he/concepts/permissions/).
- **מסמך ה-OpenAPI** בכתובת `/api/_openapi.json` דורש אסימון API תקין עד שתהפכו אותו
  לציבורי ב-**הגדרות ← תכונות ← תיעוד API**.
- **תכונות אופציונליות** כמו GraphQL, משתמשי קצה, SSO ושרת ה-MCP נשארות כבויות עד שמנהל
  עם ההרשאה `features.manage` מפעיל אותן ב-**הגדרות ← תכונות**.
- **תוספים** נשארים כבויים עד שמנהל מפעיל כל אחד מהם ב-**הגדרות ← תוספים**.
- **קריאות cross-origin מדפדפן.** אף מקור לא יכול לקרוא לאף API מדפדפן עד שתציינו אותו
  ב-`[api].cors_origins`.

## התחברות לניהול

| הגנה | פרטים |
| --- | --- |
| Hashing של סיסמאות | Argon2id עם הפרמטרים של OWASP, עם hashing מחדש כשהם משתנים. |
| סשנים | אסימון גישה ל-15 דקות שנשמר בזיכרון הדף (אף פעם לא ב-`localStorage`), ואסימון רענון ל-30 ימים בעוגייה `HttpOnly`, `SameSite=Strict` שמוגבלת ל-`/admin/api/auth`. אסימון הרענון מוחלף בכל שימוש; הצגה של אסימון ישן מסיימת את כל הסשן. |
| עוגיות מאובטחות | עוגיית הרענון היא `Secure` ב-`verdin start`. `[admin].secure_cookies = false` מכבה את זה ורושם אזהרה. |
| CSRF | רענון והתנתקות דורשים כותרת `X-Verdin-CSRF`, שטופס מאתר אחר לא יכול לשלוח. |
| נעילה | חמישה ניסיונות כושלים נועלים חשבון ל-15 דקות. הכישלונות נספרים גם בשלב הסיסמה וגם בשלב הגורם השני. כתובות דוא"ל לא מוכרות וסיסמאות שגויות מקבלות את אותה תשובה, באותו זמן. |
| הגבלת קצב | התחברות, הרשמה ורענון: `[admin].auth_rate_limit` בקשות לדקה לכל כתובת לקוח (20). |
| גורם שני | אפליקציות אימות (TOTP) ומפתחות גישה (passkeys), עם קודי שחזור. תפקיד יכול לחייב אותו (`requireTwoFactor`). ראו [אימות דו-שלבי](/he/guides/auth/two-factor/). |
| Super Admins | רק Super Admin יכול ליצור, לערוך, למחוק או לאפס Super Admin, או להעניק את התפקיד הזה. אי אפשר להסיר את ה-Super Admin הפעיל האחרון. |

המנהל הראשון נרשם דרך הפאנל כל עוד אין אף מנהל. עשו זאת מיד אחרי ההפעלה הראשונה, או צרו
אותו עם `verdin admin create --email …` לפני שאתם חושפים את השרת.

## פאנל הניהול ו-API הניהול

- API הניהול (`/admin/api`) לא שולח כותרות CORS, לא משנה מה `[api].cors_origins` אומר:
  הדפדפנים מאפשרים רק למקור של הפאנל עצמו לקרוא את התשובות שלו.
- הפאנל מוגש עם Content Security Policy קפדנית (סקריפטים רק מהמקור שלו),
  `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` ו-
  `Referrer-Policy: strict-origin-when-cross-origin`.
- Verdin לא שולח `Strict-Transport-Security`. הוסיפו אותה ב-reverse proxy שמסיים את ה-TLS.

## API התוכן

- **אסימוני API** מוצגים פעם אחת. Verdin שומר HMAC-SHA256 של כל אסימון, עם
  `VERDIN_TOKEN_PEPPER` כמפתח, ושומר קידומת של 10 תווים לתצוגה. לאסימונים יכול להיות תוקף
  ואפשר לחדש אותם.
- **הרשאות שדה ושפה** מגבילות את מה שתפקיד קורא וכותב, ו-`populate`, מסנני קשרים ומיון לפי
  קשרים מגיעים רק לסוגים שהמבקש רשאי לקרוא.
- **מגבלות שאילתה**: `pageSize` עד `[api].max_page_size` (100), עומק `populate` עד 5, לכל
  היותר 100 תנאי סינון, מחרוזות שאילתה עד 16 KB, ולכל היותר 1,000 רשומות שעוברות populate
  לכל קשר. שדות לא מוכרים או פרטיים בשאילתה הם `400`.
- ל-**GraphQL** יש מגבלות עומק ומורכבות משלו (`maxDepth`, `maxComplexity`) ומתג
  אינטרוספקציה בהגדרות התכונה.
- **הגבלות קצב**: `[api].public_rate_limit` לכל כתובת לקוח בלי אסימון ו-
  `[api].token_rate_limit` לכל אסימון API או משתמש קצה, בבקשות לדקה. שתיהן כבויות (`0`)
  כברירת מחדל. בקשות עם bearer token לא מוכר מוגבלות לפי כתובת.

### CORS

`[api].cors_origins` מפרט את מקורות הדפדפן שמורשים לקרוא ל-API התוכן ול-GraphQL:

```toml title="verdin.toml"
[api]
cors_origins = ["https://www.example.com", "https://preview.example.com"]
```

כל רשומה היא `scheme://host[:port]` בלי נתיב או לוכסן בסוף; `["*"]` מתיר כל מקור ואי אפשר
לשלב אותו עם אחרים. השיטות המותרות הן `GET`, `POST`, `PUT` ו-`DELETE`, וכותרות הבקשה
המותרות `Authorization`, `Content-Type` ו-`If-None-Match`. ההפעלה נכשלת על רשומה שאינה
מקור.

פרונטאנדים בצד השרת (Astro, Next.js בשרת) קוראים ל-API בלי דפדפן ולא צריכים רשומת CORS.

## בקשות והעלאות

| הגדרה | ברירת מחדל | מגנה מפני |
| --- | --- | --- |
| `[server].body_limit` | `"1mb"` | גופי בקשה גדולים ב-APIs הרגילים. |
| `[server].request_timeout_secs` | `30` | בקשות איטיות שמחזיקות חיבורים. |
| `[upload].max_file_size` | 200 MB | העלאות גדולות (להעלאות יש מגבלה משלהן במקום `body_limit`). |
| `[upload].max_image_megapixels` | `100` | פצצות דחיסה. |

הסוג של קובץ שהועלה נקבע לפי הבייטים שלו, לא לפי הסוג שהלקוח שולח; שם הקובץ משמש רק
כגיבוי, ולעולם לא לסוגים שדפדפנים מריצים באופן פעיל (קבצים כאלה נשמרים כ-
`application/octet-stream`). קישורים ב-`blocks` של טקסט עשיר חייבים להיות `http(s)`,
`mailto:` או יחסיים.

## כתובות לקוח מאחורי proxy

הגבלות קצב ויומני ביקורת משתמשים בכתובת של הלקוח. מאחורי reverse proxy כל בקשה מגיעה
מה-proxy, ולכן ציינו את ה-proxy ב-`[server].trusted_proxies`:

```toml title="verdin.toml"
[server]
trusted_proxies = ["10.0.0.0/8"]   # the proxies' IPs or CIDR ranges
```

אז Verdin קורא את `X-Forwarded-For` מימין לשמאל ולוקח את הכתובת הראשונה שאינה proxy מהימן.
בקשות מכל כתובת אחרת שומרות על כתובת החיבור שלהן, כך שלקוח לא יכול לזייף את הכתובת שלו
באמצעות שליחת הכותרת בעצמו. אל תציינו טווחים שלקוחות לא מהימנים יכולים להתחבר מהם.

## בקשות יוצאות

webhooks, deploy hooks, webhooks לניקוי CDN והעלאות מכתובת URL מבצעים בקשות שמנהל בוחר.
ב-`verdin start` הן מסרבות לכתובות loopback, פרטיות ו-link-local (כולל צורות IPv6 שמכילות
כתובות IPv4 פרטיות), כך שמנהל לא יכול להשתמש בהן כדי להגיע לשירותים ברשת הפנימית שלכם.
`[webhooks].allow_private_networks = true` מסיר את זה; עשו זאת רק כשכל מנהל מהימן לגבי הרשת
הפנימית.

## סודות

`VERDIN_ADMIN_JWT_SECRET` ו-`VERDIN_TOKEN_PEPPER` נקראים רק מהסביבה וכל אחד מהם חייב להיות
באורך 32 בייטים לפחות (`verdin secrets` מדפיס חדשים). ה-pepper גם חותם את סודות ה-TOTP של
המנהלים וגוזר את המפתח שמבצע hashing לכתובות של שולחי טפסים. שמרו את שניהם במנהל הסודות של
הפלטפורמה שלכם ולעולם אל תעשו commit ל-`.env`.

יומני הבקשות מסתירים את הערכים של פרמטרי שאילתה ששמם נראה סודי (`token`, `code`,
`password`, `key`, `signature`…) ואת החלק הסודי של כתובות callback של פריסות.

## מדדים

`/_metrics` כבוי אלא אם `[metrics].enabled = true`. כשהוא פעיל ולא הוגדר אסימון, כל מי
שמגיע לפורט יכול לקרוא אותו. הגדירו `VERDIN_METRICS_TOKEN` (או `[metrics].token`) ואספו עם
`Authorization: Bearer <token>`, או חסמו את הנתיב ב-proxy. ראו [ניטור](/he/deploy/monitoring/).

## תוספים

תוספים הם מודולי WebAssembly ש-Extism מריץ ב-sandbox. למודול אין מערכת קבצים, רשת או מסד
נתונים משלו: הכול עובר דרך פונקציות מארח שמוגבלות על ידי היכולות שב-`plugin.toml` שלו (סוגי
תוכן שהוא קורא או כותב, מארחי HTTP, מאגר key-value משלו), עם מגבלת זמן וזיכרון לכל קריאה
(`[limits]`, 5 שניות ו-64 MB במניפסט לדוגמה). מנהלים רואים מה תוסף מבקש לפני שהם מפעילים
אותו. סקריפטי הניהול של תוספים רצים בדף של הפאנל, ולכן התקינו רק תוספים שאתם סומכים עליהם.
ראו [תוספים](/he/extending/plugins/).

## ייצואים וגיבויים

ארכיוני `verdin export` מכילים שדות פרטיים ו-hashes של סיסמאות. אחסנו אותם כמו dumps של מסד
נתונים. ראו [גיבויים](/he/deploy/backups/).

## דיווח על פגיעות

אל תפתחו issue ציבורי לבעיית אבטחה. פעלו לפי
[מדיניות האבטחה](https://github.com/Verdin-CMS/verdin/blob/main/SECURITY.md) של המאגר:
דווחו באופן פרטי דרך הלשונית **Security** של
[המאגר](https://github.com/Verdin-CMS/verdin/security) (**Report a
vulnerability**), עם הגרסה, הצעדים לשחזור וההשפעה שאתם רואים. תיקוני אבטחה מפורטים תחת
**Security** ב[יומן השינויים](/he/project/changelog/).
