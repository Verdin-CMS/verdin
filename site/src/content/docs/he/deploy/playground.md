[`deploy/playground/`](https://github.com/verdin-cms/verdin/tree/main/deploy/playground)
בונה קונטיינר לדמו ציבורי: [דוגמת הבלוג](https://github.com/verdin-cms/verdin/tree/main/examples/blog)
על SQLite, עם כמה מאמרים מפורסמים וחשבון דמו שמבקרים יכולים להתחבר איתו. בכל שעה הוא זורק את
מסד הנתונים ומתחיל מחדש. הקונטיינר לא צריך volume, שרת מסד נתונים או סודות מכם. איפה לארח
אותו תלוי בכם; כל פלטפורמה שמריצה קונטיינר אחד עם כתובת HTTPS ציבורית מתאימה.

הסקריפטים הורצו מול בנייה מקומית ב-2026-09-30 (שלושה מחזורי איפוס); האימג' נבנה אבל לא הורץ
מגרסה שפורסמה.

## מה מקבלים המבקרים

- פאנל הניהול ב-`/admin/`, מחוברים כ-**demo@example.com** / **verdin-demo-1234**. לחשבון יש
  את התפקיד **Editor**: הוא יכול ליצור, לערוך, לפרסם ולמחוק תוכן ולהעלות מדיה, אבל לא יכול
  לנהל משתמשים, תפקידים, אסימוני API, webhooks או הגדרות.
- גישת קריאה ציבורית למאמרים, קטגוריות, תגיות ולדף הבית דרך REST
  (`/api/articles?populate=*`) ו-GraphQL.
- שני מאמרים מפורסמים, טיוטה, שתי קטגוריות, שתי תגיות ודף הבית.

קיים גם Super Admin, עם סיסמה אקראית שאף אחד לא יודע.

## איך זה עובד

`run.sh` רץ בלולאה:

1. מוחק את `/var/lib/verdin-playground` (מסד נתונים, העלאות, אינדקס חיפוש, מטמון תמונות)
   ויוצר סודות חדשים, כך שסשנים מהמחזור הקודם מסתיימים.
2. מפעיל `verdin start --migrate` וממתין ל-`/_ready`.
3. מריץ את `seed.sh`: יוצר את החשבונות דרך ה-CLI ו-API הניהול, פותח גישת קריאה ציבורית
   ויוצר את התוכן.
4. ממתין `PLAYGROUND_RESET_SECONDS` (3600), עוצר את השרת ומתחיל מחדש. אם השרת נעצר מעצמו,
   הוא מתחיל מחדש מיד.

התצורה (`deploy/playground/verdin.toml`) מגבילה העלאות ל-2 MB, מגבילה בקשות אנונימיות ל-300
בדקה לכל כתובת, מרחיקה שליחות webhook מכתובות פרטיות ומפעילה חיפוש.

## בנייה והרצה

משורש המאגר:

```sh frame="terminal"
docker build -f deploy/playground/Dockerfile -t verdin-playground .
docker run -p 1337:1337 --tmpfs /var/lib/verdin-playground:uid=65532,gid=65532 verdin-playground
```

האימג' הוא Alpine עם `curl` ו-`jq` (הסקריפטים צריכים shell, שאין באימג' הרשמי) והקובץ
הבינארי הסטטי שמועתק מ-`ghcr.io/verdin-cms/verdin`. העבירו
`--build-arg VERDIN_IMAGE=ghcr.io/verdin-cms/verdin:<version>` כדי לבחור את הגרסה. ה-`tmpfs`
שומר את הנתונים בזיכרון; בלעדיו הנתונים יושבים במערכת הקבצים של הקונטיינר, וגם זה עובד.

| משתנה | ברירת מחדל | מה |
| --- | --- | --- |
| `PLAYGROUND_RESET_SECONDS` | `3600` | הזמן בין איפוסים. |
| `PLAYGROUND_EMAIL`, `PLAYGROUND_PASSWORD` | `demo@example.com`, `verdin-demo-1234` | חשבון הדמו. |
| `VERDIN_SERVER__PUBLIC_URL` | | הכתובת הציבורית של ה-playground. |
| `VERDIN_SERVER__TRUSTED_PROXIES` | | הטווח של ה-proxy של הפלטפורמה, כך שהגבלות קצב חלות לכל מבקר. |

## אירוח

הריצו מופע אחד בדיוק (מסד הנתונים מקומי), השאירו אותו רץ (בלי scale to zero: טיימר האיפוס
חי בתהליך) ושימו HTTPS לפניו: עוגיית הסשן של פאנל הניהול היא `Secure` במצב `start`, ולכן
התחברות צריכה HTTPS. כל אחד יכול לכתוב תוכן ולהעלות תמונות עד שעה, ולכן כוונו את הדף שמקשר
אליו ללוח הזמנים של האיפוס, והשאירו את המופע בדומיין נפרד מכל דבר שחולק עוגיות.
