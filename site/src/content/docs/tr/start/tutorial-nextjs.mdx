Bu eğitimde içeriğini Verdin’den okuyan, [Next.js](https://nextjs.org) ve App Router ile bir blog
geliştireceksiniz: makaleleri listeleyen bir ana sayfa, kategorisiyle birlikte `/articles/<slug>`
adresinde makale başına bir sayfa ve isteğe bağlı olarak admin’in önizleme bağlantısından taslakları
gösteren bir sayfa. Server Components içinde, şemadan üretilen tiplerle tipli istemci
`@verdin/client`’ı kullanacaksınız.

Next.js 16.3 (`create-next-app` 16.3), React 19.2 ve Node.js 20.9 veya sonrası için, Verdin ve
`@verdin/client` 0.10 ile yazılmıştır. `cacheComponents` olmadan Next.js’in varsayılan önbelleğini
kullanır. [Astro eğitimi](/tr/start/tutorial-astro/) aynı blogu Astro ile geliştirir.

## Başlamadan önce

`PATH`’inizde `verdin` ikili dosyasına (bkz. [Hızlı başlangıç](/tr/start/quickstart/)), Node.js’e ve
Git’e ihtiyacınız var. Sonunda yan yana iki klasörünüz olur: Verdin projesi `cms` ve Next.js
uygulaması `blog`.

## 1. Verdin’i blog şemasıyla kurun

Deponun [`examples/blog`](https://github.com/Verdin-CMS/verdin/tree/main/examples/blog) projesi bir
blog modeller: başlığı, `slug`’ı, özeti, Markdown `body`’si, kategorisi ve etiketleri olan
makaleler, ayrıca bir homepage tekil tipi ve birkaç bileşen.

<Steps>

1. Bir Verdin projesi oluşturun ve örnek şemayı içine kopyalayın:

   ```sh title="Terminal"
   git clone --depth 1 https://github.com/Verdin-CMS/verdin.git
   verdin new cms
   cp verdin/examples/blog/schema/content-types/{article,category,tag,homepage}.json cms/schema/content-types/
   cp -r verdin/examples/blog/schema/components/* cms/schema/components/
   ```

2. Başlatın:

   ```sh title="Terminal"
   cd cms
   verdin dev
   ```

   İlk başlatma dört içerik tipi için tabloları oluşturur.

3. [http://localhost:1337/admin/](http://localhost:1337/admin/) adresini açın ve ilk admin’i
   oluşturun.

4. **Koleksiyonlar** altında **Category**’yi açın, **Yeni kayıt**’ı seçin, ona `News` adını verin ve
   kaydedin.

5. **Article**’ı açın, **Yeni kayıt**’ı seçin ve bir başlık, bir özet ve Markdown ile bir gövde
   doldurun. `slug` başlıktan üretilir. Kategori olarak `News`’i seçin ve **Yayınla**’yı seçin. Aynı
   şekilde ikinci bir makale ekleyin.

6. **Ayarlar → Herkese açık erişim**’i açın, **Article** ve **Category** için **Listele** ve
   **Tekini getir**’e izin verin ve **Kaydet**’i seçin.

</Steps>

API’nin yanıt verdiğini denetleyin:

```sh title="Terminal"
curl 'localhost:1337/api/articles?populate=category'
```

<Aside>
Bir ilişkiyi populate etmek hedefine okuma erişimi gerektirir. **Category** üzerinde **Listele**
olmadan `populate=category`, ``invalid key `category` in populate`` ile `400` yanıtını verir.
</Aside>

## 2. Next.js uygulamasını oluşturun

Yeni bir terminalde, `cms`’in yanında:

```sh title="Terminal"
npx create-next-app@latest blog --ts --app --src-dir --no-tailwind --no-eslint --no-react-compiler --import-alias '@/*' --yes
cd blog
npm install @verdin/client marked
```

[`marked`](https://marked.js.org), `body` alanının Markdown’ını HTML’e dönüştürür.

## 3. Tipleri üretin

`verdin types` şemayı okur ve içerik tipi ve bileşen başına bir TypeScript arayüzü ile istemci için
rotaların bir `VerdinSchema` haritasını yazar. Onu Verdin projesinin yapılandırmasına işaret ederek
`blog` içinden çalıştırın:

```sh title="Terminal"
verdin types -c ../cms/verdin.toml -o src/verdin-types.ts
```

Dosya diğerlerinin yanı sıra şunu içerir:

```ts title="src/verdin-types.ts"
export interface Article extends DocumentBase {
  title: string;
  slug: string;
  excerpt: string | null;
  body: string | null;
  // …
  category?: Category | null;
  tags?: Tag[];
}
```

İlişkiler, medya ve bileşenler isteğe bağlıdır, çünkü API onları yalnızca populate ettiğinizde
döndürür. Şema her değiştiğinde komutu yeniden çalıştırın.

## 4. Verdin’e bağlanın

Sunucunun URL’sini `.env.local` içine koyun:

```sh title=".env.local"
VERDIN_URL=http://localhost:1337
# VERDIN_TOKEN=…
```

Token olmadan istemci, 1. adımda açtığınız public rolü olarak okur. Bunun yerine bir token ile okumak
için **Ayarlar → API token’ları** bölümünde **Salt okunur** bir token oluşturun ve `VERDIN_TOKEN`’ı
ayarlayın. Her iki değişken de sunucuda kalır: `NEXT_PUBLIC_` önekleri yoktur ve istemci yalnızca
Server Components içinde çalışır.

İstemciyi bir kez oluşturun ve paylaşın:

```ts title="src/lib/verdin.ts"
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});
```

`verdin.collection('articles')` artık yalnızca şemanızın rotalarını kabul eder ve sonuçları
`Article` olarak tiplenir.

## 5. Yerleşimi değiştirin

Başlangıç yerleşimini değiştirin ve yeni sayfaların kullanmadığı `src/app/page.module.css`’i silin:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import Link from 'next/link';

export const metadata: Metadata = {
  title: 'My blog',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <header>
          <Link href="/">My blog</Link>
        </header>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

## 6. Makaleleri listeleyin

```tsx title="src/app/page.tsx"
import Link from 'next/link';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

export default async function Home() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['title', 'slug', 'excerpt', 'publishedAt'],
    populate: { category: { fields: ['name'] } },
    sort: ['publishedAt:desc'],
  });

  return (
    <>
      <h1>Articles</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.documentId}>
            <Link href={`/articles/${article.slug}`}>{article.title}</Link>
            {article.category && <small> in {article.category.name}</small>}
            {article.excerpt && <p>{article.excerpt}</p>}
          </li>
        ))}
      </ul>
    </>
  );
}
```

Sorgu, Strapi v5 biçimindeki REST çağrısıdır:
`GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc`.
`fields` yanıtı küçük tutar, `populate` ise kategoriyi yalnızca adıyla ekler. Public rolü yalnızca
yayınlanmış makaleleri okur.

`revalidate = 60` sayfayı build sırasında önceden oluşturur ve sonrasında en fazla dakikada bir
yeniler; böylece yayınlanan değişiklikler yeniden derleme olmadan görünür.

## 7. Makale başına bir sayfa ekleyin

Makale sayfası makalesini bir filtreyle slug’a göre bulur. `generateStaticParams` mevcut makaleleri
önceden oluşturur; sonradan yayınlanan makaleler ilk ziyaretlerinde oluşturulur.

```tsx title="src/app/articles/[slug]/page.tsx"
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { verdin } from '@/lib/verdin';

export const revalidate = 60;

type Props = { params: Promise<{ slug: string }> };

async function getArticle(slug: string) {
  const { data } = await verdin.collection('articles').find({
    filters: { slug: { $eq: slug } },
    populate: { category: true },
    pagination: { pageSize: 1 },
  });
  return data[0];
}

export async function generateStaticParams() {
  const { data: articles } = await verdin.collection('articles').find({
    fields: ['slug'],
    pagination: { pageSize: 100 },
  });
  return articles.map((article) => ({ slug: article.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getArticle((await params).slug);
  return { title: article?.title };
}

export default async function ArticlePage({ params }: Props) {
  const article = await getArticle((await params).slug);
  if (!article) notFound();
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Next.js 16’da `params` bir promise’tir: slug’ı okumadan önce await edin. Bilinmeyen bir slug hiçbir
makale bulmaz ve `notFound()` ile 404 yanıtını verir. `pageSize`, `[api].max_page_size` (varsayılan
100) ile sınırlıdır.

<Aside type="caution">
`marked` HTML’i temizlemez (sanitize etmez). Bu, kendi editörlerinizin yazdığı Markdown için sorun
değildir; içerik güvenilmeyen kişilerden gelebiliyorsa HTML’i göstermeden önce temizleyin.
</Aside>

## 8. Çalıştırın

```sh title="Terminal"
npm run dev
```

[http://localhost:3000](http://localhost:3000) adresini açın: liste yayınlanmış makalelerinizi gösterir
ve her biri kendi sayfasına bağlanır. `npm run build`, makaleleri önceden oluşturmak için getirdiğinden
Verdin’in çalışıyor olmasını gerektirir.

Sayfaları bir dakika içinde değil de içerik değiştiği anda yenilemek için bir Verdin webhook’unun
tetiklediği bir route handler’dan `revalidatePath` çağırın; bkz.
[Webhook’lar](/tr/guides/integrations/webhooks/).

Projeniz şimdi şöyle görünür:

<FileTree>
- blog/
  - .env.local
  - src/
    - verdin-types.ts `verdin types` tarafından üretilir
    - lib/
      - verdin.ts
    - app/
      - layout.tsx
      - page.tsx
      - articles/
        - [slug]/
          - page.tsx
</FileTree>

## 9. İsteğe bağlı: taslakları önizleme

Admin, kısa ömürlü bir önizleme token’ıyla bir taslağı sitenizde açabilir. Token o tek belgeyi,
taslaklar dâhil, okur ve başka hiçbir şeyi okumaz.

Önizleme token’ını `x-verdin-preview` başlığında gönderen bir istemci ekleyin:

```ts title="src/lib/verdin.ts" ins={11-17}
import { createClient } from '@verdin/client';
import type { VerdinSchema } from '@/verdin-types';

const url = process.env.VERDIN_URL ?? 'http://localhost:1337';

export const verdin = createClient<VerdinSchema>({
  url,
  token: process.env.VERDIN_TOKEN,
});

/** A client that reads one draft with the preview token from the admin's link. */
export function previewClient(previewToken: string) {
  return createClient<VerdinSchema>({
    url,
    headers: { 'x-verdin-preview': previewToken },
  });
}
```

Ardından sayfa. `searchParams` okuduğu için Next.js onu her istekte oluşturur; token `preview` sorgu
parametresi olarak gelir:

```tsx title="src/app/preview/[documentId]/page.tsx"
import { VerdinError } from '@verdin/client';
import { notFound } from 'next/navigation';
import { marked } from 'marked';
import { previewClient } from '@/lib/verdin';

type Props = {
  params: Promise<{ documentId: string }>;
  searchParams: Promise<{ preview?: string }>;
};

export default async function PreviewPage({ params, searchParams }: Props) {
  const { documentId } = await params;
  const { preview } = await searchParams;
  if (!preview) notFound();

  let article;
  try {
    ({ data: article } = await previewClient(preview)
      .collection('articles')
      .findOne(documentId, { status: 'draft', populate: { category: true } }));
  } catch (error) {
    if (error instanceof VerdinError) {
      return <p>This preview link is invalid or has expired.</p>;
    }
    throw error;
  }
  const html = await marked.parse(article.body ?? '');

  return (
    <article>
      <p>
        <strong>Draft preview</strong>
      </p>
      <h1>{article.title}</h1>
      {article.category && <p>Category: {article.category.name}</p>}
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}
```

Bir önizleme token’ı kayıtları listeleyemez; bu yüzden sayfa taslağı slug yerine `documentId` ile
arar. Şimdi Verdin’e sayfanın nerede olduğunu söyleyin:

<Steps>

1. Admin’de **Ayarlar → Özellikler**’i açın, **Önizleme**’yi açın ve **Önizleme URL’lerini
   yapılandır**’ı seçin.
2. **Article**’ın URL şablonunu `http://localhost:3000/preview/{documentId}` olarak ayarlayın ve
   kaydedin. Verdin token’ı `?preview=…` olarak ekler.
3. Bir makale açın, değiştirin ve **Taslağı kaydet**’i, ardından **Önizlemeyi aç**’ı seçin.

</Steps>

Sayfa taslağı gösterir. Bağlantılar varsayılan olarak 60 dakika geçerlidir. Yer tutucular ve ayarlar
için [Önizleme](/tr/guides/content/preview/) sayfasına, önizlemeden düzenlemek için
[Görsel düzenleme](/tr/guides/frontend/visual-editing/) sayfasına bakın.
