튜토리얼: Astro로 블로그 만들기

이 튜토리얼에서는 Verdin에서 콘텐츠를 읽는 정적 블로그를 Astro로 만듭니다. 글을 나열하는 홈 페이지, 카테고리와 함께 /articles/<slug>/에 있는 글마다 페이지 하나, 그리고 선택적으로 관리자의 미리 보기 링크에서 초안을 보여 주는 페이지입니다. 스키마로 생성한 타입과 함께 타입 클라이언트 @verdin/client를 씁니다.

Astro 7.3(create-astro 5.2)과 Node.js 22.12 이상, Verdin과 @verdin/client 0.10 기준으로 작성했습니다. Next.js 튜토리얼은 같은 블로그를 Next.js로 만듭니다.

시작하기 전에

섹션 제목: “시작하기 전에”

PATH에 verdin 바이너리(빠른 시작 참고), Node.js, Git이 필요합니다. 결과적으로 두 폴더가 나란히 생깁니다. Verdin 프로젝트인 cms와 Astro 사이트인 blog입니다.

1. 블로그 스키마로 Verdin 설정

섹션 제목: “1. 블로그 스키마로 Verdin 설정”

저장소의 examples/blog 프로젝트는 블로그를 모델링합니다. 제목, slug, 요약, Markdown body, 카테고리, 태그를 가진 글과, homepage 싱글 타입, 컴포넌트 몇 개입니다.

  1. Verdin 프로젝트를 만들고 예제 스키마를 복사합니다.

  2. 시작합니다.

    처음 시작하면 네 콘텐츠 타입의 테이블이 만들어집니다.

  3. http://localhost:1337/admin/을 열고 첫 관리자를 만듭니다.

  4. 컬렉션 아래에서 Category를 열고, 새 항목을 선택하고, 이름을 News로 한 뒤 저장합니다.

  5. Article을 열고, 새 항목을 선택하고, 제목, 요약, Markdown 본문을 채웁니다. slug는 제목에서 생성됩니다. 카테고리로 News를 고르고 게시를 선택합니다. 같은 방법으로 글을 하나 더 추가합니다.

  6. 설정 → 공개 접근을 열고 Article과 Category에 대해 목록 조회와 단건 조회를 허용한 뒤 저장을 선택합니다.

API가 응답하는지 확인합니다.

참고

관계를 populate하려면 대상에 대한 읽기 권한이 필요합니다. Category에 목록 조회가 없으면 populate=category는 invalid key `category` in populate와 함께 400으로 응답합니다.

2. Astro 프로젝트 만들기

섹션 제목: “2. Astro 프로젝트 만들기”

새 터미널에서 cms 옆에 만듭니다.

marked는 body 필드의 Markdown을 HTML로 바꿉니다.

3. 타입 생성

섹션 제목: “3. 타입 생성”

verdin types는 스키마를 읽고 콘텐츠 타입과 컴포넌트마다 TypeScript 인터페이스 하나와, 클라이언트용 라우트 맵 VerdinSchema를 씁니다. Verdin 프로젝트의 설정을 가리키며 blog에서 실행하세요.

파일에는 다음 등이 들어 있습니다.

관계, 미디어, 컴포넌트는 populate했을 때만 API가 반환하므로 선택 속성입니다. 스키마가 바뀔 때마다 명령을 다시 실행하세요.

4. Verdin에 연결

섹션 제목: “4. Verdin에 연결”

Astro의 타입 있는 환경에 서버 URL과 선택 사항인 API 토큰을 선언합니다.

토큰이 없으면 클라이언트는 1단계에서 연 공개 역할로 읽습니다. 대신 토큰으로 읽으려면 설정 → API 토큰에서 읽기 전용 토큰을 만들고 .env에 VERDIN_TOKEN=…으로 넣으세요.

클라이언트를 한 번 만들어 공유합니다.

이제 verdin.collection('articles')는 스키마의 라우트만 받으며, 결과의 타입은 Article입니다.

5. 레이아웃 추가

섹션 제목: “5. 레이아웃 추가”

시작 페이지의 HTML을 페이지들이 공유하는 레이아웃으로 바꿉니다.

6. 글 나열

섹션 제목: “6. 글 나열”

이 쿼리는 Strapi v5 형식의 REST 호출 GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc입니다. fields는 응답을 작게 유지하고, populate는 이름만 가진 카테고리를 추가합니다. 공개 역할은 게시된 글만 읽습니다.

7. 글마다 페이지 추가

섹션 제목: “7. 글마다 페이지 추가”

Astro가 글마다 페이지 하나를 빌드합니다. getStaticPaths가 카테고리와 함께 글을 가져와 각각을 페이지로 넘깁니다.

pageSize는 [api].max_page_size(기본 100)로 제한됩니다. 글이 더 많으면 meta.pagination.pageCount를 써서 반복문으로 페이지를 가져오세요.

주의

marked는 HTML을 정화하지 않습니다. 여러분의 편집자가 쓰는 Markdown이라면 괜찮지만, 신뢰할 수 없는 사람이 콘텐츠를 쓸 수 있다면 렌더링하기 전에 HTML을 정화하세요.

8. 실행

섹션 제목: “8. 실행”

http://localhost:4321을 엽니다. 목록에 게시된 글이 나오고, 각 글이 페이지로 연결됩니다. npm run build는 정적 사이트를 dist/에 씁니다.

정적 빌드는 콘텐츠를 한 번만 읽습니다. 변경을 게시하려면 콘텐츠가 바뀔 때 사이트를 다시 빌드하세요. 예를 들어 웹훅이나 배포 훅으로 합니다. 배포와 CDN을 참고하세요.

이제 프로젝트는 다음과 같습니다.

  • 디렉터리blog/
    • astro.config.mjs
    • 디렉터리src/
      • verdin-types.ts verdin types가 생성
      • 디렉터리lib/
        • verdin.ts
      • 디렉터리layouts/
        • Layout.astro
      • 디렉터리pages/
        • index.astro
        • 디렉터리articles/
          • [slug].astro

9. 선택 사항: 초안 미리 보기

섹션 제목: “9. 선택 사항: 초안 미리 보기”

관리자는 수명이 짧은 미리 보기 토큰으로 사이트에서 초안을 열 수 있습니다. 토큰은 초안을 포함해 그 문서 하나만 읽습니다. 초안은 빌드 후에도 바뀌므로 미리 보기 페이지는 요청마다 렌더링하며, 이를 위해 어댑터가 필요합니다.

x-verdin-preview 헤더로 미리 보기 토큰을 보내는 클라이언트를 추가합니다.

그다음 페이지입니다. prerender = false로 요청 시 렌더링하며, 토큰은 preview 쿼리 파라미터로 옵니다.

미리 보기 토큰은 항목을 나열할 수 없으므로, 페이지는 slug가 아니라 documentId로 초안을 찾습니다. 이제 Verdin에 페이지 위치를 알려 줍니다.

  1. 관리자 패널에서 설정 → 기능을 열고, 미리 보기를 켜고, 미리 보기 URL 구성을 선택합니다.
  2. Article의 URL 템플릿을 http://localhost:4321/preview/{documentId}로 설정하고 저장합니다. Verdin이 토큰을 ?preview=…로 붙입니다.
  3. 글을 열고, 바꾸고, 초안 저장을 선택한 뒤 미리 보기 열기를 선택합니다.

페이지에 초안이 나옵니다. 링크는 기본적으로 60분 동안 유효합니다. 자리 표시자와 설정은 미리 보기를, 미리 보기에서 편집하려면 비주얼 에디팅을 참고하세요.
