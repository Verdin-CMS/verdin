여러 인스턴스 실행

Verdin은 상태를 데이터베이스에 두므로, 가용성이나 부하 분산을 위해 같은 프로젝트의 인스턴스 여러 개를 로드 밸런서 뒤에서 실행할 수 있습니다. 이 페이지에서는 인스턴스가 공유하는 것, 각 인스턴스가 따로 가지는 것, 중요한 설정을 나열합니다.

체크리스트

섹션 제목: “체크리스트”
  • 공유 데이터베이스. PostgreSQL, MySQL, MariaDB. SQLite는 한 머신의 파일이므로 여러 인스턴스에서 동작하지 않습니다.
  • 모든 곳에서 같은 설정. 모든 인스턴스가 같은 verdin.toml, 스키마 파일, 시크릿(VERDIN_ADMIN_JWT_SECRET, VERDIN_TOKEN_PEPPER, VERDIN_SSO_<ID>_SECRET…)을 씁니다. 시크릿이 다르면 한 인스턴스에서 만든 세션과 API 토큰을 다른 인스턴스가 거부합니다.
  • 프로덕션 모드. verdin dev가 아니라 verdin start를 실행하세요. 스키마는 개발 환경에서 바꾸고, 커밋하고, 배포마다 한 번 마이그레이션하세요.
  • 공유 미디어 스토리지. S3 프로바이더([upload] provider = { name = "s3", … })를 쓰거나, 로컬 프로바이더라면 모든 인스턴스에 같은 볼륨을 마운트하세요.
  • 헬스 체크. 로드 밸런서는 데이터베이스에 연결할 수 없으면 503으로 응답하는 GET /_ready를 보게 하세요. GET /_health는 프로세스가 살아 있다는 것만 알려 주므로 liveness에 쓰세요.
  • 공유 이벤트 버스. 모든 인스턴스에 [cluster].bus = "database"를 설정해 실시간 이벤트, 프레즌스, 캐시 무효화, 검색 업데이트가 모든 인스턴스에 도달하게 하세요(공유 이벤트 버스 참고).
  • 플러그인 작업은 인스턴스 하나에서. 하나를 뺀 모든 인스턴스에 [plugins].run_jobs = false를 설정하세요. 그러지 않으면 인스턴스마다 예약된 작업을 실행합니다.
  • 인스턴스별 메트릭. [metrics].enabled = true이면 각 인스턴스가 자체 /_metrics를 제공합니다. 각각 스크레이프하세요.

여러 인스턴스에서의 마이그레이션

섹션 제목: “여러 인스턴스에서의 마이그레이션”

verdin start --migrate는 모든 인스턴스에서 동시에 실행해도 안전합니다. 마이그레이션 실행마다 데이터베이스에서 잠금을 잡으므로(PostgreSQL은 advisory lock, MySQL과 MariaDB는 GET_LOCK, 최대 60초 대기), 첫 인스턴스가 단계를 적용하고 나머지는 데이터베이스가 최신 상태임을 확인합니다.

롤링 배포 중에는 이전 버전의 인스턴스가 한동안 마이그레이션된 데이터베이스로 계속 실행됩니다. safe 단계는 테이블 생성, nullable이거나 기본값이 있는 컬럼과 인덱스 추가, 텍스트 컬럼 확장, enum 값 추가이며, 이전 버전은 이를 알아차리지 못합니다. risky나 destructive 단계(verdin migrate apply --allow risky|destructive)는 이전 스키마의 인스턴스가 더 이상 그 데이터를 필요로 하지 않을 때 별도 배포에서 적용하세요. 스키마 마이그레이션을 참고하세요.

공유되는 것

섹션 제목: “공유되는 것”
대상 방식
관리자 세션, API 토큰, 권한 데이터베이스에 있습니다. sticky 세션이 필요 없습니다.
기능 스위치, 플러그인 스위치, 로케일, 검토 워크플로 데이터베이스에 있습니다. 각 인스턴스가 [server].sync_interval_secs(10초)마다 다시 읽으므로, 한 인스턴스에서 바꾼 내용이 그 시간 안에 다른 인스턴스에 반영됩니다.
웹훅 전송 데이터베이스의 큐. 인스턴스가 보내기 전에 전송을 가져가므로 각 전송은 한 번만 나갑니다.
예약된 릴리스 실행 전에 데이터베이스에서 가져가므로 각 릴리스는 한 번만 실행됩니다.
일일 다이제스트 하루치 실행을 데이터베이스에서 가져가므로 관리자는 이메일을 한 통만 받습니다.
패스키 챌린지 사용한 챌린지를 데이터베이스에 기록하므로, 인스턴스 전체에서 각 챌린지는 한 번만 응답됩니다.
감사 로그 정리 모든 인스턴스에서 실행됩니다. 오래된 행을 두 번 삭제해도 문제가 없습니다.
플러그인 키-값 저장소 데이터베이스에 있습니다.
실시간 이벤트, 프레즌스, 소프트 잠금 이벤트 버스를 쓰면, 어느 인스턴스에 연결된 클라이언트든 모든 인스턴스의 이벤트를 받고 항목을 편집하는 모든 관리자를 봅니다.
익명 응답 캐시 이벤트 버스를 쓰면 어느 인스턴스에서든 쓰기가 모든 인스턴스의 캐시를 비웁니다.
검색 인덱스 이벤트 버스를 쓰면 각 인스턴스가 다른 인스턴스가 바꾼 항목을 다시 읽고 인덱싱합니다.
변환된 이미지 이벤트 버스를 쓰면 바뀌거나 삭제된 파일이 모든 인스턴스의 변환 캐시에서 빠집니다.

인스턴스마다 남는 것

섹션 제목: “인스턴스마다 남는 것”
  • 요청 한도는 인스턴스마다 셉니다. 인스턴스가 n개면 클라이언트는 분당 최대 [api].public_rate_limit의 n배만큼 요청할 수 있습니다. 전역 한도가 필요하면 로드 밸런서에서 강제하세요.
  • 이벤트 버스가 없으면([cluster].bus = "none", 기본값) 실시간 이벤트와 프레즌스는 클라이언트가 연결된 인스턴스의 것이고(이벤트 스트림에는 sticky 세션을 쓰세요), 쓰기는 자기 인스턴스의 응답 캐시만 비우며 ([api].cache_ttl_secs는 몇 초나 0으로 두세요), 검색 인덱스는 자기 인스턴스가 처리한 쓰기만 따라갑니다.
  • 검색 인덱스([search])는 인스턴스마다 디스크에 있습니다. 이벤트 버스를 쓰면 인스턴스가 서로의 변경을 발생하는 대로 인덱싱합니다. 빈 인덱스 디렉터리로 시작하는 인스턴스는 데이터베이스에서 인덱스를 만듭니다. 인스턴스가 다운된 동안 생긴 변경은 인덱스를 다시 만들 때 반영됩니다. 시작하기 전에 디렉터리를 삭제하거나 배포 후 다시 만드세요.
  • 이미지 변환([upload.transforms])은 인스턴스마다 cache_dir 아래에 캐시됩니다. 공유하려면 /uploads 앞에 CDN을 두세요.
  • 예약된 플러그인 작업: 위의 run_jobs를 참고하세요.

공유 이벤트 버스

섹션 제목: “공유 이벤트 버스”

일부는 메모리에서 일어납니다. 실시간 스트림, 누가 어떤 항목을 편집 중인지, 익명 응답 캐시, 검색 인덱스가 그렇습니다. 이벤트 버스는 이들을 일어난 인스턴스에서 다른 인스턴스로 전달합니다.

또는 모든 인스턴스에 VERDIN_CLUSTER__BUS=database. 버스는 프로젝트의 데이터베이스를 쓰므로 다른 서비스가 필요 없습니다.

  • PostgreSQL: 인스턴스가 각 이벤트를 vd_cluster_events 테이블에 쓰고 NOTIFY로 다른 인스턴스를 깨웁니다. 각 인스턴스는 풀 연결 하나를 LISTEN용으로 유지합니다. 알림에는 보낸 쪽 이름만 들어 있으므로 어떤 크기의 이벤트든 PostgreSQL의 8000바이트 제한 아래에 머뭅니다. 연결이 끊기면 인스턴스가 다시 연결하고 테이블을 읽어 따라잡습니다. 알림이 유실될 경우를 대비해 30초마다 테이블도 읽습니다.
  • MySQL, MariaDB, SQLite: 각 인스턴스가 poll_interval_ms(기본 1000)마다 vd_cluster_events의 새 행을 읽습니다. 쿼리는 기본 키를 쓰므로 빈 테이블을 읽는 비용은 작습니다. 더 빠른 업데이트가 필요하면 간격을 낮추세요. 한 인스턴스의 변경은 그 간격 안에 다른 인스턴스에 도달합니다.

전달되는 것: 콘텐츠 쓰기(실시간 스트림, 응답 캐시, 변경된 항목을 다시 읽는 검색 인덱스로), 미디어 변경(스트림, 캐시, 변환 캐시), 프레즌스 하트비트, 관리자용 댓글과 작업 알림. 각 인스턴스는 자기 이벤트를 무시합니다. 웹훅, CDN 퍼지, 기록, 감사 로그, 플러그인 훅은 전달되지 않습니다. 변경을 만든 인스턴스가 한 번 실행합니다.

행은 10분 뒤에 삭제됩니다. 새 인스턴스는 이전 이벤트가 아니라 다음 이벤트부터 시작합니다. 따라잡지 못하거나 데이터베이스 연결을 잃은 인스턴스는 쓰기를 붙잡는 대신 이벤트를 버립니다. verdin_cluster_events_total 메트릭이 보낸, 받은, 버린 이벤트를 셉니다(모니터링 참고).

각 인스턴스는 시작할 때마다 무작위 id로 버스에서 자신을 지칭하며, [cluster].instance_id를 설정했다면(예: 파드 이름) 그 값을 씁니다. id는 인스턴스를 구분할 뿐이며 다른 것은 여기에 의존하지 않습니다.

인스턴스가 하나라면 bus를 none으로 두세요. 이벤트는 메모리에 머물고 아무것도 쓰지 않습니다.

Redis와 NATS 백엔드는 아직 없습니다. 데이터베이스 버스는 다른 것을 실행하지 않고도 지원하는 모든 데이터베이스를 다룹니다.

설정

섹션 제목: “설정”

인스턴스마다 VERDIN_PLUGINS__RUN_JOBS=false로 run_jobs를 설정하세요.

데이터베이스 연결

섹션 제목: “데이터베이스 연결”

각 인스턴스는 최대 [database].pool_max개(기본 10)의 연결을 엽니다. 마이그레이션, 백업, 유지 보수를 위한 여유를 두고 인스턴스 수 × pool_max를 서버 한도보다 작게 유지하세요. PostgreSQL의 기본 한도는 연결 100개입니다. PostgreSQL에서는 이벤트 버스가 각 인스턴스의 연결 하나를 LISTEN용으로 유지합니다.
