Strapi에서 마이그레이션

verdin import strapi는 Strapi v4 또는 v5 프로젝트를 Verdin으로 가져옵니다. 콘텐츠 타입과 컴포넌트는 스키마 파일이 되고, 항목, 로케일, 미디어 라이브러리, 관계, 최종 사용자, 공개 권한을 가져옵니다. 이 페이지에서는 마이그레이션 과정을 안내하고 프런트엔드에서 바꿔야 할 것을 나열합니다. 기능별 비교는 Strapi 호환성을 참고하세요.

시작하기 전에

섹션 제목: “시작하기 전에”
  • strapi export를 실행할 수 있는 Strapi v4 또는 v5 프로젝트.
  • 새 Verdin 프로젝트(verdin new my-site), 또는 같은 이름의 스키마 파일이 없는 프로젝트. 빠른 시작을 참고하세요.
  • 가능하다면 Verdin 프로젝트가 프로덕션에서 쓸 데이터베이스와 미디어 스토리지. 가져오는 동안 파일이 설정된 업로드 프로바이더로 복사됩니다.

1. Strapi에서 내보내기

섹션 제목: “1. Strapi에서 내보내기”

Strapi 프로젝트에서 다음을 실행합니다.

Verdin은 암호화된 내보내기(.tar.gz.enc)를 읽을 수 없습니다. --no-encrypt로 다시 내보내세요. 압축하지 않은 내보내기(--no-compress, .tar)와 압축을 푼 내보내기 디렉터리도 동작합니다.

2. Verdin으로 가져오기

섹션 제목: “2. Verdin으로 가져오기”

  1. 프로젝트를 만들고 내보내기를 가져옵니다.

  2. 요약을 읽으세요. 임포터는 가져온 문서, 버전, 파일, 폴더, 로케일, 링크 수를 출력하고, 경고마다 한 줄씩 출력합니다.

  3. 개발 서버를 시작하고 관리자 패널을 엽니다.

명령은 다음 단계를 순서대로 실행합니다.

  1. api:: 콘텐츠 타입과 컴포넌트마다 스키마 파일 하나를 schema/에 씁니다. 변환한 스키마가 검증을 통과하지 못하면 아무것도 쓰지 않습니다.
  2. 데이터베이스를 마이그레이션합니다(safe 단계).
  3. 로케일, 미디어 폴더와 파일, 항목(모든 초안, 게시 버전, 로케일), 관계, 항목과 컴포넌트에 연결된 미디어를 가져옵니다.
  4. 최종 사용자, 그 역할, 공개와 인증 사용자 권한을 가져옵니다.
  5. 프로젝트 디렉터리에 strapi-id-map.json을 씁니다.
옵션 효과
--schema-only 스키마 파일을 쓴 뒤 멈춥니다. 먼저 스키마를 검토하거나 조정할 때 유용합니다.
--force 기존 스키마 파일을 덮어쓰고, 이미 항목이 있는 콘텐츠 타입으로도 가져옵니다.

--force가 없으면, 쓸 스키마 파일이 이미 있거나 콘텐츠 타입에 이미 항목이 있을 때 가져오기가 멈춥니다.

옮겨지는 것

섹션 제목: “옮겨지는 것”
Strapi Verdin
api::… 콘텐츠 타입과 컴포넌트 collectionName, 초안과 게시, i18n 옵션, 필드 옵션(required, private, unique, 길이, regex, 기본값…)을 유지한 스키마 파일
api:: 타입 사이의 관계 같은 관계
컴포넌트 안의 관계 oneWay / manyWay 참조
다형성 관계(morphToOne, morphToMany, morphOne, morphMany) 같은 관계, 가져온 콘텐츠 타입으로 가는 링크 포함
미디어 필드(컴포넌트 안 포함) 미디어 필드
v5 행(초안과 게시) 초안과 게시 버전
v4 행 초안, 그리고 publishedAt이 설정되어 있으면 게시 버전. localizations는 한 문서의 로케일이 됨
plugin::i18n.locale 로케일(Strapi의 기본 로케일이 계속 기본값)
plugin::upload.file과 folder 미디어 라이브러리 파일(포맷 포함)과 폴더
password 필드 Strapi의 bcrypt 해시를 유지한 password 필드
사용자 정의 필드(customField) customField를 유지한 속성. 아래 참고
조건부 필드(conditions, Strapi 5.17) 스키마에 유지되고 편집기가 적용
plugin::users-permissions.user bcrypt 비밀번호(다음 로그인 때 Argon2id로 다시 해싱), confirmed, blocked를 가진 최종 사용자
Users & Permissions 역할 Public 역할의 권한은 Verdin의 공개 권한이 되고, Authenticated와 사용자 지정 역할은 최종 사용자 역할이 됨
콘텐츠 타입과 업로드에 대한 역할 권한 find, findOne, create, update, delete 권한. 업로드는 find, findOne, upload, destroy

옮겨지지 않는 것

섹션 제목: “옮겨지지 않는 것”

경고로 보고되는 것:

  • 관리자 사용자, 최종 사용자, 다른 플러그인 타입으로 가는 관계(api:: 대상만 가져옴). createdBy / updatedBy 필드는 빠집니다.
  • text, richtext, blocks, json 속성의 unique(Verdin은 짧은 텍스트 타입에서 지원).
  • Verdin이 모르는 속성 타입, 컴포넌트 안에 저장할 수 없는 관계 타입.
  • inversedBy / mappedBy가 상대편과 맞지 않는 관계의 한쪽.
  • 올바르지 않은 로케일 코드.

전혀 가져오지 않는 것: 관리자 사용자와 관리자 역할, API 토큰, transfer 토큰, 웹훅, 릴리스, 검토 워크플로 단계, 콘텐츠 기록과 감사 로그, Strapi 플러그인의 설정. Strapi 코드(컨트롤러, 서비스, 라우트, 정책, 미들웨어, 라이프사이클 훅, cron 작업, 관리자 사용자 정의)는 변환되지 않습니다. 사용자 정의 코드 다시 만들기에 설명된 대로 다시 만드세요.

참고

사용자 정의 필드는 plugin::color-picker.color 같은 customField 이름을 유지합니다. 편집기는 그 필드를 제공하는 플러그인으로 보여 주며, 그런 플러그인이 없으면 저장 타입의 입력으로 대체합니다.

id 맵

섹션 제목: “id 맵”

Verdin은 새 문서 id를 만듭니다. Strapi의 documentId는 24자이고 Verdin의 것은 26자이므로 모든 문서가 새 id를 받습니다. 숫자 id도 바뀝니다. strapi-id-map.json이 매핑을 기록합니다.

  • documents의 키는 Verdin 콘텐츠 타입 uid(api::article, Strapi의 api::article.article)이고, 그 아래 키는 Strapi documentId(v5) 또는 행 id(v4: id 하나가 문서의 모든 로케일을 나타냄)입니다.
  • files는 Strapi 파일 id를 Verdin 파일 id에 매핑합니다.

CMS 밖에 저장된 id를 다시 쓸 때 쓰세요. 프런트엔드 코드의 링크, 다른 데이터베이스의 id, 분석, 북마크 등입니다.

결과 확인

섹션 제목: “결과 확인”
  1. verdin schema check가 통과하고, verdin migrate plan이 데이터베이스가 최신이라고 알려 줍니다.
  2. 관리자 패널에서 각 컬렉션을 열고 항목, 초안, 로케일 수를 Strapi와 비교합니다.
  3. 관계, 컴포넌트, 다이나믹 존, 미디어가 있는 항목 몇 개를 열어 링크가 올바른 문서와 파일을 가리키는지 확인합니다.
  4. 미디어 라이브러리를 열고 폴더와 이미지(포맷 포함)가 있는지 확인합니다.
  5. 설정 → 공개 접근과 설정 → 최종 사용자에서 가져온 권한과 역할을 검토합니다.
  6. 프런트엔드처럼 API를 호출하고 응답을 Strapi의 것과 비교합니다.

그다음 schema/를 커밋하고, 관리자, API 토큰, 웹훅을 만들고, 배포하세요 (프로덕션 체크리스트 참고).

프런트엔드 변경

섹션 제목: “프런트엔드 변경”

콘텐츠 API는 Strapi v5의 REST와 GraphQL 형식을 따르므로 대부분의 요청이 그대로 동작합니다. 다음을 바꾸세요.

  • 기본 URL. 프런트엔드가 Verdin 서버를 가리키게 하세요. 콘텐츠 API는 /api([api].prefix) 아래에 있고, GraphQL은 설정 → 기능에서 켜면 /graphql에 있습니다.
  • API 토큰. 토큰은 가져오지 않습니다. 설정 → API 토큰에서 새로 만들고 프런트엔드 환경 변수에서 바꾸세요.
  • 문서 id. 모든 documentId와 숫자 id가 새로 바뀝니다. 프런트엔드에 하드코딩한 id를 strapi-id-map.json의 값으로 바꾸거나, 더 좋은 방법으로 slug나 다른 uid 필드로 항목을 찾으세요.
  • 미디어 URL. 파일 URL은 새 프로바이더를 가리킵니다. 로컬 프로바이더는 Verdin 서버의 /uploads/…, S3는 [upload.provider].public_url입니다. 프레임워크가 허용하는 이미지 도메인(예: Next.js의 images.remotePatterns)을 업데이트하세요.
  • 로그인한 최종 사용자는 다시 로그인해야 합니다. 비밀번호는 동작하지만 Strapi가 발급한 JWT는 동작하지 않습니다.
  • CORS. 브라우저가 다른 출처에서 API를 호출하면 [api].cors_origins에 그 출처를 나열하세요.
  • 웹훅. 설정 → 웹훅에서 다시 만드세요. Strapi의 entry.draft-discard 이벤트는 entry.discard-draft라고 부르며, 전송은 서명됩니다(웹훅 참고).
  • Strapi v4 프런트엔드는 v5 변경 사항도 필요합니다. attributes 없는 평평한 응답, URL에서 id 대신 documentId, publicationState=preview 대신 status=draft입니다.

타입이 있는 접근을 원하면 verdin types로 TypeScript 타입을 생성하고 타입 클라이언트를 쓰세요.

사용자 정의 코드 다시 만들기

섹션 제목: “사용자 정의 코드 다시 만들기”

src/의 코드는 WebAssembly 플러그인으로 옮깁니다. 사용자 정의 코드 이식에서는 실제 프로젝트의 라이프사이클, 라우트, cron 작업, bootstrap을 예제 플러그인과 함께 차근차근 살펴봅니다.

Strapi Verdin
라이프사이클 훅, document service 미들웨어 플러그인 훅(beforeCreate, afterUpdate…)
사용자 정의 라우트와 컨트롤러 /api/plugins/<name>/ 아래의 플러그인 라우트
src/index.js의 bootstrap()(시딩, 공개 권한 설정) 플러그인의 시작 함수([startup]), 공개 역할에는 public_permissions 권한
Cron 작업 플러그인 작업([[jobs]])
폼 제출을 저장하는 사용자 정의 엔드포인트 기본 제공 폼
사용자 정의 필드 플러그인 사용자 정의 필드
관리자 위젯 플러그인 위젯, 또는 기본 제공 대시보드 위젯
관리자 로고, 색상, 텍스트 verdin.toml의 [admin.branding]
config/*.js verdin.toml과 환경 변수(설정 레퍼런스)
