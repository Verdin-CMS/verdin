아키텍처 개요

이 섹션은 Verdin 자체를 작업하는 사람들을 위한 것입니다. 서버와 관리자 패널이 어떻게 구성되어 있는지, 왜 그렇게 만들었는지, 코드를 어디서부터 읽으면 되는지 설명합니다. Verdin을 사용하려면 대신 빠른 시작부터 보세요.

Verdin은 Strapi v5를 따르는, Rust로 작성한 헤드리스 CMS입니다. 콘텐츠를 시각적으로 또는 JSON 파일로 모델링하면 REST와 GraphQL API, 그리고 관리자 패널이 생깁니다. 서버, CLI, Angular 관리자 패널을 담은 바이너리 하나로 배포되며, PostgreSQL, MySQL, MariaDB, SQLite에서 실행됩니다.

목표

섹션 제목: “목표”
  • 바이너리 하나. verdin에는 서버, CLI, 내장 관리자 패널이 들어 있습니다. 프로덕션에는 Node.js도 node_modules도 필요 없습니다.
  • 빠른 시작, 작은 메모리 사용량.
  • 데이터베이스 넷, 테스트 스위트 하나. PostgreSQL, MySQL, MariaDB, SQLite 모두 일급 지원이며 모두 같은 테스트로 검증합니다.
  • 코드로서의 스키마. 콘텐츠 타입은 git으로 버전 관리하는 JSON 파일입니다.
  • 합리적인 범위에서 Strapi v5 호환 REST API. 기존 프런트엔드가 약간의 변경만으로 옮겨 옵니다.
  • 모두 무료. 엔터프라이즈 에디션이 없습니다. SSO, 감사 로그, 검토 워크플로, 릴리스 등 모든 기능을 모두에게 제공합니다.

릴리스마다 제공된 것과 다음 계획은 로드맵에 있습니다.

목표가 아닌 것

섹션 제목: “목표가 아닌 것”
  • Strapi의 JavaScript 플러그인 실행. Verdin 플러그인은 WebAssembly 모듈입니다(플러그인 참고).
  • Strapi 데이터베이스를 그대로 읽기. 콘텐츠는 임포터로 옮겨 옵니다(Strapi에서 마이그레이션 참고).
  • 페이지 렌더링. Verdin은 헤드리스입니다.

설계 원칙

섹션 제목: “설계 원칙”
  1. 스키마가 진실의 원천입니다. 테이블, 검증, REST와 GraphQL API, OpenAPI 문서, 관리자 폼은 모두 스키마에서 도출합니다.
  2. SQL 식별자는 절대 요청에서 오지 않습니다. 테이블과 컬럼 이름은 검증된 스키마에서만 오며, 모든 값은 바인딩된 파라미터입니다.
  3. 방언은 일급입니다. “PostgreSQL에서 동작, MySQL은 나중에”는 없습니다. 모든 기능을 네 엔진 모두에서 테스트합니다.
  4. 기본적으로 안전합니다. 콘텐츠 API는 권한을 허용하기 전까지 닫혀 있고, private 필드는 절대 노출되지 않으며, 쿼리 깊이와 크기 한도는 항상 켜져 있습니다.
  5. 파괴적인 작업은 명시적입니다. 컬럼이나 테이블 삭제에는 승인이 필요하며, 부수 효과로 일어나는 일은 없습니다.
  6. 전역 상태가 없습니다. 서비스는 axum state와 생성자로 전달하며, 싱글톤이 없습니다.

전체 그림

섹션 제목: “전체 그림”

요청은 작은 공유 계층 스택을 거쳐 바이너리로 들어오고, API 라우터 중 하나에 도달한 뒤, 연결된 방언용 SQL을 만드는 Document Service에서 끝납니다. schema/*.json에서 로드한 스키마 레지스트리가 모든 단계에 정보를 주고, 마이그레이션 엔진이 데이터베이스를 스키마에 맞춥니다.

  • 콘텐츠 API는 [api].prefix(기본값 /api) 아래에 있습니다. 콘텐츠 타입별 REST 라우트, 업로드, OpenAPI 문서입니다. REST API를 참고하세요.
  • Admin API는 {admin.path}/api(기본값 /admin/api) 아래에 있으며, 관리자 패널이 하는 모든 일을 합니다. admin API를 참고하세요.
  • 해당 기능이 켜져 있으면 GraphQL은 /graphql, MCP는 /mcp에 있습니다. GraphQL 인자는 REST 파서가 읽는 것과 같은 파라미터 트리로 변환되므로, 두 API가 필터, 페이지네이션, populate, 권한 규칙을 공유합니다.
  • 관리자 패널은 [admin].path(기본값 /admin) 아래에 있으며, 바이너리나 [admin].assets_dir에서 제공합니다. 관리자 패널 내부 구조를 참고하세요.
  • 운영 라우트: /_health, /_ready, 그리고 메트릭이 켜져 있으면 /_metrics. 모니터링을 참고하세요.

모든 쓰기는 어떤 API에서 왔든 Document Service를 거칩니다. 데이터를 검증하고, 행과 링크 테이블을 트랜잭션 하나로 쓴 뒤, 리스너(웹훅, 검색 인덱스, 기록, 실시간, 감사 로그)에게 무엇이 바뀌었는지 알립니다.

기능을 켜거나 끌 때, 또는 verdin dev에서 콘텐츠 타입 빌더가 스키마를 바꿀 때, 라우터 전체를 다시 만들어 재시작 없이 제자리에서 교체합니다(ArcSwap).

기술 스택

섹션 제목: “기술 스택”

서버 (Rust, edition 2024)

섹션 제목: “서버 (Rust, edition 2024)”
영역 선택 이유
런타임 tokio 표준 비동기 런타임
HTTP axum, tower, tower-http CORS, 본문 한도, 타임아웃, 요청 id, tracing 미들웨어
SQL 드라이버 sqlx (postgres, mysql, sqlite) 비동기, 풀링, TLS. MySQL과 MariaDB는 드라이버 하나를 공유. SQLite는 컴파일되어 들어감
SQL 작성 Verdin 자체 빌더: verdin-migrate의 DDL, verdin-query와 verdin-content의 DML 테이블은 스키마가 정의하므로 SQL은 런타임에 만듦. 어차피 방언별 정밀 제어가 필요함(jsonb, datetime(3), binary collation, 타입 있는 NULL, SQLite 텍스트 형식). ORM도 sea-query도 없음
쿼리 문자열 verdin-query의 자체 대괄호 표기법 파서 Strapi 스타일 filters[title][$eq]=…, 깊이·길이·쌍 한도 포함
JSON serde, serde_json —
Decimal rust_decimal 서버 안에서 정밀도 손실 없음
날짜 time —
문서 id ulid 정렬 가능, 26자, 이식 가능
OpenAPI verdin-api의 자체 생성기 레지스트리로 만드는 콘텐츠 타입별 경로와 스키마
GraphQL async-graphql (동적 스키마) 콘텐츠 스키마로 만듦
인증 argon2 (argon2id), hmac + sha2 기반 HS256 JWT 몇 줄의 HS256으로 RSA 스택을 끌어오지 않음
설정 figment (TOML + 환경 변수), dotenvy 계층화와 환경별 재정의
CLI clap —
로그 tracing, tracing-subscriber 기본은 사람이 읽기 좋은 형식, [log].format = "json"이면 JSON
요청 한도 verdin-api의 자체 고정 윈도 limiter 로그인 라우트와 선택 사항인 콘텐츠 API 한도
미디어 object_store, image, infer 로컬 디스크나 S3 호환 스토리지. 포맷과 MIME 판별
검색 tantivy 바이너리 안의 선택 사항인 전문 검색 인덱스
플러그인 extism WebAssembly 플러그인
이메일 lettre, reqwest SMTP, Resend, Postmark
관리자 내장 rust-embed (embed-admin 기능) 관리자 패널이 바이너리 안에 들어감
스키마 감시 notify verdin dev에서 다시 로드
오류 라이브러리는 thiserror, 바이너리는 anyhow —
테스트 cargo test, insta (DDL 스냅샷) 테스트 참고

문서

섹션 제목: “문서”

의존성 규칙. verdin-schema와 verdin-db가 기반입니다. verdin-migrate와 verdin-query가 그 위에, verdin-content가 그 위에, 그리고 verdin-auth, verdin-upload, verdin-search, verdin-plugins가 그 아래 계층들 위에 있습니다. verdin-api와 verdin-graphql은 꼭대기 근처에 있고, verdin 바이너리는 모든 것에 의존합니다. Cargo가 순환을 금지하며, 워크스페이스 전체에서 unsafe 코드를 금지합니다.

어디서부터 읽을까

섹션 제목: “어디서부터 읽을까”
이해하려는 것 읽을 곳
바이너리가 부팅하고 라우터를 조립하는 방법 crates/verdin/src/cli.rs(start), 그다음 crates/verdin/src/app.rs
스키마 형식과 검증 규칙 crates/verdin-schema/src/raw.rs, validate.rs, naming.rs
스키마가 테이블이 되는 방법 crates/verdin-migrate/src/derive.rs, 그다음 스토리지
마이그레이션 crates/verdin-migrate/src/diff.rs, plan.rs, apply.rs, 그리고 마이그레이션 엔진
콘텐츠 API 핸들러 crates/verdin-api/src/handlers.rs와 lib.rs
쿼리 파라미터 crates/verdin-query/src/params.rs(파서), parse.rs(검증), sql.rs(SQL)
읽기와 쓰기 crates/verdin-content/src/service.rs와 input.rs, 그리고 Document Service
관리자 패널 admin/src/app/app.routes.ts, 그다음 features/content/와 관리자 패널 내부 구조

GitHub에서 코드를 둘러보세요. 이 섹션의 나머지는 스토리지, 데이터베이스 계층, 마이그레이션, Document Service, 관리자 패널, 테스트, 결정 기록을 다룹니다.

사용자에게 보이는 동작은 다른 곳에 문서화되어 있습니다. 쿼리 파라미터는 REST API, 설정은 설정 레퍼런스, 명령은 CLI 레퍼런스, 보안 강화는 보안에 있습니다.
