Посібник: блог на Next.js

У цьому посібнику ви створите блог на Next.js з App Router, що читає вміст із Verdin: домашню сторінку зі списком статей, окрему сторінку для кожної статті на /articles/<slug> з її категорією і, за бажання, сторінку, що показує чернетки за посиланням попереднього перегляду з адмінки. Ви використаєте типізований клієнт @verdin/client із типами, згенерованими зі схеми, у Server Components.

Написано для Next.js 16.3 (create-next-app 16.3), React 19.2 і Node.js 20.9 або новішого, з Verdin і @verdin/client 0.10. Використовується типове кешування Next.js, без cacheComponents. Посібник з Astro будує той самий блог на Astro.

6. Виведіть список статей

Section titled “6. Виведіть список статей”

Цей запит — це REST-виклик GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc у форматі Strapi v5. fields тримає відповідь невеликою, а populate додає категорію лише з її назвою. Публічна роль читає лише опубліковані статті.

revalidate = 60 попередньо рендерить сторінку під час збірки й після цього оновлює її щонайбільше раз на хвилину, тож опубліковані зміни з’являються без перезбирання.

7. Додайте сторінку для кожної статті

Section titled “7. Додайте сторінку для кожної статті”

Сторінка статті знаходить свою статтю за slug через фільтр. generateStaticParams попередньо рендерить наявні статті; статті, опубліковані пізніше, рендеряться під час першого відвідування.

У Next.js 16 params — це проміс: дочекайтеся його, перш ніж читати slug. Невідомий slug не знаходить статті й відповідає 404 через notFound(). pageSize обмежено [api].max_page_size (типово 100).

Обережно

marked не санітизує HTML. Для Markdown, який пишуть ваші власні редактори, це нормально; якщо вміст може надходити від недовірених людей, санітизуйте HTML перед виведенням.

8. Запустіть

Section titled “8. Запустіть”

Відкрийте http://localhost:3000: список показує опубліковані статті, і кожна веде на свою сторінку. npm run build потребує запущеного Verdin, бо отримує статті для попереднього рендерингу.

Щоб оновлювати сторінки одразу після зміни вмісту, а не протягом хвилини, викликайте revalidatePath з обробника маршруту, який запускає вебхук Verdin; див. Вебхуки.

Тепер ваш проєкт виглядає так:

  • Каталогblog/
    • .env.local
    • Каталогsrc/
      • verdin-types.ts згенеровано verdin types
      • Каталогlib/
        • verdin.ts
      • Каталогapp/
        • layout.tsx
        • page.tsx
        • Каталогarticles/
          • Каталог[slug]/
            • page.tsx

9. Необов’язково: попередній перегляд чернеток

Section titled “9. Необов’язково: попередній перегляд чернеток”

Адмінка може відкрити чернетку на вашому сайті з короткочасним токеном попереднього перегляду. Токен читає цей один документ, включно з чернетками, і нічого більше.

Додайте клієнт, що надсилає токен попереднього перегляду в заголовку x-verdin-preview:

Потім сторінка. Вона читає searchParams, тож Next.js рендерить її на кожен запит; токен надходить як параметр запиту preview:

Токен попереднього перегляду не може переглядати списки записів, тож сторінка шукає чернетку за documentId, а не за slug. Тепер повідомте Verdin, де сторінка:

  1. В адмінці відкрийте Налаштування → Функції, увімкніть Попередній перегляд і виберіть Налаштувати URL попереднього перегляду.
  2. Задайте шаблон URL для Article як http://localhost:3000/preview/{documentId} і збережіть. Verdin додає токен як ?preview=….
  3. Відкрийте статтю, змініть її й виберіть Зберегти чернетку, потім виберіть Відкрити попередній перегляд.

Сторінка показує чернетку. Посилання типово діють 60 хвилин. Про заповнювачі й налаштування див. Попередній перегляд, а щоб редагувати з попереднього перегляду — Візуальне редагування.
