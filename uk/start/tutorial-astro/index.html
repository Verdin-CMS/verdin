Посібник: блог на Astro

У цьому посібнику ви створите статичний блог на Astro, що читає вміст із Verdin: домашню сторінку зі списком статей, окрему сторінку для кожної статті на /articles/<slug>/ з її категорією і, за бажання, сторінку, що показує чернетки за посиланням попереднього перегляду з адмінки. Ви використаєте типізований клієнт @verdin/client із типами, згенерованими зі схеми.

Написано для Astro 7.3 (create-astro 5.2) і Node.js 22.12 або новішого, з Verdin і @verdin/client 0.10. Посібник із Next.js будує той самий блог на Next.js.

Перш ніж почати

Section titled “Перш ніж почати”

Вам потрібні бінарник verdin у PATH (див. Швидкий старт), Node.js і Git. У результаті матимете дві папки поруч: cms — проєкт Verdin і blog — сайт на Astro.

6. Виведіть список статей

Section titled “6. Виведіть список статей”

Цей запит — це REST-виклик GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc у форматі Strapi v5. fields тримає відповідь невеликою, а populate додає категорію лише з її назвою. Публічна роль читає лише опубліковані статті.

7. Додайте сторінку для кожної статті

Section titled “7. Додайте сторінку для кожної статті”

Astro будує по сторінці на статтю. getStaticPaths отримує статті з їхньою категорією й передає кожну на її сторінку:

pageSize обмежено [api].max_page_size (типово 100). Якщо статей більше, отримуйте сторінки в циклі за meta.pagination.pageCount.

Обережно

marked не санітизує HTML. Для Markdown, який пишуть ваші власні редактори, це нормально; якщо вміст може надходити від недовірених людей, санітизуйте HTML перед виведенням.

8. Запустіть

Section titled “8. Запустіть”

Відкрийте http://localhost:4321: список показує опубліковані статті, і кожна веде на свою сторінку. npm run build записує статичний сайт у dist/.

Статична збірка читає вміст один раз. Щоб опублікувати зміни, перезбирайте сайт, коли вміст змінюється, наприклад із вебхука чи deploy hook; див. Розгортання і CDN.

Тепер ваш проєкт виглядає так:

  • Каталогblog/
    • astro.config.mjs
    • Каталогsrc/
      • verdin-types.ts згенеровано verdin types
      • Каталогlib/
        • verdin.ts
      • Каталогlayouts/
        • Layout.astro
      • Каталогpages/
        • index.astro
        • Каталогarticles/
          • [slug].astro

9. Необов’язково: попередній перегляд чернеток

Section titled “9. Необов’язково: попередній перегляд чернеток”

Адмінка може відкрити чернетку на вашому сайті з короткочасним токеном попереднього перегляду. Токен читає цей один документ, включно з чернетками, і нічого більше. Оскільки чернетки змінюються після збірки, сторінка попереднього перегляду рендериться на кожен запит, для чого потрібен адаптер:

Додайте клієнт, що надсилає токен попереднього перегляду в заголовку x-verdin-preview:

Потім сторінка. prerender = false рендерить її на вимогу; токен надходить як параметр запиту preview:

Токен попереднього перегляду не може переглядати списки записів, тож сторінка шукає чернетку за documentId, а не за slug. Тепер повідомте Verdin, де сторінка:

  1. В адмінці відкрийте Налаштування → Функції, увімкніть Попередній перегляд і виберіть Налаштувати URL попереднього перегляду.
  2. Задайте шаблон URL для Article як http://localhost:4321/preview/{documentId} і збережіть. Verdin додає токен як ?preview=….
  3. Відкрийте статтю, змініть її й виберіть Зберегти чернетку, потім виберіть Відкрити попередній перегляд.

Сторінка показує чернетку. Посилання типово діють 60 хвилин. Про заповнювачі й налаштування див. Попередній перегляд, а щоб редагувати з попереднього перегляду — Візуальне редагування.
