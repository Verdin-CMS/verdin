Довідник типів атрибутів

Атрибути — це поля типу вмісту чи компонента, оголошені в attributes його файлу схеми. На цій сторінці перелічено кожен type, параметри, які він приймає, як Verdin його перевіряє й зберігає і як він виглядає в API. Формат — як у Strapi v5; відмінності перелічено наприкінці.

Файли схеми суворі: невідомий ключ або параметр, якого тип не приймає, — це помилка, яку verdin schema check повідомляє зі шляхом (attributes.title.maxLength).

Параметри, які приймає кожен атрибут

Section titled “Параметри, які приймає кожен атрибут”
Параметр Типово Опис
type обов’язковий Один із типів нижче.
required false Значення має бути присутнім. Перевіряється під час публікації запису (чернетки можуть бути неповними) і під час кожного запису в тип без чернеток і публікації. Діє й усередині компонентів та динамічних зон.
private false Ніколи не повертається API вмісту й не використовується у filters чи sort. Атрибути password завжди приватні.
configurable true Прапорець Strapi для конструктора адмінки; зберігається як записано.
pluginOptions.i18n.localized true У локалізованому типі вмісту false робить значення спільним для всіх локалей замість окремого значення для кожної.
customField не задано plugin::<plugin>.<field> (або global::<field>): адмінка редагує атрибут власним полем плагіна. type визначає, як зберігається значення. Див. Плагіни.
conditions не задано Умовні поля Strapi ({ "visible": <JSON Logic> }). Редактор приховує поле, поки правило хибне, а сервер не вимагає заповнювати приховане поле.
default не задано Значення нових записів, коли запис не містить атрибута. Має бути коректним для типу. Не кожен тип його приймає (див. кожен тип).

Назви атрибутів починаються з літери, далі йдуть літери, цифри й _, щонайбільше 50 символів. У типах вмісту зарезервовані id, documentId, locale, publicationState, publishedAt, createdAt, updatedAt, createdBy і updatedBy; у компонентах — id. Дві назви, що відповідають одній колонці (metaTitle і meta_title), — помилка.

Де зберігаються значення

Section titled “Де зберігаються значення”

Кожен атрибут типу вмісту — це колонка таблиці типу (collectionName або назва в множині) з назвою в snake_case. Зв’язки й медіа натомість живуть у таблицях зв’язків. Чернетка та її опублікована версія — два рядки, по одному на локаль у локалізованих типах.

Типи колонок за базами даних:

Колонка PostgreSQL MySQL і MariaDB SQLite
varchar varchar(255) varchar(255) text
text text longtext text
integer integer int integer
bigint bigint bigint integer
double double precision double real
decimal numeric(p,s) decimal(p,s) text (точно)
boolean boolean tinyint(1) integer
date date date text
time time(3) time(3) text
datetime timestamptz(3) datetime(3) text
json jsonb json text

Тип вмісту може мати щонайбільше 60 атрибутів string, email, uid і enumeration (обмеження розміру рядка MySQL); для решти використовуйте text.

unique

Section titled “unique”

Типи, що приймають unique: true, отримують унікальний індекс за (column, locale, publication_state): два опубліковані записи чи дві чернетки в одній локалі не можуть мати однакове значення, а чернетка та її власна опублікована версія — можуть. Запис, що порушує це, не вдається з помилкою валідації для атрибута. Усередині компонентів unique приймається, але не забезпечується (значення компонентів зберігаються як JSON).

Текст

Section titled “Текст”

string

Section titled “string”

Один рядок тексту.

Параметр Опис
minLength, maxLength Межі довжини в символах. maxLength — щонайбільше 255.
regex Шаблон, якому має відповідати значення. Синтаксис, подібний до JavaScript, включно з look-around і зворотними посиланнями.
unique Див. unique.
default Рядок у межах, що відповідає regex.

Зберігається як varchar(255). API: рядок.

text

Section titled “text”

Довший простий текст (textarea в адмінці).

Параметр Опис
minLength, maxLength Межі довжини без верхньої межі.
default Рядок у межах.

Зберігається як text (longtext у MySQL). API: рядок.

richtext

Section titled “richtext”

Текст Markdown. Ті самі параметри, зберігання й API, що й у text; адмінка редагує його редактором Markdown.

blocks

Section titled “blocks”

Rich text у форматі blocks JSON Strapi: список блоків paragraph, heading (level від 1 до 6), list (format ordered або unordered, з дочірніми list-item, вкладеність до 8 рівнів), quote, code (необов’язковий language) і image. Вбудовані дочірні елементи — вузли text з позначками bold, italic, underline, strikethrough і code, а також вузли link. Щонайбільше 10 000 блоків.

Без параметрів, без default. Зберігається як JSON. API: список блоків як записано.

email

Section titled “email”

Адреса ел. пошти (name@domain.tld, без пробілів).

Параметр Опис
minLength, maxLength Межі довжини; maxLength щонайбільше 255.
unique Див. unique.
default Адреса ел. пошти.

Зберігається як varchar(255). API: рядок.

password

Section titled “password”

Секрет, що хешується під час запису з Argon2id.

Параметр Опис
minLength, maxLength Межі довжини пароля в тому вигляді, як його надіслано.

Без default. Завжди приватний: ніколи не повертається, не фільтрується й не сортується. Не дозволений усередині компонентів. Зберігається як varchar(255) (хеш). Імпорт зберігає наявні хеші bcrypt і Argon2 як є, тож імпортовані облікові записи можуть і далі входити.

uid

Section titled “uid”

Ідентифікатор для URL, як-от slug. Адмінка генерує його з targetField.

Параметр Опис
targetField Атрибут string або text того самого типу, з якого генерується значення.
minLength, maxLength Межі довжини; maxLength щонайбільше 255.
regex Шаблон, якому мають відповідати значення; без нього — ^[A-Za-z0-9\-_.~]*$.
default Коректне значення.

Завжди унікальний (див. unique). Зберігається як varchar(255). API: рядок.

enumeration

Section titled “enumeration”

Одне значення з фіксованого списку.

Параметр Опис
enum Значення: щонайменше одне, кожне від 1 до 255 символів, без дублікатів.
default Одне зі значень.

Зберігається як varchar(255). API: рядок. Запис будь-якого іншого значення не вдається.

Числа

Section titled “Числа”

integer

Section titled “integer”

32-бітне ціле число (від −2 147 483 648 до 2 147 483 647).

Параметр Опис
min, max Межі (цілі числа).
unique Див. unique.
default Ціле число в межах.

Зберігається як integer. API: число. Запис приймає числа й рядки з цілими числами.

biginteger

Section titled “biginteger”

64-бітне ціле число. Ті самі параметри, що й в integer.

Зберігається як bigint. API: рядок ("9007199254740993"), як у Strapi, бо числа JavaScript втрачають точність після 2⁵³. Запис приймає рядки й числа.

float

Section titled “float”

Число з рухомою комою подвійної точності. Ті самі параметри, що й в integer, з числовими межами.

Зберігається як double precision (double, real). API: число.

decimal

Section titled “decimal”

Точне десяткове число.

Параметр Типово Опис
precision 10 Загальна кількість цифр, від 1 до 38.
scale 2 Цифри після десяткової коми, щонайбільше precision.
min, max Межі.
unique Див. unique.
default Число в межах.

Значення округлюються до scale цифр (половина — від нуля, як це роблять бази даних) і відхиляються, коли мають більше ніж precision - scale цифр до коми. Запис приймає числа й числові рядки. Зберігається як numeric(precision,scale) (text у SQLite, тож нічого не округлюється). API: число, як його повертає Strapi. Цілі значення — це цілі числа (25, а не 25.0), а решта — найкоротше число з плаваючою комою, що зчитується назад однаково (12.5). З [api].decimal_as_string API натомість повертає точний рядок.

Дати й булеві значення

Section titled “Дати й булеві значення”

boolean

Section titled “boolean”

true або false. Приймає default. Зберігається як boolean (tinyint(1), integer). API: булеве значення.

date

Section titled “date”

Календарна дата, YYYY-MM-DD. Приймає unique і default. Зберігається як date. API: "2026-09-29".

time

Section titled “time”

Час доби, HH:MM, HH:MM:SS або HH:MM:SS.mmm. Приймає unique і default. Зберігається з точністю до мілісекунд. API: "14:30:00.000".

datetime

Section titled “datetime”

Момент часу: мітка часу ISO 8601 із поясом (Z або +02:00). Приймає unique і default. Зберігається в UTC з точністю до мілісекунд. API: "2026-09-29T12:30:00.000Z".

json

Section titled “json”

Будь-яке JSON-значення. Приймає default (будь-який JSON). Зберігається як jsonb (json, text). API: значення як записано. У filters JSON-атрибути підтримують лише $null і $notNull, і за ними не можна сортувати.

Медіа

Section titled “Медіа”

media

Section titled “media”

Файли з медіатеки.

Параметр Типово Опис
multiple false Містити список файлів замість одного.
allowedTypes будь-які Види файлів: images, videos, audios, files (усе інше).

Без default. Зберігається в таблиці зв’язків {table}_{attribute}_mda з порядком. Запис приймає id файлів: 12, { "id": 12 }, їх список або null. API: лише з populate; об’єкт файлу (url, mime, width, formats…, як у Strapi), їх список або null. Див. Медіа.

Зв’язки

Section titled “Зв’язки”

relation

Section titled “relation”

Посилання на документи іншого типу вмісту.

Параметр Опис
relation oneToOne, oneToMany, manyToOne, manyToMany, oneWay, manyWay або поліморфний вид (нижче).
target Цільовий тип вмісту: article, api::article або api::article.article.
inversedBy На стороні-власнику двостороннього зв’язку: атрибут цілі, що його віддзеркалює.
mappedBy На іншій стороні: атрибут-власник цілі.

Дві сторони двостороннього зв’язку мають узгоджуватися: oneToMany віддзеркалює manyToOne, oneToOne і manyToMany віддзеркалюють самі себе, а сторона mappedBy називає атрибут, чий inversedBy вказує назад. oneWay і manyWay іншої сторони не мають.

Посилання зберігаються в {table}_{attribute}_lnk на стороні-власнику (стороні без mappedBy), вказують на documentId цілі, з порядком. Запис приймає documentId:

Запис Значення
"d8f3…", { "documentId": "d8f3…" }, їх список Замінити посилання.
null або [] Видалити всі посилання.
{ "set": [...] } Замінити посилання.
{ "connect": [...], "disconnect": [...] } Додати й видалити посилання. Елемент connect може містити position: { "before": id }, { "after": id }, { "start": true } або { "end": true }.

API: лише з populate, як пов’язані документи (щонайбільше 1 000 на запис і зв’язок), або { "count": n } з populate[tags][count]=true. Див. Зв’язки.

Усередині компонентів дозволено лише oneWay і manyWay; компонент зберігає documentId.

Поліморфні зв’язки

Section titled “Поліморфні зв’язки”

relation також приймає поліморфні види, що пов’язують документи будь-якого типу вмісту:

relation Параметри Опис
morphToOne немає Посилається на один документ будь-якого типу.
morphToMany немає Посилається на документи будь-яких типів.
morphOne target, morphBy Зворотна сторона: читає посилання атрибута morphBy типу morphToOne чи morphToMany у target.
morphMany target, morphBy Те саме, для багатьох.

Власники зберігають пари (type, documentId) у {table}_{attribute}_mph. Запис приймає елементи { "__type": "api::article", "documentId": "…" } (один, список, null або { "set": [...] }). Заповнені елементи містять свій тип у __type. Не дозволені всередині компонентів.

Компоненти й динамічні зони

Section titled “Компоненти й динамічні зони”

component

Section titled “component”

Група полів, визначена в schema/components/<category>/<name>.json.

Параметр Типово Опис
component обов’язковий Uid компонента, category.name (shared.seo).
repeatable false Містити список елементів замість одного.
min, max Кількість елементів; лише з repeatable.

Без default: нові елементи отримують типові значення власних атрибутів. Зберігається як JSON у рядку запису, кожен елемент з id. Запис приймає об’єкт елемента (або список) з id, щоб зберегти наявний елемент. API: лише з populate, увесь елемент чи список. У filters можна фільтрувати за полями компонента (filters[seo][metaTitle][$eq]=…). Див. Компоненти й динамічні зони.

dynamiczone

Section titled “dynamiczone”

Список елементів, кожен з яких — один із кількох компонентів.

Параметр Опис
components Дозволені uid компонентів: щонайменше один, без дублікатів.
min, max Кількість елементів.

Кожен елемент містить __component зі своїм uid. Зберігається як JSON у рядку запису. API: лише з populate, увесь список. Фільтруйте за компонентом через filters[blocks][__component][$eq]=blocks.hero. Динамічні зони не можуть бути вкладені в компоненти.

Валідація між полями

Section titled “Валідація між полями”

Окрім параметрів окремих атрибутів, тип вмісту може оголошувати в validations правила для кількох полів, що перевіряються тоді ж, коли й required:

rule — вираз JSON Logic над записом, який має виконуватися. Він може використовувати var, ==, !=, ===, !==, <, >, <=, >=, !, !!, and, or, in, if, ?:, +, -, *, /, %, min, max і cat. message повідомляється для field (атрибута типу) або для запису. Це доповнення Verdin; у Strapi відповідника немає.

Відмінності від Strapi

Section titled “Відмінності від Strapi”
  • Компоненти зберігаються як JSON у рядку запису, а не в таблицях компонентів із таблицями з’єднань. Читання не потребує join-ів; як наслідок, атрибути password, поліморфні зв’язки й двосторонні зв’язки не можуть бути всередині компонентів, а unique там не забезпечується.
  • Заповнені компоненти повертаються цілком. populate для компонента чи динамічної зони повертає всі його поля; вибрати вкладені поля, як у Strapi, не можна.
  • Суворі файли схеми. Невідомі ключі й параметри, яких тип не приймає, — помилки, тоді як Strapi їх ігнорує. У pluginOptions читається лише i18n.localized; решта ігнорується.
  • string, email і uid обмежено 255 символами — розміром колонки, — замість помилки в базі даних.
  • conditions (умовні поля) працюють як у Strapi 5.17: приховані поля не обов’язкові.
  • validations — власна функція Verdin.
  • Решта відповідає Strapi v5: назви типів, їхні параметри, значення biginteger як рядки, запис зв’язків через connect, disconnect, set і position та формат blocks.
