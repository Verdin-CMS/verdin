Міграція зі Strapi

verdin import strapi переносить проєкт Strapi v4 чи v5 у Verdin: його типи вмісту й компоненти стають файлами схеми, а записи, локалі, медіатека, зв’язки, кінцеві користувачі та публічні дозволи імпортуються. На цій сторінці покроково описано міграцію й перелічено, що має змінити ваш фронтенд. Порівняння за функціями див. у Сумісність зі Strapi.

Перш ніж почати

Section titled “Перш ніж почати”
  • Проєкт Strapi v4 чи v5, у якому ви можете запустити strapi export.
  • Новий проєкт Verdin (verdin new my-site) або проєкт без файлів схеми з тими самими назвами. Див. швидкий старт.
  • За можливості — база даних і медіасховище, які проєкт Verdin використовуватиме в production: під час імпорту файли копіюються в налаштований провайдер завантажень.

1. Експорт зі Strapi

Section titled “1. Експорт зі Strapi”

У проєкті Strapi:

Verdin не може читати зашифровані експорти (.tar.gz.enc); експортуйте знову з --no-encrypt. Нестиснуті експорти (--no-compress, .tar) і розпакований каталог експорту теж працюють.

2. Імпорт у Verdin

Section titled “2. Імпорт у Verdin”

  1. Створіть проєкт та імпортуйте експорт:

  2. Прочитайте підсумок. Імпортер виводить, скільки документів, версій, файлів, папок, локалей і посилань він імпортував, а потім по рядку на кожне попередження.

  3. Запустіть сервер розробки й відкрийте адмін-панель:

Команда виконує такі кроки по черзі:

  1. Записує в schema/ по одному файлу схеми на кожен тип вмісту api:: і кожен компонент. Якщо перетворена схема не проходить валідацію, нічого не записується.
  2. Мігрує базу даних (безпечні кроки).
  3. Імпортує локалі, медіапапки й файли, записи (кожну чернетку, опубліковану версію й локаль), зв’язки та медіа, прикріплені до записів і компонентів.
  4. Імпортує кінцевих користувачів, їхні ролі, а також публічні й authenticated-дозволи.
  5. Записує strapi-id-map.json у каталог проєкту.
Параметр Дія
--schema-only Зупинитися після запису файлів схеми. Корисно, щоб спершу переглянути чи скоригувати схему.
--force Перезаписати наявні файли схеми й імпортувати в типи вмісту, що вже мають записи.

Без --force імпорт зупиняється, якщо файл схеми, який він записав би, уже існує або якщо тип вмісту вже має записи.

Що не переноситься

Section titled “Що не переноситься”

Повідомляється як попередження:

  • Зв’язки з адміністраторами, кінцевими користувачами чи типами інших плагінів (імпортуються лише цілі api::). Поля createdBy / updatedBy пропускаються.
  • unique для атрибутів text, richtext, blocks і json (Verdin підтримує його для коротких текстових типів).
  • Типи атрибутів, яких Verdin не знає, і типи зв’язків, які він не може зберігати всередині компонента.
  • Половинки зв’язків, чиї inversedBy / mappedBy не збігаються з іншою стороною.
  • Некоректні коди локалей.

Зовсім не імпортуються: адміністратори й ролі адміністраторів, API-токени, transfer tokens, вебхуки, релізи, етапи процесів перевірки, історія вмісту й журнали аудиту, а також налаштування плагінів Strapi. Ваш код Strapi — контролери, сервіси, маршрути, policies, middlewares, хуки lifecycle, cron-завдання й налаштування адмінки — не має у Verdin відповідника для перетворення; див. Перепишіть власний код.

Заувага

Власні поля зберігають свою назву customField, наприклад plugin::color-picker.color. Редактор показує їх за допомогою плагіна, що надає це поле, а якщо такого немає — звичайне поле введення для типу зберігання.

Мапа id

Section titled “Мапа id”

Verdin генерує нові id документів: documentId у Strapi мають 24 символи, а у Verdin — 26, тож кожен документ отримує новий. Числові id теж змінюються. strapi-id-map.json фіксує відповідність:

  • documents має ключі за uid типу вмісту Verdin (api::article, у Strapi — api::article.article), а далі за documentId Strapi (v5) або за id рядка (v4: один id означає всі локалі документа).
  • files зіставляє id файлів Strapi з id файлів Verdin.

Використовуйте її, щоб переписати id, збережені поза CMS: посилання в коді фронтенду, id в іншій базі даних, аналітиці, закладках.

Перевірте результат

Section titled “Перевірте результат”
  1. verdin schema check проходить, а verdin migrate plan каже, що база даних актуальна.
  2. В адмін-панелі відкрийте кожну колекцію й порівняйте кількість записів, чернеток і локалей зі Strapi.
  3. Відкрийте кілька записів зі зв’язками, компонентами, динамічними зонами й медіа та перевірте, що посилання ведуть на правильні документи й файли.
  4. Відкрийте Медіатека й перевірте, що папки й зображення (з їхніми форматами) на місці.
  5. У Налаштування → Публічний доступ і Налаштування → Кінцеві користувачі перегляньте імпортовані дозволи й ролі.
  6. Викличте свій API так, як це робить фронтенд, і порівняйте відповіді з відповідями Strapi.

Потім закомітьте schema/, створіть адміністраторів, API-токени й вебхуки та розгорніть (див. чекліст для production).

Зміни у фронтенді

Section titled “Зміни у фронтенді”

API вмісту відповідає формі REST і GraphQL Strapi v5, тож більшість запитів працюють як є. Змініть таке:

  • Базова URL. Спрямуйте фронтенд на сервер Verdin. API вмісту розташований під /api ([api].prefix), GraphQL — на /graphql, щойно ви ввімкнете його в Налаштування → Функції.
  • API-токени. Токени не імпортуються: створіть нові в Налаштування → API-токени і замініть їх у середовищі фронтенду.
  • Id документів. Кожен documentId і числовий id новий. Замініть id, зашиті у фронтенді, на ті, що в strapi-id-map.json, або, краще, шукайте записи за slug чи іншим полем uid.
  • URL медіа. URL файлів вказують на новий провайдер: /uploads/… на сервері Verdin для локального провайдера або [upload.provider].public_url для S3. Оновіть домени зображень, дозволені вашим фреймворком (наприклад, images.remotePatterns у Next.js).
  • Кінцеві користувачі, що увійшли, мають увійти знову: їхні паролі працюють, а JWT, видані Strapi, — ні.
  • CORS. Якщо браузер викликає API з іншого origin, укажіть його в [api].cors_origins.
  • Вебхуки. Створіть їх заново в Налаштування → Вебхуки. Подія Strapi entry.draft-discard називається entry.discard-draft, а доставки підписуються (див. Вебхуки).
  • Фронтенди Strapi v4 потребують і змін v5: плоскі відповіді без attributes, documentId замість id в URL і status=draft замість publicationState=preview.

Для типізованого доступу згенеруйте TypeScript-типи через verdin types і використовуйте типізований клієнт.

Перепишіть власний код

Section titled “Перепишіть власний код”

Код у src/ переїжджає до плагіна WebAssembly. Перенесення власного коду проводить через lifecycle, маршрути, cron-завдання та bootstrap справжнього проєкту з робочим прикладом плагіна.

Strapi Verdin
Хуки lifecycle, middlewares Document Service Хуки плагінів (beforeCreate, afterUpdate…)
Власні маршрути й контролери Маршрути плагінів під /api/plugins/<name>/
bootstrap() у src/index.js (наповнення, налаштування публічних дозволів) Функція запуску плагіна ([startup]) з можливістю public_permissions для публічної ролі
Cron-завдання Завдання плагінів ([[jobs]])
Власний ендпоінт, що зберігає надіслані форми Вбудовані Форми
Власні поля Власні поля плагінів
Віджети адмінки Віджети плагінів або вбудовані віджети панелі
Логотип, кольори й тексти адмінки [admin.branding] у verdin.toml
config/*.js verdin.toml і змінні середовища (довідник конфігурації)
