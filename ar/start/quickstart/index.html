البدء السريع

تأخذك هذه الصفحة من لا شيء إلى أول استجابة من الـ API في نحو عشر دقائق: شغّل Verdin، وأنشئ المسؤول الأول، ونمذج نوع محتوى، وافتحه للعامة واقرأه عبر REST أو GraphQL أو عميل TypeScript.

تحتاج إما إلى Docker أو إلى جهاز يستطيع تشغيل الملف التنفيذي verdin (Linux أو macOS أو Windows على x86-64، وLinux أو macOS على ARM64).

1. شغّل Verdin

Section titled “1. شغّل Verdin”
  • Docker
  • Binary

ولّد الأسرار مرة واحدة، ثم شغّل الصورة في وضع التطوير:

تحتوي وحدة التخزين verdin-data على قاعدة بيانات SQLite (/data/verdin.db)، والوسائط المرفوعة (/data/uploads)، وفي dev، ملفات المخطط التي يكتبها منشئ أنواع المحتوى (/data/schema).

ثبّت الملف التنفيذي (لوحة الإدارة مدمجة فيه)، مثلًا بسكربت التثبيت على Linux وmacOS:

Homebrew وحزمة .deb وwinget وcargo binstall والأرشيفات العادية موجودة في التثبيت.

أنشئ هيكل مشروع وشغّله في وضع التطوير:

يأخذ verdin new الخيار --database sqlite|postgres|mysql|mariadb (SQLite افتراضيًا) لـ اختيار قاعدة البيانات التي يشير إليها .env المولَّد. لـ PostgreSQL وMySQL وMariaDB، عدّل VERDIN_DATABASE_URL في .env ليطابق خادمك قبل أن تشغّل verdin dev. تصف بنية المشروع كل ملف ينشئه.

عندما يعرض السجل verdin listening، يجيب الخادم على المنفذ 1337. ينشئ التشغيل الأول جداول قاعدة البيانات.

2. الأسرار

Section titled “2. الأسرار”

يحتاج Verdin إلى سرّين، طول كل منهما 32 بايت على الأقل:

المتغير ما يحميه
VERDIN_ADMIN_JWT_SECRET يوقّع جلسات الإدارة.
VERDIN_TOKEN_PEPPER يجزّئ رموز API ويحمي أسرار المصادقة الثنائية ورموز الاسترداد.

يطبع verdin secrets قيمًا جديدة، ويكتبها verdin new في .env. تأتي الأسرار من البيئة فقط، لا من verdin.toml أبدًا، ولا يبدأ الخادم بدونها. يُحمَّل ملف .env المجاور لـ verdin.toml عند البدء؛ والمتغيرات المعيّنة بالفعل في البيئة لها الأولوية.

تنبيه

ولّد الأسرار مرة واحدة لكل تثبيت واحتفظ بها. قيمة VERDIN_ADMIN_JWT_SECRET جديدة تبطل رموز تسجيل الدخول الحالية، وروابط المعاينة المفتوحة، وتسجيلات الدخول عبر OAuth الجارية (تجدّد لوحة الإدارة جلستها تلقائيًا)؛ وقيمة VERDIN_TOKEN_PEPPER جديدة تبطل كل رمز API وكل إعداد للمصادقة الثنائية. أبقِ .env وverdin.env خارج إدارة الإصدارات.

3. أنشئ المسؤول الأول

Section titled “3. أنشئ المسؤول الأول”

افتح http://localhost:1337/admin/. ما دام لا يوجد أي مسؤول، تعرض لوحة الإدارة مرحبًا بك في Verdin: أدخل اسمك وبريدك الإلكتروني وكلمة مرور من 8 أحرف على الأقل، ثم اختر إنشاء حساب. هذا الحساب الأول Super Admin لديه كل الصلاحيات.

يمكنك أيضًا إنشاء المسؤولين من سطر الأوامر؛ راجع المستخدمون المسؤولون من سطر الأوامر.

4. نمذج نوع محتوى

Section titled “4. نمذج نوع محتوى”
  1. في الشريط الجانبي، افتح منشئ أنواع المحتوى واختر نوع محتوى جديد.
  2. عيّن اسم العرض إلى Article. يملأ Verdin الاسم المفرد (معرّف API) بـ article والاسم الجمع (المسار) بـ articles؛ والمسار هو عنوان URL للنوع في الـ API. أبقِ النوع على مجموعة.
  3. اختر إضافة حقل، واختر نص قصير، وسمّه title، واختر تم.
  4. اختر حفظ. تسرد مراجعة الترحيل خطوات قاعدة البيانات مع SQL الخاص بها؛ اختر تطبيق.

يكتب Verdin النوع في schema/content-types/article.json وينشئ جدوله. المنشئ متاح في verdin dev فقط: في الإنتاج يأتي المخطط من ملفاتك. راجع نموذج المحتوى لأنواع الحقول وخياراتها.

الآن أضف إدخالًا: افتح Article تحت المجموعات، واختر إدخال جديد، واملأ العنوان واختر نشر. للأنواع الجديدة المسودة والنشر مفعّل، لذا تبقى إدخالاتها مسودات، غير مرئية للـ API العام، حتى تُنشر.

5. افتحه للعامة

Section titled “5. افتحه للعامة”

يبقى API المحتوى مغلقًا حتى تمنح صلاحيات عامة أو تنشئ رموز API. افتح الإعدادات ← الوصول العام، واسمح بـ بحث وبحث عن واحد لـ Article، و اختر حفظ.

للقراءة دون وصول عام، أنشئ رمزًا في الإعدادات ← رموز API وأرسله على شكل Authorization: Bearer <token>. راجع رموز API و الصلاحيات.

6. أرسل طلبًا أول

Section titled “6. أرسل طلبًا أول”
  • REST
  • GraphQL
  • TypeScript

للاستجابة الشكل المسطّح في Strapi v5. تستخدم عوامل التصفية والترتيب والتقسيم إلى صفحات و populate معاملات الاستعلام نفسها؛ راجع REST API.

فعّل الإعدادات ← الميزات ← GraphQL. عندئذ يقدّم POST /graphql مخططًا مولَّدًا من أنواع محتواك، بالصلاحيات نفسها التي لـ REST API:

راجع GraphQL API.

ولّد الأنواع من المخطط وثبّت العميل في مشروع الواجهة الأمامية:

مع Docker، يمكن للصورة طباعة الأنواع من المخطط الموجود في وحدة التخزين: docker run --rm -v verdin-data:/data ghcr.io/verdin-cms/verdin types > src/verdin-types.ts.

راجع العميل المُنمَّط.

من هنا، يبني درسا Astro وNext.js واجهة أمامية لمدونة على الـ API نفسه.

وضعا التطوير والإنتاج

Section titled “وضعا التطوير والإنتاج”
الأمر استخدمه لـ
verdin dev التطوير: تُطبَّق الترحيلات الآمنة تلقائيًا، ويستطيع منشئ أنواع المحتوى تحرير ملفات المخطط، ويعيد الخادم التحميل عندما تتغير.
verdin start الإنتاج. يرفض العمل ما دامت قاعدة البيانات متأخرة عن المخطط.
verdin start --migrate الإنتاج، مع تطبيق الترحيلات الآمنة المعلّقة قبل البدء. هذا هو الأمر الافتراضي لصورة Docker.

ملفات تعريف ارتباط التجديد Secure في verdin start وليست كذلك في verdin dev، لذا يحتاج تسجيل الدخول إلى خادم start إلى HTTPS. لتجربة start عبر HTTP العادي، عيّن VERDIN_ADMIN__SECURE_COOKIES=false.

في الإنتاج، أبقِ المخطط تحت إدارة الإصدارات وركّبه للقراءة فقط. مع Docker:

تغطي قائمة التحقق للإنتاج الباقي.

المخطط والترحيلات

Section titled “المخطط والترحيلات”

تعيش أنواع المحتوى في schema/content-types/<singularName>.json والمكوّنات في schema/components/<category>/<name>.json، بصيغة Strapi. عندما تتغير الملفات، يخطط Verdin لترحيل:

على MySQL وMariaDB، اللذين لا يدعمان DDL ضمن المعاملات، يستأنف الترحيل المنقطع من الخطوة الفاشلة في migrate apply التالي. راجع ترحيلات المخطط.

المستخدمون المسؤولون من سطر الأوامر

Section titled “المستخدمون المسؤولون من سطر الأوامر”

ينشئ admin create حساب Super Admin. ويفتح reset-password أيضًا قفل الحساب وينهي جلساته. يحتاج كلاهما إلى أن تكون قاعدة البيانات محدّثة مع المخطط.

أوامر أخرى

Section titled “أوامر أخرى”
الأمر ما يفعله
verdin types -o src/verdin-types.ts يكتب تعريفات TypeScript لـ API المحتوى (إلى المخرج القياسي دون -o).
verdin import strapi <export> يستورد مشروع Strapi؛ راجع الاستيراد من Strapi.
verdin export <file.tar.gz> يكتب المخطط والمحتوى والوسائط في أرشيف؛ ويقرؤه verdin import verdin من جديد.
verdin version يطبع الإصدار.

يأخذ كل أمر -c, --config <path> (افتراضيًا verdin.toml، أو VERDIN_CONFIG). يسرد مرجع CLI كل أمر وخيار، ويسرد مرجع التهيئة كل إعداد.

فحوص السلامة

Section titled “فحوص السلامة”

يجيب GET /_health ما دامت العملية تعمل. ويتحقق GET /_ready أيضًا من قاعدة البيانات ويجيب بـ 503 عندما يتعذر الوصول إليها: وجّه موازنات الأحمال إليه (راجع التوسّع).
