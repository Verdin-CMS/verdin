نظرة عامة على البنية

هذا القسم للأشخاص الذين يعملون على Verdin نفسه. يشرح كيف يُجمَّع الخادم ولوحة الإدارة، ولماذا بُنيا بهذه الطريقة، ومن أين تبدأ قراءة الشيفرة. لاستخدام Verdin، ابدأ بـالبدء السريع بدلًا من ذلك.

Verdin نظام إدارة محتوى headless مكتوب بلغة Rust يتبع Strapi v5: تنمذج المحتوى بصريًا أو في ملفات JSON، وتحصل على REST API وGraphQL API بالإضافة إلى لوحة إدارة. يُشحن كملف تنفيذي واحد يضم الخادم وCLI ولوحة الإدارة المبنية بـ Angular، ويعمل على PostgreSQL وMySQL وMariaDB وSQLite.

الأهداف

Section titled “الأهداف”
  • ملف تنفيذي واحد. يحتوي verdin على الخادم وCLI ولوحة الإدارة المضمَّنة. لا يحتاج الإنتاج إلى Node.js ولا إلى node_modules.
  • بدء سريع، واستهلاك ذاكرة صغير.
  • أربع قواعد بيانات، ومجموعة اختبارات واحدة. PostgreSQL وMySQL وMariaDB وSQLite كلها من الدرجة الأولى وتغطيها الاختبارات نفسها.
  • المخطط كشيفرة. أنواع المحتوى ملفات JSON تضعها تحت إدارة الإصدارات في git.
  • REST API متوافق مع Strapi v5 حيثما كان ذلك معقولًا، فتنتقل الواجهات الأمامية الموجودة بتغييرات قليلة.
  • كل شيء مجاني. لا توجد نسخة للمؤسسات: SSO وسجلات التدقيق ومسارات المراجعة وحزم النشر وكل ميزة أخرى تُشحن للجميع.

ما شُحن إصدارًا بعد إصدار، وما سيأتي لاحقًا، موجود في خارطة الطريق.

ما ليس من الأهداف

Section titled “ما ليس من الأهداف”
  • تشغيل إضافات JavaScript الخاصة بـ Strapi. إضافات Verdin وحدات WebAssembly (راجع الإضافات).
  • قراءة قاعدة بيانات Strapi كما هي. ينتقل المحتوى عبر أداة استيراد (راجع الترحيل من Strapi).
  • عرض الصفحات. Verdin نظام headless.

مبادئ التصميم

Section titled “مبادئ التصميم”
  1. المخطط هو مصدر الحقيقة. الجداول، والتحقق، وواجهات REST وGraphQL، ومستند OpenAPI، ونماذج الإدارة كلها مشتقة منه.
  2. لا يأتي أي معرّف SQL من طلب أبدًا. أسماء الجداول والأعمدة تأتي فقط من المخطط المتحقق منه، وكل قيمة معامل مربوط.
  3. اللهجات من الدرجة الأولى. لا “يعمل على PostgreSQL، وMySQL لاحقًا”. تُختبر كل ميزة على المحركات الأربعة.
  4. آمن افتراضيًا. يبقى API المحتوى مغلقًا حتى تمنح الصلاحيات، ولا تُكشف حقول private أبدًا، وحدود عمق الاستعلام وحجمه مفعّلة دائمًا.
  5. العمليات المُدمِّرة صريحة. حذف عمود أو جدول يحتاج إلى موافقتك؛ ولا يحدث أبدًا كأثر جانبي.
  6. لا حالة عامة. تُمرَّر الخدمات عبر حالة axum والمُنشئات؛ ولا توجد كائنات مفردة (singletons).

الصورة الكاملة

Section titled “الصورة الكاملة”

يدخل الطلب الملف التنفيذي عبر مجموعة صغيرة من الطبقات المشتركة، ويصل إلى أحد موجّهات الـ API، وينتهي في خدمة المستندات، التي تبني SQL للهجة المتصلة. يغذّي سجل المخطط، المحمَّل من schema/*.json، كل خطوة، ويُبقي محرك الترحيل قاعدة البيانات متوافقة معه.

  • API المحتوى تحت [api].prefix (افتراضيًا /api): مسارات REST لكل نوع محتوى، وعمليات الرفع، ومستند OpenAPI. راجع REST API.
  • API الإدارة تحت {admin.path}/api (افتراضيًا /admin/api): كل ما تفعله لوحة الإدارة. راجع API الإدارة.
  • GraphQL على /graphql وMCP على /mcp، عندما تكون تلك الميزات مفعّلة. تُترجم وسائط GraphQL إلى شجرة المعاملات نفسها التي يقرؤها محلل REST، فتتشارك الواجهتان عوامل التصفية والتقسيم إلى صفحات والتعبئة وقواعد الصلاحيات.
  • لوحة الإدارة تحت [admin].path (افتراضيًا /admin)، تُقدَّم من الملف التنفيذي أو من [admin].assets_dir. راجع داخليات لوحة الإدارة.
  • المسارات التشغيلية: /_health، و/_ready، و/_metrics عند تفعيل المقاييس. راجع المراقبة.

تمر كل عملية كتابة عبر خدمة المستندات، أيًا كان الـ API الذي جاءت منه. تتحقق من البيانات، وتكتب الصفوف وجداول الربط في معاملة واحدة، ثم تخبر المستمعين (الـ webhooks، وفهرس البحث، والسجل، والوقت الفعلي، وسجل التدقيق) بما تغيّر.

عندما تُفعَّل الميزات أو تُعطَّل، أو عندما يغيّر منشئ أنواع المحتوى المخطط في verdin dev، يُعاد بناء الموجّه بأكمله ويُستبدل في مكانه (ArcSwap)، دون إعادة تشغيل.

من أين تبدأ القراءة

Section titled “من أين تبدأ القراءة”
لفهم اقرأ
كيف يُقلع الملف التنفيذي ويجمّع موجّهاته crates/verdin/src/cli.rs (start)، ثم crates/verdin/src/app.rs
صيغة المخطط وقواعد التحقق منه crates/verdin-schema/src/raw.rs، validate.rs، naming.rs
كيف يصبح المخطط جداول crates/verdin-migrate/src/derive.rs، ثم التخزين
الترحيلات crates/verdin-migrate/src/diff.rs، plan.rs، apply.rs، ومحرك الترحيل
معالجات API المحتوى crates/verdin-api/src/handlers.rs وlib.rs
معاملات الاستعلام crates/verdin-query/src/params.rs (المحلل)، parse.rs (التحقق)، sql.rs (SQL)
القراءة والكتابة crates/verdin-content/src/service.rs وinput.rs، وخدمة المستندات
لوحة الإدارة admin/src/app/app.routes.ts، ثم features/content/ وداخليات لوحة الإدارة

تصفّح الشيفرة على GitHub. يغطي باقي هذا القسم التخزين، وطبقة قاعدة البيانات، والترحيلات، وخدمة المستندات، ولوحة الإدارة، والاختبار وسجل القرارات.

السلوك الموجّه للمستخدم موثّق في مكان آخر: معاملات الاستعلام في REST API، والإعدادات في مرجع التهيئة، والأوامر في مرجع CLI، والتقوية في الأمان.
