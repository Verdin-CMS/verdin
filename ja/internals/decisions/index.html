決定事項のログ

このログは、Verdin を形作った設計上の選択を、決めた順に記録したものです。変更を提案する前に、なぜコードが今のようになっているかを確認できます。エントリーは、マイルストーン名（M2〜M4 は最初のリリースより前のマイルストーン）を含め、書かれたときのまま残しています。28 が 1 を補足しているように、後のエントリーが前のエントリーを詳しくすることもあります。そうしなければ誰かがコードから逆算しなければならないような決定をしたら、新しい行を追加してください。

# 決定事項 結果 理由
1 コンポーネント: JSON かテーブルか JSON カラム（ストレージ） 結合が少なく、公開とバージョン管理が簡単で、マイグレーションが単純。繰り返し可能なコンポーネントでのフィルターはまれで、後から JSON 関数で追加できる
2 decimal の JSON エンコード デフォルトは数値、api.decimal_as_string で選択可能 Strapi との互換性が採用を最大化し、必要なときは正確な値も使える
3 管理画面のフォーム Signal Forms シグナル中心で zoneless の管理画面に合い、スキーマから動的なフォームツリーを導き出せる
4 言語 コード、ドキュメント、コミットは英語 オープンソースとしての届く範囲
5 Strapi の REST との互換性 同じパラメーターとレスポンスの形。Verdin 独自の拡張は actions/ 配下 フロントエンドが最小限の変更で移行できる
6 管理者の JWT のアルゴリズム HS256 シークレットが 1 つで単純。外部の検証者が現れたら EdDSA
7 ドキュメント ID ULID（26 文字） ソート可能で移植性がある。Strapi 自身の ID は不透明な 24 文字の文字列で、クライアントはそれを解析しない
8 スナップショットの内容 スキーマではなく物理モデル 後のバージョンが、変わらないスキーマから新しいテーブルを導き出せる
9 属性の NULL 許容 常に NULL 許容。required は公開時に確認 下書きは未完成でもよい（Strapi v5 の動作）。必須フィールドの追加が安全
10 unique の強制 (column, locale, publication_state) の一意インデックス 競合がない。下書きとその公開バージョンは値を共有する
11 状態のカラム名 publication_state state はよくある属性名
12 SQL の予約語 識別子を常に引用符で囲む 属性名の恣意的なブロックリストが要らない
13 DML の組み立て sea-query ではなく独自のビルダー 方言ごとの細部（型付きの NULL、照合順序、SQLite の形式）が支配的。抽象化が 1 つ減る
14 ?status=draft なしの書き込み 公開する（Strapi v5 の REST の動作） 既存のクライアントとそのまま互換
15 テキストの比較 どのエンジンでもデフォルトは完全一致。大文字小文字を区別しないのは …i の演算子 MySQL でも PostgreSQL と同じ結果
16 一時的なアクセス制御（M2〜M3） [api].open_access のスイッチ。M4 で削除 権限ができるまでデフォルトで安全
17 「対象は 1 件のドキュメントに属する」 状態ごとに、対象を移動させて強制 一意インデックスでは、下書きとその公開バージョンが対象を共有できなくなる
18 逆側（mappedBy） 読み取り専用 下書きと公開があると、逆側からの書き込みは曖昧になる（どちらの所有側のバージョンか）
19 リンクの位置 書き込みのたびに 1..n で振り直す 浮動小数点を使い切ることがない。リストは小さい
20 リンクテーブルの行 id の主キーを保持 マイグレーションエンジンと SQLite の再構築にとって一様なテーブル
21 JWT のライブラリ 独自の HS256（HMAC-SHA256、定数時間の検証、alg 固定） jsonwebtoken 11 は RSA を引き込む暗号バックエンドが必要
22 プラットフォームのテーブル コンテンツモデルと一緒に導き出す すべてに 1 つのマイグレーションの仕組み
23 リフレッシュトークンの再利用 猶予期間なしでファミリー全体を取り消す 単純で厳格。管理者はログインし直す
24 コンテンツ API での下書き 独立した readDrafts の許可 公開コンテンツを読むトークンから下書きが漏れない
25 ビルダーの適用順序 マイグレーション、ファイルの書き込み、アプリのホットスワップの順 マイグレーションが失敗しても、ファイルと実行中のアプリには触れない
26 管理画面の書き込み 下書きだけを保存。公開は明示的なアクション 編集者の期待に合う。コンテンツ API は Strapi のデフォルトで公開する動作を保つ
27 管理画面の実行時設定 インラインスクリプトではなく <meta> タグ CSP に unsafe-inline のスクリプトを入れずに済む
28 コンポーネントのフィールドでのフィルター 方言ごとの JSON パスの演算子（#>>、JSON_VALUE、json_extract）。繰り返し可能なコンポーネントとダイナミックゾーンでは配列の項目に対する EXISTS（0.8） ダイナミックゾーンは __component でのみ。項目ごとにフィールドが異なるため
29 管理画面の i18n フラットな JSON のカタログ（admin/public/i18n）と、FormatJS（独自のトランスパイラー）による ICU MessageFormat を使う Transloco を、小さな I18n のファサードの背後に置く。Angular のコンパイル時の i18n は使わない 実行時の言語切り替え。Weblate/Crowdin 向けの標準的なファイル。FormatJS はメッセージを解釈するので、厳格な CSP に unsafe-eval が不要（@messageformat/core は new Function でコンパイルする）。キーは en.json から型付けされ、完全性は npm run i18n:check で確認
30 週の始まり ブラウザーの地域タグの Intl.Locale#getWeekInfo（en-GB ≠ en-US）、地域の表へのフォールバック、ユーザーによる上書き UI の言語が共通でも、各ユーザーの地域に従う
31 ダッシュボードのレイアウトの保存 vd_admin_users のユーザーごとの JSON の preferences カラム（64 KiB 以下） ブラウザーをまたいでユーザーについていく。テーマと言語はログイン前に適用されるので localStorage に残す
32 リフレッシュ Cookie の Secure のデフォルト start ではオン、dev ではオフ、上書き可能 プレーンな HTTP での verdin dev がどのブラウザーでも動く。本番環境は厳格なまま
33 リリースプロファイル Thin LTO、codegen unit 1、strip。アンワインドは保持 パニックしたハンドラーがサーバーを落としてはならない
34 「未読」のドキュメント ユーザーごとの vd_document_views の行。ドキュメントが変わると、編集者以外の全員の行を削除。SQL では NOT EXISTS で絞り込む ページネーションと件数が正確なまま。行ごとにタイムスタンプを比較する必要がない
35 投票とアンケート 管理者専用の共同作業用テーブル（vd_document_votes、vd_polls、vd_poll_votes）、任意のコンテンツタイプ すべてのスキーマに投票のフィールドをモデル化せずに、提案箱やチームの決定ができる
36 メディアのストレージ ローカルと S3 に object_store 1 つのコードパス。マルチパートのアップロードのストリーミング。開発環境と CI では RustFS
37 メディアのリンク リレーションと同様のフィールドごとのリンクテーブル リレーションと同じ下書きと公開の意味論。カスケードでリンクの整合性を保つ
38 組み込みの権限のアップグレード vd_settings のバージョンの印。追加は一度だけ適用 既存のインストールが、管理者の後の編集を取り消さずに新しい権限を得る
39 実行時の機能 verdin-api のカタログ、vd_settings（features）のスイッチ、すべてのモードでその場でアプリを再構築（ArcSwap） 再起動なしで Strapi のようなプラグインの切り替え。使えない機能は予定のバージョンとともに一覧される
40 API リファレンスの UI {api}/docs の Scalar（scalar_api_reference、バンドルを埋め込み）。ドキュメントが公開されている場合のみ。CSP はそのインラインのブートストラップをハッシュで許可 セルフホスト（CDN、フォント、AI エージェント、テレメトリーなし）。ドキュメントはデフォルトでトークン専用のまま
41 GraphQL アプリと一緒に構築する async-graphql の動的スキーマ。引数と選択は REST のパラメーターツリーに変換され、同じクエリパーサーで解析される REST と GraphQL で、フィルター、ページネーション、populate、バリデーション、権限のルールが 1 つ。選択から導き出す populate でバッチ読み込みを保つ
42 ドキュメントのイベント Document Service のリスナー。コミット後に呼ばれる 副作用（既読の印、将来の Webhook）が、ハンドラーごとのフックなしにすべての API に適用される
