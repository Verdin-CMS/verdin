Struktura projektu

Projekt Verdin to katalog z plikiem konfiguracyjnym i schematem. Ta strona wymienia, co tworzy verdin new, co serwer dodaje w trakcie działania i co zatwierdzać.

Co tworzy verdin new

Dział zatytułowany „Co tworzy verdin new”
  • Foldermy-site/
    • verdin.toml konfiguracja projektu
    • .env sekrety i URL bazy danych, czytelne tylko dla ciebie
    • .gitignore
    • Folderschema/
      • Foldercontent-types/ jeden plik JSON na typ zawartości
        • …
      • Foldercomponents/ jeden folder na kategorię komponentów
        • …
    • Folderdata/ baza SQLite (tylko z --database sqlite)
      • …

Katalog nie może istnieć albo musi być pusty. Nazwa projektu w URL bazy danych pochodzi z nazwy katalogu, małymi literami, z innymi znakami zamienionymi na _ (My Site staje się my_site).

verdin.toml

Dział zatytułowany „verdin.toml”

Konfiguracja. Wygenerowany plik ustawia port, prefiks API treści i rozmiary stron oraz ścieżkę panelu:

Każdy klucz ma wartość domyślną, więc plik może być pusty albo go nie być. Nieznane klucze zatrzymują serwer z błędem. Każdy klucz można nadpisać ze środowiska jako VERDIN_<SECTION>__<KEY>, np. VERDIN_SERVER__PORT=8080. Polecenia czytają verdin.toml z bieżącego katalogu; przekaż -c <path> lub ustaw VERDIN_CONFIG, aby użyć innego pliku. Ścieżki w pliku, np. katalogów schematu lub przesłanych plików, są względne wobec katalogu, który go zawiera. Wszystkie ustawienia są w dokumentacji konfiguracji.

.env

Dział zatytułowany „.env”

verdin new wpisuje dwa losowe sekrety i URL bazy danych dla silnika wybranego przez --database:

--database Wygenerowany VERDIN_DATABASE_URL
sqlite (domyślnie) sqlite://data/verdin.db
postgres postgres://verdin:change-me@localhost:5432/<name>
mysql, mariadb mysql://verdin:change-me@localhost:3306/<name>

Dla PostgreSQL, MySQL i MariaDB zmień użytkownika i hasło. Względne ścieżki SQLite są rozwiązywane względem katalogu projektu, a nie katalogu, z którego uruchamiasz polecenie.

Każde polecenie wczytuje .env obok verdin.toml; zmienne już ustawione w środowisku mają pierwszeństwo. W Linux i macOS plik jest tworzony jako czytelny tylko dla właściciela. W produkcji ustaw te zmienne w magazynie sekretów swojej platformy, zamiast dostarczać plik .env. Szybki start wyjaśnia oba sekrety.

schema/

Dział zatytułowany „schema/”

Model treści w formacie schematu Strapi:

  • schema/content-types/<singularName>.json, jeden plik na typ kolekcji lub pojedynczy typ.
  • schema/components/<category>/<name>.json, jeden plik na komponent; UID komponentu to <category>.<name>.

Kreator typów zawartości zapisuje te pliki w verdin dev, a ty możesz edytować je ręcznie: verdin dev przeładowuje, gdy się zmieniają. Schemat przykładowego bloga wygląda tak:

  • Folderschema/
    • Foldercontent-types/
      • article.json
      • category.json
      • homepage.json pojedynczy typ
      • tag.json
    • Foldercomponents/
      • Folderblocks/
        • hero.json blocks.hero
        • quote.json blocks.quote
      • Foldershared/
        • seo.json shared.seo

Pliki są źródłem prawdy: Verdin wyprowadza z nich tabele bazy danych, walidację, API REST i GraphQL, dokument OpenAPI, typy TypeScript i formularze panelu. Zobacz Model treści i Migracje schematu. Katalog schematu to [schema].path w verdin.toml, domyślnie schema.

Co pojawia się, gdy Verdin działa

Dział zatytułowany „Co pojawia się, gdy Verdin działa”
  • Foldermy-site/
    • verdin.toml
    • .env
    • Folderschema/
      • …
    • Folderdata/
      • verdin.db baza SQLite, z plikami -wal i -shm
      • Foldersearch/ indeks pełnotekstowy, gdy [search].enabled jest włączone
        • …
    • Folderpublic/
      • Folderuploads/ pliki biblioteki multimediów, serwowane pod /uploads
        • …
    • Folder.cache/
      • Foldertransforms/ przeskalowane obrazy, odbudowywane na żądanie
        • …
    • Folderplugins/ wtyczki WebAssembly, po jednym folderze (tworzysz go sam)
      • …
    • strapi-id-map.json zapisywany przez verdin import strapi
Ścieżka Zapisuje Ustawienie
data/verdin.db Serwer, z SQLite VERDIN_DATABASE_URL
public/uploads/ Przesyłanie z dostawcą lokalnym (domyślnym) [upload].provider
.cache/transforms/ Transformacje obrazów żądane pod /uploads [upload.transforms].cache_dir
data/search/ Indeks pełnotekstowy [search].dir
plugins/ Ty: każda wtyczka we własnym folderze [plugins].path
strapi-id-map.json verdin import strapi: identyfikatory Strapi zmapowane na identyfikatory Verdin —

Z PostgreSQL, MySQL lub MariaDB nie ma data/verdin.db: treść jest na serwerze bazy danych. Z dostawcą S3 pliki multimediów są w buckecie, a public/uploads pozostaje puste.

Co trafia do git

Zatwierdzaj Trzymaj poza git

plugins/, jeśli używasz wtyczek public/uploads/ (multimedia)
.gitignore .cache/

Projektom utworzonym przed 0.10 brakuje linii public/uploads/: dodaj ją.

Notatka

Treść i multimedia to dane, nie kod. Twórz ich kopie zapasowe przez verdin export lub narzędzia swojej bazy danych, zamiast je zatwierdzać; zobacz Kopie zapasowe.

Zatwierdzaj schemat razem z kodem, który od niego zależy, np. wygenerowanymi typami frontendu. W produkcji wdrażaj zatwierdzony schemat i uruchamiaj verdin start --migrate: kreator typów zawartości jest wyłączony poza verdin dev, więc schemat zmienia się tylko przez twoje repozytorium.
