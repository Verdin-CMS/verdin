Справочник по плагинам

Эта страница — полный контракт между Verdin и плагином: манифест, что Verdin передаёт каждой экспортируемой функции и что ожидает в ответ, и функции хоста, которые может вызывать модуль. Введение — в разделе Плагины, разобранный пример — в руководстве по созданию плагина.

Каталог плагина

Заголовок раздела «Каталог плагина»

Каждый плагин — это каталог внутри [plugins].path (по умолчанию plugins/ рядом с verdin.toml):

Файл Обязательный Содержимое
plugin.toml да Манифест.
plugin.wasm да Модуль (другой путь задаётся через wasm).
admin/ нет Файлы, которые загружает админ-панель: модуль admin.script и его ресурсы.

При запуске Verdin загружает все каталоги, в которых есть plugin.toml, в порядке имён. Каталог пропускается и показывается с причиной в Настройки → Плагины, если его манифест некорректен, модуль отсутствует или его name уже занято другим плагином.

Манифест

Заголовок раздела «Манифест»

Неизвестные ключи — ошибка в любой таблице.

Ключи верхнего уровня

Заголовок раздела «Ключи верхнего уровня»
Ключ По умолчанию Описание
name обязательный Id плагина в URL, настройках и пользовательских полях: строчные буквы, цифры и -, начинается с буквы, не больше 64 символов.
version обязательный Показывается в админке и в логе.
description не задан Показывается в Настройки → Плагины.
wasm "plugin.wasm" Модуль относительно каталога плагина (без .., не абсолютный путь).
wasi false Дать модулю WASI: часы и случайные числа. Файлов и сокетов нет в любом случае.

[capabilities]

Заголовок раздела «[capabilities]»
Ключ По умолчанию Описание
read [] Типы содержимого, которые может читать verdin_content (findMany, findOne): UID вроде api::article или "*" для всех.
write [] Типы содержимого, для которых разрешены create, update, delete, publish и unpublish. Подразумевает read.
http [] Хосты, на которые модуль может отправлять HTTP-запросы: api.example.com или *.example.com.
kv false Собственное хранилище «ключ — значение» плагина (verdin_kv_get, verdin_kv_set).
public_permissions false Чтение и замена разрешений публичной роли в content API (verdin_public_permissions).

Возможности ограничивают только вызовы хоста. Хуки срабатывают для указанных в них типов независимо от read, а маршруты доступны всем.

[limits]

Заголовок раздела «[limits]»
Ключ По умолчанию Описание
timeout_ms 5000 Ограничение времени одного вызова в миллисекундах.
memory_mb 64 Максимальный объём памяти модуля в мегабайтах.

Оба значения должны быть положительными.

[[hooks]]

Заголовок раздела «[[hooks]]»
Ключ По умолчанию Описание
on обязательный Событие, см. ниже.
uid "*" Тип содержимого (api::article) или "*" для всех.
function обязательный Экспортируемая функция, которую нужно вызвать.

События:

До записи После записи
beforeCreate afterCreate
beforeUpdate afterUpdate
beforeDelete afterDelete
beforePublish afterPublish
beforeUnpublish afterUnpublish
beforeDiscardDraft afterDiscardDraft

Это имена событий жизненного цикла Strapi. Хуки срабатывают при записи из админ-панели, REST и GraphQL API и релизов, но не при записи, сделанной командами verdin import. Запись, сделанная плагинами, запускает хуки «после», но не хуки «до» (см. Запись из плагинов).

[routes]

Заголовок раздела «[routes]»
Ключ Описание
function Экспортируемая функция, которая обслуживает все запросы к /api/plugins/<name> и /api/plugins/<name>/… с любым методом.

Путь следует [api].prefix.

[[jobs]]

Заголовок раздела «[[jobs]]»
Ключ Описание
schedule Выражение cron в UTC, с необязательными секундами: */15 * * * *, 0 0 3 * * *.
function Экспортируемая функция, которую нужно вызвать.

[startup]

Заголовок раздела «[startup]»

Функция, которая запускается при старте плагина: то, что проект Strapi делает в bootstrap (наполнение контента, настройка публичной роли).

Ключ По умолчанию Описание
function обязательный Экспортируемая функция, которую нужно вызвать.
timeout_ms 30000 Собственный лимит времени в миллисекундах (наполнение может занять больше времени, чем хук). Должен быть положительным.

О том, когда она запускается, см. Функция запуска.

[[graphql]]

Заголовок раздела «[[graphql]]»
Ключ По умолчанию Описание
name обязательный Имя поля: начинается со строчной буквы, дальше буквы, цифры и _.
function обязательный Экспортируемая функция, которая его разрешает.
mutation false Добавить поле в Mutation вместо Query.
description не задан Описание поля в схеме.

Каждая запись добавляет name(args: JSON): JSON. Имя, которое уже использует тип содержимого или раньше занял другой плагин, пропускается с предупреждением в логе.

[admin]

Заголовок раздела «[admin]»
Ключ Описание
script ES-модуль в admin/, который определяет пользовательские элементы (без .., не абсолютный путь).
[[admin.widgets]] Типы виджетов главной панели: id, title, element, необязательный description.
[[admin.fields]] Пользовательские поля: id, title, element, type (тип атрибута, в котором хранится значение, например string или json), необязательный description.

element — имя пользовательского элемента: строчные буквы, цифры и -, минимум один - (slugs-color).

[[settings]]

Заголовок раздела «[[settings]]»

Описывает форму Настройки → Плагины → Настройки. Без этой секции настройки — это произвольный JSON-объект.

Ключ По умолчанию Описание
key обязательный Ключ в объекте настроек: буквы, цифры и _, не начинается с цифры, уникален.
label обязательный Подпись в форме.
type "string" string, text, url, number, integer, boolean или select.
description не задан Текст подсказки под полем.
required false Нужно значение (для текста — непустое), если нет default.
options [] Варианты для select (для него обязательны).
default не задан Используется, если ключ отсутствует или равен null. Должен подходить полю.
min, max не заданы Границы значений number и integer; границы длины для string и text.

Значения url пусты или являются URL http(s)://. Если форма описана, сервер отклоняет настройки с неизвестными ключами, неверными типами, значениями вне границ или без обязательных значений (400).

Экспортируемые функции

Заголовок раздела «Экспортируемые функции»

Каждая экспортируемая функция принимает один JSON-документ и возвращает один (или ничего). Пустой вывод считается null; вывод, который не является JSON, считается сбоем.

Хуки «до»

Заголовок раздела «Хуки «до»»

Вход:

Поле Описание
event Событие хука.
uid Тип содержимого.
documentId Документ или null при beforeCreate.
locale Для локализованных типов — записываемая локаль (локаль по умолчанию, если в запросе её нет); для остальных типов — null.
data Записываемые данные в том виде, в каком их отправил запрос: при создании и обновлении. Для остальных событий — null. При обновлении — только переданные поля.

Выход:

Выход Результат
{ "data": { … } } Заменяет записываемые данные. Они проверяются так же, как исходные.
{ "error": "message" } Отклоняет запись: клиент получает 400 с этим сообщением.
{} или что-то другое Запись продолжается без изменений.

Если подходит несколько хуков, они выполняются в порядке плагинов (имён каталогов), затем в порядке манифеста; каждый видит данные, которые вернул предыдущий. Упавший хук (trap, тайм-аут, некорректный вывод) записывается в лог и пропускается: запись продолжается.

Хуки «после»

Заголовок раздела «Хуки «после»»

Вход: { "event", "uid", "documentId", "locale" }, отправляется после фиксации записи. Выход игнорируется; сбои записываются в лог. Если вам нужны поля записи, прочитайте её через verdin_content (с возможностью read).

Маршруты

Заголовок раздела «Маршруты»

Вход:

Поле Описание
method HTTP-метод.
path Путь после /api/plugins/<name>, начинается с / (/ для корня плагина).
query Сырая строка запроса без ? (пустая, если её нет).
headers Только content-type, accept, user-agent и accept-language, если они есть.
body Тело запроса строкой (некорректный UTF-8 заменяется).
actor Кто вызывает: { "kind": "public" }, { "kind": "token", "id": 3 } (API-токен) или { "kind": "user", "id": 12 } (вошедший конечный пользователь).

Заголовок Authorization с недействительным токеном отклоняется с 401 до вызова плагина. Разрешения публичного доступа и API-токенов не применяются: проверяйте actor сами.

Выход:

Поле По умолчанию Описание
status 200 HTTP-статус.
headers нет Заголовки ответа. Сохраняются только content-type, cache-control, location, etag, last-modified и content-disposition.
body пусто Строка отправляется как есть (text/plain, если вы не задали content-type); любое другое значение JSON отправляется как application/json.

Выключенный или неизвестный плагин либо плагин без [routes] отвечает 404. Неудачный вызов отвечает 502 с { "data": null, "error": { "status": 502, "name": "PluginError", … } }. Маршруты используют общие с content API [server].body_limit и [server].request_timeout_secs.

Задания

Заголовок раздела «Задания»

Вход: { "scheduledAt": "2026-09-29T03:00:00+00:00" } — время, на которое был запланирован запуск. Выход игнорируется; сбои записываются в лог. Задания выполняются, только пока плагин включён, и только на экземплярах с [plugins].run_jobs = true. Запуск, пропущенный, пока сервер не работал, не наверстывается.

Функция запуска

Заголовок раздела «Функция запуска»

Вход: { "reason": "start" | "enabled" | "settings" }:

reason Когда
start Сервер запустился с включённым плагином.
enabled Плагин включили (здесь или на другом экземпляре, откуда это подхватили здесь).
settings Его настройки изменились, пока он был включён (сохранены здесь или подхвачены с другого экземпляра).

Выход: { "error": "message" } считается сбоем; всё остальное ({}, пусто) — успехом. Сбой (trap, тайм-аут, { error }) попадает в журнал плагина и в лог сервера; плагин остаётся включённым, а функция запускается снова при следующем старте, включении или изменении настроек.

Функция выполняется в фоне, после того как сервер поднялся, поэтому запросы обслуживаются параллельно. Она работает на собственном экземпляре модуля с [startup].timeout_ms, так что медленное наполнение не задерживает хуки и маршруты плагина. Хуки «после», вызванные её записями, выполняются, когда она вернётся (см. Запись из плагинов). Память модуля не делится с обычным экземпляром плагина: храните состояние в verdin_kv_set или в контенте.

При нескольких экземплярах функции запуска выполняют только те, у которых [plugins].run_jobs = true (один экземпляр, если вы следуете совету по масштабированию): они работают с общей базой данных, так что одного раза достаточно. Пишите функцию так, чтобы повторный запуск был безвреден: проверяйте, есть ли то, что вы создаёте, прежде чем создавать.

Поля GraphQL

Заголовок раздела «Поля GraphQL»

Вход: { "args": …, "actor": … }, где args — аргумент args поля (любой JSON или null), а actor — как для маршрутов. Выход — значение поля. Сбой или выключенный плагин дают ошибку GraphQL с кодом PLUGIN_ERROR. Как и в маршрутах, доступ проверяет плагин.

Функции хоста

Заголовок раздела «Функции хоста»

Импортируйте их из пространства имён extism:host/user (extern "ExtismHost" в Rust). Они принимают и возвращают JSON в виде строк; Json<Value> из extism-pdk выполняет преобразование.

Функция Вход Выход
verdin_log { "level": "info" | "warn" | "error", "message": "…" } нет
verdin_content Запрос к контенту (см. ниже) Результат или { "error": "…" }
verdin_kv_get Ключ простой строкой Сохранённое значение JSON или null
verdin_kv_set { "key": "…", "value": … } нет
verdin_config нет Объект настроек с подставленными объявленными значениями по умолчанию
verdin_public_permissions { "op": "get" } или { "op": "set", "permissions": [...] } { "permissions": [...] } или { "error": "…" }

Модуль, который импортирует функцию хоста, которой нет у сервера (более старый Verdin), загрузить нельзя: каждый вызов к нему завершается в логе сервера ошибкой unknown import.

verdin_log

Заголовок раздела «verdin_log»

Пишет в лог сервера (с именем плагина) и в журнал плагина в Настройки → Плагины → Журнал. Другие уровни считаются info. Журнал плагина хранит в памяти последние 200 сообщений, каждое обрезается до 2000 символов.

verdin_content

Заголовок раздела «verdin_content»
Поле Используется в Описание
op всех findMany, findOne, create, update, delete, publish или unpublish.
uid всех Тип содержимого. Должен быть в возможностях.
documentId findOne, update, delete, publish, unpublish Документ.
query findMany, findOne Параметры REST API в виде JSON-объекта: filters, sort, fields, populate, pagination, status.
data create, update Записываемые поля, как в data REST-запроса.
status create, update "draft" сохраняет черновик. Иначе запись публикуется, как REST-запись без ?status=draft.
locale всех Локаль для чтения или записи.

Результаты:

op Результат
findMany { "documents": [...], "meta": { "pagination": {…} } }
findOne { "document": {…} } (null, если не найден)
create, update { "documentId": "…" }
delete { "deleted": true }
publish { "published": true }
unpublish { "unpublished": true }

Вызов вне возможностей, неизвестная операция, ошибка валидации или отсутствующий документ вместо этого дают { "error": "…" }. Чтение возвращает опубликованные версии, если запрос не просит "status": "draft".

Запись из плагинов

Заголовок раздела «Запись из плагинов»

Запись через verdin_content пропускает хуки «до» всех плагинов, чтобы плагин не мог зациклиться на собственных изменениях, и правила, которые вы помещаете в хуки «до» (значения по умолчанию, проверки), к ней не применяются. Всё остальное применяется: валидация, этапы проверки, вебхуки, история, журнал аудита и хуки «после» всех плагинов, включая тот, что выполняет запись.

Хуки «после», вызванные записями плагина, выполняются не внутри записи: они ставятся в очередь и выполняются, когда вызов плагина (маршрут, задание, резолвер GraphQL, хук или функция запуска) вернулся и освободил экземпляр плагина, до отправки ответа маршрута. Поэтому плагин может писать в тип, на который у него есть хуки «после», а цепочки через несколько плагинов работают.

  • Хуки, которые пишут, вызывают дальнейшие хуки, не глубже 4 уровней (запись из REST или GraphQL — уровень 1). Более глубокие хуки пропускаются с предупреждением в журнале плагина; это не даёт хуку, который пишет в тип, на который подписан, зациклиться навсегда.
  • Функции хоста (verdin_content, verdin_public_permissions, хранилище «ключ — значение») останавливаются на лимите времени вызова и возвращают модулю ошибку, а вызывающая сторона ждёт занятый плагин не дольше лимита времени плюс 10 секунд. Застрявший вызов не может удерживать плагин или корректную остановку вечно.

verdin_kv_get и verdin_kv_set

Заголовок раздела «verdin_kv_get и verdin_kv_set»

Хранилище «ключ — значение» для каждого плагина в базе данных Verdin, общее для всех экземпляров. Ключи — от 1 до 255 байт; значения — любой JSON. Установка null удаляет ключ. Без возможности kv чтение возвращает null, а запись игнорируется.

verdin_config

Заголовок раздела «verdin_config»

Возвращает настройки, сохранённые в Настройки → Плагины, где для отсутствующих ключей подставлен default каждой объявленной настройки. {}, если ничего не сохранено.

verdin_public_permissions

Заголовок раздела «verdin_public_permissions»

Читает или заменяет разрешения публичной роли в content API — то, что редактирует Настройки → Публичный доступ. Нужна возможность public_permissions; без неё каждый вызов отвечает { "error": "…" }.

op Эффект
get Ничего; возвращает текущие разрешения.
set Заменяет все публичные разрешения значением permissions (пустой список удаляет их все).

Обе операции отвечают { "permissions": [{ "subject", "action" }, …] }, отсортированным. subject — uid типа содержимого, plugin::upload (медиатека), plugin::users-permissions.user (конечные пользователи в content API) или plugin::i18n.locale (только find). action — find, findOne, create, update, delete, publish или readDrafts (последние два не применимы к загрузкам и конечным пользователям). Они проверяются как сетка прав администратора: неизвестный subject или action либо неприменимые дают { "error": "…" } и ничего не меняют. Каждый set записывается в лог сервера.

HTTP

Заголовок раздела «HTTP»

Если хосты перечислены в http, используйте поддержку HTTP в Extism (extism_pdk::http::request в Rust). Запросы к другим хостам завершаются ошибкой.

Точки расширения админки

Заголовок раздела «Точки расширения админки»

Админ-панель запрашивает у сервера расширения включённых плагинов и один раз импортирует каждый admin.script как ES-модуль из /admin/plugins/<name>/<script> (относительно [admin].path). Файлы из каталога admin/ плагина отдаются там, пока плагин включён, с X-Content-Type-Options: nosniff и Cache-Control: no-cache. Модуль должен определить пользовательские элементы, названные в манифесте; элемент, не определённый в течение 3 секунд, пропускается.

Виджеты

Заголовок раздела «Виджеты»

Каждая запись [[admin.widgets]] — это тип виджета, который администраторы могут добавить на главную панель. Элемент получает свойство context:

Свойство Описание
apiBase Базовый путь content API, например /api.
adminApiBase Базовый путь admin API, например /admin/api.
fetch(path, init) fetch с учётными данными вошедшего администратора. Относительные пути разрешаются относительно adminApiBase; пути под любым из базовых путей и абсолютные URL сохраняются.

context.fetch отправляет сессию администратора только с запросами к admin API. Пути под context.apiBase (content API, включая маршруты вашего плагина) отправляются без неё, поскольку content API не принимает сессии администраторов; на них отвечают с разрешениями публичной роли. До 0.10 сессия отправлялась и туда, и такие запросы падали; виджеты, написанные для 0.9, которые вызывают обычный fetch, продолжают работать.

Пользовательские поля

Заголовок раздела «Пользовательские поля»

Каждая запись [[admin.fields]] — это поле, которое атрибуты могут использовать через "customField": "plugin::<name>.<id>"; type атрибута должен соответствовать тому, как поле хранит значение. Его предлагает Конструктор типов содержимого. Элемент получает:

Свойство Описание
value Текущее значение.
disabled Выключено ли редактирование.
attribute Определение атрибута из схемы.
locale Редактируемая локаль.

Новое значение элемент сообщает событием change, у которого detail — это значение (или, без detail, через собственное свойство value). Если плагин выключен или его элемента нет, редактор показывает обычное поле ввода для типа хранения. См. Типы атрибутов.

Метрики

Заголовок раздела «Метрики»

Если включён [metrics], /_metrics сообщает о каждом вызове, дошедшем до экспортируемой функции:

Метрика Тип Метки Значение
verdin_plugin_call_duration_seconds histogram plugin, kind, function Время работы функций плагинов. Корзины от 5 мс до 10 с.
verdin_plugin_call_errors_total counter plugin, kind, function Неудачные вызовы: trap, тайм-аут, вывод не в JSON или { error } из функции запуска.

kind — это hook, route, job, startup или graphql. Хук «до», который отклоняет запись через { error }, дал ответ, поэтому не считается сбоем. Вызовы функции, которую модуль не экспортирует, не записываются, так что набор меток ограничен установленными плагинами. Серии появляются после первого вызова плагина; каждый экземпляр считает только свои вызовы.
