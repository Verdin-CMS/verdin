Tutorial: un blog con Astro

En este tutorial construyes con Astro un blog estático que lee su contenido de Verdin: una página de inicio que enumera los artículos, una página por artículo en /articles/<slug>/ con su categoría y, opcionalmente, una página que muestra los borradores desde el enlace de vista previa del panel. Usas el cliente tipado @verdin/client con tipos generados a partir del esquema.

Escrito para Astro 7.3 (create-astro 5.2) y Node.js 22.12 o posterior, con Verdin y @verdin/client 0.10. El tutorial de Next.js construye el mismo blog con Next.js.

Antes de empezar

Sección titulada «Antes de empezar»

Necesitas el binario verdin en tu PATH (consulta el inicio rápido), Node.js y Git. Acabarás con dos carpetas una junto a otra: cms, el proyecto de Verdin, y blog, el sitio de Astro.

1. Prepara Verdin con el esquema del blog

Sección titulada «1. Prepara Verdin con el esquema del blog»

El proyecto examples/blog del repositorio modela un blog: artículos con un título, un slug, un extracto, un body en Markdown, una categoría y etiquetas, además de un tipo único homepage y algunos componentes.

  2. Arráncalo:

    El primer arranque crea las tablas de los cuatro tipos de contenido.

  3. Abre http://localhost:1337/admin/ y crea el primer administrador.

  4. En Colecciones, abre Category, selecciona Nueva entrada, llámala News y guarda.

  5. Abre Article, selecciona Nueva entrada y rellena un título, un extracto y un cuerpo en Markdown. El slug se genera a partir del título. Elige News como categoría y selecciona Publicar. Añade un segundo artículo de la misma forma.

  6. Abre Configuración → Acceso público, permite Buscar y Buscar uno para Article y Category, y selecciona Guardar.

6. Enumera los artículos

Sección titulada «6. Enumera los artículos»

La consulta es la llamada REST GET /api/articles?fields[0]=title&…&populate[category][fields][0]=name&sort[0]=publishedAt:desc, en el formato de Strapi v5. fields mantiene pequeña la respuesta, y populate añade la categoría solo con su nombre. El rol público solo lee los artículos publicados.

7. Añade una página por artículo

Sección titulada «7. Añade una página por artículo»

Astro construye una página por artículo. getStaticPaths pide los artículos con su categoría y pasa cada uno a su página:

pageSize está limitado por [api].max_page_size (100 por defecto). Con más artículos, pide las páginas en un bucle usando meta.pagination.pageCount.

Precaución

marked no sanea el HTML. No pasa nada con el Markdown que escriben tus propios editores; si el contenido puede venir de personas que no son de confianza, sanea el HTML antes de mostrarlo.

8. Ejecútalo

Sección titulada «8. Ejecútalo»

Abre http://localhost:4321: la lista muestra tus artículos publicados, y cada uno enlaza con su página. npm run build escribe el sitio estático en dist/.

Un build estático lee el contenido una sola vez. Para publicar los cambios, reconstruye el sitio cuando cambie el contenido, por ejemplo desde un webhook o un hook de despliegue; consulta Despliegues y CDN.

Tu proyecto queda así:

  • Directorioblog/
    • astro.config.mjs
    • Directoriosrc/
      • verdin-types.ts generado por verdin types
      • Directoriolib/
        • verdin.ts
      • Directoriolayouts/
        • Layout.astro
      • Directoriopages/
        • index.astro
        • Directorioarticles/
          • [slug].astro

9. Opcional: vista previa de borradores

Sección titulada «9. Opcional: vista previa de borradores»

El panel puede abrir un borrador en tu sitio con un token de vista previa de vida corta. El token lee ese único documento, borradores incluidos, y nada más. Como los borradores cambian después del build, la página de vista previa se genera en cada petición, lo que necesita un adaptador:

Añade un cliente que envíe el token de vista previa en la cabecera x-verdin-preview:

Después, la página. prerender = false la genera bajo demanda; el token llega como parámetro de consulta preview:

Un token de vista previa no puede listar entradas, así que la página busca el borrador por documentId y no por slug. Ahora indica a Verdin dónde está la página:

  1. En el panel, abre Configuración → Funcionalidades, activa Vista previa y selecciona Configurar las URL de vista previa.
  2. Pon http://localhost:4321/preview/{documentId} como plantilla de URL de Article y guarda. Verdin añade el token como ?preview=….
  3. Abre un artículo, cámbialo y selecciona Guardar borrador, y después Abrir vista previa.

La página muestra el borrador. Los enlaces duran 60 minutos por defecto. Consulta Vista previa para los marcadores y los ajustes, y Edición visual para editar desde la vista previa.
