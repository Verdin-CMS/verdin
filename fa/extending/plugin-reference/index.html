مرجع افزونه‌ها

این صفحه قرارداد کامل میان Verdin و یک افزونه است: مانیفست، آنچه Verdin به هر تابع صادرشده می‌فرستد و در پاسخ انتظار دارد، و توابع میزبانی که یک ماژول می‌تواند فراخوانی کند. برای آشنایی، افزونه‌ها را ببینید؛ برای یک نمونهٔ کامل، آموزش افزونه را.

پوشهٔ افزونه

Section titled “پوشهٔ افزونه”

هر افزونه یک پوشه در [plugins].path است (پیش‌فرض plugins/، کنار verdin.toml):

فایل الزامی محتوا
plugin.toml بله مانیفست.
plugin.wasm بله ماژول (با wasm می‌توان مسیر دیگری داد).
admin/ خیر فایل‌هایی که پنل مدیریت بارگذاری می‌کند: ماژول admin.script و فایل‌های همراه آن.

Verdin هنگام راه‌اندازی هر پوشه‌ای را که plugin.toml دارد، به ترتیب نام، بارگذاری می‌کند. اگر مانیفست یک پوشه نامعتبر باشد، ماژول آن وجود نداشته باشد، یا افزونهٔ دیگری از قبل همان name را داشته باشد، آن پوشه نادیده گرفته می‌شود و همراه با دلیل در تنظیمات ← افزونه‌ها فهرست می‌شود.

مانیفست

Section titled “مانیفست”

کلیدهای ناشناخته در همهٔ جدول‌ها خطا هستند.

کلیدهای سطح بالا

Section titled “کلیدهای سطح بالا”
کلید پیش‌فرض توضیح
name الزامی شناسهٔ افزونه در URLها، تنظیمات و فیلدهای سفارشی: حروف کوچک، ارقام و -، که با یک حرف شروع شود، حداکثر 64 نویسه.
version الزامی در پنل مدیریت و لاگ نمایش داده می‌شود.
description تنظیم‌نشده در تنظیمات ← افزونه‌ها نمایش داده می‌شود.
wasm "plugin.wasm" ماژول، نسبت به پوشهٔ افزونه (بدون .. و نه مسیر مطلق).
wasi false به ماژول WASI می‌دهد: یک ساعت و اعداد تصادفی. در هر حال نه فایلی در کار است و نه سوکتی.

[capabilities]

Section titled “[capabilities]”
کلید پیش‌فرض توضیح
read [] نوع‌های محتوایی که verdin_content می‌تواند بخواند (findMany، findOne): uidهایی مانند api::article، یا "*" برای همه.
write [] نوع‌های محتوایی که می‌تواند روی آن‌ها create، update، delete، publish و unpublish انجام دهد. read را هم در بر دارد.
http [] میزبان‌هایی که ماژول می‌تواند به آن‌ها درخواست HTTP بفرستد: api.example.com یا *.example.com.
kv false ذخیره‌سازی کلید-مقدار خود افزونه (verdin_kv_get، verdin_kv_set).
public_permissions false خواندن و جایگزین کردن مجوزهای content API نقش عمومی (verdin_public_permissions).

قابلیت‌ها فقط فراخوانی‌های میزبان را محدود می‌کنند. هوک‌ها صرف‌نظر از read روی نوع‌هایی که نام می‌برند اجرا می‌شوند، و مسیرها برای همه در دسترس‌اند.

[limits]

Section titled “[limits]”
کلید پیش‌فرض توضیح
timeout_ms 5000 محدودیت زمانی هر فراخوانی، به میلی‌ثانیه.
memory_mb 64 بیشترین حافظهٔ ماژول، به مگابایت.

هر دو باید مثبت باشند.

[[hooks]]

Section titled “[[hooks]]”
کلید پیش‌فرض توضیح
on الزامی رویداد، در ادامه.
uid "*" نوع محتوا (api::article)، یا "*" برای همه.
function الزامی تابع صادرشده‌ای که فراخوانی می‌شود.

رویدادها:

پیش از نوشتن پس از نوشتن
beforeCreate afterCreate
beforeUpdate afterUpdate
beforeDelete afterDelete
beforePublish afterPublish
beforeUnpublish afterUnpublish
beforeDiscardDraft afterDiscardDraft

این نام‌ها همان نام‌های چرخهٔ حیات (lifecycle) در Strapi هستند. هوک‌ها روی نوشتن‌هایی که از پنل مدیریت، APIهای REST و GraphQL و بسته‌های انتشار انجام می‌شوند اجرا می‌شوند، اما نه روی نوشتن‌هایی که فرمان‌های verdin import انجام می‌دهند. نوشتن‌هایی که افزونه‌ها انجام می‌دهند هوک‌های پس از نوشتن را اجرا می‌کنند اما هوک‌های پیش از نوشتن را نه (بخش نوشتن توسط افزونه‌ها را ببینید).

[routes]

Section titled “[routes]”
کلید توضیح
function تابع صادرشده‌ای که به همهٔ درخواست‌ها به /api/plugins/<name> و /api/plugins/<name>/… با هر متدی پاسخ می‌دهد.

این مسیر از [api].prefix پیروی می‌کند.

[[jobs]]

Section titled “[[jobs]]”
کلید توضیح
schedule عبارت Cron، به وقت UTC، با ثانیهٔ اختیاری: */15 * * * *، 0 0 3 * * *.
function تابع صادرشده‌ای که فراخوانی می‌شود.

[startup]

Section titled “[startup]”

تابعی که هنگام شروع افزونه اجرا می‌شود: کاری که یک پروژهٔ Strapi در bootstrap انجام می‌دهد (seed کردن محتوا، تنظیم نقش عمومی).

کلید پیش‌فرض توضیح
function الزامی تابع صادرشده‌ای که فراخوانی می‌شود.
timeout_ms 30000 محدودیت زمانی مخصوص خودش، به میلی‌ثانیه (seed کردن می‌تواند از یک هوک بیشتر طول بکشد). باید مثبت باشد.

برای اینکه چه وقت اجرا می‌شود، تابع راه‌اندازی را ببینید.

[[graphql]]

Section titled “[[graphql]]”
کلید پیش‌فرض توضیح
name الزامی نام فیلد: با یک حرف کوچک شروع می‌شود و پس از آن حروف، ارقام و _ می‌آید.
function الزامی تابع صادرشده‌ای که آن را resolve می‌کند.
mutation false فیلد را به‌جای Query به Mutation اضافه می‌کند.
description تنظیم‌نشده توضیح فیلد در طرح‌واره (schema).

هر مدخل name(args: JSON): JSON را اضافه می‌کند. نامی که یک نوع محتوا از قبل استفاده می‌کند، یا افزونهٔ دیگری زودتر گرفته است، با یک هشدار در لاگ نادیده گرفته می‌شود.

[admin]

Section titled “[admin]”
کلید توضیح
script ماژول ES در admin/ که عناصر سفارشی (custom elements) را تعریف می‌کند (بدون .. و نه مسیر مطلق).
[[admin.widgets]] نوع‌های ویجت داشبورد: id، title، element، و description اختیاری.
[[admin.fields]] فیلدهای سفارشی: id، title، element، type (نوع ویژگی‌ای که مقدار با آن ذخیره می‌شود، مانند string یا json)، و description اختیاری.

element نام یک عنصر سفارشی است: حروف کوچک، ارقام و -، با دست‌کم یک - (slugs-color).

[[settings]]

Section titled “[[settings]]”

فرم تنظیمات ← افزونه‌ها ← تنظیمات را تعریف می‌کند. بدون هیچ مدخلی، تنظیمات یک شیء JSON آزاد است.

کلید پیش‌فرض توضیح
key الزامی کلید در شیء تنظیمات: حروف، ارقام و _، که با رقم شروع نشود، یکتا.
label الزامی برچسب فرم.
type "string" string، text، url، number، integer، boolean یا select.
description تنظیم‌نشده متن راهنما زیر فیلد.
required false یک مقدار (برای متن، غیرخالی) لازم است، مگر اینکه default وجود داشته باشد.
options [] گزینه‌های یک select (برای آن الزامی است).
default تنظیم‌نشده وقتی کلید وجود ندارد یا null است به کار می‌رود. باید با فیلد جور باشد.
min، max تنظیم‌نشده کران‌های مقادیر number و integer؛ کران‌های طول string و text.

مقادیر url یا خالی‌اند یا URLهای http(s)://. وقتی فرم تعریف شده باشد، سرور تنظیماتی را که کلید ناشناخته، نوع نادرست، مقدار خارج از محدوده یا مقدار الزامیِ ناموجود دارند رد می‌کند (400).

توابع صادرشده

Section titled “توابع صادرشده”

هر تابع صادرشده یک سند JSON می‌گیرد و یک سند برمی‌گرداند (یا هیچ). خروجی خالی null حساب می‌شود؛ خروجی‌ای که JSON نباشد شکست حساب می‌شود.

هوک‌های پیش از نوشتن

Section titled “هوک‌های پیش از نوشتن”

ورودی:

فیلد توضیح
event رویداد هوک.
uid نوع محتوا.
documentId سند، یا null در beforeCreate.
locale در نوع‌های بومی‌سازی‌شده، زبانی که نوشته می‌شود (زبان پیش‌فرض، وقتی درخواست زبانی نام نبرده باشد)؛ در نوع‌های دیگر null.
data داده‌ای که نوشته می‌شود، همان‌طور که درخواست فرستاده است: در create و update. برای رویدادهای دیگر null. در update، فقط فیلدهای ارسال‌شده.

خروجی:

خروجی اثر
{ "data": { … } } دادهٔ نوشته‌شده را جایگزین می‌کند. مانند دادهٔ اصلی اعتبارسنجی می‌شود.
{ "error": "message" } نوشتن را رد می‌کند: فراخواننده یک 400 همراه با پیام دریافت می‌کند.
{} یا هر چیز دیگر نوشتن بدون تغییر ادامه می‌یابد.

وقتی چند هوک مطابقت داشته باشند، به ترتیب افزونه‌ها (نام پوشه‌ها) و سپس به ترتیب مانیفست اجرا می‌شوند؛ هر کدام داده‌ای را می‌بیند که قبلی برگردانده است. هوکی که شکست بخورد (trap، timeout، خروجی نامعتبر) لاگ و نادیده گرفته می‌شود: نوشتن ادامه می‌یابد.

هوک‌های پس از نوشتن

Section titled “هوک‌های پس از نوشتن”

ورودی: { "event", "uid", "documentId", "locale" }، که پس از commit شدن نوشتن فرستاده می‌شود. خروجی نادیده گرفته می‌شود؛ شکست‌ها لاگ می‌شوند. اگر به فیلدهای مدخل نیاز دارید، آن را با verdin_content بخوانید (با قابلیت read).

مسیرها

Section titled “مسیرها”

ورودی:

فیلد توضیح
method متد HTTP.
path مسیر پس از /api/plugins/<name>، که با / شروع می‌شود (/ برای ریشهٔ افزونه).
query رشتهٔ کوئری خام، بدون ? (وقتی وجود نداشته باشد خالی است).
headers فقط content-type، accept، user-agent و accept-language، در صورت وجود.
body بدنهٔ درخواست به‌صورت رشته (UTF-8 نامعتبر جایگزین می‌شود).
actor چه کسی فراخوانی می‌کند: { "kind": "public" }، { "kind": "token", "id": 3 } (یک توکن API) یا { "kind": "user", "id": 12 } (یک کاربر نهایی واردشده).

هدر Authorization با توکن نامعتبر، پیش از فراخوانی افزونه با 401 رد می‌شود. دسترسی عمومی و مجوزهای توکن API اعمال نمی‌شوند: actor را خودتان بررسی کنید.

خروجی:

فیلد پیش‌فرض توضیح
status 200 وضعیت HTTP.
headers هیچ هدرهای پاسخ. فقط content-type، cache-control، location، etag، last-modified و content-disposition نگه داشته می‌شوند.
body خالی رشته همان‌طور که هست فرستاده می‌شود (text/plain، مگر اینکه content-type را تنظیم کنید)؛ هر مقدار JSON دیگری به‌صورت application/json فرستاده می‌شود.

افزونهٔ غیرفعال یا ناشناخته، یا افزونهٔ بدون [routes]، با 404 پاسخ می‌دهد. فراخوانی ناموفق با 502 و { "data": null, "error": { "status": 502, "name": "PluginError", … } } پاسخ می‌دهد. مسیرها از [server].body_limit و [server].request_timeout_secs مشترک با API محتوا پیروی می‌کنند.

کارهای زمان‌بندی‌شده

Section titled “کارهای زمان‌بندی‌شده”

ورودی: { "scheduledAt": "2026-09-29T03:00:00+00:00" }، زمانی که اجرا برای آن زمان‌بندی شده بود. خروجی نادیده گرفته می‌شود؛ شکست‌ها لاگ می‌شوند. کارها فقط وقتی افزونه روشن است اجرا می‌شوند، و فقط روی نمونه‌هایی که [plugins].run_jobs = true دارند. اجرایی که هنگام خاموش بودن سرور از دست رفته باشد جبران نمی‌شود.

تابع راه‌اندازی

Section titled “تابع راه‌اندازی”

ورودی: { "reason": "start" | "enabled" | "settings" }:

reason چه وقت
start سرور با روشن بودن افزونه شروع شد.
enabled افزونه روشن شد (اینجا، یا روی نمونهٔ دیگری و اینجا دریافت شد).
settings تنظیماتش هنگام روشن بودن تغییر کرد (اینجا ذخیره شد، یا از نمونهٔ دیگری دریافت شد).

خروجی: { "error": "message" } شکست حساب می‌شود؛ هر چیز دیگر ({}، خالی) موفقیت. یک شکست (trap، time-out، { error }) به لاگ افزونه و لاگ سرور می‌رود؛ افزونه روشن می‌ماند، و تابع در شروع، روشن شدن یا تغییر تنظیمات بعدی دوباره اجرا می‌شود.

تابع در پس‌زمینه و پس از بالا آمدن سرور اجرا می‌شود، بنابراین در این مدت درخواست‌ها پاسخ داده می‌شوند. روی یک نمونهٔ ماژول مخصوص به خودش و با [startup].timeout_ms اجرا می‌شود، پس یک seed کند هوک‌ها و مسیرهای افزونه را معطل نمی‌کند. هوک‌های پس از نوشتنی که نوشتن‌های آن فعال می‌کند پس از بازگشت آن اجرا می‌شوند (بخش نوشتن توسط افزونه‌ها را ببینید). حافظهٔ ماژول با نمونهٔ عادی افزونه مشترک نیست: وضعیت را در verdin_kv_set یا در محتوا نگه دارید.

با چند نمونه، فقط آن‌هایی که [plugins].run_jobs = true دارند توابع راه‌اندازی را اجرا می‌کنند (یک نمونه، اگر توصیهٔ مقیاس‌پذیری را دنبال کنید): آن‌ها روی پایگاه دادهٔ مشترک کار می‌کنند، پس یک بار کافی است. تابع را طوری بنویسید که اجرای دوباره‌اش بی‌ضرر باشد: پیش از ساختن چیزی که seed می‌کنید، آن را جست‌وجو کنید.

فیلدهای GraphQL

Section titled “فیلدهای GraphQL”

ورودی: { "args": …, "actor": … }، که در آن args آرگومان args فیلد است (هر JSON، یا null) و actor مانند مسیرهاست. خروجی مقدار فیلد است. شکست، یا افزونهٔ غیرفعال، با یک خطای GraphQL با کد PLUGIN_ERROR پاسخ داده می‌شود. مانند مسیرها، بررسی دسترسی بر عهدهٔ افزونه است.

توابع میزبان

Section titled “توابع میزبان”

آن‌ها را از فضای نام extism:host/user وارد کنید (extern "ExtismHost" در Rust). این توابع JSON را به‌صورت رشته می‌گیرند و برمی‌گردانند؛ Json<Value> در extism-pdk تبدیل را انجام می‌دهد.

تابع ورودی خروجی
verdin_log { "level": "info" | "warn" | "error", "message": "…" } هیچ
verdin_content یک درخواست محتوا (در ادامه) نتیجه، یا { "error": "…" }
verdin_kv_get کلید، به‌صورت رشتهٔ ساده مقدار JSON ذخیره‌شده، یا null
verdin_kv_set { "key": "…", "value": … } هیچ
verdin_config هیچ شیء تنظیمات، با پیش‌فرض‌های تعریف‌شده پرشده
verdin_public_permissions { "op": "get" } یا { "op": "set", "permissions": [...] } { "permissions": [...] }، یا { "error": "…" }

ماژولی که یک تابع میزبان را import کند که سرور ندارد (یک Verdin قدیمی‌تر) بارگذاری نمی‌شود: هر فراخوانی آن در لاگ سرور با unknown import شکست می‌خورد.

verdin_log

Section titled “verdin_log”

در لاگ سرور (همراه با نام افزونه) و در لاگ افزونه در تنظیمات ← افزونه‌ها ← گزارش‌ها می‌نویسد. سطح‌های دیگر info حساب می‌شوند. لاگ افزونه 200 پیام آخر را، هر کدام بریده‌شده در 2,000 نویسه، در حافظه نگه می‌دارد.

verdin_content

Section titled “verdin_content”
فیلد استفاده در توضیح
op همه findMany، findOne، create، update، delete، publish یا unpublish.
uid همه نوع محتوا. باید در قابلیت‌ها باشد.
documentId findOne، update، delete، publish، unpublish سند.
query findMany، findOne پارامترهای REST API به‌صورت یک شیء JSON: filters، sort، fields، populate، pagination، status.
data create، update فیلدهایی که نوشته می‌شوند، مانند data در یک درخواست REST.
status create، update "draft" یک پیش‌نویس ذخیره می‌کند. در غیر این صورت نوشته منتشر می‌شود، مانند نوشتن REST بدون ?status=draft.
locale همه زبانی که خوانده یا نوشته می‌شود.

نتیجه‌ها:

op نتیجه
findMany { "documents": [...], "meta": { "pagination": {…} } }
findOne { "document": {…} } (وقتی پیدا نشود null)
create، update { "documentId": "…" }
delete { "deleted": true }
publish { "published": true }
unpublish { "unpublished": true }

فراخوانی خارج از قابلیت‌ها، عملیات ناشناخته، خطای اعتبارسنجی یا سند ناموجود به‌جای آن { "error": "…" } پاسخ می‌دهد. خواندن‌ها نسخه‌های منتشرشده را برمی‌گردانند، مگر اینکه کوئری "status": "draft" بخواهد.

نوشتن توسط افزونه‌ها

Section titled “نوشتن توسط افزونه‌ها”

نوشتن از طریق verdin_content از هوک‌های پیش از نوشتن همهٔ افزونه‌ها عبور نمی‌کند، بنابراین افزونه نمی‌تواند در آنجا روی تغییرات خودش در حلقه بیفتد، و قاعده‌هایی که در هوک‌های پیش از نوشتن می‌گذارید (پیش‌فرض‌ها، بررسی‌ها) روی آن‌ها اعمال نمی‌شوند. بقیهٔ موارد اعمال می‌شوند: اعتبارسنجی، مرحله‌های بازبینی، وب‌هوک‌ها، تاریخچه، گزارش حسابرسی، و هوک‌های پس از نوشتن همهٔ افزونه‌ها، از جمله خود افزونهٔ نویسنده.

هوک‌های پس از نوشتنی که نوشتن‌های یک افزونه فعال می‌کند درون نوشتن اجرا نمی‌شوند: در صف قرار می‌گیرند و پس از اینکه فراخوانی افزونه (مسیر، کار، resolver در GraphQL، هوک یا تابع راه‌اندازی) بازگشته و نمونهٔ افزونه را آزاد کرده است، پیش از ارسال پاسخ مسیر اجرا می‌شوند. بنابراین یک افزونه می‌تواند نوعی را بنویسد که روی آن هوک پس از نوشتن دارد، و زنجیره‌ها از چند افزونه کار می‌کنند.

  • هوک‌هایی که می‌نویسند هوک‌های بعدی را فعال می‌کنند، حداکثر تا 4 سطح (نوشتن از REST یا GraphQL سطح 1 است). هوک‌های عمیق‌تر با یک هشدار در لاگ افزونه رد می‌شوند، که جلوی حلقهٔ بی‌پایان هوکی را می‌گیرد که نوعی را می‌نویسد که به آن گوش می‌دهد.
  • توابع میزبان (verdin_content، verdin_public_permissions، ذخیره‌گاه کلید-مقدار) در حد زمانی فراخوانی متوقف می‌شوند و یک خطا به ماژول برمی‌گردانند، و یک فراخواننده برای افزونه‌ای که مشغول است حداکثر به اندازهٔ حد زمانی به‌علاوهٔ 10 ثانیه منتظر می‌ماند. یک فراخوانی گیرکرده نمی‌تواند افزونه، یا یک توقف ملایم، را برای همیشه نگه دارد.

verdin_kv_get و verdin_kv_set

Section titled “verdin_kv_get و verdin_kv_set”

یک مخزن کلید-مقدار برای هر افزونه، در پایگاه دادهٔ Verdin، که میان همهٔ نمونه‌ها مشترک است. کلیدها 1 تا 255 بایت‌اند؛ مقادیر هر JSONی می‌توانند باشند. تنظیم null کلید را حذف می‌کند. بدون قابلیت kv، خواندن‌ها null برمی‌گردانند و نوشتن‌ها نادیده گرفته می‌شوند.

verdin_config

Section titled “verdin_config”

تنظیمات ذخیره‌شده در تنظیمات ← افزونه‌ها را برمی‌گرداند، در حالی که default هر تنظیم تعریف‌شده برای کلیدهای ناموجود پر شده است. وقتی چیزی ذخیره نشده باشد {}.

verdin_public_permissions

Section titled “verdin_public_permissions”

مجوزهای content API نقش عمومی را می‌خواند یا جایگزین می‌کند، همان چیزی که تنظیمات ← دسترسی عمومی ویرایش می‌کند. به قابلیت public_permissions نیاز دارد؛ بدون آن، هر فراخوانی { "error": "…" } پاسخ می‌دهد.

op اثر
get هیچ؛ مجوزهای فعلی را برمی‌گرداند.
set همهٔ مجوزهای عمومی را با permissions جایگزین می‌کند (فهرست خالی همه را حذف می‌کند).

هر دو { "permissions": [{ "subject", "action" }, …] } را مرتب‌شده پاسخ می‌دهند. subject یک uid نوع محتوا، plugin::upload (کتابخانهٔ رسانه)، plugin::users-permissions.user (کاربران نهایی روی content API) یا plugin::i18n.locale (فقط find) است. action یکی از find، findOne، create، update، delete، publish یا readDrafts است (دو مورد آخر برای بارگذاری‌ها و کاربران نهایی اعمال نمی‌شوند). مانند جدول مجوزهای مدیر بررسی می‌شوند: یک subject یا action ناشناخته، یا ناسازگار، { "error": "…" } پاسخ می‌دهد و چیزی را تغییر نمی‌دهد. هر set در لاگ سرور نوشته می‌شود.

HTTP

Section titled “HTTP”

با میزبان‌هایی که در http فهرست شده‌اند، از پشتیبانی HTTP در Extism استفاده کنید (extism_pdk::http::request در Rust). درخواست به میزبان‌های دیگر شکست می‌خورد.

نقاط گسترش پنل مدیریت

Section titled “نقاط گسترش پنل مدیریت”

پنل مدیریت افزونه‌های فعال را از سرور می‌پرسد و admin.script هر کدام را یک بار، به‌صورت ماژول ES، از /admin/plugins/<name>/<script> (زیر [admin].path) وارد می‌کند. تا وقتی افزونه روشن است، فایل‌های پوشهٔ admin/ آن در همان‌جا با X-Content-Type-Options: nosniff و Cache-Control: no-cache ارائه می‌شوند. ماژول باید عناصر سفارشی‌ای را که مانیفست نام می‌برد تعریف کند؛ عنصری که ظرف 3 ثانیه تعریف نشود کنار گذاشته می‌شود.

ویجت‌ها

Section titled “ویجت‌ها”

هر مدخل [[admin.widgets]] یک نوع ویجت است که مدیران می‌توانند به داشبورد اضافه کنند. عنصر یک ویژگی context دریافت می‌کند:

ویژگی توضیح
apiBase پایهٔ API محتوا، مانند /api.
adminApiBase پایهٔ Admin API، مانند /admin/api.
fetch(path, init) fetch با اعتبارنامهٔ مدیر واردشده. مسیرهای نسبی نسبت به adminApiBase resolve می‌شوند؛ مسیرهای زیر هر یک از دو پایه و URLهای مطلق همان‌طور می‌مانند.

context.fetch نشست مدیر را فقط با درخواست‌های Admin API می‌فرستد. مسیرهای زیر context.apiBase (API محتوا، از جمله مسیرهای افزونهٔ شما) بدون آن فرستاده می‌شوند، چون API محتوا نشست‌های مدیر را نمی‌پذیرد؛ به آن‌ها با مجوزهای نقش عمومی پاسخ داده می‌شود. پیش از 0.10 نشست را به آنجا هم می‌فرستاد و آن درخواست‌ها شکست می‌خوردند؛ ویجت‌هایی که برای 0.9 نوشته شده‌اند و fetch ساده را فراخوانی می‌کنند همچنان کار می‌کنند.

فیلدهای سفارشی

Section titled “فیلدهای سفارشی”

هر مدخل [[admin.fields]] فیلدی است که ویژگی‌ها می‌توانند با "customField": "plugin::<name>.<id>" از آن استفاده کنند؛ type ویژگی باید با شیوهٔ ذخیره‌سازی مقدار آن فیلد مطابقت داشته باشد. سازندهٔ نوع محتوا آن را پیشنهاد می‌دهد. عنصر این‌ها را دریافت می‌کند:

ویژگی توضیح
value مقدار فعلی.
disabled اینکه ویرایش خاموش است یا نه.
attribute تعریف ویژگی از طرح‌واره.
locale زبانی که ویرایش می‌شود.

عنصر مقدار جدید را با یک رویداد change گزارش می‌دهد که detail آن همان مقدار است (یا، بدون detail، از طریق ویژگی value خودش). وقتی افزونه خاموش باشد یا عنصر آن وجود نداشته باشد، ویرایشگر ورودی معمولی نوع ذخیره‌سازی را نشان می‌دهد. نوع‌های ویژگی را ببینید.

زمان اجرا و محدودیت‌ها

Section titled “زمان اجرا و محدودیت‌ها”
محدودیت مقدار
زمان هر فراخوانی [limits].timeout_ms، پیش‌فرض 5,000 ms ([startup].timeout_ms، پیش‌فرض 30,000 ms، برای تابع راه‌اندازی)
حافظه [limits].memory_mb، پیش‌فرض 64 MB
همروندی برای هر افزونه در هر لحظه یک فراخوانی؛ فراخوانی‌ها منتظر یکدیگر می‌مانند (تابع راه‌اندازی در کنار آن‌ها اجرا می‌شود)
نمونهٔ ماژول یکی برای هر افزونه، که در اولین استفاده ساخته می‌شود؛ پس از شکست یک فراخوانی دوباره ساخته می‌شود (حافظهٔ آن از دست می‌رود). تابع راه‌اندازی در هر اجرا یکی تازه می‌گیرد
لاگ 200 پیام برای هر افزونه، هر کدام 2,000 نویسه، در حافظه
کلیدهای KV 1 تا 255 بایت
هدرهای درخواست مسیر content-type، accept، user-agent، accept-language
هدرهای پاسخ مسیر content-type، cache-control، location، etag، last-modified، content-disposition

تغییرات مانیفست یا ماژول پس از راه‌اندازی دوباره اعمال می‌شوند؛ کلیدهای روشن/خاموش و تنظیمات بی‌درنگ اعمال می‌شوند. مدیریت افزونه‌ها به plugins.manage نیاز دارد (بخش مرجع مجوزها را ببینید).

متریک‌ها

Section titled “متریک‌ها”

با روشن بودن [metrics]، /_metrics هر فراخوانی‌ای را که به یک تابع صادرشده رسیده گزارش می‌کند:

متریک نوع Labelها معنا
verdin_plugin_call_duration_seconds histogram plugin، kind، function زمانی که تابع‌های افزونه گرفتند. bucketها از 5 ms تا 10 s.
verdin_plugin_call_errors_total counter plugin، kind، function فراخوانی‌هایی که شکست خوردند: trap، time-out، خروجی‌ای که JSON نیست، یا { error } یک تابع راه‌اندازی.

kind برابر hook، route، job، startup یا graphql است. هوک پیش از نوشتنی که یک نوشتن را با { error } رد می‌کند پاسخی داده است، پس شکست حساب نمی‌شود. فراخوانی تابعی که ماژول صادر نمی‌کند ثبت نمی‌شود، بنابراین labelها به افزونه‌های نصب‌شده محدود می‌مانند. سری‌ها پس از نخستین فراخوانی افزونه ظاهر می‌شوند؛ هر نمونه فراخوانی‌های خودش را می‌شمارد.
